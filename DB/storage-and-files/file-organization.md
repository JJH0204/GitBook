# [생성형 AI] 파일 조직 방식 비교

## 작업 식별

| 항목 | 내용 |
|---|---|
| Task ID | DB-STO-003-DO |
| 유형 | D&O (개념) |
| 목적 | 힙, 순차, 색인 순차, 해시 파일의 구조와 적합한 질의를 비교한다 |
| 작성 | 생성형 AI 초안 (사람 검토 전) |
| 확인 상태 | 미검증 (파일 구조론의 일반 지식을 정리한 것이며 실행해 확인하지 않았다) |
| 개정 | R1 (2026-11-19) |

## 1. 목적

레코드를 디스크에 어떻게 배치하느냐에 따라 조회·삽입 속도가 달라진다. 이 문서는 네 가지 기본 방식을 비교한다. 색인 순차 파일의 구조는 DB-STO-001-DO, B+트리는 DB-STO-002-DO를 따른다.

## 2. 구성 요소

| 방식 | 배치 | 잘하는 것 | 못하는 것 |
|---|---|---|---|
| 힙 파일(heap) | 들어온 순서대로 빈 곳에 쌓는다 | 삽입이 빠르다 | 특정 값 찾기에 전체를 읽는다 |
| 순차 파일(sequential) | 키 순서로 정렬해 저장한다 | 키 순서 전체 읽기, 범위 읽기 | 중간 삽입이 느리다(재정렬 또는 별도 영역 필요) |
| 색인 순차 파일(ISAM) | 키 순서 저장 + 키별 색인 | 한 값 찾기와 범위 읽기 | 삽입이 많으면 넘침 영역이 늘어 성능이 떨어진다 |
| 해시 파일(hash) | 키를 해시 함수에 넣어 나온 버킷에 저장한다 | 같은 값 찾기(`=`)가 한두 번의 접근으로 끝난다 | 범위 조회, 정렬 순서 읽기 |

## 3. 동작 원리

### 3.1 해시 파일

| 순서 | 처리 |
|---|---|
| 1 | 키 값에 해시 함수를 적용해 버킷 번호를 얻는다 |
| 2 | 해당 버킷(디스크 블록)을 읽는다 |
| 3 | 버킷 안에서 키가 같은 레코드를 찾는다 |

서로 다른 키가 같은 버킷에 배정되는 충돌이 있으면 넘침 버킷을 연결해 처리한다. 넘침이 길어지면 조회가 느려진다.

### 3.2 질의별 선택 기준

| 질의 형태 | 적합한 방식 |
|---|---|
| 한 키 값 조회가 대부분 | 해시, 색인 |
| 범위·정렬 조회가 많다 | 순차, 색인 순차, B+트리 |
| 적재 후 전체를 읽는 분석 | 힙 |
| 삽입이 매우 많다 | 힙 또는 로그 구조 저장소 |

{% hint style="info" %}
NOTE: 현재 범용 관계형 DBMS는 대부분 B+트리 색인이 기본이다. 이 문서의 방식은 개념 비교용이다.
{% endhint %}

## 4. 약어·용어

| 용어 | 뜻 |
|---|---|
| 버킷(bucket) | 해시값 하나에 대응하는 저장 단위. 보통 디스크 블록 하나 |
| 충돌(collision) | 서로 다른 키가 같은 해시값을 갖는 일 |
| 넘침 영역(overflow) | 정해진 자리에 들어가지 못한 레코드를 두는 곳 |
