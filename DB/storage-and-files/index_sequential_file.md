## 1. 목적

색인 순차 파일은 순차 접근과 색인(Index) 접근을 결합한 파일 구조다. 데이터를 키 순서로 저장하면서, 색인으로 원하는 레코드의 위치를 빠르게 찾는다. 검색이 잦은 대량 데이터 처리에 쓴다. 색인을 유지해야 하므로 저장 공간과 갱신 비용이 더 든다.

## 2. 구성 요소

### 2.1 특징

| 번호 | 특징 | 내용 |
|---|---|---|
| 1 | 순차 + 색인 접근 | 데이터를 순차로 저장하고, 색인으로 직접 접근도 한다 |
| 2 | 색인 구조 | 키 값(기본 키)을 기준으로 색인을 만들고 관리한다 |
| 3 | 빠른 검색 | 단순 순차 파일보다 검색이 빠르다. 색인의 키 값으로 위치에 바로 접근한다 |
| 4 | 대용량 적합 | 데이터가 많을수록 전체 순차 탐색이 비효율적이어서 색인의 이점이 커진다 |

### 2.2 구성 파일

| 번호 | 구성 요소 | 역할 | 비고 |
|---|---|---|---|
| 1 | 데이터 파일 (Data File) | 실제 레코드를 키 순서로 저장한다 | |
| 2 | 색인 파일 (Index File) | 키 값과 해당 레코드의 위치를 저장한다 | 원본은 트리 또는 해시 구조로 구현된다고 적었다. 전통적인 ISAM은 키 순서의 다단계 색인을 쓴다. 확인 필요 |
| 3 | 색인 테이블 (Index Table) | 특정 키 값으로 데이터 위치를 찾을 수 있게 정리한 표다 | 검색 시 먼저 탐색한다 |

### 2.3 장점과 단점

| 장점 | 단점 |
|---|---|
| 순차 접근과 색인 접근을 모두 지원한다 | 색인 테이블을 유지할 저장 공간이 더 든다 |
| 대량 데이터에서도 검색이 빠르다 | 삭제 시 색인 재구성 부담이 생긴다 |
| 키 순서로 저장해 순차 처리에 유리하다 | 삽입과 삭제 때 색인도 갱신해야 해서 처리 속도가 떨어질 수 있다 |

### 2.4 순차 파일, 색인 순차 파일, 직접 파일 비교

| 유형 | 접근 방식 | 검색 속도 | 추가 비용 |
|---|---|---|---|
| 순차 파일 (Sequential File) | 처음부터 끝까지 순차 탐색한다 | 느리다 (전체 탐색) | 없다 |
| 색인 순차 파일 (Index Sequential File) | 순차 + 색인 검색 | 빠르다 (색인 탐색 후 직접 접근) | 색인 테이블 유지 비용 |
| 직접 파일 (Direct File, Random File) | 해시나 직접 주소 매핑으로 접근한다 | 매우 빠르다 | 저장 공간이 더 필요할 수 있다. 원본 표기는 "높은 저장 공간 필요"다. 확인 필요 |

### 2.5 활용 사례

| 번호 | 사례 |
|---|---|
| 1 | 대형 데이터베이스 시스템 |
| 2 | 파일 기반 데이터 처리 시스템 |
| 3 | 검색이 잦은 응용 프로그램 |

## 3. 동작 원리

### 3.1 기본 동작

| 번호 | 동작 | 처리 |
|---|---|---|
| 1 | 삽입 (Insertion) | 새 레코드를 키 값 순서에 맞는 위치에 넣는다. 색인도 함께 갱신한다 |
| 2 | 검색 (Search) | 색인 파일에서 먼저 위치를 찾고, 그 위치로 데이터 파일에 접근한다 |
| 3 | 삭제 (Deletion) | 레코드를 삭제 표시하고 색인에서도 항목을 제거한다. 나중에 압축(Compaction)으로 정리한다 |

{% hint style="info" %}
NOTE: 전통적인 ISAM은 삽입할 자리가 없으면 별도의 오버플로 영역에 레코드를 두고, 오버플로가 쌓이면 파일을 재구성한다. 이 설명은 원본에 없던 내용이며 미검증이다.
{% endhint %}

### 3.2 색인 기반 검색 예

색인 테이블은 다음과 같다.

| Key | Offset |
|---|---|
| 1001 | 0x0000 |
| 1023 | 0x003A |
| 1050 | 0x005C |
| 1100 | 0x00A2 |

검색 키 값이 1050일 때의 순서다.

1. 검색 키 값 1050을 정한다.
2. 색인 파일에서 1050을 찾는다. 위치는 `0x005C`다.
3. 데이터 파일의 `0x005C` 위치로 이동해 레코드를 읽는다.

{% hint style="info" %}
NOTE: 이 예는 키마다 한 항목을 둔 색인이다. 실제 ISAM 색인은 블록마다 대표 키 하나만 두는 희소 색인(sparse index)을 쓰는 경우가 많다. 이 설명은 원본에 없던 내용이며 미검증이다.
{% endhint %}

## 4. 약어·용어

| 용어 | 뜻 |
|---|---|
| ISAM | Indexed Sequential Access Method. 색인 순차 접근 방식 |
| 색인 (Index) | 키 값과 레코드 위치를 대응시킨 자료 구조 |
| 오프셋 (Offset) | 파일 시작에서 레코드까지의 거리(바이트 수) |
| 압축 (Compaction) | 삭제 표시된 공간을 정리해 파일을 재구성하는 작업 |
| 해시 (Hash) | 키 값을 계산해 저장 위치를 정하는 방식 |
