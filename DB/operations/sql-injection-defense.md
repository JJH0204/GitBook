| 항목 | 내용 |
|---|---|

| 유형 | D&O (개념) + 예제 |
| 목적 | SQL 인젝션이 생기는 원인과 데이터베이스·응용 양쪽의 방어 방법을 설명한다 |
| 작성 | 생성형 AI 초안 (사람 검토 전) |

## 1. 목적

SQL 인젝션은 사용자 입력이 SQL 문장의 구조로 해석될 때 생긴다. 점검 흐름은 DB-ASG-001-DO에서 다룬다. 이 문서는 막는 쪽, 곧 코드와 DB 설정에 집중한다.

## 2. 구성 요소

### 2.1 원인

입력값을 문자열로 이어 붙여 SQL을 만들면 입력 안의 따옴표가 문장 구조를 바꾼다.

```python
name = "' OR '1'='1"
sql = "select * from u where name='%s'" % name
# 만들어진 문장: select * from u where name='' OR '1'='1'
# 조건이 항상 참이 되어 모든 행이 대상이 된다
```

### 2.2 방어 방법

| 방어 | 내용 | 효과 |
|---|---|---|
| 매개변수화 질의(바인딩) | SQL 문장과 값을 따로 DBMS에 보낸다. 값은 문장 구조가 되지 못한다 | 근본 해결. 가장 먼저 적용한다 |
| 최소 권한 | 응용 계정에 필요한 테이블과 명령만 `GRANT`한다(DB-SQL-004-REF) | 뚫려도 피해를 줄인다 |
| 식별자 허용 목록 | 테이블·열 이름, 정렬 방향은 바인딩할 수 없으므로 코드의 고정 목록과 대조한다 | 바인딩이 안 되는 자리 보호 |
| 오류 메시지 숨김 | DB 오류 원문을 사용자 화면에 보이지 않는다 | 구조 노출 방지 |
| 입력 검증 | 길이, 형식, 범위를 확인한다 | 보조 수단. 단독으로 쓰지 않는다 |

### 2.3 매개변수화 질의 예

```python
cur.execute("select * from u where name=?", (name,))
```

같은 입력 `' OR '1'='1`을 넣으면 이름이 그 문자열인 행을 찾으므로 0행이 나온다. 이름이 `kim`이면 `kim` 행 한 개가 나온다. 자리 표시자 모양은 라이브러리마다 다르다(`?`, `%s`, `:name` 등).

{% hint style="warning" %}
CAUTION: `%`나 `format`으로 만든 문자열을 `execute`에 넘기면 바인딩이 아니다. 값은 반드시 `execute`의 둘째 인자로 넘긴다.
{% endhint %}

### 2.4 최소 권한 계정 예

```sql
CREATE USER 'app'@'localhost' IDENTIFIED BY '<비밀번호>';
GRANT SELECT, INSERT, UPDATE ON shop.* TO 'app'@'localhost';
```

`DROP`, `ALTER`, `GRANT OPTION` 같은 권한은 주지 않는다. 계정 관리 절차는 DB-OPS-004-MP를 따른다.

## 3. 동작 원리

| 방식 | DBMS가 받는 것 | 입력의 지위 |
|---|---|---|
| 문자열 이어 붙임 | 완성된 SQL 한 덩어리 | 문장 구조의 일부가 될 수 있다 |
| 매개변수 바인딩 | SQL 문장 + 값 목록 | 항상 값으로만 쓰인다 |

## 4. 탐지

| 방법 | 내용 |
|---|---|
| 코드 검토 | SQL을 만드는 코드에서 문자열 결합과 서식 지정을 찾는다 |
| 로그 | DB 오류 로그에서 구문 오류가 반복되는지 본다 |
| 점검 도구 | 승인된 환경에서만 취약점 점검 도구를 쓴다 |

## 5. 약어·용어

| 용어 | 뜻 |
|---|---|
| 바인딩(binding) | SQL 문장의 자리 표시자에 값을 따로 채우는 것 |
| 최소 권한 | 업무에 꼭 필요한 권한만 주는 원칙 |
| 허용 목록 | 정해진 값만 통과시키는 검증 방식 |
