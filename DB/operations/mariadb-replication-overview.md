# [생성형 AI] 복제와 고가용성 개요

## 작업 식별

| 항목 | 내용 |
|---|---|
| Task ID | DB-OPS-009-DO |
| 유형 | D&O (개념) |
| 목적 | 복제의 구조와 용도, 비동기 복제의 한계, 고가용성과 백업의 차이를 이해한다 |
| 작성 | 생성형 AI 초안 (사람 검토 전) |
| 확인 상태 | 미검증 (개념 설명이며 이 환경에서 복제를 구성하거나 실행하지 않았다. 구성 절차는 쓰지 않았다) |
| 개정 | R1 (2026-11-19) |

## 1. 목적

복제(replication)는 한 서버의 변경을 다른 서버가 따라 적용해 같은 데이터를 유지하는 방식이다. 읽기 부하를 나누거나 서버 장애에 대비할 때 쓴다.

## 2. 구성 요소

| 구성 | 역할 |
|---|---|
| 프라이머리(primary, 원본) | 쓰기를 받고 변경을 이진 로그에 기록한다(DB-OPS-008-DO) |
| 레플리카(replica, 복제본) | 프라이머리의 이진 로그를 받아 같은 순서로 적용한다. 과거 문서에는 master/slave라는 용어가 쓰인다 |
| 릴레이 로그 | 레플리카가 받아 둔 변경 기록. 여기서 읽어 적용한다 |
| 복제 지연 | 프라이머리의 변경이 레플리카에 반영되기까지의 시간 차이 |

## 3. 동작 원리

| 순서 | 동작 |
|---|---|
| 1 | 응용 프로그램이 프라이머리에 변경을 쓰고 커밋한다 |
| 2 | 프라이머리가 이진 로그에 기록한다 |
| 3 | 레플리카가 이진 로그를 받아 릴레이 로그에 저장한다 |
| 4 | 레플리카가 릴레이 로그를 읽어 자기 데이터에 적용한다 |

### 3.1 용도와 한계

| 용도 | 설명 |
|---|---|
| 읽기 분산 | 조회를 레플리카로 보내 프라이머리 부하를 줄인다 |
| 장애 대비 | 프라이머리가 멈추면 레플리카를 새 프라이머리로 승격한다 |
| 백업 부하 분리 | 레플리카에서 백업을 받아 프라이머리 성능 영향을 줄인다 |

| 한계 | 설명 |
|---|---|
| 비동기 복제의 데이터 손실 | 기본 복제는 비동기라 프라이머리가 갑자기 멈추면 아직 전달되지 않은 마지막 변경이 사라질 수 있다 |
| 읽기 불일치 | 복제 지연 때문에 방금 쓴 값이 레플리카에서 조회되지 않을 수 있다 |
| 승격은 자동이 아님 | 별도 도구나 절차 없이는 사람이 전환해야 한다 |

{% hint style="warning" %}
CAUTION: 복제는 백업이 아니다. 프라이머리에서 `DROP TABLE`이나 잘못된 `DELETE`를 실행하면 그 변경도 레플리카에 그대로 복제된다. 실수 복구에는 논리 백업(DB-OPS-006-MP)과 이진 로그 시점 복구(DB-OPS-008-DO)가 따로 필요하다.
{% endhint %}

## 4. 약어·용어

| 용어 | 뜻 |
|---|---|
| 고가용성(HA) | 일부 구성 요소가 고장나도 서비스가 계속되는 성질 |
| 비동기 복제 | 프라이머리가 레플리카의 적용을 기다리지 않고 커밋하는 방식 |
| 승격 | 레플리카를 새 프라이머리로 바꾸는 일 |
