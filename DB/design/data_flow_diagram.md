## 1. 목적

데이터 흐름도(DFD, Data Flow Diagram)는 시스템에서 데이터가 어떻게 흐르고 변환되는지 그리는 다이어그램이다. 분석·설계 단계에서 데이터의 흐름과 프로세스를 문서화할 때 쓴다.

DFD의 특징은 다음과 같다.

| 번호 | 특징 | 설명 |
|---|---|---|
| 1 | 데이터 흐름 중심 | 데이터의 입력, 처리, 저장, 출력에 초점을 둔다. 프로세스 내부 로직은 표현하지 않는다 |
| 2 | 가시성 | 프로세스 간 데이터 흐름을 한눈에 보고 중복되거나 비효율적인 흐름을 찾을 수 있다 |
| 3 | 계층적 상세화 | 레벨 0, 1, 2 순서로 점점 세분화한다 |
| 4 | 입출력 관계 강조 | 사용자 입력이 어떤 처리를 거쳐 출력되는지 보여 준다 |

## 2. 구성 요소

| 구성 요소 | 기호 | 설명 |
|---|---|---|
| 프로세스(Process) | ○ | 데이터를 처리하는 기능 |
| 데이터 흐름(Data Flow) | → | 데이터가 이동하는 경로. 흐름마다 데이터 이름을 붙인다 |
| 외부 개체(External Entity) | ▭ | 시스템과 데이터를 주고받는 외부 요소(사용자, 외부 시스템 등) |
| 데이터 저장소(Data Store) | ═ (평행선 두 줄) | 데이터를 저장하는 장소(DB, 파일 등) |

{% hint style="info" %}
NOTE: 기호는 표기법에 따라 다르다. 위 표는 Yourdon/DeMarco 표기다. Gane-Sarson 표기는 프로세스를 둥근 사각형, 저장소를 한쪽이 열린 사각형으로 그린다.
{% endhint %}

## 3. 동작 원리

### 레벨

DFD는 상위 레벨에서 세부 레벨로 상세화한다. 이 문서는 전체 시스템을 프로세스 하나로 그린 컨텍스트 다이어그램을 레벨 0으로 부른다.

{% hint style="info" %}
NOTE: 교재에 따라 컨텍스트 다이어그램과 레벨 0을 구분하고, 컨텍스트 다이어그램을 세분화한 첫 도면을 레벨 0이라고 부르기도 한다.
{% endhint %}

| 레벨 | 내용 | 예시(텍스트 표기) |
|---|---|---|
| 0 (컨텍스트 다이어그램) | 전체 시스템을 프로세스 하나로 그리고 외부 개체와의 흐름만 보인다 | `[사용자] → (인터넷 쇼핑몰 시스템) → [배송 업체]` |
| 1 | 레벨 0의 프로세스를 여러 세부 프로세스로 나눈다 | `[사용자] → (상품 선택) → (주문 처리) → (결제) → (배송 요청) → [배송 업체]` |
| 2 | 레벨 1의 프로세스를 더 나누고 데이터 저장소를 추가한다 | `(주문 처리) → ‖주문 DB‖`, `‖재고 DB‖ → (재고 확인)` |

* 레벨 0 예시에서 사용자는 주문 정보를 입력하고, 시스템은 배송 업체에 배송 정보를 전달한다.
* 레벨 1 예시는 쇼핑몰 시스템을 상품 선택, 주문 처리, 결제, 배송 요청의 4개 프로세스로 나눈 것이다.
* 레벨 2 예시에서 `‖ ‖`는 데이터 저장소를 뜻한다. 주문 정보를 저장하고 재고를 확인한 뒤 결제로 넘어간다.

### 작성 규칙

| 번호 | 규칙 |
|---|---|
| 1 | 각 프로세스는 입력 흐름과 출력 흐름을 최소 하나씩 가진다 |
| 2 | 데이터 흐름은 화살표 방향이 있다. 양방향 교환은 두 개의 흐름으로 따로 그린다 |
| 3 | 프로세스는 데이터 저장소와 직접 연결할 수 있다 |
| 4 | 외부 개체끼리는 직접 연결하지 않는다 |
| 5 | 데이터 저장소끼리, 데이터 저장소와 외부 개체는 직접 연결하지 않고 프로세스를 거친다 |

### 장단점

| 장점 | 단점 |
|---|---|
| 시스템의 흐름을 쉽게 이해할 수 있다 | 너무 세부적으로 나누면 복잡해진다 |
| 기능별 분석이 가능해 유지보수가 쉽다 | 프로세스 내부 로직을 표현하지 못한다 |
| 데이터 흐름을 최적화할 수 있다 | 대규모 시스템에서는 관리가 어렵다 |
