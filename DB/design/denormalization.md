# [생성형 AI] 반정규화 (Denormalization)

## 작업 식별

| 항목 | 내용 |
|---|---|
| Task ID | DB-DSN-009-DO |
| 유형 | D&O (개념) |
| 목적 | 정규화한 설계를 성능 때문에 일부러 되돌리는 반정규화의 방법, 대가, 판단 순서를 이해한다 |
| 작성 | 생성형 AI 초안 (사람 검토 전) |
| 확인 상태 | 미검증 (설계 개념 설명이며 이 환경에서 성능을 측정하지 않았다) |
| 개정 | R1 (2026-11-19) |

## 1. 목적

정규화(DB-DSN-006-DO)는 중복을 없애 이상 현상을 막지만 조회에 조인이 늘어난다. 반정규화는 조회 성능을 위해 중복이나 파생 값을 의도적으로 넣는 일이다. 물리적 설계 단계(DB-DSN-007-DO)에서 하며, 정규화를 안 한 것과는 다르다. 정규화를 먼저 끝낸 뒤 근거를 갖고 되돌린다.

## 2. 구성 요소

| 기법 | 내용 | 예 |
|---|---|---|
| 중복 열 추가 | 자주 조인하는 값을 자식 테이블에 복사한다 | 주문 테이블에 `고객명`을 함께 저장 |
| 파생 열 추가 | 계산 결과를 열로 저장한다 | 주문 테이블에 `총액`, 게시글에 `댓글 수` |
| 테이블 병합 | 1:1 관계 테이블을 하나로 합친다 | 회원과 회원 상세 |
| 테이블 분할 | 자주 쓰는 열과 드문 열을 나눈다 | 큰 본문 열을 별도 테이블로 |
| 요약 테이블 | 집계 결과를 미리 저장한다 | 일별 매출 합계 테이블 |

## 3. 동작 원리와 대가

| 항목 | 내용 |
|---|---|
| 얻는 것 | 조인과 집계가 줄어 조회가 빨라진다 |
| 잃는 것 | 같은 값이 여러 곳에 있어 갱신 이상이 생길 수 있다. 원본을 고칠 때 복사본도 고치지 않으면 값이 어긋난다 |
| 추가 비용 | 복사본을 맞추는 코드(응용 코드, 트리거 DB-SQL-016-DO, 배치)와 저장 공간이 든다 |

### 3.1 판단 순서

| 순서 | 할 일 |
|---|---|
| 1 | 느린 질의를 특정한다(실행 계획 DB-STO-002-DO) |
| 2 | 인덱스, 질의 재작성, 뷰(DB-SQL-011-DO)로 먼저 해결해 본다 |
| 3 | 그래도 부족할 때만 반정규화를 고른다 |
| 4 | 어긋난 값을 맞추는 방법과 점검 질의를 함께 정한다 |

{% hint style="warning" %}
CAUTION: 반정규화한 열은 데이터가 바뀔 때마다 동기화 규칙이 필요하다. 규칙 없이 복사하면 시간이 지나 값이 서로 달라진다.
{% endhint %}

## 4. 약어·용어

| 용어 | 뜻 |
|---|---|
| 파생 열 | 다른 열에서 계산할 수 있는 값을 저장한 열 |
| 갱신 이상 | 중복된 값 중 일부만 고쳐 불일치가 생기는 현상 |
