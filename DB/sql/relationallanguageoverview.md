## 1. 목적

관계 언어는 관계형 데이터베이스(RDB, Relational Database)에서 데이터를 정의하고 검색하고 조작하는 언어의 이론적 틀이다. 관계 언어는 두 가지다. 관계 대수는 "어떻게 검색할 것인가"를, 관계 해석은 "무엇을 검색할 것인가"를 기술한다. SQL은 두 이론을 바탕으로 만들어진 실용 언어다.

## 2. 구성 요소

### 2.1 관계 언어의 종류

| 번호 | 관계 언어 | 설명 | 특징 |
|---|---|---|---|
| 1 | 관계 대수 (Relational Algebra) | 수학적 연산자를 릴레이션에 차례로 적용해 결과를 얻는다 | 절차적 |
| 2 | 관계 해석 (Relational Calculus) | 논리식(술어)으로 원하는 데이터의 조건을 기술한다 | 비절차적 |

관계 해석은 변수의 범위에 따라 튜플 관계 해석과 도메인 관계 해석으로 나뉜다.

### 2.2 관계 대수와 관계 해석 비교

| 구분 | 관계 대수 | 관계 해석 |
|---|---|---|
| 언어 유형 | 절차적 | 비절차적 |
| 조회 방식 | 어떻게(How) 조회할지 정의한다 | 무엇(What)을 조회할지 정의한다 |
| 표현 방식 | 연산자(σ, π, ⋈ 등)를 쓴다 | 논리식(∃, ∀ 등)을 쓴다 |
| 가독성 | 연산 절차가 명확하다 | 조건을 논리적으로 표현하기 쉽다 |
| SQL과의 관계 | SQL의 내부 연산 방식과 유사하다 | SQL의 질의 표현 방식과 유사하다 |

{% hint style="info" %}
NOTE: 두 언어는 표현 능력이 같다(관계적 완전성). 관계 대수로 쓸 수 있는 질의는 관계 해석으로도 쓸 수 있고, 그 반대도 같다. 이 설명은 미검증이다.
{% endhint %}

### 2.3 관계 대수 연산자

| 번호 | 연산자 | 기호 | 분류 | 의미 | SQL 대응 |
|---|---|---|---|---|---|
| 1 | 선택(Select) | σ | 순수 관계 연산 | 조건을 만족하는 튜플(행)을 고른다 | `WHERE` |
| 2 | 프로젝트(Project) | π | 순수 관계 연산 | 지정한 속성(열)만 고른다 | `SELECT`의 열 목록 |
| 3 | 조인(Join) | ⋈ | 순수 관계 연산 | 공통 속성 값이 같은 튜플을 결합한다 | `JOIN` |
| 4 | 디비전(Division) | ÷ | 순수 관계 연산 | 한 릴레이션의 모든 값과 짝을 이루는 튜플을 찾는다 | 직접 대응 없음 (`NOT EXISTS`로 표현) |
| 5 | 합집합(Union) | ∪ | 일반 집합 연산 | 두 릴레이션의 튜플을 합한다 | `UNION` |
| 6 | 교집합(Intersection) | ∩ | 일반 집합 연산 | 두 릴레이션에 모두 있는 튜플을 고른다 | `INTERSECT` |
| 7 | 차집합(Difference) | − | 일반 집합 연산 | 앞 릴레이션에만 있는 튜플을 고른다 | `EXCEPT` (일부 DBMS는 `MINUS`) |
| 8 | 카티션 프로덕트(Cartesian Product) | × | 일반 집합 연산 | 두 릴레이션 튜플의 모든 쌍을 만든다 | `CROSS JOIN` |

{% hint style="info" %}
NOTE: SQL 대응은 개념적 대응이다. `INTERSECT`와 `EXCEPT`는 DBMS와 버전에 따라 지원 여부가 다르다. 사용할 DBMS 문서에서 확인한다. 이 표는 원본에 없던 내용이며 미검증이다.
{% endhint %}

## 3. 동작 원리

같은 질의("나이가 30 초과인 고객의 이름")를 두 언어로 표현한 예다.

| 언어 | 표현 |
|---|---|
| 관계 대수 | π<sub>name</sub>(σ<sub>age>30</sub>(Customers)) |
| 관계 해석 | { t.name \| Customers(t) ∧ t.age > 30 } |
| SQL | `SELECT name FROM Customers WHERE age > 30;` |

1. 관계 대수는 Customers에 선택(σ)을 먼저 적용하고, 그 결과에 프로젝트(π)를 적용한다. 연산 순서가 식에 드러난다.
2. 관계 해석은 연산 순서를 쓰지 않고 결과 튜플이 만족할 조건만 쓴다.
3. SQL은 조건을 선언하는 점에서 관계 해석과 닮았고, 실행 시 DBMS가 관계 대수와 비슷한 연산 순서로 바꿔 처리한다.

{% hint style="info" %}
NOTE: SQL의 `SELECT` 키워드는 관계 대수의 선택(σ)이 아니라 프로젝트(π)에 해당한다. 선택(σ)은 `WHERE` 절이다. 원본은 "SELECT 문 = 선택(σ) + 논리적 조건"으로 적어 이 부분을 정정했다. 미검증이다.
{% endhint %}

## 4. 약어·용어

| 용어 | 뜻 |
|---|---|
| RDB | Relational Database. 관계형 데이터베이스 |
| 릴레이션(relation) | 행과 열로 이루어진 표. 테이블에 해당한다 |
| 튜플(tuple) | 릴레이션의 행 |
| 속성(attribute) | 릴레이션의 열 |
| 절차적 언어 | 처리 순서를 사용자가 기술하는 언어 |
| 비절차적 언어 | 원하는 결과만 기술하고 처리 순서는 시스템이 정하는 언어 |
