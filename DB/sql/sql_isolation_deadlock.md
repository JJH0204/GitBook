# [생성형 AI] 트랜잭션 격리 수준과 교착 상태

## 작업 식별

| 항목 | 내용 |
|---|---|
| Task ID | DB-SQL-013-DO |
| 유형 | D&O (개념) |
| 목적 | 동시 실행에서 생기는 이상 현상, 네 격리 수준, 교착 상태와 대응을 설명한다 |
| 작성 | 생성형 AI 초안 (사람 검토 전) |
| 확인 상태 | 미검증 (SQL 표준과 InnoDB의 일반 지식을 정리한 것이며 MariaDB에서 실행해 확인하지 않았다) |
| 개정 | R1 (2026-11-19) |

## 1. 목적

트랜잭션이 동시에 실행되면 서로의 변경을 어느 시점에 볼지 정해야 한다. 격리 수준(isolation level)이 그 범위를 정한다. ACID의 격리성 정의는 DB-SQL-005-REF를 따른다.

## 2. 구성 요소

### 2.1 동시성 이상 현상

| 이상 | 내용 |
|---|---|
| 더티 리드(dirty read) | 다른 트랜잭션이 아직 `COMMIT`하지 않은 변경을 읽는다. 그 트랜잭션이 `ROLLBACK`하면 없던 값을 읽은 셈이 된다 |
| 반복 불가능 읽기(non-repeatable read) | 같은 행을 두 번 읽는 사이에 다른 트랜잭션이 값을 바꿔 확정해 값이 달라진다 |
| 팬텀 리드(phantom read) | 같은 조건으로 두 번 조회하는 사이에 다른 트랜잭션이 행을 추가해 행 수가 달라진다 |

### 2.2 격리 수준과 SQL 표준상 허용 이상

| 격리 수준 | 더티 리드 | 반복 불가능 읽기 | 팬텀 리드 |
|---|---|---|---|
| `READ UNCOMMITTED` | 가능 | 가능 | 가능 |
| `READ COMMITTED` | 방지 | 가능 | 가능 |
| `REPEATABLE READ` | 방지 | 방지 | 가능 |
| `SERIALIZABLE` | 방지 | 방지 | 방지 |

{% hint style="info" %}
NOTE: 위 표는 SQL 표준의 정의다. 실제 DBMS는 구현에 따라 표보다 더 강하게 막기도 한다. InnoDB의 기본 격리 수준은 `REPEATABLE READ`다. 수준이 높을수록 이상은 줄고 동시 처리량은 떨어진다.
{% endhint %}

### 2.3 설정 문법

| 목적 | 명령 |
|---|---|
| 다음 세션 전체의 수준 변경 | `SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED;` |
| 다음 트랜잭션 하나만 변경 | `SET TRANSACTION ISOLATION LEVEL SERIALIZABLE;` (`START TRANSACTION` 전에 실행한다) |
| 현재 수준 확인 | `SELECT @@tx_isolation;` (새 MariaDB 버전은 `@@transaction_isolation`. 버전별 이름은 확인 필요) |

## 3. 동작 원리

### 3.1 교착 상태(deadlock)

두 트랜잭션이 서로가 가진 잠금(lock)을 기다리면 둘 다 진행하지 못한다.

| 순서 | 트랜잭션 1 | 트랜잭션 2 |
|---|---|---|
| 1 | 행 A를 갱신한다(A 잠금) | 행 B를 갱신한다(B 잠금) |
| 2 | 행 B를 갱신하려 한다. 트랜잭션 2를 기다린다 | 행 A를 갱신하려 한다. 트랜잭션 1을 기다린다 |
| 3 | 서로 기다리는 순환이 생긴다 | |

InnoDB는 순환을 감지해 한 트랜잭션을 `ROLLBACK`하고 오류(오류 번호 1213)를 돌려준다. 응용은 이 오류를 받으면 트랜잭션 전체를 다시 시도한다. 가장 최근 교착 상태는 `SHOW ENGINE INNODB STATUS;` 출력에서 볼 수 있다.

### 3.2 줄이는 방법

| 방법 | 설명 |
|---|---|
| 잠금 순서 통일 | 모든 트랜잭션이 같은 순서(예: 행 번호 오름차순)로 행을 갱신한다 |
| 트랜잭션을 짧게 | 사용자 입력을 기다리는 동안 트랜잭션을 열어 두지 않는다 |
| 인덱스 사용 | 조건에 맞는 인덱스가 없으면 더 많은 행을 잠글 수 있다 |
| 재시도 | 오류 1213을 받으면 트랜잭션을 처음부터 다시 실행한다 |

## 4. 약어·용어

| 용어 | 뜻 |
|---|---|
| 잠금(lock) | 한 트랜잭션이 데이터를 쓰는 동안 다른 접근을 막는 장치 |
| MVCC | 다중 버전 동시성 제어. 읽기가 쓰기를 막지 않도록 이전 버전 데이터를 읽게 하는 방식. InnoDB가 쓴다 |
