## 1. 목적

뷰(view)는 저장된 `SELECT` 문에 이름을 붙인 가상 테이블이다. 뷰 자체는 행을 따로 저장하지 않고, 조회할 때마다 정의된 질의를 실행한다. `CREATE VIEW` 문법 한 줄은 DB-SQL-002-REF, 설계 관점은 DB-DSN-007-DO에 있다.

## 2. 구성 요소

| 항목 | 문법 | 설명 |
|---|---|---|
| 생성 | `CREATE VIEW <뷰 이름> AS SELECT ...;` | 질의를 뷰로 저장한다 |
| 조회 | `SELECT * FROM <뷰 이름>;` | 일반 테이블처럼 쓴다 |
| 삭제 | `DROP VIEW <뷰 이름>;` | 뷰 정의만 지운다. 원본 테이블의 데이터는 그대로다 |

### 2.1 예제

```sql
-- emp(id, name, dept_id, salary), dept(id, name)는 DB-SQL-009-DO와 같다
CREATE VIEW dev_emp AS
  SELECT id, name, salary FROM emp WHERE dept_id = 1;

SELECT * FROM dev_emp;
```

결과는 `(1,A,500)`, `(2,B,400)` 두 행이다. 개발 부서 사원을 `emp`에 한 행 더 넣고 다시 조회하면 새 행이 바로 나온다. 뷰가 원본 테이블을 그때그때 읽기 때문이다.

```sql
CREATE VIEW dept_count AS
  SELECT d.name AS dname, COUNT(e.id) AS n
  FROM dept d LEFT JOIN emp e ON e.dept_id = d.id GROUP BY d.id;
SELECT * FROM dept_count;
```

결과는 `(개발,3)`, `(영업,1)`, `(인사,0)`이다(사원 E가 개발 부서에 추가된 상태). 복잡한 조인과 집계를 뷰 하나로 감춘다.

## 3. 동작 원리

| 순서 | 처리 |
|---|---|
| 1 | `CREATE VIEW`가 뷰 이름과 질의 정의를 DBMS의 카탈로그에 저장한다 |
| 2 | 뷰를 조회하면 DBMS가 뷰 정의를 바깥 질의와 합쳐 원본 테이블에 대한 질의로 푼다 |
| 3 | 원본 테이블의 현재 데이터로 결과를 만든다 |

### 3.1 쓰는 이유

| 이유 | 내용 |
|---|---|
| 단순화 | 반복하는 복잡한 질의를 이름 하나로 줄인다 |
| 보안 | 일부 열과 행만 보이는 뷰에만 `SELECT` 권한을 줘 나머지를 숨긴다(DB-SQL-004-REF) |
| 논리적 독립성 | 테이블 구조를 바꿔도 뷰가 같은 모양을 유지하면 응용 질의를 고치지 않는다(DB-OVW-002-DO) |

### 3.2 한계

{% hint style="warning" %}
CAUTION: 일반 뷰는 조회할 때마다 질의를 실행하므로 성능이 좋아지지 않는다. 뷰를 통한 `INSERT`, `UPDATE`, `DELETE`는 집계·조인·`DISTINCT`가 들어간 뷰에서 대개 불가능하다. 가능 조건은 DBMS 문서를 확인한다.
{% endhint %}

## 4. 약어·용어

| 용어 | 뜻 |
|---|---|
| 가상 테이블 | 데이터를 저장하지 않고 질의로 정의한 테이블 |
| 카탈로그 | DBMS가 테이블, 뷰, 사용자 정보를 저장하는 내부 정보 |
