## 1. 목적

물리적 데이터 독립성(physical data independence)은 저장 방식과 접근 경로를 바꿔도 논리적 스키마(데이터의 논리적 구조)와 응용 프로그램의 질의가 바뀌지 않는 성질이다. 인덱스, 파일 구조, 클러스터링, 파티셔닝 같은 물리적 요소를 바꿔도 응용 프로그램을 고치지 않게 해, 성능 튜닝과 응용 개발을 분리한다.

## 2. 구성 요소

### 2.1 3단계 스키마 구조

| 번호 | 스키마 | 보는 사람 | 내용 |
|---|---|---|---|
| 1 | 외부 스키마 | 사용자, 응용 프로그램 | 각자 필요한 부분만 본 데이터 구조 |
| 2 | 개념 스키마 | 전체 조직, DBA | 데이터베이스 전체의 논리적 구조 |
| 3 | 내부 스키마 | DBMS, DBA | 파일, 인덱스, 저장 형식 같은 물리적 구조 |

| 번호 | 독립성 | 바뀌는 계층 | 영향받지 않는 계층 |
|---|---|---|---|
| 1 | 논리적 데이터 독립성 | 개념 스키마 (속성 추가·삭제 등) | 외부 스키마, 응용 프로그램 |
| 2 | 물리적 데이터 독립성 | 내부 스키마 (저장·접근 방식) | 개념 스키마 |

{% hint style="info" %}
NOTE: 3단계 스키마 구조(ANSI/SPARC)는 원본에 없던 내용이다. 두 독립성의 차이를 보이려고 추가했다. 확인 필요.
{% endhint %}

### 2.2 물리적 변경 예시

| 번호 | 변경 | 논리적 스키마·질의에 미치는 영향 |
|---|---|---|
| 1 | 인덱스 추가·삭제 | 질의문과 응용 코드는 그대로다. 결과도 같고 속도만 달라진다 |
| 2 | 저장 형식·정렬(클러스터링) 변경 | 릴레이션과 속성 같은 논리적 관계는 그대로다 |
| 3 | DBMS 내장 파티셔닝 방식 변경 | 질의 인터페이스는 그대로일 수 있다 |
| 4 | 응용 수준 샤딩 | 접속 대상이 나뉘므로 응용 코드가 바뀔 수 있다. 독립성이 깨진다 |

### 2.3 장점과 한계

| 구분 | 내용 |
|---|---|
| 장점 | 응용과 저장 최적화가 분리돼 유지보수 비용이 줄어든다 |
| 장점 | 응용 중단 없이 성능을 개선할 수 있다 |
| 장점 | DBA가 내부 구조를 자유롭게 튜닝할 수 있다 |
| 한계 | 완전한 독립성은 어렵다. 물리적 변경이 성능이나 동작에 영향을 줘 응용 수준의 조정이 필요할 수 있다 |
| 한계 | 정규화 수준 같은 논리적 설계와 물리적 설계가 서로 영향을 주므로 함께 검토한다 |

## 3. 동작 원리

DBMS는 아래 순서로 물리적 변경을 응용으로부터 숨긴다.

1. 응용 프로그램이 논리적 스키마 기준으로 SQL을 보낸다. 저장 위치나 접근 경로는 SQL에 쓰지 않는다.
2. 쿼리 옵티마이저가 인덱스 스캔, 테이블 스캔 같은 접근 경로 중 최적의 실행 계획을 고른다.
3. DBA가 인덱스·파티션·저장 형식(압축, 블록 크기)을 바꾸면 옵티마이저가 새 구조에 맞는 실행 계획을 다시 고른다.
4. 응용이 보내는 SQL과 결과는 그대로이므로 응용 코드는 바뀌지 않는다.

## 4. 자주 묻는 질문

| 질문 | 답 |
|---|---|
| 물리적 데이터 독립성은 완전히 보장되는가 | 완전한 보장은 어렵다. 대부분의 물리적 변경은 논리적 스키마와 응용에 직접 영향을 주지 않는다. 정렬 방식 변경으로 질의 성능이 크게 달라지는 경우처럼 응용 수준의 주의가 필요한 변경도 있다 |
| DBA는 무엇을 해야 하는가 | 옵티마이저 설정, 인덱스 설계, 파티셔닝 전략, 저장 형식을 관리하며 논리적 스키마와 응용에 미치는 영향을 최소화한다 |
| 성능과 충돌하는가 | 항상 충돌하지는 않는다. 성능 최적화로 물리적 변경이 필요하면 예상치 못한 부작용이 생길 수 있으므로 테스트와 모니터링이 필요하다 |

## 5. 약어·용어

| 용어 | 뜻 |
|---|---|
| 스키마(schema) | 데이터 구조의 정의 |
| DBA | Database Administrator. 데이터베이스 관리자 |
| 옵티마이저(optimizer) | 질의의 실행 계획을 고르는 DBMS 구성 요소 |
| 파티셔닝(partitioning) | 큰 테이블을 기준에 따라 나눠 저장하는 방식 |
| 샤딩(sharding) | 데이터를 여러 서버에 나눠 저장하는 방식 |
