## 1. 목적

업로드되는 파일을 검증하지 않으면 공격자가 서버에서 실행되는 형식의 파일을 올릴 수 있다. 이 문서는 DVWA의 수준별 검증 방식과 그 한계를 설명한다.

## 2. 수준별 관찰

| 수준 | 검증 방식 | 관찰 | 한계 |
|---|---|---|---|
| low | 검증 없음 | 임의 파일이 업로드된다 | 서버 측 검증이 없다 |
| medium | MIME 타입(JPEG, PNG)만 확인한다 | 확장자가 바뀌어도 파일 내용은 유지된다. 업로드만으로는 실행되지 않는다. 프록시로 요청의 파일명을 바꾸면 서버에 다른 확장자로 저장된다 | MIME 타입은 클라이언트가 보내는 값이라 속일 수 있다 |
| high | 확장자(`uploaded_ext`)를 확인한다 | 프록시에서 파일명을 바꿔도 업로드되지 않는다 | 이미지 형식의 메타데이터에 내용을 넣는 우회가 가능한지 원본이 의문으로 남겼다(미검증) |
| impossible | 1회성 사용자 토큰을 쓴다 | 우회가 어렵다 | 업로드 외 다른 취약점과 결합하면 공략 가능성이 남는다 |

## 3. 관찰 과정 (medium, 프록시 사용)

1. 업로드 요청을 프록시에서 가로챈다(intercept).
2. 요청 안의 파일명을 바꾼다.
3. 요청을 전달한다. → 결과: 바뀐 파일명으로 저장된다. 업로드 타입은 MIME 헤더로 정해지므로 사용자가 확장자만 맞추는 것을 서버가 구별하지 못한다.

## 4. 탐지·방어 (일부 미검증)

| 방어 | 설명 |
|---|---|
| 서버 측 검증 | MIME 헤더를 믿지 않고 확장자 허용 목록과 파일 시그니처(매직 넘버)를 함께 검사한다 |
| 재인코딩 | 이미지를 서버에서 다시 인코딩해 메타데이터와 덧붙은 데이터를 제거한다 |
| 저장 위치 | 웹 루트 밖에 저장하고, 업로드 디렉터리에서는 스크립트 실행을 끈다 |
| 파일명 | 서버가 무작위 이름을 정하고 원래 이름을 쓰지 않는다 |
| 크기 제한 | 크기와 개수를 제한한다 |
| 토큰 | 1회성 토큰으로 요청 위조를 막는다 |
| 로그 | 이미지 업로드인데 스크립트 확장자·이중 확장자가 있거나, 업로드 폴더에 새 실행 파일이 생기면 흔적이다 |

## 5. 약어·용어

| 용어 | 뜻 |
|---|---|
| MIME | 콘텐츠 형식을 알리는 값. 클라이언트가 보낸다 |
| 메타데이터 | 이미지 파일에 포함된 부가 정보(EXIF 등) |
| 매직 넘버 | 파일 형식을 나타내는 앞부분 바이트 |
