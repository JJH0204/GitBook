## 1. 목적

캡차는 사람과 자동화 프로그램을 구별한다. 검증 결과를 클라이언트가 전달하는 값에 의존하거나 검증 단계를 건너뛸 수 있으면 캡차가 의미를 잃는다.

## 2. 탐지·방어 (미검증)

| 방어 | 설명 |
|---|---|
| 서버 측 검증 | 캡차 응답을 서버가 캡차 서비스에 직접 확인한다 |
| 단계 강제 | 검증 통과 여부를 서버 세션에 저장하고 다음 단계에서 다시 확인한다 |
| 1회성 | 한 번 쓴 캡차 응답은 재사용을 거부한다 |
| 토큰 | 상태 변경 요청에는 CSRF 토큰을 함께 쓴다([CSRF](csrf.md)) |

## 3. 참조

* OWASP, Testing for Captcha (OWASP-AT-012). 원본에 외부 리다이렉트 링크로 있던 문서이며 현재 주소는 확인 필요다.
