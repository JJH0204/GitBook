## 1. 목적

CSRF(Cross-Site Request Forgery, 요청 위조)는 공격자가 권한이 없는 상태에서 로그인된 사용자의 브라우저가 의도하지 않은 요청을 서버에 보내게 하는 공격이다. 서버는 쿠키가 유효하면 정상 요청으로 처리한다.

## 2. 구성 요소

| 요소 | 역할 |
|---|---|
| 피해자 | 대상 서비스에 로그인한 상태의 사용자 |
| 위조 요청 | 비밀번호 변경 같은 상태 변경 요청 |
| 전달 수단 | 이메일, 게시글 등에 넣은 링크 또는 이미지 태그 |
| 취약 조건 | 요청이 쿠키만으로 인증되고, 요청 출처를 확인하는 값이 없다 |

## 3. 동작 원리

1. 피해자가 DVWA에 로그인한다. 브라우저에 세션 쿠키가 있다.
2. 피해자가 위조 요청이 담긴 메일을 연다.
3. 브라우저가 쿠키를 자동으로 붙여 `<DVWA IP>`의 비밀번호 변경 주소로 요청을 보낸다.
4. 비밀번호 변경 기능이 GET 방식이고 확인 값이 없으면 서버가 비밀번호를 바꾼다.

원본이 관찰한 점은 다음과 같다.

* 비밀번호 변경이 GET 파라미터(`password_new`, `password_conf`)로 처리된다.
* 이미지 태그의 `src`에 요청 주소를 넣으면 메일을 여는 것만으로 요청이 나간다.
* 이미지 크기를 0으로 하면 화면에 보이지 않는다.
* 피해자가 나중에 DVWA에 로그인하면 공격자가 정한 비밀번호로 바뀌어 있다.

## 4. 보안 수준별 차이

| 수준 | 방어 | 평가 |
|---|---|---|
| low | 보안 코드가 없다. 입력을 그대로 신뢰해 처리한다 | 위조 가능 |
| medium | 요청 헤더의 출처에 서버 도메인이 포함되는지 대소문자 구분 없이 검사한다 | 도메인 포함 여부만 보므로 의미가 작다 |
| high | 사용자 토큰을 요구한다. 입력값은 `mysql_real_escape_string`으로 처리한다 | 토큰 때문에 위조가 거의 불가능하다 |

## 5. 탐지·방어 (일부 미검증)

| 방어 | 설명 |
|---|---|
| CSRF 토큰 | 요청마다 예측할 수 없는 1회성 값을 폼에 넣고 서버가 세션과 대조한다 |
| 상태 변경은 POST | GET으로 상태를 바꾸지 않는다 |
| 현재 비밀번호 재입력 | 비밀번호 변경 시 기존 비밀번호를 요구한다 |
| SameSite 쿠키 | `SameSite=Lax` 또는 `Strict`로 다른 사이트에서 온 요청에 쿠키를 붙이지 않는다 |
| Origin/Referer 검증 | 출처가 자기 도메인과 정확히 일치하는지 확인한다(부분 포함 검사는 금지) |
| 로그 | 외부 Referer에서 온 상태 변경 요청, 연속된 비밀번호 변경이 흔적이다 |

## 6. 약어·용어

| 용어 | 뜻 |
|---|---|
| CSRF | 요청 위조 |
| 토큰 | 서버가 발급하는 1회성 검증 값 |
| SameSite | 쿠키를 다른 사이트의 요청에 보낼지 정하는 속성 |
