## 1. 목적

워게임이나 CTF 문제에서 플래그를 찾는 과정을 정리한 글을 라이트업(write-up)이라 한다. 대회는 문제를 정당하게 풀었는지 확인하려고 라이트업을 요구하기도 한다. 대회 종료 후 라이트업을 공유하기도 한다. 직접 푼 문제를 라이트업으로 정리하면 이해가 정확해진다.

## 2. 구성 요소

### 2.1 풀이를 보기 전 점검 항목

풀이를 볼지 고민될 때 아래 항목을 순서대로 확인한다. 풀이자는 문제를 풀 때 이 순서로 진행한다.

| 번호 | 점검 항목 |
|---|---|
| 1 | 주어진 문제가 어떤 프로그램 또는 서비스인지 이해했다 |
| 2 | 취약점(또는 이상한 부분)이 무엇인지 파악했다 |
| 3 | 찾은 취약점을 어떻게 공략할지 구상했다 |
| 4 | 풀이에 필요한 코드나 페이로드를 작성했다 |

1번(문제의 성격 이해)은 스스로 해결한 뒤에 풀이를 보는 것을 권장한다.

## 3. 동작 원리

라이트업은 아래 순서로 쓴다.

1. 문제 이름, 분야, 출처를 적는다.
2. 문제에서 파악한 단서를 적는다.
3. 취약점과 그 원인을 적는다.
4. 접근 방법과 사용한 개념·도구를 적는다.
5. 플래그는 `FLAG{<생략>}`로 대체한다.
6. 방어 방법을 한 줄 덧붙인다.

{% hint style="warning" %}
CAUTION: 진행 중인 대회의 풀이와 플래그는 공개하지 않는다. 종료된 대회여도 플래그 값은 쓰지 않는다.
{% endhint %}

## 4. 약어·용어

| 용어 | 뜻 |
|---|---|
| 라이트업(write-up) | 문제 풀이 과정을 정리한 글 |
| 플래그(flag) | 정답 문자열 |
| 페이로드(payload) | 취약점에 입력하는 데이터 |
