## 1. 증상 (스캔 결과)

| 항목 | 값 |
|---|---|
| 대상 IP | `192.168.56.105` (실습망 사설 주소) |
| 22/tcp (SSH) | OpenSSH 7.2p2 (Ubuntu 4ubuntu2.10) |
| 80/tcp (HTTP) | Apache httpd 2.4.18 (Ubuntu) |
| HTTP 생성기 | WordPress 5.5.1 |
| 운영 체제 | Linux 3.x ~ 4.x (Oracle VirtualBox 환경) |

세 서비스 모두 오래된 버전이다. 알려진 취약점에 노출됐을 가능성이 있다.

## 2. 가능 원인

| 번호 | 서비스 | 원인 | 관련 CVE |
|---|---|---|---|
| 1 | OpenSSH 7.2p2 | 패치되지 않은 구버전 | CVE-2016-6210, CVE-2016-3115 |
| 2 | Apache 2.4.18 | 패치되지 않은 구버전 | CVE-2019-0211, CVE-2017-15715 |
| 3 | WordPress 5.5.1 | 지원이 끝난 구버전 | CVE-2020-28039, CVE-2020-4047 |

## 3. 격리 절차

1. 스캔 결과의 서비스 이름과 버전을 확인한다.
2. 각 버전에 알려진 CVE를 공식 보안 공지에서 조회한다.
3. 배포판이 패치를 백포트했는지 패키지 버전으로 확인한다(Ubuntu는 버전 번호가 같아도 패치가 적용될 수 있다).
4. 실제로 영향받는지 허가받은 실습 환경에서만 검증한다.

## 5. 시정 조치

### 5.1 OpenSSH

1. OpenSSH를 최신 버전으로 업데이트한다.
2. 사용하지 않는 `root` 로그인을 비활성화한다.
3. 키 기반 인증을 켜고 가능하면 비밀번호 인증을 끈다.

### 5.2 Apache

1. Apache를 최신 2.4.x로 업데이트한다.
2. 웹 애플리케이션 방화벽 모듈(`mod_security`)을 적용한다.
3. 불필요한 HTTP 메서드(PUT, DELETE 등)를 제한한다.

### 5.3 WordPress

1. WordPress를 최신 버전으로 업데이트한다.
2. 사용하지 않는 플러그인과 테마를 제거한다.
3. 관리자 비밀번호를 강하게 하고 2단계 인증을 쓴다. 관리자 접근을 제한한다.

### 5.4 추가 설정

1. 방화벽으로 불필요한 포트를 차단한다.
2. Fail2Ban으로 SSH 무차별 대입 공격을 막는다.
3. 정기적으로 패치하고 취약점을 점검한다.
