## 학습 목표

- 패킷트레이서에 장비를 놓고 연결하고, 불빛으로 연결 상태를 읽는다.
- 시스코 장비의 네 가지 모드를 오가며 명령을 입력한다.
- 장비로 들어오는 문 세 개에 잠금을 걸고, PC에서 텔넷으로 직접 두드려 본다.
- enable password와 enable secret의 차이, service password-encryption의 한계를 안다.
- 인터페이스에 주소를 주고, 설정을 저장하고, 설정 텍스트를 커밋한다.

## 목적

설계표에서 본사 영업팀의 게이트웨이를 192.168.10.1로 정했다. 이 주소는 본사 라우터에 붙는다. 이제 라우터를 직접 설정한다.

그런데 주소를 주기 전에 할 일이 있다. 회사의 모든 통신이 지나가는 장비에 아무나 들어와 설정을 바꿀 수 있다면, 1일차 계획서에 적은 "장비 설정의 무결성"은 처음부터 지켜지지 않는다. 네트워크에 연결하기 전에 먼저 잠그는 것이 순서다.

## 1. 오늘의 토폴로지

```
 [Sales-PC1]--+
              +--[HQ-SW1]--Gi0/1 ---- Gi0/0--[HQ-R1]
 [Sales-PC2]--+
```

패킷트레이서에 2911 라우터 한 대(HQ-R1), 2960 스위치 한 대(HQ-SW1), PC 두 대를 놓는다. 장비 이름은 위치와 역할로 짓는다. HQ는 본사, R은 라우터, SW는 스위치다. 4일차에 지사 라우터 BR-R1이 더해진다.

패킷트레이서를 처음 쓴다면 이것만 알면 된다.

| 할 일 | 방법 |
|---|---|
| 장비 놓기 | 아래쪽 장비 상자에서 종류를 고르고 모델을 끌어다 놓는다 |
| 연결하기 | 케이블 상자의 Copper Straight-Through를 고르고, 두 장비를 차례로 눌러 포트를 고른다 |
| 설정하기 | 장비를 누르고 CLI 탭에서 명령을 입력한다. Config 탭은 쓰지 않는다 |
| PC 설정 | PC를 누르고 Desktop 탭에서 IP Configuration, Command Prompt를 쓴다 |

연결선 양 끝의 불빛이 상태를 알려 준다.

| 불빛 | 뜻 |
|---|---|
| 초록 | 통신할 수 있다 |
| 주황 | 스위치가 포트를 준비하는 중이다. 30초쯤 기다리면 초록이 된다 |
| 빨강 | 포트가 꺼져 있거나 연결이 잘못되었다 |

라우터 쪽 불빛은 처음에 빨강이다. 라우터의 포트는 꺼진 채로 시작하기 때문이다. 7번 절에서 켠다. 주황을 기다리기 지루하면 화면 아래의 Fast Forward Time을 누른다.

Config 탭을 쓰지 않는 이유는 명령을 손에 익히기 위해서다. 실제 장비에는 Config 탭이 없고, 시험에도 명령이 나온다.

## 2. 네 가지 모드

```
HQ-R1>              사용자 모드       enable 로 위로
HQ-R1#              관리자 모드       configure terminal 로 위로
HQ-R1(config)#      전역 설정 모드    interface, line 으로 안으로
HQ-R1(config-if)#   세부 설정 모드    exit 는 한 단계 아래로, end 는 관리자 모드로
```

| 모드 | 할 수 있는 일 |
|---|---|
| 사용자 모드 | 몇 가지 확인만 |
| 관리자 모드 (이네이블 모드) | 모든 설정 확인, 저장, 재시작 |
| 전역 설정 모드 | 장비 전체의 설정 (이름, 비밀번호) |
| 세부 설정 모드 | 포트 하나, 회선 하나의 설정 |

관리자 모드에 들어온 사람은 장비의 모든 것을 바꿀 수 있다. 그래서 enable 앞에 잠금이 필요하다.

CLI를 빨리 다루는 요령이 몇 가지 있다.

| 요령 | 쓰는 법 |
|---|---|
| 자동 완성 | 명령을 앞부분만 입력하고 Tab |
| 도움말 | 명령 뒤에 `?`를 입력하면 다음에 올 수 있는 것이 보인다 |
| 줄여 입력 | `conf t`, `sh run`, `int gi0/0` |
| 이전 명령 | 위쪽 화살표 키 |
| 관리자 모드로 바로 | `end` 또는 Ctrl+Z |
| 설정 모드에서 확인 명령 | 앞에 `do`를 붙인다. `do show ip interface brief` |
| 긴 출력 넘기기 | `--More--`에서 Enter는 한 줄, Space는 한 화면 |

## 3. 장비로 들어오는 문 세 개

| 문 | 무엇인가 | 잠금 |
|---|---|---|
| 콘솔 | 장비에 케이블을 직접 꽂고 들어오는 문 | `line console 0`에 비밀번호와 `login` |
| 원격(VTY) | 네트워크를 통해 원격으로 들어오는 문 | `line vty`에 비밀번호와 `login` |
| 관리자 모드 | 들어온 뒤 설정 권한을 얻는 문 | `enable secret` |

회사 건물로 치면 콘솔은 서버실 안쪽의 직원용 문, VTY는 바깥에서 여는 원격 출입문, enable은 서버실 안의 금고다. 셋 중 하나라도 열려 있으면 나머지 잠금이 소용없다.

`login`은 이 회선으로 들어올 때 비밀번호를 물으라는 명령이다. 콘솔은 기본으로 비밀번호를 묻지 않으므로, 비밀번호만 적고 `login`을 빼면 잠금이 걸리지 않는다.

VTY는 조금 다르다. 시스코 라우터는 VTY에 비밀번호가 없으면 원격 접속을 아예 받지 않고 `Password required, but none set`이라며 끊는다. 처음부터 닫혀 있는 문, 1일차의 기본 거부다. 우리가 VTY에 비밀번호를 거는 것은 원격 관리를 하려고 이 문을 여는 일이다. 연 문은 지켜야 할 문이 된다.

`exec-timeout 5 0`은 5분 동안 아무 입력이 없으면 연결을 끊는다. 관리자가 접속을 열어 둔 채 자리를 비우면 지나가던 사람이 관리자 권한을 그대로 얻게 된다. 콘솔과 VTY 모두에 건다.

## 4. enable password와 enable secret

| 구분 | enable password | enable secret |
|---|---|---|
| show running-config에서 | 그대로 보인다 | 해시로 바뀌어 보인다 |
| 둘 다 설정하면 | 무시된다 | 이것이 쓰인다 |

해시는 비밀번호를 되돌릴 수 없는 값으로 바꾼 것이다. 장비는 비밀번호를 저장하지 않고 해시만 저장해 두었다가, 누군가 비밀번호를 입력하면 같은 방식으로 바꿔 비교한다. 1일차에 본 Git 커밋의 지문과 같은 원리다. 그래서 enable에는 secret만 쓴다.

`show running-config`에는 이렇게 보인다. 해시 문자열은 자리만 표시했다.

```
enable secret 5 $1$<salt>$<해시>
```

5는 해시 방식의 번호(MD5)이고, 그 뒤가 해시다. 해시를 만들 때 섞는 값(salt)이 장비마다 달라서 같은 비밀번호라도 장비마다 다른 문자열이 나온다.

## 5. service password-encryption의 한계

콘솔과 VTY의 비밀번호는 password로 걸었기 때문에 `show running-config`에 그대로 보인다.

```
line con 0
 password <password>
```

`service password-encryption`을 켜면 이 비밀번호들이 `password 7` 뒤의 문자열로 바뀐다.

```
line con 0
 password 7 <7번 문자열>
line vty 0 4
 password 7 <7번 문자열>
```

두 줄의 비밀번호가 같아도 문자열이 다르게 나온다. 그런데 이 7번 방식은 해시가 아니라 되돌릴 수 있는 간단한 변환이라, 두 문자열 모두 원래 비밀번호로 쉽게 되돌아간다. 이 문자열을 넣으면 원래 비밀번호를 바로 보여 주는 도구가 흔하다. **옆 사람이 화면을 어깨 너머로 보는 것을 막는 정도이고, 설정 파일을 가져간 사람은 막지 못한다.**

정리하면 이렇다.

| 할 일 | 이유 |
|---|---|
| 관리자 모드는 enable secret으로 잠근다 | 해시라 설정 파일이 새어도 바로 드러나지 않는다 |
| 회선 비밀번호는 service password-encryption으로 가린다 | 어깨 너머 보기는 막는다 |
| 설정 파일 자체를 비밀 문서로 다룬다 | 7번 문자열은 되돌릴 수 있고, 해시도 시간을 들이면 풀릴 수 있다 |

{% hint style="info" %}
NOTE: VTY 비밀번호는 텔넷으로 오가는데, 텔넷은 비밀번호를 암호화하지 않고 그대로 보낸다. 12일차에 Wireshark로 이것을 직접 보고, 사용자 계정과 SSH로 바꾼다.
{% endhint %}

## 6. 경고문(배너)

`banner motd`는 장비에 접속하는 사람에게 가장 먼저 보여 주는 문구다. 허가받은 사람만 들어올 수 있고 접속이 기록된다는 것을 미리 알린다. 무단 접속을 문제 삼을 때 미리 알렸다는 근거가 된다.

배너에 장비 모델, 회사 이름, 담당자 이름은 적지 않는다. 비밀번호를 묻기도 전에 보이는 문구라, 들어오려는 사람에게 단서를 주게 된다. 패킷트레이서에서는 한글이 깨질 수 있어 영어로 쓴다.

`banner motd #`처럼 문구의 앞뒤를 같은 기호로 감싼다. 이 기호는 문구 안에 들어가지 않는 것이면 무엇이든 된다.

## 7. 주소 주기와 확인

라우터의 포트는 처음에 꺼져 있다(shutdown). `no shutdown`을 빼먹으면 주소를 줘도 통신이 되지 않는다. `show ip interface brief`로 확인한다.

```
Interface              IP-Address      OK? Method Status                Protocol
GigabitEthernet0/0     192.168.10.1    YES manual up                    up
GigabitEthernet0/1     unassigned      YES unset  administratively down down
GigabitEthernet0/2     unassigned      YES unset  administratively down down
```

| 칸 | 읽는 법 |
|---|---|
| Status | 포트가 켜져 있나. administratively down은 관리자가 꺼 둔 상태(`shutdown`) |
| Protocol | 상대와 실제로 통신할 준비가 되었나 |

Gi0/0의 Status와 Protocol이 모두 up이면 된다. 다른 줄이 더 보여도 괜찮다.

라우터에서 PC로 ping을 보내면 시스코 장비는 결과를 기호로 보여 준다.

```
HQ-R1#ping 192.168.10.2

Type escape sequence to abort.
Sending 5, 100-byte ICMP Echos to 192.168.10.2, timeout is 2 seconds:
.!!!!
Success rate is 80 percent (4/5), round-trip min/avg/max = 0/0/1 ms
```

`!`는 답이 왔다, `.`는 시간 안에 답이 오지 않았다는 뜻이다. 처음 하나가 `.`인 것은 상대의 MAC 주소를 알아내는 동안 첫 패킷을 보내지 못했기 때문이고, 다시 입력하면 `!!!!!`가 된다.

PC 두 대에 영업팀 대역의 주소를 주고 서로, 그리고 게이트웨이와 ping이 되는지 본다. 그다음 한 대를 인사팀 대역(192.168.10.40)으로 바꾸고 다시 입력한다.

```
C:\>ping 192.168.10.40

Pinging 192.168.10.40 with 32 bytes of data:

Reply from 192.168.10.1: Destination host unreachable.
```

같은 스위치에 꽂혀 있어도 통하지 않는다. 네트워크 부분이 다르니 PC는 라우터로 보내는데, 라우터는 아직 인사팀 네트워크를 모르기 때문이다. 답을 보낸 쪽이 192.168.10.40이 아니라 라우터(192.168.10.1)라는 점을 본다. 라우터가 "그쪽으로 가는 길을 모른다"고 알려 온 것이다. 3번 노트에서 그은 경계가 실제로 작동하는 첫 장면이다.

## 8. 원격 문 두드려 보기

잠금이 실제로 걸렸는지 확인한다. Sales-PC1의 Command Prompt에서 라우터로 텔넷 접속을 한다. 이 접속은 실습망 안의 내 라우터(HQ-R1)에 대해서만 한다.

```
C:\>telnet 192.168.10.1
Trying 192.168.10.1 ...Open
Authorized access only. All access is logged.

User Access Verification

Password:
HQ-R1>enable
Password:
HQ-R1#
```

배너가 먼저 보이고, VTY 비밀번호를 묻고, enable에서 다시 secret을 묻는다. 세 문 중 두 개(VTY와 관리자 모드)를 차례로 지난 것이다. 비밀번호를 입력할 때 화면에 아무것도 나오지 않는 것은 정상이다. `exit`로 나온다.

지금 PC와 라우터 사이에서 이 비밀번호들은 암호화되지 않은 채 오갔다. 같은 네트워크에서 누군가 엿보고 있었다면 그대로 보였을 것이다.

{% hint style="info" %}
NOTE: 12일차에 바로 이 텔넷 접속을 Wireshark로 잡아 비밀번호가 글자 그대로 보이는 것을 확인한다.
{% endhint %}

## 9. 저장

| 설정 | 있는 곳 | 전원이 꺼지면 |
|---|---|---|
| running-config | RAM | 사라진다 |
| startup-config | NVRAM | 남는다 |

설정은 먼저 RAM에만 들어간다. 저장해야 다시 켰을 때 살아 있다.

```
HQ-R1#copy running-config startup-config
Destination filename [startup-config]?
Building configuration...
[OK]
```

파일 이름을 묻는 줄에서는 Enter만 누른다. `write memory`(줄여서 `wr`)도 같은 일을 한다. 저장을 빼먹어 재부팅 뒤에 설정이 사라지는 사고는 현장에서도 일어난다. `show startup-config`로 저장된 내용을 확인할 수 있다.

## 10. 설정 파일을 저장소로

개인 실습에서 내 주소로 바꾼 뒤에 한다. `show running-config`의 결과를 텍스트로 복사해 `configs/HQ-R1.txt`에 넣고 커밋한다. 3일차부터 설정을 바꿀 때마다 이 파일을 덮어쓰고 커밋하면, `git diff`에 그날 바뀐 줄만 나타난다. 누가 언제 무엇을 바꿨는지 남는 것이 1일차에 본 기록의 원칙이다.

`.pkt` 파일도 함께 커밋하지만, 이 파일은 바이너리라 Git이 무엇이 바뀌었는지 보여 주지 못한다. 텍스트를 따로 남기는 이유가 이것이다.

이 파일에는 enable secret의 해시와 7번 문자열이 그대로 들어간다. 수업에서 정한 실습용 비밀번호라 공개해도 괜찮다. 하지만 실제 회사라면 이 파일은 공개 저장소에 올리지 않는다. 5번에서 본 것처럼 설정 파일 자체가 비밀 문서다.

## 약어·용어

| 용어 | 뜻 |
|---|---|
| CLI (Command Line Interface) | 명령을 글자로 입력해 장비를 다루는 화면 |
| 콘솔 | 장비에 케이블을 직접 꽂고 들어가는 관리 포트 |
| VTY (Virtual Teletype) | 텔넷이나 SSH로 원격 접속할 때 쓰는 가상 회선 |
| enable secret | 관리자 모드 비밀번호. 해시로 저장된다 |
| 7번 방식 | `service password-encryption`이 쓰는, 되돌릴 수 있는 변환 |
| 배너 (banner motd) | 접속하는 사람에게 처음 보여 주는 경고문 |
| running-config | RAM에 있는 현재 설정 |
| startup-config | NVRAM에 저장된 설정. 다시 켜면 이 설정으로 시작한다 |
| 텔넷 (Telnet) | 암호화하지 않는 원격 접속 방식. 23번 포트 |

## 함께 생각해 보기

- 회사 라우터의 설정 파일이 밖으로 새어 나갔다면 무엇이 위험한가? 기밀성, 무결성, 가용성 중 무엇이 깨질 수 있는가?
- VTY에 비밀번호를 걸지 않으면 원격 접속이 막힌다고 했다. 그렇다면 VTY에 비밀번호를 걸지 않고 두는 것이 더 안전한가?

## 강의 메모

### 시간 배분 (함께 40분, 개인 실습 30분)

| 구간 | 절 | 시간 | 방식 |
|---|---|---|---|
| 함께 | 1 토폴로지와 패킷트레이서 기본 | 6분 | 대본 1번. 장비를 놓고 선을 잇는다 |
| 함께 | 2 네 가지 모드 | 4분 | `?`와 Tab을 같이 입력해 본다 |
| 함께 | 3~6 세 문, secret, 7번 방식, 배너 | 13분 | 대본 2, 3번을 입력하면서 절마다 멈춰 `show running-config`로 본다 |
| 함께 | 7 주소와 확인, 다른 대역 실험 | 9분 | 대본 4번 |
| 함께 | 8 텔넷으로 두드려 보기 | 5분 | 대본 5번 |
| 함께 | 9 저장 | 3분 | 대본 6번 |
| 개인 | 내 주소로 바꾸고 확인, 10 설정 파일을 저장소로 | 30분 | 대본 8~10번 |

함께 하는 40분에는 새봄상사의 주소로 입력한다. 개인 실습에서 내 설계표의 주소로 바꾸면서 7, 8번 절의 확인을 한 번 더 한다.

### 물어볼 것

- "`login`을 빼고 비밀번호만 걸면 어떻게 될까요?" 콘솔에서 직접 확인시킨다. 비밀번호를 묻지 않고 바로 들어가진다.
- "7번 문자열이 원래 비밀번호로 되돌아간다면 왜 켜 둘까요?" 어깨 너머 보기를 막는 정도의 쓸모는 있고, 끄면 그마저도 없다. 하지만 이것에 기대면 안 된다.
- "ping에 답한 것이 .40이 아니라 .1이었습니다. 무슨 뜻일까요?" 라우터가 길을 모른다고 대신 알려 준 것이다.
- 두 번째 함께 생각해 보기의 답: 원격 접속을 막아 두는 것 자체는 더 안전하다. 하지만 장비가 수십 대면 관리자가 매번 서버실에 가야 한다. 그래서 원격 관리를 열되, 관리 네트워크에서만(10일차) 암호화된 SSH로만(12일차) 열어 위험을 줄인다. 1일차의 위험 대응 중 감소다.

### 자주 헷갈리는 것

| 헷갈리는 것 | 바로잡기 |
|---|---|
| `exit`와 `end` | `exit`는 한 단계 아래로, `end`는 어디서든 관리자 모드로 |
| password와 secret | secret은 해시로 저장되고, 둘 다 있으면 secret이 쓰인다 |
| service password-encryption이면 안전하다 | 7번 방식은 되돌릴 수 있다. 어깨 너머 보기만 막는다 |
| 라우터와 스위치의 VTY 번호 | 오늘의 2911 라우터는 `line vty 0 4`, 2960 스위치는 원격 회선이 16개라 `line vty 0 15`로 한 번에 잠근다 |
| 설정하면 저장된다 | running-config는 RAM에 있다. `copy running-config startup-config`를 해야 남는다 |

### 진행 요령

- 실습용 비밀번호는 칠판에 하나로 정해 준다. 패킷트레이서에서 비밀번호를 잊으면 장비를 지우고 다시 놓는 편이 빠르다.
- 스위치에도 같은 잠금을 건다(대본 3번). 같은 명령을 두 번 입력하면 손에 붙는다.
- 다른 대역 실험은 학생이 직접 IP를 바꿔 보게 한다. 3일차 VLAN 간 통신에서 "그럼 라우터에 인사팀을 알려 주면 되나"로 이어진다.
- VTY가 기본으로 닫혀 있다는 것은 강사 시연으로 보여 줄 수 있다. 새 라우터에 주소만 주고 PC에서 텔넷을 하면 `Password required, but none set`이 뜨고 끊긴다.
- 텔넷 실습에서 enable secret 없이 들어가면 원격에서는 `% No password set`으로 관리자 모드에 들어가지 못한다. 학생이 이 메시지를 보면 enable secret을 빠뜨린 것이다.
- 첫 번째 함께 생각해 보기의 답: 비밀번호가 드러나면 누군가 장비에 들어와 설정을 바꿀 수 있다(무결성). 주소 체계와 접속 경로가 드러난다(기밀성). 설정을 지우거나 포트를 꺼서 회사 통신을 멈출 수 있다(가용성).
