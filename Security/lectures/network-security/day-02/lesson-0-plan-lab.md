## 5. 절차

### A. 저장소 갱신과 폴더 준비

1. (5-A-01) 다른 곳에서 고친 것이 있으면 받아 온다: `git pull` → 결과: `Already up to date.`가 보인다.
2. (5-A-02) 1일차 계획서를 다시 읽고 고칠 곳이 있으면 고친다. → 결과: 고친 곳이 저장된다.
3. (5-A-03) 오늘 쓸 폴더를 한 번에 만든다: `mkdir 00_작업계획 02_설계 configs _실습` → 결과: 폴더 네 개가 생긴다. 이미 있는 폴더는 `File exists` 오류가 나며 무시해도 된다.

### B. 작업 계획서 쓰기

1. (5-B-01) VS Code에서 `00_작업계획/02일차.md`를 만든다. → 결과: 빈 파일이 열린다.
2. (5-B-02) [1일차 4번 노트](../day-01/lesson-4.md) 10절의 양식을 붙여 넣는다. → 결과: 6개 칸의 제목이 보인다.
3. (5-B-03) 강사가 새봄상사의 칸을 쓰는 것을 보면서, 같은 칸을 내 회사로 1~5번까지 쓴다. 20분 안에 쓴다. → 결과: 1~5번 칸이 채워진다. 6번 결과 칸은 비워 둔다(개인 실습이 끝날 때 채운다).

아래는 새봄상사의 2일차 작업 계획서 예시다.

#### 새봄상사 2일차 작업 계획서

**1. 목표**

- 프로젝트 계획서 3번 칸의 "부서마다 네트워크를 나눈다"를 주소 설계로 옮긴다.
- 프로젝트 계획서 4번 칸의 "아무나 라우터에 접속해 설정을 바꾼다"를 막는다.

**2. 작업 대상**

| 대상 | 무엇을 |
|---|---|
| `02_설계/IP_설계표.md` | 본사와 지사의 주소를 부서별로 나눈다 |
| HQ-R1 | 이름, 콘솔과 VTY와 관리자 모드의 잠금, 영업팀 게이트웨이 주소 |
| HQ-SW1 | 이름, 잠금 |
| Sales-PC1, Sales-PC2 | 영업팀 주소 |

**3. 작업 내용**

1. 본사 192.168.10.0/24를 /27로 나눠 설계표를 쓴다.
2. 패킷트레이서에 라우터, 스위치, PC 두 대를 놓고 잇는다.
3. HQ-R1과 HQ-SW1에 잠금을 건다.
4. HQ-R1 Gi0/0에 영업팀 게이트웨이 주소를 준다.
5. PC에 영업팀 주소를 준다.
6. 저장하고 설정 텍스트를 뽑아 커밋한다.

**4. 확인 방법**

| 확인할 것 | 방법 | 기대하는 결과 |
|---|---|---|
| 라우터 포트가 켜졌다 | `show ip interface brief` | Gi0/0이 up, up |
| 영업팀 안의 통신 | Sales-PC1에서 Sales-PC2로 ping | Reply |
| 게이트웨이까지의 통신 | Sales-PC1에서 192.168.10.1로 ping | Reply |
| 다른 부서와 나뉘었다 | PC2를 인사팀 대역(192.168.10.40)으로 바꾸고 ping | 라우터가 Destination host unreachable로 답한다 |
| 원격 접속에 잠금이 걸렸다 | Sales-PC1에서 `telnet 192.168.10.1` | 배너, VTY 비밀번호, enable secret을 차례로 묻는다 |
| 비밀번호가 그대로 보이지 않는다 | `show running-config` | enable secret 5, password 7 |

**5. 되돌리는 방법**

- 저장하기 전이면 `reload`에서 저장하지 않음(no)을 골라 마지막으로 저장한 상태로 돌아간다.
- 오늘은 첫 설정이라 꼬이면 장비를 지우고 다시 놓는다.
- 설계표는 Git에 커밋된 이전 판으로 돌아갈 수 있다.

**6. 결과 (개인 실습이 끝날 때 채운다)**

- 한 일:
- 확인 결과:
- 막힌 곳과 어떻게 풀었나:
- 다음 회차에 이어서 할 일: 인사팀, 개발팀, 서버, 장비 관리 네트워크를 VLAN으로 만든다

### C. 커밋

1. (5-C-01) 1일차 계획서를 고쳤다면 함께 올리도록 모두 추가한다: `git add .` → 결과: 오류 없이 끝난다.
2. (5-C-02) 상태를 확인한다: `git status` → 결과: `00_작업계획/02일차.md`가 초록 글씨로 보인다.
3. (5-C-03) 커밋한다: `git commit -m "2일차: 작업 계획서"` → 결과: 커밋이 만들어진다.
4. (5-C-04) 올린다: `git push` → 결과: 오류 없이 끝난다.

`02_설계`와 `configs`는 아직 비어 있어서 커밋되지 않는다. 1일차에 본 빈 폴더 이야기다.

## 7. 복구

1. (7-01) 커밋 전에 계획서를 되돌리려면 `git restore 00_작업계획/02일차.md`를 입력한다. 새로 만든 파일이라 이전 판이 없으면 파일을 직접 지운다.
2. (7-02) 이미 커밋했다면 파일을 고치고 새 커밋을 만든다. 과거 커밋은 고치지 않는다.
