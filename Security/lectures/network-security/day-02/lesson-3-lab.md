## 5. 절차

### A. 계산

1. (5-A-01) 본사의 네트워크 목록을 적는다. 부서마다 하나, 서버 하나, 장비 관리 하나다. → 결과: 네트워크 이름 목록이 완성된다.
2. (5-A-02) 지사의 네트워크 목록을 적는다. → 결과: 지사 네트워크 이름 목록이 완성된다.
3. (5-A-03) 본사와 지사의 대역을 정한다. 셋째 칸을 새봄상사와 다른 숫자로 고른다(예: 192.168.30.0/24). → 결과: 본사 대역과 지사 대역이 정해진다.
4. (5-A-04) 본사 네트워크 수로 n을 구한다. 2ⁿ이 네트워크 수 이상이 되는 가장 작은 n이다. → 결과: n이 정해진다.
5. (5-A-05) 가장 큰 부서의 인원이 2ʰ - 2 이하인지 확인한다. 넘으면 n을 줄이거나 대역을 다시 정한다. → 결과: 한 네트워크에 둘 수 있는 장비 수가 인원 이상이다.
6. (5-A-06) 블록 크기(256 - 마스크의 마지막 칸)로 각 네트워크의 범위를 적고, 첫 번째 쓸 수 있는 주소를 게이트웨이로 정한다. → 결과: 네트워크마다 대역, 게이트웨이, 장비에 줄 주소 범위가 정해진다.
7. (5-A-07) 본사와 지사를 잇는 구간에 /30 하나를 준다. → 결과: 연결 구간의 대역과 양쪽 주소가 정해진다.

### B. 표 작성

1. (5-B-01) VS Code에서 `02_설계/IP_설계표.md`를 만든다. → 결과: 빈 파일이 열린다.
2. (5-B-02) 아래 양식을 붙여 넣고 빈칸을 채운다. → 결과: 대역 계획, 설계표, 규칙이 모두 채워진다.

````markdown
# IP 주소 설계표

## 대역 계획

- 본사: 192.168.__.0/24 를 /__ 로 나눈다 (네트워크 __개, 네트워크마다 장비 __대)
- 지사: 192.168.__.0/24 를 /__ 로 나눈다
- 본사와 지사 연결: 192.168.__.0/30

## 설계표

| 위치 | 네트워크 | 대역 | 게이트웨이 | 장비에 줄 주소 | 인원과 장비 | 쓰는 날 |
|------|----------|------|------------|----------------|-------------|---------|
|      |          |      |            |                |             |         |

## 규칙

- 게이트웨이는 각 네트워크의 첫 번째 쓸 수 있는 주소로 한다
- 라우터와 스위치에는 장비 관리 네트워크에서만 접속한다 (10일차에 ACL로 강제한다)
````

3. (5-B-03) 저장한다: Ctrl+S → 결과: 파일 탭의 점이 사라진다.

## 6. 기능 확인

| 번호 | 확인 동작 | 기대 결과 | 합격 기준 |
|---|---|---|---|
| 1 | 모든 네트워크 대역의 블록 시작 값을 블록 크기의 배수로 확인한다 | 0, 32, 64처럼 블록 크기씩 늘어난다 | 겹치는 대역이 없다 |
| 2 | 게이트웨이가 각 대역의 첫 번째 쓸 수 있는 주소인지 본다 | 네트워크 주소 + 1이다 | 모든 줄이 해당한다 |
| 3 | 가장 큰 부서의 인원과 쓸 수 있는 주소 수를 비교한다 | 인원이 주소 수 이하다 | 해당 |
| 4 | 연결 구간이 /30인지 본다 | 호스트 주소가 2개다 | 해당 |
