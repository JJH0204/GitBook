# 1. 네트워크의 계층과 TCP, UDP

> 상위: [2일차 주소 설계와 장비 접근 보안](README.md)
> 드로잉: 1. 네트워크의 계층과 TCP, UDP 드로잉 (12장)

## 학습 목표

- OSI 7계층이 왜 생겼는지 압니다
- 캡슐화를 택배 포장에 빗대어 설명하고, 계층마다 헤더에 무엇이 적히는지 압니다
- 계층마다 데이터를 부르는 이름을 압니다
- TCP와 UDP의 차이, 포트 번호의 역할을 압니다
- 내 PC에서 지금 열려 있는 연결을 직접 봅니다

## 다리 놓기

1일차에 네트워크를 택배망에 빗댔습니다. 택배 하나가 오가려면 포장하는 사람, 송장을 붙이는 사람, 분류 센터, 배송 차량이 각자 맡은 일을 해야 합니다. 네트워크도 통신을 여러 층으로 나눠 각 층에 한 가지 일을 맡깁니다.

## 1. 왜 계층으로 나누나

예전에는 회사마다 장비와 통신 방식이 달라 서로 연결하기 어려웠습니다. 그래서 1970~80년대에 국제표준화기구(ISO)가 통신을 일곱 단계로 나눈 표준 모델을 정리했습니다. 이것이 OSI 7계층(Open Systems Interconnection)입니다.

일을 나누자 각 계층을 만드는 사람은 자기 층에만 집중할 수 있게 되었습니다. 랜카드를 만드는 회사는 웹 브라우저를 몰라도 되고, 브라우저를 만드는 회사는 케이블을 몰라도 됩니다. 한 층을 바꿔도 다른 층은 그대로 둘 수 있습니다. 유선 랜을 와이파이로 바꿔도 브라우저는 고칠 필요가 없습니다.

## 2. 일곱 계층

| 계층 | 이름 | 하는 일 | 예 |
|------|------|---------|----|
| 7 | 응용 | 사용자가 쓰는 서비스 | HTTP, FTP, SMTP, DNS |
| 6 | 표현 | 데이터 형식 변환, 압축, 암호화 | |
| 5 | 세션 | 통신 연결의 시작과 끝을 관리 | |
| 4 | 전송 | 끝에서 끝까지 전달을 책임진다. 포트 번호를 쓴다 | TCP, UDP |
| 3 | 네트워크 | 다른 네트워크로 가는 길을 고른다. IP 주소를 쓴다 | IP, ICMP, 라우터 |
| 2 | 데이터 링크 | 같은 네트워크 안에서 전달한다. MAC 주소를 쓴다 | 이더넷, 스위치 |
| 1 | 물리 | 0과 1을 전기, 빛, 전파로 보낸다 | 케이블, 커넥터 |

메일 한 통을 보낼 때 일곱 계층이 하는 일을 따라가 보면 이렇습니다.

| 계층 | 메일을 보낼 때 |
|------|----------------|
| 7 | 메일을 쓰고 보내기를 누른다. 메일 프로그램이 메일 보내는 규칙(SMTP)에 맞춰 넘긴다 |
| 6 | 첨부 파일을 보낼 수 있는 형식으로 바꾸고, 필요하면 암호화한다 |
| 5 | 메일 서버와의 대화를 시작하고, 다 보내면 끝낸다 |
| 4 | TCP가 메일을 조각내 번호를 붙이고, 메일 서버의 포트 번호를 적는다 |
| 3 | 조각마다 메일 서버의 IP 주소를 붙인다 |
| 2 | 바로 다음 장비(공유기)의 MAC 주소를 붙인다 |
| 1 | 랜선의 전기 신호로 나간다 |

받는 쪽에서는 1계층부터 거꾸로 올라가며 하나씩 풀어 원래의 메일을 꺼냅니다.

실제 인터넷은 계층을 넷으로 묶은 TCP/IP 모델로 돌아갑니다. OSI의 5~7계층을 응용 계층 하나로, 1, 2계층을 네트워크 접근 계층 하나로 묶은 것입니다. 그래도 장비와 보안을 이야기할 때는 "2계층 스위치", "3계층 장비", "7계층 공격"처럼 OSI의 번호로 부릅니다.

| TCP/IP 모델 | OSI |
|-------------|-----|
| 응용 | 5, 6, 7 |
| 전송 | 4 |
| 인터넷 | 3 |
| 네트워크 접근 | 1, 2 |

## 3. 캡슐화: 포장하고 풀기

보내는 쪽에서는 데이터가 위 계층에서 아래 계층으로 내려가며 계층마다 머리글(헤더)이 하나씩 붙습니다. 받는 쪽에서는 아래에서 위로 올라가며 하나씩 떼어 냅니다. 붙이는 것을 캡슐화, 떼는 것을 역캡슐화라고 합니다.

```
7~5   [데이터]
4     [TCP 헤더 | 데이터]                              세그먼트
3     [IP 헤더 | TCP 헤더 | 데이터]                     패킷
2     [MAC 헤더 | IP 헤더 | TCP 헤더 | 데이터 | 꼬리]    프레임
1     0101101001...                                    비트
```

택배로 치면 물건을 상자에 담고(4계층), 받는 사람 주소가 적힌 송장을 붙이고(3계층), 이번 구간을 실어 나를 차량의 번호표를 붙이는(2계층) 것입니다. 송장의 주소는 끝까지 그대로지만 차량 번호표는 분류 센터를 지날 때마다 새로 붙습니다. 마찬가지로 IP 주소는 끝까지 같고, MAC 주소는 라우터를 지날 때마다 바뀝니다.

헤더마다 적히는 칸은 이렇습니다. 오늘은 이 정도만 알아 둡니다.

| 헤더 | 주요 칸 | 택배로 치면 |
|------|---------|-------------|
| TCP 헤더 (4계층) | 출발지 포트, 목적지 포트, 순서 번호, SYN과 ACK 같은 표시 | 몇 번째 상자인지, 건물의 몇 호로 가는지 |
| IP 헤더 (3계층) | 출발지 IP, 목적지 IP, TTL | 송장의 보내는 사람 주소와 받는 사람 주소 |
| 이더넷 헤더 (2계층) | 출발지 MAC, 목적지 MAC | 이번 구간 차량의 번호표 |

TTL(Time To Live)은 라우터를 하나 지날 때마다 1씩 줄고, 0이 되면 그 패킷은 버려집니다. 길을 잃은 패킷이 네트워크를 영원히 돌지 않게 하는 장치입니다.

MAC 주소는 랜카드를 만들 때 정해지는 48비트 주소로, `00-1A-2B-3C-4D-5E` 처럼 16진수 12자리로 씁니다. Windows의 명령 프롬프트에서 `ipconfig /all` 을 치면 "물리적 주소(Physical Address)" 줄에 내 PC의 MAC 주소가 보입니다.

| 계층 | 데이터를 부르는 이름 |
|------|----------------------|
| 4 | 세그먼트 |
| 3 | 패킷 |
| 2 | 프레임 |
| 1 | 비트 |

현장에서는 계층을 가리지 않고 모두 패킷이라고 부르는 경우가 많습니다.

> 12일차에 Wireshark로 실제 프레임을 열면 이 헤더들이 층층이 쌓인 모습을 그대로 봅니다.

## 4. TCP와 UDP

|  | TCP | UDP |
|--|-----|-----|
| 방식 | 연결을 맺고, 받았는지 확인하고, 빠진 것은 다시 보낸다 | 확인 없이 보낸다 |
| 장점 | 확실하다 | 빠르다 |
| 쓰는 곳 | 웹, 파일 전송, 원격 접속, 메일 | 실시간 영상, 음성 통화, DNS 조회 |

등기우편과 일반 우편의 차이와 비슷합니다. 등기는 받았다는 서명을 받아 오고, 일반 우편은 보내고 끝입니다. 어느 쪽이 더 좋은 것이 아니라 쓰임이 다릅니다. 영상 통화에서 0.1초 전 화면을 다시 받아 봐야 소용이 없으니 UDP를 씁니다. 반대로 파일 하나에서 조각 하나가 빠지면 파일 전체가 망가지니 TCP를 씁니다.

TCP는 데이터를 보내기 전에 세 번 주고받으며 연결을 맺습니다. 이것을 3-way handshake라고 합니다.

```
 내 PC                                    서버
   | ---- SYN       (연결해도 될까요) ----->  |
   | <--- SYN, ACK  (좋아요, 저도요) -------  |
   | ---- ACK       (확인했어요) ---------->  |
   |          이제 데이터를 주고받는다          |
```

전화로 치면 "여보세요", "네, 들려요", "네, 저도 들려요"를 주고받은 뒤에 본론을 꺼내는 것과 같습니다.

> 10일차 ACL의 established와 12일차 서비스 거부 공격이 모두 이 세 번의 주고받기를 이용합니다. 연결 요청(SYN)만 잔뜩 보내고 마지막 확인을 하지 않으면 서버는 답을 기다리느라 지칩니다.

## 5. 포트 번호

IP 주소가 건물 주소라면 포트 번호는 그 건물 안의 호실 번호입니다. 서버 한 대에서 웹, 메일, 원격 접속 서비스가 함께 돌아도 포트 번호로 어느 서비스에 갈지 구분합니다.

| 포트 | 서비스 | 전송 |
|------|--------|------|
| 22 | SSH (암호화된 원격 접속) | TCP |
| 23 | Telnet (암호화하지 않는 원격 접속) | TCP |
| 25 | SMTP (메일 보내기) | TCP |
| 53 | DNS (이름으로 주소 찾기) | UDP, TCP |
| 80 | HTTP (웹) | TCP |
| 443 | HTTPS (암호화된 웹) | TCP |

포트 번호는 0부터 65535까지 있고, 쓰임에 따라 세 구간으로 나뉩니다.

| 구간 | 이름 | 누가 쓰나 |
|------|------|-----------|
| 0~1023 | 잘 알려진 포트 | 서버의 대표 서비스. 위 표의 번호들 |
| 1024~49151 | 등록된 포트 | 특정 프로그램이 등록해 쓰는 번호 |
| 49152~65535 | 동적 포트 | 내 PC가 접속할 때 그때그때 골라 쓰는 번호 |

내 PC가 웹 서버에 접속하면 서버 쪽은 443번이지만, 내 PC 쪽은 동적 포트 중 하나를 그때 골라 씁니다. 브라우저 탭 세 개가 같은 서버에 붙어 있어도 내 쪽 포트 번호가 서로 달라서 답이 엉뚱한 탭으로 가지 않습니다.

내 PC에서 직접 확인할 수 있습니다. 브라우저로 아무 사이트나 연 채 명령 프롬프트에서 칩니다.

```
netstat -an | findstr ESTABLISHED
```

```
  TCP    192.168.0.15:51234     142.250.x.x:443    ESTABLISHED
```

왼쪽이 내 PC의 주소와 포트, 오른쪽이 상대 서버의 주소와 포트입니다. 내 쪽은 큰 번호, 상대 쪽은 443입니다. ESTABLISHED는 3-way handshake를 마치고 연결이 맺어진 상태라는 뜻입니다.

보안에서 포트가 중요한 이유는 포트가 곧 문이기 때문입니다. 서비스를 다 만들어도 방화벽이 그 포트를 막으면 들어갈 수 없습니다. 반대로 쓰지 않는 포트가 열려 있으면 공격자가 들어올 수 있는 문이 하나 더 생깁니다.

## 6. 계층으로 보는 보안 지도

| 계층 | 이 계층을 노리는 공격의 예 | 이 과목에서 막는 곳 |
|------|----------------------------|---------------------|
| 2 | 같은 네트워크 안에서 주소 속이기 | 12일차 관찰과 대응 |
| 3 | 허락하지 않은 네트워크에서 오는 접근 | 10일차 ACL |
| 4 | 열린 포트로 들어오는 접근, 연결 요청 폭주 | 13, 14일차 방화벽 |
| 7 | 웹 서비스의 입력을 노린 공격 | 웹 보안 과목 |

공격자는 어느 계층이든 가장 약한 곳을 노립니다. 그래서 한 계층만 막아서는 부족하고, 1일차에 본 심층 방어처럼 여러 계층에 걸쳐 막습니다.

### 시간 배분 (25분)

| 절 | 시간 | 방식 |
|----|------|------|
| 다리 놓기, 1 | 2분 | |
| 2 일곱 계층 | 4분 | 표만 짚는다. 메일 표와 TCP/IP 대응표는 시간이 남을 때 |
| 3 캡슐화와 헤더 | 8분 | 택배 그림. 학생이 `ipconfig /all` 로 MAC 주소를 찾는다 |
| 4 TCP와 UDP | 5분 | 전화 비유로 3-way handshake |
| 5 포트 번호 | 5분 | 학생이 `netstat` 으로 자기 PC의 연결을 본다 |
| 6 보안 지도 | 1분 | 날짜 예고만 |

25분 안에 다 다루기 빠듯한 노트입니다. 12일차 Wireshark에서 계층과 헤더를 다시 보므로, 오늘은 캡슐화와 포트가 손에 잡히면 충분합니다.

### 물어볼 것

- "와이파이로 바꾸면 브라우저를 다시 깔아야 할까요?" 아니라는 답으로 계층을 나눈 이유를 짚습니다.
- "택배가 서울 분류 센터에서 대구 분류 센터로 갈 때, 송장 주소가 바뀌나요, 차량 번호가 바뀌나요?" 차량 번호(MAC)만 바뀝니다.
- "`netstat` 결과에서 내 쪽 포트가 443인 줄이 있나요?" 대개 없습니다. 내 PC는 서버가 아니라 접속하는 쪽이기 때문입니다.

### 자주 헷갈리는 것

| 헷갈리는 것 | 바로잡기 |
|-------------|----------|
| OSI 7계층대로 실제 프로그램이 일곱 개 있다 | 일을 나눠 부르는 틀이다. 실제 인터넷은 TCP/IP 네 계층으로 돈다 |
| UDP는 나쁜 프로토콜이다 | 확인을 생략한 대신 빠르다. 쓰임이 다를 뿐이다 |
| MAC 주소도 끝까지 그대로 간다 | 라우터를 지날 때마다 다음 구간의 MAC으로 바뀐다. 끝까지 가는 것은 IP 주소다 |
| 포트는 랜카드의 구멍이다 | 여기서의 포트는 서비스를 가르는 번호다. 스위치의 물리 포트와 이름만 같다 |

### 진행 요령

- OSI는 외우게 하지 않습니다. "2계층 스위치", "3계층 라우터"처럼 번호로 장비를 부르는 말을 알아듣는 것이 목표입니다. 시간이 밀리면 2번 절의 메일 표와 TCP/IP 대응표를 건너뜁니다. 12일차 Wireshark에서 계층을 다시 봅니다.
- `netstat` 은 내 PC의 연결을 보는 명령이라 마음껏 쳐도 됩니다. 1일차 실습의 약속과 비교해 "내 PC는 내 땅"이라는 것을 짚습니다.
- 공유기 질문의 답: http는 80번으로 암호화 없이, https는 443번으로 암호화해서 오갑니다. 같은 와이파이의 누군가가 관리자 비밀번호를 볼 수 있는지가 갈립니다. 1일차의 기밀성과 이어 줍니다.
