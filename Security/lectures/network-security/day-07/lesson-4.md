# 4. 경계에서 걸러 내기

> 상위: [7일차 EIGRP와 재분배](README.md)
> 대본: [실습 명령어 모음](commands.md) 7~9번
> 드로잉: 4. 경계에서 걸러 내기 드로잉 (9장)

## 학습 목표

- 신뢰 경계를 정하고, 경계 라우터에서 받을 경로와 알릴 경로를 고릅니다
- prefix-list로 경로를 고르고, distribute-list와 route-map으로 적용합니다
- EIGRP 인증을 겁니다
- 경로를 숨기는 것만으로는 접근을 막지 못한다는 것을 압니다

## 다리 놓기

앞 노트에서 거르지 않은 재분배는 새봄상사의 인사팀과 장비 관리 대역까지 한결물류에 알렸습니다. 그리고 한결물류 쪽에서 무엇을 알리든 새봄상사 전체에 퍼뜨릴 준비가 되어 있습니다. 인수한 지 한 달 된 회사는 아직 우리가 관리하지 않는 망입니다. 그 망과 맞닿은 곳에서 무엇을 주고받을지 정해야 합니다.

## 1. 신뢰 경계

신뢰 경계는 "여기서부터는 우리가 관리하지 않는다"는 선입니다. 새봄상사에서는 본사 라우터의 Gi0/2가 그 선입니다.

| 방향 | 원칙 | 1일차 원칙 |
|------|------|------------|
| 한결물류에서 받는 경로 | 한결물류의 망(172.16.10.0/24)만 받는다 | 기본 거부 |
| 한결물류에 알리는 경로 | 업무에 필요한 서버 VLAN만 알린다 | 최소 권한 |
| 이웃 맺기 | 키를 아는 라우터만 | 인증 |

## 2. 고를 경로의 목록: prefix-list

경로를 고를 때는 prefix-list를 씁니다. 네트워크와 프리픽스 길이로 경로를 정확히 가리키는 목록입니다.

```
ip prefix-list LC-IN seq 10 permit 172.16.10.0/24
ip prefix-list TO-LC seq 10 permit 192.168.10.96/27
```

| 목록 | 뜻 |
|------|----|
| LC-IN | 한결물류에서 받을 것. 172.16.10.0/24 하나 |
| TO-LC | 한결물류에 알릴 것. 서버 VLAN 192.168.10.96/27 하나 |

목록에 없는 경로는 모두 거부됩니다. prefix-list의 끝에는 보이지 않는 "나머지는 모두 거부" 줄이 있습니다. 이 성질은 10일차 ACL에서 그대로 다시 만납니다.

## 3. 받을 것 고르기: distribute-list

```
router eigrp 20
 distribute-list prefix LC-IN in gi0/2
```

Gi0/2로 들어오는 EIGRP 경로 중 LC-IN 목록에 있는 것만 경로표에 넣습니다. 한결물류 쪽에서 엉뚱한 경로를 알려도 본사 라우터가 받지 않으니, 새봄상사 전체로 퍼지지도 않습니다.

5일차에 영업팀 자리의 가짜 장비가 서버 대역의 /28을 알려 서버 통신을 빼앗았습니다. 같은 일이 한결물류 쪽에서 일어나면 어떨까요. 강사가 한결물류 라우터에 192.168.10.96/28을 알리게 하고, 필터를 걸기 전과 뒤의 본사 경로표를 보여 줍니다.

| | 필터 전 | 필터 뒤 |
|-|---------|---------|
| 본사 경로표 | `D 192.168.10.96/28 via 192.168.99.10` 이 생긴다 | 생기지 않는다 |
| 다른 VLAN에서 서버로 | 한결물류로 빨려 간다 | 서버로 간다 |

## 4. 알릴 것 고르기: route-map

재분배에 조건을 붙일 때는 route-map을 씁니다. route-map은 "이 목록에 맞으면 이렇게 하라"는 규칙 묶음입니다.

```
route-map TO-LC permit 10
 match ip address prefix-list TO-LC
router eigrp 20
 redistribute ospf 1 metric 100000 100 255 1 1500 route-map TO-LC
```

OSPF에서 EIGRP로 재분배할 때 TO-LC 목록에 맞는 경로(서버 VLAN)만 넘깁니다. 한결물류 라우터의 경로표에는 `D EX 192.168.10.96/27` 한 줄만 남습니다.

반대 방향(EIGRP에서 OSPF로)은 3번 절의 distribute-list가 이미 172.16.10.0/24만 받으므로 그대로 둡니다.

## 5. 이웃 사이에는 인증

```
key chain EIGRPKEY
 key 1
  key-string <실습용 키>
interface gi0/2
 ip authentication mode eigrp 20 md5
 ip authentication key-chain eigrp 20 EIGRPKEY
```

한결물류 라우터의 Gi0/1에도 같은 키를 겁니다. 한쪽만 걸면 이웃이 끊깁니다. 5, 6일차와 같은 원리입니다.

## 6. 길을 숨겨도 문은 열려 있다

경로를 알리지 않으면 한결물류 라우터는 인사팀으로 가는 길을 모릅니다. 그런데 한결물류의 관리자가 자기 라우터에 정적 경로 한 줄(`ip route 192.168.10.0 255.255.255.0 192.168.99.9`)을 넣으면 어떨까요. 패킷은 본사 라우터까지 오고, 본사 라우터는 인사팀으로 가는 길을 알고 있으니 그대로 전달합니다.

| 하는 일 | 막는 것 | 막지 못하는 것 |
|---------|---------|----------------|
| 경로를 알리지 않는다 (오늘) | 상대가 길을 저절로 아는 것 | 상대가 길을 손으로 넣는 것 |
| 경로를 받지 않는다 (오늘) | 상대가 우리 경로표를 흔드는 것 | |
| 패킷을 거른다 (10일차 ACL) | 경계를 넘는 패킷 자체 | |

경로 필터는 지도를 나눠 주지 않는 일이고, 문을 잠그는 일은 아닙니다. 1일차의 심층 방어처럼 두 겹을 겹쳐야 합니다.

> 10일차에 본사 라우터의 Gi0/2로 들어오는 패킷 중 서버 VLAN으로 가는 것만 허락하는 ACL을 겁니다. 그 전에 이 틈으로 실제 접근이 일어나는 장면을 [첫 침해사고 분석 보고서](../incident-report.md)로 씁니다.

## 7. 오늘의 기록

`03_구축/인수회사_연결.md` 를 이렇게 씁니다.

```markdown
# 인수한 회사 연결

## 구성

- 상대: 한결물류, 172.16.10.0/24, EIGRP AS 20
- 연결: HQ-R1 Gi0/2 192.168.99.9/30 - LC-R1 Gi0/1 .10
- 경계 라우터: HQ-R1 (OSPF 1 과 EIGRP 20)

## 재분배

| 방향 | 걸러 내는 것 | 결과 |
|------|--------------|------|
| 한결물류에서 받음 | LC-IN: 172.16.10.0/24 만 | 지사 경로표에 O E2 172.16.10.0/24 |
| 한결물류에 알림 | TO-LC: 서버 VLAN 만 | 한결물류 경로표에 D EX 192.168.10.96/27 |

## 시험

| 시험 | 결과 |
|------|------|
| 한결물류 PC에서 서버로 ping | |
| 한결물류 PC에서 인사팀으로 ping | |
| 한결물류가 서버 /28을 알렸을 때 (강사 시연) | 필터 전: , 필터 뒤: |

## 남은 위험

- 경로 필터는 패킷을 막지 않는다. 한결물류가 정적 경로를 넣으면 인사팀에 닿는다. 10일차 ACL로 막는다
```

## 함께 생각해 보기

- 우리 회사의 신뢰 경계는 어디어디인가요? 인수한 회사 말고도 우리가 관리하지 않는 망과 맞닿은 곳을 찾아봅니다.
- 6번 절에서 한결물류 관리자가 정적 경로를 넣었다면, 우리는 그것을 어떻게 알아챌 수 있을까요?

### 물어볼 것

- "prefix-list에 없는 경로는 어떻게 될까요?" 거부됩니다. 끝에 보이지 않는 거부 줄이 있습니다.
- "경로를 숨기면 인사팀은 안전할까요?" 아닙니다. 6번 절이 답입니다.
- 두 번째 함께 생각해 보기의 답: 경로만으로는 알아채기 어렵습니다. 경계를 지나는 패킷을 기록하고 이상한 목적지를 찾는 일이 필요하고, 10일차 ACL의 로그와 15일차 모니터링에서 합니다.

### 자주 헷갈리는 것

| 헷갈리는 것 | 바로잡기 |
|-------------|----------|
| distribute-list in은 패킷을 막는다 | 경로를 막는다. 패킷은 ACL이 막는다 |
| route-map에 permit만 있으면 나머지도 통과한다 | route-map도 끝에 보이지 않는 거부가 있다. 맞지 않는 경로는 재분배되지 않는다 |
| prefix-list의 /27과 와일드카드 마스크는 같은 표기다 | prefix-list는 /27처럼 프리픽스 길이로, ACL과 OSPF `network` 는 와일드카드 마스크로 쓴다 |

### 진행 요령

- 패킷트레이서가 `ip prefix-list` 나 `distribute-list prefix` 를 받지 않으면, 표준 ACL로 대신합니다(`access-list 10 permit 172.16.10.0 0.0.0.255`, `distribute-list 10 in gi0/2`, route-map의 `match ip address 10`). 수업 전에 확인합니다.
- /28 시연은 강사의 한결물류 라우터에서만 합니다. 학생은 필터가 걸린 상태를 확인합니다.
- 6번 절의 "길을 숨겨도 문은 열려 있다"는 10일차까지 이어지는 질문이라 칠판에 남겨 둡니다.
