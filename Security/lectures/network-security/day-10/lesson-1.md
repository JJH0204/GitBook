## 1. 위에서부터, 처음 맞는 줄에서 끝

ACL(Access Control List)은 규칙의 목록이다. 라우터는 패킷이 오면 목록의 첫 줄부터 비교하고, 처음으로 맞는 줄의 결정(permit 또는 deny)을 따른 뒤 나머지 줄은 보지 않는다.

아파트 경비실의 출입 명부와 같다. 경비원은 명부를 위에서부터 읽다가 방문자의 이름이 나오는 첫 줄에서 들일지 말지 정한다. 명부에 끝까지 이름이 없으면 들이지 않는다.

| 원리 | 뜻 |
|---|---|
| 위에서부터 | 순서가 결과를 바꾼다 |
| 처음 맞는 줄에서 끝 | 아래에 더 맞는 줄이 있어도 보지 않는다 |
| 보이지 않는 마지막 줄 | 어느 줄에도 맞지 않으면 버린다(`deny any`). 화면에는 안 보인다 |

순서가 결과를 바꾸는 예는 다음과 같다.

| 순서 | 10.0.0.1에서 온 패킷 |
|---|---|
| 1. permit host 10.0.0.1, 2. deny 10.0.0.0/24 | 통과. 1번 줄에서 끝 |
| 1. deny 10.0.0.0/24, 2. permit host 10.0.0.1 | 버림. 1번 줄에서 끝, 2번 줄은 보지도 않는다 |

좁은 규칙을 넓은 규칙보다 위에 둔다. 4일차의 "가장 구체적인 줄이 이긴다"는 경로표가 알아서 해 주지만, ACL은 사람이 순서로 정해 줘야 한다.

{% hint style="info" %}
NOTE: 7일차 prefix-list의 끝에도 보이지 않는 거부가 있었다. 1일차의 기본 거부가 장비의 설계에 들어 있는 모습이다.
{% endhint %}

## 2. 표준과 확장

| | 표준 ACL | 확장 ACL |
|---|---|---|
| 보는 것 | 출발지 주소만 | 출발지, 목적지, 프로토콜, 포트 |
| 번호 | 1~99 | 100~199 |
| 거는 자리 | 목적지 가까이 | 출발지 가까이 |
| 새봄상사에서 | 장비 접속 제한(`access-class`), NAT 대상 고르기 | 부서 사이, 인수한 회사 경계 |

표준 ACL은 출발지만 보니, 출발지 가까이 걸면 그 출발지의 모든 통신을 막아 버린다. 그래서 목적지 가까이 건다. 확장 ACL은 목적지와 포트까지 보니 출발지 가까이 걸어, 버릴 패킷이 회사 안을 돌아다니지 않게 한다.

번호 대신 이름을 붙일 수도 있다(`ip access-list extended SALES-IN`). 이 과목은 이름 붙인 ACL을 쓴다. 설정 텍스트에서 무엇을 막는 목록인지 이름만 보고 안다.

## 3. 확장 ACL 한 줄 읽기

```
deny tcp 192.168.10.0 0.0.0.31 host 192.168.10.98 eq 23
```

| 부분 | 뜻 |
|---|---|
| `deny` | 버린다 |
| `tcp` | 프로토콜. ip는 모두, icmp, udp도 쓸 수 있다 |
| `192.168.10.0 0.0.0.31` | 출발지. 6일차의 와일드카드 마스크 (영업팀 /27) |
| `host 192.168.10.98` | 목적지 한 주소. `0.0.0.0` 마스크와 같다 |
| `eq 23` | 목적지 포트가 23(텔넷)일 때 |

`any`는 모든 주소다. 줄 끝에 `log`를 붙이면 그 줄에 맞은 패킷을 장비의 로그에 남긴다. 3번 노트의 사고 01을 이 `log`로 알아챈다.

## 4. 거는 곳과 방향

ACL은 만들기만 해서는 아무 일도 하지 않는다. 포트에 방향을 정해 걸어야 동작한다.

```
interface vlan 10
 ip access-group SALES-IN in
```

| 방향 | 언제 비교하나 |
|---|---|
| in | 패킷이 그 포트로 장비에 들어올 때 |
| out | 패킷이 그 포트로 장비에서 나갈 때 |

방향은 장비의 자리에서 본다. 영업팀 PC가 보낸 패킷은 HQ-DSW1의 `interface vlan 10`으로 들어오니 in이다. 포트 하나에 방향마다 ACL을 하나씩만 걸 수 있다.

## 5. 줄 번호로 끼워 넣기

이름 붙인 ACL의 줄에는 10, 20, 30처럼 번호가 붙는다. 10씩 띄우는 이유는 사이에 끼워 넣을 자리를 남기기 위해서다.

9일차 기록의 남은 위험에 "장비 관리 VLAN도 NAT-INSIDE에 들어 있어 인터넷에 나갈 수 있다"고 적었다. 장비는 인터넷에 나갈 일이 없다. NAT-INSIDE의 맨 위에 거부 줄을 끼워 넣는다.

```
ip access-list standard NAT-INSIDE
 5 deny 192.168.10.128 0.0.0.31
```

```
HQ-R1#show access-lists NAT-INSIDE
Standard IP access list NAT-INSIDE
    5 deny 192.168.10.128 0.0.0.31
    10 permit 192.168.10.0 0.0.0.255
    20 permit 192.168.20.0 0.0.0.255
```

5번 줄이 10번 줄보다 위에 들어갔다. 순서가 바뀌어 거부가 아래에 있었다면 10번 줄(본사 /24)에 먼저 걸려 아무 일도 하지 않았을 것이다.

{% hint style="info" %}
NOTE: NAT-INSIDE에서 `deny`는 패킷을 버리는 것이 아니라 "주소를 바꿔 주지 않는다"는 뜻이다. 변환되지 않은 사설 주소는 인터넷 쪽에서 버려지므로 결과는 인터넷에 나가지 못하는 것과 같다. 패킷을 장비에서 직접 막으려면 이 노트의 확장 ACL을 쓴다.
{% endhint %}

## 약어·용어

| 용어 | 뜻 |
|---|---|
| ACL (Access Control List) | 패킷을 통과(permit)시키거나 버리는(deny) 규칙의 목록 |
| 보이지 않는 거부 (implicit deny) | 목록의 어느 줄에도 맞지 않는 패킷을 버리는, 화면에 보이지 않는 마지막 줄 |
| 표준 ACL (standard) | 출발지 주소만 보는 ACL. 번호 1~99 |
| 확장 ACL (extended) | 출발지, 목적지, 프로토콜, 포트를 보는 ACL. 번호 100~199 |
| 와일드카드 마스크 (wildcard mask) | 비교할 비트를 0, 무시할 비트를 1로 쓰는 마스크. /27은 0.0.0.31 |
| `access-group` | ACL을 포트와 방향에 거는 명령 |

### 물어볼 것

- "ACL에 아무 줄도 맞지 않는 패킷은 어떻게 될까?" 버려진다. 보이지 않는 마지막 줄이다.
- "표준 ACL을 영업팀 쪽에 걸면 무엇이 문제일까?" 영업팀이 보내는 모든 것이 막힌다.
- 첫 번째 함께 생각해 보기의 답: 닿지 않는다. 텔넷 말고는 맞는 줄이 없어 보이지 않는 거부에 걸린다. 거부 줄만 쓴 ACL은 모든 것을 막는다.

### 자주 헷갈리는 것

| 헷갈리는 것 | 바로잡기 |
|---|---|
| 가장 잘 맞는 줄을 찾아 적용한다 | 처음 맞는 줄에서 끝난다. 경로표와 다르다 |
| ACL을 만들면 바로 걸린다 | `ip access-group`으로 포트와 방향에 걸어야 한다 |
| ACL은 서브넷 마스크로 쓴다 | 와일드카드 마스크로 쓴다. /27은 0.0.0.31 |
| 마지막에 `deny any`를 꼭 써야 한다 | 보이지 않게 이미 있다. 다만 `log`를 붙여 무엇이 버려지는지 보고 싶으면 직접 쓴다 |

### 진행 요령

- 5번 절은 끼워 넣기의 첫 경험이라 `show access-lists`로 순서를 꼭 확인시킨다.
