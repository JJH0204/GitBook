## 학습 목표

- 막기 전에 기록부터 거는 감시용 ACL로 실제 흐름을 본다.
- 로그와 적중 횟수로 사고를 알아채고, 증거를 파일로 남긴다.
- 경계에 확장 ACL을 걸어 막고, 막는 조치가 만든 장애까지 기록한다.
- 첫 침해사고 분석 보고서의 칸을 어디서 채우는지 안다.

## 목적

7일차 4번 노트의 마지막 절 제목은 "길을 숨겨도 문은 열려 있다"였다. 한결물류에 인사팀으로 가는 경로를 알려 주지 않았지만, 한결물류 관리자가 자기 라우터에 정적 경로 한 줄만 넣으면 패킷은 본사 라우터까지 오고, 본사 라우터는 인사팀으로 가는 길을 알고 있으니 그대로 넘겨 준다고 했다. 그리고 `03_구축/인수회사_연결.md`의 남은 위험 칸에 적었다.

남은 위험은 적어 두는 것으로 끝나지 않는다. 오늘 그 위험이 실제로 일어난다.

{% hint style="danger" %}
WARNING: 이 노트의 "공격 역할"(한결물류 관리자가 정적 경로를 넣는 일)은 자기 실습 파일의 시뮬레이터 안(가상 장비)에서만 한다. 허가받지 않은 시스템에 이 절차를 수행하는 것은 불법이다.
{% endhint %}

## 1. 상황

강사는 수업 전에 한결물류 관리자 역할로 LC-R1에 정적 경로를 넣어 둔다. 배송 주소를 확인하려고 인사팀 자료를 보고 싶었다는 설정이다.

```
LC-R1(config)#ip route 192.168.10.0 255.255.255.0 192.168.99.9
```

새봄상사의 네트워크 담당자는 이 사실을 모른다. 담당자가 아는 것은 오늘 경계에 ACL을 건다는 계획뿐이다. 학생도 자기 파일에서는 한결물류 관리자 역할로 이 줄을 먼저 넣고, 그다음 새봄상사 담당자로 돌아온다.

## 2. 막기 전에 보기: 감시용 ACL

경계에 바로 거부 ACL을 걸면, 한결물류의 정상 업무까지 끊을 수 있다. 무엇이 실제로 오가는지 모르는 채 막는 것이기 때문이다. 그래서 먼저 모두 허락하면서 기록만 하는 ACL을 건다.

```
ip access-list extended LC-WATCH
 10 permit eigrp host 192.168.99.10 any
 20 permit ip 172.16.10.0 0.0.0.255 192.168.10.96 0.0.0.31
 30 permit ip any any log
interface gi0/2
 ip access-group LC-WATCH in
```

| 줄 | 뜻 |
|---|---|
| 10 | 한결물류 라우터의 EIGRP 알림. 5초마다 오니 기록에서 뺀다 |
| 20 | 서버 VLAN으로 가는 것. 업무라 기록하지 않는다 |
| 30 | 그 밖의 모든 것은 통과시키되 기록한다 |

모두 통과시키니 아무것도 끊지 않는다. 30번 줄의 적중 횟수와 로그가 "업무 밖의 통신"이 있는지 알려 준다.

## 3. 탐지

강사가 한결물류 직원 역할로 LC-PC1에서 인사팀 PC로 ping을 입력한다. 본사 라우터의 화면에 기록이 뜬다.

```
%SEC-6-IPACCESSLOGDP: list LC-WATCH permitted icmp 172.16.10.10 -> 192.168.10.42 (8/0), 1 packet
```

```
HQ-R1#show access-lists LC-WATCH
Extended IP access list LC-WATCH
    10 permit eigrp host 192.168.99.10 any (31 matches)
    20 permit ip 172.16.10.0 0.0.0.255 192.168.10.96 0.0.0.31
    30 permit ip any any log (4 matches)
```

| 읽을 것 | 뜻 |
|---|---|
| `172.16.10.10 -> 192.168.10.42` | 한결물류 PC에서 인사팀 PC로 |
| `icmp ... (8/0)` | ping 요청(종류 8) |
| 30번 줄 `(4 matches)` | 업무 밖의 통신이 네 번 |

이것이 탐지다. 사람이 이상하다고 느끼기 전에 장비의 기록이 먼저 알려 줬다.

## 4. 증거를 남긴다

장비를 고치면 고치기 전의 화면은 다시 볼 수 없다. 막기 전에 먼저 저장한다.

| 증거 파일 | 담는 것 | 어디서 |
|---|---|---|
| `증거/01_acl_log.txt` | 위의 로그 줄과 시각 | HQ-R1 CLI 화면 |
| `증거/01_acl_count.txt` | `show access-lists LC-WATCH` | HQ-R1 |
| `증거/01_lc-r1_route.txt` | `show ip route static`의 `S 192.168.10.0/24 ... via 192.168.99.9` | LC-R1 (상대 회사의 협조를 받았다고 정한다) |

파일 이름 앞에 사고 번호(01)를 붙여, 사고가 여러 건 쌓여도 섞이지 않게 한다. 시각은 패킷트레이서 화면의 시계가 아니라 수업 시계로 적어도 된다. 중요한 것은 일의 순서다.

## 5. 판정과 막기

판정은 정탐이다. 한결물류의 업무(배송 처리)에 인사팀 접근은 필요 없다. 정책표의 "한결물류에서 서버 VLAN만 허락" 줄을 그대로 건다.

```
ip access-list extended LC-IN
 10 permit ip 172.16.10.0 0.0.0.255 192.168.10.96 0.0.0.31
 20 deny ip any any log
interface gi0/2
 no ip access-group LC-WATCH in
 ip access-group LC-IN in
```

1분이 지나지 않아 본사 라우터에 이런 줄이 뜬다.

```
%DUAL-5-NBRCHANGE: EIGRP-IPv4 20: Neighbor 192.168.99.10 (GigabitEthernet0/2) is down: holding time expired
```

LC-WATCH에는 있던 EIGRP 허락 줄을 LC-IN에서 빠뜨렸다. 한결물류 라우터의 EIGRP 알림이 20번 줄에 걸려 버려지니, 15초 뒤 이웃이 끊기고 한결물류와의 경로가 모두 사라졌다. 막으려던 것은 인사팀 접근이었는데 서버로 가는 배송 업무까지 멈췄다. 1번 노트의 끼워 넣기로 고친다.

```
ip access-list extended LC-IN
 5 permit eigrp host 192.168.99.10 any
```

이웃이 다시 맺어지면 확인한다.

| 시험 | 결과 |
|---|---|
| LC-PC1에서 인사팀 PC로 ping | 닿을 수 없음. LC-IN 20번 줄 적중 |
| LC-PC1에서 서버로 ping | Reply |
| `show ip eigrp neighbors` | 192.168.99.10 |

{% hint style="info" %}
NOTE: 6일차 OSPF 인증을 걸 때 "한쪽만 걸면 이웃이 끊기니 작업 계획서에 잠시 끊김을 적는다"고 했다. 라우팅 알림이 지나가는 포트에 ACL을 걸 때도 같은 자리를 조심한다.
{% endhint %}

막는 조치가 만든 장애도 사고의 일부다. 보고서의 타임라인에 그대로 적는다. 숨기지 않은 실수가 다음 사람을 지켜 준다.

## 6. 보고서를 쓴다

[침해사고 분석 보고서](../incident-report.md)의 칸을 오늘 무엇으로 채우는지 본다. 새봄상사 예시가 양식 문서 5번 절에 있다.

| 칸 | 오늘 어디서 가져오나 |
|---|---|
| 요약 | 무슨 일, 원인, 한 일 세 문장 |
| 탐지 | 3번 절. 언제, LC-WATCH의 로그와 적중 횟수, 누가 |
| 타임라인 | 7일차 결정부터 이웃 복구까지 시각 순서대로 |
| 분석 | 경로, 판정(정탐), 근거(로그 줄, LC-R1 경로), 확인하지 못한 것 |
| 영향 | 인사팀 VLAN, 장비 관리 VLAN의 기밀성 |
| 원인 | 기술: 경로 필터만 걸었다. 관리: 연결 규정이 없었다 |
| 대응 | 즉시: LC-IN과 커밋 해시. 근본: 연결 규정 |
| 재발 방지와 남은 위험 | 4번 노트의 돌아오는 길, 13일차 서버 방화벽 |
| 교훈 | 잘한 것, 아쉬운 것 |

오늘 개인 실습의 20분 동안 요약, 탐지, 타임라인, 분석까지 사실을 먼저 적고 커밋한다. 원인과 재발 방지, 교훈은 11일차 작업 계획서 시간에 다듬는다.

근본 대응으로 `01_요구사항/인수회사_연결_규정.md`를 짧게 쓴다.

```markdown
# 인수한 회사 연결 규정

- 연결 구간(192.168.99.8/30)과 한결물류 라우터의 경로 변경은 새봄상사에 미리 알린다
- 한결물류는 새봄상사의 서버 VLAN 만 쓴다. 그 밖의 접근은 경계(HQ-R1 Gi0/2)에서 막는다
- 경계 ACL 의 거부 기록은 매주 확인한다 (15일차부터 모니터링)
```

## 7. 탐지·방어

확인 상태: 미검증 (일반 지식으로 짧게 정리했다).

| 항목 | 내용 |
|---|---|
| 원인 | 경계에서 경로 정보만 거르고 패킷은 거르지 않았다. 상대 회사가 자기 라우터에 정적 경로를 넣으면 우리 쪽 경로표가 그 패킷을 그대로 넘긴다. 연결 규정이라는 관리 통제도 없었다 |
| 완화 | 신뢰 경계에는 "필요한 것만 여는" ACL을 건다. 적용 전에 감시용 ACL로 실제 흐름을 먼저 본다. 라우팅 프로토콜 알림은 ACL의 첫 줄에서 허락한다. 연결 규정으로 상대 설정의 변경을 미리 알리게 한다 |
| 로그에서 보이는 흔적 | `%SEC-6-IPACCESSLOGDP`의 출발지가 연결 대역(172.16.10.0/24)이고 목적지가 업무 대역 밖인 줄. `show access-lists`의 30번 줄(`permit ip any any log`) 적중 횟수 증가. 막은 뒤에는 LC-IN 20번 줄 적중 횟수와 `%DUAL-5-NBRCHANGE` |

## 약어·용어

| 용어 | 뜻 |
|---|---|
| 감시용 ACL | 모두 허락하면서 업무 밖의 통신만 `log`로 기록하는 ACL. 막기 전에 실제 흐름을 본다 |
| 탐지 (detection) | 장비의 기록으로 이상한 통신을 알아채는 일 |
| 증거 (evidence) | 고치기 전의 화면과 기록을 텍스트로 저장한 파일 |
| 정탐 / 오탐 | 실제 사고로 확인된 경보 / 사고가 아닌데 울린 경보 |
| 신뢰 경계 | 우리가 관리하지 않는 망과 맞닿은 자리. 이 과목에서는 HQ-R1 Gi0/2 |
| EIGRP 이웃 (neighbor) | EIGRP 알림을 주고받는 인접 라우터. 알림이 끊기면 15초 뒤 끊어진다 |

### 물어볼 것

- "로그가 뜨기 전에 이 접근을 알 방법이 있었을까?" 없었다. 그래서 막기 전에 보는 단계가 필요하다.
- "EIGRP 이웃이 왜 끊겼을까?" 보이지 않는 거부가 아니라 20번 줄이 라우팅 알림까지 버렸다.
- 첫 번째 함께 생각해 보기의 답: 막혔으니 피해는 없었겠지만, 한결물류가 인사팀을 노렸다는 사실은 영영 몰랐을 것이다. 원인(정적 경로, 연결 규정 없음)을 모르면 같은 틈이 다른 곳에서 다시 열린다.

### 자주 헷갈리는 것

| 헷갈리는 것 | 바로잡기 |
|---|---|
| 감시용 ACL은 아무 일도 안 한다 | 아무것도 막지 않을 뿐, 기록과 적중 횟수를 남긴다 |
| 포트에 ACL 두 개를 함께 건다 | 방향마다 하나뿐이다. LC-WATCH를 떼고 LC-IN을 건다 |
| 보고서는 다 고친 뒤에 한 번에 쓴다 | 증거는 고치기 전에, 사실은 그날, 원인과 교훈은 다음 회차에 |
| LC-R1의 정적 경로를 지우면 끝이다 | 상대 회사의 설정은 우리가 지킬 수 없다. 우리 경계에서 막는 것이 즉시 대응이다 |

### 진행 요령

- 패킷트레이서가 ACL `log`의 로그를 띄우지 않으면 적중 횟수만으로 탐지한다. 수업 전에 확인하고, 로그가 안 뜨면 3번 절의 로그 줄은 "실제 장비라면 이렇게 뜬다"로 보여 준다.
- 학생 파일에서는 학생이 먼저 한결물류 관리자 역할(정적 경로)을 하고, 그다음 새봄상사 담당자로 탐지와 대응을 한다. 역할을 바꾸는 순간을 분명히 말해 준다.
- 공격 역할은 자기 실습 파일 안에서만 한다. 1일차의 실습 약속을 한 번 다시 말한다.
