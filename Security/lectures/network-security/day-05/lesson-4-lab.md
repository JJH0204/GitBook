## 5. 절차

### A. 내 회사로 RIP 바꾸기 (대본 9번)

1. (5-A-01) [2-1 실습](lesson-2-lab.md)의 구역 A~E를 내 주소로 한다. `network`에는 내 본사, 지사, 연결 대역의 클래스 단위 주소를 적는다. → 결과: 두 라우터의 `show ip route rip`에 상대 쪽 네트워크가 R 줄로 보인다.
2. (5-A-02) [3-1 실습](lesson-3-lab.md)의 구역 B(passive)와 구역 C(인증)를 한다. 구역 A(거짓 경로 시연)는 하지 않는다. → 결과: 사무실 쪽 포트가 passive이고, RIP이 켜진 포트에 인증이 걸려 있다.
3. (5-A-03) 창고 네트워크는 내 지사 /24 안의 두 번째 /27로 만든다. 루프백 마스크는 `255.255.255.224`로 준다. → 결과: 본사 경로표에 그 /27이 R 줄로 보인다.

### B. 장애 시험과 시험 결과 모으기 (대본 10번)

1. (5-B-01) 2-1 실습의 구역 E를 내 망에서 한다. BR 쪽 PC에서 `ping -t`를 걸고 본사 주 회선을 끈다.
2. (5-B-02) 빠진 ping 개수를 센다. → 결과: 숫자 하나를 얻는다.
3. (5-B-03) 창고 네트워크를 만든 뒤 본사 경로표에 나타나기까지 걸린 초를 적는다. → 결과: 숫자 하나를 얻는다.
4. (5-B-04) 주 회선을 `no shutdown`으로 되살린다. → 결과: R 줄이 돌아온다.

### C. 비교 기록 쓰기 (대본 10번)

1. (5-C-01) VS Code에서 `03_구축/라우팅_비교.md`를 만든다.
2. (5-C-02) [4번 노트](lesson-4.md)의 2절 양식을 붙여 넣는다.
3. (5-C-03) 비교 표를 내 회사 기준으로 고친다.
4. (5-C-04) 시험 결과 표의 `__` 칸을 5-B에서 얻은 숫자로 채운다. → 결과: 빈칸이 없다.
5. (5-C-05) 결정 칸에 내 회사의 선택과 이유를 한 줄 쓴다. → 결과: 파일이 저장된다.

### D. 설정 텍스트 (대본 11번)

1. (5-D-01) HQ-R1과 BR-R1에서 `show running-config`를 입력하고 출력을 복사한다.
2. (5-D-02) `configs/HQ-R1.txt`와 `configs/BR-R1.txt`를 덮어쓴다.
3. (5-D-03) Git Bash에서 `git diff configs/HQ-R1.txt`를 입력한다. → 결과: 정적 경로 줄이 빠지고 `router rip`, `key chain` 줄이 생긴 것이 보인다.

### E. 결과 기록과 커밋 (대본 12번)

1. (5-E-01) `00_작업계획/05일차.md`의 결과 칸(한 일, 확인 결과, 막힌 곳, 다음 회차에 이어서 할 일)을 채운다.
2. (5-E-02) `README.md`의 진행 현황에 한 줄을 더한다.

```markdown
| 5 | 정적에서 RIPv2로, passive와 인증, 두 방식 비교 | [작업 계획서](00_작업계획/05일차.md), [라우팅 비교](03_구축/라우팅_비교.md), [설정](configs/) |
```

3. (5-E-03) 변경을 스테이지에 올린다: `git add .`
4. (5-E-04) 커밋한다: `git commit -m "5일차: RIPv2 전환, passive와 인증, 정적과 비교"` → 결과: 커밋 해시가 출력된다.
5. (5-E-05) GitHub로 보낸다: `git push` → 결과: `main -> main` 줄이 보인다.

## 7. 복구

1. (7-01) RIP이 꼬이면 `no router rip`으로 지우고 `configs/`의 4일차 설정에서 정적 경로를 다시 넣는다.
2. (7-02) 인증으로 지사 경로가 돌아오지 않으면 양쪽 `no ip rip authentication mode md5`로 푼 뒤 key-string을 글자 하나까지 맞춰 다시 건다.
3. (7-03) 마지막 커밋을 잘못했으면 push 전에는 `git reset --soft HEAD~1`로 커밋만 되돌린다.
