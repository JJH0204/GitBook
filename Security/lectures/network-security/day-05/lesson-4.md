## 학습 목표

- 정적 경로와 RIP을 같은 기준으로 비교해 문서로 남긴다.
- `git diff`로 오늘 바뀐 설정을 읽는다.
- 새봄상사가 6일차에 OSPF를 실험하는 이유를 안다.

## 목적

4일차와 5일차에 같은 망을 두 가지 방법으로 움직였다. 어느 쪽이 나은지는 회사의 사정에 따라 다르다. 회사에서 이런 결정을 내릴 때는 기준을 세워 비교한 문서가 남는다. 오늘의 마지막 산출물이 그 문서다.

## 1. 비교 기준

| 기준 | 정적 경로 (4일차) | RIPv2 (5일차) |
|---|---|---|
| 설정의 양 | 본사 2줄, 지사 2줄 | 라우터마다 RIP, passive, 인증 설정 |
| 네트워크가 늘면 | 상대 라우터에 줄을 더한다 | 저절로 퍼진다 (창고 네트워크) |
| 주 회선 포트가 꺼지면 | 바로 예비로 넘어간다 | 바로 예비로 넘어간다 |
| 중간 장비가 고장 나면 | 모른다 | 180~240초 뒤 안다 |
| 회선 속도 | 사람이 정한다 | 모른다 (예비 회선을 똑같이 1홉으로 봄) |
| 보안 | 설정 권한만 지키면 된다 | 거짓 광고를 막으려 passive와 인증이 필요하다 |
| 회선에 흐르는 것 | 없다 | 30초마다 경로 알림 |

어느 쪽이 무조건 낫지 않다. 새봄상사처럼 라우터 두 대에 길이 뻔한 망은 정적 경로로도 충분하다. 다만 7일차에 인수한 회사가 붙고 길이 많아지면 동적 라우팅이 필요해진다.

## 2. 오늘의 기록

`03_구축/라우팅_비교.md`를 이렇게 쓴다.

```markdown
# 라우팅 방식 비교

## 비교한 것

- 4일차: 정적 경로 (주 회선, 관리 거리 250 예비 경로)
- 5일차: RIPv2 (주 회선, 예비 회선 passive, 예비 정적 경로 유지)

## 비교 표

(1번 절의 표를 내 회사 기준으로)

## 시험 결과

| 시험 | 정적 | RIP |
|------|------|-----|
| 지사에 새 네트워크를 만들었을 때 본사가 아는가 | 줄을 넣어야 함 | __초 뒤 R 줄 |
| 주 회선 shutdown 때 빠진 ping 수 | __개 | __개 |
| 영업팀 자리에서 거짓 경로를 알렸을 때 | 해당 없음 | 인증 전: 받아들임, 인증 뒤: 버림 |

## 결정

- 지금은 RIPv2를 쓴다
- RIP이 회선 속도를 모르는 문제는 6일차에 OSPF를 브랜치에서 실험해 비교한다
```

## 3. git diff로 오늘을 읽기

오늘 저녁 설정 텍스트를 덮어쓴 뒤 커밋하기 전에 본다.

```bash
git diff configs/HQ-R1.txt
```

```
-ip route 192.168.20.0 255.255.255.224 192.168.99.2
-ip route 192.168.20.0 255.255.255.224 192.168.99.6 250
+ip route 192.168.20.0 255.255.255.0 192.168.99.6 250
+router rip
+ version 2
+ passive-interface GigabitEthernet0/0.10
...
+ network 192.168.10.0
+ network 192.168.99.0
+ no auto-summary
```

빠진 줄(-)과 생긴 줄(+)만 보면 오늘 무엇을 바꿨는지 한눈에 들어온다. 1일차에 Git을 쓰는 이유로 든 "바뀐 기록"이 이것이다. 장비 설정에서 줄의 순서는 장비가 정하므로, 내가 입력한 순서와 다를 수 있다.

## 약어·용어

| 용어 | 뜻 |
|---|---|
| 비교 기준 | 두 방식을 같은 잣대로 견주는 항목(설정의 양, 확장, 장애 감지, 속도, 보안 등) |
| 시험 결과 | 비교 기준을 실제 망에서 시험해 얻은 값 |
| `git diff` | 커밋하지 않은 변경에서 빠진 줄(-)과 생긴 줄(+)을 보는 명령 |

## 함께 생각해 보기

- 우리 회사가 지사를 열 곳으로 늘린다면 정적과 RIP 중 무엇을 고르겠는가? 비교 표의 어느 줄이 결정을 좌우했나?

## 강의 메모

### 시간 배분 (30분)

| 절 | 시간 | 방식 |
|---|---|---|
| 목적, 1 비교 기준 | 12분 | 표를 같이 채운다. 학생에게 줄을 하나씩 말하게 한다 |
| 2 기록 양식 | 8분 | 개인 실습에서 채울 칸을 짚는다 |
| 3 git diff | 10분 | 강사 저장소에서 실제로 diff를 띄운다 |

### 물어볼 것

- "정적 경로가 RIP보다 나은 점은 무엇이었나?" 설정이 단순하고, 밖에서 거짓 경로를 넣을 틈이 없다.
- "RIP을 쓰면서 가장 불편했던 점은?" 대개 회선 속도를 모르는 것과 인증 설정이다. 6일차로 넘기는 질문이다.

### 진행 요령

- 비교 표는 학생 회사의 시험 결과로 채워야 의미가 있다. 빈칸을 남기지 않게 개인 실습에서 확인한다.
- `git diff`의 줄 순서가 입력한 순서와 다르다는 질문이 나온다. 장비가 설정을 정리해 보여 주기 때문이다.
