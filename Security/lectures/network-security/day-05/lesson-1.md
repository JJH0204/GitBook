## 학습 목표

- 라우터끼리 경로를 알려 주는 동적 라우팅이 필요한 이유를 안다.
- RIP이 이웃에게 30초마다 경로표를 알리고 홉 수로 길을 고른다는 것을 안다.
- RIP의 한계(회선 속도를 모름, 15홉)를 안다.
- RIP 버전 1과 2의 차이를 안다.

## 목적

4일차 장애 시험의 마지막에 한계를 하나 적었다. 정적 경로는 내 포트가 꺼져야만 회선이 끊긴 것을 알고, 중간 장비가 고장 나면 모른다. 그리고 지사에 네트워크가 하나 늘 때마다 본사 라우터에 사람이 줄을 넣어야 한다.

라우터끼리 "나는 이런 네트워크를 알고 있다"고 서로 알려 주면 두 문제가 함께 풀린다. 이것이 동적 라우팅이다.

## 1. 정적과 동적

| | 정적 라우팅 | 동적 라우팅 |
|---|---|---|
| 경로를 아는 방법 | 관리자가 줄마다 넣는다 | 라우터끼리 알려 준다 |
| 네트워크가 늘면 | 라우터마다 줄을 더한다 | 저절로 퍼진다 |
| 길이 끊기면 | 내 포트가 꺼져야 안다 | 이웃의 소식이 끊기면 안다 |
| 라우터의 일 | 거의 없다 | 알리고, 듣고, 계산한다 |
| 보안 | 밖에서 바꿀 틈이 없다 | 거짓 정보를 받을 수 있어 지켜야 한다 |

동적 라우팅의 방법(프로토콜)은 여럿이다. 이 과목에서는 5일차 RIP, 6일차 OSPF, 7일차 EIGRP를 차례로 같은 새봄상사 망에 얹어 본다.

## 2. RIP은 이웃에게 소문을 낸다

RIP(Routing Information Protocol)은 가장 단순한 동적 라우팅이다. 라우터가 30초마다 자기 경로표를 이웃 라우터에게 알린다. 이웃은 받은 표에 "한 칸 더"를 더해 자기 표에 넣고, 다시 자기 이웃에게 알린다.

```
BR-R1 : "192.168.20.0/27 은 내게 붙어 있다"
            |  30초마다 알림
            v
HQ-R1 : "192.168.20.0/27 은 BR-R1 을 거쳐 1칸"   ->  경로표에 R 줄
```

동네 소문과 비슷하다. 옆집이 "우리 골목 끝에 빵집이 있다"고 말해 주면, 나는 "옆집을 거쳐 한 골목 가면 빵집"이라고 기억하고 다음 집에 전한다. 나는 빵집까지의 길을 직접 본 적이 없고, 이웃의 말을 믿을 뿐이다. 이 믿음이 3번 노트에서 보안 문제가 된다.

이렇게 이웃에게 들은 거리와 방향으로 길을 고르는 방식을 거리 벡터(distance vector) 방식이라고 한다.

## 3. 홉 수로 고른다

RIP은 목적지까지 거치는 라우터의 수(홉 수)를 메트릭으로 쓴다.

| 목적지 | 홉 수 | 경로표에서 |
|---|---|---|
| 라우터에 직접 붙은 네트워크 | 0 | C 줄 |
| 이웃 라우터에 붙은 네트워크 | 1 | `R ... [120/1]` |
| 이웃의 이웃에 붙은 네트워크 | 2 | `R ... [120/2]` |
| 16칸 이상 | 갈 수 없음 | 표에서 빠진다 |

`[120/1]`의 120은 4일차에 본 RIP의 관리 거리, 1은 홉 수다.

홉 수만 보기 때문에 RIP은 회선의 속도를 모른다.

| 길 | 홉 수 | 실제 속도 | RIP의 선택 |
|---|---|---|---|
| 시리얼 2 Mbps로 바로 | 1 | 느리다 | 이 길 |
| 1 Gbps로 라우터 하나를 더 거쳐 | 2 | 훨씬 빠르다 | 버린다 |

새봄상사의 주 회선(1 Gbps)과 예비 회선(시리얼)도 RIP에게는 둘 다 1칸이다. 오늘 실습에서 RIP이 두 회선을 번갈아 쓰려는 장면을 직접 본다.

16칸을 "갈 수 없음"으로 정해 둔 것은 경로가 라우터 사이를 끝없이 도는 것을 막으려는 장치다. 대신 RIP은 큰 망에는 쓸 수 없다.

## 4. 끊긴 길을 알아채는 시간

| 시간 | 일어나는 일 |
|---|---|
| 30초마다 | 이웃에게 경로표를 알린다 |
| 180초 동안 소식이 없으면 | 그 이웃을 거친 경로를 믿지 않는다 |
| 240초가 지나면 | 경로를 표에서 지운다 |

정적 경로와 달리 RIP은 중간 장비가 고장 나서 이웃의 소식이 끊겨도 알아챈다. 다만 몇 분이 걸린다. 회사 업무가 몇 분 멈춰도 되는지가 RIP을 쓸지의 기준이 된다.

{% hint style="info" %}
NOTE: 6일차 OSPF는 이웃과 10초마다 안부를 주고받아 훨씬 빨리 알아챈다.
{% endhint %}

## 5. 버전 1과 2

| | RIPv1 | RIPv2 |
|---|---|---|
| 마스크를 함께 알리나 | 아니다. 클래스 단위로만(클래스풀) | 알린다(클래스리스) |
| /27 같은 쪼갠 네트워크 | 큰 네트워크의 경계를 넘을 때 /24로 뭉쳐 알린다 | 그대로 알린다 |
| 알리는 방법 | 브로드캐스트(모두에게) | 멀티캐스트 224.0.0.9 (RIP 라우터에게만) |
| 인증 | 없다 | 있다 |

새봄상사는 2일차에 /24를 /27로 쪼갰다. 버전 1은 마스크를 알리지 않아, 본사의 /27 다섯 개를 지사에 192.168.10.0/24 하나로 뭉쳐 알린다. 지금은 우연히 통하지만, 크기가 다른 네트워크가 섞이거나 같은 /24가 여러 곳에 흩어지면 엉뚱한 길이 생긴다. 그리고 버전 1에는 인증이 없어 3번 노트에서 볼 보안 설정을 할 수 없다. 그래서 버전 2를 쓴다.

버전 2도 처음에는 경계에서 클래스 단위로 묶어 알리는 자동 요약이 켜져 있다. `no auto-summary`로 꺼서 /27을 그대로 알리게 한다.

두 라우터의 버전이 다르면 한쪽 또는 양쪽이 상대의 알림을 받지 않아 경로가 오가지 않는다. 버전은 늘 양쪽을 맞춘다.

## 약어·용어

| 용어 | 뜻 |
|---|---|
| 동적 라우팅 (dynamic routing) | 라우터끼리 경로를 알려 주어 경로표를 자동으로 채우는 방식 |
| RIP (Routing Information Protocol) | 30초마다 경로표를 알리고 홉 수로 길을 고르는 단순한 동적 라우팅 |
| 거리 벡터 (distance vector) | 이웃에게 들은 거리와 방향으로 길을 고르는 방식 |
| 홉 수 (hop count) | 목적지까지 거치는 라우터의 수. RIP의 메트릭. 16은 도달 불가 |
| 관리 거리 (administrative distance) | 경로를 배운 방법의 신뢰도. RIP은 120 |
| 클래스풀 / 클래스리스 | 마스크를 알리지 않는 방식 / 알리는 방식 |
| 자동 요약 (auto-summary) | 클래스 경계에서 /24 같은 큰 단위로 뭉쳐 알리는 동작 |

## 함께 생각해 보기

- 우리 회사가 지사를 열 곳으로 늘린다면, 정적 경로와 RIP 중 어느 쪽이 편할까? 지사가 모두 본사에만 이어진다면 어떨까?
- RIP 라우터가 이웃의 말을 확인 없이 믿는다면, 누가 거짓말을 할 때 무슨 일이 생길까?

### 물어볼 것

- "옆집 말만 듣고 빵집 위치를 기억한 나는 빵집을 직접 봤을까?" 아니다. 동적 라우팅은 이웃의 말을 믿는 구조다.
- "RIP은 2 Mbps 한 칸과 1 Gbps 두 칸 중 어디로 갈까?" 한 칸이다. 홉 수만 본다.
- 첫 번째 함께 생각해 보기의 답: 지사가 모두 본사에만 이어지는 별 모양이면 지사는 기본 경로 하나로 충분하고, 본사에만 지사 수만큼 줄이 늘어난다. 지사끼리도 이어지고 길이 여럿이면 동적 라우팅이 편하다.
- 두 번째 함께 생각해 보기의 답: 거짓 경로를 따라 통신이 엉뚱한 곳으로 간다. 3번 노트의 주제다.

### 자주 헷갈리는 것

| 헷갈리는 것 | 바로잡기 |
|---|---|
| 직접 연결된 네트워크가 1홉이다 | 직접 연결은 0이고 C 줄로 보인다. 이웃 라우터에 붙은 네트워크가 1홉이다 |
| `[120/1]`의 120이 홉 수다 | 120은 관리 거리, 1이 홉 수다 |
| RIP은 빠른 길을 고른다 | 홉 수가 적은 길을 고른다. 속도는 모른다 |
| 버전 2는 버전 1과 섞어 써도 된다 | 섞으면 알림을 받지 않는 쪽이 생긴다. 양쪽을 맞춘다 |

### 진행 요령

- RIP은 현장에서 거의 쓰지 않는다. 오늘 RIP을 배우는 이유는 동적 라우팅의 기본 생각(이웃에게 알린다, 이웃을 믿는다)을 가장 단순한 형태로 보고, 그 믿음을 어떻게 지키는지 연습하기 위해서라고 처음에 말해 둔다.
- 네트워크관리사 필기에는 RIP의 15홉, 30초, 거리 벡터가 자주 나온다.
