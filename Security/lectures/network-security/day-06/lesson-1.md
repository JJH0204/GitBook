# 1. OSPF: 소문 대신 지도

> 상위: [6일차 OSPF와 Git 브랜치](README.md)
> 드로잉: 1. OSPF: 소문 대신 지도 드로잉 (9장)

## 학습 목표

- RIP(거리 벡터)과 OSPF(링크 상태)의 차이를 소문과 지도로 설명합니다
- OSPF가 회선 속도로 비용을 매겨 길을 고른다는 것을 압니다
- 이웃 관계(hello)와 그 조건, 끊김을 알아채는 시간을 압니다
- 라우터 ID, 에어리어, DR과 BDR이 무엇인지 압니다

## 다리 놓기

5일차에 RIP의 약점 두 가지를 보았습니다. 1 Gbps 주 회선과 시리얼 예비 회선을 똑같이 1홉으로 보았고, 중간 장비의 고장을 알아채는 데 3~4분이 걸립니다. 그래서 예비 회선을 passive로 막고 정적 예비 경로로 버텼습니다.

오늘은 이 두 약점이 없는 OSPF를 새봄상사 망에 얹어 봅니다. 다만 RIP을 지우고 바로 바꾸지 않고, Git 브랜치에서 실험한 뒤 비교해서 정합니다.

## 1. 소문과 지도

| | RIP (거리 벡터) | OSPF (링크 상태) |
|-|-----------------|------------------|
| 이웃에게 알리는 것 | 내 경로표. "어디까지 몇 칸" | 내 연결 상태. "나는 누구와 어떤 회선으로 이어져 있다" |
| 라우터가 가진 것 | 이웃에게 들은 결과 | 망 전체의 지도 |
| 길을 고르는 방법 | 이웃이 알려 준 칸 수를 믿는다 | 지도를 놓고 스스로 가장 싼 길을 계산한다 |
| 비유 | 옆집이 말해 준 빵집 위치 | 동네 지도를 펴 놓고 직접 찾는 길 |

OSPF(Open Shortest Path First) 라우터는 자기 연결 정보(LSA)를 모든 라우터에게 퍼뜨립니다. 그러면 같은 구역의 라우터들은 똑같은 지도(LSDB)를 갖게 되고, 각자 그 지도에서 가장 싼 길을 계산합니다(SPF 계산). 이웃이 계산해 준 결과를 믿는 것이 아니라, 지도 조각을 모아 스스로 계산한다는 점이 RIP과 다릅니다.

## 2. 비용은 회선 속도로

OSPF의 메트릭은 비용(cost)입니다. 기준 속도 100 Mbps를 회선 속도로 나눈 값이고, 1보다 작으면 1로 둡니다.

| 회선 | 속도 | 비용 |
|------|------|------|
| 기가비트 이더넷 | 1 Gbps | 1 |
| 패스트 이더넷 | 100 Mbps | 1 |
| 시리얼 | 1.544 Mbps | 64 |

길의 비용은 지나는 회선의 비용을 더한 값입니다. 새봄상사 본사에서 지사 영업팀으로 가는 길은 이렇습니다.

| 길 | 비용 |
|----|------|
| 주 회선(1) + 지사 LAN(1) | 2 |
| 예비 회선(64) + 지사 LAN(1) | 65 |

OSPF는 비용 2인 주 회선을 고르고, 주 회선이 끊기면 비용 65인 예비 회선으로 넘어갑니다. 5일차처럼 예비 회선을 막고 정적 예비 경로를 따로 둘 필요가 없습니다.

기가비트와 패스트 이더넷이 둘 다 1인 것은 기준 속도가 100 Mbps이기 때문입니다. 현장에서는 `auto-cost reference-bandwidth` 로 기준을 올려 둘을 구분합니다. 새봄상사 망에서는 문제가 되지 않아 기본값을 씁니다.

관리 거리는 110입니다. RIP(120)보다 더 믿습니다.

## 3. 이웃 맺기

OSPF 라우터는 hello 패킷을 10초마다 보내 이웃을 찾고 안부를 묻습니다. 40초 동안 hello가 없으면 이웃이 사라진 것으로 보고 지도를 고칩니다. 5일차 RIP이 180~240초 걸렸던 것보다 훨씬 빠릅니다.

hello를 주고받는다고 아무나 이웃이 되지는 않습니다. 아래가 모두 같아야 이웃이 됩니다.

| 조건 | 다르면 |
|------|--------|
| 에어리어 번호 | 이웃이 되지 않고 area mismatch 알림이 뜬다 |
| hello, dead 시간 | 이웃이 되지 않는다 |
| 연결 구간의 네트워크와 마스크 | 이웃이 되지 않는다 |
| 인증 방식과 키 | 이웃이 되지 않는다 |

이웃이 되어 지도를 다 주고받은 상태를 FULL이라고 부릅니다. `show ip ospf neighbor` 에서 FULL이 보이면 이웃 맺기가 끝난 것입니다.

> 4번 노트에서는 마지막 조건(인증)을 써서 아무나 이웃이 되지 못하게 합니다.

## 4. 라우터 ID

OSPF 라우터는 지도 위에서 자기 이름으로 라우터 ID를 씁니다. 주소 모양(점으로 나눈 숫자 넷)이지만 주소가 아니라 이름입니다. 정하는 순서는 이렇습니다.

1. `router-id` 명령으로 정한 값
2. 없으면 루프백 인터페이스 중 가장 큰 주소
3. 그것도 없으면 켜져 있는 포트 중 가장 큰 주소

포트 주소로 정해지면 그 포트가 꺼지거나 주소가 바뀔 때 이름이 흔들립니다. 그래서 라우터마다 늘 켜져 있는 루프백을 하나 만들고, `router-id` 로도 같은 값을 못 박습니다. 새봄상사는 장비 루프백 대역 192.168.255.0/24를 새로 정해 HQ-R1에 192.168.255.1, BR-R1에 192.168.255.2를 줍니다.

## 5. 에어리어

OSPF는 망을 에어리어로 나눌 수 있습니다. 같은 에어리어 안의 라우터끼리만 지도를 자세히 나누고, 다른 에어리어에는 요약만 알립니다. 망이 커져도 라우터마다 지도의 크기와 계산이 감당할 만큼으로 줄어듭니다.

| 에어리어 | 역할 |
|----------|------|
| 0 | 백본. 반드시 있어야 한다 |
| 1, 2, ... | 일반 에어리어. 반드시 0에 붙어야 한다 |

새봄상사는 라우터가 두 대라 에어리어 0 하나로 충분합니다. 지사가 여럿이 되면 지사마다 에어리어를 나누는 것을 생각합니다.

## 6. DR과 BDR

이더넷처럼 여러 라우터가 한 구간에 붙을 수 있는 곳에서는, 모든 라우터가 서로 지도를 주고받으면 통신이 너무 많아집니다. 그래서 대표(DR)와 부대표(BDR)를 뽑고, 다른 라우터는 대표와만 지도를 나눕니다. 라우터 ID가 큰 쪽이 대표가 됩니다(우선순위가 같을 때).

시리얼처럼 두 라우터만 잇는 1대1 구간에는 대표가 필요 없어 뽑지 않습니다. 오늘 `show ip ospf neighbor` 에서 주 회선(이더넷)에는 DR이나 BDR이, 예비 회선(시리얼)에는 `-` 가 보입니다.

## 함께 생각해 보기

- 지도를 가진 라우터와 소문만 아는 라우터 중, 거짓 정보에 더 잘 속는 쪽은 어디일까요? 그렇다면 OSPF는 인증이 필요 없을까요?
- 우리 회사에 기가비트와 패스트 이더넷 회선이 섞여 있다면 기본 비용 계산에서 무엇이 문제일까요?

### 물어볼 것

- "OSPF는 주 회선과 예비 회선 중 어디로 갈까요? 비용을 계산해 봅시다." 2와 65로 주 회선입니다.
- "이웃의 hello가 40초 동안 없으면?" 이웃이 사라진 것으로 보고 길을 다시 계산합니다.
- 첫 번째 함께 생각해 보기의 답: OSPF도 지도 조각(LSA)을 받아서 지도를 그립니다. 거짓 조각을 받아들이면 지도가 틀어집니다. 그래서 OSPF도 이웃을 확인하는 인증이 필요하고, 4번 노트에서 겁니다.
- 두 번째 함께 생각해 보기의 답: 둘 다 비용 1이 되어 OSPF가 빠른 길과 느린 길을 구분하지 못합니다. 기준 속도를 올립니다.

### 자주 헷갈리는 것

| 헷갈리는 것 | 바로잡기 |
|-------------|----------|
| 라우터 ID는 라우터의 주소다 | 이름이다. 주소 모양일 뿐이고, 그 주소로 ping이 될 필요는 없다 |
| OSPF는 이웃의 경로표를 받는다 | 연결 상태(지도 조각)를 받아 스스로 계산한다 |
| 에어리어를 많이 나눌수록 좋다 | 작은 망은 에어리어 0 하나가 단순하다 |
| DR은 가장 좋은 라우터다 | 지도 나누기를 대신하는 대표일 뿐, 통신이 DR을 지나가는 것은 아니다 |

### 진행 요령

- 오늘의 축은 5일차와 같은 망을 OSPF로 바꿔 비교하는 것입니다. 이론은 비교에 필요한 만큼만 합니다.
- SPF 계산(다익스트라)의 원리는 이름만 소개합니다. "지도에서 가장 싼 길 찾기"로 충분합니다.
- 루프백 대역 192.168.255.0/24는 설계표에 새 줄로 더하게 합니다. 9일차 null 경로(192.168.0.0/16) 안에 들어가도록 일부러 고른 대역입니다.
