# 4. OSPF를 지키기와 고르기

> 상위: [6일차 OSPF와 Git 브랜치](README.md)
> 대본: [실습 명령어 모음](commands.md) 7~9번
> 드로잉: 4. OSPF를 지키기와 고르기 드로잉 (7장)

## 학습 목표

- OSPF의 passive-interface가 RIP과 달리 이웃 맺기 자체를 막는다는 것을 압니다
- 주 회선과 예비 회선에 OSPF 인증을 겁니다
- RIP과 OSPF를 같은 기준으로 비교하고, 병합을 결정합니다

## 다리 놓기

5일차에 RIP을 지킬 때 passive-interface만으로는 영업팀 자리에서 흘려 넣는 거짓 경로를 막지 못했습니다. RIP의 passive는 "말하지 않기"일 뿐이었기 때문입니다. OSPF는 경로를 주고받기 전에 이웃 맺기라는 단계를 거칩니다. 이 차이가 지키는 방법을 바꿉니다.

## 1. OSPF의 passive는 이웃 맺기를 막는다

OSPF에서 passive-interface로 둔 포트는 hello를 보내지도, 받은 hello에 답하지도 않습니다. 이웃이 되지 않으니 지도 조각(LSA)도 오가지 않습니다. 5일차의 가짜 장비가 영업팀 자리에서 OSPF로 거짓 경로를 알리려 해도, 본사 라우터가 이웃으로 받아 주지 않습니다.

| | RIP의 passive | OSPF의 passive |
|-|---------------|----------------|
| 그 포트로 알림을 보내나 | 보내지 않는다 | hello를 보내지 않는다 |
| 그 포트에서 온 정보를 받나 | 받는다 | 이웃이 되지 않으니 받지 않는다 |
| 사무실 쪽 거짓 경로 | 막지 못한다. 인증이 필요하다 | 막는다 |

사무실 쪽 포트가 많으니 모두 passive로 두고, 이웃 라우터와 이어진 포트만 엽니다. 1일차의 기본 거부를 설정 한 줄로 쓰는 셈입니다.

```
router ospf 1
 passive-interface default
 no passive-interface gi0/1
 no passive-interface se0/0/0
```

`passive-interface default` 는 모든 포트를 passive로 두고, `no passive-interface` 로 연 포트만 이웃을 맺게 합니다. 나중에 VLAN이 늘어도 새 서브인터페이스는 저절로 passive입니다.

## 2. 이웃 사이에는 인증

이웃 라우터와 이어진 구간은 열려 있어야 합니다. 이 구간에서 누군가 우리 라우터인 척 이웃을 맺으려 할 수 있으니, 인증을 겁니다.

```
interface gi0/1
 ip ospf authentication message-digest
 ip ospf message-digest-key 1 md5 <실습용 키>
```

| 명령 | 하는 일 |
|------|---------|
| `ip ospf authentication message-digest` | 이 포트의 OSPF 패킷에 MD5 인증을 쓴다 |
| `ip ospf message-digest-key 1 md5 ...` | 1번 키와 그 값 |

주 회선과 예비 회선 양쪽 끝, 모두 네 곳에 겁니다. 한쪽에만 걸면 이웃 맺기의 조건(인증)이 어긋나 이웃이 끊깁니다. 3번 노트의 장애 시험처럼 통신이 넘어가거나 끊기니, 인증을 바꾸는 작업은 작업 계획서에 "잠시 끊김"을 적고 합니다.

`show ip ospf neighbor` 에 이웃이 다시 FULL로 보이면 인증이 맞은 것입니다. 현장의 새 장비는 MD5보다 강한 SHA 방식을 쓸 수 있습니다.

## 3. 이웃 목록이 곧 감시 대상

OSPF를 쓰는 회사에서 이웃 목록은 고정되어 있습니다. 새봄상사라면 본사 라우터의 이웃은 지사 라우터 하나(두 구간)뿐입니다. `show ip ospf neighbor` 에 낯선 라우터 ID가 보이면, 누군가 회사 망에 라우터를 꽂았다는 신호입니다.

> 15일차 모니터링에서 이런 변화를 사람이 매번 확인하지 않아도 알림이 오게 합니다.

## 4. 비교하고 고른다

5일차의 `03_구축/라우팅_비교.md` 에 OSPF 칸을 더합니다.

| 기준 | 정적 경로 | RIPv2 | OSPF |
|------|-----------|-------|------|
| 회선 속도 | 사람이 정한다 | 모른다 | 비용으로 반영한다 |
| 예비 회선 | 예비 정적 경로 | passive로 막고 예비 정적 경로 | 비용 65로 스스로 예비 |
| 중간 장비 고장을 알아채는 시간 | 모른다 | 180~240초 | 40초 |
| 새 네트워크 | 줄을 더한다 | 저절로 | 저절로 |
| 사무실 쪽 거짓 경로 | 해당 없음 | 인증이 있어야 막는다 | passive만으로 막는다 |
| 설정의 양 | 적다 | 중간 | 중간 |

새봄상사는 OSPF를 고릅니다. 회선 속도를 알고, 예비 회선을 따로 꾸미지 않아도 되고, 사무실 쪽을 passive 한 줄로 닫을 수 있기 때문입니다. 비교 기록의 결정 칸에 이 이유를 적고, ospf 브랜치를 main에 병합합니다.

## 함께 생각해 보기

- 우리 회사라면 RIP과 OSPF 중 무엇을 고르겠습니까? 결정 칸에 쓸 이유 한 줄은 무엇인가요?
- `passive-interface default` 를 쓰지 않고 사무실 포트를 하나씩 passive로 둔다면, 3일차에 VLAN을 하나 더 만들 때 무엇을 잊기 쉬울까요?

### 물어볼 것

- "5일차에 RIP은 passive를 걸어도 거짓 경로가 남았습니다. OSPF는 왜 다를까요?" 이웃 맺기를 거쳐야 정보가 오가기 때문입니다.
- "인증을 한쪽에만 걸면?" 이웃 조건이 어긋나 이웃이 끊깁니다.
- 두 번째 함께 생각해 보기의 답: 새 VLAN의 서브인터페이스에 passive를 거는 것을 잊습니다. `passive-interface default` 는 잊어도 닫혀 있는 쪽으로 기울어 있어 안전합니다(기본 거부).

### 자주 헷갈리는 것

| 헷갈리는 것 | 바로잡기 |
|-------------|----------|
| passive를 걸면 그 포트의 네트워크가 알려지지 않는다 | 알려진다. 그 포트로 이웃을 맺지 않을 뿐이다 |
| `passive-interface default` 를 쳤더니 지사 경로가 사라졌다 | 이웃 쪽 포트를 `no passive-interface` 로 열지 않았다 |
| 인증 키를 OSPF 설정 아래에 넣는다 | 키는 포트 설정에 넣는다(`ip ospf message-digest-key`) |
