# 3. VLAN 사이의 통신과 관리 VLAN

> 상위: [3일차 스위칭과 VLAN](README.md)
> 대본: [실습 명령어 모음](commands.md) 5~7번
> 드로잉: 3. VLAN 사이의 통신과 관리 VLAN 드로잉 (10장)

## 학습 목표

- 라우터 하나에 서브인터페이스를 만들어 VLAN 사이를 잇습니다(router-on-a-stick)
- 2일차의 라우터 설정을 서브인터페이스로 옮깁니다
- 스위치에 관리 주소를 주고, 관리 VLAN에서 접속합니다
- 경계를 다시 이은 지금, 무엇을 막아야 하는지 목록으로 남깁니다

## 다리 놓기

VLAN으로 나누자 이제는 정말 아무도 경계를 넘지 못합니다. 그런데 영업팀도 서버(VLAN 40)의 주문 관리 프로그램은 써야 하고, 개발팀은 쇼핑몰 서버를 관리해야 합니다.

2일차의 다른 대역 실험에서 라우터는 "인사팀 네트워크로 가는 길을 모른다"고 답했습니다. 오늘은 라우터에 VLAN마다 문을 하나씩 달아, 경계를 넘는 통신이 반드시 라우터를 지나게 만듭니다.

## 1. 라우터 하나, 문 여러 개

라우터의 포트 하나를 논리적으로 여러 개로 나눈 것을 서브인터페이스라고 합니다. `gi0/0.10`, `gi0/0.20` 처럼 포트 이름 뒤에 점과 번호를 붙입니다. 서브인터페이스마다 VLAN 하나를 맡고, 그 VLAN의 게이트웨이 주소를 가집니다.

```
              트렁크 (VLAN 10, 20, 30, 40, 99)
 HQ-SW1 Gi0/1 ======================== Gi0/0  HQ-R1
                                         ├─ gi0/0.10  192.168.10.1    VLAN 10
                                         ├─ gi0/0.20  192.168.10.33   VLAN 20
                                         ├─ gi0/0.30  192.168.10.65   VLAN 30
                                         ├─ gi0/0.40  192.168.10.97   VLAN 40
                                         └─ gi0/0.99  192.168.10.129  VLAN 99
```

건물 출입구는 하나인데 그 안에 부서별 창구가 여러 개 있는 것과 같습니다. 선 하나에 라우터가 매달린 모양이라 router-on-a-stick이라고 부릅니다.

## 2. 2일차 설정을 서브인터페이스로 옮기기

2일차에 HQ-R1의 Gi0/0에 192.168.10.1을 직접 주었습니다. 이 주소를 그대로 두고 서브인터페이스에 같은 주소를 주면 `% 192.168.10.0 overlaps with GigabitEthernet0/0` 오류가 납니다. 같은 네트워크를 두 문이 맡을 수는 없기 때문입니다. 그래서 먼저 물리 포트의 주소를 지웁니다.

```
interface gi0/0
 no ip address
 no shutdown
interface gi0/0.10
 description SALES
 encapsulation dot1Q 10
 ip address 192.168.10.1 255.255.255.224
```

| 명령 | 하는 일 |
|------|---------|
| `no ip address` | 물리 포트의 주소를 지운다. 포트는 켜 둔다 |
| `interface gi0/0.10` | VLAN 10을 맡을 서브인터페이스를 만든다. 점 뒤의 번호는 이름일 뿐이지만 VLAN 번호와 맞춘다 |
| `encapsulation dot1Q 10` | 이 서브인터페이스가 VLAN 10의 태그를 맡는다 |
| `ip address ...` | VLAN 10의 게이트웨이 주소 |

`encapsulation` 을 `ip address` 보다 먼저 칩니다. 순서를 바꾸면 주소가 들어가지 않습니다. 실제로 어느 VLAN을 맡는지는 서브인터페이스 번호가 아니라 `encapsulation dot1Q` 뒤의 번호가 정합니다.

오늘 저녁 `configs/HQ-R1.txt` 를 덮어쓰고 커밋하면, `git diff` 에 Gi0/0의 주소가 빠지고 서브인터페이스 다섯 개가 생긴 것이 그대로 보입니다.

## 3. 확인

PC의 게이트웨이를 각 VLAN의 서브인터페이스 주소로 맞추고, 영업팀 PC에서 인사팀 PC로 ping을 칩니다. 2일차에 `Destination host unreachable` 이 나왔던 바로 그 통신입니다.

```
C:\>tracert 192.168.10.34

Tracing route to 192.168.10.34 over a maximum of 30 hops:

  1   0 ms      0 ms      0 ms      192.168.10.1
  2   0 ms      0 ms      0 ms      192.168.10.34

Trace complete.
```

첫 번째 줄의 192.168.10.1이 라우터입니다. VLAN이 다른 통신은 반드시 라우터를 한 번 거칩니다. 라우터의 경로표에는 VLAN마다 두 줄이 생깁니다.

```
HQ-R1#show ip route
     192.168.10.0/24 is variably subnetted, 10 subnets, 2 masks
C       192.168.10.0/27 is directly connected, GigabitEthernet0/0.10
L       192.168.10.1/32 is directly connected, GigabitEthernet0/0.10
C       192.168.10.32/27 is directly connected, GigabitEthernet0/0.20
L       192.168.10.33/32 is directly connected, GigabitEthernet0/0.20
```

| 기호 | 뜻 |
|------|----|
| C | 직접 연결된 네트워크(Connected). 이 문 너머에 이 네트워크가 있다 |
| L | 라우터 자신의 주소(Local) |

> 4일차에 지사를 이으면 이 표에 S(정적 경로) 줄이 더해집니다.

## 4. 스위치의 관리 주소

2일차에 스위치에도 VTY 비밀번호를 걸었지만, 스위치에는 주소가 없어서 원격으로 들어갈 수 없었습니다. 오늘 장비 관리 VLAN(99)에 스위치의 주소를 줍니다.

```
interface vlan 99
 ip address 192.168.10.130 255.255.255.224
 no shutdown
ip default-gateway 192.168.10.129
```

| 명령 | 하는 일 |
|------|---------|
| `interface vlan 99` | 스위치가 VLAN 99에 가진 가상 포트(SVI) |
| `ip address` | 스위치의 관리 주소. HQ-SW1은 .130, HQ-SW2는 .131 |
| `ip default-gateway` | 다른 네트워크에서 온 접속에 답할 때 쓰는 게이트웨이 |

스위치는 이 주소로 오는 관리 접속만 받습니다. 영업팀이나 인사팀 VLAN에는 스위치의 주소가 없습니다. 관리자 PC(VLAN 99, 192.168.10.150)에서 `telnet 192.168.10.130` 으로 들어가 봅니다.

## 5. 이제는 모두 통한다

라우터가 VLAN 사이를 이었으니, 지금은 모든 VLAN이 서로 통합니다. 영업팀 PC에서 인사팀 PC로, 심지어 관리 VLAN의 스위치 주소로 텔넷까지 됩니다.

```
C:\>telnet 192.168.10.130
Trying 192.168.10.130 ...Open
Authorized access only. All access is logged.

User Access Verification

Password:
```

영업팀 PC에서 친 것입니다. 비밀번호 창까지 왔다는 것은 문 앞까지는 누구나 온다는 뜻입니다.

경계를 그었다가 라우터로 다시 이은 것은 헛수고가 아닙니다. 이제 모든 경계 통신이 라우터 한 곳을 지나니, 그곳에서 필요한 것만 허락할 수 있게 되었습니다. 오늘은 무엇을 막아야 하는지 목록으로만 남깁니다.

| 지금 통하는 것 | 필요한가 |
|----------------|----------|
| 영업팀에서 서버 VLAN | 필요하다. 주문 관리 |
| 영업팀에서 인사팀 | 필요 없다. 1일차 계획서의 "통신할 일이 없다" |
| 모든 VLAN에서 관리 VLAN의 장비 | 관리자 PC에서만 필요하다 |

> 10일차 ACL에서 이 표가 정책표가 되고, 관리 VLAN 접속은 `access-class` 로 관리자 PC만 남깁니다.

### 물어볼 것

- "VLAN으로 나눴는데 라우터로 다시 이으면 나눈 의미가 있을까요?" 기대하는 답은 "이제 모든 경계 통신이 라우터 한 곳을 지나서, 거기서 고를 수 있다"입니다. 오늘의 핵심 질문입니다.
- "tracert 의 첫 줄은 누구일까요?" 영업팀의 게이트웨이, 곧 라우터의 서브인터페이스입니다.
- 첫 번째 함께 생각해 보기의 답: VLAN 사이의 통신이 모두 멈춥니다. 같은 VLAN 안은 스위치만으로 통하므로 그대로입니다. 라우터 하나에 모든 것을 기대는 구조라 가용성이 약하고, 8일차에 L3 스위치와 HSRP로 보완합니다.
- 두 번째 함께 생각해 보기의 답: 장비에 닿을 수 있는 곳을 VLAN 하나로 좁혀 두면, 그 VLAN만 지키면 됩니다(최소 권한). 영업팀 VLAN에 두면 영업팀 PC 하나가 악성코드에 걸렸을 때 바로 장비 앞까지 옵니다.

### 자주 헷갈리는 것

| 헷갈리는 것 | 바로잡기 |
|-------------|----------|
| 서브인터페이스마다 `no shutdown` 을 친다 | 물리 포트 Gi0/0만 켜면 서브인터페이스는 함께 켜진다 |
| `interface gi0/0.20` 의 20이 VLAN을 정한다 | VLAN을 정하는 것은 `encapsulation dot1Q 20` 이다. 번호를 맞추는 것은 읽기 쉽게 하려는 약속이다 |
| 스위치의 관리 주소를 `interface fa0/24` 에 준다 | 2960 같은 L2 스위치의 포트에는 주소를 줄 수 없다. `interface vlan 99` 에 준다 |
| `ip default-gateway` 가 없어도 관리 접속이 된다 | 같은 VLAN 99 안에서는 된다. 다른 VLAN에서 온 접속에는 답을 돌려보내지 못한다 |

### 진행 요령

- overlaps 오류는 2일차 설정을 그대로 둔 학생이면 누구나 만납니다. 강사가 먼저 일부러 내 보이고 `no ip address` 로 푸는 순서를 보여 주면 질문이 줄어듭니다.
- 5번 절의 표는 학생 회사로 각자 채워 작업 계획서의 결과 칸 "다음 회차에 이어서 할 일"에 옮기게 합니다. 10일차에 다시 꺼냅니다.
- PC의 게이트웨이를 바꾸지 않아 VLAN 사이 통신이 안 되는 경우가 가장 흔합니다. 2일차에는 모든 PC가 .1을 썼지만 오늘부터는 VLAN마다 다릅니다.
