## 목적

오늘 스위치 두 대에 같은 VLAN을 일일이 만들었다. 스위치가 스무 대인 회사에서 부서가 하나 생기면 스무 번 접속해야 한다. 하나라도 빠뜨리면 그 층의 그 부서만 통하지 않는 이상한 장애가 난다.

VLAN 목록을 한 곳에서 바꾸면 나머지 스위치가 따라 바뀌게 하는 프로토콜이 VTP(VLAN Trunking Protocol)다. 편리한 만큼 사고도 크게 난다.

## 1. VTP가 하는 일

VTP는 트렁크를 타고 VLAN 목록을 다른 스위치에 알린다. 아래 조건이 모두 맞는 스위치끼리만 목록을 맞춘다.

| 조건 | 내용 |
|---|---|
| 도메인 이름이 같다 | `vtp domain`으로 정한 이름 |
| 비밀번호가 같다 | `vtp password`로 정한 값 |
| 트렁크로 이어져 있다 | VTP 알림은 트렁크로만 오간다 |

스위치마다 맡는 역할(모드)이 있다.

| 모드 | VLAN 만들기와 지우기 | 알림 |
|---|---|---|
| server | 할 수 있다 | 보내고, 받아서 따른다 |
| client | 할 수 없다 | 받아서 따른다 |
| transparent | 할 수 있다. 자기 것만 | 따르지 않고, 지나가는 알림은 옆으로 넘겨 준다 |

처음 상태의 시스코 스위치는 server 모드이고 도메인 이름이 비어 있다.

## 2. 리비전 번호와 사라지는 VLAN

VTP는 누구의 목록이 최신인지 리비전 번호로 판단한다. VLAN을 만들거나 지우거나 이름을 바꿀 때마다 번호가 1씩 오르고, 같은 도메인에서는 번호가 가장 큰 목록이 이긴다.

사고는 이렇게 난다. 다른 사무실에서 쓰던 스위치를 가져와 꽂았는데, 그 스위치의 도메인 이름이 우리와 같고 리비전 번호가 우리보다 높았다. 그 스위치에는 VLAN이 몇 개 없다. 꽂는 순간 회사의 모든 스위치가 "더 새 목록"을 따라 VLAN을 지우고, VLAN에 속해 있던 포트는 갈 곳을 잃는다. 회사 전체의 통신이 한꺼번에 멈춘다.

1일차의 CIA로 보면 가용성이 깨진 사고이고, 공격자가 없어도 일어난다. 누군가 일부러 높은 번호의 스위치를 꽂으면 공격이 된다.

리비전 번호는 VLAN 정보 파일(vlan.dat)에 저장되어 껐다 켜도 남는다. 0으로 되돌리는 방법은 도메인 이름을 바꾸거나 transparent 모드로 잠시 바꾸는 것이다. 새 스위치를 들이기 전에는 리비전 번호를 0으로 만들어 두는 것이 현장의 습관이다.

## 3. 새봄상사의 선택: transparent

새봄상사는 스위치가 두 대뿐이라 VTP의 편리함보다 위험이 크다. 두 스위치를 모두 transparent 모드로 둔다.

```
vtp mode transparent
```

이유는 두 가지다.

| 이유 | 설명 |
|---|---|
| 덮어쓰기 사고가 없다 | 다른 스위치의 알림을 따르지 않는다 |
| VLAN 설정이 설정 텍스트에 남는다 | server와 client 모드에서는 VLAN이 vlan.dat에만 저장되어 `show running-config`에 나오지 않는다. transparent 모드에서는 `vlan 10`, `name SALES` 줄이 running-config에 들어간다 |

두 번째 이유가 이 과목에는 특히 중요하다. 설정 텍스트를 커밋해 바뀐 줄을 `git diff`로 보는 것이 이 과목의 방식인데, server 모드에서는 VLAN이 바뀌어도 설정 텍스트에는 아무것도 남지 않는다. transparent로 바꾼 뒤 `show running-config`를 다시 보면 VLAN 줄이 생긴 것을 확인할 수 있다.

```
HQ-SW1#show running-config | include vlan
vlan 10
vlan 20
vlan 30
vlan 40
vlan 99
vlan 900
vlan 999
```

`| include vlan`은 출력에서 vlan이 들어간 줄만 골라 보는 방법이다. 실제 출력에는 `switchport access vlan` 같은 줄도 함께 보인다.

스위치가 많은 회사라면 VTP를 쓰되, 도메인 이름과 비밀번호를 정하고 server는 한두 대로 줄이는 식으로 위험을 줄인다.

## 4. 오늘의 스위치 보안 점검표

오늘 스위치에 건 설정을 보안의 눈으로 다시 모은다. 작업 계획서의 결과 칸과 `02_설계/` 문서에 이 표를 옮겨 두면 16일차 보고서의 한 절이 된다.

| 한 일 | 명령 | 막는 것 | 1일차 원칙 |
|---|---|---|---|
| 부서마다 VLAN | `switchport access vlan` | 주소만 바꿔 다른 부서로 넘어가기 | 최소 권한 |
| PC 자리를 access로 고정 | `switchport mode access` | 가짜 트렁크 | 기본 거부 |
| 쓰지 않는 포트 닫기 | VLAN 999, `shutdown` | 빈 단자에 꽂은 장비 | 기본 거부, 심층 방어 |
| 트렁크 협상 끄기 | `switchport nonegotiate` | 협상으로 생기는 트렁크 | 기본 거부 |
| native VLAN 바꾸기 | `switchport trunk native vlan 900` | 이중 태그 | 심층 방어 |
| 트렁크에 필요한 VLAN만 | `switchport trunk allowed vlan` | 필요 없는 곳까지 퍼지는 VLAN | 최소 권한 |
| VTP transparent | `vtp mode transparent` | VLAN 덮어쓰기 사고 | 가용성 |
| 관리 주소는 VLAN 99에만 | `interface vlan 99` | 아무 VLAN에서나 장비에 닿기 | 최소 권한 |

아직 남은 구멍도 적어 둔다.

| 남은 구멍 | 메우는 날 |
|---|---|
| 모든 VLAN에서 관리 VLAN의 장비에 텔넷 창까지 온다 | 10일차 `access-class` |
| 텔넷은 비밀번호가 평문으로 오간다 | 12일차 SSH |
| 포트에 소형 스위치나 낯선 장비를 꽂아도 막지 못한다 | 12일차 포트 보안 |

## 5. 탐지·방어

| 항목 | 내용 |
|---|---|
| 원인 | 도메인 이름과 비밀번호가 같고 리비전 번호가 높은 스위치가 트렁크에 연결되면 VLAN 목록이 덮어쓰인다 |
| 완화 | 스위치가 적으면 `vtp mode transparent`. 많으면 도메인 비밀번호를 설정하고 server를 한두 대로 줄이며, 새 스위치는 리비전을 0으로 만든 뒤 연결한다 |
| 흔적 | `show vtp status`의 Configuration Revision 값이 갑자기 오르거나 VLAN 목록이 줄어든다. 포트가 사라진 VLAN에 속해 있으면 `show vlan brief`에서 해당 포트가 보이지 않는다 (미검증) |

## 약어·용어

| 용어 | 뜻 |
|---|---|
| VTP | VLAN Trunking Protocol. 트렁크로 VLAN 목록을 다른 스위치에 알리는 시스코 프로토콜 |
| 리비전 번호 | VLAN 목록이 바뀔 때마다 오르는 번호. 큰 쪽이 최신으로 취급된다 |
| vlan.dat | 스위치가 VLAN 정보를 저장하는 파일 |
| transparent 모드 | 자기 VLAN만 관리하고 다른 스위치의 알림은 따르지 않는 VTP 모드 |
| 가용성 | 필요할 때 서비스를 쓸 수 있는 성질 (CIA의 A) |

## 강의 메모

### 시간 배분 (35분)

| 절 | 시간 | 방식 |
|---|---|---|
| 목적, 1 VTP | 8분 | 스위치 스무 대 그림 |
| 2 리비전 번호 사고 | 8분 | 사고 이야기로. 실습으로 재현하지 않는다 |

### 물어볼 것

- "새 스위치를 꽂았을 뿐인데 회사 전체가 멈췄다면 CIA 중 무엇이 깨졌나?" 가용성이다.
- "VTP를 transparent로 두면 VLAN 설정이 설정 텍스트에 남는다. 이것이 왜 이 과목에 중요할까?" `git diff`로 VLAN의 변경을 추적할 수 있기 때문이다. 1일차의 기록 원칙과 잇는다.
- 첫 번째 함께 생각해 보기의 답: 서른 대면 VTP의 편리함이 크다. 도메인 이름과 비밀번호를 정하고, server는 한두 대만 두고 나머지는 client로, 새 스위치는 리비전을 0으로 만든 뒤 들인다. 위험을 없애지는 못하고 줄이는 것이라 1일차의 위험 대응 중 감소다.

### 자주 헷갈리는 것

| 헷갈리는 것 | 바로잡기 |
|---|---|
| 리비전 번호는 껐다 켜면 0이 된다 | vlan.dat에 저장되어 남는다. 도메인 이름을 바꾸거나 transparent로 바꾸면 0이 된다 |
| transparent 스위치는 VTP 알림을 막는다 | 자기는 따르지 않을 뿐, 지나가는 알림은 옆 스위치로 넘겨 준다 |
| client 모드에서도 VLAN을 만들 수 있다 | client는 만들 수 없다. 받은 목록만 쓴다 |
| VTP가 포트를 VLAN에 넣어 준다 | VTP는 VLAN 목록만 맞춘다. 포트 배정은 스위치마다 따로 한다 |

### 진행 요령

- 리비전 번호 사고는 실습으로 재현하지 않는다. 교실 전체 실습망이 멈출 수 있고, 학생 각자의 패킷트레이서 안에서도 VLAN을 다시 만드는 데 시간이 든다. 이야기와 그림으로 충분하다.
- 일찍 끝낸 학생에게는 더 해 볼 것으로 server와 client 동기화를 시켜 본다. 도메인 이름과 비밀번호를 맞추고, server에서 VLAN을 하나 만들어 client의 `show vlan brief`에 나타나는지 본다. 확인한 뒤 transparent로 되돌린다.
- 점검표는 16일차 보고서의 재료라는 것을 분명히 말한다. 학생 회사의 VLAN 번호로 고쳐 커밋하게 한다.
