## 학습 목표

- IPv6 주소를 읽고 줄여 쓴다.
- 링크 로컬, 글로벌, 문서용 주소와 자동 설정을 안다.
- 한 포트에 IPv4와 IPv6를 함께 거는 듀얼 스택을 해 본다.
- IPv4에만 건 ACL을 IPv6가 우회하는 것을 보고, IPv6 ACL로 막는다.

## 목적

9일차에 NAT가 생긴 이유는 IPv4 주소가 모자라서였다. 32비트로는 약 43억 개뿐이라, 회사마다 사설 주소를 쓰고 경계에서 바꿔 다는 방법이 퍼졌다. IPv6는 주소를 128비트로 늘려 이 문제를 처음부터 푼다.

IPv6는 먼 이야기가 아니다. 지금 쓰는 Windows PC는 처음부터 IPv6가 켜져 있다. 회사가 IPv6를 계획하지 않았어도, 장비들은 이미 IPv6로 말할 준비가 되어 있다는 뜻이다. 오늘 이 사실이 보안에서 무엇을 뜻하는지 본다.

## 1. IPv6 주소 읽기

128비트를 16비트씩 여덟 칸으로 나누고, 칸마다 16진수 네 자리로 쓴다.

```
2001:0db8:0010:0010:0000:0000:0000:0001
```

| 줄이는 규칙 | 결과 |
|---|---|
| 칸 앞의 0은 뺀다 | `2001:db8:10:10:0:0:0:1` |
| 0만 있는 칸이 이어지면 `::`로 한 번만 줄인다 | `2001:db8:10:10::1` |

`::`는 주소 안에서 한 번만 쓴다. 두 번 쓰면 0이 몇 칸씩 빠졌는지 알 수 없기 때문이다. 네트워크와 호스트의 경계는 2일차처럼 프리픽스로 적는다. 회사 안의 네트워크 하나는 보통 /64다.

## 2. 주소의 종류와 자동 설정

| 종류 | 대역 | IPv4로 치면 |
|---|---|---|
| 글로벌 주소 | 2000::/3 | 공인 주소 |
| 링크 로컬 주소 | fe80::/10 | 같은 네트워크 안에서만. 포트마다 저절로 생긴다 |
| 고유 로컬 주소(ULA) | fc00::/7 | 사설 주소와 비슷 |
| 문서용 주소 | 2001:db8::/32 | 203.0.113.0/24 같은 문서용. 이 과목의 IPv6 주소 |

IPv6에는 DHCP 없이도 주소를 얻는 방법이 있다. 라우터가 "이 네트워크는 2001:db8:10:10::/64"라고 알리면(라우터 광고), PC가 그 프리픽스 뒤에 자기 몫을 붙여 주소를 스스로 만든다. 이것을 자동 설정(SLAAC)이라고 한다.

{% hint style="info" %}
NOTE: 8일차의 가짜 DHCP 서버를 떠올린다. 라우터 광고도 누구든 보낼 수 있다. 가짜 라우터 광고로 PC의 게이트웨이를 바꾸는 공격이 있고, 스위치의 RA Guard가 DHCP 스누핑과 같은 일을 한다.
{% endhint %}

## 3. 듀얼 스택 시범

한 포트에 IPv4와 IPv6 주소를 함께 거는 것을 듀얼 스택이라고 한다. 오늘은 HQ-R1의 영업팀과 인사팀 서브인터페이스에만 시범으로 켠다.

```
ipv6 unicast-routing
interface gi0/0.10
 ipv6 address 2001:db8:10:10::1/64
interface gi0/0.20
 ipv6 address 2001:db8:10:20::1/64
```

세 번째 칸의 10은 본사(192.168.10.x), 네 번째 칸의 10과 20은 VLAN 번호다. 주소만 보고 어디인지 알 수 있게 짝을 짓는 것은 3일차의 VLAN 번호와 대역을 짝지은 것과 같은 생각이다.

PC의 IP Configuration에서 IPv6를 자동(Automatic)으로 두면, PC가 HQ-R1의 라우터 광고를 받아 2001:db8:10:10::으로 시작하는 주소를 스스로 만든다.

## 4. IPv4 정책을 비켜 가는 IPv6

10일차의 SALES-IN은 영업팀에서 인사팀으로 가는 것을 막았다. 영업팀 PC에서 두 가지로 인사팀 PC에 ping을 쳐 본다.

| 명령 | 결과 |
|---|---|
| `ping 192.168.10.42` (IPv4) | 닿을 수 없음. SALES-IN 20번 줄 |
| `ping 2001:db8:10:20::(HR-PC1의 IPv6 주소)` | Reply |

IPv4 ACL은 IPv4 패킷만 본다. 같은 두 PC가 IPv6로 말하면 정책이 아예 없는 것과 같다. 문을 하나 잠갔는데, 바로 옆에 아무도 신경 쓰지 않던 문이 하나 더 있었던 셈이다. 장비들이 처음부터 IPv6를 켜고 있으니, 회사가 계획하지 않은 사이에 이런 뒷문이 생긴다.

IPv6에는 IPv6 ACL을 따로 건다.

```
ipv6 access-list SALES-IN6
 deny ipv6 2001:db8:10:10::/64 2001:db8:10:20::/64 log
 permit ipv6 any any
interface gi0/0.10
 ipv6 traffic-filter SALES-IN6 in
```

IPv4의 `ip access-group` 대신 `ipv6 traffic-filter`로 건다. 다시 IPv6로 ping을 치면 막힌다.

정책은 주소 체계마다 따로 있어야 한다. 2번 노트 정책표에 IPv6 줄을 더하거나, IPv6를 쓰지 않을 곳이라면 장비에서 IPv6를 꺼 두는 것도 정책이다.

## 5. IPv6와 보안에 대한 오해

| 오해 | 바로잡기 |
|---|---|
| IPv6는 IPSec이 기본이라 더 안전하다 | 처음 표준에 IPSec 지원이 들어 있었을 뿐, 켜야 암호화된다. 오늘 3번 노트처럼 따로 설정한다 |
| NAT가 없으니 위험하다 | NAT는 원래 막는 장치가 아니었다(9일차). IPv6에서도 막는 일은 방화벽과 ACL이 한다 |
| 사설 주소는 FEC0::/10이다 | 사이트 로컬(FEC0::/10)은 오래전에 쓰지 않게 되었다. 지금은 고유 로컬 주소(fc00::/7) |

## 약어·용어

| 용어 | 뜻 |
|---|---|
| IPv6 | 128비트 주소를 쓰는 인터넷 프로토콜. 16비트씩 여덟 칸, 16진수로 쓴다 |
| 듀얼 스택 | 한 포트에 IPv4와 IPv6 주소를 함께 거는 것 |
| 링크 로컬 주소 | fe80::/10. 같은 네트워크 안에서만 쓰는, 포트마다 저절로 생기는 주소 |
| 고유 로컬 주소 (ULA) | fc00::/7. IPv4의 사설 주소와 비슷한 주소 |
| 문서용 주소 | 2001:db8::/32. 문서와 예제에만 쓰는 주소 |
| 라우터 광고 (RA) | 라우터가 네트워크의 프리픽스를 알리는 메시지 |
| SLAAC | 라우터 광고의 프리픽스에 자기 몫을 붙여 주소를 스스로 만드는 자동 설정 |
| RA Guard | 스위치에서 가짜 라우터 광고를 막는 기능. DHCP 스누핑과 같은 일을 한다 |
| `ipv6 traffic-filter` | 인터페이스에 IPv6 ACL을 거는 명령 |

## 함께 생각해 보기

- 우리 회사는 IPv6를 쓰는가. 쓰지 않는다면 장비와 PC의 IPv6를 어떻게 하겠는가.
- 10일차 정책표의 줄마다 IPv6에서도 같은 일이 일어나는지 점검해 본다. 가장 먼저 막아야 할 줄은 무엇인가.

### 물어볼 것

- "`2001:0db8:0000:0000:0000:0000:0000:0001`을 줄이면?" `2001:db8::1`이다.
- "SALES-IN은 왜 IPv6 ping을 막지 못했을까?" IPv4 ACL은 IPv4 패킷만 본다.
- 첫 번째 함께 생각해 보기의 답: 쓰지 않는다면 쓰지 않는다는 것도 정책으로 적고, 라우터와 스위치에서 IPv6 라우팅을 켜지 않으며, 경계 방화벽에서 IPv6를 막는다. 켜 둔 채 잊는 것이 가장 위험하다.

### 자주 헷갈리는 것

| 헷갈리는 것 | 바로잡기 |
|---|---|
| `::`를 두 번 쓴다 | 한 번만 쓴다 |
| IPv6 ACL도 `ip access-group`으로 건다 | `ipv6 traffic-filter`로 건다 |
| 링크 로컬 주소로 다른 네트워크에 간다 | fe80::은 같은 네트워크 안에서만 쓴다 |
| PC에 IPv6 주소가 안 생긴다 | HQ-R1에 `ipv6 unicast-routing`이 없으면 라우터 광고를 보내지 않는다 |

### 진행 요령

- 오늘의 IPv6는 시범이라 HQ-R1의 두 서브인터페이스에만 켠다. HQ-DSW1과 HSRP의 IPv6, OSPFv3는 다루지 않는다.
- 수업이 끝나면 IPv6를 그대로 둘지 끌지 학생이 정해 정책표에 적게 한다. 어느 쪽이든 근거가 있으면 된다.
