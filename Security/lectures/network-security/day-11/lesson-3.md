## 학습 목표

- 시뮬레이션 모드로 GRE 터널 안의 내용이 그대로 보이는 것을 확인한다.
- IPSec이 주는 기밀성, 무결성, 인증을 안다.
- IKE 1단계와 2단계를 안다.
- GRE 위에 IPSec을 얹고, 암호화 전후의 패킷을 비교해 기록한다.

## 목적

1번 노트에서 GRE는 터널만 주고 내용은 숨기지 않는다고 했다. 말로 듣는 것과 눈으로 보는 것은 다르다. 패킷트레이서의 시뮬레이션 모드로, 인터넷 한가운데의 ISP-R1을 지나는 겉 상자를 열어 본다.

## 1. 열어 본 GRE 상자

시뮬레이션 모드에서 BR-PC1이 서버로 ping을 보내고, ISP-R1에 머문 패킷을 눌러 본다.

| 층 | 보이는 것 |
|---|---|
| 겉 IP 헤더 | 203.0.113.6에서 203.0.113.2로, 프로토콜 GRE |
| GRE 헤더 | 안에 IP가 들어 있다 |
| 안의 IP 헤더 | 192.168.20.10에서 192.168.10.98로 |
| ICMP | echo 요청 |

ISP-R1의 자리에 선 사람, 곧 인터넷 중간의 누구든 지사 PC의 주소, 서버의 주소, 무엇을 주고받는지 모두 본다. ping이 아니라 주문서나 급여 파일이었어도 마찬가지다.

## 2. IPSec이 주는 것

| 기능 | 하는 일 | 1일차 CIA |
|---|---|---|
| 암호화 | 상자 안을 읽지 못하게 한다 | 기밀성 |
| 무결성 확인 | 중간에 바뀌었는지 해시로 확인한다 | 무결성 |
| 상대 인증 | 미리 나눈 키로 상대가 진짜 지사인지 확인한다 | (인증) |

IPSec은 두 단계로 일한다. 두 지점장이 처음 만나 서로 신분을 확인하고 앞으로 쓸 암호 수첩을 정하는 것이 1단계, 그 수첩으로 실제 서류를 넣을 금고를 정하는 것이 2단계다.

| 단계 | 정하는 것 | 설정 |
|---|---|---|
| IKE 1단계 (ISAKMP) | 두 라우터가 서로를 인증하고, 2단계를 의논할 안전한 통로를 만든다 | `crypto isakmp policy`, `crypto isakmp key` |
| IKE 2단계 (IPSec) | 실제 데이터를 쌀 암호화와 해시 방식 | `crypto ipsec transform-set` |
| 대상과 묶음 | 무엇을 암호화할지, 누구와, 어느 포트에서 | ACL, `crypto map` |

## 3. 설정

HQ-R1이다. BR-R1은 상대 주소만 203.0.113.2로 바꾼다.

```
crypto isakmp policy 10
 encryption aes 256
 hash sha
 authentication pre-share
 group 5
crypto isakmp key <key> address 203.0.113.6
crypto ipsec transform-set HQBR esp-aes 256 esp-sha-hmac
ip access-list extended VPN-HQBR
 permit gre host 203.0.113.2 host 203.0.113.6
crypto map VPNMAP 10 ipsec-isakmp
 set peer 203.0.113.6
 set transform-set HQBR
 match address VPN-HQBR
interface se0/0/1
 crypto map VPNMAP
```

| 줄 | 뜻 |
|---|---|
| `encryption aes 256` | 1단계 통로의 암호화. AES 256비트 |
| `hash sha` | 1단계의 무결성 확인 |
| `authentication pre-share` | 미리 나눈 키로 상대를 인증 |
| `group 5` | 키를 안전하게 나누는 계산(디피-헬만)의 크기 |
| `crypto isakmp key` | 상대 203.0.113.6과 나눈 키. 두 라우터가 글자 하나까지 같아야 한다 |
| `transform-set` | 2단계. 데이터를 AES로 싸고 SHA로 확인 |
| `VPN-HQBR` | 암호화할 대상. 두 라우터 사이의 GRE(겉 상자) 전부 |
| `crypto map` | 위의 것들을 상대 하나와 묶어 인터넷 쪽 포트에 건다 |

GRE 겉 상자를 통째로 암호화하니, 터널 안의 모든 것(업무 통신, OSPF 알림)이 함께 암호화된다. GRE가 터널을, IPSec이 암호화와 인증을 맡는 이 짝을 흔히 GRE over IPSec이라고 부른다.

## 4. 확인

```
HQ-R1#show crypto isakmp sa
IPv4 Crypto ISAKMP SA
dst             src             state          conn-id slot status
203.0.113.6     203.0.113.2     QM_IDLE           1001    0 ACTIVE
```

```
HQ-R1#show crypto ipsec sa
interface: Serial0/0/1
    Crypto map tag: VPNMAP, local addr 203.0.113.2
   local  ident (addr/mask/prot/port): (203.0.113.2/255.255.255.255/47/0)
   remote ident (addr/mask/prot/port): (203.0.113.6/255.255.255.255/47/0)
   current_peer 203.0.113.6 port 500
    #pkts encaps: 25, #pkts encrypt: 25, #pkts digest: 25
    #pkts decaps: 24, #pkts decrypt: 24, #pkts verify: 24
```

| 읽을 것 | 뜻 |
|---|---|
| `QM_IDLE`, `ACTIVE` | 1단계가 끝나 2단계까지 맺어졌다 |
| `prot 47` | 대상이 GRE(프로토콜 번호 47) |
| `#pkts encrypt`, `#pkts decrypt` | 암호화한 패킷과 푼 패킷. ping을 칠 때마다 는다 |

암호화가 처음 맺어지는 동안 첫 ping 한두 개가 빠질 수 있다. 양쪽이 키를 맞추는 시간이다.

시뮬레이션 모드로 ISP-R1의 패킷을 다시 열어 본다.

| 층 | GRE만 | GRE와 IPSec |
|---|---|---|
| 겉 IP 헤더 | 203.0.113.6에서 203.0.113.2로 | 같다 |
| 그다음 | GRE, 안의 IP, ICMP가 보인다 | ESP. 그 안은 암호화되어 읽을 수 없다 |

겉 주소는 여전히 보인다. 인터넷이 상자를 날라야 하니까. 하지만 상자 안에 누가 누구에게 무엇을 보냈는지는 이제 보이지 않는다. 이 두 화면이 강의계획서에 적은 "암호화 전후 캡처 비교"다.

## 5. 알고리즘과 키

키워드 요약은 DES, 3DES, MD5를 예로 든다. DES는 오래전에 깨졌고, MD5는 5일차에 말한 대로 오래된 해시다. 지금 새로 설정한다면 AES와 SHA 계열을 고른다.

{% hint style="info" %}
NOTE: 정보보안개론 7장(암호의 이해)에서 대칭키 암호와 해시를 자세히 다룬다. 오늘은 "AES는 상자를 잠그는 자물쇠, SHA는 상자가 뜯겼는지 보는 봉인"으로 기억한다.
{% endhint %}

{% hint style="info" %}
NOTE: 이 노트의 `hash sha`(SHA-1)와 `group 5`(1536비트)는 수업용 값이다. 실제 장비에 새로 설정한다면 더 강한 해시(SHA-256 이상)와 큰 디피-헬만 그룹(14 이상)을 쓰는지 장비 문서로 확인한다. (미검증)
{% endhint %}

미리 나눈 키는 장비 설정에 그대로 들어간다. 5일차에 정한 규칙을 그대로 따른다. 설정 텍스트를 저장소에 올릴 때는 키를 `<key>`로 바꾼 뒤 올린다. 실제 회사라면 설정 파일을 공개 저장소에 올리지 않고, 키는 지점마다 다르게, 정기적으로 바꾼다.

## 약어·용어

| 용어 | 뜻 |
|---|---|
| IPSec | 패킷에 암호화, 무결성 확인, 상대 인증을 더하는 프로토콜 묶음 |
| IKE (ISAKMP) | 두 라우터가 서로를 인증하고 암호 방식과 키를 정하는 절차. 1단계와 2단계로 나뉜다 |
| 미리 나눈 키 (pre-shared key) | 두 라우터가 미리 같은 값을 설정해 두고 상대를 인증하는 방식 |
| 디피-헬만 그룹 (`group`) | 키를 안전하게 나누는 계산의 크기 |
| `transform-set` | 2단계에서 쓸 암호화와 해시 방식의 묶음 |
| `crypto map` | 대상 ACL, 상대, `transform-set`을 묶어 인터페이스에 거는 설정 |
| ESP | 암호화된 IPSec 패킷의 프로토콜. 암호화와 무결성 확인을 맡는다 |
| GRE over IPSec | GRE가 터널을, IPSec이 암호화와 인증을 맡는 구성 |
| `QM_IDLE` | 1단계가 끝나 2단계(퀵 모드) 교섭을 기다리는 ISAKMP SA 상태 |

## 함께 생각해 보기

- 겉 IP 헤더는 왜 암호화하지 않는가. 암호화하면 무엇이 안 되는가.
- 지사가 열 곳이 되면 미리 나눈 키를 어떻게 관리해야 하는가. 모두 같은 키를 쓰면 무엇이 걱정인가.

### 물어볼 것

- "GRE 상자를 연 사람은 무엇을 알 수 있나?" 출발지와 목적지의 사설 주소, 프로토콜, 내용까지 모두다.
- "IPSec을 걸어도 ISP에서 보이는 것은 무엇일까?" 겉의 공인 주소 두 개와, 무언가 암호화된 것이 오간다는 사실이다.
- 두 번째 함께 생각해 보기의 답: 한 지사의 키가 새면 모든 지사의 터널이 위험해진다. 지사마다 다른 키를 쓰고, 규모가 커지면 미리 나눈 키 대신 인증서를 쓴다.

### 자주 헷갈리는 것

| 헷갈리는 것 | 바로잡기 |
|---|---|
| crypto map을 터널 인터페이스에 건다 | 겉 상자가 나가는 인터넷 쪽 물리 포트(Se0/0/1)에 건다 |
| 대상 ACL에 사설 대역을 적는다 | 이 방식에서 암호화할 것은 GRE 겉 상자다. 두 공인 주소 사이의 gre |
| 키를 바꿨더니 터널이 끊겼다 | 양쪽 키가 다르면 1단계에서 서로를 인증하지 못한다 |
| `#pkts encrypt`가 0이다 | 대상 ACL이 틀렸거나 crypto map을 안 걸었다. 터널은 GRE로 통하지만 암호화가 안 된 상태다 |

### 진행 요령

- crypto 명령은 라이선스(securityk9)를 켜고 재시작한 뒤에야 받아들여진다. 대본 1번을 빠뜨린 학생이 많으니 시작할 때 `show version`으로 확인시킨다.
- 패킷트레이서가 `aes 256`이나 `group 5`를 받지 않으면 `aes`와 `group 2`로 바꾼다. 수업 전에 확인한다.
- 4번 절의 비교 화면 두 장을 학생이 직접 캡처해 VPN 정책 문서에 붙이게 한다. 포트폴리오에서 가장 설득력 있는 그림이다.
