## 5. 절차

### A. 내 파일에 1~12번

1. (5-A-01) `_실습/새봄상사.pkt`를 저장하고 닫은 뒤 `configs/network.pkt`를 연다. → 결과: 내 회사 구성이 열린다.
2. (5-A-02) [2-1 실습](lesson-2-lab.md)의 1번(라이선스)을 가장 먼저 한다. 재시작에 시간이 걸린다. → 결과: `show version`에 securityk9가 있다.
3. (5-A-03) 2~9번은 인터넷 쪽 주소를 그대로 쓰고, 터널 주소는 내 설계표의 다음 /30을 쓴다. → 결과: 내 파일에서 터널이 서고 터널 위로 OSPF 이웃이 생기며, 주 회선 장애 때 터널로 넘어가고, `show crypto ipsec sa`의 암호화 횟수가 는다.
4. (5-A-04) 10~12번은 내 회사 부서 두 곳으로 한다. 시간이 모자라면 IPv6는 더 해 볼 것으로 넘긴다. → 결과: IPv6 ACL로 한 부서에서 다른 부서로 가는 IPv6 ping이 막힌다.

### B. 지사 연결 기록, VPN 정책, 설계표와 정책표

1. (5-B-01) `03_구축/지사_연결.md`에 "11일차: 예비 시리얼 회선 해지, 인터넷 VPN으로" 절을 더하고, 장애 시험 결과를 4일차, 6일차와 나란히 적는다. → 결과: 끊긴 ping 개수가 세 회차 비교표에 들어 있다.
2. (5-B-02) [3번 노트](lesson-3.md) 6번 절의 양식으로 `04_보안정책/VPN_정책.md`를 만들고, [3-1 실습](lesson-3-lab.md)에서 캡처한 두 장을 붙인다. → 결과: 암호화 전후 비교 표가 채워진다.
3. (5-B-03) `02_설계/IP_설계표.md`에 지사 인터넷 회선(203.0.113.4/30), 터널(192.168.99.12/30), IPv6 프리픽스를 더한다. → 결과: 세 항목이 표에 있다.
4. (5-B-04) `04_보안정책/ACL_정책표.md`에 IPv6 줄을 더하거나, IPv6를 쓰지 않기로 했다면 그 결정을 적는다. → 결과: IPv6 줄이나 IPv6를 쓰지 않는다는 결정이 있다.

## 7. 복구

1. (7-01) 터널이 꼬이면 `no interface tunnel 0`과 Se0/0/0 `no shutdown`으로 4일차의 예비 회선으로 돌아간다.
2. (7-02) IPSec 때문에 터널이 끊기면 Se0/0/1에서 `no crypto map VPNMAP`으로 떼면 GRE만으로 다시 통한다.
3. (7-03) IPv6는 `no ipv6 unicast-routing`으로 끈다. 라우터 광고가 멈추고, PC의 기존 IPv6 주소는 수명이 끝날 때 사라진다.
4. (7-04) 커밋을 취소하려면 push 전에 `git reset --soft HEAD~1`을 쓴다. 이미 push했다면 새 커밋으로 고친다. 키가 들어간 채 push했다면 키를 즉시 교체한다.
