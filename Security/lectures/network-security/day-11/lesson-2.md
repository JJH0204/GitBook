## 학습 목표

- 지사 라우터를 인터넷에 잇고, 터널의 두 끝으로 가는 길을 인터넷 쪽으로 정한다.
- 터널 인터페이스를 만들고 GRE 터널을 맺는다.
- OSPF를 터널 위로 돌려 예비 시리얼 회선의 자리를 터널로 바꾼다.
- 장애 시험으로 주 회선이 끊기면 터널로 넘어가는 것을 확인한다.

## 목적

앞 노트에서 터널은 상자를 더 큰 상자에 넣어 부치는 일이라고 했다. 겉 상자에 적힐 주소는 본사와 지사 라우터의 인터넷 쪽 공인 주소다. 본사는 9일차에 203.0.113.2를 받았다. 지사도 인터넷 회선이 있어야 겉 상자의 주소가 생긴다.

## 1. 지사의 인터넷 회선

| 장비 | 포트 | 주소 |
|---|---|---|
| ISP-R1 | Se0/0/1 | 203.0.113.5/30 |
| BR-R1 | Se0/0/1 | 203.0.113.6/30 |

BR-R1은 4일차에 꽂은 시리얼 모듈의 두 번째 포트를 쓴다. 지사의 일반 인터넷은 지금처럼 본사를 거쳐 나간다(9일차의 O*E2 기본 경로). 인터넷 경계의 방화벽과 기록을 본사 한 곳에 모으기 위해서다. 지사의 인터넷 회선은 터널의 겉 상자를 나르는 데만 쓴다.

## 2. 터널의 두 끝으로 가는 길

| 장비 | 경로 | 이유 |
|---|---|---|
| BR-R1 | `ip route 203.0.113.2 255.255.255.255 203.0.113.5` | 본사의 공인 주소로는 반드시 지사의 인터넷 회선으로 |
| HQ-R1 | `ip route 203.0.113.6 255.255.255.255 203.0.113.1` | 지사의 공인 주소로는 반드시 본사의 인터넷 회선으로 |

BR-R1의 기본 경로는 OSPF가 알려 준 "본사 쪽"이다. 이 줄이 없으면 지사 라우터는 겉 상자를 주 회선(Gi0/1)으로 본사에 보낸다. 주 회선이 살아 있을 때는 우연히 통하지만, 주 회선이 끊기는 순간 겉 상자도 갈 길을 잃는다. 예비 길이 주 회선에 기대는 셈이라 예비가 아니다.

더 나쁜 경우도 있다. 터널의 목적지로 가는 길이 터널 자신을 가리키면, 상자를 넣은 상자를 다시 그 상자에 넣으려는 고리가 된다. 라우터는 `%TUN-5-RECURDOWN` 알림과 함께 터널을 내린다. 터널의 두 끝으로 가는 길은 늘 인터넷 쪽으로 못 박는다. 4일차의 가장 구체적인 줄 규칙(/32 한 주소)이 여기서도 쓰인다.

## 3. 터널 인터페이스

```
interface tunnel 0
 ip address 192.168.99.13 255.255.255.252
 tunnel source se0/0/1
 tunnel destination 203.0.113.6
```

| 명령 | 하는 일 |
|---|---|
| `interface tunnel 0` | 논리적인 포트를 만든다. 6일차 루프백과 같은 종류 |
| `ip address` | 터널 안쪽의 주소. 2일차 설계표의 192.168.99.0/24에서 다음 /30 |
| `tunnel source` | 겉 상자의 출발지. 내 인터넷 쪽 포트 |
| `tunnel destination` | 겉 상자의 목적지. 상대의 공인 주소 |

BR-R1은 주소가 192.168.99.14, 목적지가 203.0.113.2다. 모드를 따로 적지 않으면 GRE다. 두 끝을 모두 만들고 `ping 192.168.99.14`가 되면 터널이 선 것이다.

| 구간 | 대역 |
|---|---|
| 지사 주 회선 | 192.168.99.0/30 |
| 지사 예비 회선 (오늘 해지) | 192.168.99.4/30 |
| 한결물류 연결 | 192.168.99.8/30 |
| 본사와 지사 터널 | 192.168.99.12/30 |

## 4. 터널 위로 OSPF

터널은 OSPF에게 평범한 포트 하나다. 6일차에 한 대로 네트워크를 고르고, passive를 풀고, 인증을 건다.

```
router ospf 1
 network 192.168.99.12 0.0.0.3 area 0
 no passive-interface tunnel0
interface tunnel 0
 ip ospf authentication message-digest
 ip ospf message-digest-key 1 md5 <key>
```

OSPF는 터널의 비용을 크게 본다. 터널의 대역폭 값이 작게 잡혀 있기 때문이다. 그래서 평소에는 주 회선(비용 1)을 쓰고, 주 회선이 끊길 때만 터널로 간다. 4일차에 예비 시리얼 회선이 하던 일을 터널이 그대로 이어받는다.

HQ-R1에서는 터널에 `ip nat inside`도 건다. 9일차에 지사 쪽 포트 두 곳을 inside로 둔 것처럼, 장애 때 터널로 들어오는 지사의 인터넷 통신도 PAT로 나가야 한다.

## 5. 예비 회선 해지와 장애 시험

예비 시리얼 회선은 해지했으니 양쪽 Se0/0/0을 `shutdown`한다. 그리고 4일차부터 이어 온 장애 시험을 다시 한다.

| 순서 | 할 일 | 보이는 것 |
|---|---|---|
| 1 | BR-PC1에서 `ping -t 192.168.10.98` | Reply |
| 2 | HQ-R1 Gi0/1을 `shutdown` | 몇 번 끊긴 뒤 다시 Reply |
| 3 | BR-R1 `show ip route ospf` | 본사 대역이 Tunnel0으로, 비용이 큰 값 |
| 4 | BR-PC1에서 `tracert 192.168.10.98` | 192.168.20.1, 192.168.99.13, 192.168.10.98 |
| 5 | HQ-R1 Gi0/1을 `no shutdown` | 다시 주 회선으로 |

4번의 tracert에 ISP-R1이 보이지 않는다. 겉 상자가 인터넷을 지나는 동안 안의 패킷은 TTL이 줄지 않으니, 지사에서 보면 본사 라우터까지 한 칸이다. 키워드 요약이 GRE를 "경로 은폐"라고 부른 이유다. 다만 숨는 것은 경로이고, 내용은 숨지 않는다.

{% hint style="info" %}
NOTE: 4일차, 6일차의 장애 시험 결과와 오늘 끊긴 ping 개수를 지사 연결 기록에 나란히 적는다. 같은 시험을 회차마다 되풀이한 기록이 16일차 보고서의 가용성 절이 된다.
{% endhint %}

## 약어·용어

| 용어 | 뜻 |
|---|---|
| `tunnel source` | 겉 상자의 출발지로 쓰는 내 인터넷 쪽 포트 |
| `tunnel destination` | 겉 상자의 목적지. 상대 라우터의 공인 주소 |
| /32 경로 | 한 주소만을 가리키는 가장 구체적인 정적 경로. 터널 끝으로 가는 길을 못 박는 데 쓴다 |
| `%TUN-5-RECURDOWN` | 터널 목적지로 가는 길이 터널 자신을 가리킬 때 라우터가 터널을 내리며 띄우는 알림 |
| O*E2 | OSPF가 알려 준, 밖에서 들어온 기본 경로 |
| 경로 은폐 | 안의 패킷의 TTL이 줄지 않아 tracert에 중간 경로가 보이지 않는 현상. 내용이 숨는 것은 아니다 |

## 함께 생각해 보기

- 2번 절의 경로를 빠뜨린 채 장애 시험을 하면 무엇이 보이는가.
- 터널이 주 회선보다 비용이 작게 잡혔다면 평소에 무슨 일이 생기는가.

## 강의 메모

### 시간 배분 (45분)

| 절 | 시간 | 방식 |
|---|---|---|
| 라이선스와 재시작 | 7분 | 대본 1번. 노트 1번을 설명하는 동안 미리 걸어 둔다 |
| 목적, 1, 2 | 10분 | 대본 2번. 터널 끝으로 가는 길의 이유 |
| 3 터널 | 8분 | 대본 3번 |
| 4 OSPF | 8분 | 대본 4번 |
| 5 해지와 장애 시험 | 12분 | 대본 5번 |

### 물어볼 것

- "지사의 일반 인터넷은 왜 지사 회선으로 바로 나가지 않을까?" 경계의 방화벽과 기록을 본사 한 곳에 모으기 위해서다. 대신 지사의 인터넷은 본사 회선에 기댄다.
- "tracert에 ISP가 안 보이는 것은 ISP를 안 지나서일까?" 지난다. 안의 패킷은 겉 상자 안에 있어 TTL이 줄지 않을 뿐이다.
- 첫 번째 함께 생각해 보기의 답: 주 회선을 끊는 순간 터널의 겉 상자도 주 회선으로 가려다 막혀 터널이 함께 내려간다. 예비가 동작하지 않는다.

### 자주 헷갈리는 것

| 헷갈리는 것 | 바로잡기 |
|---|---|
| `tunnel destination`에 상대의 터널 주소(.14)를 쓴다 | 상대의 공인 주소(203.0.113.6)를 쓴다 |
| 터널이 up인데 ping이 안 된다 | 상대 쪽 터널이 없거나, 겉 상자의 목적지로 가는 길이 없다 |
| `%TUN-5-RECURDOWN`이 뜬다 | 터널 목적지로 가는 길이 터널 자신을 가리킨다. 2번 절의 /32 경로 |
| 장애 때 지사가 인터넷에 못 나간다 | HQ-R1 Tunnel0에 `ip nat inside`가 없다 |

### 진행 요령

- 대본 1번의 라이선스 명령은 재시작이 필요해 노트 1번 설명을 시작할 때 미리 걸어 두게 한다. 저장을 빠뜨리면 재시작으로 설정이 사라진다.
- 터널의 비용 숫자는 패킷트레이서 버전에 따라 다를 수 있다. 숫자보다 "주 회선보다 크다"를 확인한다.
