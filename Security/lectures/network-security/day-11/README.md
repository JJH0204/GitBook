# 11일차 VPN과 IPv6

> 상위: [네트워크 보안 강의계획서](../plan.md)
> 이전: [10일차 ACL과 첫 침해사고](../day-10/README.md)
> 다음: 12일차 패킷 분석과 사고 02 (작성 예정)

새봄상사는 비싼 예비 시리얼 회선의 계약을 끝내고, 지사에 들인 인터넷 회선 위의 VPN을 예비로 쓰기로 했습니다. GRE로 터널을 만들어 장애 때 지사가 터널로 넘어가게 하고, 시뮬레이션 모드로 터널 안의 내용이 인터넷에서 그대로 보이는 것을 확인한 뒤 IPSec으로 암호화합니다. 암호화 전후의 두 화면이 오늘의 산출물입니다.

마지막으로 IPv6를 켜 봅니다. 10일차에 건 IPv4 ACL을 IPv6가 그대로 비켜 가는 것을 보고, 정책은 주소 체계마다 있어야 한다는 것을 배웁니다.

## 학습 목표

- 전용선과 VPN, 터널과 GRE, 사이트 간 VPN과 원격 접속 VPN을 구분합니다
- GRE 터널을 맺고 OSPF를 그 위로 돌려, 주 회선 장애 때 터널로 넘어가게 합니다
- IPSec(IKE 1단계와 2단계, crypto map)을 얹고 암호화 전후의 패킷을 비교합니다
- IPv6 주소를 읽고, 듀얼 스택에서 IPv4 ACL을 비켜 가는 통신을 IPv6 ACL로 막습니다

### 새봄상사 11일차 작업 계획서

#### 1. 목표

- 예비 시리얼 회선을 해지하고, 인터넷 위의 VPN을 본사와 지사의 예비 길로 쓴다
- 인터넷을 지나는 본사와 지사의 통신을 암호화한다
- IPv6를 시범으로 켜고, IPv4 정책이 IPv6에도 닿는지 점검한다

#### 2. 작업 대상

| 대상 | 무엇을 |
|------|--------|
| HQ-R1, BR-R1 | 보안 라이선스, 터널 끝으로 가는 /32 경로, Tunnel0, 터널 위 OSPF, IPSec, Se0/0/0 해지 |
| BR-R1, ISP-R1 | 지사의 인터넷 회선 203.0.113.4/30 |
| HQ-R1 | IPv6 시범(영업팀, 인사팀), SALES-IN6 |
| `04_보안정책/VPN_정책.md` (새로) | VPN 정책과 암호화 전후 캡처 |
| `03_구축/지사_연결.md` | 예비 회선 변경과 장애 시험 |

#### 3. 작업 내용

1. 두 라우터에 보안 라이선스를 켜고 재시작한다. 먼저 저장한다
2. 지사를 인터넷에 잇고, 터널 끝으로 가는 길을 /32로 못 박는다
3. GRE 터널을 맺고 그 위로 OSPF와 인증을 건다
4. 예비 시리얼 회선을 끄고, 주 회선 장애 시험으로 터널로 넘어가는 것을 본다
5. 시뮬레이션 모드로 GRE 상자를 연 뒤, IPSec을 얹고 다시 연다
6. 영업팀과 인사팀에 IPv6를 켜고, IPv6 ACL로 정책을 맞춘다

#### 4. 확인 방법

| 확인할 것 | 방법 | 기대하는 결과 |
|-----------|------|---------------|
| 터널이 섰다 | HQ-R1에서 `ping 192.168.99.14` | Reply |
| 터널 위 OSPF | `show ip ospf neighbor` | Tunnel0 쪽 이웃 FULL |
| 장애 때 터널로 | Gi0/1 shutdown 중 BR-PC1의 `ping -t`, BR-R1 경로표 | 몇 개 빠진 뒤 Reply, Tunnel0 경유 |
| 암호화된다 | `show crypto ipsec sa` | encrypt, decrypt 횟수 증가 |
| 인터넷에서 안이 안 보인다 | 시뮬레이션 모드로 ISP-R1의 패킷 | 겉 IP 다음 ESP |
| IPv6로도 영업팀에서 인사팀이 막힌다 | Sales-PC1에서 IPv6 ping | 닿을 수 없음 |

#### 5. 되돌리는 방법

- 터널이 꼬이면 `no interface tunnel 0` 과 Se0/0/0 `no shutdown` 으로 4일차의 예비 회선으로 돌아간다
- IPSec 때문에 터널이 끊기면 Se0/0/1에서 `no crypto map VPNMAP` 으로 떼면 GRE만으로 다시 통한다
- IPv6는 `no ipv6 unicast-routing` 으로 끄면 PC들의 IPv6 주소도 사라진다

## 수업 전에 확인할 것

- 패킷트레이서 2911에서 `license boot module c2900 technology-package securityk9` 와 재시작이 되는지, 재시작에 걸리는 시간
- `crypto isakmp policy` 의 `encryption aes 256`, `group 5` 를 받는지. 안 되면 `aes`, `group 2`
- GRE 위에 crypto map을 건 구성(GRE over IPSec)이 패킷트레이서에서 동작하는지, `show crypto ipsec sa` 의 횟수가 느는지
- 시뮬레이션 모드에서 GRE 패킷의 안쪽 IP와 ESP가 PDU 정보에 어떻게 보이는지
- 터널 인터페이스의 OSPF 비용이 패킷트레이서에서 몇으로 잡히는지(주 회선보다 큰지)
- PC의 IPv6 자동 설정, 서브인터페이스의 IPv6 주소, `ipv6 traffic-filter` 가 되는지
- 강사 레퍼런스 저장소에 새봄상사의 VPN 정책과 캡처 두 장, 지사 연결 기록의 변경이 미리 커밋되어 있는지
