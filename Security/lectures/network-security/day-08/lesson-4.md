## 1. 가짜 DHCP 서버

같은 VLAN에 DHCP 서버가 하나 더 있으면, PC는 먼저 답한 쪽의 설정을 받는다.

| 가짜가 알려 주는 것 | 생기는 일 | 깨지는 것 |
|---|---|---|
| 게이트웨이를 가짜 자신으로 | 밖으로 가는 모든 통신이 가짜를 거친다 | 기밀성, 무결성 |
| DNS를 가짜 서버로 | 주소창에 쇼핑몰 이름을 쳐도 가짜 사이트로 간다 | 기밀성 |
| 엉뚱한 대역의 주소 | PC가 아무 데도 닿지 못한다 | 가용성 |

가장 흔한 범인은 공격자가 아니다. 직원이 집에서 쓰던 공유기를 자리에 꽂으면, 공유기의 DHCP가 켜진 채로 옆자리 PC들에게 192.168.0.x 주소를 나눠 준다. 아침에 출근한 영업팀 절반이 인터넷이 안 된다고 하는 사고가 이렇게 생긴다.

## 2. 시연: 영업팀 자리의 가짜 서버

강사가 HQ-SW1의 Fa0/3(영업팀 자리)에 서버 한 대를 꽂고 DHCP 서비스를 켠다. 가짜는 게이트웨이를 자기 주소로 알려 준다. 이 시연은 패킷트레이서의 가상 실습망 안에서만 한다.

| 칸 | 가짜 서버의 값 |
|---|---|
| 서버 자신의 주소 | 192.168.10.25 |
| Default Gateway | 192.168.10.25 |
| Start IP Address | 192.168.10.21 |

영업팀 PC에서 IP Configuration을 Static으로 바꿨다가 다시 DHCP로 바꾼다. 게이트웨이 칸에 192.168.10.25가 보이면 가짜에게 받은 것이다. 이 PC가 지사로 보내는 패킷은 이제 가짜 서버로 간다.

## 3. DHCP 스누핑

스위치가 포트를 두 가지로 나눈다.

| 포트 | DHCP 서버의 답(Offer, Ack) | 새봄상사 |
|---|---|---|
| 믿는 포트 (trust) | 통과 | 진짜 서버의 답이 들어오는 쪽 |
| 믿지 않는 포트 (기본) | 버린다 | PC 자리 전부, HQ-DSW1 쪽 |

PC의 요청(Discover, Request)은 어느 포트에서든 통과한다. 버리는 것은 서버만 보내는 답이다. 그래서 PC 자리에 서버를 꽂아도 그 서버의 답은 스위치에서 사라진다. 1일차의 기본 거부와 같다. 모든 포트를 믿지 않는 것에서 시작해 진짜 서버 쪽만 연다.

| 스위치 | 믿는 포트 | 이유 |
|---|---|---|
| HQ-SW1 | Gi0/1 | HQ-R1(DHCP 서버) 쪽 |
| HQ-SW2 | Gi0/1 | HQ-SW1을 거쳐 서버의 답이 들어오는 쪽 |
| BR-SW1 | Gi0/1 | BR-R1(릴레이)이 본사의 답을 전해 주는 쪽 |

HQ-SW1이다.

```
ip dhcp snooping
ip dhcp snooping vlan 10,20,30,40
no ip dhcp snooping information option
interface gi0/1
 ip dhcp snooping trust
```

세 번째 줄은 짝을 맞추는 줄이다. 스누핑을 켠 스위치는 PC의 요청에 "몇 번 포트에서 왔다"는 꼬리표(옵션 82)를 붙인다. 시스코 라우터의 DHCP 서버는 릴레이를 거치지 않았는데 꼬리표가 붙은 요청을 이상하다고 보고 버린다. 그래서 스위치가 꼬리표를 붙이지 않게 한다. 이 줄을 빼면 스누핑을 켜는 순간 진짜 서버에서도 주소를 받지 못한다.

스누핑을 켜고 영업팀 PC가 다시 주소를 받으면 게이트웨이는 192.168.10.1로 돌아온다.

```
HQ-SW1#show ip dhcp snooping
Switch DHCP snooping is enabled
DHCP snooping is configured on following VLANs:
10,20,30,40
...
Interface                  Trusted    Allow option    Rate limit (pps)
-----------------------    -------    ------------    ----------------
GigabitEthernet0/1         yes        yes             unlimited
```

스누핑은 덤으로 표 하나를 만든다. 어느 포트의 어느 MAC 주소가 어느 주소를 받았는지다(`show ip dhcp snooping binding`). 12일차에 같은 네트워크 안에서 주소를 속이는 공격을 막을 때 스위치가 이 표를 기준으로 쓴다.

## 4. 주소를 바닥내는 공격

공격자가 MAC 주소를 바꿔 가며 Discover를 수천 번 외치면, 풀의 주소가 모두 빌려 나가고 진짜 직원의 PC는 169.254를 붙인다. 주소 고갈 공격이라고 한다.

| 막는 방법 | 언제 |
|---|---|
| 믿지 않는 포트의 DHCP 요청 수를 제한한다: `ip dhcp snooping limit rate` | 더 해 볼 것 |
| 포트 하나에 붙을 수 있는 MAC 주소의 수를 제한한다: 포트 보안 | 12일차 |

## 5. HSRP 가로채기와 인증

HSRP 장비들은 3초마다 "나는 그룹 10, 우선순위 110"이라고 알린다. 영업팀 자리에 장비를 꽂고 "나는 그룹 10, 우선순위 255, preempt"라고 알리면, 그 장비가 Active가 된다. 영업팀 PC들이 게이트웨이로 보내는 패킷이 모두 그 장비로 간다. 가짜 DHCP와 같은 결과를 DHCP 없이 얻는 셈이다.

인증을 걸면 진짜 두 장비는 키를 모르는 장비의 알림을 무시한다.

```
interface vlan 10
 standby 10 authentication md5 key-string <password>
```

HQ-R1의 Gi0/0.10에도 같은 줄을 넣고, 그룹 20, 30, 40도 같게 한다. 5일차부터 같은 원리다.

인증에는 두 가지를 덧붙여 알아 둔다.

| 알아 둘 것 | 내용 |
|---|---|
| 한쪽에만 걸면 | 두 장비가 서로의 알림을 무시하고 둘 다 Active가 된다. 가상 주소가 둘로 갈라진다 |
| 인증이 막는 것 | 진짜 장비가 가짜에게 Active를 내주는 것. 가짜가 가상 주소의 주인 행세를 하며 PC를 속이는 것은 따로 막아야 하고, 12일차에 본다 |

그래서 두 장비에 같은 순간에 걸고, 걸자마자 `show standby brief`로 Active가 하나인지 본다.

## 약어·용어

| 용어 | 뜻 |
|---|---|
| 가짜 DHCP 서버(rogue DHCP server) | 허가받지 않은 장비가 켠 DHCP 서버. 잘못 꽂은 공유기도 해당한다 |
| DHCP 스누핑(snooping) | 믿는 포트에서 온 서버의 답만 통과시키고 나머지 포트의 답은 버리는 스위치 기능 |
| 믿는 포트(trust) | 진짜 DHCP 서버의 답이 들어오는 포트. 스위치마다 하나씩 정한다 |
| 옵션 82 | 스누핑한 스위치가 요청에 붙이는 "몇 번 포트에서 왔다"는 꼬리표 |
| 주소 고갈 공격 | MAC 주소를 바꿔 가며 Discover를 보내 풀의 주소를 모두 빌려 가는 공격 |
| HSRP 인증 | 키를 아는 장비의 알림만 믿게 하는 설정 |
| 바인딩 표 | 스누핑이 만드는 포트, MAC, 주소의 대응표 |

### 물어볼 것

- "PC는 어느 DHCP 서버가 진짜인지 알 수 있을까?" 모른다. 먼저 답한 쪽을 받는다.
- "스누핑은 PC의 요청도 막을까?" 아니다. 믿지 않는 포트에서 들어오는 서버의 답만 버린다.
- "HQ-DSW1 쪽 포트(Fa0/23)는 믿어야 할까?" 아니다. HQ-DSW1은 DHCP 서버가 아니다. 믿는 포트는 적을수록 좋다.
- 두 번째 함께 생각해 보기의 답: HQ-R1의 `show ip dhcp binding`에 우리가 준 주소가 없는 PC, 그리고 스누핑을 켰다면 스위치 로그에 버려진 답이 들어온 포트가 남는다. 15일차 모니터링에서 이런 기록을 모아 본다.

### 자주 헷갈리는 것

| 헷갈리는 것 | 바로잡기 |
|---|---|
| 믿는 포트에 PC 자리를 넣는다 | 믿는 포트는 진짜 서버의 답이 들어오는 쪽뿐이다 |
| 스누핑을 켜면 바로 동작한다 | `ip dhcp snooping vlan`으로 VLAN을 정해야 한다 |
| 스누핑을 켜자 모두 주소를 못 받는다 | `no ip dhcp snooping information option`을 빠뜨렸다 |
| HSRP 인증은 가짜의 모든 행동을 막는다 | 진짜 장비가 자리를 내주지 않게 할 뿐이다 |

### 진행 요령

- 가짜 서버 시연에서 진짜 서버가 먼저 답하면 PC의 DHCP를 몇 번 다시 받는다. 누가 먼저 답하느냐의 경주라는 것 자체가 설명이 된다.
- 시연이 끝나면 강사는 가짜 서버를 지우거나 DHCP 서비스를 끈다. 학생 파일에는 가짜 서버를 두지 않는다.
- HSRP 가로채기는 시연하지 않고 말로 설명한다. 시간이 남으면 강사가 영업팀 자리에 라우터를 꽂아 우선순위 255로 Active를 빼앗는 것을 보여 주고, 인증을 건 뒤 다시 본다.
- 1일차와 12일차의 고지처럼, 가짜 서버와 가짜 게이트웨이는 각자의 실습 파일 안에서만 다룬다.
