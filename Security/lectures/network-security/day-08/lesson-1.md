## 목적

2일차에 169.254로 시작하는 주소를 "주소를 자동으로 받지 못했다는 신호"라고만 짚고 넘어갔다. 오늘 그 자동으로 주는 쪽을 만든다.

## 1. DHCP가 나눠 주는 것

DHCP(Dynamic Host Configuration Protocol)는 네트워크에 들어온 장비에 설정을 자동으로 나눠 주는 서비스다.

| 나눠 주는 것 | 예 (새봄상사 영업팀) |
|---|---|
| IP 주소 | 192.168.10.10 |
| 서브넷 마스크 | 255.255.255.224 |
| 기본 게이트웨이 | 192.168.10.1 |
| DNS 서버 | (9일차 이후) |
| 빌려주는 기간(임대 기간) | 기본 1일 |

DHCP는 주소를 영원히 주지 않고 빌려준다. 기간이 끝나기 전에 PC가 연장을 요청하고, 오래 안 쓰인 주소는 다른 장비에 다시 빌려준다.

## 2. 주소를 받는 네 단계

새로 들어온 PC는 자기 주소도, DHCP 서버의 주소도 모른다. 그래서 처음에는 네트워크 전체에 외친다.

| 단계 | 방향 | 내용 |
|---|---|---|
| Discover | PC에서 모두에게 (브로드캐스트) | "DHCP 서버 있나요?" |
| Offer | 서버에서 PC로 | "192.168.10.10을 쓰세요" |
| Request | PC에서 모두에게 (브로드캐스트) | "그 주소를 쓰겠습니다" |
| Ack | 서버에서 PC로 | "확정. 기간은 하루" |

첫 글자를 따서 DORA라고 부른다. Request를 다시 모두에게 외치는 이유는, 서버가 여러 대일 때 고르지 않은 서버들에게도 "다른 서버의 제안을 받았다"고 알리기 위해서다.

PC가 Discover를 외쳤는데 아무도 답하지 않으면, PC는 169.254로 시작하는 주소를 스스로 붙인다. 2일차의 그 주소다.

{% hint style="info" %}
NOTE: 4번 노트에서 이 "아무나 답할 수 있다"는 성질을 노린 공격과 막는 법을 본다.
{% endhint %}

## 3. 라우터를 DHCP 서버로

시스코 라우터는 DHCP 서버 역할도 할 수 있다. 새봄상사는 본사 라우터 HQ-R1이 모든 부서의 주소를 나눠 준다.

```
ip dhcp excluded-address 192.168.10.1 192.168.10.9
ip dhcp excluded-address 192.168.10.21 192.168.10.30
ip dhcp pool SALES
 network 192.168.10.0 255.255.255.224
 default-router 192.168.10.1
```

| 명령 | 하는 일 |
|---|---|
| `ip dhcp excluded-address 시작 끝` | 이 범위는 빌려주지 않는다 |
| `ip dhcp pool SALES` | 주소를 빌려줄 묶음(풀)을 만든다 |
| `network` | 이 풀이 빌려줄 대역 |
| `default-router` | PC에게 알려 줄 게이트웨이 |

제외 주소를 먼저 넣는 이유는, 게이트웨이나 장비에 손으로 준 주소를 DHCP가 다른 PC에게 빌려주면 주소가 겹치기 때문이다. 새봄상사는 대역마다 앞쪽 아홉 개(.1~.9)와 뒤쪽(.21~.30)을 장비용으로 남긴다. 뒤쪽 범위의 마지막 두 주소는 3번 노트에서 라우터와 L3 스위치의 실제 주소로 쓰고, 나머지는 프린터 같은 고정 장비 자리다.

지사 풀(BR-SALES)도 본사 라우터에 만들어 두기만 한다. 지사 PC가 이 풀에서 주소를 받는 길은 2번 노트에서 연다.

| 풀 | 대역 | 게이트웨이 | 빌려주는 주소 |
|---|---|---|---|
| SALES | 192.168.10.0/27 | .1 | .10 ~ .20 |
| HR | 192.168.10.32/27 | .33 | .42 ~ .52 |
| DEV | 192.168.10.64/27 | .65 | .74 ~ .84 |
| BR-SALES | 192.168.20.0/27 | 192.168.20.1 | 192.168.20.10 ~ .20 |

빌려준 현황은 `show ip dhcp binding`으로 본다. 어느 MAC 주소의 장비에 어느 주소를 언제까지 빌려줬는지 나온다.

## 4. 고정 주소로 남길 장비

모든 장비를 DHCP로 두지는 않는다. 주소가 바뀌면 다른 장비가 찾아오지 못하는 장비는 고정 주소를 쓴다.

| 장비 | 주소 | 이유 |
|---|---|---|
| 사무실 PC, 노트북 | DHCP | 바뀌어도 아무도 찾아오지 않는다 |
| 서버(VLAN 40) | 고정 | 직원들이 이 주소로 찾아온다 |
| 라우터, 스위치(VLAN 99) | 고정 | 관리자가 이 주소로 접속하고, 다른 장비의 게이트웨이다 |
| 관리자 PC | 고정 | 10일차에 이 주소만 장비 접속을 허락한다 |

{% hint style="info" %}
NOTE: 10일차에 관리자 PC의 주소로 장비 접속을 허락할 것이므로, 관리자 PC가 DHCP로 주소를 받으면 날마다 규칙이 어긋난다.
{% endhint %}

## 약어·용어

| 용어 | 뜻 |
|---|---|
| DHCP(Dynamic Host Configuration Protocol) | 주소, 마스크, 게이트웨이 같은 설정을 자동으로 빌려주는 서비스 |
| DORA | Discover, Offer, Request, Ack의 첫 글자. 주소를 받는 네 단계 |
| 풀(pool) | DHCP 서버가 빌려줄 주소의 묶음. 대역마다 하나 만든다 |
| 제외 주소(excluded-address) | 풀 안에 있어도 빌려주지 않는 범위. 전역 설정으로 넣는다 |
| 임대 기간(lease) | 주소를 빌려주는 기간. 기본 1일 |
| 169.254.x.x | 주소를 받지 못한 PC가 스스로 붙이는 주소 |
| 바인딩(binding) | 어느 MAC 주소의 장비에 어느 주소를 빌려줬는지 적은 표 |

- DHCP 서버가 멈추면, 이미 주소를 받은 PC와 새로 켠 PC는 각각 어떻게 될까.

## 강의 메모

| 절 | 시간 | 방식 |

### 물어볼 것

- "새로 들어온 PC는 DHCP 서버의 주소를 알까?" 모른다. 그래서 모두에게 외친다.
- "PC가 169.254 주소를 갖고 있다면 무슨 뜻일까?" 외쳤는데 아무도 답하지 않았다는 뜻이다.
- 두 번째 함께 생각해 보기의 답: 이미 받은 PC는 임대 기간 동안 그 주소를 계속 쓴다. 새로 켠 PC는 주소를 받지 못해 169.254를 붙이고 통신하지 못한다. DHCP 서버도 가용성을 지켜야 할 장비다.

### 자주 헷갈리는 것

| 헷갈리는 것 | 바로잡기 |
|---|---|
| DHCP 순서는 Request, Reply, Request, Ack | Discover, Offer, Request, Ack다 |
| `excluded-address`를 풀 안에 넣는다 | 풀 밖(전역 설정)에 넣는다 |
| 서버도 DHCP로 받으면 편하다 | 주소가 바뀌면 직원들이 서버를 찾지 못한다 |
| DHCP를 켜면 PC가 저절로 받는다 | PC의 IP Configuration을 DHCP로 바꿔야 요청한다 |

### 진행 요령

- 패킷트레이서 PC의 IP Configuration에서 DHCP를 고르면 "DHCP request successful"이 뜨고 주소가 채워진다. 첫 번째 성공 화면을 같이 본다.
- 시스코 라우터의 DHCP 서버는 처음부터 켜져 있다. 꺼져 있으면 `service dhcp`로 켠다.
