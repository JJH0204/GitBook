## 3. 안전 사항

{% hint style="danger" %}
WARNING: 설정 텍스트(`configs/*.txt`)를 커밋하기 전에 `enable secret`, `password` 줄의 비밀번호를 `<password>`로 바꾼다. 공개 저장소에 올린 비밀번호는 지워도 커밋 기록에 남는다.

{% hint style="warning" %}

{% endhint %}

## 5. 절차

### A. 내 회사 지사 주소

1. (5-A-01) VS Code에서 `02_설계/IP_설계표.md`를 연다.
2. (5-A-02) 예비 회선 줄을 더한다. 본사와 지사 연결 /30 다음의 /30을 쓴다. → 결과: 설계표에 예비 회선 줄이 생긴다.

```markdown
| 연결 | 본사와 지사 예비 | 192.168.__.4/30 | 없음 | .5 본사, .6 지사 | 시리얼 | 4일차 |
```

### B. 내 파일에서 지사 연결과 장애 시험

1. (5-B-01) `_실습/새봄상사.pkt`를 저장하고 닫은 뒤 `configs/network.pkt`를 연다.
2. (5-B-02) [2-1 실습](lesson-2-lab.md)의 절차를 내 설계표의 주소로 입력한다. 장비 이름과 포트는 새봄상사와 같아도 된다. → 결과: 지사 PC에서 본사 서버로 ping이 성공한다.
3. (5-B-03) 경로를 잘못 넣었으면 앞에 `no`를 붙여 같은 줄을 입력해 지운다.

```
no ip route 192.168.20.0 255.255.255.224 192.168.99.2
```

4. (5-B-04) [3-1 실습](lesson-3-lab.md)의 절차를 내 주소로 입력한다. → 결과: 장애 시험에서 `[250/0]` 경로가 보인다.
5. (5-B-05) 2-1 실습의 확인(tracert, `show ip route static`)을 내 주소로 다시 한다.

### C. 장애 시험 기록과 설정 텍스트

1. (5-C-01) 장애 시험에서 끄기 전과 뒤의 `show ip route static` 출력을 복사해 둔다.
2. (5-C-02) [4번 노트](lesson-4.md) 5번 절의 양식으로 `03_구축/지사_연결.md`를 쓴다. → 결과: 구성, 경로, 장애 시험(빠진 ping 개수, 한계)이 들어 있다.
3. (5-C-03) `configs/`에 HQ-R1, BR-R1, BR-SW1의 설정 텍스트를 저장한다. 비밀번호는 `<password>`로 바꾼다.
4. (5-C-04) 바뀐 줄을 확인한다: `git diff configs/HQ-R1.txt` → 결과: Gi0/1, Se0/0/0과 `ip route` 줄이 더해진 것이 보인다.

### D. 결과 기록과 커밋

1. (5-D-01) `00_작업계획/04일차.md`의 결과 칸(한 일, 확인 결과, 막힌 곳, 다음 회차에 이어서 할 일)을 채운다.
2. (5-D-02) README의 진행 현황 표에 한 줄을 더한다.

```markdown
| 4 | 지사 연결, 정적 경로, 예비 회선, 장애 시험 | [작업 계획서](00_작업계획/04일차.md), [지사 연결](03_구축/지사_연결.md), [설정](configs/) |
```

3. (5-D-03) 커밋하고 올린다.

```bash
git add .
git commit -m "4일차: 지사 연결과 정적 경로, 예비 회선 장애 시험"
git push
```

→ 결과: push가 오류 없이 끝나고 GitHub에서 새 파일이 보인다.

## 7. 복구

1. (7-01) 경로를 잘못 넣었으면 같은 줄 앞에 `no`를 붙여 지운다.
2. (7-02) 주 회선이 꺼진 채라면 HQ-R1의 Gi0/1에서 `no shutdown`을 입력한다.
3. (7-03) 커밋을 취소하려면 push 전에 `git reset --soft HEAD~1`을 쓴다. 이미 push했다면 새 커밋으로 고친다.
