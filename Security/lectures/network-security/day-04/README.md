## 개요

3일차까지 새봄상사는 본사 안에서만 통했다. 오늘은 서울 지사를 잇는다. 라우터는 직접 붙지 않은 네트워크를 모르므로, 관리자가 정적 경로로 길을 알려 준다. 그리고 회선 하나가 끊겨도 지사가 멈추지 않도록 예비 회선을 두고, 실제로 끊어 보는 장애 시험을 한다.

오늘이 끝나면 저장소에 지사 장비 두 대의 설정과, 이중화를 증명하는 장애 시험 기록이 더해진다.

### 새봄상사 4일차 작업 계획서

#### 1. 목표

- 프로젝트 계획서 3번 칸의 "지사 영업팀은 본사의 주문 관리와 파일 서버를 쓴다"를 이룬다.
- 본사와 지사 사이 회선 하나가 끊겨도 지사가 멈추지 않게 한다 (계획서 4번 칸의 가용성).

#### 2. 작업 대상

| 대상 | 무엇을 |
|---|---|
| BR-R1, BR-SW1 (새로) | 기본 잠금, 스위치 보안, 지사 영업팀 주소 |
| HQ-R1 | Gi0/1 주 회선, Se0/0/0 예비 회선, 지사로 가는 경로 |
| 두 라우터 | HWIC-2T 시리얼 모듈 |
| `02_설계/IP_설계표.md` | 예비 회선 192.168.99.4/30 |
| `03_구축/지사_연결.md` | 구성과 장애 시험 기록 |

#### 3. 작업 내용

1. 지사 장비를 놓고 잠근다.
2. 주 회선 192.168.99.0/30으로 두 라우터를 잇는다.
3. 본사에 지사로 가는 정적 경로, 지사에 기본 경로를 넣는다.
4. 두 라우터에 시리얼 모듈을 꽂고 예비 회선 192.168.99.4/30을 잇는다.
5. 관리 거리 250의 예비 경로를 넣는다.
6. 주 회선을 끊어 장애 시험을 한다.

#### 4. 확인 방법

| 확인할 것 | 방법 | 기대하는 결과 |
|---|---|---|
| 두 라우터가 이어졌다 | BR-R1에서 `ping 192.168.99.1` | Reply |
| 지사에서 본사로 간다 | BR-PC1에서 `tracert 192.168.10.98` | 세 칸 |
| 경로가 들어갔다 | `show ip route static` | 본사 S, 지사 S* |
| 예비 회선이 이어졌다 | HQ-R1에서 `ping 192.168.99.6` | Reply |
| 장애 때 넘어간다 | 본사 Gi0/1 shutdown 중 BR-PC1의 `ping -t` | 몇 개 빠진 뒤 다시 Reply, 경로표에 [250/0] |

#### 5. 되돌리는 방법

- 모듈을 꽂기 전에 반드시 저장한다. 저장하지 않고 꽂으면 설정이 비고, 저장한 설정이 있으면 그 설정으로 부팅된다.
- 경로를 잘못 넣었으면 같은 줄 앞에 `no`를 붙여 지운다.
- 장애 시험 뒤에는 반드시 `no shutdown`으로 주 회선을 살린다.

#### 6. 결과 (개인 실습이 끝날 때 채운다)

- 한 일:
- 확인 결과:
- 막힌 곳과 어떻게 풀었나:
- 다음 회차에 이어서 할 일: 정적 경로를 동적 라우팅(RIP)으로 바꾸고, 중간 장비 고장도 알아채는지 다시 시험한다

2. 모듈을 꽂다 설정이 날아간 학생. 2일차와 오늘의 대본으로 다시 치게 하고, 저장을 먼저 하는 습관을 짚는다.
3. 장애 시험에서 넘어가지 않는 학생. 예비 회선을 직접 ping해 보게 한다.
4. 나머지 학생은 장애 시험 기록을 읽고, "중간 장비 고장" 한계를 문서에 적었는지 본다.

## 수업 전에 확인할 것

- 패킷트레이서 2911에 HWIC-2T를 넣었을 때 포트 이름이 Serial0/0/0인지.
- Serial DCE 케이블의 DCE 쪽에 clock rate가 저절로 들어가는지, `show controllers serial`이 되는지.
- 패킷트레이서 PC에서 `ping -t`가 되는지. 안 되면 `ping -n 100`으로 대신한다.
- 장애 시험에서 예비 경로로 넘어가기까지 빠지는 ping 개수.
- `show ip route static`, `show running-config | include ip route`가 되는지.
- 강사 레퍼런스 저장소에 새봄상사의 4일차 작업 계획서, 지사 연결 문서, 설정 세 개가 미리 커밋되어 있는지.
