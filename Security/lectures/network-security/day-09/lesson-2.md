## 학습 목표

- ISP 라우터와 인터넷 쪽 장비를 놓고 HQ-R1과 잇는 구성을 안다.
- 기본 경로를 넣고, OSPF로 지사에도 알리는 방법을 안다.
- 4일차에 예고한 null 경로를 넣는 이유를 안다.
- PAT를 설정하고 변환 표를 읽는다.

## 목적

앞 노트에서 NAT는 경계 라우터의 우편실이라고 했다. 새봄상사의 경계 라우터는 HQ-R1이다. 지사와 인수한 회사로 가는 문이 이미 이 라우터에 있으니, 인터넷으로 가는 문도 여기에 단다.

## 1. 인터넷 쪽 장비

| 장비 | 역할 | 주소 |
|---|---|---|
| ISP-R1 (2911) | 인터넷 서비스 회사의 라우터 | Se0/0/0 203.0.113.1/30, Gi0/0 198.51.100.1/24 |
| NET-PC (PC) | 인터넷 어딘가의 PC, 고객 | 198.51.100.10 |
| HQ-R1 Se0/0/1 | 새봄상사의 인터넷 쪽 문 | 203.0.113.2/30 |

HQ-R1에는 4일차에 꽂은 시리얼 모듈의 두 번째 포트(Se0/0/1)가 남아 있다. 여기에 ISP를 잇는다. ISP 쪽이 시계를 맞춰 주는 쪽(DCE)이다.

ISP-R1은 새봄상사의 사설 대역을 모른다. ISP가 새봄상사에 대해 아는 것은 회선(203.0.113.0/30)과 새봄상사에 빌려준 공인 주소 묶음(203.0.113.8/29)뿐이다. 이것이 실제 인터넷과 같은 조건이다.

## 2. 기본 경로와 null 경로

```
ip route 0.0.0.0 0.0.0.0 203.0.113.1
ip route 192.168.0.0 255.255.0.0 null0
router ospf 1
 default-information originate
```

| 명령 | 하는 일 |
|---|---|
| 첫 줄 | 모르는 목적지는 모두 ISP로 |
| 둘째 줄 | 회사 안의 주소인데 경로표에 없는 것은 인터넷으로 내보내지 않고 버린다 |
| `default-information originate` | HQ-R1이 가진 기본 경로를 OSPF로 지사에 알린다 |

{% hint style="info" %}
NOTE: 4일차 4번 노트에서 "9일차에 기본 경로를 넣는 날 null 경로를 함께 넣는다"고 했다. 기본 경로가 생기는 오늘부터, 아직 쓰지 않는 본사 여유 대역(192.168.10.160/27) 같은 회사 안의 주소가 인터넷으로 새어 나갈 수 있기 때문이다.
{% endhint %}

지사 라우터의 경로표에 `O*E2 0.0.0.0/0 [110/1] via 192.168.99.1`이 생긴다. 지사는 6일차 이후 OSPF로 본사와 이어져 있으니, 본사가 알려 준 기본 경로를 따라 인터넷에 나간다. HQ-DSW1은 8일차에 넣은 기본 경로로 HQ-R1에 넘긴다.

인터넷 쪽 포트(Se0/0/1)는 OSPF에 넣지 않는다. OSPF의 `network`에 203.0.113.0이 없고, 6일차의 `passive-interface default`가 있으니 hello가 ISP로 나가지 않는다.

## 3. PAT 설정

```
ip access-list standard NAT-INSIDE
 permit 192.168.10.0 0.0.0.255
 permit 192.168.20.0 0.0.0.255
ip nat inside source list NAT-INSIDE interface se0/0/1 overload
interface se0/0/1
 ip nat outside
interface gi0/0.10
 ip nat inside
```

| 명령 | 하는 일 |
|---|---|
| `ip access-list standard NAT-INSIDE` | 바꿔 줄 출발지 목록. 본사와 지사 |
| `ip nat inside source list ... interface se0/0/1 overload` | 목록에 맞는 출발지를 Se0/0/1의 주소로 바꾸고, 포트까지 바꿔 함께 쓴다(overload = PAT) |
| `ip nat outside` | 인터넷 쪽 포트 |
| `ip nat inside` | 회사 안쪽 포트. 서브인터페이스 다섯 개, 지사 쪽 Gi0/1과 Se0/0/0에 모두 |

여기서 처음으로 ACL이 나온다. 오늘의 ACL은 무엇을 막는 데가 아니라 "누구를 바꿔 줄지" 고르는 데 쓴다. ACL의 원래 쓰임인 막고 허락하기는 10일차에 배운다.

inside를 빠뜨리기 쉬운 곳이 지사 쪽 포트다. 지사 PC의 패킷은 Gi0/1(평소)이나 Se0/0/0(장애 때)으로 HQ-R1에 들어오니, 두 포트 모두 inside여야 지사도 인터넷에 나간다. 4일차 장애 시험이 여기서도 쓸모 있다.

한결물류 쪽 Gi0/2는 inside로 두지 않는다. 인수한 회사의 인터넷은 그 회사가 따로 쓴다. NAT-INSIDE 목록에도 172.16.10.0이 없다.

## 4. 확인

영업팀 PC에서 NET-PC로 ping을 입력한 뒤 HQ-R1의 변환 표를 본다.

```
HQ-R1#show ip nat translations
Pro  Inside global      Inside local       Outside local      Outside global
icmp 203.0.113.2:1      192.168.10.10:1    198.51.100.10:1    198.51.100.10:1
icmp 203.0.113.2:2      192.168.20.10:2    198.51.100.10:2    198.51.100.10:2
```

| 칸 | 첫 줄의 뜻 |
|---|---|
| Inside local | 영업팀 PC의 원래 주소 |
| Inside global | 밖에 보인 주소. 회선 주소 하나를 함께 쓴다 |
| Outside local, Outside global | 상대(NET-PC). 상대 주소는 바꾸지 않으니 둘이 같다 |
| 끝의 :1, :2 | PAT가 구분에 쓴 번호. ping은 포트 대신 식별 번호를 쓴다 |

둘째 줄은 지사 PC다. 두 PC가 같은 203.0.113.2로 나갔다. `show ip nat statistics`로 inside와 outside 포트, 지금 변환 중인 개수를 본다.

변환 표의 줄은 통신이 끝나고 조금 지나면 사라진다. 표가 비어 있으면 ping을 다시 입력하고 바로 본다.

## 약어·용어

| 용어 | 뜻 |
|---|---|
| 기본 경로 (default route) | 경로표에 맞는 줄이 없을 때 쓰는 `0.0.0.0/0` 경로 |
| null 경로 | 다음 장비 대신 `null0`을 가리켜 패킷을 그 자리에서 버리는 경로 |
| `default-information originate` | 라우터가 가진 기본 경로를 OSPF로 이웃에게 알리는 명령 |
| `O*E2` | OSPF가 알려 준 외부(E2) 기본 경로. `*`는 기본 경로 후보 |
| overload | 한 공인 주소에 여러 사설 주소를 포트로 구분해 얹는 PAT 옵션 |
| DCE | 시리얼 회선에서 시계(clock rate)를 맞춰 주는 쪽 |

## 함께 생각해 보기

- 지사 쪽 Se0/0/0에 `ip nat inside`를 빠뜨렸다면, 평소와 장애 때 지사의 인터넷은 각각 어떻게 될까?
- NET-PC에서 203.0.113.2로 ping을 입력하면 영업팀 PC에 닿을까? 변환 표를 떠올려 답해 본다.

### 물어볼 것

- "ISP 라우터에 192.168.10.0으로 가는 길을 넣어 주면 NAT가 필요 없을까?" 실습에서는 통하겠지만 실제 인터넷은 그 길을 받아 주지 않는다. 그래서 넣지 않는다.
- "오늘의 ACL은 무엇을 막나?" 아무것도 막지 않는다. 바꿔 줄 대상을 고를 뿐이다.
- 두 번째 함께 생각해 보기의 답: 영업팀 PC에는 닿지 않는다. 변환 표에 밖에서 먼저 들어온 줄이 없으니 HQ-R1은 누구에게 넘길지 모른다. 203.0.113.2는 HQ-R1 자신의 주소라서, ping에는 HQ-R1이 직접 답한다(경계 라우터가 ping에 답하는 것을 막는 일은 10일차 ACL의 몫이다). 이 성질을 4번 노트에서 다시 본다.

### 자주 헷갈리는 것

| 헷갈리는 것 | 바로잡기 |
|---|---|
| inside와 outside를 거꾸로 건다 | 회사 안쪽이 inside, ISP 쪽이 outside |
| 지사가 인터넷에 못 나간다 | 지사 쪽 포트에 `ip nat inside`가 없거나, `default-information originate`를 빠뜨렸다 |
| `overload`를 빠뜨렸다 | 회선 주소 하나로는 한 번에 한 PC만 나간다 |
| null 경로 때문에 회사 안 통신이 끊길까 걱정 | /16이라 실제로 쓰는 /27, /30 줄에 진다. 4일차의 가장 구체적인 줄 규칙 |

### 진행 요령

- 패킷트레이서가 이름 붙인 ACL(`NAT-INSIDE`)을 NAT에 받지 않으면 번호 ACL(`access-list 10 permit ...`, `ip nat inside source list 10 ...`)로 바꾼다. 수업 전에 확인한다.
- 변환 표는 시뮬레이션 시간이 지나면 금방 비니, 강사가 ping과 `show`를 이어 입력해서 보여 준다.
