## 5. 절차

### A. 밖에서 친 tracert (새봄상사 파일, 대본 9번)

1. (5-A-01) NET-PC의 Command Prompt에서 `tracert 203.0.113.10`을 입력한다.
2. (5-A-02) 출력을 읽는다. → 결과: 1번 줄 198.51.100.1, 2번 줄 203.0.113.2까지 보이고 그 뒤로는 답이 없거나 HQ-R1이 "닿을 수 없음"으로 답한다. 192.168.으로 시작하는 주소가 한 줄도 없다.
3. (5-A-03) Ctrl+C로 멈춘다.
4. (5-A-04) 설정을 바꾼 두 장비(HQ-R1, ISP-R1)에서 `copy running-config startup-config`를 입력해 저장한다.

### B. 내 회사 파일에 1~9번 적용 (대본 10번)

1. (5-B-01) `_실습/새봄상사.pkt`를 저장하고 닫는다.
2. (5-B-02) `configs/network.pkt`를 연다. → 결과: 내 회사의 토폴로지가 보인다.
3. (5-B-03) 2-1 실습(LEC-SN-09-006-MP)의 구역 A~E를 내 파일에서 따른다. 인터넷 쪽 장비(ISP-R1, NET-PC)와 주소는 그대로 쓴다. 내 회사의 경계 라우터 Se0/0/1이 203.0.113.2다.
4. (5-B-04) NAT-INSIDE에는 내 회사의 본사와 지사 대역을 적는다.
5. (5-B-05) 3-1 실습(LEC-SN-09-007-MP)의 구역 B~C를 따른다. 구역 A의 1:1 정적 NAT와 FTP 시연은 하지 않는다. 포트 포워딩은 내 계획서의 "밖에서 접속하는 서비스"가 쓰는 포트만 연다.
6. (5-B-06) 내 파일의 Sales-PC와 지사 PC에서 NET-PC로 ping을 입력한다. → 결과: Reply가 온다.
7. (5-B-07) NET-PC에서 내 공개 서비스와 열지 않은 포트(예: FTP)를 확인한다. → 결과: 공개 서비스는 열리고 나머지는 닫혀 있다.
8. (5-B-08) NET-PC에서 `tracert 203.0.113.10`을 입력한다. → 결과: 내 회사 안의 주소가 나오지 않는다.

### C. 인터넷 연결 기록과 공개 서비스 목록 (대본 11번)

1. (5-C-01) [lesson-4.md](lesson-4.md) 5절의 양식으로 `03_구축/인터넷_연결.md`를 쓴다. → 결과: 구성, NAT, 시험, 남은 위험 칸이 채워진다.
2. (5-C-02) lesson-4.md 3절의 양식으로 `02_설계/공개_서비스.md`를 만들고, "열지 않기로 한 것"까지 적는다. → 결과: 연 문과 열지 않기로 한 문이 모두 적힌다.
3. (5-C-03) `02_설계/IP_설계표.md`의 "인터넷 ISP 쪽" 줄을 채운다. → 결과: 회선 203.0.113.0/30, 서버용 203.0.113.8/29가 적힌다.

### D. 설정 텍스트 (대본 12번)

1. (5-D-01) 내 경계 라우터(HQ-R1에 해당)에서 `show running-config`를 입력해 결과를 복사한다.
2. (5-D-02) `configs/`에 HQ-R1 설정 텍스트를 저장한다. → 결과: 인터넷 회선, 기본 경로, null 경로, NAT가 들어 있다.
3. (5-D-03) ISP-R1도 같은 방법으로 `configs/`에 저장한다. → 결과: ISP-R1은 새로 생기는 파일이다.
4. (5-D-04) 두 파일에 실제 비밀번호나 키가 있으면 `<password>`로 바꾼다.

## 7. 복구

1. (7-01) 내 파일의 NAT가 꼬이면 2-1 실습 7절의 순서로 지운다: `ip nat inside source` 줄, 포트의 `ip nat inside`/`outside`, ACL 순이다.
2. (7-02) 포트 포워딩이 의도와 다르면 3-1 실습 8절을 따른다.
3. (7-03) 인터넷 연결 전체를 끊으려면 내 경계 라우터의 Se0/0/1을 `shutdown`한다. 회사 안 통신은 그대로다.
4. (7-04) 파일이 섞였으면 저장하지 않고 닫은 뒤, 마지막으로 커밋한 `configs/network.pkt`를 `git checkout -- configs/network.pkt`로 되돌린다.

## 8. 더 해 볼 것

확인 상태: 미검증. 시간이 남으면 한다. 모두 내 패킷트레이서 안에서만 한다.

1. (8-01) 동적 NAT를 해 본다. 203.0.113.11~.12 두 개만 풀로 주고(`ip nat pool`), PC 세 대로 동시에 나가 보아 세 번째가 막히는 것을 확인한 뒤 PAT로 되돌린다.
2. (8-02) NET-PC에서 `telnet 203.0.113.2`를 입력해 본다. HQ-R1의 텔넷 창이 인터넷에서 열리는지 확인하고, 결과를 인터넷 연결 기록의 남은 위험에 적는다. 열리면 관리 접속이 인터넷에 닿는다는 뜻이며, 10일차 ACL과 12일차 사고 02로 이어진다.
3. (8-03) `show ip nat statistics`의 Hits와 Misses가 무엇을 세는지 찾아본다.
