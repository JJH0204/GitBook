## 목적

이 과목은 개인 프로젝트 하나를 두 달 동안 완성하는 과정이다. 1일차에 학생마다 가상의 회사를 정하고, 강사와 함께 프로젝트 계획서를 쓴다. 그 뒤로 매 회차 배운 기술을 그 회사의 네트워크에 적용하고, 결과를 GitHub 저장소에 커밋한다. 16일차에 학생은 설계부터 보안 정책, 침해사고 분석 보고서, 최종 보고서까지 담긴 네트워크 보안 프로젝트를 포트폴리오로 가져간다.

기술을 배우는 순서는 그대로다. 먼저 스위칭과 라우팅으로 길을 만들고, 그다음 ACL, NAT, VPN, 방화벽, 모니터링으로 그 길을 통제하고 지킨다. 프로젝트는 이 순서를 담는 그릇이다.

## 2. 프로젝트: 우리 회사 네트워크를 설계하고 지킨다

### 진행 방식

강사도 같은 흐름의 레퍼런스 프로젝트를 진행한다. 가상 회사의 이름은 새봄상사다. 매 회차 강사가 새봄상사에 먼저 적용해 보이고, 학생은 자기 회사로 따라 만든다.

2일차부터 매 회차는 같은 세 구간으로 흘러간다. 첫 30분에 그날의 작업 계획서를 쓰고, 150분 동안 이론을 배우며 새봄상사로 함께 실습하고, 마지막 60분은 같은 일을 내 회사에 적용하는 개인 실습이다. 개인 실습 동안 강사는 한 사람씩 1:1로 봐 주고, 학생은 작업 계획서에 결과를 적어 커밋한다.

회사의 뼈대는 모두 같게 둔다. 본사 하나와 지사 하나, 부서 셋 이상, 인터넷 연결과 밖에서 접속하는 서비스 하나, 재택 근무자다. 회사 이름, 업종, 부서, 주소 대역, 보안 요구사항은 학생마다 다르다. 강사는 같은 구조를 보며 지도하고, 결과물은 학생마다 다르게 나온다.

### 1일차에 함께 쓰는 프로젝트 계획서

| 칸 | 담는 것 |
|---|---|
| 회사 소개 | 이름, 업종, 본사와 지사의 위치, 직원 수, 밖에서 접속하는 서비스 |
| 부서와 사용자 | 부서별 인원과 쓰는 서비스 |
| 연결 요구사항 | 부서 사이, 본사와 지사 사이, 인터넷, 밖에서 들어오는 접속, 재택 근무 |
| 지킬 것과 걱정되는 것 | 지킬 자산, 깨지면 안 되는 요소, 무엇이 잘못될 수 있는가 |
| 일정 | 이 문서의 주차표를 자기 회사 기준으로 옮긴 16일 계획 |
| 완료 기준 | 16일차에 낼 산출물 목록 |

보안 요구사항은 1일차에는 거칠어도 된다. 10일차 ACL과 13, 14일차 방화벽에서 다시 꺼내 구체적인 정책으로 바꾼다. 계획서가 다듬어지는 과정 자체가 커밋 기록으로 남는다.

### 포트폴리오 저장소 (16일차 완성 모습)

폴더는 처음부터 다 만들지 않고, 그 폴더가 필요한 날에 만든다. 커밋 기록에 저장소가 자라는 모습이 그대로 남는다.

```
my-netsec-project/
├── README.md          프로젝트 개요와 진행 현황 (1일차부터 계속 갱신)
├── 00_작업계획/        회차별 작업 계획서와 결과 (2일차부터, 02일차.md ~ 16일차.md)
├── 01_요구사항/        회사 시나리오, 프로젝트 계획서 (1일차)
├── 02_설계/            IP와 서브넷 설계표, 구성도 (2, 3일차부터)
├── 03_구축/            VLAN, 라우팅, DHCP, NAT 구성과 확인 결과 (3~9일차)
├── 04_보안정책/        ACL, VPN, 방화벽 정책과 근거 (10, 11, 13, 14일차)
├── 05_진단과_대응/     침해사고 분석 보고서 사고_01~04 와 증거/ (10, 12, 14, 15일차)
├── 06_운영/            모니터링 구성 (15일차)
├── 07_보고서/          최종 보고서, 트러블슈팅 기록 (16일차, 기록은 누적)
├── _실습/              함께 하는 실습의 새봄상사 파일 (2일차부터, 연습용)
└── configs/            내 회사 장비별 설정 텍스트와 .pkt 파일 (2일차부터)
```

장비 설정은 텍스트로도 커밋한다. `.pkt` 파일은 바이너리라 무엇이 바뀌었는지 보이지 않는다. `show running-config` 결과를 텍스트로 남기면 회차마다 바뀐 설정이 `git diff`로 보인다.

공개 저장소에는 비밀값을 올리지 않는다. 실습 장비에도 평소 쓰는 비밀번호는 넣지 않는다. 이것이 1일차의 첫 보안 수업이다.

### 두 번째 달: 침해사고 분석 보고서

9~16일차에는 작업 계획서와 함께 [침해사고 분석 보고서](incident-report.md)(LEC-SN-00-005-DO)를 쓴다. 첫 달에 "남은 위험"으로 적어 둔 틈이 실제 사고로 일어났을 때, 무엇으로 알았고 어떻게 막았는지를 남기는 문서다. 보안 관제와 침해사고 대응 직무가 매일 쓰는 문서와 같은 모양이다.

| 사고 | 일차 | 무슨 일 | 처음 생긴 틈 |
|---|---|---|---|
| 01 | 10 | 인수한 회사에서 인사팀으로 들어온 접근 | 7일차, 경로 필터만 둔 신뢰 경계 |
| 02 | 12 | 텔넷으로 오간 관리자 비밀번호 | 2일차, 비밀번호만 건 텔넷 VTY |
| 03 | 14 | 공개한 서비스로 들어온 포트 스캔과 로그인 시도 | 9일차, 밖으로 공개한 서비스 |
| 04 | 15 | IDS 경보 두 건의 정탐과 오탐 판정 | 15일차, 처음 켠 IDS |

조치는 설정을 바꾼 커밋 해시로 남긴다. 16일차에 네 건을 최종 보고서의 한 장으로 묶는다.

## 3. 운영 방식

- 2개월, 주말, 16일, 하루 4시간이다.
- 1일차 첫 교시는 오리엔테이션이다(과정 안내, 정보보안의 큰 그림, 실습의 법과 약속). 강사의 새봄상사 계획서를 공유하고, 마지막 한 시간에 각자 프로젝트 계획서를 쓴다.
- 2일차부터 하루는 세 구간이다.

| 시간 | 구간 | 하는 일 |
|---|---|---|
| 14:00~14:30 | 작업 계획서 | 지난 회차 확인, 오늘의 작업 계획서(목표, 작업 대상, 작업 내용, 확인 방법, 되돌리는 방법) |
| 14:30~17:00 | 함께 하는 이론과 실습 | 쉬는 시간 10분 두 번을 포함한다. 실제 수업은 130분이다 |
| 17:00~18:00 | 개인 실습과 1:1 멘토링 | 내 회사에 적용, 작업 계획서의 결과 칸, 커밋 |

## 6. 실습 환경과 사전 확인

- 1일차 전에 학생에게 GitHub 계정을 미리 만들어 오라고 공지한다. 이메일 인증에 시간이 걸린다.
- 교실 PC에 Git for Windows, VS Code, Cisco 패킷트레이서 설치를 미리 요청한다. 패킷트레이서 로그인에는 Cisco Networking Academy 계정이 필요하다.
- 12일차부터는 GNS3와 GNS3 VM, VirtualBox를 쓴다. ASAv와 PFSense는 GNS3 VM 위에서 돌아 메모리를 많이 쓰므로 교실 PC 사양을 미리 확인한다.

## 7. 수업 전 확인할 것

확인하지 않은 항목이 세 가지 남아 있다.

- ASAv 이미지는 Cisco 라이선스 대상이다. 학생에게 배포하기 어려우면 ASAv는 강사 시연으로 하고, 학생 실습은 무료 오픈소스인 PFSense로 한다.
- 패킷트레이서도 ZFW, IPSec, ASA 기본 실습을 지원하는 것으로 알려져 있다. 리허설로 확인되면 GNS3에 기대는 부분을 줄인다. 아직 확인하지 않았다.
- 사고 04의 IDS를 무엇으로 돌릴지(리눅스 VM의 Snort나 Suricata)와, 패킷트레이서가 ACL `log`의 로그를 띄우는지(사고 01의 탐지 수단) 아직 확인하지 않았다.

16일, 토요일과 일요일, 하루 4시간은 가정값이므로 실제 학사일정에 맞춰 조정한다.
