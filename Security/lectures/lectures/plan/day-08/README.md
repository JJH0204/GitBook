# 8일차 DHCP와 게이트웨이 이중화

> 상위: [네트워크 보안 강의계획서](../) 이전: [7일차 EIGRP와 재분배](../day-07/) 다음: [9일차 NAT와 서비스 공개](../day-09/)

지금까지 PC마다 주소를 손으로 넣었고, 본사의 모든 VLAN은 HQ-R1 한 대를 게이트웨이로 삼았습니다. 오늘은 주소를 자동으로 나눠 주고(DHCP), 지사 PC도 본사에서 주소를 받게 하고(릴레이), 게이트웨이를 두 대로 늘립니다(L3 스위치와 HSRP).

자동으로 나눠 주는 쪽과 자동으로 이어받는 쪽은 둘 다 "누구의 말을 믿을 것인가"라는 약점을 갖습니다. 그래서 가짜 DHCP 서버를 막는 스누핑과 HSRP 인증으로 하루를 닫습니다.

## 학습 목표

* DHCP의 네 단계와 풀, 제외 주소를 알고 부서별 풀을 만듭니다
* 릴레이로 다른 네트워크의 PC에게 주소를 나눠 줍니다
* L3 스위치에 SVI와 `ip routing` 을 넣어 VLAN 사이를 라우팅합니다
* HSRP로 게이트웨이를 이중화하고 장애 시험으로 확인합니다
* DHCP 스누핑과 HSRP 인증으로 오늘 만든 두 자동 장치를 지킵니다

### 새봄상사 8일차 작업 계획서

#### 1. 목표

* 직원 PC의 주소를 DHCP로 나눠 주고, 지사 PC도 본사에서 받게 한다
* 본사 게이트웨이를 두 대로 늘려, 한 대가 멈춰도 영업팀에서 주문 관리 서버로 가는 통신이 이어지게 한다
* 가짜 DHCP 서버와 게이트웨이 가로채기를 막는다

#### 2. 작업 대상

| 대상                   | 무엇을                                             |
| -------------------- | ----------------------------------------------- |
| HQ-R1                | DHCP 풀 네 개, 서브인터페이스 주소 이동, HSRP, HSRP 인증        |
| BR-R1                | Gi0/0에 릴레이                                      |
| HQ-DSW1 (새로)         | 3560. VLAN, 트렁크, SVI, `ip routing`, HSRP, 기본 경로 |
| HQ-SW1               | Fa0/23을 트렁크로 열기, DHCP 스누핑                       |
| HQ-SW2, BR-SW1       | DHCP 스누핑                                        |
| 직원 PC 7대             | 고정 주소에서 DHCP로                                   |
| `02_설계/`             | IP 설계표, 구성도                                     |
| `03_구축/주소할당과_이중화.md` | 풀, 이중화, 장애 시험, 보안, 남은 위험                        |

#### 3. 작업 내용

1. HQ-R1에 제외 주소와 풀을 만들고 PC를 DHCP로 바꾼다
2. BR-R1에 릴레이를 넣고 지사 PC를 DHCP로 바꾼다
3. HQ-DSW1을 HQ-SW1 Fa0/23에 트렁크로 붙이고 SVI와 `ip routing` 을 넣는다
4. HQ-R1의 실제 주소를 옮기고 HSRP를 건다. 이때 몇 초 끊기므로 직원이 적은 시간에 한다
5. 장애 시험을 하고 끊긴 횟수를 적는다
6. DHCP 스누핑과 HSRP 인증을 건다

#### 4. 확인 방법

| 확인할 것            | 방법                                 | 기대하는 결과                       |
| ---------------- | ---------------------------------- | ----------------------------- |
| 본사 PC가 주소를 받는다   | HQ-R1 `show ip dhcp binding`       | 본사 PC 다섯 대                    |
| 지사 PC가 주소를 받는다   | 같은 명령                              | 192.168.20.10, .11            |
| HQ-DSW1이 Active다 | HQ-DSW1 `show standby brief`       | 네 그룹 Active, Standby는 HQ-R1   |
| 게이트웨이가 넘어간다      | `ping -t` 중 HQ-DSW1 Gi0/1 shutdown | 몇 번 끊긴 뒤 Reply, HQ-R1이 Active |
| 가짜 DHCP 서버가 막힌다  | 시연 뒤 영업팀 PC 다시 받기                  | 게이트웨이가 192.168.10.1           |
| 인증이 맞다           | 인증 뒤 `show standby brief`          | Active와 Standby가 하나씩          |

#### 5. 되돌리는 방법

* 이중화가 꼬이면 HQ-R1 서브인터페이스의 `standby` 줄을 지우고 주소를 원래 게이트웨이(.1, .33, .65, .97)로 되돌린 뒤, HQ-DSW1의 Gi0/1을 `shutdown` 한다. 3일차 모습으로 돌아간다
* 스누핑을 켠 뒤 주소를 못 받으면 `no ip dhcp snooping` 으로 끄고 믿는 포트부터 다시 본다
* DHCP가 꼬이면 PC를 고정 주소로 되돌린다. 본사 주소표는 3일차 대본 7번, 지사는 4일차 대본에 있다

#### 6. 결과 (개인 실습이 끝날 때 채운다)

* 한 일:
* 확인 결과:
* 막힌 곳과 어떻게 풀었나:

## 수업 전에 확인할 것

* 패킷트레이서 2911의 서브인터페이스에서 `standby` 가 되는지, 3560 SVI의 HSRP와 preempt가 되는지
* `standby ... authentication md5 key-string` 이 되는지. 안 되면 평문 인증(`standby 10 authentication <키>`)으로 대본을 바꾼다
* `ip helper-address` 가 루프백(192.168.255.1)으로 보내도 지사 PC가 주소를 받는지
* 2960에서 `ip dhcp snooping` 이 되는지, `no ip dhcp snooping information option` 없이 PC가 주소를 받는지 못 받는지
* 가짜 DHCP 서버(Server-PT)가 진짜보다 먼저 답하는지, 스누핑 뒤 버려지는지
* PC의 `arp -a` 에 가상 MAC(0000.0c07.ac0a)이 보이는지, `tracert` 첫 줄이 HQ-DSW1의 실제 주소인지
* 장애 시험에서 끊기는 횟수와 HQ-DSW1이 Active를 되찾기까지 걸리는 시간
* 강사 레퍼런스 저장소에 새봄상사의 8일차 작업 계획서, 기록, 설정 여섯 개가 미리 커밋되어 있는지
