# 4. DHCP와 HSRP를 지키기

> 대본: [실습 명령어 모음](commands.md) 8~10번

## 학습 목표

- 가짜 DHCP 서버가 무엇을 할 수 있는지 설명합니다
- DHCP 스누핑으로 믿는 포트와 믿지 않는 포트를 나눕니다
- HSRP를 가로채는 원리를 알고, HSRP 인증을 겁니다
- 오늘 바꾼 것과 남은 위험을 기록합니다

## 다리 놓기

오늘 배운 두 프로토콜에는 같은 약점이 있습니다. DHCP를 쓰는 PC는 먼저 답한 서버를 믿습니다. HSRP 장비들은 우선순위가 높다고 말하는 장비에게 Active를 넘깁니다. 둘 다 같은 VLAN 안의 누구든 말을 걸 수 있습니다.

> 5일차 RIP은 누가 알려 준 경로든 믿었고, 가짜 장비 하나가 서버로 가는 길을 빼앗았습니다.

오늘도 같은 질문을 합니다. 누구의 말을 믿을 것인가.

## 1. 가짜 DHCP 서버

같은 VLAN에 DHCP 서버가 하나 더 있으면, PC는 먼저 답한 쪽의 설정을 받습니다.

| 가짜가 알려 주는 것 | 생기는 일 | 깨지는 것 |
|---------------------|-----------|-----------|
| 게이트웨이를 가짜 자신으로 | 밖으로 가는 모든 통신이 가짜를 거친다 | 기밀성, 무결성 |
| DNS를 가짜 서버로 | 주소창에 쇼핑몰 이름을 쳐도 가짜 사이트로 간다 | 기밀성 |
| 엉뚱한 대역의 주소 | PC가 아무 데도 닿지 못한다 | 가용성 |

가장 흔한 범인은 공격자가 아닙니다. 직원이 집에서 쓰던 공유기를 자리에 꽂으면, 공유기의 DHCP가 켜진 채로 옆자리 PC들에게 192.168.0.x 주소를 나눠 줍니다. 아침에 출근한 영업팀 절반이 인터넷이 안 된다고 하는 사고가 이렇게 생깁니다.

## 2. 시연: 영업팀 자리의 가짜 서버

강사가 HQ-SW1의 Fa0/3(영업팀 자리)에 서버 한 대를 꽂고 DHCP 서비스를 켭니다. 가짜는 게이트웨이를 자기 주소로 알려 줍니다.

| 칸 | 가짜 서버의 값 |
|----|----------------|
| 서버 자신의 주소 | 192.168.10.25 |
| Default Gateway | 192.168.10.25 |
| Start IP Address | 192.168.10.21 |

영업팀 PC에서 IP Configuration을 Static으로 바꿨다가 다시 DHCP로 바꿉니다. 게이트웨이 칸에 192.168.10.25가 보이면 가짜에게 받은 것입니다. 이 PC가 지사로 보내는 패킷은 이제 가짜 서버로 갑니다.

## 3. DHCP 스누핑

스위치가 포트를 두 가지로 나눕니다.

| 포트 | DHCP 서버의 답(Offer, Ack) | 새봄상사 |
|------|----------------------------|----------|
| 믿는 포트 (trust) | 통과 | 진짜 서버의 답이 들어오는 쪽 |
| 믿지 않는 포트 (기본) | 버린다 | PC 자리 전부, HQ-DSW1 쪽 |

PC의 요청(Discover, Request)은 어느 포트에서든 통과합니다. 버리는 것은 서버만 보내는 답입니다. 그래서 PC 자리에 서버를 꽂아도 그 서버의 답은 스위치에서 사라집니다. 1일차의 기본 거부와 같습니다. 모든 포트를 믿지 않는 것에서 시작해 진짜 서버 쪽만 엽니다.

| 스위치 | 믿는 포트 | 이유 |
|--------|-----------|------|
| HQ-SW1 | Gi0/1 | HQ-R1(DHCP 서버) 쪽 |
| HQ-SW2 | Gi0/1 | HQ-SW1을 거쳐 서버의 답이 들어오는 쪽 |
| BR-SW1 | Gi0/1 | BR-R1(릴레이)이 본사의 답을 전해 주는 쪽 |

HQ-SW1입니다.

```
ip dhcp snooping
ip dhcp snooping vlan 10,20,30,40
no ip dhcp snooping information option
interface gi0/1
 ip dhcp snooping trust
```

세 번째 줄은 짝을 맞추는 줄입니다. 스누핑을 켠 스위치는 PC의 요청에 "몇 번 포트에서 왔다"는 꼬리표(옵션 82)를 붙입니다. 시스코 라우터의 DHCP 서버는 릴레이를 거치지 않았는데 꼬리표가 붙은 요청을 이상하다고 보고 버립니다. 그래서 스위치가 꼬리표를 붙이지 않게 합니다. 이 줄을 빼면 스누핑을 켜는 순간 진짜 서버에서도 주소를 받지 못합니다.

스누핑을 켜고 영업팀 PC가 다시 주소를 받으면 게이트웨이는 192.168.10.1로 돌아옵니다.

```
HQ-SW1#show ip dhcp snooping
Switch DHCP snooping is enabled
DHCP snooping is configured on following VLANs:
10,20,30,40
...
Interface                  Trusted    Allow option    Rate limit (pps)
-----------------------    -------    ------------    ----------------
GigabitEthernet0/1         yes        yes             unlimited
```

스누핑은 덤으로 표 하나를 만듭니다. 어느 포트의 어느 MAC 주소가 어느 주소를 받았는지입니다(`show ip dhcp snooping binding`). 12일차에 같은 네트워크 안에서 주소를 속이는 공격을 막을 때 스위치가 이 표를 기준으로 씁니다.

## 4. 주소를 바닥내는 공격

공격자가 MAC 주소를 바꿔 가며 Discover를 수천 번 외치면, 풀의 주소가 모두 빌려 나가고 진짜 직원의 PC는 169.254를 붙입니다. 주소 고갈 공격이라고 합니다.

| 막는 방법 | 언제 |
|-----------|------|
| 믿지 않는 포트의 DHCP 요청 수를 제한한다: `ip dhcp snooping limit rate` | 더 해 볼 것 |
| 포트 하나에 붙을 수 있는 MAC 주소의 수를 제한한다: 포트 보안 | 12일차 |

## 5. HSRP 가로채기와 인증

HSRP 장비들은 3초마다 "나는 그룹 10, 우선순위 110"이라고 알립니다. 영업팀 자리에 장비를 꽂고 "나는 그룹 10, 우선순위 255, preempt"라고 알리면, 그 장비가 Active가 됩니다. 영업팀 PC들이 게이트웨이로 보내는 패킷이 모두 그 장비로 갑니다. 가짜 DHCP와 같은 결과를 DHCP 없이 얻는 셈입니다.

인증을 걸면 진짜 두 장비는 키를 모르는 장비의 알림을 무시합니다.

```
interface vlan 10
 standby 10 authentication md5 key-string <실습용 키>
```

HQ-R1의 Gi0/0.10에도 같은 줄을 넣고, 그룹 20, 30, 40도 같게 합니다. 5일차부터 같은 원리입니다.

인증에는 두 가지를 덧붙여 알아 둡니다.

| 알아 둘 것 | 내용 |
|------------|------|
| 한쪽에만 걸면 | 두 장비가 서로의 알림을 무시하고 둘 다 Active가 된다. 가상 주소가 둘로 갈라진다 |
| 인증이 막는 것 | 진짜 장비가 가짜에게 Active를 내주는 것. 가짜가 가상 주소의 주인 행세를 하며 PC를 속이는 것은 따로 막아야 하고, 12일차에 본다 |

그래서 두 장비에 같은 순간에 걸고, 걸자마자 `show standby brief` 로 Active가 하나인지 봅니다.

## 6. 스위치 보안 점검표에 더하기

3일차에 만든 점검표에 오늘의 줄을 더합니다.

|-------|------|---------|------------|
| DHCP 스누핑 | `ip dhcp snooping`, 서버 쪽만 `trust` | 가짜 DHCP 서버, 잘못 꽂은 공유기 | 기본 거부 |
| HSRP 인증 | `standby 10 authentication md5` | 게이트웨이 가로채기 | 인증 |

### 물어볼 것

- "PC는 어느 DHCP 서버가 진짜인지 알 수 있을까요?" 모릅니다. 먼저 답한 쪽을 받습니다.
- "스누핑은 PC의 요청도 막을까요?" 아닙니다. 믿지 않는 포트에서 들어오는 서버의 답만 버립니다.
- "HQ-DSW1 쪽 포트(Fa0/23)는 믿어야 할까요?" 아닙니다. HQ-DSW1은 DHCP 서버가 아닙니다. 믿는 포트는 적을수록 좋습니다.
- 두 번째 함께 생각해 보기의 답: HQ-R1의 `show ip dhcp binding` 에 우리가 준 주소가 없는 PC, 그리고 스누핑을 켰다면 스위치 로그에 버려진 답이 들어온 포트가 남습니다. 15일차 모니터링에서 이런 기록을 모아 봅니다.

### 자주 헷갈리는 것

| 헷갈리는 것 | 바로잡기 |
|-------------|----------|
| 믿는 포트에 PC 자리를 넣는다 | 믿는 포트는 진짜 서버의 답이 들어오는 쪽뿐이다 |
| 스누핑을 켜면 바로 동작한다 | `ip dhcp snooping vlan` 으로 VLAN을 정해야 한다 |
| 스누핑을 켜자 모두 주소를 못 받는다 | `no ip dhcp snooping information option` 을 빠뜨렸다 |
| HSRP 인증은 가짜의 모든 행동을 막는다 | 진짜 장비가 자리를 내주지 않게 할 뿐이다 |

### 진행 요령

- 가짜 서버 시연에서 진짜 서버가 먼저 답하면 PC의 DHCP를 몇 번 다시 받습니다. 누가 먼저 답하느냐의 경주라는 것 자체가 설명이 됩니다.
- 시연이 끝나면 강사는 가짜 서버를 지우거나 DHCP 서비스를 끕니다. 학생 파일에는 가짜 서버를 두지 않습니다.
- HSRP 가로채기는 시연하지 않고 말로 설명합니다. 시간이 남으면 강사가 영업팀 자리에 라우터를 꽂아 우선순위 255로 Active를 빼앗는 것을 보여 주고, 인증을 건 뒤 다시 봅니다.
- 1일차와 12일차의 고지처럼, 가짜 서버와 가짜 게이트웨이는 각자의 실습 파일 안에서만 다룹니다.
