# 3. RIP을 지키기

> 상위: [5일차 동적 라우팅 RIP](README.md)
> 대본: [실습 명령어 모음](commands.md) 6~8번
> 드로잉: 3. RIP을 지키기 드로잉 (9장)

## 학습 목표

- 거짓 경로 광고가 통신을 어떻게 가로채는지 설명합니다
- passive-interface가 막는 것과 막지 못하는 것을 구분합니다
- RIP 인증을 걸어 확인된 이웃의 말만 믿게 합니다
- 인증 키도 설정 파일에 남는다는 것을 알고, 공개 저장소에서 어떻게 다룰지 정합니다

## 다리 놓기

1번 노트에서 RIP은 이웃의 말을 믿는 구조라고 했고, 2번 노트에서 새 네트워크가 저절로 회사 전체에 퍼지는 것을 보았습니다. 편리한 이 두 성질을 뒤집어 보면 위험이 됩니다. 누군가 거짓 소문을 내면, 라우터들은 확인 없이 믿고 회사 전체에 퍼뜨립니다.

## 1. 거짓 경로 하나로 통신을 가로챈다

본사 라우터의 영업팀 서브인터페이스(gi0/0.10)에도 RIP이 켜져 있습니다. `network 192.168.10.0` 한 줄이 본사의 서브인터페이스를 모두 골랐기 때문입니다. 그래서 영업팀 자리에 RIP을 말하는 장비를 꽂으면, 본사 라우터는 그 장비를 이웃으로 믿습니다.

그 장비가 이렇게 알린다고 해 봅니다.

```
가짜 장비 : "192.168.10.96/28 은 나에게 붙어 있다. 1칸"
```

192.168.10.96/28은 서버 VLAN(192.168.10.96/27)의 앞쪽 절반입니다. 본사 라우터의 경로표에는 이제 두 줄이 생깁니다.

| 줄 | 프리픽스 | 서버(192.168.10.98)로 가는 패킷 |
|----|----------|--------------------------------|
| `C 192.168.10.96/27` 서버 VLAN | /27 | 맞는다 |
| `R 192.168.10.96/28 via 가짜 장비` | /28 | 맞는다. 더 구체적이라 이 줄을 쓴다 |

4일차에 배운 "가장 구체적인 줄이 이긴다" 규칙 때문에, 다른 VLAN에서 서버로 가는 통신이 가짜 장비로 갑니다. 가짜 장비는 받은 것을 엿보고 서버로 넘겨 줄 수도 있고(기밀성), 바꿔 넘길 수도 있고(무결성), 버릴 수도 있습니다(가용성). 경로표 한 줄로 1일차의 CIA가 모두 깨집니다.

오늘 강사가 패킷트레이서 안에서 이 장면을 보여 줍니다. 영업팀 자리에 라우터를 하나 꽂고 RIP으로 위의 경로를 알리게 합니다.

> 12일차에는 같은 네트워크 안에서 주소를 속여 통신을 가로채는 다른 공격들을 봅니다. 원리는 같습니다. 확인하지 않고 믿는 곳이 틈이 됩니다.

## 2. 말하지 않기: passive-interface

먼저 본사 라우터가 영업팀이나 인사팀 쪽으로 RIP 알림을 보내지 않게 합니다. 그쪽에는 이웃 라우터가 없으니 알릴 이유가 없습니다.

```
router rip
 passive-interface gi0/0.10
 passive-interface gi0/0.20
 passive-interface gi0/0.30
 passive-interface gi0/0.40
 passive-interface gi0/0.99
```

이것만으로도 얻는 것이 있습니다. 전에는 영업팀 PC 누구나 30초마다 회사 전체의 경로표를 받아 볼 수 있었습니다. 이제는 경로표가 사무실로 흘러 나가지 않습니다.

그런데 가짜 장비의 경로는 그대로 남아 있습니다. RIP의 passive-interface는 "말하지 않기"일 뿐 "듣지 않기"가 아니기 때문입니다. passive로 둔 포트에서도 들어온 알림은 받아들입니다.

| | passive-interface 전 | passive-interface 뒤 |
|-|----------------------|----------------------|
| 본사 라우터가 영업팀 쪽으로 알림을 보내나 | 보낸다 | 보내지 않는다 |
| 영업팀 쪽에서 온 알림을 받아들이나 | 받는다 | 여전히 받는다 |

> 6일차 OSPF와 7일차 EIGRP는 passive로 두면 그 포트에서 이웃 맺기 자체를 하지 않아 듣지도 않게 됩니다. RIP만 이렇게 다릅니다.

## 3. 확인하고 믿기: 인증

인증은 미리 나눠 가진 키를 아는 장비의 알림만 받아들이게 하는 설정입니다. 키를 모르는 장비의 알림은 버립니다.

```
key chain RIPKEY
 key 1
  key-string <실습용 키>
interface gi0/1
 ip rip authentication mode md5
 ip rip authentication key-chain RIPKEY
```

| 명령 | 하는 일 |
|------|---------|
| `key chain RIPKEY` | 키를 모아 두는 열쇠고리를 만든다 |
| `key 1`, `key-string` | 1번 키와 그 값 |
| `ip rip authentication mode md5` | 키 값을 그대로 보내지 않고, 알림과 키로 만든 해시를 붙여 보낸다 |
| `ip rip authentication key-chain RIPKEY` | 이 포트는 이 열쇠고리의 키를 쓴다 |

인증은 RIP이 켜진 포트에 모두 겁니다. 이웃 라우터와 이어진 주 회선(gi0/1)은 지사 라우터에도 같은 키를 걸어야 경로가 다시 오갑니다. 그리고 영업팀, 인사팀 쪽 서브인터페이스에도 걸어야 합니다. 그래야 그쪽에서 들어오는 키 없는 알림을 버립니다.

인증을 건 뒤 가짜 장비의 경로는 길어야 몇 분 안에 경로표에서 사라집니다. `clear ip route *` 를 치면 바로 사라집니다.

md5 모드에서 키 값 자체는 회선에 실리지 않습니다. 2일차에 본 enable secret처럼, 받는 쪽이 같은 방식으로 해시를 만들어 비교합니다. 다만 MD5는 오래된 방식이라 현장에서는 더 강한 방식(SHA)을 쓰는 프로토콜을 고릅니다. RIP은 MD5까지만 지원합니다.

## 4. 키도 설정 파일에 남는다

`show running-config` 를 보면 key-string이 7번 문자열로 들어 있습니다. 2일차에 본 대로 7번 문자열은 쉽게 되돌아갑니다. 오늘 저녁 `configs/HQ-R1.txt` 를 커밋하면 이 키가 공개 저장소에 올라갑니다.

수업의 실습용 키라 괜찮지만, 실제 회사라면 라우팅 키가 새는 순간 누구나 진짜 이웃 행세를 할 수 있습니다. 이 과목의 규칙은 이렇습니다.

| 상황 | 하는 일 |
|------|---------|
| 수업 실습 | 실습용 키를 쓰고, 설정 텍스트를 그대로 커밋한다 |
| 실제 회사 | 설정 파일은 공개 저장소에 올리지 않는다. 키는 장비마다, 정기적으로 바꾼다 |
| 포트폴리오에 쓸 때 | 보고서에 "실습용 키이며 실제 환경에서는 공개하지 않음"이라고 적어 둔다 |

## 5. 정리

| 위협 | 막는 설정 | 막는 범위 |
|------|-----------|-----------|
| 사무실에서 회사 경로표를 엿보기 | passive-interface | 알림을 보내지 않는다 |
| 사무실에서 거짓 경로 흘려 넣기 | 인증 | 키 없는 알림을 버린다 |
| 이웃 라우터를 사칭하기 | 인증 | 키를 아는 장비만 이웃 |
| 키가 새기 | 설정 파일을 비밀 문서로 | 2일차의 원칙 그대로 |

### 물어볼 것

- "본사 라우터에 192.168.10.96/27(C)과 192.168.10.96/28(R)이 함께 있으면, 서버로 가는 패킷은 어느 줄을 탈까요?" /28입니다. 4일차의 규칙이 공격에 쓰이는 순간입니다.
- "passive-interface를 걸었는데 왜 가짜 경로가 남아 있을까요?" RIP의 passive는 듣기는 계속하기 때문입니다.
- 두 번째 함께 생각해 보기의 답: 라우터 한 대의 설정 파일이 새면 회사 전체의 키가 샙니다. 구간마다 다른 키를 쓰면 피해가 그 구간에 머뭅니다. 1일차의 심층 방어입니다.

### 자주 헷갈리는 것

| 헷갈리는 것 | 바로잡기 |
|-------------|----------|
| passive-interface면 그 포트의 RIP이 꺼진다 | RIP의 passive는 보내기만 멈춘다. 받기는 계속한다 |
| 인증을 주 회선 한쪽에만 걸었다 | 양쪽 키가 맞아야 경로가 오간다. 한쪽만 걸면 서로의 알림을 버려 R 줄이 사라진다 |
| key-string 끝에 띄어쓰기가 들어갔다 | 띄어쓰기도 키의 일부다. 양쪽이 글자 하나까지 같아야 한다 |
| md5면 키가 암호화되어 회선에 실린다 | 키는 실리지 않는다. 알림과 키로 만든 해시만 실린다 |

### 진행 요령

- 가짜 장비 시연은 강사의 패킷트레이서 안에서만 합니다. 학생에게는 원리와 막는 법을 실습하게 하고, 공격 장비를 직접 만들게 하지 않습니다. 1일차 실습의 약속을 다시 짚습니다.
- 시연용 가짜 장비 설정은 대본 6번에 있습니다. 시연이 끝나면 지웁니다.
- 인증을 걸면 지사와의 경로가 잠시 사라집니다. 양쪽에 다 걸 때까지 기다리게 하고, 그 사이 끊기는 것도 "작업 중 장애"로 기록하게 합니다. 현장에서 인증을 바꿀 때 통신이 끊기는 시간을 계획서에 미리 적는 이유입니다.
- 패킷트레이서가 RIP 인증 명령을 받아들이는지 수업 전에 확인합니다. 받지 않으면 3번 절은 개념과 설정 줄만 보여 주고, passive-interface까지 실습합니다.
