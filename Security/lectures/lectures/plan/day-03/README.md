# 3일차 스위칭과 VLAN

> 상위: [네트워크 보안 강의계획서](../) 이전: [2일차 주소 설계와 장비 접근 보안](../day-02/) 다음: [4일차 정적 라우팅과 지사 연결](../day-04/)

2일차에 부서마다 주소를 나눴지만, 그 경계는 PC가 지켜 주는 약속이었습니다. 인사팀 PC가 주소를 바꾸면 바로 영업팀 네트워크에 들어갑니다. 오늘은 경계를 스위치가 지키게 만들고(VLAN), 경계를 넘는 통신은 반드시 라우터 한 곳을 지나게 합니다.

오늘이 끝나면 새봄상사에는 2층 스위치가 생기고, 부서마다 VLAN이 있고, 쓰지 않는 포트는 닫혀 있습니다. 저장소에는 구성도 첫 판과 장비 세 대의 설정이 더해집니다.

## 오늘 답할 질문

| 질문                       | 오늘의 답                                       | 노트 |
| ------------------------ | ------------------------------------------- | -- |
| 주소만 나누면 충분한가?            | 아니다. PC가 주소를 바꾸면 넘어간다. 스위치가 VLAN으로 막는다      | 1  |
| 스위치 두 대에 걸친 부서는?         | 트렁크가 VLAN 태그를 붙여 선 하나로 나른다                  | 2  |
| 나눈 VLAN끼리는 어떻게 통신하나?     | 라우터의 서브인터페이스를 지난다. 그래서 거기서 고를 수 있다          | 3  |
| 스위치 여러 대의 VLAN은 어떻게 맞추나? | VTP가 맞춰 주지만, 새봄상사는 사고를 막으려고 transparent로 둔다 | 4  |

## 학습 목표

* 주소만 나눈 경계와 VLAN으로 나눈 경계의 차이를 설명합니다
* VLAN을 만들고 포트를 넣고, 쓰지 않는 포트를 닫습니다
* 트렁크를 설정하고, 트렁크가 저절로 생기지 않게 막습니다
* 라우터 서브인터페이스로 VLAN 사이를 잇고, 스위치에 관리 주소를 줍니다
* 오늘의 스위치 보안 설정을 점검표로 정리해 커밋합니다

### 새봄상사 3일차 작업 계획서

#### 1. 목표

* 프로젝트 계획서 3번 칸의 "부서마다 네트워크를 나눈다"를 스위치가 지키게 한다
* 2일차 다른 대역 실험에서 라우터가 몰랐던 길을 열어, 부서 사이 통신이 라우터를 지나게 한다

#### 2. 작업 대상

| 대상          | 무엇을                                      |
| ----------- | ---------------------------------------- |
| HQ-SW2 (새로) | 2층 스위치. 기본 잠금, VLAN, 트렁크, 관리 주소          |
| HQ-SW1      | VLAN, 포트 배정, 쓰지 않는 포트 닫기, 트렁크 두 곳, 관리 주소 |
| HQ-R1       | Gi0/0의 주소를 서브인터페이스 다섯 개로 옮기기             |
| PC 5대       | 인사팀, 개발팀, 서버, 관리자, 2층 영업팀                |
| `02_설계/`    | 설계표에 VLAN 칸, 구성도 첫 판                     |

#### 3. 작업 내용

1. HQ-SW2를 놓고 2일차와 같은 기본 잠금을 건다
2. 두 스위치에 VLAN 10, 20, 30, 40, 99, 900, 999를 만든다
3. 포트를 부서 VLAN에 넣고, 쓰지 않는 포트는 VLAN 999에 넣어 끈다
4. 트렁크 두 곳을 설정한다(필요한 VLAN만, 협상 끄기, 스위치 사이는 native VLAN 900)
5. HQ-R1에 서브인터페이스를 만든다
6. 스위치에 VLAN 99 관리 주소를 준다
7. 두 스위치를 VTP transparent로 바꾼다

#### 4. 확인 방법

| 확인할 것               | 방법                           | 기대하는 결과                          |
| ------------------- | ---------------------------- | -------------------------------- |
| 포트가 VLAN에 들어갔다      | `show vlan brief`            | 부서별 포트 목록, 트렁크는 목록에 없음           |
| 트렁크가 섰다             | `show interfaces trunk`      | Gi0/1, Gi0/2 trunking, 허락한 VLAN만 |
| 같은 VLAN이 두 스위치를 건넌다 | Sales-PC1에서 Sales-PC3으로 ping | Reply                            |
| 다른 VLAN은 라우터를 지난다   | Sales-PC1에서 HR-PC1으로 tracert | 첫 줄이 192.168.10.1                |
| 주소를 바꿔도 못 넘어간다      | HR-PC1을 영업팀 대역 주소로 바꾸고 ping  | Request timed out                |
| 관리 접속               | Admin-PC에서 두 스위치로 telnet     | 비밀번호 창                           |
| VLAN이 설정 텍스트에 남는다   | `show running-config`        | `vlan 10` 줄                      |

#### 5. 되돌리는 방법

* 저장 전이면 `reload` 에서 저장하지 않음(no)
* 라우터가 꼬이면 `configs/HQ-R1.txt` 의 2일차 설정을 붙여 넣는다
* 패킷트레이서 파일은 `git restore configs/network.pkt` 로 마지막 커밋의 판으로 돌아간다

#### 6. 결과 (개인 실습이 끝날 때 채운다)

* 한 일:
* 확인 결과:
* 막힌 곳과 어떻게 풀었나:
* 다음 회차에 이어서 할 일: 지사와 연결(4일차). 10일차에 막을 통신: 영업팀과 인사팀 사이, 관리자 PC가 아닌 곳에서 장비로의 접속

## 수업 전에 확인할 것

* 패킷트레이서에서 `interface range fa0/16 - 20 , fa0/23` 처럼 쉼표로 이은 범위가 받아들여지는지
* native VLAN을 한쪽만 바꿨을 때 `%CDP-4-NATIVE_VLAN_MISMATCH` 알림이 몇 초 뒤에 뜨는지
* `show running-config | include vlan` 처럼 `|` 로 거르는 명령이 패킷트레이서에서 되는지
* VS Code에서 마크다운에 캡처를 붙여 넣으면 그림 파일이 만들어지는지
* 강사 레퍼런스 저장소에 새봄상사의 3일차 작업 계획서, 구성도, 설정 세 개가 미리 커밋되어 있는지
