# 1. VLAN: 스위치가 지키는 경계

> 상위: [3일차 스위칭과 VLAN](README.md)
> 대본: [실습 명령어 모음](commands.md) 1~3번
> 드로잉: 1. VLAN: 스위치가 지키는 경계 드로잉 (10장)

## 학습 목표

- 주소만 나눈 경계가 왜 약한지 설명합니다
- VLAN이 스위치 하나를 여러 네트워크로 나눈다는 것을 압니다
- VLAN을 만들고 포트를 넣고, `show vlan brief` 로 확인합니다
- 쓰지 않는 포트를 닫는 이유와 방법을 압니다

## 다리 놓기

2일차에 부서마다 /27을 나눴고, 같은 스위치에 꽂힌 PC라도 대역이 다르면 통하지 않는 것을 보았습니다. 그런데 그 경계는 누가 지키고 있었을까요.

답은 PC입니다. PC가 "상대가 다른 네트워크에 있으니 라우터로 보내야지"라고 스스로 판단했기 때문에 통하지 않았던 것입니다. 인사팀 PC의 주소를 영업팀 대역으로 바꾸면 그 PC는 바로 영업팀 네트워크의 일원이 됩니다. 스위치는 아무것도 막지 않습니다. **주소만 나눈 경계는 PC가 지켜 주는 약속일 뿐입니다.**

오늘은 이 경계를 스위치가 지키게 만듭니다.

## 1. 주소만 나눈 경계의 한계

| 장면 | 주소만 나눈 경우 | VLAN으로 나눈 경우 |
|------|------------------|--------------------|
| 인사팀 PC가 주소를 영업팀 대역으로 바꾼다 | 영업팀과 바로 통신한다 | 포트가 인사팀 VLAN이라 영업팀에 닿지 않는다 |
| 영업팀 PC가 브로드캐스트를 보낸다 | 같은 스위치의 모든 PC가 받는다 | 영업팀 VLAN 안에서만 퍼진다 |
| 누가 빈 포트에 노트북을 꽂는다 | 주소만 맞추면 어느 부서든 들어간다 | 그 포트가 속한 VLAN에만 닿는다 |

브로드캐스트는 같은 네트워크의 모두에게 가는 통신입니다. 주소만 나눠도 같은 스위치에 있으면 브로드캐스트는 모든 PC에 도착합니다. 부서가 늘수록 쓸데없는 통신이 늘고, 다른 부서의 PC가 내 브로드캐스트를 엿들을 수도 있습니다.

> 12일차에 같은 네트워크 안에서 주소를 속이는 공격을 볼 때, 공격이 닿는 범위가 바로 이 브로드캐스트 범위입니다.

## 2. VLAN: 스위치 하나를 여러 개처럼

VLAN(Virtual LAN)은 스위치의 포트를 묶음으로 나눠, 묶음마다 서로 다른 네트워크처럼 동작하게 하는 기능입니다. 같은 VLAN의 포트끼리만 통신하고, 다른 VLAN으로는 프레임이 건너가지 않습니다.

강의실 하나를 칸막이로 나눠 두 반으로 쓰는 것과 같습니다. 중요한 것은 칸막이를 학생이 세우는 것이 아니라 건물이 세운다는 점입니다. 학생이 반 이름표를 바꿔 달아도 칸막이를 넘을 수는 없습니다. 포트가 어느 VLAN에 속하는지는 스위치 관리자만 바꿀 수 있습니다.

| 나누는 기준 | 내용 | 쓰는 정도 |
|-------------|------|-----------|
| 포트 | 스위치의 몇 번 포트인지로 VLAN을 정한다 | 현장에서 가장 많이 쓴다. 이 과목도 이 방식 |
| MAC 주소 | 장비의 MAC 주소로 정한다 | 장비를 바꿀 때마다 다시 등록해야 한다 |

VLAN 번호는 1부터 4094까지 쓸 수 있습니다. 1번은 처음부터 모든 포트가 들어 있는 기본 VLAN이고, 1002~1005번은 예전 장비용으로 예약되어 있습니다.

## 3. 새봄상사의 VLAN 설계

2일차 설계표의 네트워크마다 VLAN 번호를 하나씩 붙입니다. 번호를 대역과 짝지어 두면 설정을 읽기 쉽습니다.

| VLAN | 이름 | 대역 | 게이트웨이 | 포트 |
|------|------|------|------------|------|
| 10 | SALES | 192.168.10.0/27 | 192.168.10.1 | HQ-SW1 Fa0/1~10, HQ-SW2 Fa0/11~12 |
| 20 | HR | 192.168.10.32/27 | 192.168.10.33 | HQ-SW1 Fa0/11~15 |
| 30 | DEV | 192.168.10.64/27 | 192.168.10.65 | HQ-SW2 Fa0/1~10 |
| 40 | SERVER | 192.168.10.96/27 | 192.168.10.97 | HQ-SW1 Fa0/21~22 |
| 99 | MGMT | 192.168.10.128/27 | 192.168.10.129 | HQ-SW1 Fa0/24 (관리자 PC) |
| 999 | UNUSED | 없음 | 없음 | 쓰지 않는 모든 포트 |

VLAN 이름은 영어로 짓습니다. 패킷트레이서에서 한글이 깨질 수 있고, 현장의 장비도 대부분 영어 이름을 씁니다.

2층의 HQ-SW2에는 개발팀 자리와 영업팀 자리 두 개가 있습니다. 영업팀이 두 스위치에 걸쳐 있으니, 스위치 사이로 VLAN 10이 오가야 합니다. 이것은 다음 노트의 트렁크가 해결합니다.

## 4. 만들고 포트에 넣기

VLAN은 두 단계로 만듭니다. 먼저 VLAN을 만들고 이름을 붙인 뒤, 포트를 그 VLAN에 넣습니다.

```
vlan 10
 name SALES
interface range fa0/1 - 10
 switchport mode access
 switchport access vlan 10
```

| 명령 | 하는 일 |
|------|---------|
| `vlan 10`, `name SALES` | VLAN을 만들고 이름을 붙인다 |
| `interface range fa0/1 - 10` | 포트 열 개를 한 번에 고른다 |
| `switchport mode access` | 이 포트는 PC를 꽂는 자리이고, VLAN 하나만 다룬다고 못 박는다 |
| `switchport access vlan 10` | 이 포트를 VLAN 10에 넣는다 |

`switchport mode access` 를 빼먹어도 대개 통신은 됩니다. 하지만 이 줄이 없으면 포트가 상대와 협상해 트렁크로 바뀔 여지가 남습니다. 다음 노트에서 이것이 왜 위험한지 봅니다.

확인은 `show vlan brief` 로 합니다.

```
VLAN Name                             Status    Ports
---- -------------------------------- --------- -------------------------------
1    default                          active
10   SALES                            active    Fa0/1, Fa0/2, Fa0/3, Fa0/4
                                                Fa0/5, Fa0/6, Fa0/7, Fa0/8
                                                Fa0/9, Fa0/10
20   HR                               active    Fa0/11, Fa0/12, Fa0/13, Fa0/14
                                                Fa0/15
40   SERVER                           active    Fa0/21, Fa0/22
99   MGMT                             active    Fa0/24
999  UNUSED                           active    Fa0/16, Fa0/17, Fa0/18, Fa0/19
                                                Fa0/20, Fa0/23
```

HQ-SW1의 예입니다. 끝에 1002~1005번 줄이 더 보입니다. 트렁크로 쓰는 Gi0/1, Gi0/2는 이 목록에 나오지 않는 것이 정상입니다.

## 5. 쓰지 않는 포트는 닫는다

스위치에는 아무것도 꽂히지 않은 포트가 많습니다. 처음 상태에서 이 포트들은 모두 VLAN 1에 들어 있고 켜져 있습니다. 누군가 사무실 빈자리의 랜 단자에 노트북을 꽂으면 바로 네트워크에 들어올 수 있다는 뜻입니다.

그래서 쓰지 않는 포트는 아무도 쓰지 않는 VLAN 999에 넣고 꺼 둡니다.

```
vlan 999
 name UNUSED
interface range fa0/16 - 20 , fa0/23
 switchport mode access
 switchport access vlan 999
 shutdown
```

포트를 끄기만 해도 되지만, 누가 실수로 켜더라도 갈 곳이 없게 VLAN 999에 함께 넣습니다. 한 겹이 풀려도 다른 한 겹이 남는 1일차의 심층 방어이고, 허락하지 않은 것은 막힌 상태로 두는 기본 거부입니다. 새 직원이 오면 그때 포트를 켜고 부서 VLAN으로 옮깁니다.

## 6. 같은 실험을 다시

2일차의 다른 대역 실험을 뒤집어 봅니다. 인사팀 PC(VLAN 20 포트)의 주소를 영업팀 대역 192.168.10.5로 바꾸고 영업팀 PC에 ping을 칩니다.

```
C:\>ping 192.168.10.2

Request timed out.
Request timed out.
```

주소는 같은 대역인데 통하지 않습니다. 인사팀 PC가 보낸 프레임은 VLAN 20 안에만 머물고, 영업팀 PC는 VLAN 10에 있기 때문입니다. 이제 경계를 지키는 것은 PC의 약속이 아니라 스위치입니다. 확인한 뒤 인사팀 PC의 주소를 되돌립니다.

## 함께 생각해 보기

- 우리 회사의 회의실에 있는 랜 단자는 어느 VLAN에 넣어야 할까요? 손님도 쓰고 직원도 씁니다.
- 영업팀 직원이 인사팀 자리로 옮겨 앉았습니다. 스위치에서 무엇을 바꿔야 할까요?

## 강의 메모

### 시간 배분 (35분)

| 절 | 시간 | 방식 |
|----|------|------|
| 다리 놓기, 1 | 7분 | 인사팀 PC의 주소만 바꾸면 영업팀과 통하는 것을 먼저 보여 준다 |
| 2, 3 VLAN과 새봄상사 설계 | 8분 | 칸막이 비유. 설계표에 VLAN 칸을 더한다 |
| 4 만들고 넣기 | 12분 | 대본 2번. `show vlan brief` 를 같이 읽는다 |
| 5 쓰지 않는 포트 | 4분 | 대본 3번 |
| 6 같은 실험 다시 | 4분 | |

### 물어볼 것

- "2일차에 다른 대역 PC와 통신이 안 된 것은 누가 막았기 때문일까요?" 기대하는 답은 "아무도 막지 않았다. PC가 라우터로 보냈을 뿐"입니다. 다리 놓기의 핵심입니다.
- "VLAN 999에 넣고 끄는 것과, 끄기만 하는 것은 무엇이 다를까요?" 누가 실수로 `no shutdown` 을 쳐도 VLAN 999에는 갈 곳이 없습니다. 심층 방어입니다.
- 회의실 질문의 답: 직원용과 손님용을 나눕니다. 손님용 VLAN을 따로 만들어 인터넷만 나가게 하는 것이 흔한 방법입니다. 인터넷만 나가게 하는 일은 9일차 NAT와 10일차 ACL에서 합니다.

### 자주 헷갈리는 것

| 헷갈리는 것 | 바로잡기 |
|-------------|----------|
| VLAN을 만들면 포트가 저절로 들어간다 | VLAN을 만드는 것과 포트를 넣는 것은 따로다 |
| VLAN 번호와 대역은 자동으로 이어진다 | 둘은 관계가 없다. 짝짓는 것은 사람의 약속이고 설계표에 적어 둔다 |
| 트렁크 포트가 `show vlan brief` 에 없으면 잘못이다 | 트렁크는 여러 VLAN을 실어 나르는 포트라 목록에서 빠지는 것이 정상이다 |
| `interface range fa0/1-10` 이 안 먹는다 | 패킷트레이서에서는 `fa0/1 - 10` 처럼 하이픈 앞뒤를 띄우는 편이 안전하다 |

### 진행 요령

- 다리 놓기의 실험(주소만 바꾸면 넘어가는 장면)은 강사가 직접 보여 줍니다. 2일차 패킷트레이서 파일 그대로, 인사팀 대역 PC를 영업팀 대역 주소로 바꾸기만 하면 됩니다.
- VLAN 이름은 대문자로 통일합니다. 대소문자가 섞이면 두 스위치에서 이름이 달라 보입니다.
- 포트 번호는 학생마다 토폴로지가 조금씩 다릅니다. 대본의 포트 번호보다 자기 화면의 연결을 먼저 확인하게 합니다.
