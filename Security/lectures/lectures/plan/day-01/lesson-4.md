# 4. 프로젝트 계획서

> 상위: [1일차 프로젝트 시작](./) 대본: [실습 명령어 모음](commands.md) 4\~6번 드로잉: 4. 프로젝트 계획서 드로잉 (9장)

## 학습 목표

* 내 가상 회사를 정하고 프로젝트 계획서를 씁니다
* 지킬 것과 걱정되는 것을 누가, 어디서, 무엇을의 문장으로 씁니다
* 계획서와 README를 저장소에 커밋합니다
* 2일차부터 매 회차 쓰는 작업 계획서의 양식을 압니다

## 다리 놓기

그릇이 생겼으니 담을 것을 정할 차례입니다. [2번 노트](lesson-2.md)의 네 가지 질문 중 앞의 두 개, 무엇을 만드는가와 무엇이 잘못될 수 있는가에 내 회사로 답해 봅니다.

## 1. 회사의 뼈대는 모두 같다

회사의 이름, 업종, 부서는 마음대로 정합니다. 다만 뼈대는 모두 같게 둡니다. 16일 수업이 이 뼈대에 맞춰 짜여 있기 때문입니다.

| 뼈대                      | 이것이 있어야 하는 날                          |
| ----------------------- | ------------------------------------- |
| 본사 하나와 지사 하나            | 4일차에 라우팅할 길이, 11일차에 암호화할 구간이 생긴다      |
| 부서 셋 이상                 | 3일차에 VLAN으로 나눌 것이, 10일차에 서로 막을 것이 생긴다 |
| 인터넷 연결과 밖에서 접속하는 서비스 하나 | 9일차 NAT와 14일차 방화벽에서 열어 줄 문이 생긴다       |
| 집에서 일하는 직원              | 14일차에 원격 접속 VPN을 만들 이유가 생긴다           |

## 2. 회사 정하기

업종은 내가 잘 아는 곳에서 고르면 쓰기 쉽습니다. 일해 본 곳, 자주 가는 곳, 가족이 일하는 곳을 떠올려 봅니다. 그 회사에서 무엇이 새면 큰일이 나는지 감이 오기 때문입니다.

규모는 이 정도로 정합니다.

| 항목        | 권하는 크기  | 이유                              |
| --------- | ------- | ------------------------------- |
| 본사 직원     | 15\~30명 | 패킷트레이서에서 다루기 좋은 크기              |
| 지사 직원     | 5\~10명  |                                 |
| 부서 하나의 인원 | 30명 이하  | 2일차 주소 설계에서 부서마다 같은 크기로 나눌 수 있다 |

실제 회사 이름은 쓰지 않습니다. 실제 회사의 이름을 붙이면 그 회사의 내부 구조를 아는 것처럼 보일 수 있고, 공개 저장소에 올라갑니다.

## 3. 쓰는 순서

계획서는 두 단계로 씁니다. 16:30부터 30분 동안은 강사가 새봄상사의 계획서를 칸마다 보여 주며 쓰는 요령을 설명합니다. 17:00부터 한 시간은 개인 실습입니다. 각자 자기 회사로 칸을 채우고, 강사는 한 사람씩 돌며 걱정 칸을 함께 봅니다.

개인 실습 한 시간은 이렇게 나눠 씁니다.

| 순서 | 칸            | 시간  |
| -- | ------------ | --- |
| 1  | 회사 소개        | 5분  |
| 2  | 부서와 사용자      | 10분 |
| 3  | 연결 요구사항      | 10분 |
| 4  | 지킬 것과 걱정되는 것 | 15분 |
| 5  | 일정과 완료 기준    | 5분  |
| 6  | README       | 5분  |
| 7  | 커밋과 push     | 10분 |

## 4. 칸마다 쓰는 요령

계획서에서 가장 흔한 문제는 문장이 흐린 것입니다. 흐린 문장은 나중에 설정으로 바꿀 수가 없습니다.

| 칸            | 흐린 문장        | 쓸 수 있는 문장                           |
| ------------ | ------------ | ----------------------------------- |
| 회사 소개        | IT 회사        | 반려동물 용품 온라인 판매, 본사 부산 18명, 지사 대구 6명 |
| 부서와 사용자      | 직원들이 컴퓨터를 쓴다 | 회계팀 3명은 급여 자료와 메일을 쓴다               |
| 연결 요구사항      | 다 잘 연결된다     | 지사 영업팀은 본사의 주문 관리 서버만 쓴다            |
| 지킬 것과 걱정되는 것 | 해킹이 걱정된다     | 밖에서 쇼핑몰을 통해 고객 정보 데이터베이스에 접근한다      |

"지킬 것과 걱정되는 것" 칸은 2번 노트의 자산, 위협, 취약점으로 씁니다. 지킬 것 칸에는 자산을 적고, 그것이 깨지면 안 되는 이유를 기밀성, 무결성, 가용성 중에서 고릅니다. 걱정 칸에는 누가, 어디서, 무엇을 하는지가 들어간 문장을 적습니다.

| 들어갈 것 | 예                                 |
| ----- | --------------------------------- |
| 누가    | 밖의 공격자, 다른 부서 직원, 퇴사한 직원, 실수한 관리자 |
| 어디서   | 인터넷에서, 사내망에서, 지사와 본사 사이에서         |
| 무엇을   | 엿본다, 바꾼다, 멈추게 한다                  |

이 세 가지가 들어가면 10일차에 "어디서 오는 무엇을 막는다"는 ACL 한 줄로 바로 옮길 수 있습니다.

## 5. 계획서 양식

`01_요구사항/프로젝트_계획서.md` 에 붙여 넣고 채웁니다.

```markdown
# 프로젝트 계획서

## 1. 회사 소개

- 회사 이름:
- 업종:
- 본사 위치와 직원 수:
- 지사 위치와 직원 수:
- 밖에서 접속하는 서비스:

## 2. 부서와 사용자

| 부서 | 위치 | 인원 | 쓰는 서비스 |
|------|------|------|-------------|
|      |      |      |             |

## 3. 연결 요구사항

- 부서 사이:
- 본사와 지사 사이:
- 인터넷:
- 밖에서 들어오는 접속:
- 재택 근무:

## 4. 지킬 것과 걱정되는 것

| 지킬 것 | 깨지면 안 되는 것 (기밀성, 무결성, 가용성) | 무엇이 잘못될 수 있나 |
|---------|--------------------------------------------|------------------------|
|         |                                            |                        |

## 5. 일정

| 일차 | 배우는 것 | 우리 회사에서 할 일 |
|------|-----------|---------------------|
| 1 | 오리엔테이션, Git | 이 계획서 |
| 2 | 네트워크 기초, CLI, 서브네팅 | |
| ... | | |
| 16 | 프로젝트 완성 | 최종 보고서와 발표 |

## 6. 완료 기준

- [ ] 구성도
- [ ] IP와 서브넷 설계표
- [ ] 장비 설정 파일
- [ ] 보안 정책표와 그 근거
- [ ] 공격 관찰과 대응 기록
- [ ] 최종 보고서
- [ ] 발표
```

5번 일정 칸은 [강의계획서](../)의 주차표에서 "배우는 것"을 옮기고, 마지막 칸만 내 회사의 말로 바꿔 적습니다.

## 6. 강사 예시: 새봄상사

수업에서 강사가 한 칸씩 채워 보이는 예시입니다.

### 회사 소개

* 회사 이름: 새봄상사
* 업종: 생활용품 온라인 판매
* 본사: 대구, 22명
* 지사: 서울, 6명
* 밖에서 접속하는 서비스: 쇼핑몰 웹사이트

### 부서와 사용자

| 부서  | 위치        | 인원    | 쓰는 서비스           |
| --- | --------- | ----- | ---------------- |
| 영업팀 | 본사, 지사    | 8 + 6 | 주문 관리, 파일 서버, 메일 |
| 인사팀 | 본사        | 4     | 급여 자료(파일 서버), 메일 |
| 개발팀 | 본사, 재택 3명 | 10    | 쇼핑몰 서버 관리, 파일 서버 |
| 서버  | 본사 서버실    |       | 쇼핑몰 웹 서버, 파일 서버  |

### 연결 요구사항

* 부서 사이: 부서마다 네트워크를 나눈다. 영업팀과 인사팀은 서로 통신할 일이 없다
* 본사와 지사 사이: 지사 영업팀은 본사의 주문 관리와 파일 서버를 쓴다
* 인터넷: 모든 직원이 쓴다
* 밖에서 들어오는 접속: 쇼핑몰은 누구나 접속한다. 그 밖의 서버는 밖에서 보이지 않아야 한다
* 재택 근무: 개발팀 재택 직원은 집에서 본사 내부망에 들어와 쇼핑몰 서버를 관리한다

### 지킬 것과 걱정되는 것

| 지킬 것    | 깨지면 안 되는 것 | 무엇이 잘못될 수 있나                 |
| ------- | ---------- | ---------------------------- |
| 고객 개인정보 | 기밀성        | 밖에서 쇼핑몰 서버 뒤의 데이터에 접근한다      |
| 급여 자료   | 기밀성        | 다른 부서 직원이 인사팀 자료를 연다         |
| 주문 내역   | 무결성        | 본사와 지사 사이에서 주문 내용이 엿보이거나 바뀐다 |
| 쇼핑몰 서비스 | 가용성        | 접속이 몰리거나 공격을 받아 쇼핑몰이 멈춘다     |
| 장비 설정   | 무결성        | 아무나 라우터에 접속해 설정을 바꾼다         |

이 표가 10일차 ACL 정책표, 11일차 VPN, 14일차 방화벽 규칙의 출발점이 됩니다.

## 7. 다른 업종이라면

뼈대는 같아도 업종이 바뀌면 지킬 것이 달라집니다.

| 업종      | 밖에서 접속하는 서비스 | 지킬 것과 깨지면 안 되는 것                             |
| ------- | ------------ | -------------------------------------------- |
| 동물병원 체인 | 온라인 진료 예약    | 진료 기록(기밀성), 처방 기록(무결성), 예약 사이트(가용성)          |
| 입시 학원   | 수강 신청 사이트    | 학생과 학부모 연락처(기밀성), 성적(무결성), 수강 신청 날의 사이트(가용성) |
| 물류 회사   | 배송 조회        | 고객 주소(기밀성), 배송 상태(무결성), 배차 시스템(가용성)          |

새봄상사의 표를 그대로 옮기지 말고, 내 업종에서 무엇이 새면 가장 곤란할지부터 생각합니다.

## 8. 저장소 README

저장소 첫 화면에 보이는 `README.md` 는 프로젝트의 표지입니다. 다음 양식으로 바꿉니다.

```markdown
# 새봄상사 네트워크 보안 프로젝트

가상 회사 새봄상사의 네트워크를 설계하고, 보안 정책을 적용하고, 점검한 기록입니다.
코리아IT아카데미 대구 정보보안 과정 네트워크 보안 과목에서 진행했습니다.

## 진행 현황

| 일차 | 한 일 | 문서 |
|------|-------|------|
| 1 | 프로젝트 계획서 작성 | [프로젝트 계획서](01_요구사항/프로젝트_계획서.md) |
```

진행 현황 표는 매 회차 한 줄씩 늘어납니다. 16일차에는 이 표가 그대로 프로젝트의 목차가 됩니다. 면접관이 가장 먼저 보는 화면이라 회사 이름과 한 줄 소개만큼은 오늘 제대로 씁니다.

## 9. 커밋하기 전에

| 확인할 것                           | 보는 곳         |
| ------------------------------- | ------------ |
| 실제 회사 이름, 내 이름 외의 개인 정보가 없다     | 계획서 전체       |
| 부서가 셋 이상이고, 부서 하나가 30명 이하다      | 2번 칸         |
| 걱정 칸의 문장에 누가, 어디서, 무엇을이 들어 있다   | 4번 칸         |
| 미리보기(Ctrl+Shift+V)에서 표가 깨지지 않는다 | VS Code      |
| README의 링크를 누르면 계획서가 열린다        | VS Code 미리보기 |

다 되면 [대본](commands.md)의 4\~6번을 따라 커밋하고 push합니다. GitHub에서 내 저장소를 열어 README와 계획서가 보이는지 확인하고, 저장소 주소를 강사에게 알려 줍니다.

## 10. 2일차부터 쓰는 작업 계획서

오늘 쓴 프로젝트 계획서는 두 달 전체의 계획입니다. 2일차부터는 수업 첫 30분에 그날의 작업 계획서를 하나씩 씁니다. 회사에서 장비 설정을 바꾸기 전에 쓰는 작업 계획서와 같은 문서입니다. 무엇을 왜 바꾸는지, 어떻게 확인하는지, 잘못되면 어떻게 되돌리는지를 먼저 적어 둡니다. 현장에서는 되돌리는 방법이 없는 작업은 시작하지 않습니다.

파일은 `00_작업계획/02일차.md` 처럼 회차마다 하나씩 만듭니다. 양식은 이렇습니다.

```markdown
# 2일차 작업 계획서

- 날짜:

## 1. 목표

- 프로젝트 계획서의 어느 줄을 해결하나:

## 2. 작업 대상

| 대상 | 무엇을 |
|------|--------|
|      |        |

## 3. 작업 내용

1.

## 4. 확인 방법

| 확인할 것 | 방법 | 기대하는 결과 |
|-----------|------|---------------|
|           |      |               |

## 5. 되돌리는 방법

-

## 6. 결과 (개인 실습이 끝날 때 채운다)

- 한 일:
- 확인 결과:
- 막힌 곳과 어떻게 풀었나:
- 다음 회차에 이어서 할 일:
```

| 칸    | 쓰는 때      | 이어지는 곳               |
| ---- | --------- | -------------------- |
| 1\~5 | 수업 첫 30분  | 오늘 수업에서 배울 것을 미리 훑는다 |
| 6 결과 | 개인 실습 마지막 | 16일차 최종 보고서의 재료가 된다  |

계획서는 수업 시작에 한 번, 결과를 채운 뒤에 한 번 커밋합니다. 커밋 기록에 계획과 결과가 시간 순서대로 남습니다.

## 함께 생각해 보기

* 내 계획서의 지킬 것 중 하나를 골라, 2번 노트의 위험 대응 네 가지(감소, 회피, 전가, 수용) 중 무엇을 할지 정해 봅니다.
* 옆자리의 계획서를 읽고, 걱정 칸에서 빠진 것을 하나 찾아 알려 줍니다.

## 강의 메모

### 시간 배분 (함께 30분, 개인 실습 60분)

| 구간 | 절                                | 시간  | 방식                             |
| -- | -------------------------------- | --- | ------------------------------ |
| 함께 | 1, 2 뼈대와 회사 정하기                  | 5분  | 업종이 안 떠오르는 학생에게 7번 절의 표를 보여 준다 |
| 함께 | 4, 6 작성 요령과 새봄상사 계획서             | 17분 | 칸마다 흐린 문장과 새봄상사의 문장을 나란히 보여 준다 |
| 함께 | 5, 8 양식과 README                  | 3분  | 붙여 넣을 곳만 짚는다                   |
| 함께 | 10 작업 계획서 예고                     | 5분  | 2일차 첫 30분에 쓴다는 것만 알린다          |
| 개인 | 3번 절의 순서대로 칸 채우기, 9 확인, 커밋과 push | 60분 | 대본 4\~6번. 강사는 한 사람씩 돈다         |

### 1:1로 볼 때

개인 실습 한 시간에 모든 학생을 깊게 보기는 어렵습니다. 순서를 정해 둡니다.

1. 15분이 지나도 저장소에 첫 커밋이 없는 학생. Git에서 막힌 것이라 먼저 풀어 줍니다.
2. 걱정 칸이 "해킹이 걱정된다"처럼 흐린 학생. 누가, 어디서, 무엇을 중 빠진 것 하나만 짚습니다.
3. 나머지 학생은 9번 절의 확인 표를 스스로 보게 하고, 시간이 남으면 걱정 칸을 함께 읽습니다.

일찍 끝낸 학생에게는 함께 생각해 보기의 두 질문을 계획서에 반영하게 합니다.

### 물어볼 것

* "내 회사에서 하루 동안 멈추면 가장 곤란한 것은?" 가용성 칸의 답이 바로 나옵니다.
* "내 회사에서 밖으로 새면 뉴스에 나올 정보는?" 기밀성 칸의 답이 나옵니다.
* "걱정 칸에 '해킹'이라고만 쓰면 10일차에 무엇을 막아야 할까요?" 막을 수가 없다는 답으로 누가, 어디서, 무엇을의 필요를 짚습니다.

### 자주 헷갈리는 것

| 흔한 실수            | 바로잡기                                        |
| ---------------- | ------------------------------------------- |
| 지킬 것에 "라우터"를 적는다 | 라우터 자체보다 라우터의 설정(무결성)이나 라우터가 나르는 통신이 지킬 것이다 |
| 부서를 열 개 넘게 만든다   | 오늘은 셋에서 다섯이면 충분하다. 주소 설계와 VLAN이 그만큼 늘어난다    |
| 재택 근무를 빠뜨린다      | 14일차 원격 접속 VPN이 할 일이 없어진다. 한 명이라도 둔다        |
| 계획서를 오늘 완성하려 한다  | 오늘은 초안이다. 커밋 기록에 다듬어지는 과정이 남는 것이 오히려 좋다     |

### 진행 요령

* 회사가 떠오르지 않는 학생에게 줄 업종 예시입니다. 카페 체인, 동물병원, 학원, 물류 회사, 치과, 여행사. 실제 회사 이름은 쓰지 않게 합니다.
* 4번 칸에서 시간이 가장 오래 걸립니다. 지킬 것 세 개, 걱정 세 개면 충분하다고 끊습니다. 12일차 이후에 다시 고칩니다.
* 계획서는 오늘 완성하지 않아도 되지만 커밋은 오늘 반드시 합니다. 2일차 첫 30분의 작업 계획서 시간에 함께 다듬습니다.
* 다른 과목에서 넘어온 학생은 시스템 보안이나 웹 보안에서 다룬 서버를 회사에 넣고 싶어 합니다. 서버는 이름과 역할만 적게 하고, 서버 자체의 보안은 그 과목의 몫으로 둡니다.
* 학생 저장소 주소는 강사가 한곳에 모아 둡니다. 회차 점검을 이 목록으로 합니다.
