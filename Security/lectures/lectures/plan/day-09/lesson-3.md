# 3. 서비스 공개: 고객을 쇼핑몰로

> 상위: [9일차 NAT와 서비스 공개](README.md)
> 대본: [실습 명령어 모음](commands.md) 6~8번

## 학습 목표

- 밖에서 안쪽 서버로 들어오려면 무엇이 필요한지 압니다
- 정적 NAT와 포트 포워딩의 차이를 압니다
- 1:1 정적 NAT가 서버의 모든 문을 함께 연다는 것을 직접 봅니다
- 쇼핑몰의 80, 443번만 열고 밖에서 확인합니다

## 다리 놓기

앞 노트의 PAT는 안에서 먼저 말을 건 통신의 답만 돌려보냈습니다. NET-PC가 203.0.113.2로 먼저 말을 걸면 변환 표에 맞는 줄이 없어 아무 데도 닿지 않습니다. 직원의 인터넷에는 이것으로 충분하지만, 고객은 쇼핑몰에 먼저 말을 거는 쪽입니다.

1일차 계획서 3번 칸에 새봄상사는 이렇게 적었습니다. "쇼핑몰은 누구나 접속한다. 그 밖의 서버는 밖에서 보이지 않아야 한다." 오늘 이 두 문장을 설정으로 옮깁니다.

## 1. 밖에서 먼저 들어오려면

밖에서 들어오는 통신을 위해서는 변환 표에 미리 줄을 적어 두어야 합니다. 우편실에 "회사 대표 주소의 고객 상담 창구로 온 편지는 쇼핑몰 담당에게"라는 규칙을 붙여 두는 것과 같습니다.

| 방법 | 미리 적는 것 | 밖에서 열리는 것 |
|------|--------------|------------------|
| 정적 NAT (1:1) | 사설 주소 하나와 공인 주소 하나 | 그 서버의 모든 포트 |
| 포트 포워딩 (정적 PAT) | 공인 주소와 포트 하나, 사설 주소와 포트 하나 | 적어 둔 포트 하나 |

집 공유기의 "포트 포워딩" 메뉴가 두 번째 방법입니다.

## 2. 강사 시연: 1:1 정적 NAT가 연 문

먼저 간단한 1:1 정적 NAT로 쇼핑몰(Server1, 192.168.10.98)을 공개해 봅니다.

```
ip nat inside source static 192.168.10.98 203.0.113.10
```

NET-PC의 웹 브라우저에서 `http://203.0.113.10` 을 열면 쇼핑몰 화면이 나옵니다. 목적은 이뤘습니다. 그런데 같은 NET-PC에서 FTP로 들어가 봅니다.

```
C:\>ftp 203.0.113.10
Trying to connect...203.0.113.10
Connected to 203.0.113.10
220- Welcome to PT Ftp server
Username:cisco
331- Username ok, need password
Password:
230- Logged in
```

패킷트레이서의 서버는 처음부터 FTP가 켜져 있고, 기본 계정(cisco)이 들어 있습니다. 쇼핑몰만 열려고 했는데 서버의 파일 창고까지 인터넷에 열렸고, 기본 계정으로 들어가졌습니다. 1:1 정적 NAT는 주소를 통째로 넘기기 때문에 서버에 켜져 있는 모든 문이 밖에서 보입니다.

실제 서버도 다르지 않습니다. 설치하며 켜진 관리 화면, 원격 접속, 데이터베이스 포트가 그대로 인터넷에 닿습니다. 2일차에 "쓰지 않는 포트가 열려 있으면 들어올 수 있는 문이 하나 더"라고 했던 그 문입니다.

> 12일차 같은 네트워크 안의 공격과 15일차 모니터링을 볼 때, 인터넷에 열린 서버는 쉬지 않고 이런 문을 두드리는 스캔을 받는다는 것을 확인합니다.

## 3. 포트 포워딩으로 바꾼다

1:1 줄을 지우고, 쇼핑몰이 쓰는 두 포트만 적습니다.

```
no ip nat inside source static 192.168.10.98 203.0.113.10
ip nat inside source static tcp 192.168.10.98 80 203.0.113.10 80
ip nat inside source static tcp 192.168.10.98 443 203.0.113.10 443
```

| 부분 | 뜻 |
|------|----|
| `static tcp` | TCP 포트 하나만 고정해서 바꾼다 |
| `192.168.10.98 80` | 안쪽 서버와 포트 |
| `203.0.113.10 80` | 밖에서 보이는 주소와 포트 |

80은 HTTP, 443은 HTTPS입니다. 2일차 포트 표의 두 줄입니다.

## 4. 밖에서 확인

| NET-PC에서 | 결과 | 이유 |
|------------|------|------|
| 웹 브라우저 `http://203.0.113.10` | 쇼핑몰 화면 | 80번은 적어 두었다 |
| `ftp 203.0.113.10` | 연결되지 않음 | 21번은 적어 두지 않았다 |
| `ping 203.0.113.10` | Request timed out | ICMP는 적어 두지 않았다 |

```
HQ-R1#show ip nat translations
Pro  Inside global      Inside local       Outside local      Outside global
tcp  203.0.113.10:80    192.168.10.98:80   ---                ---
tcp  203.0.113.10:443   192.168.10.98:443  ---                ---
```

`---` 줄은 미리 적어 둔 정적 줄입니다. 고객이 들어오면 그 고객의 주소가 채워진 줄이 더 생깁니다.

ping이 안 된다고 쇼핑몰이 죽은 것은 아닙니다. 밖에서 ping으로 서비스를 확인하던 습관은 여기서 버립니다. 확인은 그 서비스의 포트로 합니다.

## 5. ISP도 알아야 한다

ISP-R1은 203.0.113.10이 새봄상사에 있다는 것을 알아야 고객의 패킷을 HQ-R1로 보냅니다. 대본 1번에서 ISP-R1에 넣은 경로가 이 일을 합니다.

```
ISP-R1(config)#ip route 203.0.113.8 255.255.255.248 203.0.113.2
```

실제로는 ISP가 계약할 때 넣어 주는 줄입니다. 학생이 ISP 역할까지 맡는 것은 실습이라서입니다.

HQ-R1에는 반대로 이 묶음을 null 경로로 넣습니다.

```
HQ-R1(config)#ip route 203.0.113.8 255.255.255.248 null0
```

ISP는 묶음 전체(.8~.15)를 HQ-R1로 보냅니다. 그런데 HQ-R1이 바꿔 줄 줄은 203.0.113.10의 80, 443번뿐입니다. 나머지 주소나 다른 포트로 온 패킷은 HQ-R1의 경로표에서 기본 경로에 맞아 다시 ISP로 나가고, ISP는 또 HQ-R1로 보냅니다. TTL이 다할 때까지 두 라우터 사이를 오가는 고리입니다. null 경로가 있으면 HQ-R1이 그 자리에서 버립니다. 2번 노트에서 사설 대역에 건 null 경로와 같은 생각을, 받은 공인 주소에도 씁니다.

## 함께 생각해 보기

- 우리 회사가 밖에 열어야 하는 서비스는 무엇이고, 각각 몇 번 포트인가요? 1일차 계획서의 "밖에서 들어오는 접속"을 다시 읽어 봅니다.
- 1:1 정적 NAT가 꼭 필요한 경우는 언제일까요? 열어야 할 포트가 많거나 미리 알 수 없는 서비스를 떠올려 봅니다.

## 강의 메모

### 시간 배분 (40분)

| 절 | 시간 | 방식 |
|----|------|------|
| 다리 놓기, 1 | 7분 | 계획서 3번 칸을 다시 띄운다 |
| 2 시연 | 10분 | 대본 6번. 강사 화면만. FTP 로그인이 되는 순간을 보여 준다 |
| 3 포트 포워딩 | 10분 | 대본 7번. 함께 |
| 4, 5 확인 | 13분 | 대본 8번. 표의 세 줄을 학생이 직접 |

### 물어볼 것

- "쇼핑몰만 열었는데 FTP는 왜 열렸을까요?" 1:1 정적 NAT는 포트를 고르지 않고 주소를 통째로 넘깁니다.
- "밖에서 ping이 안 되면 쇼핑몰이 죽은 걸까요?" 아닙니다. 80번으로 확인합니다.
- 두 번째 함께 생각해 보기의 답: 메일 서버나 화상 회의 장비처럼 쓰는 포트가 많은 서비스입니다. 그때도 앞에 방화벽(13, 14일차)을 두고 필요한 포트만 통과시킵니다.

### 자주 헷갈리는 것

| 헷갈리는 것 | 바로잡기 |
|-------------|----------|
| 정적 NAT와 포트 포워딩을 같이 걸어도 된다 | 같은 서버에 1:1 줄이 남아 있으면 그 줄이 모든 포트를 연다. 반드시 지운다 |
| 밖에서 `http://192.168.10.98` 로 들어간다 | 밖에서는 공인 주소(203.0.113.10)로만 들어온다 |
| 포트 포워딩을 하면 ISP는 몰라도 된다 | ISP가 203.0.113.8/29를 HQ-R1로 보내야 고객이 닿는다 |
| 안쪽 PC에서 `http://203.0.113.10` 이 안 열린다 | 안에서 공인 주소로 돌아 들어오는 것은 따로 설정이 필요하다. 안에서는 192.168.10.98로 연다 |

### 진행 요령

- 패킷트레이서 서버의 FTP 기본 계정과 기본으로 켜진 서비스는 수업 전에 확인합니다. FTP가 꺼져 있으면 Services 탭에서 켜 두고 시연합니다.
- 시연이 끝나면 강사도 1:1 줄을 지웠는지 `show running-config | include nat` 으로 함께 확인합니다. 남아 있으면 포트 포워딩이 의미가 없어집니다.
- 학생 파일에서는 1:1 정적 NAT를 걸지 않고 바로 포트 포워딩으로 갑니다.
