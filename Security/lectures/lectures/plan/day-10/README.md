> 상위: [네트워크 보안 강의계획서](../) 이전: [9일차 NAT와 서비스 공개](../day-09/) 다음: [11일차 VPN과 IPv6](../day-11/)

첫 달 내내 "막는 일은 10일차 ACL이 한다"고 미뤄 왔습니다. 오늘 3일차의 "필요한가" 표를 정책표로 바꾸고, 부서 사이와 장비 접속을 ACL로 막습니다. 8일차에 남긴 약속대로 게이트웨이 두 장비에 모두 겁니다.

그리고 첫 사고가 납니다. 7일차에 남은 위험으로 적어 둔 틈으로, 인수한 한결물류에서 인사팀으로 접근이 들어옵니다. 막기 전에 기록부터 걸어 알아채고, 증거를 남기고, 막고, 첫 침해사고 분석 보고서를 씁니다.

## 학습 목표

* ACL의 비교 순서와 보이지 않는 거부, 표준과 확장, 방향을 압니다
* ACL 정책표를 근거와 함께 쓰고, 확장 ACL로 HQ-DSW1과 HQ-R1에 겁니다
* `access-class` 로 장비 접속을 관리자 PC로 좁힙니다
* 감시용 ACL로 사고를 탐지하고, 증거를 남기고, 첫 침해사고 분석 보고서를 씁니다
* `established` 와 Reflexive ACL로 안에서 시작한 통신의 답을 들입니다

### 새봄상사 10일차 작업 계획서

#### 1. 목표

* 계획서의 "영업팀과 인사팀은 서로 통신할 일이 없다"와 3일차의 "필요한가" 표를 ACL 정책으로 건다
* 장비 접속을 관리자 PC 한 대로 좁힌다
* 한결물류와 맞닿은 경계(HQ-R1 Gi0/2)에 정책을 건다. 걸기 전에 실제 흐름을 기록해 확인한다

#### 2. 작업 대상

| 대상                        | 무엇을                                                           |
| ------------------------- | ------------------------------------------------------------- |
| HQ-R1                     | NAT-INSIDE 5번 줄, SALES-IN, MGMT-ONLY, LC-WATCH, LC-IN, LC-OUT |
| HQ-DSW1                   | SALES-IN, MGMT-ONLY                                           |
| BR-R1, 스위치 세 대            | MGMT-ONLY                                                     |
| `04_보안정책/ACL_정책표.md` (새로) | 정책과 근거                                                        |
| `05_진단과_대응/` (새로)         | 사고 01 보고서와 증거                                                 |

#### 3. 작업 내용

1. NAT-INSIDE에 장비 관리 VLAN 거부 줄을 끼워 넣는다
2. 정책표를 쓰고, SALES-IN을 HQ-DSW1과 HQ-R1에 건다
3. 모든 장비의 VTY에 `access-class` 를 건다. 콘솔에서 한다
4. Gi0/2에 감시용 ACL(LC-WATCH)을 걸고 흐름을 본다
5. 기록을 보고 판단해 LC-IN으로 바꾼다. 라우팅 알림이 지나가는 포트라 이웃이 끊길 수 있다
6. 새봄상사에서 먼저 건 통신의 답이 들어오게 Reflexive ACL을 건다

#### 4. 확인 방법

| 확인할 것            | 방법                               | 기대하는 결과                  |
| ---------------- | -------------------------------- | ------------------------ |
| 영업팀이 인사팀에 못 간다   | Sales-PC1에서 `ping 192.168.10.42` | 닿을 수 없음                  |
| 장애 때도 정책이 그대로다   | HQ-DSW1 Gi0/1 shutdown 뒤 같은 ping | 닿을 수 없음, HQ-R1의 적중 횟수 증가 |
| 장비 접속은 관리자 PC만   | Sales-PC1, NET-PC에서 `telnet`     | 연결 거부                    |
| 한결물류는 서버만        | LC-PC1에서 인사팀, 서버로 ping           | 인사팀 막힘, 서버 Reply         |
| EIGRP 이웃이 살아 있다  | `show ip eigrp neighbors`        | 192.168.99.10            |
| 내가 건 통신의 답은 들어온다 | BR-PC1에서 `ping 172.16.10.10`     | Reply                    |

#### 5. 되돌리는 방법

* ACL이 업무를 막으면 그 포트에서 `no ip access-group 이름 in` 으로 떼면 바로 원래대로
* `access-class` 를 걸다 관리자까지 막히면 콘솔에서 `line vty`, `no access-class` 로 푼다. 그래서 오늘은 콘솔에서만 건다
* LC-IN으로 한결물류 업무가 멈추면 LC-WATCH로 되돌리고 기록을 다시 본다

#### 6. 결과 (개인 실습이 끝날 때 채운다)

## 수업 전에 확인할 것

* 패킷트레이서가 이름 붙인 ACL의 줄 번호 끼워 넣기(`5 deny ...`)를 받는지
* 3560의 SVI(`interface vlan 10`)에 `ip access-group` 이 걸리는지
* 확장 ACL의 `log` 가 `%SEC-6-IPACCESSLOGDP` 로그를 띄우는지. 안 되면 적중 횟수만으로 탐지한다(3번 노트)
* `reflect` 와 `evaluate` 를 받는지. 안 되면 4번 노트는 `established` 로 TCP만 확인한다
* ACL에 막힌 ping이 PC에 어떻게 보이는지(`Destination ... unreachable` 인지 `Request timed out` 인지)
* 강사 파일의 LC-R1에 정적 경로를 미리 넣어 두었는지, HR-PC1의 DHCP 주소가 192.168.10.42인지
* 강사 레퍼런스 저장소에 새봄상사의 정책표, 사고 01 보고서와 증거, 연결 규정이 미리 커밋되어 있는지
