# 6일차 OSPF와 Git 브랜치

> 상위: [네트워크 보안 강의계획서](../) 이전: [5일차 동적 라우팅 RIP](../day-05/) 다음: [7일차 EIGRP와 재분배](../day-07/)

5일차에 RIP은 회선 속도를 모르고, 장애를 알아채는 데 몇 분이 걸렸습니다. 오늘은 회선 속도를 비용으로 보고 40초 안에 장애를 알아채는 OSPF를 얹어 봅니다.

다만 잘 돌아가는 RIP 망을 바로 바꾸지 않습니다. Git 브랜치에 실험 판을 따로 만들어 OSPF로 바꾸고, 같은 기준으로 비교한 뒤 병합할지 정합니다. 현장에서 설정을 바꾸는 방식 그대로입니다.

## 학습 목표

* 거리 벡터와 링크 상태의 차이, OSPF의 비용과 이웃 맺기를 압니다
* Git 브랜치를 만들어 실험하고, 비교한 뒤 병합합니다
* RIP을 OSPF로 바꾸고 이웃, 경로, 비용을 확인합니다
* OSPF의 passive가 RIP과 어떻게 다른지 알고, 인증을 겁니다
* RIP과 OSPF를 같은 기준으로 비교해 결정을 기록합니다

### 새봄상사 6일차 작업 계획서

#### 1. 목표

* RIP이 회선 속도를 모르고 장애를 늦게 알아채는 문제를 OSPF로 풀 수 있는지 실험한다
* 실험은 ospf 브랜치에서 하고, 비교한 뒤 병합을 정한다

#### 2. 작업 대상

| 대상                | 무엇을                                        |
| ----------------- | ------------------------------------------ |
| HQ-R1, BR-R1      | RIP과 예비 정적 경로 삭제, 루프백 0, OSPF, passive, 인증 |
| BR-R1 루프백 1       | 창고 네트워크를 /27로 알리게                          |
| `02_설계/IP_설계표.md` | 장비 루프백 대역 192.168.255.0/24                 |
| `03_구축/라우팅_비교.md` | OSPF 칸과 결정                                 |

#### 3. 작업 내용

1. ospf 브랜치를 만든다
2. RIP, RIP 인증 줄, key chain, 예비 정적 경로를 지운다
3. 루프백 0과 `router-id` 를 정한다
4. 에어리어 0 하나로 OSPF를 켠다
5. 이웃, 경로, 비용을 확인하고 장애 시험을 한다
6. `passive-interface default` 로 사무실 쪽을 닫고, 이웃 구간 네 곳에 인증을 건다
7. 비교 기록을 쓰고 병합을 정한다

#### 4. 확인 방법

| 확인할 것             | 방법                      | 기대하는 결과                               |
| ----------------- | ----------------------- | ------------------------------------- |
| 이웃이 맺어졌다          | `show ip ospf neighbor` | 192.168.255.2 두 줄, FULL               |
| 주 회선을 쓴다          | `show ip route ospf`    | `O 192.168.20.0/27 [110/2]` via Gi0/1 |
| 예비 회선으로 넘어간다      | 주 회선 shutdown           | `[110/65]` via Se0/0/0                |
| 창고가 /27로 보인다      | `show ip route ospf`    | `O 192.168.20.32/27`                  |
| 사무실 쪽은 이웃을 맺지 않는다 | `show ip protocols`     | Passive Interface(s)에 사무실 쪽 포트        |
| 인증이 맞다            | `show ip ospf neighbor` | 인증 뒤에도 FULL                           |

#### 5. 되돌리는 방법

* 모든 변경은 ospf 브랜치에 있다. 실험이 실패하면 `git switch main` 으로 RIP 판으로 돌아간다
* 장비에서 꼬이면 `no router ospf 1` 로 지우고 main의 `configs/` 설정을 붙여 넣는다

## 수업 전에 확인할 것

* 교실 PC의 Git이 `git switch` 를 지원하는지(2.23 이상). 아니면 `git checkout -b ospf`, `git checkout main` 으로 대신한다
* 패킷트레이서에서 `passive-interface default`, `ip ospf message-digest-key` 가 되는지
