## 1. 목적

IDOR은 요청에 담긴 객체 식별자(계정 이름, 가격, 번호)를 서버가 소유권 확인 없이 믿는 결함이다. 숨은 입력란이나 스크립트 상수에 든 값을 바꾸면 다른 객체가 처리된다.

## 2. 구성 요소

| 번호 | 항목 | 관찰한 현상 | 원인 |
|---|---|---|---|
| 1 | Change Secret | 화면에 보이지 않는 `login` 입력란(`hidden`)에 계정 이름이 들어 있다. 그 값을 바꾸면 바뀐 이름의 계정에 적용된다 | 서버가 세션의 사용자 대신 요청의 계정 이름을 쓴다 |
| 2 | Reset Secret | 버튼이 부르는 `ResetSecret()` 함수에 계정 이름이 상수로 들어 있다 | 같은 원인. 클라이언트 코드는 사용자가 바꿀 수 있다 |
| 3 | Order Tickets | 숨은 입력란에 단가가 있고, 요청에서 단가와 수량을 바꾸면 결제 금액이 달라진다 | 가격을 서버가 계산하지 않고 클라이언트 값을 쓴다 |

## 3. 동작 원리

* `hidden` 입력란은 화면에 안 보일 뿐 요청 값이다. 개발자 도구나 프록시에서 볼 수 있고 바꿔 보낼 수 있다.
* 프록시로 가로챈 요청의 값도 같은 방식으로 바뀐다.
* 서버가 요청 값을 신뢰하면 "내 객체"와 "남의 객체"를 구별하지 못한다.

## 4. 탐지·방어

| 방어 | 내용 |
|---|---|
| 서버 측 소유권 확인 | 대상 계정은 세션에서 얻고, 요청의 식별자는 세션 사용자의 소유인지 확인한다 |
| 서버 측 가격 계산 | 단가는 서버의 상품 정보에서 읽고 요청 값은 수량만 받는다 |
| 예측하기 어려운 식별자 | 순차 번호 대신 무작위 식별자(UUID)를 쓴다. 단 이것만으로는 방어가 되지 않는다 |
| 로그 흔적 | 한 세션이 자기 것이 아닌 식별자를 연속해서 요청한다. 같은 상품의 단가가 요청마다 다르다 |

## 5. 약어와 용어

| 용어 | 뜻 |
|---|---|
| IDOR | 객체 식별자를 직접 노출하고 접근 권한을 확인하지 않는 결함 |
| `hidden` 입력란 | 화면에 표시되지 않지만 요청에 포함되는 `<input>` |
| 프록시 | 브라우저와 서버 사이에서 요청을 보고 바꾸는 도구 |
