## 1. 목적

웹 애플리케이션이 사용자 입력을 운영체제 셸 명령의 일부로 실행할 때 생기는 취약점을 정리한다. 상위 개념은 [A1 인젝션 취약점 모음 (Injection)](a1-injection.md)에 있고, 클라이언트 측 XSS와의 구분은 [커맨드 인젝션 분석 다이어그램](comminjection.md)에 있다.

## 2. 구성 요소

| 구성 | 설명 |
|---|---|
| 취약 지점 | 서버 코드가 `system()`, `exec()`, `shell_exec()` 같은 함수에 입력을 이어 붙여 넘기는 곳 |
| 원인 | 입력과 명령 문법을 분리하지 않고, 셸이 해석하는 특수 문자(명령 구분자, 파이프 등)를 걸러내지 않는다 |
| 영향 | 웹 서버 프로세스 권한으로 서버에서 명령이 실행된다. 파일 읽기, 서버 내부망 접근, 추가 침투의 출발점이 된다 |

{% hint style="warning" %}
CAUTION: 원본에는 공격 PC로 셸 연결을 되돌리는 명령 한 줄이 입력 예시로 적혀 있었다. 실행 가능한 공격 페이로드는 이 저장소에 싣지 않기로 하여 삭제했다. 실습에서는 허가된 VM 안에서 입력이 명령으로 해석되는지(예: 호스트 이름 출력) 확인하는 수준으로 학습 목적을 달성한다.
{% endhint %}

## 3. 동작 원리

1. 애플리케이션이 입력값(예: 도메인 이름)을 받아 `명령어 + 입력` 문자열을 만든다.
2. 이 문자열을 셸에 넘기면 셸이 입력 속의 특수 문자를 명령 문법으로 해석한다.
3. 의도한 명령 뒤에 다른 명령이 이어져 실행된다.
4. 결과가 응답에 그대로 출력되면 공격자가 명령 실행 여부를 바로 알 수 있다.

## 4. 탐지·방어

| 구분 | 내용 |
|---|---|
| 근본 대책 | 셸을 거치지 않는다. 언어가 제공하는 API로 같은 기능을 구현하거나, 인자를 배열로 넘기는 실행 API를 쓴다 |
| 허용 목록 검증 | 입력 형식(예: 도메인 문자, 길이)을 허용 목록으로 서버에서 검증한다 |
| PHP 이스케이프 함수 | `escapeshellcmd()`는 명령 문자열 전체의 셸 특수 문자 앞에 백슬래시(\\)를 붙여 셸이 다른 명령으로 해석하지 못하게 한다. 원본은 "무조건 shell 스크립트에 \\를 붙인다"고 적었다. 개별 인자에는 `escapeshellarg()`를 쓴다. 두 함수 모두 완전한 방어는 아니며(인자 주입 등) 셸을 쓰지 않는 것이 우선이다 (미검증) |
| 최소 권한 | 웹 서버 프로세스 계정의 권한과 아웃바운드 연결을 제한한다 |
| 로그 흔적 | 웹 접근 로그에 `;`, `|`, `&`, 백틱과 그 URL 인코딩(`%3B`, `%7C`, `%26`)이 든 요청, 웹 서버 계정이 만든 비정상 자식 프로세스, 서버에서 외부로 향하는 예상 밖 연결이 남는다 |

{% hint style="info" %}
escapeshellcmd(): 무조건 shell 스크립트에 \\(백슬래시)를 붙여 명령어를 인식하지 못하도록 한다.
{% endhint %}

## 5. 약어와 용어

| 용어 | 뜻 |
|---|---|
| 셸 메타문자 | 셸이 명령 구분·연결·치환에 쓰는 특수 문자 |
| 허용 목록(allowlist) | 허용할 값만 정의하고 나머지를 거부하는 검증 방식 |
