## 1. 목적

CSRF는 로그인된 사용자의 브라우저가 사용자 의도와 무관한 요청을 서버에 보내게 하는 공격이다. bWAPP의 계좌 이체 화면(`csrf_2.php`)은 이체 정보가 URL 쿼리(계좌, 금액, 동작)로 전달되어 이 원리를 관찰하는 데 쓰인다.

{% hint style="info" %}
NOTE: 원본에는 실습 서버 주소가 포함된 이체 요청 URL 한 줄만 있었다. 실제 주소라서 문서에 옮기지 않았다.
{% endhint %}

## 2. 구성 요소

| 번호 | 요소 | 역할 |
|---|---|---|
| 1 | 세션 쿠키 | 브라우저가 대상 사이트 요청에 자동으로 붙인다 |
| 2 | 상태 변경 요청 | 계좌 이체처럼 서버의 데이터를 바꾸는 요청 |
| 3 | 쿼리 매개변수 | `account`, `amount`, `action`. 요청 형식이 예측 가능하다 |

## 3. 동작 원리

1. 사용자가 대상 사이트에 로그인해 세션 쿠키를 가진다.
2. 사용자가 다른 페이지를 열면, 그 페이지가 대상 사이트로 가는 요청을 만든다.
3. 브라우저가 요청에 세션 쿠키를 자동으로 붙인다.
4. 서버는 요청이 사용자의 의도인지 구별하지 못하고 처리한다.

요청에 예측 가능한 값만 있고 요청이 사용자 화면에서 나왔다는 증거가 없는 것이 원인이다. 상태를 바꾸는 요청을 GET으로 받는 것도 위험을 키운다.

## 4. 탐지·방어

| 방어 | 내용 |
|---|---|
| CSRF 토큰 | 폼마다 무작위 토큰을 넣고 서버가 세션과 대조한다 |
| `SameSite` 쿠키 | 세션 쿠키에 `SameSite=Lax` 또는 `Strict`를 설정한다 |
| 메서드 | 상태 변경은 POST 등으로만 받는다. GET으로 받지 않는다 |
| 재인증 | 이체 같은 중요 동작은 비밀번호나 OTP를 다시 요구한다 |
| Origin 확인 | `Origin`, `Referer` 헤더가 자기 사이트인지 확인한다 |
| 로그 흔적 | `Referer`가 외부 사이트이거나 비어 있는 이체 요청, 사용자 행동 없이 연속된 이체 요청 |

## 5. 약어와 용어

| 용어 | 뜻 |
|---|---|
| CSRF | Cross-Site Request Forgery. 사이트 간 요청 위조 |
| OTP | 1회용 비밀번호 |
| `SameSite` | 다른 사이트에서 온 요청에 쿠키를 붙일지 정하는 쿠키 속성 |
