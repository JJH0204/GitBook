## 1. 목적

사용자 입력이 PHP 코드로 평가될 때 생기는 취약점을 정리한다. 원본 메모의 위험도는 medium/high다. 상위 개념은 [A1 인젝션 취약점 모음 (Injection)](a1-injection.md)에 있다.

{% hint style="warning" %}
Severity: medium/high
{% endhint %}

## 2. 구성 요소

| 구성 | 설명 |
|---|---|
| 실습 페이지 | 원본은 bWAPP의 `phpi.php`를 대상으로 했다. `message` 매개변수로 입력을 받는다 |
| 취약 지점 | 입력 문자열을 `eval()` 같은 코드 평가 함수에 넘기는 곳 |
| 원인 | 입력을 데이터가 아니라 코드로 취급한다 |
| 영향 | PHP 코드가 서버에서 실행되므로 [OS 커맨드 인젝션](os_command_injection.md)과 같은 수준의 서버 장악으로 이어질 수 있다 |

{% hint style="warning" %}
CAUTION: 원본에는 `message` 값에 셸 연결을 되돌리는 명령을 넣은 공격 URL이 있었다. 실행 가능한 공격 페이로드는 싣지 않기로 하여 삭제했다.
{% endhint %}

## 3. 동작 원리

1. 서버 코드가 요청 매개변수를 읽는다.
2. 값을 `eval()` 등으로 평가해 결과를 응답에 포함한다.
3. 입력이 PHP 문법이면 그대로 실행된다. 서버가 실행하는 코드를 요청자가 정하게 된다.

## 4. 탐지·방어

| 구분 | 내용 |
|---|---|
| 근본 대책 | 입력을 평가하는 코드를 없앤다. `eval()`, `assert()`, 동적 `include` 사용을 금지한다 |
| 대안 | 필요한 기능은 허용 목록에 있는 값만 처리하는 분기 또는 매핑 테이블로 구현한다 |
| 설정 | `php.ini`의 `disable_functions`로 `system`, `exec`, `passthru`, `shell_exec` 같은 위험 함수를 막는다 (미검증) |
| 정적 분석 | 코드 검토와 정적 분석 도구로 `eval` 호출을 찾는다 |
| 로그 흔적 | 접근 로그의 쿼리 문자열에 PHP 함수 이름, 괄호, 따옴표(또는 `%28`, `%27`)가 든 요청, 웹 서버 계정의 비정상 자식 프로세스와 외부 연결이 남는다 |

## 5. 약어와 용어

| 용어 | 뜻 |
|---|---|
| 코드 인젝션 | 입력이 프로그래밍 언어의 코드로 평가되는 취약점 |
| eval | 문자열을 코드로 실행하는 함수 |
