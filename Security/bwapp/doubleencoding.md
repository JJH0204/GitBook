## 1. 목적

URL 인코딩은 특수 문자를 `%`와 16진수 두 자리로 바꾸는 방식이다. 이미 인코딩된 문자열의 `%`를 다시 인코딩하는 것이 더블 인코딩이다. 입력 검증과 디코딩의 순서가 어긋나면 필터가 우회되는 원리를 이해하기 위해 정리한다.

## 2. 구성 요소

| 문자 | 1회 인코딩 | 2회 인코딩 |
|---|---|---|
| `<` | `%3c` | `%253c` |
| `>` | `%3e` | `%253e` |
| `%` | `%25` | `%2525` |

변환 규칙은 한 가지다. 인코딩 결과의 `%`를 `%25`로 바꾼다. 예: `%3c`는 `%25` + `3c`이므로 `%253c`다.

## 3. 동작 원리

1. 브라우저는 요청 값을 URL 인코딩해 보낸다.
2. 서버(또는 프레임워크)가 값을 디코딩한다.
3. 디코딩을 두 번 하는 구성에서, 검증이 첫 번째 디코딩 뒤에 있고 사용이 두 번째 디코딩 뒤에 있으면 검증 통과 후 특수 문자가 되살아난다.
4. 이 단계 불일치가 필터 회피의 원인이다.

## 4. 탐지·방어

| 방어 | 내용 |
|---|---|
| 한 번만 디코딩 | 디코딩은 입력 경계에서 한 번만 하고, 그 결과를 검증한 뒤 그대로 쓴다 |
| 검증 위치 | 사용 직전의 최종 형태에서 검증한다 |
| 출력 인코딩 | 입력 필터에 의존하지 않고 출력 시 이스케이프한다 |
| 로그 흔적 | 요청에 `%25`가 연속해서 나타나거나 `%253c`, `%2527` 같은 문자열이 있다 |

## 5. 약어와 용어

| 용어 | 뜻 |
|---|---|
| URL 인코딩(퍼센트 인코딩) | 문자를 `%XX`로 표현하는 방식 |
| 더블 인코딩 | 인코딩 결과를 한 번 더 인코딩한 것 |
