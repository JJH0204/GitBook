## 1. 목적

SSI(Server Side Includes)는 응답을 만들 때 서버가 HTML 안의 지시문을 추가로 실행하는 기능이다. 사용자 입력이 이 지시문으로 해석되면 서버에서 명령이 실행된다. 상위 개념은 [A1 인젝션 취약점 모음 (Injection)](a1-injection.md)에 있다.

## 2. 구성 요소

| 구성 | 설명 |
|---|---|
| 실습 페이지 | 원본은 bWAPP의 `ssii.shtml`을 대상으로 했다 (`http://192.168.56.122/bWAPP/ssii.shtml`) |
| 지시문 형식 | HTML 주석 모양이며 `#지시어`로 시작한다. 지시어마다 매개변수를 `이름="값"`으로 받는다 |
| 지시문 예 | 원본의 기본 문법 예시는 `<!--#exec cmd="ls"-->`다. `exec` 지시어는 서버에서 명령을 실행한다 |
| 취약 조건 | 서버가 `.shtml` 같은 SSI 처리 대상 파일에서 `exec`를 허용하고, 입력이 검증 없이 그 파일 출력에 들어간다 |

{% hint style="warning" %}
CAUTION: 원본에는 `exec` 안에 공격 PC로 셸 연결을 되돌리는 명령을 넣은 예시도 있었다. 실행 가능한 공격 페이로드는 싣지 않기로 하여 삭제했다.
{% endhint %}

## 3. 동작 원리

1. 웹 서버가 SSI 처리 대상 파일을 읽는다.
2. 파일 안의 지시문을 실행하고 그 결과로 지시문을 바꿔 응답한다.
3. 사용자 입력이 파일에 그대로 들어가면 입력 속 지시문도 같은 방식으로 실행된다.

## 4. 탐지·방어

| 구분 | 내용 |
|---|---|
| 근본 대책 | 사용자 입력을 SSI 처리 대상 출력에 넣지 않는다. 출력 시 `<`, `>`, `!`, `#`을 HTML 인코딩한다 |
| 서버 설정 | SSI가 필요 없으면 끈다. 필요하면 Apache의 `Options +IncludesNOEXEC`처럼 `exec` 지시어를 막는 옵션을 쓴다 (미검증) |
| 최소 권한 | 웹 서버 계정의 권한과 아웃바운드 연결을 제한한다 |
| 로그 흔적 | 접근 로그와 저장된 입력에 `<!--#`(또는 `%3C%21--%23`)가 보인다. 웹 서버 계정이 만든 비정상 자식 프로세스가 남는다 |

## 5. 약어와 용어

| 용어 | 뜻 |
|---|---|
| SSI | Server Side Includes. 서버가 HTML 속 지시문을 처리하는 기능 |
| exec 지시어 | 서버에서 명령을 실행하는 SSI 지시어 |
