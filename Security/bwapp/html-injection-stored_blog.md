## 1. 목적

저장형은 입력이 서버에 저장되었다가 다른 사용자가 페이지를 열 때 출력되는 방식이다. 반사형보다 피해 범위가 넓다. bWAPP 블로그 항목에서 수준별 방어를 본다.

## 2. 구성 요소

| 번호 | 수준 | 관찰한 현상 |
|---|---|---|
| 1 | low | 입력 필드에 든 HTML이 그대로 저장되고 출력된다 |
| 2 | medium | 소스에 `mysqli_real_escape_string()`이 쓰인다 |

## 3. 동작 원리

* `mysqli_real_escape_string()`은 SQL 문장에서 특수 문자를 이스케이프한다. SQL 인젝션 방어용이다. 원본은 "특수문자를 제거하는 함수"라고 적었으나 제거가 아니라 이스케이프이고, 목적이 SQL용이므로 HTML 출력 방어는 되지 않는다.
* 저장된 값은 출력할 때 HTML 이스케이프를 해야 한다. 저장 시 처리와 출력 시 처리는 서로 다른 문제다.
* 저장형은 한 번 저장되면 그 페이지를 여는 모든 사용자에게 영향을 준다.

## 4. 탐지·방어

| 방어 | 내용 |
|---|---|
| 출력 시 이스케이프 | 저장된 글을 화면에 쓸 때 `htmlspecialchars()`를 적용한다 |
| SQL 방어 분리 | 저장은 매개변수화된 쿼리를 쓴다 |
| 허용 태그 제한 | 서식이 필요하면 검증된 HTML 정화(sanitizer) 라이브러리를 쓴다 |
| 로그·DB 점검 | 저장된 글에 `<script`, `<iframe`, `onerror=` 같은 문자열이 있는지 검색한다 |

## 5. 약어와 용어

| 용어 | 뜻 |
|---|---|
| 저장형 | 입력이 저장된 뒤 다른 사용자 화면에 출력되는 방식 |
| 정화(sanitize) | 허용하지 않는 태그와 속성을 제거하는 처리 |
