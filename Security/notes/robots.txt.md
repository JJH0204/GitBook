# robots.txt와 크롤러 접근 제어

## 작업 식별

| 항목 | 내용 |
|---|---|
| Task ID | SEC-NOT-007-DO |
| 유형 | D&O (개념) |
| 목적 | robots.txt가 무엇이고 무엇을 하지 못하는지 설명한다 |
| 확인 상태 | 미검증 (원본 두 문장과 일반 지식을 정리한 것이다) |
| 개정 | R1 (2026-11-18) |

## 1. 목적

검색 엔진은 크롤러(봇)로 사이트의 정보를 수집한다. 사이트 운영자는 `robots.txt`로 크롤러가 접근해도 되는 파일과 디렉터리를 알린다.

{% hint style="danger" %}
WARNING: robots.txt는 보안 수단이 아니다. 접근을 막지 못하고, 규칙을 지키는 크롤러에게 요청하는 관례일 뿐이다. 누구나 파일을 읽을 수 있으므로 숨기려는 경로를 적으면 오히려 그 경로가 노출된다. 민감한 자료는 인증과 접근 권한으로 보호한다.
{% endhint %}

## 2. 구성 요소

| 항목 | 설명 |
|---|---|
| 위치 | 사이트 루트의 `/robots.txt` (예: `https://<도메인>/robots.txt`) |
| `User-agent` | 규칙을 적용할 크롤러 이름. `*`은 모든 크롤러다 |
| `Disallow` | 크롤링하지 말아 달라고 요청하는 경로 |
| `Allow` | `Disallow` 범위 안에서 허용하는 경로 (RFC 9309가 정의한다) |
| `Sitemap` | 사이트맵 주소 (널리 쓰는 확장 지시어다) |

## 3. 동작 원리

```
User-agent: *
Disallow: /private/
```

1. 크롤러가 사이트의 다른 페이지를 가져오기 전에 `/robots.txt`를 요청한다.
2. 크롤러가 자신의 `User-agent`에 맞는 규칙을 읽는다.
3. 규칙을 지키는 크롤러는 `Disallow` 경로를 수집하지 않는다.
4. 규칙을 무시하는 크롤러나 사람은 해당 경로에 그대로 요청할 수 있다.

## 4. 탐지·방어 관점

| 항목 | 내용 |
|---|---|
| 정찰에서의 역할 | 점검자와 공격자는 가장 먼저 `/robots.txt`를 읽어 숨기고 싶은 경로 단서를 얻는다. 실습 풀이에서도 이 파일이 첫 단서로 나온다 ([CTF 풀이](../ctf-and-wargame/ctf-writeups/ctf_1.md)) |
| 방어 | 민감 경로를 robots.txt에 나열하지 않는다. 인증, 접근 제어, 불필요한 파일 제거로 보호한다 |
| 검색 결과 노출 방지 | 색인을 막으려면 `noindex` 메타 태그나 `X-Robots-Tag` 응답 헤더를 쓴다 (이 역시 접근 통제가 아니다) |

## 5. 약어·용어

| 용어 | 뜻 |
|---|---|
| 크롤러(Crawler) | 웹 페이지를 자동으로 수집하는 프로그램 |
| REP | Robots Exclusion Protocol. robots.txt의 표준 이름이다 (RFC 9309) |
