# 웹 렌더링 엔진 원리

## 작업 식별

| 항목 | 내용 |
|---|---|
| Task ID | SEC-NOT-005-DO |
| 유형 | D&O (개념) |
| 목적 | 브라우저가 서버 응답을 화면으로 바꾸는 과정과 엔진의 종류를 설명한다 |
| 확인 상태 | 미검증 (원본과 일반 브라우저 지식을 정리했다. 렌더링 단계 표는 원본에 없던 보충이다) |
| 개정 | R1 (2026-11-18) |

## 1. 목적

웹 렌더링은 서버에서 받은 리소스를 이용자에게 시각화하는 일이다. 브라우저는 응답의 리소스 타입을 확인하고 적절한 방식으로 처리한다. 이 일은 렌더링 엔진이 한다.

## 2. 구성 요소

### 2.1 브라우저별 엔진

| 브라우저 | 렌더링 엔진 |
|---|---|
| 사파리 | 웹킷(WebKit) |
| 크롬 | 블링크(Blink) |
| 파이어폭스 | 개코(Gecko) |

엔진마다 렌더링 과정, 순서, 속도에 차이가 있다. HTML을 파싱해 시각화한다는 점은 같다.

### 2.2 렌더링 단계 (보충)

| 단계 | 하는 일 |
|---|---|
| 1. HTML 파싱 | HTML을 읽어 DOM(Document Object Model) 트리를 만든다 |
| 2. CSS 파싱 | CSS를 읽어 CSSOM(CSS Object Model) 트리를 만든다 |
| 3. 렌더 트리 생성 | DOM과 CSSOM을 합쳐 화면에 그릴 노드만 모은다 |
| 4. 레이아웃 | 각 노드의 크기와 위치를 계산한다 |
| 5. 페인트 | 노드를 화소로 그린다 |

JavaScript는 DOM과 CSSOM을 바꿀 수 있다. 일반 `<script>`는 실행되는 동안 HTML 파싱을 멈춘다.

## 3. 동작 원리

1. 브라우저가 서버에 요청하고 응답을 받는다.
2. 응답의 `Content-Type`으로 리소스 종류를 판단한다.
3. HTML이면 렌더링 엔진이 2.2의 단계를 거쳐 화면을 만든다.

## 4. 보안 관점

브라우저는 응답에 들어 있는 HTML과 스크립트를 해석해 실행한다. 서버가 이용자 입력을 걸러내지 않고 응답에 넣으면, 입력에 포함된 태그나 스크립트도 해석된다. 이것이 HTML 인젝션과 XSS의 바탕이다. 방어는 출력 시 이스케이프, 입력 검증, CSP(Content Security Policy) 헤더로 한다.

## 5. 약어·용어

| 용어 | 뜻 |
|---|---|
| DOM | HTML 문서를 트리로 나타낸 객체 모델 |
| CSSOM | CSS 규칙을 트리로 나타낸 객체 모델 |
| XSS | Cross-Site Scripting |
| CSP | 허용할 스크립트·리소스 출처를 응답 헤더로 제한하는 정책 |
