## 1. 목적

정적 분석(static analysis)은 파일을 실행하지 않고 구조와 문자열, 가져오기 함수(import)를 보고 동작을 추정하는 방법이다. 동적 분석은 격리 환경에서 실행해 프로세스·파일·네트워크 변화를 관찰하는 방법이다. 두 방법은 서로 보완한다.

## 2. 구성 요소

| 구분 | 확인 항목 | 알 수 있는 것 |
|---|---|---|
| 정적 | PE 헤더·섹션 | 파일 종류, 컴파일 시각, 섹션 이름과 크기 |
| 정적 | 패킹 여부 | 섹션 엔트로피가 높고 import가 거의 없으면 패킹을 의심한다 |
| 정적 | import 함수 | 파일·레지스트리·네트워크·프로세스 API 사용 여부 |
| 정적 | 문자열 | 경로, 주소, 레지스트리 키 |
| 동적 | 프로세스 목록 | 실행 중인 프로세스 이름과 부모 관계 |
| 동적 | 파일·레지스트리·네트워크 감시 | 생성·변경된 항목, 외부 연결 |

## 3. 동작 원리

1. 파일의 PE 헤더와 섹션을 읽는다.
2. 패킹 여부를 판단한다. 패킹되어 있으면 import와 문자열이 거의 보이지 않아 내용을 추정하기 어렵다.
3. 패킹된 파일은 압축을 푼 뒤 다시 분석하거나 동적 분석으로 넘어간다.
4. 동적 분석에서 의심 프로세스가 보이지 않으면 프로세스 은닉, 짧은 수명, 다른 프로세스로의 주입을 원인으로 의심한다.

## 4. 탐지·방어

| 관점 | 내용 |
|---|---|
| 흔적 | 의심 파일의 비정상 섹션 이름, 높은 엔트로피 |
| 완화 | 출처 불명 실행 파일을 실행하지 않고, 격리 환경에서 먼저 분석한다 |

## 5. 약어·용어

| 용어 | 뜻 |
|---|---|
| PE | Portable Executable, Windows 실행 파일 형식 |
| 패킹 | 실행 파일을 압축·암호화해 분석을 어렵게 하는 기법 |
| import | 파일이 외부 라이브러리에서 가져다 쓰는 함수 |
