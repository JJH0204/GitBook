## 1. 목적

기법과 도구를 배우기 전에 무엇을 지키는지, 어떤 원칙으로 지키는지를 정한다. 이 기준이 있어야 공격 기법의 의미와 방어 선택의 이유를 설명할 수 있다.

## 2. 구성 요소

### 2.1 정보 보안 3요소 (CIA)

| 요소 | 뜻 | 침해 예 | 대표 통제 |
|---|---|---|---|
| 기밀성(Confidentiality) | 허가된 사람만 정보를 볼 수 있다 | 데이터 유출 | 암호화, 접근 통제 |
| 무결성(Integrity) | 정보가 허가 없이 바뀌지 않는다 | 웹 페이지 변조 | 전자서명, 해시 검증, 권한 분리 |
| 가용성(Availability) | 필요할 때 서비스를 쓸 수 있다 | [DDoS](../../offensive-security/system/ddos.md) | 이중화, 백업, 트래픽 제어 |

### 2.2 접근 통제 용어

| 용어 | 뜻 | 질문 |
|---|---|---|
| 식별 | 사용자가 자신이 누구라고 밝힌다 | 누구인가 |
| 인증(Authentication) | 그 주장을 증명한다 | 정말 그 사람인가 |
| 인가(Authorization) | 허용된 작업만 하게 한다 | 이 작업을 해도 되는가 |
| 감사(Accounting) | 행위를 기록한다 | 누가 언제 무엇을 했는가 |

### 2.3 설계 원칙

| 원칙 | 내용 |
|---|---|
| 최소 권한 | 업무에 필요한 최소한의 권한만 준다 |
| 심층 방어 | 방어 계층을 여러 겹 두어 한 계층이 뚫려도 막는다 |
| 기본 거부 | 명시적으로 허용하지 않은 것은 막는다 |
| 직무 분리 | 중요한 작업을 한 사람이 혼자 끝내지 못하게 나눈다 |
| 공격 표면 축소 | 불필요한 서비스, 포트, 기능을 끈다 |
| 실패 시 안전 | 오류가 나면 열리는 대신 닫히게 한다 |

## 3. 동작 원리 (위협 모델링)

위협 모델링은 개발·구축 단계에서 어떤 공격이 가능한지 미리 따지는 활동이다. 다음 네 질문을 순서대로 답한다.

1. 무엇을 만들고 있는가. 구성 요소, 데이터 흐름, 신뢰 경계를 그림으로 그린다.
2. 무엇이 잘못될 수 있는가. 아래 STRIDE로 점검한다.
3. 어떻게 대응할 것인가. 완화, 수용, 회피, 전가 중에서 고른다.
4. 충분히 잘했는가. 대응이 적용되었는지 점검한다.

STRIDE는 위협을 여섯 종류로 나눈 분류다.

| 위협 | 뜻 | 침해되는 속성 | 대표 대응 |
|---|---|---|---|
| Spoofing | 다른 사람이나 시스템인 척한다 | 인증 | 강한 인증, 다중 인증 |
| Tampering | 데이터나 코드를 변조한다 | 무결성 | 서명, 무결성 검사, 접근 통제 |
| Repudiation | 한 행위를 부인한다 | 부인 방지 | 감사 로그, 서명 |
| Information disclosure | 정보가 노출된다 | 기밀성 | 암호화, 접근 통제 |
| Denial of service | 서비스를 못 쓰게 한다 | 가용성 | 속도 제한, 이중화 |
| Elevation of privilege | 허용되지 않은 권한을 얻는다 | 인가 | 최소 권한, 입력 검증 |

OWASP Top 10의 [A04 Insecure Design](../../../owasp-top10/owasp.md)은 설계 단계의 결함이며 위협 모델링이 대표 대책이다.

## 4. 약어와 용어

| 용어 | 뜻 |
|---|---|
| CIA | Confidentiality, Integrity, Availability |
| STRIDE | 위협 여섯 종류의 머리글자 |
| 신뢰 경계 | 데이터가 신뢰 수준이 다른 영역으로 넘어가는 지점 |
| 공격 표면 | 공격자가 접근할 수 있는 모든 진입점 |
