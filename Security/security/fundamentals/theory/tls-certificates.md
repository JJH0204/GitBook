## 1. 목적

TLS(Transport Layer Security)는 네트워크 위에서 기밀성, 무결성, 상대 인증을 제공하는 프로토콜이다. 이 페이지는 핸드셰이크의 큰 흐름, 인증서가 검증되는 원리, 흔한 설정 실수를 정리한다. 관련 개념은 [공개키 암호 시스템](publickeysystem.md)과 [해시 함수와 무결성](hash-integrity.md)에 있다.

## 2. 구성 요소

| 요소 | 역할 |
|---|---|
| 서버 인증서 | 도메인 이름과 공개키를 묶고 인증 기관(CA)이 서명한 문서 |
| 인증 기관(CA) | 인증서에 서명하는 신뢰 주체 |
| 루트 인증서 | 운영체제·브라우저에 미리 신뢰 목록으로 들어 있는 최상위 인증서 |
| 중간 인증서 | 루트와 서버 인증서 사이의 서명 단계 |
| 개인키 | 서버만 가진 비밀 값. 유출되면 인증서를 폐기해야 한다 |
| 세션 키 | 핸드셰이크로 합의한 대칭키. 실제 데이터 암호화에 쓴다 |

## 3. 동작 원리

1. 클라이언트가 지원하는 TLS 버전과 암호 묶음을 서버에 보낸다.
2. 서버가 인증서 체인을 보낸다.
3. 클라이언트가 인증서를 검증한다(아래 표).
4. 양쪽이 키 교환(현재 주로 ECDHE)으로 세션 키를 합의한다.
5. 이후 데이터는 세션 키로 암호화하고 인증 코드로 변조를 탐지한다.

| 검증 항목 | 실패하면 |
|---|---|
| 체인이 신뢰하는 루트까지 이어지는가 | 알 수 없는 발급자 경고 |
| 서명이 올바른가 | 변조된 인증서로 간주 |
| 유효 기간 안인가 | 만료 경고 |
| 접속 도메인이 인증서의 이름(SAN)과 일치하는가 | 이름 불일치 경고 |
| 폐기(CRL, OCSP)되지 않았는가 | 폐기된 인증서 경고 |

ECDHE처럼 임시 키를 쓰는 키 교환은 서버 개인키가 나중에 유출되어도 과거 통신을 복호화하지 못하게 한다(전방 비밀성).

## 4. 인증서 내용 확인

인증서 파일은 OpenSSL로 읽을 수 있다. 아래는 실습용 자체 서명 인증서 예다.

```bash
openssl x509 -in <인증서 파일> -noout -subject -issuer -dates -fingerprint -sha256
```

→ 결과: `subject`, `issuer`, `notBefore`, `notAfter`, SHA-256 지문이 출력된다. 자체 서명 인증서는 subject와 issuer가 같다.

## 5. 흔한 설정 실수와 방어

| 실수 | 위험 | 방어 |
|---|---|---|
| 인증서 검증을 끄는 코드(검증 생략 옵션) | 중간자 공격에 노출 | 운영 코드에서 검증 생략 옵션을 쓰지 않는다 |
| 오래된 프로토콜(SSL, TLS 1.0, 1.1) 허용 | 알려진 약점 | TLS 1.2 이상만 허용한다 |
| 만료 방치 | 서비스 중단 | 만료 30일 전 알림과 자동 갱신을 둔다 |
| 개인키를 저장소·공유 폴더에 둔다 | 서버 사칭 | 권한을 제한하고 유출 시 즉시 재발급·폐기한다 |
| HTTP에서 HTTPS 전환 누락 | 평문 노출 | 리다이렉트와 HSTS 헤더를 쓴다 |

## 6. 로그와 탐지

- 인증서 만료일 점검을 정기 작업으로 둔다.
- 서버 로그에서 핸드셰이크 실패 급증은 설정 불일치나 스캔 신호일 수 있다.
- 인증서 투명성(CT) 로그를 감시하면 내 도메인으로 발급된 의도치 않은 인증서를 찾을 수 있다.

## 7. 약어·용어

| 용어 | 뜻 |
|---|---|
| PKI | 공개키 기반 구조. CA, 인증서, 폐기 체계를 묶은 것 |
| SAN | 인증서가 유효한 도메인 이름 목록 |
| HSTS | 브라우저가 항상 HTTPS로만 접속하도록 지시하는 응답 헤더 |
| OCSP | 인증서 폐기 여부를 실시간 조회하는 프로토콜 |
