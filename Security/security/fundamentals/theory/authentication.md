## 1. 목적

인증(authentication)은 "누구인가"를 확인하는 일이고 인가(authorization)는 "무엇을 할 수 있는가"를 정하는 일이다. 인증이 뚫리면 이후 모든 통제가 무의미해진다. 저장 방식은 [패스워드 저장과 해시 방어](password-storage.md), 인가는 [접근 통제 모델](access-control.md)을 본다.

## 2. 구성 요소

### 2.1 인증 요소

| 요소 | 예 | 약점 |
|---|---|---|
| 지식(아는 것) | 비밀번호, PIN | 추측, 재사용, 피싱 |
| 소유(가진 것) | 보안 키, 인증 앱, 스마트 카드 | 분실, 일부 방식은 피싱에 취약 |
| 고유(자신의 것) | 지문, 얼굴 | 변경이 어렵고 오인식이 있다 |

서로 다른 요소를 둘 이상 쓰는 것이 다중 인증(MFA)이다. 비밀번호 두 개는 같은 요소이므로 MFA가 아니다.

### 2.2 MFA 방식 비교

| 방식 | 평가 |
|---|---|
| 문자 메시지 일회용 코드 | 도입이 쉽지만 가로채기와 SIM 교체 위험이 있다 |
| 인증 앱의 시간 기반 코드(TOTP) | 널리 쓰이며 문자보다 낫다. 코드를 가짜 사이트에 입력하는 피싱은 막지 못한다 |
| 푸시 승인 | 반복 요청으로 사용자를 지치게 하는 피로 공격에 주의한다 |
| 보안 키, 패스키(FIDO2/WebAuthn) | 접속 도메인에 묶여 피싱 저항성이 높다 |

## 3. 세션 관리

로그인 성공 후 서버는 세션 식별자를 발급한다. 이 값이 유출되면 비밀번호 없이 사칭이 가능하다.

| 항목 | 방어 |
|---|---|
| 식별자 | 예측할 수 없는 충분히 긴 무작위 값을 쓴다 |
| 쿠키 속성 | `Secure`, `HttpOnly`, `SameSite`를 설정한다 |
| 로그인 직후 | 세션 식별자를 새로 발급한다(세션 고정 방어) |
| 수명 | 유휴·절대 만료를 두고 로그아웃 시 서버에서 폐기한다 |
| 권한 변경 | 비밀번호 변경이나 권한 상승 후 기존 세션을 무효화한다 |

## 4. 흔한 약점과 방어

| 약점 | 방어 |
|---|---|
| 무차별 대입, 비밀번호 대입 | 시도 횟수 제한, 지연, 계정·IP 단위 잠금. [무차별 대입](../../offensive-security/pentest/brute-force/README.md) 참조 |
| 유출된 계정 정보 재사용(크리덴셜 스터핑) | MFA, 유출 비밀번호 목록 대조, 이상 로그인 알림 |
| 약한 비밀번호 | 길이 중심 정책(길수록 좋다)과 흔한 비밀번호 차단. 주기적 강제 변경은 권하지 않는다는 것이 최근 지침의 방향이다(미검증) |
| 계정 존재 노출 | 실패 응답과 복구 응답을 계정 유무와 관계없이 같게 한다 |
| 비밀번호 복구 악용 | 복구 링크는 일회용·단기 만료로 하고 이용 시 알림을 보낸다 |

## 5. 로그에서 보이는 흔적

| 징후 | 해석 |
|---|---|
| 한 계정에 로그인 실패가 짧은 시간에 반복 | 대입 시도 |
| 한 IP가 여러 계정에 한두 번씩 실패 | 스터핑 또는 분무 시도 |
| 평소와 다른 국가·시간대 로그인 성공 | 계정 탈취 의심 |
| MFA 푸시 거절이 반복되다 승인 | 피로 공격 의심 |

## 6. 약어·용어

| 용어 | 뜻 |
|---|---|
| MFA | 다중 인증 |
| TOTP | 시간 기반 일회용 비밀번호 |
| FIDO2/WebAuthn | 공개키 기반의 피싱 저항 인증 표준 |
| 크리덴셜 스터핑 | 다른 곳에서 유출된 계정 정보를 대입하는 공격 |
