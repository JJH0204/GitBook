| 항목 | 내용 |
|---|---|
| Task ID | SEC-FND-010-DO |

| 목적 | 접근 통제의 대표 모델(DAC, MAC, RBAC, ABAC)과 설계 원칙을 이해한다 |
| 적용 대상 | 권한 설계와 점검을 하는 사람 |

## 1. 목적

접근 통제는 "누가(주체) 무엇에(객체) 어떤 행위(권한)를 할 수 있는가"를 정하고 강제하는 일이다. 인증이 끝난 뒤 인가 단계에서 쓴다. 원칙은 [보안 기본 원칙과 위협 모델링](security-principles.md), Windows의 구현은 [DACL](../../offensive-security/system/dacl.md)을 본다.

## 2. 구성 요소

| 용어 | 뜻 |
|---|---|
| 주체 | 사용자, 프로세스, 서비스 |
| 객체 | 파일, 데이터, API 같은 보호 대상 |
| 권한 | 읽기, 쓰기, 실행, 삭제 등 행위 |
| 정책 | 주체와 객체와 권한을 연결하는 규칙 |

## 3. 모델 비교

| 모델 | 결정 주체 | 특징 | 예 |
|---|---|---|---|
| DAC (임의 접근 통제) | 객체 소유자 | 유연하지만 소유자 실수에 취약하다 | Linux 파일 권한, Windows DACL |
| MAC (강제 접근 통제) | 시스템 정책 | 소유자도 못 바꾼다. 엄격하다 | SELinux, 등급 기반 체계 |
| RBAC (역할 기반) | 역할 부여 | 사용자에게 역할을 주고 역할에 권한을 묶는다. 관리가 쉽다 | 클라우드·기업 시스템의 역할 |
| ABAC (속성 기반) | 속성 조건 | 사용자·자원·환경 속성으로 판단한다. 세밀하지만 복잡하다 | 부서와 시간대 조건 정책 |

## 4. 설계 원칙

1. 최소 권한: 업무에 필요한 최소한만 부여한다.
2. 기본 거부: 명시적으로 허용되지 않은 것은 거부한다.
3. 직무 분리: 한 사람이 승인과 실행을 모두 하지 못하게 한다.
4. 모든 요청을 서버에서 검사한다. 화면에서 버튼을 숨기는 것은 통제가 아니다.

## 5. 흔한 약점과 방어

| 약점 | 설명 | 방어 |
|---|---|---|
| 취약한 접근 통제(IDOR 등) | 객체 번호만 바꿔 남의 자료를 본다 | 요청마다 소유권·권한을 서버에서 확인한다. [OWASP Top 10](../../../owasp-top10/owasp.md) 참조 |
| 권한 상승 | 낮은 권한으로 높은 권한 기능에 접근한다 | 기능별 권한 검사, 관리 기능 분리 |
| 권한 누적 | 부서 이동 후에도 옛 권한이 남는다 | 정기 권한 재검토 |
| 과도한 서비스 계정 | 관리자 권한으로 도는 서비스 | 서비스별 전용 계정과 최소 권한 |

## 6. 로그에서 보이는 흔적

- 한 계정이 짧은 시간에 연속된 객체 번호를 조회하며 403·404가 섞인다.
- 평소 쓰지 않던 관리 기능 호출이 일반 계정에서 나타난다.
- 권한 변경, 역할 부여 이벤트가 승인 기록 없이 발생한다.

## 7. 약어·용어

| 용어 | 뜻 |
|---|---|
| 최소 권한 | 필요한 만큼만 권한을 주는 원칙 |
| IDOR | 객체 참조를 바꿔 권한 없는 객체에 접근하는 결함 |
| 직무 분리 | 중요 작업을 둘 이상의 주체로 나누는 통제 |
