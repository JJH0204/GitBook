## 1. 목적

클라우드 보안은 사용자 환경(네트워크, 접근 권한, 데이터, 로그)을 사용자가 직접 설계해 보호하는 일이다. 중요한 서비스(DB 등)를 외부에서 접근할 수 없는 사설 공간에 두고, 방화벽으로 통신을 제한하며, 로그와 탐지 서비스로 이상을 확인하는 것이 핵심이다.

## 2. 구성 요소

### 2.1 공유 책임 모델

| 구분 | AWS 책임 | 사용자 책임 |
|---|---|---|
| 범위 | 클라우드 자체의 보안(데이터센터, 하드웨어, 하이퍼바이저) | 클라우드 안의 보안(IAM 권한, 네트워크 설정, 데이터 암호화, OS·애플리케이션 패치) |

### 2.2 네트워크 격리

| 구성 요소 | 역할 | 원본 메모 |
|---|---|---|
| VPC (Virtual Private Cloud) | 사용자 전용 가상 네트워크 | 어느 네트워크에 연결할지 서브넷을 추가해 IP 대역을 정한다 |
| 퍼블릭 서브넷 | 인터넷과 통신할 수 있는 서브넷 | 웹 서버(EC2)를 둔다 |
| 프라이빗 서브넷 | 외부에서 접근할 수 없는 서브넷(사설 IP) | RDS(MySQL) 같은 중요한 서비스를 둔다 |
| 라우팅 테이블 | 서브넷의 트래픽 경로 | 서브넷을 만들면 기존 서브넷과 통신하도록 라우팅 테이블을 설정해야 한다 |
| 인터넷 게이트웨이, NAT 게이트웨이 | 인터넷 연결 통로 | 원본 그림의 "Routing Gateway NAT". 프라이빗 서브넷이 외부로 나갈 때 NAT를 쓴다 |
| IAM | 사용자·서비스의 접근 권한 관리 | 원본 그림의 부서별(교무, 운영, 사업) 구분에 권한을 나눠 부여한다 |

원본 그림의 구성: 외부 사용자는 퍼블릭 영역의 웹 서버(EC2)에 접근하고, 프라이빗 영역의 RDS와 S3(저장소)는 외부 접근을 허용하지 않는다.

### 2.3 방화벽

| 구성 요소 | 특징 |
|---|---|
| 네트워크 ACL | VPC·서브넷 단위의 방화벽. 규칙은 번호가 작은 것부터 평가하고 처음 일치한 규칙을 적용한다. 허용과 거부 규칙을 둘 수 있다. 상태를 저장하지 않는다(stateless) |
| 보안 그룹 | 인스턴스 단위의 방화벽. 허용 규칙만 있다. 상태를 저장한다(stateful) |
| AWS WAF | 웹 요청(HTTP)을 검사하는 웹 방화벽. 특정 국가에서 오는 요청의 차단 규칙을 만들 수 있다(추정: 원본의 "특정 국가 필터링") |
| AWS Network Firewall | VPC용 관리형 방화벽(추정: 원본의 "정책 당 100$" 비용 항목) |

{% hint style="warning" %}
CAUTION: 원본의 "작성된 순서로 acl 정책 적용"은 네트워크 ACL에서는 "규칙 번호 순서"로 정정했다. 원본의 "(삭제/거부/알림) 순서"와 "정책 당 100$"는 근거를 확인하지 못해 해석하지 않았다.
{% endhint %}

### 2.4 로깅·탐지

| 원본 메모 | 대응 서비스(추정) | 기능 |
|---|---|---|
| 로그 관리 서비스, 실시간 로그 확인, 특정 패턴만 확인 | Amazon CloudWatch Logs | 로그를 수집하고 패턴(필터)으로 찾는다. 조건에 맞으면 경고(알람)를 보내고 대시보드로 지표를 본다 |
| 데이터의 이동을 관찰하고 기록 | VPC Flow Logs | VPC의 네트워크 트래픽 메타데이터를 기록한다 |
| 탐지 활성화, 탐지 빈도·그룹 설정 | Amazon GuardDuty | 로그를 분석해 위협을 탐지한다 |
| 이미 알려진 취약점·공격 패턴을 지속 점검 | Amazon Inspector | 인스턴스·컨테이너의 알려진 취약점을 점검한다 |
| 트랜잭션, X-Ray(원본에 물음표) | AWS X-Ray | 애플리케이션 요청을 추적한다. 보안 서비스라기보다 성능·장애 추적 용도다 |
| 이벤트 발생 빈도·종류를 빠르게 확인 | CloudWatch Logs Insights, CloudTrail(추정) | 원하는 이벤트를 쿼리로 찾는다. CloudTrail은 AWS API 호출 기록이다 |
| 따로 설정하지 않아도 암호화되어 관리됨 | 서비스 확인 필요 | 어느 서비스인지 원본에 없다 |

## 3. 동작 원리

1. 사용자가 VPC를 만들고 퍼블릭·프라이빗 서브넷으로 나눈다.
2. 웹 서버는 퍼블릭 서브넷에, DB는 프라이빗 서브넷에 둔다.
3. 라우팅 테이블로 서브넷 간 통신 경로를 정하고, 프라이빗 서브넷의 외부 접근은 NAT로 제한한다.
4. 네트워크 ACL, 보안 그룹, WAF로 허용할 트래픽만 통과시킨다.
5. IAM으로 사용자·서비스별 권한을 최소로 부여한다.
6. 로그를 수집하고 탐지 서비스로 이상을 확인해 경고를 받는다.

## 4. 약어·용어

| 용어 | 뜻 |
|---|---|

| S3 | 객체 저장소 서비스 |

| WAF | Web Application Firewall |
| IAM | Identity and Access Management |
