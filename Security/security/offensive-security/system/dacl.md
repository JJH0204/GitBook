# [생성형 AI] DACL (Windows 접근 통제 목록)

## 작업 식별

| 항목 | 내용 |
|---|---|
| Task ID | SEC-OFS-008-DO |
| 작성 | 생성형 AI 초안 (사람 검토 전) |
| 유형 | D&O (개념) |
| 목적 | Windows가 객체 접근을 허용·거부하는 DACL의 구조와 점검·방어 방법을 이해한다 |
| 적용 대상 | Windows 10/11, Windows Server |
| 확인 상태 | 미검증 (이 환경에서 실행하지 않았다. 명령은 Windows 문서 기준) |
| 개정 | R1 (2026-11-19) |

## 1. 목적

DACL(Discretionary Access Control List)은 Windows 객체(파일, 레지스트리 키, 서비스 등)마다 붙는 접근 통제 목록이다. 잘못된 DACL은 권한 상승과 설정 변조의 통로가 된다. 이 페이지는 개념과 점검, 방어를 다룬다. 일반 모델은 [접근 통제 모델](../../fundamentals/theory/access-control.md)에 있다.

## 2. 구성 요소

| 용어 | 뜻 |
|---|---|
| 보안 설명자 | 소유자, DACL, SACL을 담은 구조 |
| DACL | 누구에게 어떤 접근을 허용·거부하는지 적은 목록 |
| SACL | 어떤 접근을 감사 로그에 남길지 정하는 목록 |
| ACE | DACL을 이루는 한 항목. 주체(SID), 허용·거부, 권한 마스크를 가진다 |
| SID | 사용자·그룹을 식별하는 값 |
| 액세스 토큰 | 로그인한 주체의 SID와 권한 정보를 담은 값 |

## 3. 동작 원리

1. 프로세스가 객체에 접근을 요청한다.
2. 시스템이 프로세스의 액세스 토큰과 객체의 DACL을 비교한다.
3. ACE를 순서대로 평가한다. 거부 ACE가 먼저 오도록 정렬되는 것이 일반 규칙이다.
4. 요청한 권한이 모두 허용되면 접근을 허락한다.
5. DACL이 아예 없으면(null) 모두 허용, 비어 있으면(empty) 모두 거부다.

null DACL은 위험한 설정이므로 점검 대상이다.

## 4. 점검 방법

```
icacls <경로>
```

→ 결과: 경로에 적용된 ACE 목록이 출력된다. `F`는 모든 권한, `M`은 수정, `RX`는 읽기·실행, `(I)`는 상속이다. (미검증)

점검 시 볼 항목은 다음과 같다.

| 점검 | 위험 신호 |
|---|---|
| 일반 사용자(`Users`, `Everyone`)에 쓰기·수정 권한 | 실행 파일, 서비스 경로, 시작 프로그램 폴더에 있으면 권한 상승 경로 |
| 서비스 실행 파일 폴더의 쓰기 권한 | 서비스 계정이 실행하는 파일을 바꿀 수 있다 |
| 소유자 변경 권한 | 소유자는 DACL을 바꿀 수 있다 |

## 5. 방어

1. 최소 권한으로 DACL을 구성하고 `Everyone`에 쓰기를 주지 않는다.
2. 서비스·예약 작업의 실행 파일과 폴더는 관리자만 쓰기 가능하게 한다.
3. 상속을 이해하고 의도치 않은 상속은 끊는다.
4. 중요 객체에는 SACL을 설정해 변경 시도를 감사한다.
5. 권한 점검 도구의 결과를 정기적으로 비교한다.
