## 1. 목적

포너블(pwnable)은 프로그램의 메모리 처리 결함을 찾아 의도하지 않은 동작을 일으키는 분야다. 아래 표로 결함 유형과 그 방어를 연결해 두면 공격 기법보다 원인과 대책을 먼저 이해할 수 있다.

## 2. 구성 요소 (결함 유형과 대응)

| 결함 유형 | 원인 | 주된 방어 | 관련 문서 |
|---|---|---|---|
| 스택·힙 버퍼 오버플로우 | 버퍼 크기를 확인하지 않고 데이터를 복사한다 | 길이 검사, 경계 검사 함수 사용, 카나리, NX, ASLR | [버퍼 오버플로우 (BOF)](bof.md) |
| 포맷 스트링 | 사용자 입력을 출력 서식 문자열로 사용한다 | 서식 문자열을 상수로 고정한다. 컴파일러 경고 활성화 | [포맷 스트링 공격 (FSB)](formatstringattack.md) |
| 해제 후 사용(use-after-free) | 해제한 메모리를 계속 참조한다 | 해제 후 포인터 초기화, 메모리 안전 언어 사용 | 이 저장소에 문서 없음 |
| 정수 오버플로우 | 크기 계산이 범위를 넘어 작은 값이 된다 | 연산 전 범위 검사, 안전한 정수 라이브러리 | 이 저장소에 문서 없음 |

## 3. 동작 원리

포너블 학습은 보통 다음 순서로 진행한다.

1. 프로그램이 어떤 입력을 받고 그 입력이 메모리에 어떻게 놓이는지 읽는다.
2. 입력 크기나 형식을 검사하지 않는 지점을 찾는다.
3. 그 결함이 어떤 보호 기법에 막히거나 우회 가능한지 따진다.
4. 결함의 원인을 코드 수준에서 고치는 방법을 정리한다.

보호 기법의 종류와 확인 방법은 [메모리 보호 기법](memory-protections.md)에 정리했다. 연습은 공개된 워게임 플랫폼과 [워게임 개요](../../../ctf-and-wargame/wargame.md)에서 소개하는 허가된 환경에서만 한다.

## 4. 약어와 용어

| 용어 | 뜻 |
|---|---|
| pwn | 시스템을 장악했다는 속어 |
| NX | 데이터 영역에서 코드를 실행하지 못하게 하는 보호 |
| ASLR | 메모리 배치를 실행마다 무작위로 바꾸는 보호 |
| 카나리 | 스택 오염을 감지하는 보호 값 |
