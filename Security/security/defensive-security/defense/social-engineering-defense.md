## 1. 목적

사회공학(social engineering)은 시스템이 아니라 사람의 신뢰와 긴박감을 이용해 정보나 행동을 얻어 내는 공격이다. 기술적 통제를 우회하므로 사람 대상 방어가 함께 필요하다.

## 2. 구성 요소

### 2.1 유형

| 유형 | 경로 | 특징 |
|---|---|---|
| 피싱 | 이메일 | 다수에게 가짜 링크나 첨부 파일을 보낸다 |
| 스피어 피싱 | 이메일 | 특정인의 정보를 이용해 맞춤형으로 보낸다 |
| 스미싱 | 문자 | 택배·결제 알림으로 가장한다 |
| 비싱 | 전화 | 기관·금융사 직원을 사칭한다 |
| BEC(업무 이메일 사칭) | 이메일 | 임원·거래처를 사칭해 송금이나 정보를 요구한다 |
| 프리텍스팅 | 모든 경로 | 그럴듯한 사연을 만들어 정보를 얻는다 |

### 2.2 공통 징후

| 징후 | 예 |
|---|---|
| 긴박감 | "오늘 안에 확인하지 않으면 계정이 정지된다" |
| 권위 사칭 | 상사, 기관, 고객센터 |
| 평소와 다른 요청 | 비밀번호, 인증 코드, 송금 계좌 변경 요구 |
| 이상한 발신 정보 | 표시 이름은 같지만 실제 주소의 도메인이 다르다 |
| 이상한 링크 | 표시 문구와 실제 도착 주소가 다르다 |

## 3. 개인 방어

1. 메시지 속 링크를 누르지 않고 공식 앱이나 직접 입력한 주소로 접속한다.
2. 인증 코드와 비밀번호는 누구에게도 알려 주지 않는다. 정당한 직원은 묻지 않는다.
3. 계좌 변경·송금 요청은 기존에 알던 연락처로 전화해 확인한다.
4. 첨부 파일은 예상한 것만 열고 실행 파일·매크로 문서는 열지 않는다.
5. 의심되면 눌렀는지와 무관하게 보안 담당자에게 신고한다. 눌렀다면 비밀번호를 바꾸고 MFA를 확인한다.

## 4. 조직 방어

| 통제 | 효과 |
|---|---|
| 이메일 인증(SPF, DKIM, DMARC) | 발신 도메인 위조를 줄인다 |
| 메일 게이트웨이의 링크·첨부 검사 | 악성 링크와 파일을 격리한다 |
| 피싱 저항 MFA(보안 키, 패스키) | 입력한 코드·비밀번호를 가로채도 로그인을 막는다. [인증과 다중 인증](../../fundamentals/theory/authentication.md) 참조 |
| 송금·정보 요청의 별도 확인 절차 | BEC 피해를 막는다 |
| 신고 경로와 정기 교육 | 탐지를 빠르게 한다 |
| 승인된 모의 훈련 | 취약 지점을 측정한다 |

## 5. 로그에서 보이는 흔적

- 메일 헤더의 SPF·DKIM·DMARC 결과가 실패이거나 발신 도메인이 유사 도메인이다.
- 여러 수신자가 같은 링크를 같은 시각에 클릭한다.
- 클릭 직후 평소와 다른 위치·기기에서 로그인이 성공한다.
- 받은편지함 자동 전달·삭제 규칙이 갑자기 생긴다(계정 탈취 후 은폐 징후).

## 6. 약어·용어

| 용어 | 뜻 |
|---|---|
| SPF | 메일을 보낼 수 있는 서버를 도메인이 선언하는 방식 |
| DKIM | 메일에 서명해 변조와 발신을 확인하는 방식 |
| DMARC | SPF·DKIM 실패 시 처리 정책을 도메인이 선언하는 방식 |
| BEC | 업무 이메일 사칭 |
