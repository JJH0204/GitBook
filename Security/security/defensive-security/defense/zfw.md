## 1. 목적

ZFW는 일반 라우터 같은 네트워크 장비를 방화벽처럼 쓰게 해 주는 기능이다. 인터페이스를 존(zone)으로 묶고, 존이 서로 다르면 기본적으로 통신을 차단한 뒤 정책으로 허용할 트래픽만 지정하는 방식으로 구현한다. 방화벽 장치 일반은 [방화벽 장치 유형](../../../../Network/security/firewall.md) (NET-NSC-005-DO)을 따른다.

## 2. 구성 요소

| 순서 | 원본 단계 | 하는 일 | Cisco IOS 명령 대응 (일반 지식) |
|---|---|---|---|
| 1 | 존 생성 | 보안 영역을 만들고 인터페이스를 넣는다 | `zone security <존 이름>`, 인터페이스의 `zone-member security <존 이름>` |
| 2 | 트래픽 방향 설정 | 어느 존에서 어느 존으로 가는 트래픽인지 정한다 | `zone-pair security <이름> source <존> destination <존>` |
| 3 | 트래픽 분류 지정 | 포트, 프로토콜, IP 등으로 트래픽을 분류한다 | `class-map type inspect`, `match protocol`, `match access-group` |
| 4 | 정책 설정 | 분류된 트래픽에 허용(inspect, pass)·차단(drop) 동작을 지정한다 | `policy-map type inspect` |
| 5 | 정책 적용 | 정책을 존 쌍에 적용한다 | `service-policy type inspect <정책 이름>` |

## 3. 동작 원리

1. 같은 존 안의 인터페이스끼리는 통신이 허용된다.
2. 다른 존으로 가는 트래픽은 존 쌍(zone-pair)에 정책이 없으면 차단된다.
3. 존 쌍에 적용한 정책이 트래픽을 분류하고 동작(`inspect`, `pass`, `drop`)을 적용한다.
4. `inspect` 동작은 연결 상태를 기록해 돌아오는 응답을 자동으로 허용한다.

{% hint style="warning" %}
CAUTION: 존에 인터페이스를 넣는 순간 다른 존과의 통신이 차단된다. 원격 관리 접속(SSH)에 쓰는 인터페이스를 존에 넣기 전에 관리 트래픽을 허용하는 정책을 준비하고 콘솔 접근을 확보한다.
{% endhint %}

## 4. 약어와 용어

| 용어 | 뜻 |
|---|---|
| ZFW / ZBF | Zone-Based (Policy) Firewall |
| 존(zone) | 같은 보안 수준으로 묶은 인터페이스 그룹 |
| 존 쌍(zone-pair) | 출발 존과 도착 존의 한 방향 조합 |
| inspect | 연결 상태를 추적하며 허용하는 동작 |
