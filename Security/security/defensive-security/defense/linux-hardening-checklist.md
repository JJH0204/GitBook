## 1. 점검 항목

| # | 영역 | 점검 | 확인 방법(예) | 합격 기준 |
|---|---|---|---|---|
| 1 | 패치 | 보안 업데이트가 적용되어 있다 | 배포판 패키지 관리자의 업데이트 목록 | 보안 업데이트 대기 0건 |
| 2 | 계정 | 불필요한 계정과 빈 비밀번호가 없다 | `/etc/passwd`, `/etc/shadow` 검토 | 빈 비밀번호 0개 |
| 3 | 계정 | 관리자 권한을 가진 계정이 최소다 | `sudo` 그룹과 `/etc/sudoers` 검토 | 업무상 필요한 계정만 |
| 4 | SSH | 루트 직접 로그인을 막았다 | `sshd_config`의 `PermitRootLogin` | `no` |
| 5 | SSH | 비밀번호 대신 키 인증을 쓴다 | `sshd_config`의 `PasswordAuthentication` | `no` (키 등록 후) |
| 6 | 서비스 | 불필요한 서비스가 꺼져 있다 | `ss -tulpn`으로 열린 포트 확인 | 용도를 설명할 수 없는 열린 포트 0개 |
| 7 | 방화벽 | 필요한 포트만 허용한다 | 호스트 방화벽 규칙 목록 | 기본 차단, 필요한 것만 허용 |
| 8 | 권한 | 중요 파일 권한이 적절하다 | `ls -l /etc/shadow` | 일반 사용자 읽기 불가 |
| 9 | 권한 | 모든 사용자가 쓸 수 있는 파일이 최소다 | 쓰기 권한이 전체에 열린 파일 검색 | 의도한 것(임시 폴더 등) 외 0개 |
| 10 | 권한 | SUID 파일이 알려진 목록과 같다 | SUID 파일 목록을 기준선과 비교 | 기준선에 없는 항목 0개 |
| 11 | 로그 | 인증·시스템 로그가 중앙 서버로 전송된다 | 로그 전송 설정 | 전송 확인. [보안 로깅 설계](security-logging-design.md) 참조 |
| 12 | 시간 | 시간 동기화가 켜져 있다 | `timedatectl` | 동기화 활성 |
| 13 | 무결성 | 파일 변경 감시가 있다 | [HIDS](hids.md) 또는 유사 도구 | 중요 경로 감시 중 |
| 14 | 접근 통제 | 필수 접근 통제 모듈(SELinux, AppArmor)이 켜져 있다 | 해당 모듈 상태 명령 | 강제(enforcing) 모드 |
| 15 | 백업 | 복원 시험을 했다 | 시험 기록 | 최근 시험 기록 존재. [백업과 랜섬웨어 방어](backup-ransomware-defense.md) 참조 |

## 2. 항목별 해설

- 4, 5번: SSH는 인터넷에서 가장 많이 시도되는 대입 대상이다. 키 인증과 루트 로그인 차단이 [무차별 대입](../../offensive-security/pentest/brute-force/README.md)에 대한 기본 방어다. 변경 후 `sshd_config` 문법을 검사하고 재시작하며, 기존 세션을 닫기 전에 새 세션을 확인한다.
- 6번: 열린 포트 목록은 가장 값싼 점검이다. 공격 표면을 줄이는 일이다([보안 기본 원칙](../../fundamentals/theory/security-principles.md)).
- 10번: SUID 파일은 소유자 권한으로 실행되므로 권한 상승 경로가 될 수 있다. 목록 비교로 새 항목을 찾는다.
- 14번: 접근 통제 모듈은 서비스가 침해되어도 접근 범위를 제한한다.

## 3. 로그에서 보이는 흔적

| 징후 | 해석 |
|---|---|
| 인증 로그에 같은 출발지의 실패가 반복 | 대입 시도 |
| 새로운 계정 생성, `sudoers` 변경 | 권한 변경. 승인 기록과 대조한다 |
| 기준선에 없는 SUID 파일 | 변조 또는 권한 상승 준비 |
| 예상 밖의 새 열린 포트 | 미승인 서비스 또는 백도어 의심 |

침해가 의심되면 [Linux 침해 분석 아티팩트](linuxintrusionanalysis.md)를 따른다.
