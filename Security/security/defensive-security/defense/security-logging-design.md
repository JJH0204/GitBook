# [생성형 AI] 보안 로깅 설계

## 작업 식별

| 항목 | 내용 |
|---|---|
| Task ID | SEC-DEF-019-DO |
| 작성 | 생성형 AI 초안 (사람 검토 전) |

| 목적 | 탐지와 사고 분석에 쓸 수 있도록 무엇을, 어떻게 기록하고 보관할지 설계 기준을 이해한다 |
| 적용 대상 | 서비스와 서버의 로그를 설계·운영하는 사람 |

## 1. 목적

로그는 [SIEM](siem.md), [IDS](ids.md), [침해사고 분석](securityincidentanalysisresponse.md)의 원료다. 기록하지 않은 사건은 탐지도 분석도 할 수 없다. 이 페이지는 도구 설치가 아니라 기록 대상과 품질 기준을 다룬다.

## 2. 무엇을 기록할까

| 영역 | 기록 대상 | 목적 |
|---|---|---|
| 인증 | 로그인 성공·실패, 로그아웃, MFA 결과, 비밀번호 변경·복구 | 탈취·대입 탐지 |
| 인가 | 접근 거부, 권한·역할 변경, 관리 기능 사용 | 권한 오남용 탐지 |
| 입력 검증 | 검증 실패, 차단된 요청 | 공격 시도 탐지 |
| 데이터 | 민감 데이터 조회·내보내기·삭제 | 유출 추적 |
| 시스템 | 서비스 시작·중지, 설정 변경, 프로세스 생성, 오류 | 변조·이상 동작 탐지 |
| 네트워크 | 방화벽·프록시 허용·차단, DNS 질의 | 이상 통신 탐지 |

## 3. 각 기록에 담을 항목

| 항목 | 이유 |
|---|---|
| 시각(표준 시간대 명시) | 여러 장비 로그를 이어 보려면 필요하다 |
| 주체(계정, 출발지 주소) | 누가 했는지 |
| 대상(자원, 요청 경로) | 무엇에 했는지 |
| 행위와 결과(성공·실패, 응답 코드) | 어떤 일이 있었는지 |
| 요청을 잇는 식별자 | 여러 서비스에 걸친 흐름을 추적한다 |

## 4. 기록하지 말 것

| 항목 | 이유 |
|---|---|
| 비밀번호, 토큰, 세션 값, 키 | 로그 유출이 곧 계정 유출이 된다 |
| 주민등록번호, 카드번호 등 개인정보 원문 | 법적 책임과 유출 위험. 마스킹하거나 해시한다 |
| 사용자 입력 원문을 그대로 | 로그 위조(줄바꿈 삽입)의 통로가 된다. 이스케이프한다 |

## 5. 운영 기준

1. 시간 동기화: 모든 장비가 같은 시간 원천을 쓰게 한다.
2. 중앙 수집: 로그를 별도 서버로 전송한다. 침입자는 로컬 로그를 지울 수 있다.
3. 접근 통제: 로그를 읽고 지우는 권한을 분리한다.
4. 무결성: 전송 구간을 암호화하고 보관본의 변조를 점검한다. [해시 함수와 무결성](../../fundamentals/theory/hash-integrity.md) 참조.
5. 보관 기간: 법규와 조사 필요를 기준으로 정한다. 이 문서는 기간 값을 정하지 않는다.
6. 용량과 유실: 디스크가 차면 기록이 멈추지 않는지, 수집이 끊기면 알림이 가는지 점검한다.
7. 경보 연결: 기록만 하고 보지 않으면 소용없다. 핵심 사건은 경보 규칙과 연결한다.

## 6. 흔한 실수

| 실수 | 방어 |
|---|---|
| 성공만 기록하고 실패는 기록하지 않는다 | 실패와 거부를 반드시 기록한다 |
| 장비마다 시간대·형식이 달라 합치기 어렵다 | 형식과 시간대를 표준화한다 |
| 로그가 한 서버에만 남는다 | 중앙 수집으로 복제한다 |
| 디버그 수준 로그에 비밀 값이 섞인다 | 운영 수준에서 민감 값을 제외한다 |

## 7. 약어·용어

| 용어 | 뜻 |
|---|---|
| 중앙 수집 | 여러 장비의 로그를 한 곳으로 모으는 것 |
| 로그 인젝션 | 사용자 입력으로 가짜 로그 줄을 만드는 공격 |
| 마스킹 | 값 일부를 가려 원문 노출을 막는 처리 |
