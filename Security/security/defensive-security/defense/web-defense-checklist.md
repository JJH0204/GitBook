## 1. 점검 항목

각 항목에서 방어가 적용되어 있으면 합격, 없으면 불합격으로 기록한다.

| 번호 | 취약점 | 방어 조치 | 확인 방법 | 합격 기준 | 실습 문서 |
|---|---|---|---|---|---|
| 1 | SQL 인젝션 | 매개변수화된 질의(prepared statement)를 쓴다. DB 계정은 필요한 권한만 갖는다 | 코드에서 문자열을 이어 붙여 만든 질의를 찾는다 | 사용자 입력이 질의 문자열에 직접 들어가지 않는다 | [SQL 인젝션 (DVWA)](../../../dvwa/sql-injection.md) |
| 2 | XSS | 출력 위치(HTML, 속성, 스크립트)에 맞게 출력 인코딩한다. CSP를 설정한다 | 입력이 화면에 출력되는 모든 위치의 인코딩 여부를 확인한다 | 사용자 입력이 인코딩 없이 출력되지 않는다 | [XSS (DVWA)](../../../dvwa/xss.md) |
| 3 | CSRF | 요청 위조 방지 토큰과 `SameSite` 쿠키를 쓴다. 중요 작업은 재인증을 요구한다 | 상태 변경 요청에 토큰 검증이 있는지 확인한다 | 토큰 없는 상태 변경 요청이 거절된다 | [CSRF (DVWA)](../../../dvwa/csrf.md) |
| 4 | 커맨드 인젝션 | 셸을 호출하지 않는다. 불가피하면 인자를 배열로 전달하고 허용 목록으로 검증한다 | 코드에서 셸 호출 함수와 입력 연결 여부를 찾는다 | 사용자 입력이 셸 명령 문자열에 들어가지 않는다 | [커맨드 인젝션 (DVWA)](../../../dvwa/command_injection.md) |
| 5 | 파일 업로드 | 확장자와 내용 형식을 허용 목록으로 검사한다. 업로드 파일을 웹 루트 밖에 두고 이름을 새로 정한다. 실행 권한을 주지 않는다 | 업로드 저장 위치와 실행 설정을 확인한다 | 업로드 파일이 서버에서 실행되지 않는다 | [파일 업로드 (DVWA)](../../../dvwa/file_upload.md) |
| 6 | 파일 인클루전 | 사용자 입력으로 파일 경로를 정하지 않는다. 불가피하면 허용 목록을 쓴다. 원격 인클루전 설정은 끈다 | 파일 포함 함수의 인자 출처를 확인한다 | 경로가 허용 목록에서만 선택된다 | [파일 인클루전 (DVWA)](../../../dvwa/file_inclusion.md) |
| 7 | 객체 직접 참조(IDOR) | 모든 요청에서 서버가 소유권과 권한을 검사한다 | 다른 사용자의 식별자를 쓴 요청이 거절되는지 허가받은 테스트 계정 둘로 확인한다 | 소유하지 않은 객체 요청이 거절된다 | [A4 IDOR (bWAPP)](../../../bwapp/a4-insecure_dor.md) |
| 8 | 세션 관리 | 쿠키에 `Secure`, `HttpOnly`, `SameSite`를 설정한다. 로그인 시 세션 식별자를 새로 발급한다. 만료 시간을 둔다 | 응답 헤더의 `Set-Cookie`를 확인한다 | 세 속성이 모두 있고 로그인 후 식별자가 바뀐다 | [OWASP Top 10](../../../owasp-top10/owasp.md) A07 |
| 9 | 전송 보안 | 전 구간 HTTPS와 HSTS를 쓴다 | 응답 헤더에서 `Strict-Transport-Security`를 확인한다 | HTTP 요청이 HTTPS로 넘어간다 | |
| 10 | 오류 처리 | 상세 오류와 스택 추적을 사용자에게 보이지 않는다. 서버 로그에만 남긴다 | 잘못된 요청의 응답 내용을 확인한다 | 내부 경로나 질의가 응답에 나오지 않는다 | |
| 11 | 로깅 | 로그인 실패, 권한 오류, 입력 검증 실패를 기록하고 알린다 | 로그에서 해당 이벤트가 보이는지 확인한다 | 이벤트가 기록되고 알림이 간다 | [SIEM](siem.md) |

## 2. 보완 통제

| 통제 | 역할 | 참조 |
|---|---|---|
| WAF | 알려진 공격 패턴을 앞단에서 차단한다. 코드 수정을 대신하지 못한다 | [WAF](waf.md) |
| 로그 수집과 탐지 | 공격 시도의 흔적을 모은다 | [Wazuh](wazuh.md), [IDS](ids.md) |
| 구성 요소 업데이트 | 알려진 취약점이 있는 라이브러리를 제거한다 | [CVE](../../offensive-security/pentest/cve/README.md) |

{% hint style="info" %}
NOTE: 입력 검증(허용 목록)은 모든 항목의 보조 수단이다. 주 방어는 위 표의 구조적 조치(매개변수화, 출력 인코딩, 서버 측 권한 검사)다.
{% endhint %}

## 3. 약어와 용어

| 용어 | 뜻 |
|---|---|
| CSP | Content Security Policy. 브라우저가 불러올 수 있는 자원 출처를 제한하는 정책 |
| HSTS | HTTP Strict Transport Security. 브라우저가 HTTPS만 쓰게 하는 헤더 |
| IDOR | Insecure Direct Object Reference |
| 허용 목록 | 허용할 값만 나열하고 나머지는 거절하는 방식 |
