# Snort 룰 문법 (Snort Rule)

## 작업 식별

| 항목 | 내용 |
|---|---|
| Task ID | SEC-DEF-004-REF |
| 유형 | REF (참조) |
| 목적 | Snort 룰의 헤더(action, protocol, 주소·포트, 방향)와 주요 옵션을 찾아본다 |
| 확인 상태 | 미검증 (원본 목록과 Snort 룰 문법 지식을 정리한 것이며 이 환경에서 실행해 확인하지 않았다) |
| 개정 | R1 (2026-11-18) |

{% hint style="info" %}
NOTE: 룰 형식은 `action protocol 출발지주소 출발지포트 방향 목적지주소 목적지포트 (옵션; 옵션;)`이다. Suricata도 같은 형식을 쓴다(SEC-DEF-006-MP).
{% endhint %}

## 1. 참조

| 참조 문서 | Task ID | 제목 |
|---|---|---|
| [Snort 설치 및 침입 탐지 구축](snort.md) | SEC-DEF-005-MP | 룰 파일을 포함하는 방법 |
| [Suricata 설치 및 설정](suricata.md) | SEC-DEF-006-MP | 같은 룰 형식 사용 |

## 2. action

| action | 동작 |
|---|---|
| `alert` | 경고를 기록한다 |
| `log` | 패킷을 기록한다 |
| `pass` | 패킷을 무시한다 |
| `active` | 경고를 기록하고 해당 동적 룰을 켠다 (Snort 2 기준. 확인 필요) |
| `reject` | 패킷을 차단하고 기록하며 상대에게 거부 메시지를 보낸다 |
| `drop` | 패킷을 차단하고 기록한다 |
| `sdrop` | 패킷을 차단하고 기록하지 않는다 |

{% hint style="warning" %}
CAUTION: `reject`, `drop`, `sdrop`은 IPS(인라인) 모드에서만 실제로 차단한다. 인라인 모드에서 오탐이 있는 룰은 정상 통신을 끊는다. 새 룰은 `alert`로 먼저 시험한다.
{% endhint %}

## 3. protocol

| 값 | 뜻 |
|---|---|
| `tcp`, `udp`, `icmp` | 해당 프로토콜 패킷 |
| `ip` | 모든 IP 패킷 |
| `any` | 모든 프로토콜 (Snort 3에서의 허용 여부는 확인 필요) |

## 4. 주소와 포트

| 표기 | 뜻 |
|---|---|
| `any` | 모든 주소 또는 모든 포트 |
| `192.168.100.0/24` | 네트워크 대역 |
| `[192.168.100.0/24,192.168.200.0/24]` | 둘 이상의 주소 |
| `10:20` | 10번에서 20번 포트 (원본은 `10-20`으로 적었으나 Snort 룰은 `:` 범위 표기를 쓴다. 확인 필요) |
| `:10` | 10번 포트 이하 |
| `10:` | 10번 포트 이상 |
| `!10` | 10번을 제외한 모든 포트 |
| `$HOME_NET`, `$EXTERNAL_NET` | 설정 파일에 정의한 변수 |

## 5. 방향

| 표기 | 뜻 |
|---|---|
| `->` | 출발지에서 목적지로 가는 트래픽 |
| `<>` | 양방향 트래픽 |

## 6. 주요 옵션

| 옵션 | 뜻 |
|---|---|
| `msg` | 탐지 시 출력할 메시지 |
| `sid` | 룰의 고유 번호. 중복할 수 없다. 사용자 정의 룰은 1,000,000 이상을 쓴다 |
| `rev` | 룰의 개정 번호. 룰을 고칠 때 사람이 1 올린다 (원본의 "자동으로 1 증가"는 정정했다) |
| `content` | 패킷 안의 문자열을 검사한다. 웹 공격 패턴 탐지에 쓴다 |
| `nocase` | `content`의 대소문자를 구분하지 않는다 |

## 7. 사용 예

```
alert icmp any any -> $HOME_NET any (msg:"icmp msg"; sid:1000001; rev:1;)
```

→ 의미: 모든 출발지에서 `$HOME_NET`으로 가는 ICMP 패킷을 경고로 기록한다. 이 룰은 원본 [Snort](snort.md) 문서의 예시다.
