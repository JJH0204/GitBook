## 1. 목적

랜섬웨어는 파일을 암호화하거나 훔친 뒤 대가를 요구하는 악성코드다. 이 페이지는 샘플 분석이나 제작이 아니라 피해를 줄이는 방어를 다룬다. 복구 수단이 확실하면 협상 압박이 줄어든다.

## 2. 피해 구조

| 단계 | 일어나는 일 |
|---|---|
| 침투 | 피싱 첨부, 노출된 원격 접속, 미패치 취약점, 탈취된 계정 |
| 확산 | 권한 상승 후 공유 폴더와 다른 서버로 퍼진다 |
| 영향 | 파일 암호화, 백업 삭제 시도, 자료 유출 후 공개 협박 |
| 요구 | 복호화·비공개 대가를 요구한다 |

## 4. 백업 원칙

대표 기준은 3-2-1이다.

| 숫자 | 뜻 |
|---|---|
| 3 | 데이터 사본을 3개 둔다(원본 포함) |
| 2 | 서로 다른 매체 2종에 둔다 |
| 1 | 1개는 떨어진 곳(오프사이트)에 둔다 |

추가로 다음을 지킨다.

1. 백업 한 벌은 오프라인이거나 변경 불가(불변) 설정으로 둔다. 공격자가 백업을 먼저 지우려 한다.
2. 백업 서버의 계정은 일반 운영 계정과 분리한다.
3. 복원 시험을 정기적으로 한다. 복원해 보지 않은 백업은 있는 것으로 보지 않는다.
4. 복구 목표(어느 시점까지, 얼마 안에)를 정해 둔다.

## 5. 탐지 징후

| 징후 | 해석 |
|---|---|
| 짧은 시간에 많은 파일의 이름·확장자가 바뀐다 | 대량 암호화 |
| 파일 내용의 무작위성이 갑자기 높아진다 | 암호화된 데이터 |
| 볼륨 섀도 복사본·백업 삭제 시도 | 복구 수단 제거 |
| 보안 도구 중지 시도 | 방어 회피 |
| 대용량 외부 전송 | 이중 협박용 유출 |
| 안내문 파일이 폴더마다 생성된다 | 감염 진행 |

[HIDS](hids.md)의 파일 변경 감시와 [SIEM](siem.md) 상관 규칙으로 대량 변경을 경보할 수 있다.

## 6. 감염 의심 시 대응

{% hint style="danger" %}
WARNING: 감염 장비를 분석할 때 원본 증거를 훼손하지 않는다. 분석용 샘플은 격리된 분석 환경(스냅샷 가능한 VM, 네트워크 차단)에서만 다룬다.
{% endhint %}

1. 감염 장비를 네트워크에서 분리한다. 전원은 증거 보존 방침에 따라 정한다.
2. 다른 장비로 번졌는지 확인하고 의심 계정의 비밀번호를 교체한다.
3. 백업이 안전한지 먼저 확인한 뒤 복구한다. 감염 원인(침투 경로)을 막기 전에 복구하면 재감염된다.
4. 신고와 법적 의무를 확인한다. 흐름은 [침해사고 분석 및 대응 절차](securityincidentanalysisresponse.md)를 따른다.

## 7. 약어·용어

| 용어 | 뜻 |
|---|---|
| 3-2-1 | 사본 3개, 매체 2종, 오프사이트 1개 |
| 불변 백업 | 일정 기간 수정·삭제할 수 없게 한 백업 |
| 이중 협박 | 암호화와 함께 유출 자료 공개를 협박하는 방식 |
| RPO/RTO | 허용 데이터 손실 시점 / 허용 복구 시간 |
