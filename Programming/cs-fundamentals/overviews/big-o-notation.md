## 1. 정의

빅오(Big-O) 표기법은 입력 크기 n이 커질 때 알고리즘의 실행 시간(또는 공간)이 **어떤 비율로 늘어나는지의 상한**을 나타낸다. 정확한 시간이 아니라 증가 추세만 본다. 그래서 다음 규칙으로 식을 단순화한다.

1. 상수 계수를 버린다. `3n`은 O(n)이다.
2. 낮은 차수 항을 버린다. `n^2 + n`은 O(n^2)이다.
3. 입력이 여럿이면 변수를 구분한다. 길이가 n, m인 두 배열을 한 번씩 훑으면 O(n + m)이다.

최선·평균·최악은 입력 구성에 따라 따로 말한다. 최악의 경우를 기본으로 쓰는 경우가 많다. 엄밀히 빅오는 상한이고 하한은 빅오메가(Ω), 상한과 하한이 같으면 빅세타(Θ)다.

## 2. 자주 나오는 증가율

| 표기 | 이름 | 예 |
|---|---|---|
| O(1) | 상수 | 배열 인덱스 접근, 해시 테이블 평균 검색 |
| O(log n) | 로그 | [이진 탐색](../algorithms/binary-search.md), 균형 트리 탐색 |
| O(n) | 선형 | 배열 전체 순회, 선형 탐색 |
| O(n log n) | 선형 로그 | [병합 정렬](../algorithms/merge-sort.md), [힙 정렬](../algorithms/heap-sort.md) |
| O(n^2) | 제곱 | 이중 반복문, [삽입 정렬](../algorithms/insertion-sort.md) 최악 |
| O(2^n) | 지수 | 부분 집합을 모두 만드는 완전 탐색 |
| O(n!) | 팩토리얼 | 모든 순열 나열 |

n이 커질수록 위 순서대로 빠르게 느려진다. 지수·팩토리얼은 n이 수십만 되기 전에 현실적인 시간 안에 끝나지 않는다.

## 3. 예제 코드 (Python)

배열 `[0, 1, ..., n-1]`에서 마지막 값을 찾을 때 비교 횟수와, 이중 반복문의 반복 횟수를 센다.

{% code title="bigo.py" %}
```python
def linear(a, t):
    c = 0
    for x in a:
        c += 1
        if x == t:
            break
    return c

def binary(a, t):
    lo, hi, c = 0, len(a) - 1, 0
    while lo <= hi:
        c += 1
        m = (lo + hi) // 2
        if a[m] == t:
            break
        if a[m] < t:
            lo = m + 1
        else:
            hi = m - 1
    return c

def pairs(n):
    c = 0
    for i in range(n):
        for j in range(n):
            c += 1
    return c

for n in (10, 100, 1000, 10000):
    a = list(range(n))
    print(n, linear(a, n - 1), binary(a, n - 1), pairs(n) if n <= 1000 else "-")
```
{% endcode %}

실행 결과:

```
10 10 4 100
100 100 7 10000
1000 1000 10 1000000
10000 10000 14 -
```

열은 차례로 n, 선형 탐색 비교 횟수, 이진 탐색 비교 횟수, 이중 반복문 반복 횟수다. n이 10배가 될 때 선형은 10배, 이중 반복문은 100배가 되지만 이진 탐색은 3~4회만 늘어난다. 세 열이 각각 O(n), O(log n), O(n^2)의 증가 양상을 보인다. 마지막 줄의 `-`는 반복 횟수가 많아 계산을 생략했다는 표시다.

## 4. 코드에서 복잡도 읽는 법

| 코드 형태 | 복잡도 |
|---|---|
| 반복문 하나가 n번 | O(n) |
| 반복문 안에 반복문(둘 다 n번) | O(n^2) |
| 반복할 때마다 범위가 절반이 됨 | O(log n) |
| 순서대로 이어진 두 반복문(O(n) 뒤에 O(n)) | O(n) (더하고 상수를 버린다) |
| 재귀 호출이 두 번씩 갈라지고 깊이가 n | 대략 O(2^n) |

## 5. 한계와 주의

* 빅오는 증가율이지 실제 속도가 아니다. n이 작으면 계수와 캐시 영향 때문에 O(n^2) 알고리즘이 O(n log n)보다 빠를 수 있다. 삽입 정렬이 작은 배열에서 쓰이는 이유다.
* 평균 복잡도는 입력 분포 가정에 의존한다. 해시 테이블의 평균 O(1)이 그 예다.
* 공간 복잡도도 같은 방식으로 센다. 재귀 호출 깊이가 쓰는 호출 스택도 공간에 포함한다.
* 분할상환(amortized) 복잡도는 연산 여러 번의 평균 비용이다. 동적 배열의 끝 삽입이 분할상환 O(1)인 것이 예다.
