## 1. 정의

선택 정렬은 정렬되지 않은 구간에서 가장 작은(또는 가장 큰) 요소를 골라 그 구간의 맨 앞 요소와 교환하는 과정을 반복하는 비교 기반 정렬이다. 구현이 단순하지만 입력 상태와 관계없이 비교 횟수가 같아 큰 입력에는 쓰지 않는다.

## 2. 동작 원리

`i`번째 반복에서 인덱스 `i` 앞쪽은 이미 정렬돼 있고, `i` 이후가 정렬되지 않은 구간이다.

1. 정렬되지 않은 구간(`i`부터 끝까지)에서 최솟값의 인덱스 `minIdx`를 찾는다.
2. `arr[i]`와 `arr[minIdx]`를 교환한다.
3. `i`를 1 늘리고 1~2를 반복한다.
4. `i`가 `n - 1`에 도달하면 종료한다. 마지막 요소는 비교 없이 제자리에 놓인다.

`{64, 25, 12, 22, 11}`의 진행 과정이다. `|` 왼쪽이 정렬된 구간이다.

| 반복 | 배열 상태 | 선택된 최솟값 | 교환 |
|---|---|---|---|
| 시작 | `64 25 12 22 11` | - | - |
| i=0 | `11 \| 25 12 22 64` | 11 | 64와 11 |
| i=1 | `11 12 \| 25 22 64` | 12 | 25와 12 |
| i=2 | `11 12 22 \| 25 64` | 22 | 25와 22 |
| i=3 | `11 12 22 25 \| 64` | 25 | 자기 자신(이동 없음) |

## 3. 복잡도와 성질

| 항목 | 값 | 비고 |
|---|---|---|
| 시간(최선) | O(n²) | 이미 정렬돼 있어도 비교 횟수가 같다 |
| 시간(평균) | O(n²) | |
| 시간(최악) | O(n²) | |
| 비교 횟수 | n(n−1)/2 | (n−1) + (n−2) + … + 1. 입력과 무관하다 |
| 교환 횟수 | 최대 n−1 | 교환 횟수가 적어 쓰기 비용이 큰 환경에서는 유리할 수 있다 |
| 공간 | O(1) | 제자리(in-place) 정렬 |
| 안정성 | 불안정 | 아래 예시 참조 |

{% hint style="info" %}
NOTE: 선택 정렬은 불안정(unstable) 정렬이다. 값이 같은 요소의 원래 순서가 유지되지 않을 수 있다.
{% endhint %}

불안정한 예시다. 같은 값 5를 구분하려고 `5a`, `5b`로 표기한다.

| 단계 | 배열 |
|---|---|
| 입력 | `5a 5b 2` |
| i=0: 최솟값 2와 `5a` 교환 | `2 5b 5a` |
| i=1: 최솟값 `5b`가 이미 제자리 | `2 5b 5a` |

결과에서 `5b`가 `5a`보다 앞에 놓여 원래 순서가 뒤바뀌었다. 안정 버전은 교환 대신 삽입식으로 요소를 한 칸씩 밀어서 만들 수 있다.

## 4. 예제 코드 (C)

{% code title="selection_sort.c" %}
```c
#include <stdio.h>

void selectionSort(int arr[], int n) {
	int i, j, minIdx, temp;

	for (i = 0; i < n - 1; i++) {
		minIdx = i;

		for (j = i + 1; j < n; j++) {
			if (arr[j] < arr[minIdx]) {
				minIdx = j;
			}
		}

		temp = arr[i];
		arr[i] = arr[minIdx];
		arr[minIdx] = temp;
	}
}

void printArr(int arr[], int n) {
	for (int i = 0; i < n; i++) {
		printf("%d ", arr[i]);
	}
	printf("\n");
}

int main() {
	int arr[] = {64, 25, 12, 22, 11};
	int n = sizeof(arr) / sizeof(arr[0]);

	printf("pre-sort: ");
	printArr(arr, n);

	selectionSort(arr, n);

	printf("post-sort: ");
	printArr(arr, n);
	return 0;
}
```
{% endcode %}

출력 예:

```
pre-sort: 64 25 12 22 11 
post-sort: 11 12 22 25 64 
```

## 5. 코드 설명

| 위치 | 설명 |
|---|---|
| `for (i = 0; i < n - 1; i++)` | 바깥 반복. 정렬된 구간의 끝을 나타낸다. `n - 1`번만 돈다 |
| `minIdx = i` | 현재 구간의 첫 요소를 최솟값 후보로 둔다 |
| 안쪽 `for (j = i + 1; ...)` | 나머지 구간을 훑으며 더 작은 값을 만나면 `minIdx`를 갱신한다 |
| `temp`로 교환 | `arr[i]`와 `arr[minIdx]`를 교환한다. `minIdx == i`이면 자기 자신과 교환하므로 값은 변하지 않는다 |
| `sizeof(arr) / sizeof(arr[0])` | 배열 요소 수를 구한다. 배열을 함수 인자로 넘기면 포인터가 되므로 이 계산은 선언된 범위에서만 유효하다 |

## 6. 응용과 한계

내림차순 정렬은 최솟값 대신 최댓값을 찾는다. 변수 이름도 `maxIdx`로 바꾼다.

{% code title="내림차순으로 바꾸는 조건" %}
```c
if (arr[j] > arr[maxIdx]) {
	maxIdx = j;
}
```
{% endcode %}

양방향 선택 정렬(Double Selection Sort)은 한 번 훑을 때 최솟값과 최댓값을 함께 찾아 양쪽 끝에 배치한다.

* 시간 복잡도는 여전히 O(n²)이다. 반복 횟수는 절반 정도로 줄지만 비교 횟수의 차수는 같다.
* 최댓값이 구간의 첫 위치에 있을 때 최솟값 교환 후 최댓값 위치를 보정해야 한다. 이 처리를 빠뜨리면 틀린 결과가 나온다.

한계는 다음과 같다.

* 입력이 거의 정렬돼 있어도 빨라지지 않는다. 삽입 정렬은 이 경우 O(n)이다.
* 불안정 정렬이므로, 여러 키로 연속해서 정렬하는 경우에는 쓸 수 없다.
* 입력 크기가 큰 경우에는 O(n log n) 정렬(병합, 퀵, 힙)을 쓴다.

## 7. 약어·용어

| 용어 | 뜻 |
|---|---|
| 제자리 정렬(in-place sort) | 입력 크기와 무관한 상수 크기의 추가 메모리만 쓰는 정렬 |
| 안정 정렬(stable sort) | 값이 같은 요소의 원래 순서가 정렬 후에도 유지되는 정렬 |
| 비교 기반 정렬 | 요소끼리 비교해서 순서를 정하는 정렬 |
