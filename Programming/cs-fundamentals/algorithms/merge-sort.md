## 1. 원리

병합 정렬은 배열을 반으로 나누어 각각 정렬한 뒤, 정렬된 두 구간을 하나로 합치는 분할 정복(divide and conquer) 정렬이다.

1. 구간 길이가 1 이하이면 이미 정렬된 것으로 보고 끝낸다.
2. 구간을 가운데(`mid`)에서 둘로 나눈다.
3. 왼쪽 구간과 오른쪽 구간을 각각 재귀로 정렬한다.
4. 두 정렬된 구간의 맨 앞 요소끼리 비교해 작은 쪽을 보조 배열에 차례로 옮긴다(병합).
5. 한쪽이 바닥나면 남은 쪽을 그대로 옮기고, 보조 배열의 내용을 원래 구간에 되돌려 복사한다.

## 2. 단계별 추적

`{38, 27, 43, 3, 9, 82, 10}`의 진행 과정이다. 재귀가 가장 깊은 곳부터 병합이 일어난다.

| 순서 | 병합하는 두 구간 | 결과 구간 |
|---|---|---|
| 1 | `38` + `27` | `27 38` |
| 2 | `43` + `3` | `3 43` |
| 3 | `27 38` + `3 43` | `3 27 38 43` |
| 4 | `9` + `82` | `9 82` |
| 5 | `9 82` + `10` | `9 10 82` |
| 6 | `3 27 38 43` + `9 10 82` | `3 9 10 27 38 43 82` |

## 3. 예제 코드 (C)

{% code title="merge_sort.c" %}
```c
#include <stdio.h>

/* arr[lo..mid]와 arr[mid+1..hi]는 각각 정렬돼 있다. tmp는 n칸 이상의 보조 배열 */
void merge(int arr[], int tmp[], int lo, int mid, int hi) {
	int i = lo, j = mid + 1, k = lo;

	while (i <= mid && j <= hi) {
		if (arr[i] <= arr[j]) {
			tmp[k++] = arr[i++];
		} else {
			tmp[k++] = arr[j++];
		}
	}
	while (i <= mid) tmp[k++] = arr[i++];
	while (j <= hi) tmp[k++] = arr[j++];

	for (k = lo; k <= hi; k++) {
		arr[k] = tmp[k];
	}
}

void mergeSort(int arr[], int tmp[], int lo, int hi) {
	if (lo >= hi) return;

	int mid = lo + (hi - lo) / 2;
	mergeSort(arr, tmp, lo, mid);
	mergeSort(arr, tmp, mid + 1, hi);
	merge(arr, tmp, lo, mid, hi);
}

int main(void) {
	int arr[] = {38, 27, 43, 3, 9, 82, 10};
	int n = sizeof(arr) / sizeof(arr[0]);
	int tmp[sizeof(arr) / sizeof(arr[0])];

	mergeSort(arr, tmp, 0, n - 1);
	for (int i = 0; i < n; i++) {
		printf("%d ", arr[i]);
	}
	printf("\n");
	return 0;
}
```
{% endcode %}

출력 예:

```
3 9 10 27 38 43 82 
```

| 위치 | 설명 |
|---|---|
| `int mid = lo + (hi - lo) / 2` | 구간의 가운데. `(lo + hi) / 2`와 결과는 같지만 `lo + hi`가 `int` 범위를 넘는 경우를 피한다 |
| `if (lo >= hi) return` | 길이 0 또는 1인 구간은 재귀를 끝낸다 |
| `arr[i] <= arr[j]` | 같은 값이면 왼쪽 구간 요소를 먼저 옮긴다. 이 조건이 안정성을 보장한다 |
| 남은 요소 복사 두 줄 | 한쪽 구간이 먼저 바닥났을 때 나머지를 옮긴다 |
| `tmp` | 병합 결과를 담는 보조 배열. 재귀마다 새로 만들지 않고 한 번 만들어 넘긴다 |

## 4. 복잡도

| 항목 | 값 | 비고 |
|---|---|---|
| 시간(최선·평균·최악) | O(n log n) | 입력 상태와 무관하다. 구간을 log n번 나누고 각 단계에서 n개를 병합한다 |
| 공간 | O(n) | 배열 기준 보조 배열이 필요하다. 재귀 깊이는 O(log n)이다 |
| 안정성 | 안정 | 병합 시 같은 값은 왼쪽 구간을 먼저 옮긴다 |

## 5. 안정성과 한계

* 최악의 입력에서도 O(n log n)이라 성능이 예측 가능하다.
* 배열 구현은 O(n)의 추가 메모리가 필요하다. 메모리가 빠듯하면 힙 정렬이 대안이다.
* 안정 정렬이므로 여러 키를 차례로 정렬할 때 쓸 수 있다.
* 연결 리스트는 임의 접근이 필요 없는 병합 연산 특성상 보조 배열 없이도 구현할 수 있다.
* 요소 수가 매우 적은 구간에서는 재귀 비용 때문에 삽입 정렬보다 느릴 수 있다.
