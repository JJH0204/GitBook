## 1. 원리

이진 탐색은 오름차순으로 정렬된 배열에서 가운데 요소와 목표 값을 비교해, 목표가 있을 수 없는 절반을 버리며 범위를 좁히는 탐색이다. 정렬돼 있어야만 쓸 수 있다.

1. 탐색 범위를 `lo = 0`, `hi = n - 1`로 둔다.
2. `lo <= hi`인 동안 `mid`를 구한다.
3. `arr[mid]`가 목표와 같으면 `mid`를 반환한다.
4. `arr[mid]`가 목표보다 작으면 목표는 오른쪽에 있으므로 `lo = mid + 1`로 한다.
5. `arr[mid]`가 목표보다 크면 `hi = mid - 1`로 한다.
6. 범위가 비면(`lo > hi`) -1을 반환한다.

## 2. 단계별 추적

`{2, 5, 8, 12, 16, 23, 38}`에서의 진행 과정이다.

| 목표 | lo | hi | mid | arr[mid] | 판단 |
|---|---|---|---|---|---|
| 23 | 0 | 6 | 3 | 12 | 12 < 23이므로 `lo = 4` |
| 23 | 4 | 6 | 5 | 23 | 찾음. 인덱스 5 반환 |
| 7 | 0 | 6 | 3 | 12 | 12 > 7이므로 `hi = 2` |
| 7 | 0 | 2 | 1 | 5 | 5 < 7이므로 `lo = 2` |
| 7 | 2 | 2 | 2 | 8 | 8 > 7이므로 `hi = 1` |
| 7 | 2 | 1 | - | - | `lo > hi`. -1 반환 |

## 3. 예제 코드 (C)

{% code title="binary_search.c" %}
```c
#include <stdio.h>

/* 오름차순 배열에서 target의 인덱스를 반환한다. 없으면 -1 */
int binarySearch(const int arr[], int n, int target) {
	int lo = 0, hi = n - 1;

	while (lo <= hi) {
		int mid = lo + (hi - lo) / 2;

		if (arr[mid] == target) {
			return mid;
		} else if (arr[mid] < target) {
			lo = mid + 1;
		} else {
			hi = mid - 1;
		}
	}
	return -1;
}

int main(void) {
	int arr[] = {2, 5, 8, 12, 16, 23, 38};
	int n = sizeof(arr) / sizeof(arr[0]);

	printf("23 -> %d\n", binarySearch(arr, n, 23));
	printf("7 -> %d\n", binarySearch(arr, n, 7));
	return 0;
}
```
{% endcode %}

출력 예:

```
23 -> 5
7 -> -1
```

| 위치 | 설명 |
|---|---|
| `lo <= hi` | 범위에 요소가 하나 남았을 때(`lo == hi`)도 검사하도록 `<=`를 쓴다 |
| `int mid = lo + (hi - lo) / 2` | `(lo + hi) / 2`는 `lo + hi`가 `int` 범위를 넘으면 오버플로한다. 이 식은 그 경우를 피한다 |
| `lo = mid + 1`, `hi = mid - 1` | 이미 검사한 `mid`를 범위에서 제외한다. `mid`를 그대로 두면 무한 반복이 될 수 있다 |
| `const int arr[]` | 탐색은 배열을 바꾸지 않는다 |

## 4. 복잡도

| 항목 | 값 | 비고 |
|---|---|---|
| 시간(최선) | O(1) | 첫 `mid`에서 찾을 때 |
| 시간(평균·최악) | O(log n) | 비교마다 범위가 절반이 된다 |
| 공간 | O(1) | 반복문 구현. 재귀 구현은 O(log n) |
| 전제 조건 | 정렬됨 | 정렬되지 않은 배열에서는 결과가 틀린다 |

## 5. 안정성과 한계

* 정렬이 전제이므로 정렬되지 않은 데이터를 한 번만 찾을 때는 선형 탐색이 더 낫다. 정렬 비용 O(n log n)이 들기 때문이다.
* 연결 리스트처럼 가운데 요소에 바로 접근할 수 없는 구조에서는 이점이 없다.
* 같은 값이 여러 개일 때 이 코드는 그중 어느 것의 인덱스를 반환할지 보장하지 않는다. 첫 번째 위치가 필요하면 하한(lower bound) 방식으로 따로 구현한다.
* 경계 조건(`<=` 대 `<`, `mid + 1` 대 `mid`)이 흔한 오류 원인이다.
