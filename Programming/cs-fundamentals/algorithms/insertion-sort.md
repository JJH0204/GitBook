## 1. 원리

삽입 정렬은 배열을 정렬된 앞부분과 정렬되지 않은 뒷부분으로 나누고, 뒷부분의 요소를 하나씩 꺼내 앞부분의 알맞은 위치에 끼워 넣는 비교 기반 정렬이다. 카드 게임에서 손에 든 카드 사이에 새 카드를 끼워 넣는 방식과 같다.

1. `i = 1`부터 시작한다. `arr[0]`은 길이 1의 정렬된 구간이다.
2. `key = arr[i]`를 꺼낸다.
3. 정렬된 구간의 끝에서 앞으로 가며 `key`보다 큰 요소를 한 칸씩 뒤로 민다.
4. 밀기가 멈춘 빈자리에 `key`를 넣는다.
5. `i`가 `n - 1`에 도달할 때까지 2~4를 반복한다.

## 2. 단계별 추적

`{64, 25, 12, 22, 11}`의 진행 과정이다. `|` 왼쪽이 정렬된 구간이다.

| 반복 | key | 뒤로 민 요소 | 배열 상태 |
|---|---|---|---|
| 시작 | - | - | `64 \| 25 12 22 11` |
| i=1 | 25 | 64 | `25 64 \| 12 22 11` |
| i=2 | 12 | 64, 25 | `12 25 64 \| 22 11` |
| i=3 | 22 | 64, 25 | `12 22 25 64 \| 11` |
| i=4 | 11 | 64, 25, 22, 12 | `11 12 22 25 64` |

## 3. 예제 코드 (C)

{% code title="insertion_sort.c" %}
```c
#include <stdio.h>

void insertionSort(int arr[], int n) {
	for (int i = 1; i < n; i++) {
		int key = arr[i];
		int j = i - 1;

		while (j >= 0 && arr[j] > key) {
			arr[j + 1] = arr[j];
			j--;
		}
		arr[j + 1] = key;
	}
}

void printArr(int arr[], int n) {
	for (int i = 0; i < n; i++) {
		printf("%d ", arr[i]);
	}
	printf("\n");
}

int main(void) {
	int arr[] = {64, 25, 12, 22, 11};
	int n = sizeof(arr) / sizeof(arr[0]);

	printf("pre-sort: ");
	printArr(arr, n);
	insertionSort(arr, n);
	printf("post-sort: ");
	printArr(arr, n);
	return 0;
}
```
{% endcode %}

출력 예:

```
pre-sort: 64 25 12 22 11 
post-sort: 11 12 22 25 64 
```

| 위치 | 설명 |
|---|---|
| `int key = arr[i]` | 끼워 넣을 값을 따로 저장한다. 밀기로 `arr[i]`가 덮어써지기 때문이다 |
| `while (j >= 0 && arr[j] > key)` | `j >= 0` 검사를 먼저 해서 배열 앞 경계를 넘지 않게 한다. 비교 연산자가 `>`(`>=`가 아님)이므로 같은 값은 밀지 않는다 |
| `arr[j + 1] = arr[j]` | 큰 요소를 한 칸 뒤로 민다 |
| `arr[j + 1] = key` | 밀기가 멈춘 자리(`j + 1`)에 `key`를 넣는다 |

이 추적의 총 이동 횟수는 1 + 2 + 2 + 4 = 9번이다. 이 값은 입력 `{64, 25, 12, 22, 11}`의 역순쌍(앞 요소가 뒤 요소보다 큰 쌍) 수와 같다.

## 4. 복잡도

| 항목 | 값 | 비고 |
|---|---|---|
| 시간(최선) | O(n) | 이미 정렬돼 있으면 비교만 n−1번 하고 이동이 없다 |
| 시간(평균) | O(n²) | |
| 시간(최악) | O(n²) | 역순 입력. 비교·이동이 n(n−1)/2번이다 |
| 이동 횟수 | 역순쌍 수 | 입력이 정렬에 가까울수록 적다 |
| 공간 | O(1) | 제자리(in-place) 정렬 |
| 안정성 | 안정 | 같은 값은 밀지 않으므로 원래 순서가 유지된다 |

## 5. 안정성과 한계

* 안정 정렬이다. 비교 조건이 `arr[j] > key`이기 때문이며, `>=`로 바꾸면 같은 값끼리 순서가 뒤바뀌어 불안정해진다.
* 거의 정렬된 입력이나 요소 수가 적은 입력에서 빠르다. 이 성질 때문에 O(n log n) 정렬의 작은 구간 처리에 함께 쓰기도 한다.
* 입력이 크고 무작위이면 O(n²)이므로 병합·퀵·힙 정렬을 쓴다.
* 배열에서는 요소를 한 칸씩 미는 비용이 든다. 연결 리스트에서는 밀기 없이 노드만 연결하면 된다.
