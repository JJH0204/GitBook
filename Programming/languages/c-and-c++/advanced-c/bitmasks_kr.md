## 1. 정의

비트 마스킹(bit masking)은 데이터를 문자, 정수, 부동 소수점 값으로 저장하는 대신 개별 비트로 저장하고 조작하는 방식이다. 특정 유형의 데이터를 작고 효율적으로 저장할 때 유용하다.

비트 마스킹은 불리언(Boolean) 논리에 기반한다. 불리언 논리는 0과 1을 인자로 하는 논리 연산으로 참(1)과 거짓(0)을 다룬다. 비트마스크는 `켜짐/꺼짐`, `이동/정지`처럼 두 가지 상태를 가진 값인 플래그(flag)를 설정할 때 자주 쓴다.

## 2. 구성 요소

### 2-1. 논리 연산

| 연산 | C 연산자 | 결과 |
|---|---|---|
| NOT a | `~a` | 입력의 반대 값이다(1 → 0, 0 → 1) |
| a AND b | `a & b` | 두 값이 모두 1이면 1, 아니면 0이다 |
| a OR b | `a \| b` | 둘 중 하나라도 1이면 1, 아니면 0이다 |
| a XOR b | `a ^ b` | 두 값이 서로 다르면 1, 같으면 0이다 |

### 2-2. 비트 수와 정수 타입

C의 기본 타입(`int`, `float` 등)은 정해진 개수의 비트로 구성된다. 이 수는 대개 8의 배수이지만, 표준이 보장하는 것은 `CHAR_BIT` ≥ 8뿐이다. 예를 들어 `int`는 최소 16비트, `char`는 대개 8비트다. 8비트를 일반적으로 바이트라고 한다.

C99에서 `<stdint.h>`가 도입되어 `uint8_t`, `uint32_t`처럼 비트 수가 정해진 정수 타입을 쓸 수 있다. 마스크를 쓸 때 유용하다.

### 2-3. 연산 요약

`storage`는 플래그를 담는 변수, `n`은 비트 번호(0부터 시작)다.

| 동작 | 코드 | 원리 |
|---|---|---|
| 설정(set) | `storage \|= 1u << n;` | 비트 n을 1로 만든다 |
| 해제(clear) | `storage &= ~(1u << n);` | 비트 n을 0으로 만든다 |
| 토글(toggle) | `storage ^= 1u << n;` | 비트 n을 뒤집는다 |
| 검사(check) | `bit = (storage >> n) & 1u;` | 비트 n의 값(0 또는 1)을 얻는다 |

## 3. 동작 원리

마스크 `1u << n`은 비트 n만 1이고 나머지는 0인 값, 즉 2^n이다. 이 마스크를 저장 변수와 연산해 같은 위치의 비트에 접근한다.

{% stepper %}
{% step %}
### 비트 n 설정 (Setting bit n)

저장 변수와 2^n을 OR한다.

{% code title="예" %}
```c
storage |= 1u << n;
```
{% endcode %}

저장소가 8비트일 때 비트 3을 설정하는 예:

```
01000010 OR 00001000 == 01001010
```
{% endstep %}

{% step %}
### 비트 n 해제 (Clearing bit n)

2^n을 NOT한 값과 저장 변수를 AND한다.

{% code title="예" %}
```c
storage &= ~(1u << n);
```
{% endcode %}

예:

```
01001010 AND 11110111 == 01000010
```
{% endstep %}

{% step %}
### 비트 n 토글 (Flipping bit n)

저장 변수와 2^n을 XOR한다.

{% code title="예" %}
```c
storage ^= 1u << n;
```
{% endcode %}

예:

```
01000010 XOR 00001000 == 01001010
01001010 XOR 00001000 == 01000010
```
{% endstep %}

{% step %}
### 비트 n 검사 (Checking bit n)

저장 변수와 2^n을 AND한다. 결과는 비트가 꺼져 있으면 0이고, 켜져 있으면 0이 아닌 값(2^n)이다.

{% code title="예" %}
```c
bit = storage & (1u << n);
```
{% endcode %}

예:

```
01000010 AND 00001000 == 00000000
01001010 AND 00001000 == 00001000
```

0 또는 1로 받으려면 `bit = (storage >> n) & 1u;`를 쓴다.
{% endstep %}
{% endstepper %}

## 4. 한계와 주의

{% hint style="danger" %}
WARNING: 부호 있는 시프트는 정의되지 않은 동작(UB)에 걸리기 쉽다. 원본의 `1 << n`에서 `1`은 부호 있는 `int`다. 결과가 `int`로 표현되지 않으면(예: 32비트 `int`에서 `1 << 31`) 동작이 정의되지 않는다. 마스크는 `1u << n`처럼 부호 없는 상수로 쓴다.
{% endhint %}

* 시프트 횟수 `n`은 0 이상이고 시프트되는 타입의 비트 수보다 작아야 한다. 32비트 `unsigned int`에서 `n`은 0~31이다.
* 32비트를 넘는 비트(32~63)는 `1ull << n` 또는 `uint64_t`를 쓴다. `1u << 40`은 정의되지 않는다.
* `~`와 `&`는 피연산자가 `int`보다 작은 타입(`uint8_t` 등)이면 먼저 `int`로 승격(integer promotion)된다. 예를 들어 `uint8_t x = 0x08;`일 때 `~x`는 8비트 `11110111`이 아니라 `int` 전체가 뒤집힌 `0xFFFFFFF7`(32비트 `int` 기준)이다. 이 값을 `uint8_t`에 다시 대입하면 하위 8비트만 남아 문제가 없다. 그러나 `~x`를 그대로 비교하거나 출력하면 예상과 다른 값이 나온다.
* 원본 해제 예제의 `~(1 << n)`은 부호 있는 `int`를 뒤집으므로 `~(1u << n)`으로 정정했다.
