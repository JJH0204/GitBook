## 1. 목적

해시 함수(hash function)는 임의 길이의 입력을 고정 길이의 값(해시 값, 다이제스트)으로 바꾸는 함수이다. 암호화와 달리 단방향이다. 해시된 데이터는 복호화할 수 없고 원래 데이터로 바꿀 수 없다.

## 2. 구성 요소

### 2.1 해시 함수의 성질

| 성질 | 내용 |
|---|---|
| 고정 길이 출력 | 입력 길이와 무관하게 출력 길이가 같다 |
| 결정성 | 같은 입력은 항상 같은 출력을 낸다 |
| 눈사태 효과 | 입력이 1비트만 달라도 출력이 크게 달라진다 |
| 단방향성(역상 저항) | 출력에서 입력을 찾기 어렵다 (암호학적 해시) |
| 충돌 저항성 | 같은 출력을 내는 서로 다른 두 입력을 찾기 어렵다 (암호학적 해시) |

### 2.2 체크섬과 암호학적 해시

| 구분 | 체크섬(오류 검출 코드) | 암호학적 해시 |
|---|---|---|
| 목적 | 전송·저장 중 우발적 오류 검출 | 무결성 보장, 서명, 식별 |
| 공격자 가정 | 없다. 의도적 조작은 막지 못한다 | 있다. 충돌·역상 공격에 저항해야 한다 |
| 예 | 패리티, CRC32 | SHA-256, SHA-3 |

CRC32(32비트 순환 중복 검사)는 이더넷 프레임, ZIP, PNG의 오류 검출에 쓴다. 속도가 빠르지만 의도적으로 같은 CRC를 만드는 조작이 쉬워서 보안 용도로 쓰지 않는다.

### 2.3 대표 알고리즘

| 알고리즘 | 출력 길이 | 16진수 자릿수 | 보안 용도 |
|---|---|---|---|
| CRC32 | 32비트 | 8 | 부적합 (체크섬) |
| MD5 | 128비트 | 32 | 부적합 (충돌 발견). [MD5 (PRG-HSH-002-DO)](md5.md) 참조 |
| SHA-1 | 160비트 | 40 | 부적합 (충돌 발견) |
| SHA-256 (SHA-2 계열) | 256비트 | 64 | 적합 |
| SHA-512 (SHA-2 계열) | 512비트 | 128 | 적합 |

SHA-2 계열은 SHA-224, SHA-256, SHA-384, SHA-512를 포함하며 출력 길이는 이름의 숫자와 같다(비트).

## 3. 동작 원리

### 3.1 빈 입력과 짧은 입력의 해시 예

| 입력 | MD5 | SHA-256 |
|---|---|---|
| (빈 문자열) | `d41d8cd98f00b204e9800998ecf8427e` | `e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855` |
| `abc` | `900150983cd24fb0d6963f7d28e17f72` | `ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad` |

### 3.2 용도

* 파일 무결성 확인: 배포자가 게시한 해시와 내려받은 파일의 해시를 비교한다.
* 비밀번호 저장: 원문 대신 해시를 저장한다. 아래 NOTE를 따른다.
* 자료 구조: 해시 테이블의 키 분포에 쓴다(암호학적 성질은 필요 없다).

{% hint style="info" %}
NOTE: 비밀번호 저장에는 SHA-256 같은 빠른 해시를 단독으로 쓰지 않는다. 사용자마다 무작위 솔트(salt)를 붙이고, 일부러 느리게 설계된 해시(bcrypt, scrypt, Argon2 등)를 쓴다. 빠른 해시는 무차별 대입에 취약하다.
{% endhint %}

{% hint style="warning" %}
CAUTION: 해시는 복호화할 수 없다. 다만 입력 후보를 대입해 같은 해시가 나오는지 찾는 무차별 대입이나 미리 계산한 표(레인보 테이블)로 원문을 알아낼 수 있다. 짧거나 흔한 입력은 해시만으로 보호되지 않는다.
{% endhint %}
