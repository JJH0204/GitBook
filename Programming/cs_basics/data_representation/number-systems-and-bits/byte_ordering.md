## 1. 목적

2바이트 이상의 데이터는 메모리에 연속으로 저장된다. 이때 각 바이트가 놓이는 순서를 바이트 순서(byte ordering, 엔디안)라 한다. 서로 다른 순서의 기계가 데이터를 주고받을 때 이를 맞춰야 한다.

## 2. 구성 요소

| 방식 | 낮은 주소에 놓이는 바이트 | 대표 환경 |
|---|---|---|
| 빅 엔디안(Big-endian) | 가장 왼쪽(MSB, 최상위 바이트) | 네트워크 바이트 순서, SPARC, 과거 PowerPC·Motorola 68k |
| 리틀 엔디안(Little-endian) | 가장 오른쪽(LSB, 최하위 바이트) | x86, x86-64 |

* ARM은 설정으로 둘 다 가능한 바이엔디안(bi-endian)이지만 Android, iOS, Windows on ARM 등 대부분의 환경은 리틀 엔디안으로 동작한다.
* 대다수의 개인용 컴퓨터와 서버가 x86-64이므로 리틀 엔디안을 기본으로 안다.

{% hint style="info" %}
NOTE: 바이트 순서에서 MSB, LSB는 비트(Bit)가 아니라 바이트(Byte)를 뜻한다. 바이트 안의 비트 순서는 그대로이고 바이트의 순서만 달라진다.
{% endhint %}

## 3. 동작 원리

4바이트 16진수 `0x01234567`을 주소 `0x100`에 저장한 결과다.

| 주소 | 0x100 | 0x101 | 0x102 | 0x103 |
|---|---|---|---|---|
| 빅 엔디안 | 01 | 23 | 45 | 67 |
| 리틀 엔디안 | 67 | 45 | 23 | 01 |

메모리 덤프를 읽을 때 리틀 엔디안에서는 바이트 순서를 뒤집어 값을 읽는다. 덤프 `67 45 23 01`은 값 `0x01234567`이다.

### 3.1 네트워크 바이트 순서

네트워크 프로토콜의 다중 바이트 필드는 빅 엔디안으로 전송한다(네트워크 바이트 순서). 리틀 엔디안 호스트는 보내기 전에 변환한다.

| 변환 | 함수(C, POSIX) | 의미 |
|---|---|---|
| host → network (16비트 / 32비트) | `htons`, `htonl` | 호스트 순서를 네트워크 순서로 |
| network → host | `ntohs`, `ntohl` | 네트워크 순서를 호스트 순서로 |

### 3.2 문자열과 정수

* 1바이트 문자(ASCII, UTF-8)로 이루어진 문자열은 바이트 순서의 영향을 받지 않는다. 문자 순서 그대로 저장한다.
* 정수, 부동소수점 같은 2바이트 이상 자료형은 바이트 순서에 따라 저장된다.
* UTF-16, UTF-32는 문자 하나가 2~4바이트라 엔디안이 있다. 그래서 파일 앞에 BOM(Byte Order Mark)을 두거나 UTF-16LE, UTF-16BE로 명시한다.

### 3.3 확인 방법

C 예제(미검증)이다. 값을 `unsigned char`로 읽는 것은 허용된다.

```c
#include <stdio.h>
#include <stdint.h>

int main(void) {
    uint32_t v = 0x01234567;
    unsigned char *p = (unsigned char *)&v;
    printf("%02x %02x %02x %02x\n", p[0], p[1], p[2], p[3]);
    return 0;
}
```

* 리틀 엔디안 출력: `67 45 23 01`
* 빅 엔디안 출력: `01 23 45 67`

C#에서는 `BitConverter.IsLittleEndian` 값으로 현재 환경의 순서를 확인한다. x86-64에서는 `true`다.
