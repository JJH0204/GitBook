## 1. 목적

인코딩(encoding)은 데이터를 정해진 형식으로 변환하는 일이다. 디코딩(decoding)은 인코딩된 데이터를 원래 값으로 되돌리는 일이다. 데이터를 저장·전송하기 좋은 형태로 바꾸거나, 텍스트만 허용되는 환경에 이진 데이터를 싣거나, 크기를 줄일 때 쓴다.

## 2. 구성 요소

### 2.1 인코딩, 암호화, 해시 비교

| 구분 | 목적 | 되돌리기 | 키 |
|---|---|---|---|
| 인코딩 | 형식 변환, 호환성 | 표준 방식으로 누구나 디코딩할 수 있다 | 없다 |
| 암호화 | 기밀성 | 비밀 키가 있어야 원문을 복구한다 | 필요하다 |
| 해시 | 무결성 확인, 식별 | 원문을 복구할 수 없다 ([해싱](../hashing-and-checksums/hashing.md) 참조) | 없다 |

{% hint style="warning" %}
CAUTION: Base64 같은 인코딩은 비밀을 지키지 않는다. 인코딩된 값을 암호화된 값으로 취급하지 않는다.
{% endhint %}

### 2.2 인코딩 종류

| 종류 | 대상 | 문서 |
|---|---|---|
| 문자 인코딩 | 문자를 숫자(바이트)로 대응 | [아스키 코드](ascii.md), [유니코드](unicode.md) |
| 이진-텍스트 인코딩 | 이진 데이터를 텍스트 문자로 표현 | [Base64](base64.md) |
| 퍼센트 인코딩 | URL에서 예약 문자를 `%XX`로 표현 | [URL](../../web_technologies/http-and-urls/url.md) |
| 줄 바꿈 표현 | 운영체제별 줄 끝 문자 | [개행 문자](crlf.md) |
| 압축 | 데이터 크기를 줄이는 변환. 일종의 인코딩이다 | |

## 3. 동작 원리

인코딩된 데이터의 생김새를 보고 방식을 유추해 직접 디코딩해야 할 때가 있다(예: 분석 과제의 단서). 자주 쓰이는 인코딩의 형태를 알아 두면 유추가 쉽다.

| 생김새 | 유추 |
|---|---|
| 영문 대소문자, 숫자, `+`, `/`로 구성되고 끝에 `=`가 있다 | Base64 |
| `%` 뒤에 16진수 두 자리가 반복된다 | 퍼센트 인코딩 |
| `U+` 뒤에 16진수가 붙는다 | 유니코드 코드 포인트 표기 |
