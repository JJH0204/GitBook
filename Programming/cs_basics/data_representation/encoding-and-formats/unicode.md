## 1. 목적

ASCII는 알파벳, 숫자, 기호, 제어 문자만 포함한다. 여러 언어가 등장하면서 문자 집합이 서로 호환되지 않는 문제가 생겼고, 이를 해결하려고 유니코드(Unicode)가 만들어졌다. 유니코드는 전 세계 문자에 고유한 번호를 부여하는 국제 표준이다.

## 2. 구성 요소

### 2.1 코드 포인트

| 항목 | 내용 |
|---|---|
| 코드 포인트(code point) | 문자에 부여한 번호. `U+` 뒤에 16진수를 붙여 표기한다 (예: `U+0041` = `A`) |
| 범위 | U+0000~U+10FFFF (21비트로 표현되는 범위). 32비트는 UTF-32의 저장 폭이다 |
| 문자 수 | 14만 개 이상의 문자를 포함한다 |
| ASCII 호환 | 처음 128개(U+0000~U+007F)는 ASCII와 일치한다 |

### 2.2 인코딩 형식 비교

UTF 뒤의 숫자는 코드 단위(code unit)의 비트 수이다.

| 형식 | 코드 단위 | 문자당 길이 | 특징 |
|---|---|---|---|
| UTF-8 | 8비트 | 1~4바이트 가변 | ASCII 영역(0~127)과 바이트가 같아 호환된다. 대부분의 환경에서 기본으로 쓴다 |
| UTF-16 | 16비트 | 2바이트 또는 4바이트(서로게이트 쌍) | 바이트 순서(엔디언)가 있다 |
| UTF-32 | 32비트 | 4바이트 고정 | 바이트 순서가 있다. 크기가 크다 |

### 2.3 UTF-8 바이트 구조

| 코드 포인트 범위 | 바이트 수 | 비트 패턴 |
|---|---|---|
| U+0000~U+007F | 1 | `0xxxxxxx` |
| U+0080~U+07FF | 2 | `110xxxxx 10xxxxxx` |
| U+0800~U+FFFF | 3 | `1110xxxx 10xxxxxx 10xxxxxx` |
| U+10000~U+10FFFF | 4 | `11110xxx 10xxxxxx 10xxxxxx 10xxxxxx` |

### 2.4 UTF-16 서로게이트

U+0000~U+FFFF(기본 다국어 평면, BMP)는 16비트 코드 단위 1개로 표현한다. U+10000 이상은 코드 단위 2개(서로게이트 쌍, surrogate pair)로 표현한다. 상위 서로게이트는 0xD800~0xDBFF, 하위 서로게이트는 0xDC00~0xDFFF이다. U+D800~U+DFFF는 단독 문자에 쓰지 않는다.

### 2.5 바이트 순서 표시 (BOM)

BOM(Byte Order Mark)은 파일 맨 앞에 두는 U+FEFF이다. UTF-16과 UTF-32에서 빅 엔디언(BE)인지 리틀 엔디언(LE)인지 알린다. UTF-8은 바이트 순서 문제가 없지만 BOM(`EF BB BF`)을 붙이는 경우가 있다.

## 3. 동작 원리

### 3.1 인코딩 예

| 문자 | 코드 포인트 | UTF-8 (16진수) | UTF-16BE | UTF-16LE | UTF-32BE |
|---|---|---|---|---|---|
| `A` | U+0041 | 41 | 0041 | 4100 | 00000041 |
| `가` | U+AC00 | EA B0 80 | AC00 | 00AC | 0000AC00 |
| 😀 | U+1F600 | F0 9F 98 80 | D83D DE00 | 3DD8 00DE | 0001F600 |

### 3.2 한글 인코딩 비교

| 인코딩 | 한글 표현 | 비고 |
|---|---|---|
| EUC-KR (KS X 1001) | 완성형 한글 2,350자 | 표에 없는 음절(예: `똠`)은 표현하지 못한다. `가`는 B0 A1 |
| CP949 (확장 완성형) | 현대 한글 11,172자 전체 | EUC-KR의 상위 집합. Windows 한국어 환경에서 쓴다 |
| 유니코드 (UTF-8 등) | 11,172자 전체와 다국어 | 한글 음절은 UTF-8에서 3바이트다 |

{% hint style="info" %}
NOTE: EUC-KR로 작성된 파일을 UTF-8로 해석하면 글자가 깨진다. 파일의 인코딩을 먼저 확인한다.
{% endhint %}
