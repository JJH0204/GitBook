## 1. 목적

가상 메모리(virtual memory)는 프로세스마다 독립된 연속 주소 공간을 제공하고, 필요한 부분만 물리 메모리에 올려 물리 메모리보다 큰 공간을 쓰게 하는 기법이다.

| 이점 | 설명 |
|---|---|
| 독립성 | 프로세스가 서로의 메모리를 볼 수 없다 |
| 보호 | 페이지마다 읽기·쓰기·실행 권한을 둔다 |
| 용량 | 물리 메모리보다 큰 프로그램을 실행한다 |
| 단순함 | 프로그램이 물리 주소 배치를 신경 쓰지 않는다 |

## 2. 구성 요소

| 용어 | 설명 |
|---|---|
| 가상 주소 | 프로세스가 사용하는 주소 |
| 물리 주소 | 실제 RAM의 주소 |
| 페이지(page) | 가상 주소 공간을 나눈 고정 크기 블록. 일반적으로 4 KiB |
| 프레임(frame) | 물리 메모리를 같은 크기로 나눈 블록 |
| 페이지 테이블 | 페이지 번호를 프레임 번호로 바꾸는 표. 프로세스마다 있다 |
| MMU | 주소 변환을 하는 하드웨어 |
| TLB | 최근 변환 결과를 저장하는 캐시 |
| 스왑 영역 | 내보낸 페이지를 보관하는 보조기억장치 영역(Windows는 [pagefile.sys](../windows-internals/windowssystemfile.md)) |

x86-64는 현재 일반적으로 48비트 가상 주소를 사용해 256 TiB 공간을 쓴다.

## 3. 동작 원리

### 3.1 주소 변환

페이지 크기가 4 KiB이면 오프셋은 12비트다. 가상 주소의 상위 비트가 페이지 번호, 하위 12비트가 오프셋이다.

예: 가상 주소 `0x00403A10`

| 항목 | 값 |
|---|---|
| 페이지 번호 | `0x00403A10 >> 12 = 0x403` |
| 오프셋 | `0x00403A10 & 0xFFF = 0xA10` |

페이지 테이블에서 `0x403`번 페이지가 프레임 `0x1F2`에 매핑돼 있다면 물리 주소는 `(0x1F2 << 12) + 0xA10 = 0x1F2A10`이다.

### 3.2 페이지 폴트

1. CPU가 가상 주소에 접근한다.
2. 페이지 테이블의 해당 항목이 "메모리에 없음"이면 페이지 폴트가 발생한다.
3. 커널이 스왑 영역이나 파일에서 페이지를 읽어 빈 프레임에 올린다. 빈 프레임이 없으면 [페이지 교체 알고리즘](pagereplacement.md)으로 내보낼 페이지를 고른다.
4. 페이지 테이블을 갱신하고 중단된 명령을 다시 실행한다.
5. 권한이 없거나 유효하지 않은 주소이면 프로세스를 종료한다. → [세그멘테이션 결함](segmentationfault.md)

### 3.3 페이징과 세그멘테이션 비교

| 항목 | 페이징 | 세그멘테이션 |
|---|---|---|
| 분할 단위 | 고정 크기(페이지) | 가변 크기(논리 단위) |
| 단편화 | 내부 단편화 | 외부 단편화 |
| 프로그래머가 보는가 | 보이지 않는다 | 논리 구조가 반영된다 |
| 현대 x86-64 | 사용 | 사실상 평면(flat) 모델로 거의 쓰지 않는다 |

### 3.4 단편화

| 종류 | 설명 | 주로 발생하는 방식 |
|---|---|---|
| 내부 단편화 | 할당 단위보다 작게 쓰고 남는 공간. 예: 4 KiB 페이지에 100바이트만 쓰면 약 3,996바이트가 낭비된다 | 고정 크기 할당(페이징) |
| 외부 단편화 | 빈 공간 총량은 충분하지만 연속하지 않아 큰 요청을 만족하지 못한다 | 가변 크기 할당(세그멘테이션, `malloc` 힙) |

외부 단편화의 해결책은 조각 모음(compaction)이다. 힙에서는 크기별 풀(pool) 같은 할당자 전략을 쓴다.
