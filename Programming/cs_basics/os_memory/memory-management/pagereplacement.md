{% hint style="info" %}
NOTE: 이 문서는 원본에 없던 새 문서다. 페이지 교체 알고리즘은 이 저장소에 해당 문서가 없어 새로 작성했다.
{% endhint %}

## 1. 목적

물리 메모리의 프레임이 모두 찼을 때 새 페이지를 올리려면 기존 페이지 하나를 내보내야 한다. 내보낼 페이지를 고르는 규칙이 페이지 교체 알고리즘이다. 목표는 페이지 부재(page fault) 횟수를 줄이는 것이다. 배경은 [가상 메모리와 페이징](virtualmemory.md)을 본다.

## 2. 구성 요소

| 알고리즘 | 내보낼 페이지 | 구현 비용 | 비고 |
|---|---|---|---|
| FIFO | 가장 먼저 들어온 페이지 | 낮다(큐) | 벨라디의 모순이 생길 수 있다 |
| LRU | 가장 오래 사용하지 않은 페이지 | 높다(사용 시각 추적) | 성능이 좋아 근사 구현을 쓴다 |
| Optimal(OPT) | 앞으로 가장 늦게 쓰일 페이지 | 구현 불가(미래를 알아야 함) | 다른 알고리즘의 비교 기준이다 |
| Clock(2차 기회) | 참조 비트가 0인 페이지(시계 방향 검사) | 낮다 | LRU의 근사 |

LRU와 Optimal은 스택 성질을 가져 프레임 수를 늘리면 페이지 부재가 줄거나 같다. FIFO는 이 성질이 없다.

## 3. 동작 원리

### 3.1 예: 프레임 3개

참조열(페이지 번호): `7 0 1 2 0 3 0 4 2 3 0 3 2 1 2 0 1 7 0 1` (20회 참조, 교과서에 자주 쓰이는 예)

| 알고리즘 | 페이지 부재 횟수 |
|---|---|
| FIFO | 15 |
| LRU | 12 |
| Optimal | 9 |

### 3.2 벨라디의 모순 (FIFO)

참조열 `1 2 3 4 1 2 5 1 2 3 4 5`에서 FIFO는 프레임이 많아져도 부재가 늘어난다.

| 프레임 수 | 페이지 부재 횟수 |
|---|---|
| 3 | 9 |
| 4 | 10 |

프레임 3개 추적(앞쪽이 가장 오래된 페이지):

| 참조 | 1 | 2 | 3 | 4 | 1 | 2 | 5 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 메모리 | 1 | 1 2 | 1 2 3 | 2 3 4 | 3 4 1 | 4 1 2 | 1 2 5 | 1 2 5 | 1 2 5 | 2 5 3 | 5 3 4 | 5 3 4 |
| 부재 | O | O | O | O | O | O | O | | | O | O | |

## 4. 복잡도

| 알고리즘 | 참조당 시간(구현에 따라) | 추가 공간 | 벨라디 모순 |
|---|---|---|---|
| FIFO | O(1) (큐 사용) | O(프레임 수) | 발생 가능 |
| LRU | O(1) (해시 + 이중 연결 리스트) 또는 O(프레임 수) (배열) | O(프레임 수) | 없음 |
| Optimal | O(남은 참조열 길이) | 참조열 전체 필요 | 없음 |

## 5. 예제 코드

```python
def count_faults(refs, frames, policy):
    memory = []          # 앞쪽이 FIFO는 가장 오래된, LRU는 가장 오래 쓰지 않은 페이지
    faults = 0
    for page in refs:
        if page in memory:
            if policy == "LRU":      # LRU는 사용할 때마다 맨 뒤로 보낸다
                memory.remove(page)
                memory.append(page)
            continue
        faults += 1
        if len(memory) == frames:
            memory.pop(0)            # 맨 앞 페이지를 내보낸다
        memory.append(page)
    return faults

refs = [7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 3, 2, 1, 2, 0, 1, 7, 0, 1]
print(count_faults(refs, 3, "FIFO"))   # 15
print(count_faults(refs, 3, "LRU"))    # 12

belady = [1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5]
print(count_faults(belady, 3, "FIFO")) # 9
print(count_faults(belady, 4, "FIFO")) # 10
```

## 6. 코드 설명

1. `memory`는 현재 메모리에 올라온 페이지 목록이다.
2. 참조한 페이지가 메모리에 있으면 부재가 아니다. LRU는 해당 페이지를 맨 뒤로 옮겨 "최근 사용"으로 표시한다.
3. 없으면 부재 횟수를 올린다. 프레임이 가득 찼으면 맨 앞 페이지를 내보낸다. FIFO는 들어온 순서, LRU는 최근 사용 순서로 앞쪽이 정해진다.
4. 새 페이지를 맨 뒤에 넣는다.

## 7. 한계·주의

* 위 코드는 학습용이며 `memory.remove`가 O(프레임 수)다.
* 실제 운영체제는 하드웨어 참조 비트를 쓰는 Clock 계열 근사 알고리즘을 쓴다.
* Optimal은 미래를 알아야 하므로 실제 구현이 불가능하고 비교용으로만 쓴다.

## 8. 약어·용어

| 용어 | 뜻 |
|---|---|
| 페이지 부재(page fault) | 필요한 페이지가 메모리에 없는 상태 |
| 참조열 | 프로세스가 접근하는 페이지 번호의 순서 |
| 벨라디의 모순 | 프레임이 늘었는데 페이지 부재가 오히려 늘어나는 현상 |
| 스택 성질 | n개 프레임의 내용이 n+1개 프레임 내용의 부분집합인 성질 |
