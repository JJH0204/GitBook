## 1. 목적

메모리 레이아웃은 프로세스 하나의 가상 주소 공간이 어떤 구획으로 구성되는지를 가리킨다. 프로그램을 실행하면 운영체제가 프로그램 정보를 참조해 프로세스마다 독립된 가상 주소 공간을 만들고, 데이터를 알맞은 구획에 배치한다.

유사한 데이터를 한 구획에 모으면 두 가지 이점이 있다.

* 운영체제가 구획마다 읽기·쓰기·실행 권한을 따로 부여할 수 있다.
* 개발자가 프로세스의 메모리를 구조적으로 이해할 수 있다.

## 2. 구성 요소

일반적인 C 프로그램의 구획이다. 정확한 이름과 배치는 운영체제와 실행 파일 형식(ELF, PE)마다 다르다.

| 구획 | 저장하는 것 | 일반적 권한 | 크기 결정 시점 |
|---|---|---|---|
| 코드(text) | 실행할 기계어 코드 | 읽기, 실행 | 컴파일·링크 시 |
| 데이터(data) | 초기값이 있는 전역·정적 변수 | 읽기, 쓰기 | 컴파일·링크 시 |
| 읽기 전용 데이터(rodata) | 문자열 상수, 전역 상수 | 읽기 | 컴파일·링크 시 |
| BSS | 초기화하지 않은(또는 0으로 초기화한) 전역·정적 변수 | 읽기, 쓰기 | 컴파일·링크 시, 파일에는 크기만 기록 |
| 힙(heap) | `malloc` 등으로 동적 할당한 데이터 | 읽기, 쓰기 | 실행 중 |
| 스택(stack) | 지역 변수, 함수 인자, 복귀 주소 | 읽기, 쓰기 | 실행 중, 함수 호출마다 증감 |

### 2.1 주소 배치와 성장 방향

```
높은 주소
+------------------+
| 스택             |  ↓ 낮은 주소 방향으로 자란다
|        ...       |
| (빈 공간)        |
|        ...       |
| 힙               |  ↑ 높은 주소 방향으로 자란다
+------------------+
| BSS              |
| 데이터           |
| 읽기 전용 데이터 |
| 코드             |
+------------------+
낮은 주소
```

* 스택은 높은 주소에서 낮은 주소로 자란다(x86, x86-64, ARM 등 대부분의 구현). 구현에 따라 다를 수 있다.
* 힙은 일반적으로 낮은 주소에서 높은 주소로 자란다. 현대 할당자는 `mmap` 등으로 흩어진 영역을 쓰기도 한다.
* 현대 운영체제는 ASLR(주소 공간 배치 무작위화)로 구획의 시작 주소를 실행마다 바꾼다.
* 프로세스마다 독립된 주소 공간을 가지므로, 서로 다른 프로세스의 같은 가상 주소는 다른 물리 메모리를 가리킨다.

## 3. 동작 원리

1. 사용자가 프로그램을 실행한다.
2. 운영체제가 실행 파일 헤더를 읽고 섹션별 크기·권한을 확인한다.
3. 운영체제가 프로세스의 가상 주소 공간을 만들고 섹션을 구획에 매핑한다.
4. 프로그램 시작 후 스택과 힙이 실행 중에 늘거나 줄어든다.
5. 권한에 어긋나는 접근(예: 읽기 전용 영역에 쓰기)이 발생하면 운영체제가 프로세스에 오류를 낸다. → [세그멘테이션 결함](segmentationfault.md)

### 3.1 스택과 힙 비교

| 항목 | 스택 | 힙 |
|---|---|---|
| 할당 시점 | 함수 호출 시 자동 | 프로그램이 요청할 때(`malloc`) |
| 해제 | 함수 반환 시 자동 | 프로그램이 해제한다(`free`) |
| 크기 | 작다(Linux 기본 약 8 MiB, Windows 기본 1 MiB) | 상대적으로 크다 |
| 접근 범위 | 해당 함수와 호출한 함수 | 포인터를 공유하는 모든 곳 |
| 주요 오류 | 스택 오버플로, 지역 변수 주소 반환 | 메모리 누수, 해제 후 사용(use-after-free), 이중 해제 |

### 3.2 예제 코드

```c
#include <stdio.h>
#include <stdlib.h>

int g_init = 10;          // 데이터 구획
int g_uninit;             // BSS 구획
const char *g_msg = "hi"; // g_msg는 데이터, 문자열 "hi"는 읽기 전용 데이터

int main(void) {
    int local = 1;                              // 스택
    int *p = malloc(sizeof *p);                 // p는 스택, 가리키는 4바이트는 힙
    if (p == NULL) return 1;
    *p = 2;
    printf("%p %p %p %p\n", (void *)&g_init, (void *)&g_uninit, (void *)&local, (void *)p);
    free(p);
    return 0;
}
```

* `&g_init`, `&g_uninit`은 낮은 주소 쪽 구획에 있다.
* `&local`은 스택, `p`가 가리키는 주소는 힙에 있다. 출력 주소는 실행마다 달라질 수 있다.

### 3.3 `malloc`과 `free`

* `malloc(n)`은 힙에서 n바이트를 할당하고 시작 주소를 반환한다. 실패하면 `NULL`을 반환한다.
* `free(p)`는 `malloc`으로 받은 주소를 해제한다. 같은 주소를 두 번 해제하면 정의되지 않은 동작이다.
* 할당과 해제를 반복하면 힙에 빈 조각이 생긴다. 이를 단편화라 한다([PRG-MEM-008-DO](virtualmemory.md)).
* 실패 처리 방법은 [메모리 할당 유효성 검사](memoryallocationvaliditycheck.md)에서 다룬다.

## 4. 약어·용어

| 용어 | 뜻 |
|---|---|
| 가상 주소 공간 | 프로세스가 보는 독립된 주소 범위 |
| BSS | Block Started by Symbol. 초기화하지 않은 전역·정적 변수 영역 |
| ASLR | Address Space Layout Randomization |
| 단편화 | 메모리에 쓰지 못하는 빈 조각이 생기는 현상 |
| use-after-free | 해제한 메모리를 다시 사용하는 오류 |
