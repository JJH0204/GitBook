## 1. 목적

라이브러리(library)는 자주 쓰는 표준 함수와 데이터 타입을 미리 만들어 모아 둔 것이다. 같은 함수를 매번 새로 만들지 않아도 되어 개발 속도와 신뢰성이 높아진다. 라이브러리는 언제 메인 프로그램에 연결하느냐에 따라 정적 링크(static link)와 동적 링크(dynamic link)로 나뉘며, DLL은 후자에 속한다.

## 2. 구성 요소

### 2.1 정적 링크와 동적 링크

| 항목 | 정적 링크 | 동적 링크 |
|---|---|---|
| 연결 시점 | 빌드의 링크 단계 | 프로그램 로드 시 또는 실행 중 |
| 라이브러리 코드 | 실행 파일 안에 복사된다 | 별도 파일로 남고 실행 시 메모리에 올린다 |
| 파일 형태 | Linux `.a`, Windows `.lib` | Linux `.so`, Windows `.dll`, macOS `.dylib` |
| 실행 파일 크기 | 크다 | 작다 |
| 실행 시 의존성 | 없다. 파일 하나로 실행된다 | 라이브러리 파일이 있어야 한다 |
| 라이브러리 수정 | 다시 링크해야 반영된다 | 파일만 교체하면 반영된다(ABI가 같을 때) |
| 메모리 | 프로세스마다 복사본이 있다 | 읽기 전용 코드 페이지를 여러 프로세스가 공유할 수 있다 |

### 2.2 DLL과 공유 라이브러리

| 이름 | 운영체제 | 형식 |
|---|---|---|
| DLL (Dynamic-Link Library) | Windows | PE 형식 |
| 공유 객체(shared object, `.so`) | Linux, Unix | [ELF](elf.md) 형식 |
| 다이내믹 라이브러리(`.dylib`) | macOS | Mach-O 형식 |

DLL은 Windows의 동적 링크 라이브러리를 가리키는 이름이다. 개념적으로 `.so`, `.dylib`와 같은 역할이다.

## 3. 동작 원리

### 3.1 로드 시 링크와 실행 중 로딩

| 방식 | 동작 | Windows | Linux |
|---|---|---|---|
| 로드 시 링크(load-time) | 실행 파일이 필요한 라이브러리 목록을 갖고, 로더가 프로그램 시작 전에 모두 올린다 | 임포트 테이블, 임포트 라이브러리(`.lib`)로 빌드 | 동적 링커(ld.so)가 `DT_NEEDED` 목록을 처리 |
| 실행 중 로딩(run-time) | 코드가 필요한 때 라이브러리를 직접 올린다 | `LoadLibrary`, `GetProcAddress` | `dlopen`, `dlsym` |

* Windows에서 DLL을 쓰기 위한 `.lib`는 정적 라이브러리가 아니라 DLL의 함수 목록을 담은 임포트 라이브러리일 수 있다.
* 로드 시 링크는 라이브러리가 없으면 프로그램이 시작하지 못한다. 실행 중 로딩은 없을 때 대체 동작을 할 수 있어 플러그인 구조에 쓴다.

### 3.2 장단점

| 구분 | 내용 |
|---|---|
| 장점 | 실행 파일이 작다. 라이브러리 수정·보안 패치를 파일 교체로 반영한다. 메모리를 공유한다. 플러그인을 실행 중에 붙인다 |
| 단점 | 배포 때 라이브러리를 함께 제공해야 한다. 버전이 맞지 않으면 실행에 실패한다. 호출이 간접적이라 약간 느리다 |

### 3.3 DLL 지옥 (DLL Hell)

여러 프로그램이 같은 이름의 DLL을 공유하는데 버전이 서로 달라 충돌하는 문제다. 한 프로그램이 설치하며 공유 DLL을 새 버전으로 덮어써서 다른 프로그램이 동작하지 않는 식이다. 대응은 프로그램 폴더에 자기 DLL을 두거나, 버전을 구분해 나란히 설치(Windows side-by-side)하거나, 컨테이너로 의존성을 묶는 것이다.

### 3.4 Unity 네이티브 플러그인

Unity에서 C/C++로 만든 네이티브 라이브러리는 C#의 `DllImport`로 호출한다(P/Invoke).

```csharp
[DllImport("mylib")]
private static extern int Add(int a, int b);
```

| 플랫폼 | 네이티브 플러그인 형식 |
|---|---|
| Windows | `.dll` |
| Linux, Android | `.so` |
| macOS | `.bundle` 또는 `.dylib` |
| iOS | 정적 라이브러리(`.a`)를 앱에 링크하고 `DllImport("__Internal")`로 호출한다 |

위 표는 일반적인 설정이며 Unity 버전과 대상 플랫폼 문서에서 확인해야 한다(확인 필요).

## 4. 약어·용어

| 용어 | 뜻 |
|---|---|
| DLL | Dynamic-Link Library |
| ABI | Application Binary Interface. 바이너리 수준의 호출 규약 |
| P/Invoke | Platform Invoke. .NET에서 네이티브 함수를 호출하는 기능 |
| 임포트 라이브러리 | DLL의 함수 목록을 담은 링크용 `.lib` |
