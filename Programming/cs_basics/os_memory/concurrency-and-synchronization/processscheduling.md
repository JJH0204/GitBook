## 1. 목적

스케줄링(scheduling)은 준비 큐의 프로세스 중 다음에 CPU를 받을 프로세스를 고르는 일이다. 알고리즘마다 평균 대기 시간, 응답성, 공정성이 다르다.

## 2. 구성 요소

### 2.1 선점과 비선점

| 구분 | 내용 |
|---|---|
| 비선점(Non-Preemptive) | 프로세스가 종료하거나 스스로 CPU를 내놓을 때까지 다른 프로세스가 CPU를 가져가지 못한다 |
| 선점(Preemptive) | 다른 프로세스가 CPU를 요청하면 실행 중인 프로세스를 중단시킨다 |

### 2.2 알고리즘 분류

| 알고리즘 | 선점 여부 | 선택 기준 | 주된 단점 |
|---|---|---|---|
| FIFO(FCFS) | 비선점 | 도착 순서 | 긴 작업이 앞에 오면 평균 대기 시간이 길어진다 |
| SJF | 비선점 | 실행 시간이 가장 짧은 것 | 실행 시간 예측이 어렵다. 긴 작업이 기아에 빠질 수 있다 |
| HRN | 비선점 | 응답 비율이 가장 높은 것 | 스케줄링 시점마다 비율을 다시 계산한다 |
| SRT | 선점 | 남은 실행 시간이 가장 짧은 것 | 기아, 잦은 선점의 문맥 교환 비용 |
| Round Robin(RR) | 선점 | 시간 할당량 순환 | 할당량이 너무 짧으면 문맥 교환이 잦다 |
| Priority | 선점·비선점 모두 가능 | 우선순위 | 기아 |
| Deadline(EDF) | 선점·비선점 모두 가능 (선점형이 일반적) | 마감 시간이 가장 이른 것 | 마감만으로는 중요도를 고려하기 어렵다 |
| Rate Monotonic(RM) | 선점형 고정 우선순위가 정석 | 주기가 짧을수록 높은 우선순위 | 스케줄 가능 조건이 EDF보다 엄격하다 |
| MQ | 큐마다 다름 | 큐 우선순위 후 큐별 알고리즘 | 기아, 설계 복잡 |
| MFQ | 선점 | 큐 사이 이동 | 설계·조정 복잡 |

### 2.3 성능 지표

| 지표 | 정의 |
|---|---|
| 대기 시간(Waiting Time) | 준비 큐에서 실행 전까지 기다린 시간 |
| 반환 시간(Turnaround Time) | 도착부터 종료까지 걸린 전체 시간 |
| 응답 시간(Response Time) | 도착부터 처음 CPU를 받기까지의 시간 |

도착 시각이 같다면 대기 시간 = 반환 시간 − 실행 시간(버스트 시간)이다.

## 3. 동작 원리

### 3.1 Priority (우선순위 방식)

* 각 프로세스에 우선순위를 부여하고 가장 높은 프로세스를 먼저 실행한다.
* 숫자가 작을수록 높은 우선순위로 쓰는 시스템이 많으나 OS마다 규칙이 다르다.
* 장점: 긴급하거나 중요한 작업을 먼저 처리하고 유연하다.
* 단점: 낮은 우선순위 프로세스가 CPU를 받지 못하는 기아가 생긴다. 대기 시간이 길어질수록 우선순위를 올리는 에이징(aging)으로 완화한다.

### 3.2 Deadline: EDF와 RM

* 실시간 시스템(real-time system)에서 쓰는 방식이다. 각 작업이 마감 시간(deadline) 안에 끝나야 하는 경우에 유리하다.
* EDF(Earliest Deadline First): 가장 이른 마감 시간을 가진 작업을 먼저 실행한다. 선점형에서 CPU 사용률 합이 1 이하이면 스케줄 가능하다.
* RM(Rate Monotonic): 작업 주기가 짧을수록 높은 우선순위를 준다. 선점형 고정 우선순위 방식이다. n개 작업의 CPU 사용률 합이 n(2^(1/n) − 1) 이하이면 스케줄 가능이 보장된다(n이 크면 약 69%).
* 장점: 시간 제약을 만족시키는 데 적합하다.
* 단점: 일반 목적 OS에서는 잘 쓰이지 않는다(Linux에는 `SCHED_DEADLINE` 정책이 있다). 마감만으로 작업의 중요도나 실행 시간을 충분히 반영하기 어렵다.

### 3.3 FIFO

* 먼저 도착한 프로세스를 먼저 실행한다. 큐에 도착한 순서대로 CPU를 할당한다.
* 장점: 구현이 간단해 교육용으로 자주 쓴다.
* 단점: 실행 시간이 긴 프로세스가 먼저 오면 뒤의 짧은 프로세스가 오래 기다린다(호송 효과, convoy effect). 응답성과 공정성이 떨어진다.

### 3.4 SJF

* 실행 시간이 가장 짧은 프로세스를 먼저 실행한다. 비선점 알고리즘 중 평균 대기 시간이 가장 짧다(이론적 최적). 단 실행 시간(버스트 타임)을 미리 알아야 한다.
* 단점: 실행 시간 예측이 어렵다(보통 과거 실행 통계로 추정). 긴 작업이 계속 밀려 기아가 생길 수 있다.

### 3.5 HRN

* 대기 시간과 실행 시간으로 우선순위를 동적으로 계산해 응답 비율이 가장 높은 프로세스를 먼저 실행한다.
* 응답 비율 = (대기 시간 + 서비스 시간) / 서비스 시간. 서비스 시간은 예상 실행 시간이다.
* 짧은 작업은 비율이 높아 빨리 실행되고, 긴 작업도 오래 기다리면 비율이 올라가 실행된다. SJF의 기아 문제를 완화한다.
* 단점: 스케줄링 시점마다 비율을 다시 계산해야 한다.

### 3.6 Round Robin (RR)

* 시간 할당량(time quantum)을 정하고 준비 큐의 프로세스를 순환하며 실행한다. 할당량을 다 쓰고도 끝나지 않으면 큐 뒤로 보낸다.
* 모든 프로세스가 동등한 기회를 얻으므로 빠른 응답이 필요한 시분할 시스템(time-sharing system)에 적합하다.
* 할당량이 너무 짧으면 문맥 교환이 너무 자주 일어나 성능이 떨어지고, 너무 길면 FIFO와 비슷해진다.

### 3.7 SRT

* SJF의 선점형 버전이다. 새 프로세스가 도착할 때마다 남은 실행 시간이 가장 짧은 프로세스를 선택한다.
* 평균 대기 시간 면에서 최적이다. 하드 실시간 보장과는 무관하며 실시간용은 EDF·RM이다.
* 단점: SJF처럼 기아가 생기고 잦은 선점으로 문맥 교환에 CPU를 쓴다.

### 3.8 MQ와 MFQ

* MQ(다단계 큐): 여러 큐를 두고 프로세스 종류별로 따로 관리한다. 큐마다 다른 알고리즘을 쓸 수 있고, 우선순위가 높은 큐부터 실행한다. 장점은 유연성(대화형 프로세스 우선, 실시간·비실시간 구분)이고, 단점은 기아 가능성(에이징으로 완화)과 설계 복잡도다. 정적 MQ는 프로세스가 큐 사이를 옮기지 못해 유연성이 떨어진다.
* MFQ(다단계 피드백 큐): MQ를 보완해 프로세스가 큐 사이를 이동한다. CPU를 많이 쓰는 프로세스는 낮은 우선순위 큐로 내려가고, 입출력 중심 프로세스는 높은 우선순위를 유지한다. 큐마다 다른 시간 할당량과 알고리즘을 쓸 수 있다.

### 3.9 계산 예제

도착 시각이 모두 0이고 실행 시간이 P1 = 6, P2 = 3, P3 = 1인 프로세스를 도착 순서(P1, P2, P3)로 둔다.

| 알고리즘 | 간트 차트 (시간 축) | P1 대기 | P2 대기 | P3 대기 | 평균 대기 |
|---|---|---|---|---|---|
| FIFO | P1 (0~6), P2 (6~9), P3 (9~10) | 0 | 6 | 9 | 5.00 |
| SJF | P3 (0~1), P2 (1~4), P1 (4~10) | 4 | 1 | 0 | 1.67 |
| RR (할당량 2) | P1 (0~2), P2 (2~4), P3 (4~5), P1 (5~7), P2 (7~8), P1 (8~10) | 4 | 5 | 4 | 4.33 |

RR 대기 시간은 종료 시각 − 실행 시간이다(P1: 10 − 6, P2: 8 − 3, P3: 5 − 1). 같은 프로세스에서 FIFO는 평균 5.00, SJF는 1.67이다. SJF가 짧은 작업을 앞세워 평균을 줄인다.

| HRN | Highest Response ratio Next |
| EDF | Earliest Deadline First |
| RM | Rate Monotonic |
| MQ/MFQ | Multilevel Queue / Multilevel Feedback Queue |
