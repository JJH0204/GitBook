## 1. 목적

임계 구역을 보호하고 실행 순서를 맞추는 도구와, 그 도구를 잘못 쓸 때 생기는 교착 상태를 정리한다.

## 2. 구성 요소

### 2.1 도구 비교

| 도구 | 개념 | 소유권 | 대표 용도 |
|---|---|---|---|
| 뮤텍스(mutex) | 잠금 하나. lock, unlock | 있다. 잠근 스레드가 푼다 | 임계 구역의 상호 배제 |
| 세마포어(semaphore) | 정수 카운터와 `wait`(P), `signal`(V) 연산 | 없다. 다른 흐름이 signal할 수 있다 | 자원 N개의 접근 제한(카운팅), 실행 순서 신호 |
| 이진 세마포어 | 값이 0 또는 1인 세마포어 | 없다 | 신호 전달, 뮤텍스 대용(소유권 없음에 주의) |
| 모니터(monitor) | 공유 데이터와 이를 다루는 함수를 묶고 한 번에 한 흐름만 진입시키는 언어 수준 구조, 조건 변수 포함 | 있다 | Java `synchronized`, C# `lock` |
| 스핀락(spinlock) | 잠금을 얻을 때까지 반복 검사(busy waiting) | 보통 있다 | 임계 구역이 매우 짧은 멀티코어 커널 코드 |

* 뮤텍스는 "잠금", 세마포어는 "신호와 개수"라고 구분한다.
* 스핀락은 대기 중에도 CPU를 쓰므로 코어가 하나이거나 임계 구역이 길면 낭비다. 대기 시간이 길면 잠들어 기다리는 뮤텍스가 낫다.

### 2.2 세마포어 연산

| 연산 | 동작 |
|---|---|
| `wait(S)` (P) | S를 1 줄인다. 줄이기 전에 S가 0이면 양수가 될 때까지 대기한다 |
| `signal(S)` (V) | S를 1 늘리고, 대기 중인 흐름이 있으면 하나를 깨운다 |

두 연산은 원자적으로 실행되어야 한다.

## 3. 동작 원리

### 3.1 예제: 생산자-소비자 (유한 버퍼, 의사 코드)

버퍼 크기가 N인 경우다. 의사 코드이며 실행하지 않았다.

```
semaphore mutex = 1;   // 버퍼 접근 보호
semaphore empty = N;   // 빈 칸 수
semaphore full  = 0;   // 찬 칸 수

producer:
    wait(empty);       // 빈 칸이 있을 때까지 대기
    wait(mutex);
    버퍼에 항목 추가
    signal(mutex);
    signal(full);      // 찬 칸 +1

consumer:
    wait(full);        // 찬 칸이 있을 때까지 대기
    wait(mutex);
    버퍼에서 항목 제거
    signal(mutex);
    signal(empty);     // 빈 칸 +1
```

{% hint style="warning" %}
CAUTION: 생산자에서 `wait(mutex)`를 `wait(empty)`보다 먼저 호출하면 교착 상태가 생긴다. 버퍼가 가득 찼을 때 생산자가 mutex를 쥔 채 empty를 기다리고, 소비자는 mutex를 얻지 못해 empty를 늘리지 못한다. 개수 확인(`empty`, `full`)을 먼저, 상호 배제(`mutex`)를 나중에 한다.
{% endhint %}

### 3.2 교착 상태

교착 상태(deadlock)는 여러 프로세스가 서로 상대가 가진 자원을 기다리며 아무도 진행하지 못하는 상태다. 아래 4가지가 모두 성립할 때 발생한다(Coffman 조건).

| 조건 | 뜻 |
|---|---|
| 상호 배제 | 자원을 한 번에 한 프로세스만 쓴다 |
| 점유 대기(hold and wait) | 자원을 쥔 채 다른 자원을 기다린다 |
| 비선점(no preemption) | 쥔 자원을 강제로 빼앗을 수 없다 |
| 순환 대기(circular wait) | 대기 관계가 원형으로 이어진다 |

예: 스레드 1이 잠금 A를 쥐고 B를 기다리고, 스레드 2가 B를 쥐고 A를 기다린다.

### 3.3 대응 방법

| 방법 | 내용 | 예 |
|---|---|---|
| 예방(prevention) | 4조건 중 하나를 깬다 | 잠금을 항상 같은 순서로 얻어 순환 대기를 없앤다 |
| 회피(avoidance) | 자원 요청마다 안전 상태인지 검사한다 | 은행원 알고리즘 |
| 탐지와 복구 | 교착을 감지하고 프로세스를 종료하거나 자원을 회수한다 | 대기 그래프 검사 |
| 무시 | 드물게 일어나므로 처리하지 않는다 | 많은 범용 OS |

## 4. 한계·주의

* 상호 배제 3요건(상호 배제, 진행, 한정 대기)과 교착 4조건은 다른 목록이다([임계 구역](criticalsection.md)).
* 뮤텍스는 잠근 스레드가 풀어야 한다. 이진 세마포어는 아무 흐름이나 signal할 수 있다.
* 교착 상태와 기아는 다르다. 기아는 일부 프로세스만 계속 밀리는 상태이고 시스템은 진행한다.

## 5. 약어·용어

| 용어 | 뜻 |
|---|---|
| P, V | 세마포어 연산의 전통 이름(네덜란드어 proberen, verhogen) |
| busy waiting | 조건이 참이 될 때까지 CPU를 쓰며 반복 검사하는 대기 |
| 조건 변수 | 모니터 안에서 어떤 조건이 참이 될 때까지 기다리게 하는 장치 |
