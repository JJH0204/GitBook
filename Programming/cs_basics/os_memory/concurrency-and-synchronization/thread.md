## 1. 목적

스레드(thread)는 프로세스 안에서 실행되는 제어 흐름의 단위다. 프로세스보다 작은 단위이며 처리 능률을 높이려고 쓴다. 한 프로세스가 여러 스레드를 가지면 각 스레드가 개별 제어 흐름을 갖고 병행 실행된다.

## 2. 구성 요소

### 2.1 프로세스와 스레드의 비교

| 항목 | 프로세스 | 스레드 |
|---|---|---|
| 주소 공간 | 프로세스마다 독립 | 같은 프로세스의 스레드가 공유 |
| 코드, 데이터, 힙 | 독립 | 공유 |
| 열린 파일 | 독립 | 공유 |
| 스택 | 독립 | 스레드마다 개별 |
| 레지스터, PC | 독립 | 스레드마다 개별 |
| 생성·전환 비용 | 큼 | 작음 |
| 통신 | IPC(파이프, 소켓, 공유 메모리 등)가 필요 | 공유 변수로 바로 통신. 대신 동기화가 필요 |
| 한쪽이 비정상 종료하면 | 다른 프로세스는 영향 없음 | 프로세스 전체가 종료될 수 있음 |

### 2.2 커널 스레드와 사용자 스레드

| 구분 | 제어 주체 | 특징 |
|---|---|---|
| 커널 스레드 | 운영체제 | 커널이 직접 스케줄링한다. 멀티코어에서 병렬 실행이 가능하다 |
| 사용자 스레드 | 사용자가 만든 라이브러리 | 커널은 존재를 모른다. 전환이 빠르나 한 스레드가 블로킹 호출을 하면 프로세스 전체가 멈출 수 있다 |

### 2.3 매핑 모델

| 모델 | 구성 | 예 |
|---|---|---|
| 1:1 | 사용자 스레드 하나가 커널 스레드 하나에 대응한다 | Linux(NPTL), Windows |
| N:1 | 사용자 스레드 여러 개가 커널 스레드 하나에 대응한다 | 초기 그린 스레드 |
| M:N | 사용자 스레드 M개가 커널 스레드 N개에 대응한다 | 일부 런타임의 경량 스레드 |

## 3. 동작 원리

멀티스레드의 이점은 응답성(한 스레드가 I/O를 기다려도 다른 스레드가 진행), 자원 공유, 멀티코어 활용이다. 위험은 공유 데이터에 대한 경쟁 상태다. 같은 변수를 두 스레드가 동시에 바꾸면 결과가 틀어질 수 있으며 이는 [임계 구역](criticalsection.md)에서 다룬다.

### 3.1 Unity와의 연결

* Unity의 대부분의 API는 메인 스레드에서만 호출해야 한다. 다른 스레드에서 `Transform` 등을 만지면 예외가 난다.
* 무거운 계산은 별도 스레드, C# `Task`, 또는 Unity의 Job System으로 보내고 결과만 메인 스레드에서 적용한다.

## 4. 약어·용어

| 용어 | 뜻 |
|---|---|
