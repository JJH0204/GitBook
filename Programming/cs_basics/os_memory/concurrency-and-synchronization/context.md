## 1. 목적

여러 프로세스가 한 CPU를 나눠 쓰려면 실행 중이던 프로세스의 상태를 저장했다가 나중에 이어서 실행해야 한다. 이 상태가 컨텍스트(context)다. 이 문서는 컨텍스트와 이를 바꾸는 컨텍스트 스위치(context switch, 문맥 교환)를 설명한다.

## 2. 구성 요소

### 2.1 CPU 컨텍스트

| 항목 | 설명 |
|---|---|
| 프로그램 카운터(PC) | 다음에 실행할 명령의 주소 |
| 범용 레지스터 | 연산 중인 값 |
| 스택 포인터 | 현재 스택의 꼭대기 |
| 상태·플래그 레지스터 | 비교·연산 결과 플래그 |
| 주소 공간 정보 | 프로세스의 페이지 테이블을 가리키는 값(프로세스 전환 시 바뀐다) |

컨텍스트는 [프로세스 제어 블록](pcb.md)(PCB)에 저장된다. PCB는 컨텍스트에 더해 프로세스 식별자, 상태, 우선순위, 열린 파일 목록 같은 관리 정보를 가진다.

### 2.2 프로세스 상태

| 상태 | 설명 |
|---|---|
| 생성(new) | 프로세스를 만드는 중 |
| 준비(ready) | CPU를 받을 수 있으나 기다리는 중 |
| 실행(running) | CPU에서 실행 중 |
| 대기(waiting, blocked) | I/O 완료 등 사건을 기다리는 중 |
| 종료(terminated) | 실행을 마침 |

## 3. 동작 원리

프로세스 A에서 B로 CPU를 넘길 때의 순서다.

| 순서 | 동작 |
|---|---|
| 1 | 타이머 인터럽트, I/O 요청, 시스템 호출 등으로 커널이 개입한다 |
| 2 | 커널이 A의 컨텍스트를 A의 PCB에 저장한다 |
| 3 | A의 상태를 준비 또는 대기로 바꾼다 |
| 4 | 스케줄러가 다음에 실행할 프로세스 B를 고른다([프로세스 스케줄링](processscheduling.md)) |
| 5 | B의 PCB에서 컨텍스트를 레지스터에 복원한다(필요하면 주소 공간도 B의 것으로 바꾼다) |
| 6 | B의 상태를 실행으로 바꾸고 B의 PC부터 이어서 실행한다 |

### 3.1 비용

* 컨텍스트 스위치 중에는 CPU가 사용자 작업을 하지 못하므로 순수한 오버헤드다.
* 직접 비용: 레지스터 저장·복원, 커널의 스케줄링 코드 실행.
* 간접 비용: 프로세스가 바뀌면 캐시와 TLB(주소 변환 캐시) 내용이 새 프로세스에 맞지 않아 한동안 느려진다.
* 같은 프로세스 안의 스레드 사이 전환은 주소 공간을 바꾸지 않아 프로세스 사이 전환보다 비용이 작다([스레드 개념](thread.md)).
* 시간 할당량이 너무 짧으면 전환이 잦아 성능이 떨어진다.

## 4. 약어·용어

| 용어 | 뜻 |
|---|---|
| PC | Program Counter. 다음 명령의 주소 |
| PCB | Process Control Block. 프로세스 제어 블록 |
| TLB | Translation Lookaside Buffer. 가상 주소를 물리 주소로 바꾼 결과의 캐시 |
| 인터럽트 | 하드웨어나 소프트웨어가 CPU에 보내는 처리 요청 신호 |
