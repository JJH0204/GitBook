## 1. 목적

여러 프로세스(또는 스레드)가 시간상 겹쳐 진행되는 상황을 병행 프로세스(concurrent process)라 한다. 이 문서는 병행 실행의 이유와 그에 따라 생기는 문제를 정리한다.

## 2. 구성 요소

### 2.1 병행과 병렬

| 구분 | 뜻 | 필요한 하드웨어 |
|---|---|---|
| 병행(concurrency) | 여러 작업이 겹쳐 진행된다. 시간을 쪼개 번갈아 실행해도 병행이다 | 코어 1개로 충분하다 |
| 병렬(parallelism) | 여러 작업이 같은 순간에 실제로 실행된다 | 코어 2개 이상 |

### 2.2 병행 실행의 이유

| 이유 | 설명 |
|---|---|
| 자원 활용 극대화 | CPU, I/O 같은 자원을 놀리지 않는다. 한 프로세스가 I/O를 기다리는 동안 다른 프로세스가 CPU를 쓴다 |
| 응답성 향상 | 사용자와의 상호작용이 빠르다 |
| 구조적 프로그램 설계 | 독립적인 모듈로 나눌 수 있다 |
| 멀티코어 활용 | 병렬 실행으로 처리량을 높인다 |

### 2.3 프로세스 간 관계

| 유형 | 설명 |
|---|---|
| 독립적 | 서로 상호작용하지 않는다. 자원을 공유하지 않는다 |
| 협력적 | 자원을 공유하거나 데이터를 교환한다. 동기화가 필요하다 |

## 3. 동작 원리

병행 실행에서 협력 프로세스가 공유 자원을 다룰 때 아래 문제가 생긴다.

| 개념 | 설명 | 상세 문서 |
|---|---|---|
| 상호 배제(Mutual Exclusion) | 둘 이상의 프로세스가 공유 자원에 동시에 접근하지 못하게 하는 원칙 | [상호 배제](mutualexclusion.md) |
| 동기화(Synchronization) | 프로세스 간 실행 순서를 조절한다 | [동기화 도구와 교착 상태](synchronization-primitives.md) |
| 교착 상태(Deadlock) | 여러 프로세스가 서로 자원을 기다리며 아무도 진행하지 못하는 상태 | [동기화 도구와 교착 상태](synchronization-primitives.md) |
| 문맥 교환(Context Switching) | 운영체제가 CPU를 한 프로세스에서 다른 프로세스로 넘기는 과정. 코어가 하나여도 시분할로 병행을 구현하게 해 준다 | [컨텍스트 개념](context.md) |

## 4. 약어·용어

| 용어 | 뜻 |
|---|---|
| 시분할(time-sharing) | CPU 시간을 짧은 조각으로 나눠 번갈아 할당하는 방식 |
| 공유 자원 | 둘 이상의 실행 흐름이 접근하는 변수, 파일, 장치 |
