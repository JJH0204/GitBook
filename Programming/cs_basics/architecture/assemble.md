## 1. 목적

어셈블(Assemble)은 컴파일로 생성된 어셈블리어 코드를 목적 파일(Object file)로 변환하는 과정이다. Linux에서 목적 파일은 [ELF](../os_memory/executables-and-linking/elf.md) 형식이다. 목적 파일은 기계어로 번역되므로 더 이상 사람이 읽기 어렵다.

## 2. 구성 요소

| 단계 | 입력 | 출력 | 비고 |
|---|---|---|---|
| 전처리·컴파일 | 소스 코드 | 어셈블리 코드(`.s`, `.S`) | `.S`는 전처리가 필요한 어셈블리 파일 |
| 어셈블 | 어셈블리 코드 | 목적 파일(`.o`, Windows는 `.obj`) | gcc `-c` 옵션 |
| 링크 | 목적 파일, 라이브러리 | 실행 파일 | 이 문서 범위 밖 |

운영체제별 목적 파일 형식은 다음과 같다.

| 운영체제 | 목적 파일 | 실행 파일 |
|---|---|---|
| Linux | ELF (relocatable) | ELF |
| Windows | COFF (`.obj`) | PE (`.exe`, `.dll`) |

## 3. 동작 원리

gcc의 `-c` 옵션으로 `add.S` 파일을 목적 파일로 변환하고, 결과 파일을 16진수로 출력한다.

### 3.1 헤더 해석

| 오프셋 | 바이트 | 의미 |
|---|---|---|
| 0x00 ~ 0x03 | `7f 45 4c 46` | ELF 매직 (0x7f, 'E', 'L', 'F') |
| 0x04 | `02` | 64비트 (ELFCLASS64) |
| 0x05 | `01` | 리틀 엔디언 |
| 0x06 | `01` | ELF 버전 1 |
| 0x10 ~ 0x11 | `01 00` | 파일 종류: 재배치 가능 목적 파일 (REL) |
| 0x12 ~ 0x13 | `3e 00` | 대상 머신: x86-64 (0x3e) |

### 3.2 코드 영역 해석 (오프셋 0x40)

`55 48 89 e5 89 7d fc 89 75 f8 8b 55 fc 8b 45 f8 01 d0 5d c3`는 다음 기계어로 읽힌다(Intel 문법, 확인 필요).

| 바이트 | 명령어 | 설명 |
|---|---|---|
| `55` | `push rbp` | 이전 rbp 저장 |
| `48 89 e5` | `mov rbp, rsp` | 프레임 설정 |
| `89 7d fc` | `mov [rbp-4], edi` | 첫째 인자(System V에서 edi) 저장 |
| `89 75 f8` | `mov [rbp-8], esi` | 둘째 인자(esi) 저장 |
| `8b 55 fc` | `mov edx, [rbp-4]` | 첫째 인자 읽기 |
| `8b 45 f8` | `mov eax, [rbp-8]` | 둘째 인자 읽기 |
| `01 d0` | `add eax, edx` | eax = eax + edx |
| `5d` | `pop rbp` | rbp 복원 |
| `c3` | `ret` | 복귀 (반환 값은 eax) |

이 코드는 두 정수 인자를 더해 반환하는 함수로 보인다. `add.S`의 원본 소스는 원본에 없어 확인하지 못했다.

읽을 수 있는 문자열 중 코드로 보이는 것은 없다. 오프셋 0x55 이후의 `GCC: (Ubuntu 7.5.0...)`는 컴파일러 버전 문자열이다.

## 4. 약어·용어

| 용어 | 뜻 |
|---|---|
| 목적 파일 | Object file. 링크 전의 기계어 파일 |
| ELF | Executable and Linkable Format. Linux 실행·목적 파일 형식 |
| COFF / PE | Common Object File Format / Portable Executable. Windows의 목적 / 실행 파일 형식 |
| REL | 재배치 가능(Relocatable) 파일 종류 |
