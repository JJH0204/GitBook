# UML 다이어그램 개요

## 작업 식별

| 항목 | 내용 |
|---|---|
| Task ID | PRG-UML-001-DO |
| 유형 | D&O (개념) |
| 목적 | UML 2.x 다이어그램 14종을 구조/행위로 분류해 설명한다 |
| 확인 상태 | 미검증 (원본과 표준 문서 지식으로 작성했으며 이 환경에서 도구로 확인하지 않았다) |
| 개정 | R1 (2026-11-18) |

## 1. 정의

UML 다이어그램은 소프트웨어 시스템의 구조와 동작을 그림으로 표현하는 표준 표기법이다. UML 2.x는 다이어그램 14종을 정의하며 구조 다이어그램 7종과 행위 다이어그램 7종으로 나눈다.

## 2. 구성 요소

### 2.1 UML의 특징

| 특징 | 설명 |
|---|---|
| 표준 모델링 언어 | OMG(Object Management Group)가 관리하는 공통 표준이다 |
| 객체지향 기반 | 객체지향 프로그래밍 개념을 바탕으로 한다 |
| 시각적 표현 | 복잡한 구조와 동작을 그림으로 표현한다 |
| 전 과정 사용 | 요구 분석, 설계, 구현, 테스트에서 활용한다 |
| 확장성 | 스테레오타입과 프로파일로 사용자 정의 확장이 가능하다 |

### 2.2 구조 다이어그램 (Structural Diagrams, 7종)

시스템의 정적인 요소와 그 관계를 표현한다.

| 다이어그램 | 표현 대상 |
|---|---|
| 클래스 다이어그램 (Class Diagram) | 클래스, 속성, 연산, 관계 |
| 객체 다이어그램 (Object Diagram) | 특정 시점의 객체 인스턴스와 연결 |
| 컴포넌트 다이어그램 (Component Diagram) | 소프트웨어 구성 요소 사이의 관계 |
| 배치 다이어그램 (Deployment Diagram) | 하드웨어 노드와 소프트웨어의 배치 |
| 패키지 다이어그램 (Package Diagram) | 클래스와 모듈의 그룹화와 의존 |
| 복합 구조 다이어그램 (Composite Structure Diagram) | 클래스 내부 구조와 부분 사이의 연결 |
| 프로파일 다이어그램 (Profile Diagram) | 스테레오타입 등 UML 확장 정의 |

### 2.3 행위 다이어그램 (Behavioral Diagrams, 7종)

시스템의 동적인 동작을 표현한다.

| 다이어그램 | 표현 대상 |
|---|---|
| 유스케이스 다이어그램 (Use Case Diagram) | 사용자(액터)와 시스템의 상호작용 |
| 활동 다이어그램 (Activity Diagram) | 업무·처리의 흐름 |
| 상태 다이어그램 (State Machine Diagram) | 객체의 상태 변화 |
| 시퀀스 다이어그램 (Sequence Diagram) | 객체 사이 메시지의 시간 순서 |
| 커뮤니케이션 다이어그램 (Communication Diagram) | 객체 사이 메시지 교환과 연결 구조 |
| 상호작용 개요 다이어그램 (Interaction Overview Diagram) | 여러 상호작용 다이어그램의 흐름 조합 |
| 타이밍 다이어그램 (Timing Diagram) | 시간 축에 따른 상태 변화 |

{% hint style="info" %}
NOTE: 시퀀스, 커뮤니케이션, 상호작용 개요, 타이밍 다이어그램 4종은 행위 다이어그램 안의 상호작용 다이어그램(Interaction Diagrams) 하위 분류다. 상호작용은 행위와 병렬인 분류가 아니다. UML 1.x는 다이어그램이 9종이었고 2.0부터 13종, 2.x 이후 프로파일 다이어그램을 포함해 14종으로 센다. 문서와 도구에 따라 13종 또는 14종으로 쓰이므로 기준 버전을 확인한다.
{% endhint %}

## 3. 동작 원리

다이어그램은 같은 모델을 다른 관점에서 보여 주는 뷰다. 한 시스템을 설명할 때 목적에 맞는 다이어그램을 고른다.

```
무엇으로 이루어져 있는가?     -> 구조 다이어그램 (클래스, 컴포넌트, 배치 ...)
어떻게 동작하는가?            -> 행위 다이어그램 (시퀀스, 상태, 활동 ...)
```

## 4. 장점

* 구조와 동작을 시각적으로 표현한다.
* 표준 표기여서 개발자 사이의 의사소통이 쉽다.
* 객체지향 설계에 맞는 표기를 제공한다.
* 분석부터 구현까지 같은 표기를 유지한다.

## 5. 약어·용어

| 약어 | 원어 | 뜻 |
|---|---|---|
| UML | Unified Modeling Language | 통합 모델링 언어 |
| OMG | Object Management Group | UML 표준을 관리하는 단체 |
| 스테레오타입 | Stereotype | `<<interface>>`처럼 기존 요소에 의미를 덧붙이는 확장 표기 |
