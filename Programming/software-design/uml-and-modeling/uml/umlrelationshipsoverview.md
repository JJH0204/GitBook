## 1. 정의

UML 관계는 클래스, 객체, 컴포넌트 같은 요소 사이의 연결을 표현한다. 클래스 다이어그램, 객체 다이어그램, 컴포넌트 다이어그램 등에서 쓴다.

## 2. 구성 요소

| 관계 | 영문 | 기호 | 의미 | 코드 대응 |
|---|---|---|---|---|
| 연관 | Association | 실선. 방향이 있으면 끝에 열린 화살표 | 한 클래스가 다른 클래스를 필드로 가진다 | 멤버 변수 |
| 집합 | Aggregation | 전체 쪽에 속이 빈 마름모 `◇` | 전체-부분 관계. 부분이 독립적으로 존재한다 | 외부에서 받은 객체 참조 |
| 합성 | Composition | 전체 쪽에 속이 찬 마름모 `◆` | 강한 전체-부분 관계. 부분이 전체와 수명을 함께한다 | 전체가 부분을 생성·소유 |
| 일반화 | Generalization | 실선 + 상위 클래스 쪽 속이 빈 삼각형 `▷` | 상속(is-a) | `extends` |
| 실체화 | Realization | 점선 + 인터페이스 쪽 속이 빈 삼각형 `▷` | 인터페이스 구현 | `implements` |
| 의존 | Dependency | 점선 + 열린 화살표 | 일시적 사용. 매개변수, 지역 변수, 반환 타입 등 | 메서드 내 사용 |

## 3. 동작 원리

### 3.1 기호 (텍스트 표기)

화살표 방향은 "의존하는 쪽 → 의존 대상"이다. 일반화·실체화는 하위 → 상위다.

```
연관(양방향)   A ─────────── B
연관(방향)     A ─────────> B
집합           Department ◇────────── Employee
합성           House      ◆────────── Room
일반화         Dog ─────────▷ Animal
실체화         Dog ┄┄┄┄┄┄┄┄▷ Animal     (Animal이 인터페이스일 때)
의존           A ┄┄┄┄┄┄┄┄> B
```

### 3.2 다중도(Multiplicity)

관계의 양 끝에 연결 개수를 적는다.

| 표기 | 의미 |
|---|---|
| `1` | 정확히 1개 |
| `0..1` | 0개 또는 1개 |
| `*` 또는 `0..*` | 0개 이상 |
| `1..*` | 1개 이상 |

```
Department 1 ◇────────── 0..* Employee
```

### 3.3 집합과 합성의 차이

| 구분 | 집합 | 합성 |
|---|---|---|
| 부분의 독립성 | 전체 없이도 존재한다 | 전체 없이는 존재하지 않는다 |
| 전체 소멸 시 | 부분은 남는다 | 부분도 함께 소멸한다 |
| 한 부분이 속하는 전체 | 여러 전체와 공유할 수 있다 | 한 전체에만 속한다 |

## 4. 예제 코드 (Java)

원본은 Java와 C#을 섞어 썼다. 아래는 Java로 통일하고 각 관계에 대응하는 코드를 보인다.

```java
import java.util.List;

interface Animal { void speak(); }                  // 실체화 대상

class Dog implements Animal {                       // 실체화: Dog ┄▷ Animal
    public void speak() { System.out.println("멍"); }
}

class Puppy extends Dog { }                         // 일반화: Puppy ─▷ Dog

class Employee { }

class Department {                                  // 집합: Department ◇─ Employee
    private final List<Employee> employees;         // 외부에서 받은 객체를 참조
    Department(List<Employee> employees) { this.employees = employees; }
}

class Room { }

class House {                                       // 합성: House ◆─ Room
    private final Room room = new Room();           // 전체가 부분을 직접 생성·소유
}

class A {
    private Dog dog;                                // 연관: A ─> Dog (필드)

    void walk(Dog d) {                              // 의존: A ┄> Dog (매개변수)
        d.speak();
    }
}
```

## 5. 한계·주의

{% hint style="info" %}
NOTE: 의존 < 연관 < 집합 < 합성 순으로 결합이 강해진다고 보는 것이 관례다. UML 표준이 정한 순서는 아니다. 일반화(상속)는 결합 강도 척도에 넣지 않고 따로 구분하는 편이 정확하다. 상속은 가장 강한 결합이라고 설명하기도 한다.
{% endhint %}

* 집합과 합성의 구분은 코드가 아니라 설계 의도로 정한다. 같은 코드가 한 설계에서는 집합, 다른 설계에서는 합성일 수 있다.
* 집합은 UML 2.x에서도 의미가 약해 쓰지 말라는 의견이 있다. 팀 규칙에 따라 연관으로 통일하기도 한다.
* 의존은 매개변수, 지역 변수, 반환 타입처럼 일시적으로 쓰는 경우다. "실행 시점에서만 영향을 준다"는 표현은 부정확하다. 컴파일 시점에도 타입 의존이 생긴다.

## 6. 약어·용어

| 용어 | 뜻 |
|---|---|
| is-a | 일반화(상속) 관계를 부르는 말 |
| has-a | 연관, 집합, 합성처럼 객체를 소유·참조하는 관계 |
| 다중도(Multiplicity) | 관계 양 끝의 연결 개수 |
