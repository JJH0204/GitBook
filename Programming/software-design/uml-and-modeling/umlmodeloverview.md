## 1. 정의

UML(Unified Modeling Language, 통합 모델링 언어)은 소프트웨어 시스템을 시각적으로 표현하는 표준 모델링 언어다. UML 모델은 UML 다이어그램으로 시스템의 구조, 동작, 상호작용을 표현한 결과물이다.

* OMG(Object Management Group)가 표준을 관리한다.
* 특정 프로그래밍 언어나 플랫폼에 종속되지 않는다.
* 개발자, 설계자, 분석가가 같은 그림으로 소통하는 도구다.

{% hint style="info" %}
NOTE: 이 문서는 UML 2.x 기준이다. 다이어그램 종류 수(13종 또는 14종)는 [UML 다이어그램 개요](umldiagramoverview.md)에서 설명한다.
{% endhint %}

## 2. 구성 요소

| 구분 | 설명 | 대표 다이어그램 |
|---|---|---|
| 구조 모델 | 시스템의 정적 구조 | 클래스, 객체, 컴포넌트 |
| 행위 모델 | 시스템의 동적 동작 | 유스케이스, 상태, 활동 |
| 상호작용 | 행위 모델에 속하며 객체 사이 메시지 교환을 표현한다 | 시퀀스, 커뮤니케이션 |

## 3. 동작 원리

### 3.1 객체지향 설계에서의 대응

| 설계 대상 | 쓰는 다이어그램 |
|---|---|
| 시스템 구조 | 클래스 다이어그램 |
| 객체 사이 메시지 흐름 | 시퀀스 다이어그램 |
| 객체의 상태 변화 | 상태 다이어그램 |
| 모듈 구조 | 컴포넌트 다이어그램 |

### 3.2 개발 단계별 활용 예

아래는 자주 쓰는 대응이며 정해진 규칙은 아니다. 프로젝트마다 다르게 쓴다.

| 단계 | 자주 쓰는 다이어그램 |
|---|---|
| 요구사항 분석 | 유스케이스 다이어그램 |
| 설계 | 클래스, 컴포넌트, 시퀀스, 상태 다이어그램 |
| 구현·배포 | 패키지, 배치 다이어그램 |
| 유지보수 | 변경 사항을 모델에 반영 |

### 3.3 소프트웨어 아키텍처 표현

* MVC(Model-View-Controller) 구조를 클래스·컴포넌트 다이어그램으로 표현한다.
* 마이크로서비스 구성을 컴포넌트·배치 다이어그램으로 표현한다.
* 모듈 사이의 상호작용을 시퀀스 다이어그램으로 표현한다.

## 4. 활용상 이점

* 시스템 복잡도를 시각화해 이해를 돕는다.
* 개발 방법론(RUP, 애자일 등)과 함께 쓸 수 있다.
* 설계 변경과 유지보수 때 기준 문서가 된다.

## 5. 약어·용어

| 약어 | 원어 | 뜻 |
|---|---|---|
| UML | Unified Modeling Language | 통합 모델링 언어 |
| OMG | Object Management Group | UML 표준 관리 단체 |
| OOP | Object-Oriented Programming | 객체지향 프로그래밍 |
| RUP | Rational Unified Process | UML을 쓰는 반복적 개발 프로세스 |
| MVC | Model-View-Controller | 모델·뷰·컨트롤러 분리 구조 |
