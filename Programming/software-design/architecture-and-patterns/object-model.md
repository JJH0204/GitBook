## 1. 정의

객체 모델은 시스템을 이루는 객체와 객체 사이의 관계를 정의해 정적 구조를 표현하는 모델이다. 표기는 UML 클래스 다이어그램과 비슷하다.

## 2. 구성 요소

| 요소 | 설명 | 예 |
|---|---|---|
| 객체(Object) | 실세계의 개체 하나. 클래스의 인스턴스다 | 학생 홍길동 |
| 클래스(Class) | 공통 속성과 연산을 가진 객체의 집합 | `Student` |
| 속성(Attribute) | 객체가 가진 데이터. 객체의 상태를 나타낸다 | `studentID`, `name`, `major` |
| 연산(Operation) | 객체가 수행하는 기능. 구현 단위는 메서드다 | `enroll()`, `graduate()` |
| 관계(Relationship) | 객체(클래스) 사이의 연결 | 연관, 집합, 합성, 일반화 |

## 3. 동작 원리

### 3.1 객체와 클래스

비슷한 객체를 묶어 클래스로 정리한다.

```
객체 (인스턴스)
  학생1 -> 이름: 홍길동, 학번: 101, 전공: 컴퓨터공학
  학생2 -> 이름: 김철수, 학번: 102, 전공: 전자공학

클래스
  클래스명: Student
  속성    : 학번, 이름, 전공
  연산    : 등록(), 수강신청(), 졸업()
```

### 3.2 클래스 표기 (UML 클래스 다이어그램 형태)

클래스 상자는 이름, 속성, 연산 세 칸으로 나눈다. `-`는 private, `+`는 public 가시성이다.

```
+----------------+
|    Student     |   <- 이름
+----------------+
| - studentID    |   <- 속성
| - name         |
| - major        |
+----------------+
| + enroll()     |   <- 연산
| + graduate()   |
+----------------+
```

### 3.3 관계 표기

| 관계 | 의미 | 기호 (전체/부모 쪽이 왼쪽) |
|---|---|---|
| 연관(Association) | 두 클래스가 서로 연결된다 | `────` |
| 집합(Aggregation) | 부분-전체 관계. 부분이 독립적으로 존재한다 | `◇────` |
| 합성(Composition) | 부분이 전체에 종속된다. 전체가 사라지면 부분도 사라진다 | `◆────` |
| 일반화(Generalization) | 하위 클래스가 상위 클래스를 상속한다 | `▷────` (속 빈 삼각형이 상위 쪽) |

기호의 정확한 의미와 의존·실체화 관계는 [UML 관계 개요 (Relationships)](../uml-and-modeling/uml/umlrelationshipsoverview.md)에서 설명한다.

### 3.4 객체 모델 작성 순서

1. 시스템에서 필요한 객체(클래스)를 찾는다.
2. 각 클래스의 속성과 연산을 정한다.
3. 클래스 사이의 연관, 집합, 합성, 일반화 관계를 정한다.
4. 클래스 다이어그램으로 그린다.

## 4. 장점

* 시스템 구조를 직관적으로 표현한다.
* 클래스를 재사용하기 쉽다.
* 설계와 구현의 일관성을 유지한다.
* 변경에 유연한 구조를 만들 수 있다.

## 5. 약어·용어

| 용어 | 뜻 |
|---|---|
| 인스턴스(Instance) | 클래스로 만든 실제 객체 |
| 가시성(Visibility) | 멤버 접근 범위. `+` public, `-` private, `#` protected, `~` package |
| 연산과 메서드 | 연산은 명세(이름·인자), 메서드는 그 구현이다 |
