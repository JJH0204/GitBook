## 1. 정의

동적 모델은 시간의 흐름에 따라 객체의 상태가 어떻게 바뀌는지 표현하는 모델이다. 객체가 이벤트를 받으면 상태가 어떻게 변하는지 분석하는 것이 핵심이다. UML 상태 다이어그램(상태 기계 다이어그램)과 개념이 비슷하다.

## 2. 구성 요소

| 요소 | 설명 |
|---|---|
| 상태(State) | 객체가 특정 시점에 가진 속성 값 또는 조건 |
| 이벤트(Event) | 상태를 바꾸는 사건. 사용자 행동, 시스템 신호, 시간 경과 등이다 |
| 상태 전이(State Transition) | 이벤트로 인해 한 상태에서 다른 상태로 바뀌는 것 |
| 상태 다이어그램(State Diagram) | 상태와 전이를 그린 그림 |

## 3. 동작 원리

### 3.1 상태와 이벤트

학생 객체의 상태는 다음 순서로 변한다.

```
미등록 --(등록 신청)--> 등록 완료 --(수강 신청)--> 수강 중 --(졸업)--> 졸업 완료
```

| 단계 | 이벤트 | 이전 상태 | 이후 상태 |
|---|---|---|---|
| 1 | 등록 신청 버튼 클릭 | 미등록 | 등록 완료 |
| 2 | 수강 신청 완료 | 등록 완료 | 수강 중 |
| 3 | 졸업 조건 충족 | 수강 중 | 졸업 완료 |

강의 객체도 같은 방식으로 표현한다.

```
강의 생성 --(학생 등록)--> 강의 진행 --(수업 종료)--> 강의 완료
```

### 3.2 상태 다이어그램 표기

| 요소 | 설명 | 기호 |
|---|---|---|
| 시작 상태(initial) | 객체의 최초 지점 | ● (속이 찬 원) |
| 상태 | 객체가 가질 수 있는 상태 | 모서리가 둥근 사각형 |
| 전이 | 상태 사이의 변화 | 화살표 |
| 이벤트 | 전이를 일으키는 트리거 | 화살표 위의 이름 |
| 종료 상태(final) | 객체의 최종 지점 | ◉ (테두리 있는 속이 찬 원) |

텍스트로 그린 예시는 다음과 같다. `( )`는 둥근 사각형 상태를 뜻한다.

```
●
|
v
(미등록) --등록 신청--> (등록 완료) --수강 신청--> (수강 중) --졸업--> (졸업 완료)
                                                                      |
                                                                      v
                                                                      ◉
```

## 4. 활용 사례

| 사례 | 상태 흐름 |
|---|---|
| 사용자 로그인 | 로그인 버튼 클릭 → 로그인 성공 → 메인 화면 이동 |
| 주문 상태 관리 | 주문 접수 → 결제 완료 → 배송 중 → 배송 완료 |
| ATM | 카드 삽입 → PIN 입력 → 출금 요청 → 현금 인출 |

## 5. 장점

1. 객체의 상태 변화를 명확하게 분석한다.
2. 실시간 시스템 분석에 유용하다.
3. 객체 모델과 결합해 시스템 설계를 보완한다.
4. UML 상태 다이어그램과 연계할 수 있다.

## 6. 약어·용어

| 용어 | 뜻 |
|---|---|
| 트리거(Trigger) | 전이를 일으키는 이벤트 |
| 상태 기계(State Machine) | 상태와 전이로 동작을 정의하는 모델. UML 2.x의 정식 이름은 State Machine Diagram이다 |
