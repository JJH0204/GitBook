## 1. 정의

기능 모델은 시스템이 수행할 기능과 데이터 흐름을 표현하는 모델이다. 데이터가 입력되고, 변환되고, 출력되는 과정을 분석하는 것이 핵심이다. 럼바우 기법에서는 데이터 흐름도(DFD)로 그린다.

* 객체 모델은 구조를, 동적 모델은 상태 변화를, 기능 모델은 데이터의 처리를 정의한다.

{% hint style="info" %}
NOTE: UML 활동 다이어그램(Activity Diagram)도 처리 순서를 표현하지만 OMT 기능 모델의 도구는 아니다. 둘은 관점이 다르다. DFD는 데이터의 이동에, 활동 다이어그램은 제어의 순서에 초점을 둔다.
{% endhint %}

## 2. 구성 요소

| 요소 | 설명 | 예 |
|---|---|---|
| 프로세스(Process) | 입력을 받아 처리하고 출력을 만드는 기능 | 고객 등록, 주문 처리 |
| 데이터 흐름(Data Flow) | 프로세스·저장소·엔티티 사이에서 데이터가 이동하는 경로 | 고객 정보, 주문 정보 |
| 데이터 저장소(Data Store) | 데이터를 보관하고 제공하는 곳 (DB, 파일 등) | 주문 데이터 저장소 |
| 외부 엔티티(External Entity) | 시스템과 데이터를 주고받는 외부 요소 (사용자, 다른 시스템) | 고객, 결제 시스템 |

## 3. 동작 원리

### 3.1 DFD 표기

DFD 표기는 교재와 도구마다 조금씩 다르다. 대표 표기와 이 문서의 텍스트 표기는 다음과 같다.

| 요소 | 대표 도형 | 이 문서의 텍스트 표기 |
|---|---|---|
| 프로세스 | 원 또는 둥근 사각형 | `( 이름 )` |
| 데이터 저장소 | 평행한 두 줄 | `= 이름 =` |
| 외부 엔티티 | 사각형 | `[ 이름 ]` |
| 데이터 흐름 | 이름 붙은 화살표 | `--이름-->` |

### 3.2 예시: 주문 처리

```
[고객] --주문 요청--> ( 주문 처리 ) --주문 정보--> = 주문 데이터 저장소 =
```

### 3.3 예시: 고객 등록

```
[고객] --고객 정보--> ( 고객 등록 ) --고객 레코드--> = 고객 DB =
```

### 3.4 예시: 외부 시스템 연동

```
[결제 시스템] --승인 결과--> ( 결제 승인 )
[고객]       --검색어-----> ( 상품 검색 ) --검색 결과--> [고객]
```

### 3.5 작성 규칙

* 데이터 흐름은 반드시 프로세스를 한쪽 끝에 둔다. 외부 엔티티와 저장소를 직접 연결하지 않는다.
* 프로세스는 입력과 출력이 모두 있어야 한다.
* 모든 흐름에 이름(데이터 이름)을 붙인다.

## 4. 장점

* 데이터 흐름을 명확하게 분석한다.
* 시스템 기능을 시각적으로 표현한다.
* 기능 정의 단계에서 유용하다.
* 객체 모델, 동적 모델과 결합해 분석을 완성한다.
