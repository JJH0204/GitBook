## 1. 정의

럼바우 객체지향 분석(OOA)은 제임스 럼바우(James Rumbaugh) 등이 제안한 객체 모델링 기법(OMT, Object Modeling Technique)의 분석 단계다. 현실 세계를 객체로 나누고, 시스템을 세 가지 관점의 모델로 나누어 분석한다.

* 객체 모델(Object Model): 시스템의 정적 구조를 정의한다.
* 동적 모델(Dynamic Model): 시간에 따른 상태 변화를 정의한다.
* 기능 모델(Functional Model): 데이터 변환과 흐름을 정의한다.

{% hint style="info" %}
NOTE: OMT는 1990년대 초에 발표되었고(1991년 저서 *Object-Oriented Modeling and Design*), 이후 UML 통합 과정에서 UML의 모태 중 하나가 되었다. 정보처리 시험 등에서 분석 순서는 객체 모델 → 동적 모델 → 기능 모델로 출제된다.
{% endhint %}

## 2. 구성 요소

| 모델 | 관점 | 주요 개념 | 표기 도구 | 상세 문서 |
|---|---|---|---|---|
| 객체 모델 | 구조 (무엇으로 이루어져 있는가) | 객체, 클래스, 속성, 연산, 관계 | 객체 다이어그램(UML 클래스 다이어그램과 유사) | [PRG-ARP-002-DO](object-model.md) |
| 동적 모델 | 시간 (어떻게 변하는가) | 상태, 이벤트, 전이 | 상태 다이어그램 | [PRG-ARP-003-DO](rumbaughooa/dynamic-model.md) |
| 기능 모델 | 처리 (데이터를 어떻게 바꾸는가) | 프로세스, 데이터 흐름, 데이터 저장소, 외부 엔티티 | 데이터 흐름도(DFD) | [PRG-ARP-004-DO](rumbaughooa/functional-model.md) |

예시 대응은 다음과 같다.

| 모델 | 예시 |
|---|---|
| 객체 모델 | 학생 클래스와 강의 클래스의 연관 |
| 동적 모델 | 학생의 수강 신청 상태 변화 |
| 기능 모델 | 도서 대출 시스템의 데이터 흐름 |

{% hint style="info" %}
NOTE: 럼바우 기법의 기능 모델 도구는 데이터 흐름도(DFD)다. UML 활동 다이어그램은 처리 순서를 그리는 비슷한 용도의 UML 다이어그램이지만 OMT의 구성 요소는 아니다.
{% endhint %}

## 3. 동작 원리

분석은 세 모델을 순서대로 만들고 서로 보완한다.

```
1. 객체 모델   : 객체와 관계를 찾는다.            → 무엇이 있는가
2. 동적 모델   : 객체의 상태와 이벤트를 찾는다.     → 언제 어떻게 바뀌는가
3. 기능 모델   : 입력에서 출력까지의 처리를 찾는다. → 무엇을 계산하는가
```

* 세 모델은 서로의 정보를 참조한다. 동적 모델의 상태는 객체 모델의 속성 값에서 나오고, 기능 모델의 프로세스는 객체 모델의 연산에 대응한다.
* 분석 결과는 설계와 구현 단계로 이어지며, 같은 객체 개념을 단계 전체에서 유지한다.

## 4. 장점과 단점

| 장점 | 단점 |
|---|---|
| 객체 기반 분석이어서 재사용성이 높다 | 다이어그램이 많아지면 복잡해진다 |
| 세 관점으로 시스템을 다각도로 분석한다 | 동적 모델과 기능 모델을 연결하기 어렵다 |
| UML과 개념이 비슷해 설계·구현으로 자연스럽게 이어진다 | 객체 모델에 비해 동적 모델의 비중이 작게 다뤄진다 |

## 5. 약어·용어

| 약어 | 원어 | 뜻 |
|---|---|---|
| OOA | Object-Oriented Analysis | 객체지향 분석 |
| OMT | Object Modeling Technique | 럼바우의 객체 모델링 기법 |
| DFD | Data Flow Diagram | 데이터 흐름도 |
| UML | Unified Modeling Language | 통합 모델링 언어 |
