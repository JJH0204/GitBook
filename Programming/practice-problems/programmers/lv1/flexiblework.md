## 1. 문제 개요

직원마다 출근 희망 시각(`hhmm` 정수)이 있고, 일주일 동안의 실제 출근 시각이 주어진다. 평일(월~금)에 희망 시각 + 10분을 넘겨 출근한 날이 한 번도 없는 직원의 수를 구한다. 주말 기록은 판정에서 뺀다. 이벤트 시작 요일 `startday`는 1(월)부터 7(일)까지다. 입력 범위와 예시는 프로그래머스 문제 페이지에서 확인한다.

## 2. 동작 원리

### 2-1. 시각 덧셈

시각을 `hhmm` 정수로 표현하므로 일반 덧셈을 쓰면 안 된다. `950 + 10 = 960`은 존재하지 않는 시각이다.

| 희망 시각 | 단순 덧셈 | 올바른 마감 시각 |
|---|---|---|
| 950 | 960 | 1000 |
| 958 | 968 | 1008 |
| 1000 | 1010 | 1010 |

분(`s % 100`)에 10을 더해 60 이상이면 시를 1 올리고 분에서 60을 뺀다. 원본 메모의 한 줄 공식 `(s + 10) % 100 >= 60 ? s + 50 : s + 10`도 같은 결과다. 희망 시각의 분은 0~59이므로 분 자리의 합은 최대 69다. 60 이상이면 `+10`에 올림 보정 `+40`을 더한 `+50`이 정확히 한 시간 올림이 된다.

### 2-2. 요일 인덱스

`startday`가 1(월)이면 `timelogs[i][0]`이 월요일이다. `j`번째 기록의 요일 번호는 다음과 같다.

```
day = (startday - 1 + j) % 7      // 0=월, 1=화, 2=수, 3=목, 4=금, 5=토, 6=일
```

`day`가 5 또는 6이면 주말이므로 건너뛴다. `startday = 2`(화)이면 `j = 0..6`의 `day`는 1, 2, 3, 4, 5, 6, 0이다.

### 2-3. 판정

1. 직원 한 명의 마감 시각을 구한다.
2. `j = 0..6`을 돌며 주말을 건너뛰고 `마감 시각 < 실제 출근 시각`이면 지각으로 표시하고 반복을 끝낸다.
3. 지각이 없으면 답을 1 올린다.

## 3. 복잡도

| 항목 | 값 | 이유 |
|---|---|---|
| 시간 | O(n) | 직원 수 n에 대해 직원당 7일만 본다 |
| 공간 | O(1) | 추가 배열이 없다 |

## 4. 예제 코드

```cpp
#include <string>
#include <vector>

using namespace std;

int solution(vector<int> schedules, vector<vector<int>> timelogs, int startday) {
    int answer = 0;

    int hour = 0;
    int minute = 0;
    int limitTime = 0;

    bool isFail = false;

    for (int i = 0; i < schedules.size(); i++)
    {
        isFail = false;

        hour = schedules[i] / 100;
        minute = schedules[i] % 100 + 10;
        if (minute >= 60)
        {
            hour += 1;
            minute -= 60;
        }
        limitTime = hour * 100 + minute;

        for (int j = 0; j < 7 && !isFail; j++)
        {
            int day = (j + startday - 1) % 7;  // 0~6
            if (day == 5 || day == 6) continue;  // 5: 토, 6: 일

            if ( limitTime < timelogs[i][j] )  // 지각인지 점검
                isFail = true;
        }

        if (!isFail)
            answer++;
    }

    return answer;
}
```

## 5. 코드 설명

| 위치 | 설명 |
|---|---|
| `hour`, `minute` 계산 | 마감 시각의 시와 분을 따로 구하고 분이 60 이상이면 올림한다 |
| `limitTime` | `hour * 100 + minute`로 다시 `hhmm` 정수로 합친다. 실제 출근 시각과 같은 형식이라 대소 비교가 가능하다 |
| `day` | 2-2절의 요일 인덱스. 5(토), 6(일)이면 `continue` |
| `limitTime < timelogs[i][j]` | 마감 시각을 넘긴 출근만 지각이다. 같으면 지각이 아니다 |
| `!isFail` 조건 | 지각이 확인되면 안쪽 반복이 즉시 끝난다 |

## 6. 한계·주의

* 원본 메모의 첫 시도는 `(j + startday) % 6 == 0 || (j + startday) % 7 == 0`로 주말을 걸러냈고 일부 테스트가 실패했다. 6과 7로 따로 나눈 나머지는 요일 순환을 표현하지 못한다. 7로 나눈 나머지 하나로 요일 번호를 만든다.
* 마감 시각이 24시를 넘는 입력(예: 희망 시각 2355)은 이 코드가 처리하지 않는다. 문제의 희망 시각 범위 안에서는 발생하지 않는다고 본다(범위는 문제 페이지에서 확인한다).
* `i < schedules.size()`는 부호 있는 정수와 부호 없는 정수의 비교라 컴파일러 경고가 날 수 있다. 오류는 아니다.
