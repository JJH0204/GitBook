## 1. 정의

헝가리안 표기법(Hungarian notation)은 변수와 함수 이름 앞에 접두어를 붙여 이름만 보고 성질을 알 수 있게 하는 명명 규칙이다. 접두어가 무엇을 나타내느냐에 따라 시스템 헝가리안과 애플리케이션 헝가리안으로 나뉜다.

| 구분 | 접두어가 나타내는 것 | 예 |
|---|---|---|
| 시스템 헝가리안 | 언어의 자료형 | `iCount`(`int`), `strName`(문자열) |
| 애플리케이션 헝가리안 | 값의 용도나 종류(kind) | `bIsVisible`(논리값), `rwWidth`(행 기준 값) |

## 2. 구성 요소

### 2-1. 시스템 헝가리안

접두어는 변수의 데이터 타입을 나타낸다.

| 접두어 | 의미 | 예 |
|---|---|---|
| `i` | 정수(integer) | `iCount` |
| `c` | 문자(char) | `cLetter` |
| `f` | 부동소수점(float) | `fPrice` |
| `str` | 문자열 | `strName` |

{% code title="예시 (C++)" %}
```cpp
#include <string>

int iCount;            // 정수를 나타내는 변수
char cLetter;          // 문자를 나타내는 변수
float fPrice;          // 부동소수점을 나타내는 변수
std::string strName;   // 문자열을 나타내는 변수
```
{% endcode %}

* 장점: 코드를 읽는 사람이 변수의 타입을 바로 안다.
* 단점: 현대 IDE(통합 개발 환경)가 타입을 바로 보여 주므로 이득이 작다. 타입을 바꾸면 이름도 모두 바꿔야 한다.

{% hint style="info" %}
NOTE: C에는 `string` 타입이 없다. 원본의 `string strName;`은 C 코드가 아니므로 C++(`std::string`)로 바꿨다. C에서는 `char szName[32];`처럼 쓴다(`sz`는 널 종료 문자열을 뜻하는 관례). 접두어는 프로젝트마다 다르다. 예를 들어 Windows API 코드에서 `f`는 부동소수점이 아니라 논리값(flag)에 흔히 쓰이고 부동소수점은 `fl`이나 `d`를 쓴다. 프로젝트의 규칙표를 먼저 확인한다.
{% endhint %}

### 2-2. 애플리케이션 헝가리안

접두어는 자료형이 아니라 변수의 목적이나 역할을 나타낸다. 이 표기법을 처음 제안한 사람은 Charles Simonyi이고, 애플리케이션 헝가리안이 원래 의도에 가깝다고 알려져 있다. 시스템 헝가리안은 "type"을 언어 자료형으로 오해해 퍼졌다는 평가가 있다.

| 접두어 | 의미 | 예 |
|---|---|---|
| `rw` | 행(row) | `rwWidth` |
| `us` | 안전하지 않은 문자열(unsafe string) | `usUserCount` |
| `b` | 논리값(boolean) | `bIsVisible` |

{% hint style="warning" %}
CAUTION: `us`는 문맥에 따라 뜻이 다르다. 애플리케이션 헝가리안에서는 unsafe string(검증하지 않은 외부 입력 문자열)이고 시스템 헝가리안에서는 unsigned short일 수 있다. 같은 접두어가 두 규칙에서 다르게 쓰이므로 한 프로젝트에서는 한 규칙만 쓴다. 원본의 `usUserCount`는 이름이 개수를 뜻해 접두어와 어긋나므로 접두어의 뜻을 보여 주는 용도로만 읽는다.
{% endhint %}

* 장점: 변수의 용도를 알기 쉬워 가독성과 유지보수성이 높아진다.

{% code title="예시 (C++)" %}
```cpp
#include <string>

int iTotal = 0;
float fAverage = 0.0f;
std::string strUserName = "John Doe";
bool bIsLoggedIn = false;

// 함수 사용 예시
void UpdateUserScore(int iScore) {
    // 함수 내부 로직
}
```
{% endcode %}

## 3. 동작 원리와 현재 쓰임

1. 이름을 `<접두어><이름>` 형태로 짓는다. 접두어는 소문자, 이름은 단어 첫 글자를 대문자로 쓴다.
2. 읽는 사람은 접두어로 타입(시스템) 또는 용도(애플리케이션)를 안다.
3. 규칙이 일관돼야 효과가 있다. 일부 변수만 접두어를 쓰면 오히려 혼란을 준다.

| 항목 | 내용 |
|---|---|
| 큰 규모 프로젝트 | 같은 규칙을 팀 전체가 지키면 이름만으로 의도를 읽기 쉽다 |
| 현재 경향 | 타입을 도구가 보여 주고 타입 시스템이 강력한 언어에서는 시스템 헝가리안을 쓰지 않는 편이 많다. 예를 들어 .NET 명명 지침은 헝가리안 접두어를 권하지 않는다 |
| 이 저장소의 코드 | [연결 스택 헤더 (MyStack.h)](../c-snippets/mystack.h.md)가 `pTop`(포인터), `nCurrentCount`(개수), `cData`(문자) 접두어를 쓴다 |

## 4. 약어·용어

| 용어 | 뜻 |
|---|---|
| 접두어(prefix) | 이름 앞에 붙는 소문자 약어 |
| kind | 애플리케이션 헝가리안에서 접두어가 나타내는 값의 종류나 용도 |
| 널 종료 문자열 | 끝에 `'\0'`이 있는 C 문자열 |
