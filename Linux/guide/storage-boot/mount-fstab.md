# 파일 시스템 마운트와 fstab 등록

## 작업 식별

| 항목 | 내용 |
|---|---|
| Task ID | LNX-STB-009-MP |
| 목적 | 새 파티션을 수동으로 마운트하고, `/etc/fstab`에 등록해 부팅 때 자동 마운트하게 한다 |
| 적용 대상 | RHEL 계열 리눅스, root 또는 `sudo`, 이미 파일 시스템이 만들어진 파티션(예: `/dev/sdb1`, ext4) |
| 소요 시간 | 약 15분 |
| 확인 상태 | 미검증 (원본 페이지와 util-linux 일반 지식을 정리한 것이며 직접 실행해 확인하지 않았다) |
| 개정 | R1 (2026-11-18) |

## 2. 필요 장비와 자재

| 번호 | 이름 | 사양 | 비고 |
|---|---|---|---|
| 1 | 관리자 권한 | root 또는 `sudo` | |
| 2 | 대상 파티션 | `<장치>` (예: `/dev/sdb1`) | 파일 시스템이 있어야 한다 |
| 3 | 마운트 지점 | `<마운트 지점>` (예: `/mnt/media`) | 비어 있는 디렉터리 |
| 4 | 복구 콘솔 | 설치 미디어 또는 rescue 부팅, 가상 머신이면 콘솔 | 5-C 전에 확보한다 |

## 3. 안전 사항

{% hint style="info" %}
NOTE: 5-A, 5-B는 재부팅 없이 되돌릴 수 있는 작업이다. 5-C부터 부팅에 영향을 준다.
{% endhint %}

## 4. 준비

| 번호 | 항목 | 확인 방법 |
|---|---|---|
| 1 | 장치를 확인한다: `lsblk` 또는 `fdisk -l` | 대상 파티션(`<장치>`)이 보인다 |
| 2 | 파일 시스템 형식과 UUID를 확인한다: `blkid <장치>` | `TYPE="ext4"`와 `UUID="<UUID>"`가 보인다 |
| 3 | 마운트 지점을 만든다: `sudo mkdir -p <마운트 지점>` | 디렉터리가 존재한다 |
| 4 | 마운트 지점이 비어 있는지 확인한다: `ls <마운트 지점>` | 출력이 없다 |

## 5. 절차

### A. 수동 마운트

1. (5-A-01) 장치를 마운트한다: `sudo mount <장치> <마운트 지점>` → 결과: 오류 없이 끝난다.
2. (5-A-02) 연결을 확인한다: `df -h <마운트 지점>` → 결과: `Filesystem`이 `<장치>`이고 `Mounted on`이 `<마운트 지점>`이다.
3. (5-A-03) 내용을 확인한다: `ls <마운트 지점>` → 결과: 장치 안의 파일이 보인다.

### B. 옵션 변경과 해제

1. (5-B-01) 읽기 전용으로 바꾼다: `sudo mount -o remount,ro <마운트 지점>` → 결과: `mount | grep <마운트 지점>`에 `ro`가 보인다.
2. (5-B-02) 읽기·쓰기로 되돌린다: `sudo mount -o remount,rw <마운트 지점>` → 결과: `mount | grep <마운트 지점>`에 `rw`가 보인다.
3. (5-B-03) 마운트 지점 밖으로 이동한다: `cd /`
4. (5-B-04) 해제한다: `sudo umount <마운트 지점>` → 결과: 오류 없이 끝나고 `df -h <마운트 지점>`이 루트 파일 시스템을 가리킨다. `target is busy`가 나오면 mount.md(LNX-STB-008-REF)의 5절을 따른다.

### C. /etc/fstab에 등록

{% hint style="danger" %}
WARNING: `/etc/fstab`을 잘못 고치면 다음 부팅에서 시스템이 멈추거나 비상 모드로 들어간다. 편집 전에 파일을 백업하고, 복구 콘솔을 확보한다. 저장 후에는 재부팅하기 전에 반드시 5-C-05의 `mount -a`로 검증한다. 이 단계를 건너뛰고 재부팅하지 않는다.
{% endhint %}

1. (5-C-01) 백업한다: `sudo cp /etc/fstab /etc/fstab.bak` → 결과: `/etc/fstab.bak`이 생긴다.
2. (5-C-02) 편집기로 연다: `sudo vi /etc/fstab`
3. (5-C-03) 파일 끝에 6개 필드를 한 줄로 추가한다: `UUID=<UUID> <마운트 지점> ext4 defaults 0 2`
4. (5-C-04) 저장하고 종료한다.
5. (5-C-05) 검증한다: `sudo mount -a` → 결과: 오류 메시지 없이 끝난다. 5-B-04로 해제한 상태였다면 `df -h <마운트 지점>`에서 마운트가 보인다.

{% hint style="info" %}
NOTE: 외장 장치나 네트워크 공유처럼 부팅 때 없을 수 있는 장치는 옵션에 `nofail`을 넣으면 장치가 없어도 부팅이 멈추지 않는다. `findmnt --verify`로 fstab 문법을 점검할 수도 있다(util-linux 2.29 이상, 미검증).
{% endhint %}

### D. 재부팅 확인

1. (5-D-01) 5-C-05가 오류 없이 끝났는지 다시 확인한다.
2. (5-D-02) 재부팅한다: `sudo reboot` → 결과: 시스템이 정상 부팅한다.
3. (5-D-03) 자동 마운트를 확인한다: `df -h <마운트 지점>` → 결과: `<장치>`가 `<마운트 지점>`에 마운트돼 있다.

## 6. 기능 확인

| 번호 | 확인 동작 | 기대 결과 | 합격 기준 |
|---|---|---|---|
| 1 | `sudo mount -a` | 출력 없음 | 오류가 없다 |
| 2 | `df -h <마운트 지점>` | 마운트 확인 | `Mounted on`이 `<마운트 지점>` |
| 3 | 재부팅 후 `df -h <마운트 지점>` | 자동 마운트 | 1회 재부팅 뒤에도 마운트돼 있다 |

## 7. 복구

1. (7-01) 부팅이 되는 경우: `sudo cp /etc/fstab.bak /etc/fstab`로 복원한다. 그 뒤 `sudo mount -a`로 검증한다.
2. (7-02) 부팅이 멈추고 비상 모드(emergency mode)로 들어간 경우: root 암호로 로그인한다. 루트 파일 시스템이 읽기 전용이면 `mount -o remount,rw /`로 바꾼다. `/etc/fstab`의 새 줄을 지우거나 `/etc/fstab.bak`을 복원한 뒤 `reboot`한다.
3. (7-03) 비상 모드로도 들어가지 못하면 설치 미디어나 rescue 부팅으로 시스템을 열어 같은 파일을 복원한다.
