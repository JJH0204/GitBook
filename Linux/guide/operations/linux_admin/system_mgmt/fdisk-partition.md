| 목적 | 대상 디스크를 확인한 뒤 fdisk로 파티션을 만들고 지운다 |

| 소요 시간 | 약 10분 |

## 3. 안전 사항

{% hint style="danger" %}
WARNING: 잘못된 디스크를 고르면 그 디스크의 파티션과 데이터를 잃는다. 실행 전에 `lsblk`로 대상 디스크의 이름, 크기, 마운트 위치를 확인한다. 시스템이 설치된 디스크(`/`가 마운트된 디스크)는 대상으로 삼지 않는다.
{% endhint %}

{% hint style="info" %}
NOTE: fdisk는 `w`를 입력하기 전까지 변경을 디스크에 쓰지 않는다. 중간에 멈추려면 `q`를 입력한다.
{% endhint %}

## 4. 준비

| 번호 | 항목 | 확인 방법 |
|---|---|---|
| 1 | 대상 디스크의 데이터를 백업한다 | 백업 파일이 다른 저장 장치에 있다 |
| 2 | 대상 디스크의 파티션이 마운트돼 있지 않은지 확인한다 | `lsblk`의 `MOUNTPOINTS` 열이 비어 있다 |
| 3 | root 권한을 확보한다 | `id -u`가 `0`이거나 `sudo`를 쓸 수 있다 |

## 5. 절차

### A. 대상 디스크 식별과 백업

1. (5-A-01) 디스크 목록을 출력한다: `lsblk` → 결과: `NAME`, `SIZE`, `TYPE`, `MOUNTPOINTS` 열이 보인다.
2. (5-A-02) 대상 디스크를 고른다. 크기와 마운트 위치를 5-A-01의 출력과 대조한다. → 결과: `/`가 마운트되지 않은 디스크 하나를 `<디스크>`(예: `/dev/sdb`)로 정한다.
3. (5-A-03) 현재 파티션 테이블을 출력한다: `sudo fdisk -l <디스크>` → 결과: 기존 파티션 목록이 보인다. 기대와 다르면 여기서 중단한다.
4. (5-A-04) 파티션 테이블을 파일로 백업한다: `sudo sfdisk -d <디스크> > <백업 파일>` → 결과: 백업 파일이 생긴다. 파일은 대상 디스크가 아닌 곳에 둔다.

### B. 파티션 생성

{% hint style="danger" %}
WARNING: 5-B-01 이후 단계는 파티션 테이블을 바꾼다. 5-B-01에서 `<디스크>`가 5-A-02에서 정한 디스크와 같은지 다시 확인한다. 변경은 5-B-09의 `w`에서 디스크에 쓰인다.
{% endhint %}

1. (5-B-01) fdisk를 연다: `sudo fdisk <디스크>` → 결과: `Command (m for help):` 프롬프트가 나타난다.
2. (5-B-02) 현재 테이블을 확인한다: `p` 입력 → 결과: 5-A-03과 같은 파티션 목록이 보인다.
3. (5-B-03) 새 파티션 추가를 시작한다: `n` 입력 → 결과: 파티션 종류(MBR) 또는 파티션 번호(GPT)를 묻는다.
4. (5-B-04) MBR 디스크에서는 종류를 고른다: 기본 파티션은 `p`, 확장 파티션은 `e`를 입력한다. GPT 디스크에서는 이 질문이 나오지 않는다.
5. (5-B-05) 파티션 번호를 입력한다: 기본값(Enter)을 쓰거나 빈 번호를 지정한다. → 결과: 시작 섹터를 묻는다.
6. (5-B-06) 시작 섹터를 입력한다: 기본값(Enter)을 쓴다. → 결과: 끝 섹터 또는 크기를 묻는다.
7. (5-B-07) 크기를 입력한다: `+<크기>` 형식으로 쓴다(예: `+10G`). 남은 공간 전체를 쓰려면 Enter를 입력한다. → 결과: `Created a new partition` 메시지가 나온다.
8. (5-B-08) 결과를 확인한다: `p` 입력 → 결과: 새 파티션이 목록에 보인다. 아직 디스크에는 쓰이지 않았다.
9. (5-B-09) 변경을 디스크에 쓴다: `w` 입력 → 결과: `The partition table has been altered.` 메시지가 나오고 fdisk가 종료된다.

{% hint style="info" %}
NOTE: 이 단계의 결과가 의도와 다르면 5-B-09 전에 `q`를 입력해 변경을 버린다.
{% endhint %}

### C. 파티션 삭제

{% hint style="danger" %}
WARNING: 파티션을 삭제하면 그 파티션의 데이터에 접근할 수 없게 된다. 삭제 대상 파티션이 마운트돼 있으면 먼저 `sudo umount <파티션>`으로 해제한다. 삭제할 파티션 번호를 `p`의 출력으로 확인한 뒤 진행한다.
{% endhint %}

1. (5-C-01) 5-B-01과 같이 fdisk를 연다: `sudo fdisk <디스크>` → 결과: 프롬프트가 나타난다.
2. (5-C-02) 파티션 목록을 확인한다: `p` 입력 → 결과: 삭제할 파티션의 번호가 보인다.
3. (5-C-03) 삭제를 시작한다: `d` 입력 → 결과: 삭제할 파티션 번호를 묻는다. 파티션이 하나뿐이면 묻지 않고 바로 삭제 대상으로 선택한다.
4. (5-C-04) 삭제할 파티션 번호를 입력한다. → 결과: `Partition <번호> has been deleted.` 메시지가 나온다.
5. (5-C-05) 결과를 확인한다: `p` 입력 → 결과: 해당 파티션이 목록에서 사라진다. 아직 디스크에는 쓰이지 않았다.
6. (5-C-06) 변경을 디스크에 쓴다: `w` 입력 → 결과: 변경이 기록되고 fdisk가 종료된다.

## 6. 기능 확인

| 번호 | 확인 동작 | 기대 결과 | 합격 기준 |
|---|---|---|---|
| 1 | `lsblk <디스크>` | 생성한 파티션이 보인다. 삭제한 경우 사라진다 | 목록이 의도와 같다 |
| 2 | `sudo fdisk -l <디스크>` | 파티션 크기와 종류가 입력과 같다 | 크기 오차가 없다 |

{% hint style="info" %}
NOTE: 새 파티션은 파일시스템이 없는 상태다. 사용하려면 파일시스템 생성과 마운트가 별도로 필요하다. 이 문서는 파티션 테이블 작업까지만 다룬다.
{% endhint %}

{% hint style="info" %}
NOTE: `lsblk`에 새 파티션이 보이지 않으면 `sudo partprobe <디스크>`로 커널이 테이블을 다시 읽게 한다. 이 동작은 미검증이다.
{% endhint %}

## 7. 복구

1. (7-01) 5-B-09 또는 5-C-06 이전이면 `q`로 fdisk를 종료한다. → 결과: 디스크가 바뀌지 않는다.
2. (7-02) `w` 이후 파티션 테이블을 되돌린다: `sudo sfdisk <디스크> < <백업 파일>` → 결과: 5-A-04 시점의 테이블로 돌아간다. 같은 위치에 새 파티션을 덮어 쓴 데이터는 복구되지 않는다.
3. (7-03) 복구 후 `sudo fdisk -l <디스크>`로 5-A-03의 출력과 비교한다.
