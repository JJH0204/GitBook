## 1. 목적

ACL(Access Control List, 접근 제어 목록)은 라우터를 지나는 트래픽을 검사해 분류하고, 분류에 따라 허용 또는 차단을 수행하는 규칙 목록이다. 이 문서는 ACL을 읽고 설계하는 데 필요한 개념을 설명한다.

## 2. 구성 요소

### 제어 기준에 따른 종류

| 종류 | 검사 항목 | 특징 |
|---|---|---|
| standard | 출발지 IP | 규칙이 단순하다 |
| extended | 출발지 IP, 목적지 IP, 프로토콜, 포트 | 세밀하게 제어한다. 원본 페이지는 이 종류를 추천한다 |

### 방향

| 방향 | 적용 대상 패킷 |
|---|---|
| in | 인터페이스를 통해 라우터로 들어오는 패킷 |
| out | 인터페이스를 통해 라우터 밖으로 나가는 패킷 |

### 서비스와 프로토콜

| 프로토콜 | 서비스 |
|---|---|
| tcp | http, https, ftp |
| icmp | ping |

* ping을 허용하거나 차단할 때는 `echo`와 `echo-reply`를 모두 같은 정책으로 다룬다.

## 3. 동작 원리

### 설정 순서

1. ACL 규칙 목록(access-list)을 구성한다.
2. 적용할 인터페이스에 방향(in 또는 out)을 지정해 ACL을 적용한다.

### 평가 규칙

* 규칙은 위에서 아래로 순서대로 평가한다.
* 처음 일치한 규칙을 적용하고 나머지는 평가하지 않는다.
* 어떤 규칙에도 일치하지 않는 트래픽은 차단한다(암묵적 deny).
* 나머지 트래픽을 허용하려면 목록 끝에 `permit ip any any`를 추가한다.

### 해석 예

| 항목 | 내용 |
|---|---|
| 규칙 의미 | 10.10.10.0 네트워크에서 출발해 192.168.10.1로 향하는 http 트래픽을 허용한다 |
| 서브넷 표기 | 와일드카드 마스크로 쓴다. 단일 호스트는 `0.0.0.0`이다 |

### 적용 위치

{% hint style="warning" %}
CAUTION: 원본 페이지는 "ACL을 목적지와 가까운 라우터에 설정한다"고 적었다. 일반적인 설계 권장은 종류에 따라 다르다. standard ACL은 출발지만 보므로 목적지에 가까운 곳에, extended ACL은 불필요한 트래픽을 일찍 막기 위해 출발지에 가까운 곳에 둔다. 장비 문서로 확인한 뒤 적용한다.
{% endhint %}

* 라우터가 수행하는 검사 횟수가 늘면 트래픽 처리 부하가 늘어난다. 적용 위치는 이 부하를 함께 고려해 정한다.

## 4. 약어·용어

| 용어 | 뜻 |
|---|---|
| ACL | Access Control List. 접근 제어 목록 |
| standard / extended | 출발지만 보는 ACL / 목적지와 프로토콜까지 보는 ACL |
| 와일드카드 마스크 | 서브넷 마스크의 반대 표기. 0은 일치 필요, 1은 무시 |
| 암묵적 deny | 어떤 규칙에도 일치하지 않으면 차단하는 기본 동작 |
| RACL, DACL | 네트워크 보안에 쓰는 ACL 종류. 원본에 이름만 있고 설명이 없다(확인 필요) |
