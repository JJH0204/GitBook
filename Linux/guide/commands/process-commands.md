# [생성형 AI] 프로세스 관리 명령어 (ps, top, kill, nice)

## 작업 식별

| 항목 | 내용 |
|---|---|
| Task ID | LNX-CMD-007-REF |
| 유형 | REF (명령 표) |
| 목적 | 프로세스를 조회하고 종료하고 우선순위를 바꾸는 명령과 옵션을 참조한다 |
| 확인 상태 | 일부 확인 (Ubuntu 26.04에서 `ps -eo`, `ps aux`, `nice -n 5`, `kill -0/-TERM`, `kill -l`을 실행했다. `top`의 대화형 키, `pkill`, `renice`, `nohup`은 미검증) |
| 작성 | 생성형 AI 초안 (사람 검토 전) |
| 개정 | R1 (2026-11-19) |

{% hint style="info" %}
NOTE: 서비스로 실행되는 프로세스는 `kill` 대신 `systemctl`로 중지한다(LNX-LAS-004-MP). 직접 죽이면 systemd가 `Restart=` 설정에 따라 다시 시작할 수 있다.
{% endhint %}

## 1. 조회

| 명령어 | 설명 | 형식 | 주요 옵션 | 예 |
|---|---|---|---|---|
| `ps` | 현재 시점의 프로세스 목록을 출력한다 | `ps [옵션]` | `-ef`: 모든 프로세스를 UID, PID, PPID, 시작 시각, 명령 열로 출력<br>`aux`: 모든 프로세스를 사용자, CPU%, MEM%, 상태 열로 출력<br>`-eo <열,열>`: 출력 열을 지정<br>`--sort=-%mem`: 메모리 사용률 내림차순 | `ps -eo pid,ppid,stat,ni,comm --sort=-%mem` |
| `pgrep` | 이름으로 PID를 찾는다 | `pgrep [옵션] <패턴>` | `-a`: 전체 명령줄도 출력<br>`-u <사용자>`: 해당 사용자 프로세스만 | `pgrep -a sshd` |
| `top` | 프로세스를 실시간으로 갱신해 보여 준다 | `top` | `q`: 종료<br>`k`: PID를 물어 신호를 보냄<br>`r`: PID를 물어 nice 값을 바꿈<br>`P`, `M`: CPU, 메모리 순 정렬<br>`-b -n 1`: 한 번만 출력하고 끝남(스크립트용) | `top -b -n 1` |

`ps`의 `STAT` 열 첫 글자: `R` 실행 중, `S` 잠듦(인터럽트 가능), `D` 잠듦(인터럽트 불가, 보통 입출력 대기), `T` 중지됨, `Z` 좀비(종료했으나 부모가 회수하지 않음). 뒤에 붙는 `s`는 세션 리더, `+`는 포그라운드 프로세스 그룹이다.

## 2. 종료와 신호

| 명령어 | 설명 | 형식 | 주요 옵션 | 예 |
|---|---|---|---|---|
| `kill` | PID에 신호를 보낸다. 신호를 생략하면 `SIGTERM`(15)이다 | `kill [-<신호>] <PID>` | `-l`: 신호 목록<br>`-TERM`(15): 정상 종료 요청<br>`-HUP`(1): 터미널 끊김 또는 설정 다시 읽기<br>`-KILL`(9): 강제 종료(프로세스가 잡을 수 없음)<br>`-0`: 신호를 보내지 않고 PID가 존재하는지만 확인 | `kill -TERM <PID>` |
| `pkill` | 이름으로 신호를 보낸다 | `pkill [-<신호>] <패턴>` | `-u <사용자>`: 해당 사용자 것만 | `pkill -TERM <패턴>` |

{% hint style="warning" %}
CAUTION: `kill -KILL`은 프로세스가 정리 작업을 하지 못하게 한다. 먼저 `-TERM`을 보내고 응답이 없을 때만 쓴다. `pkill`의 패턴은 여러 프로세스에 맞을 수 있다. 먼저 `pgrep -a <패턴>`으로 대상을 확인한다.
{% endhint %}

신호로 종료된 프로세스의 종료 코드는 128에 신호 번호를 더한 값이다. `SIGTERM`으로 종료된 프로세스를 `wait`하면 143(128+15)이다(실행 확인).

## 3. 우선순위와 백그라운드 실행

| 명령어 | 설명 | 형식 | 주요 옵션 | 예 |
|---|---|---|---|---|
| `nice` | 우선순위를 바꿔 명령을 시작한다. nice 값 범위는 -20(높음)에서 19(낮음), 기본은 0이다 | `nice -n <값> <명령>` | `-n <값>`: nice 값에 더할 증가량. 음수는 root만 쓸 수 있다 | `nice -n 5 <명령>` |
| `renice` | 실행 중인 프로세스의 nice 값을 바꾼다 | `renice -n <값> -p <PID>` | `-p`: PID 지정 | `renice -n 10 -p <PID>` |
| `&` | 명령을 백그라운드로 시작한다(셸 기능) | `<명령> &` | | `sleep 100 &` |
| `jobs`, `fg`, `bg` | 셸의 작업 목록 조회, 포그라운드 복귀, 중지된 작업의 백그라운드 재개 | `jobs`, `fg %<번호>`, `bg %<번호>` | `Ctrl+Z`: 포그라운드 작업 중지 | `fg %1` |
| `nohup` | 터미널을 닫아도(`SIGHUP`) 명령이 계속 실행되게 한다 | `nohup <명령> &` | 출력은 `nohup.out`에 저장된다 | `nohup <명령> &` |

## 4. 약어

| 용어 | 뜻 |
|---|---|
| PID | Process ID, 프로세스 번호 |
| PPID | Parent PID, 부모 프로세스 번호 |
| NI | nice 값. `ps -o ni`로 볼 수 있다 |
