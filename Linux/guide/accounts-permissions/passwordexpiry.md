## 3. 안전 사항

{% hint style="danger" %}
WARNING: 구역 C는 UID 1000 이상인 모든 계정의 비밀번호를 만료시킨다. 자동화 작업이나 서비스가 쓰는 계정은 다음 로그인 때 대화형 변경을 요구받아 실패할 수 있다. 실행 전에 5-C-01의 대상 목록을 확인하고, 현재 작업 중인 관리자 계정은 비밀번호를 기억해 둔다.
{% endhint %}

## 4. 준비

| 번호 | 항목 | 확인 방법 |
|---|---|---|
| 1 | root 권한을 확인한다: `id -u` | 출력이 `0`이다 |
| 2 | 대상 계정을 확인한다: `id <사용자명>` | UID가 출력된다 |

## 5. 절차

### A. 만료 정보 조회

1. (5-A-01) 전체 정보를 본다: `chage -l <사용자명>` → 결과: `Last password change`, `Password expires` 등이 출력된다.
2. (5-A-02) 만료일만 본다: `chage -l <사용자명> | grep -i "^password expires"` → 결과: 만료일 또는 `never`가 나온다.

### B. 만료 기간 설정

1. (5-B-01) 최대 사용 일수를 정한다: `chage -M 90 <사용자명>` → 결과: 출력 없이 끝난다. 90은 예시값이며 조직 규정에 맞게 바꾼다.
2. (5-B-02) 만료 경고 시작일을 정한다: `chage -W 7 <사용자명>` → 결과: 출력 없이 끝난다.
3. (5-B-03) 확인한다: `chage -l <사용자명>` → 결과: `Maximum number of days between password change`가 `90`, `Number of days of warning before password expires`가 `7`이다.

### C. 일반 사용자 전체의 비밀번호 변경 강제

1. (5-C-01) 대상 계정 목록을 출력한다: `awk -F: '$3 >= 1000 && $3 < 65534 {print $1}' /etc/passwd` → 결과: 일반 계정 이름이 나온다. 65534는 `nobody`를 제외하는 기준이다.
2. (5-C-02) 스크립트 `change-passwords.sh`를 만든다.

{% code title="change-passwords.sh" %}
```bash
#!/bin/bash

for user in $(awk -F: '$3 >= 1000 && $3 < 65534 {print $1}' /etc/passwd); do
    chage -d 0 "$user"
done
```
{% endcode %}

3. (5-C-03) 스크립트를 실행한다: `bash change-passwords.sh` → 결과: 출력 없이 끝난다.
4. (5-C-04) 한 계정을 확인한다: `chage -l <사용자명>` → 결과: `Last password change`가 `password must be changed`다.

{% hint style="info" %}
NOTE: 원본 스크립트의 오류 두 곳을 고쳤다. `awk` 프로그램을 큰따옴표로 감싸면 셸이 `$3`, `$1`을 먼저 해석하므로 작은따옴표를 쓴다. `chage -d O`의 `O`는 영문자이며 숫자 `0`이 맞다.
{% endhint %}

## 6. 기능 확인

| 번호 | 확인 동작 | 기대 결과 | 합격 기준 |
|---|---|---|---|
| 1 | `chage -l <사용자명>` (구역 B 후) | 최대 사용 일수가 90이다 | 값이 설정과 같다 |
| 2 | 대상 계정으로 로그인 (구역 C 후) | 새 비밀번호를 요구한다 | 변경 전에는 셸이 열리지 않는다 |

## 7. 복구

1. (7-01) 기간 제한을 푼다: `chage -M 99999 <사용자명>` → 결과: 사실상 만료가 없어진다.
2. (7-02) 강제 변경 상태를 푼다: 계정으로 로그인해 비밀번호를 바꾸거나, root가 `chage -d $(date +%F) <사용자명>`을 실행한다 → 결과: `chage -l`의 `Last password change`가 오늘 날짜다.
