## 3. 안전 사항

{% hint style="danger" %}
WARNING: `/etc/sudoers`를 일반 편집기로 직접 고쳐 문법 오류가 생기면 `sudo`가 모든 사용자에게 동작하지 않는다. 반드시 `visudo`로 편집한다. `visudo`는 저장 시 문법을 검사한다.
{% endhint %}

{% hint style="warning" %}
CAUTION: `<사용자> ALL=(ALL) NOPASSWD: ALL`은 비밀번호 없이 모든 명령을 관리자 권한으로 허용한다. 계정이 탈취되면 서버 전체가 넘어간다. 꼭 필요한 명령만 허용하고, 가능하면 비밀번호를 요구한다.
{% endhint %}

## 4. 준비

| 번호 | 항목 | 확인 방법 |
|---|---|---|
| 1 | root 터미널을 하나 더 열어 둔다 | `id`가 `uid=0(root)`를 출력한다 |
| 2 | 대상 계정이 있다 | `id <사용자>`가 출력된다 |

## 5. 절차

### A. 관리자 그룹에 가입 (가장 단순한 방법)

1. (5-A-01) RHEL 계열: `usermod -aG wheel <사용자>` → 결과: 오류 없이 끝난다. Ubuntu: `usermod -aG sudo <사용자>`.
2. (5-A-02) 그룹을 확인한다: `id <사용자>` → 결과: 그룹 목록에 `wheel`(Ubuntu는 `sudo`)이 있다.
3. (5-A-03) 대상 사용자가 로그아웃 후 다시 로그인한다 → 결과: 새 그룹이 적용된다.

{% hint style="info" %}
NOTE: `-a` 없이 `-G`만 쓰면 기존 보조 그룹이 모두 사라진다. 반드시 `-aG`로 쓴다.
{% endhint %}

### B. 별도 규칙 파일로 위임

1. (5-B-01) 파일을 편집기로 연다: `visudo -f /etc/sudoers.d/<파일 이름>` → 결과: 편집기가 열린다.
2. (5-B-02) 한 줄을 입력한다: `<사용자> ALL=(ALL) /usr/bin/systemctl restart <서비스>` → 결과: `<사용자>`가 그 명령 하나만 `sudo`로 실행할 수 있다. 형식은 `<사용자> <호스트>=(<실행 대상 사용자>) <명령>`이다.
3. (5-B-03) 저장하고 종료한다 → 결과: `visudo`가 문법 오류가 없으면 저장한다. 오류가 있으면 다시 편집할지 묻는다.
4. (5-B-04) 전체 문법을 검사한다: `visudo -c` → 결과: 각 파일이 `parsed OK`로 출력된다.

## 6. 기능 확인

| 번호 | 확인 동작 | 기대 결과 | 합격 기준 |
|---|---|---|---|
| 1 | `<사용자>`로 `sudo -l` | 허용된 명령 목록이 출력된다 | 5-B-02의 명령이 있다 |
| 2 | `<사용자>`로 허용된 명령을 `sudo`로 실행 | 실행된다 | 오류가 없다 |
| 3 | `<사용자>`로 허용되지 않은 명령을 `sudo`로 실행 | 거부된다 | `not allowed` 계열의 거부 메시지가 나온다 |

## 7. 복구

1. (7-01) 규칙 파일을 지운다: `rm /etc/sudoers.d/<파일 이름>` → 결과: `sudo -l`에서 그 명령이 사라진다.
2. (7-02) 그룹에서 뺀다: `gpasswd -d <사용자> wheel` (Ubuntu는 `sudo`) → 결과: `id <사용자>`에서 그룹이 사라진다.
