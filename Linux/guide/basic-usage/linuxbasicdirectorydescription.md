## 1. 목적

리눅스는 모든 파일을 최상위 디렉터리 `/` 아래 한 개의 트리로 관리한다. 디렉터리마다 놓는 파일의 종류가 정해져 있어, 이름만 알아도 파일의 용도를 짐작할 수 있다.

## 2. 구성 요소

### 2.1 최상위 디렉터리

| 번호 | 디렉터리 | 역할 | 비고 |
|---|---|---|---|
| 1 | `/` | 파일 시스템의 최상위. 모든 디렉터리의 출발점이며 다른 파일 시스템과 연결되는 지점이다 | |
| 2 | `/bin` | 기본 명령어를 둔다. root와 일반 사용자 모두 쓴다 | 최신 RHEL 계열·Debian 계열은 `/usr/bin`의 심볼릭 링크인 경우가 많다 |
| 3 | `/sbin` | 시스템 관리 명령어를 둔다 | 최신 배포판은 `/usr/sbin`의 링크인 경우가 많다 |
| 4 | `/boot` | 부팅에 필요한 커널 이미지와 부트 로더 파일을 둔다 | |
| 5 | `/dev` | 장치 파일(디바이스)을 둔다 | |
| 6 | `/etc` | 시스템 설정 파일을 둔다. 계정·암호·보안 관련 설정 파일도 여기에 있다 | |
| 7 | `/home` | 일반 사용자의 홈 디렉터리를 둔다 | |
| 8 | `/lib` | 공유 라이브러리와 커널 모듈을 둔다. 프로그램 실행을 지원한다 | 최신 배포판은 `/usr/lib`의 링크인 경우가 많다 |
| 9 | `/lost+found` | `fsck`가 복구한 파일 조각을 두는 디렉터리다 | ext 계열 파일 시스템의 최상위에 생긴다. 이 형식이 아닌 파일 시스템에는 없을 수 있다 |
| 10 | `/mnt` | 파일 시스템을 임시로 마운트할 때 쓴다 | |
| 11 | `/proc` | 실행 중인 프로세스와 커널·하드웨어 정보를 보여 주는 가상 파일 시스템이다 | 디스크에 실제 파일이 없다 |
| 12 | `/root` | 관리자(root)의 홈 디렉터리다 | |
| 13 | `/tmp` | 임시 파일을 둔다 | 재부팅 때 지워질 수 있다 |
| 14 | `/usr` | 사용자 프로그램과 공유 데이터를 둔다 | |
| 15 | `/var` | 내용이 계속 바뀌는 데이터(로그, 스풀, 캐시, 메일)를 둔다 | |
| 16 | `/opt` | 별도로 설치하는 응용 프로그램 패키지를 둔다 | 원본에 없던 항목 |
| 17 | `/run` | 부팅 이후의 실행 시점 데이터(PID 파일, 소켓)를 둔다 | 원본에 없던 항목 |
| 18 | `/sys` | 커널과 장치 정보를 보여 주는 가상 파일 시스템이다 | 원본에 없던 항목 |

### 2.2 `/etc` 아래 주요 항목

| 경로 | 역할 | 비고 |
|---|---|---|
| `/etc/passwd` | 계정 정보 | |
| `/etc/shadow` | 암호화된 암호와 암호 만기일, 계정 만기일을 둔다. `/etc/passwd`의 두 번째 필드(암호) 부분을 분리해 관리한다 | root만 읽을 수 있다 |
| `/etc/group` | 그룹 정보 | |
| `/etc/ssh` | `sshd` 데몬과 SSH 클라이언트의 설정 파일 | |
| `/etc/samba` | 삼바(Samba) 설정 파일 | |
| `/etc/mail` | sendmail 설정 파일 | sendmail을 쓰는 경우 |
| `/etc/rc.d`, `/etc/rc.d/init.d` | 부팅 단계(런레벨)별 스크립트, 시스템 초기화 스크립트 | 구형 SysV init 방식. 최근 RHEL 계열은 systemd를 쓴다. 미검증 |
| `/etc/xinetd.d` | 슈퍼 데몬(`xinetd`)이 제공하는 서비스의 설정 파일 | 원본 표기 `/etc/winitd.d`는 오타로 보고 정정했다. 미검증 |

### 2.3 `/usr` 아래 주요 항목

| 경로 | 역할 | 비고 |
|---|---|---|
| `/usr/bin` | 사용자 명령어 | 원본은 설명이 비어 있었다. 대부분의 명령 실행 파일이 여기에 있다 |
| `/usr/lib` | 라이브러리 | 원본은 "`/lib`에 들어가지 않은 라이브러리"로 설명했다 |
| `/usr/local` | 관리자가 직접 설치한 소프트웨어(예: 소스 컴파일로 설치한 Apache, PHP)를 둔다 | |
| `/usr/share/man` | 매뉴얼 페이지 | |
| `/usr/X11R6` | 구형 X Window 시스템 | 최신 FHS에서 제외됐다. 현재 배포판에는 보통 없다. 미검증 |

### 2.4 `/var` 아래 주요 항목

| 경로 | 역할 | 비고 |
|---|---|---|
| `/var/log` | 시스템 로그 파일 | |
| `/var/tmp` | 재부팅 후에도 유지되는 임시 파일. `/tmp`와 함께 공용 디렉터리다 | 퍼미션 1777(sticky bit) |
| `/var/spool/cron` | 사용자별 cron 설정 파일 | |
| `/var/spool/at` | `atd`(예약 작업) 관련 파일 | |
| `/var/spool/mqueue` | 발송 대기 중인 메일 | sendmail을 쓰는 경우 |
| `/var/spool/lpd` | 프린트 스풀 디렉터리 | 구형 lpd 방식. 최근에는 CUPS의 `/var/spool/cups`를 쓴다. 미검증 |
| `/var/named` | DNS(BIND)의 zone 파일 | 배포판별로 위치가 다르다. 미검증 |

## 3. 동작 원리

```
/ (루트)
├── bin sbin lib      실행 파일과 라이브러리 (최신 배포판은 /usr 아래 링크)
├── boot              부팅 파일
├── dev proc sys      장치와 커널 정보 (가상)
├── etc               설정 파일
├── home root         사용자 홈
├── usr               프로그램과 공유 데이터
├── var               로그, 스풀 등 변하는 데이터
└── tmp mnt opt run   임시, 마운트, 추가 패키지, 실행 시점 데이터
```

1. 시스템은 `/boot`의 커널로 시작해 `/etc`의 설정을 읽는다.
2. 프로그램은 `/usr/bin` 등에서 실행되고 `/lib` 계열의 라이브러리를 불러온다.
3. 실행 중 생기는 로그와 스풀은 `/var`에 쌓인다.
4. 다른 디스크는 `/mnt` 같은 마운트 지점에 연결해 트리에 붙인다.

{% hint style="info" %}
NOTE: `/tmp`와 `/var/tmp`는 sticky bit(`1777`)가 설정돼 있어 모든 사용자가 파일을 만들 수 있지만 남의 파일은 지우지 못한다.
{% endhint %}

## 4. 약어·용어

| 용어 | 뜻 |
|---|---|
| FHS | Filesystem Hierarchy Standard. 리눅스 디렉터리 배치 표준 |
| 마운트(mount) | 파일 시스템을 디렉터리에 연결하는 동작 |
| 스풀(spool) | 처리 대기 중인 작업 데이터를 임시로 쌓아 두는 것 |
| 데몬(daemon) | 백그라운드에서 계속 실행되는 서비스 프로그램 |
| sticky bit | 디렉터리 안의 파일을 소유자만 지울 수 있게 하는 권한 비트 |
| `fsck` | 파일 시스템 검사·복구 도구 |
