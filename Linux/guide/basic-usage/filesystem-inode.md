## 1. 목적

파일 시스템은 디스크에 파일과 디렉터리를 저장하고 찾는 방식이다. inode는 파일의 이름을 제외한 정보를 담는 자료 구조다. 두 개념을 알면 하드 링크, 디스크 가득 참 오류, 마운트의 의미를 이해할 수 있다.

## 2. 구성 요소

### 2.1 주요 파일 시스템

| 이름 | 특징 | 주로 쓰이는 곳 |
|---|---|---|
| ext4 | 리눅스 범용 저널링 파일 시스템 | Debian 계열 기본 |
| xfs | 큰 파일과 큰 용량에 강한 저널링 파일 시스템. 크기를 줄일 수 없다 | RHEL 계열 기본 |
| btrfs | 스냅샷, 체크섬을 지원하는 파일 시스템 | 일부 배포판 |
| vfat | FAT 계열. 리눅스 권한을 저장하지 못한다 | EFI 시스템 파티션, USB |
| tmpfs | 메모리에 만드는 임시 파일 시스템. 재부팅하면 사라진다 | `/tmp`, `/run` 등 |

저널링(journaling)은 변경 내용을 먼저 기록해 두어, 갑작스러운 전원 차단 뒤 복구를 빠르게 하는 방식이다.

### 2.2 inode가 담는 정보

| 정보 | 예 |
|---|---|
| 파일 종류 | 일반 파일, 디렉터리, 심볼릭 링크 |
| 권한과 소유자 | 모드, UID, GID |
| 크기와 시각 | 크기, atime, mtime, ctime |
| 하드 링크 수 | 이 inode를 가리키는 이름의 수 |
| 데이터 블록 위치 | 내용이 저장된 곳 |

파일 이름은 inode에 들어 있지 않다. 이름은 디렉터리가 `이름 → inode 번호`로 저장한다.

## 3. 동작 원리

1. 디렉터리는 이름과 inode 번호의 목록이다.
2. 이름으로 파일을 열면 커널이 inode 번호를 찾고, inode에서 데이터 블록 위치를 읽는다.
3. 하드 링크는 같은 inode 번호에 이름을 하나 더 붙이는 것이다. 심볼릭 링크는 경로 문자열을 담은 별도의 파일이라 inode 번호가 다르다.

확인한 출력(실행, 번호는 환경마다 다르다).

```
$ ln data.txt hl.txt
$ ls -li data.txt hl.txt
35739 -rw-rw-r-- 2 ... data.txt
35739 -rw-rw-r-- 2 ... hl.txt
$ ln -s data.txt sl.txt
$ ls -li sl.txt
35749 lrwxrwxrwx 1 ... sl.txt -> data.txt
```

하드 링크 둘은 inode 번호(35739)와 링크 수(2)가 같다. 심볼릭 링크는 번호가 다르다.

### 조회 명령

| 목적 | 명령 | 설명 |
|---|---|---|
| 파일의 inode 번호 | `ls -i <파일>` | 첫 열에 inode 번호를 출력한다 |
| inode 상세 정보 | `stat <파일>` | 크기, 링크 수, inode, 권한, 시각을 출력한다 |
| 마운트별 파일 시스템 종류 | `df -T` | `Type` 열에 종류를 출력한다 |
| inode 사용량 | `df -i` | `Inodes`, `IUsed`, `IFree`, `IUse%`를 출력한다 |

{% hint style="warning" %}
CAUTION: 디스크 용량(`df -h`)이 남아 있어도 `df -i`의 `IUse%`가 100%이면 새 파일을 만들 수 없다(`No space left on device`). 작은 파일이 매우 많은 디렉터리(세션, 캐시 등)가 원인인 경우가 많다. 원인 디렉터리를 찾아 정리한다.
{% endhint %}

{% hint style="info" %}
NOTE: 하드 링크는 같은 파일 시스템 안에서만 만들 수 있다. 자세한 비교는 [하드 링크와 심볼릭 링크](../references/linuxlink.md)를 본다.
{% endhint %}
