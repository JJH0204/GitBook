# [생성형 AI] auditd 감사 개요

## 작업 식별

| 항목 | 내용 |
|---|---|
| Task ID | LNX-SEC-008-DO |
| 유형 | D&O (개념) |
| 목적 | 리눅스 감사 시스템(auditd)의 구성과 감사 규칙의 개념, 로그 조회 명령을 설명한다 |
| 확인 상태 | 미검증 (이 환경에 `auditctl`이 설치되어 있지 않아 실행하지 못했다. 공식 문서의 알려진 동작을 정리한 것이다) |
| 작성 | 생성형 AI 초안 (사람 검토 전) |
| 개정 | R1 (2026-11-19) |

## 1. 목적

리눅스 감사 시스템은 커널이 보안과 관련된 이벤트(파일 접근, 시스템 호출, 계정 변경 등)를 기록하게 한다. 누가 언제 무엇을 했는지 사후에 확인하는 탐지·추적 용도다. 접근을 막는 기능은 없다.

## 2. 구성 요소

| 번호 | 구성 요소 | 역할 |
|---|---|---|
| 1 | 커널 감사 기능 | 규칙에 맞는 이벤트를 만들어 사용자 공간으로 보낸다 |
| 2 | `auditd` | 이벤트를 받아 로그 파일에 기록하는 데몬. 로그는 기본 `/var/log/audit/audit.log` |
| 3 | `auditctl` | 실행 중인 감사 규칙을 조회하고 추가한다 |
| 4 | `/etc/audit/rules.d/*.rules`, `augenrules` | 부팅 때 읽는 영구 규칙 파일과 이를 합치는 도구 |
| 5 | `ausearch`, `aureport` | 로그를 조건으로 검색하고 요약 보고서를 만든다 |
| 6 | `/etc/audit/auditd.conf` | 로그 크기, 회전, 디스크 부족 시 동작 설정 |

## 3. 동작 원리

1. 관리자가 감사 규칙을 정한다. 규칙은 크게 세 종류다. 파일·디렉터리 감시(watch), 시스템 호출 감사, 실행 파일 감사.
2. 커널이 규칙에 맞는 동작을 감지해 이벤트를 만든다.
3. `auditd`가 이벤트를 로그에 기록한다. 한 이벤트는 여러 줄(`type=SYSCALL`, `type=PATH` 등)로 나뉘며 같은 `msg=audit(<시각>:<번호>)`로 묶인다.
4. 관리자가 `ausearch`, `aureport`로 조회한다.

감시 규칙의 모양(개념 설명용 예. 규칙을 적용하기 전에 로그 증가량을 고려한다):

```
-w /etc/passwd -p wa -k identity
```

`-w <경로>`는 감시 대상, `-p wa`는 쓰기(w)와 속성 변경(a)을 기록하라는 뜻이다(`r` 읽기, `x` 실행도 있다). `-k <키>`는 검색용 이름표다.

| 목적 | 명령 | 비고 |
|---|---|---|
| 현재 규칙 조회 | `auditctl -l` | root 필요 |
| 키로 검색 | `ausearch -k <키>` | root 필요 |
| 계정 변경 요약 | `aureport -m` | 계정 관련 이벤트 보고 |
| 로그인 실패 요약 | `aureport --failed` | 실패한 이벤트 보고 |
| 서비스 상태 | `systemctl status auditd` | 서비스 이름은 `auditd` |

{% hint style="warning" %}
CAUTION: 광범위한 규칙(예: 모든 시스템 호출)은 로그가 빠르게 쌓여 디스크를 채우고 성능을 떨어뜨린다. 대상을 좁히고 `auditd.conf`의 로그 크기와 회전 설정을 확인한다.
{% endhint %}

{% hint style="info" %}
NOTE: `auditd`가 쓰는 감사 로그는 시스템 로그(`/var/log/messages` 등, LNX-LOG-001-REF)와 별개 파일이다. 로그 무결성이 중요하면 원격 로그 서버로 전달하고 접근 권한을 제한한다.
{% endhint %}

|---|---|
