## 1. 목적

쉘(shell)은 사용자가 입력한 명령을 해석해 운영체제에 전달하는 프로그램이다. 쉘 스크립트는 쉘 명령을 파일 하나에 순서대로 적어 한 번에 실행하는 텍스트 파일이다. 스크립트는 컴파일하지 않고 한 줄씩 해석해 실행한다(인터프리터 방식).

반복 작업, 보안 점검, 시스템 점검을 자동화할 때 쓴다. 문법 표는 [쉘 스크립트 문법 참조](shell-script-syntax.md)(LNX-SCR-002-REF), 실습은 [쉘 스크립트 작성과 실행](shell-script-practice.md)(LNX-SCR-003-MP)를 따른다.

## 2. 구성 요소

### 쉘 종류

| 쉘 | 설명 |
|---|---|
| `sh` | 초기 유닉스 쉘(Bourne shell). 이식성 기준이 되는 최소 문법이다 |
| `ksh` | 콘 쉘(Korn shell). `sh`를 확장했다 |
| `csh` | 버클리 대학에서 개발한 쉘. 문법이 C 언어와 비슷하다 |
| `bash` | Bourne Again shell. 대부분의 리눅스 배포판의 기본 쉘이며 `sh` 문법과 호환된다 |
| `zsh` | `bash`와 비슷하되 기능을 더 확장한 쉘 |

이 그룹의 문서는 `bash`를 기준으로 한다. 쉘 위치는 아래 명령으로 확인한다.

```bash
command -v bash
# /usr/bin/bash  (배포판에 따라 /bin/bash)
```

### 스크립트 파일의 구성

| 구성 | 예 | 역할 |
|---|---|---|
| 셔뱅(shebang) | `#!/bin/bash` | 첫 줄에 쓴다. 이 파일을 실행할 인터프리터를 지정한다 |
| 주석 | `# 설명` | `#`부터 줄 끝까지는 실행하지 않는다 |
| 명령과 제어문 | `mkdir`, `if`, `for` | 위에서 아래로 한 줄씩 실행한다 |
| 종료 코드 | `exit 0` | 실행 결과를 숫자로 돌려준다. `0`이 성공이다 |
| 실행 권한 | `chmod +x` | `./파일명`으로 직접 실행하려면 필요하다 |

{% hint style="warning" %}
CAUTION: 셔뱅 줄에는 인터프리터 경로만 쓴다. 같은 줄에 주석을 붙이면(`#!/bin/bash # 설명`) 커널이 `# 설명`까지 인터프리터의 인수로 넘겨 실행에 실패할 수 있다. 주석은 다음 줄에 쓴다.
{% endhint %}

### 변수의 범위

| 구분 | 선언 | 보이는 범위 |
|---|---|---|
| 전역 변수 | `name="value"` | 선언한 쉘(또는 스크립트) 안 전체 |
| 지역 변수 | 함수 안에서 `local name="value"` | 그 함수 안 |
| 환경 변수 | `export name="value"` | 선언한 쉘과 그 쉘이 실행하는 자식 프로세스 |
| 매개 변수 | `$1`, `$2`, `$#` | 스크립트 또는 함수에 넘긴 인자 |
| 예약 변수 | `HOME`, `PATH`, `UID`, `SHELL`, `USER`, `TERM`, `LANG` | 쉘이 미리 정의한 변수. 값을 함부로 바꾸지 않는다 |

## 3. 동작 원리

### 스크립트 실행 순서

1. 사용자가 `./script.sh`를 입력한다.
2. 쉘이 파일의 실행 권한을 확인한다. 권한이 없으면 `Permission denied`로 끝난다(종료 코드 126).
3. 커널이 첫 줄의 셔뱅을 읽어 지정한 인터프리터(`/bin/bash`)를 자식 프로세스로 시작한다.
4. 인터프리터가 스크립트를 위에서 아래로 한 줄씩 실행한다.
5. 마지막 명령(또는 `exit`)의 종료 코드를 부모 쉘에 돌려준다. 부모 쉘은 이 값을 `$?`로 읽는다.

### 실행 방법에 따른 차이

| 방법 | 실행 권한 | 셔뱅 | 실행 위치 |
|---|---|---|---|
| `./script.sh` | 필요하다 | 사용한다 | 자식 프로세스 |
| `bash script.sh` | 필요하지 않다 | 무시한다 | 자식 프로세스 |
| `source script.sh` (또는 `. script.sh`) | 필요하지 않다 | 무시한다 | 현재 쉘 |

스크립트는 자식 프로세스에서 실행되므로 스크립트 안에서 바꾼 변수는 부모 쉘에 남지 않는다. 반대로 부모 쉘의 변수는 `export`한 것만 스크립트에서 보인다. 현재 쉘의 변수를 바꾸는 스크립트는 `source`로 실행한다.

### 변수 명령

| 명령 | 역할 |
|---|---|
| `set` | 쉘 변수와 함수를 모두 출력한다 |
| `env` | 환경 변수만 출력한다 |
| `export <이름>=<값>` | 환경 변수로 선언한다 |
| `unset <이름>` | 변수를 삭제한다 |

## 4. 약어·용어

| 용어 | 뜻 |
|---|---|
| 셔뱅(shebang, hashbang) | 스크립트 첫 줄의 `#!<인터프리터 경로>` |
| 인터프리터 | 소스를 한 줄씩 해석해 실행하는 프로그램. `bash`가 여기에 해당한다 |
| 종료 코드(exit code) | 프로세스가 끝날 때 돌려주는 0~255 숫자. `0`은 성공이다 |
| 자식 프로세스 | 다른 프로세스가 시작한 프로세스. 부모의 변수를 `export`한 것만 물려받는다 |
| 이식성(portability) | 다른 쉘이나 배포판에서도 같은 스크립트가 도는 정도 |
