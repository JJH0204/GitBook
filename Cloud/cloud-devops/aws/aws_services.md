## 1. 목적

AWS는 서비스가 많아 처음에는 역할을 구분하기 어렵다. 이 문서는 원본에서 다룬 서비스를 분류별로 정리한다.

## 2. 구성 요소

| 번호 | 분류 | 서비스 | 역할 | 비고 |
|---|---|---|---|---|
| 1 | 접근 관리 | IAM | 사용자, 그룹, 정책으로 접근 권한을 관리한다 | CLD-AWS-001-DO 참조 |
| 2 | 저장소 | S3 | 객체 저장소다. 저장 단위를 버킷(bucket)이라 부른다 | 액세스 키가 없어도 다른 조건(정책, 역할)으로 접근할 수 있다 |
| 3 | 가상 서버 | EC2 | 가상 서버(인스턴스)를 만든다 | CLD-AWS-003-MP 참조 |
| 4 | 서버리스 컴퓨팅 | Lambda | 서버를 관리하지 않고 코드를 실행한다 | Python 등 언어를 지원한다. 환경 설정 없이 바로 코드를 작성할 수 있다 |
| 5 | 관계형 DB | RDS | MySQL, MariaDB, MS SQL 등 관계형 DB를 관리형으로 제공한다 | 정해진 스키마(규칙)에 따라 동작한다 |
| 6 | 비관계형 DB | DynamoDB 등 | 형식이 정해지지 않은 데이터를 다룬다 | SNS(소셜 미디어)처럼 형식이 일정하지 않은 데이터에 쓴다 |
| 7 | 컨테이너 | EKS | 관리형 쿠버네티스 서비스다 | 구축은 [AWS EKS 구축 및 운영](../kubernetes/kubernetes/eks.md) 참조 |
| 8 | 로그 | 로그 자동화 서비스 | 로그 수집과 분석을 자동화한다 | 원본은 서비스 이름 없이 "loging 자동화"로만 적었다. 서비스 이름은 확인 필요 |
| 9 | DevSecOps | DevSecOps 서비스 | 개발 파이프라인에 보안 점검을 넣는다 | 원본은 서비스 이름 없이 적었다. 확인 필요 |

{% hint style="info" %}
NOTE: 원본의 "S3 = 버킷이라는 명칭을 사용" 항목은 S3 행에 합쳤다. 원본 목록의 서비스 이름이 비어 있던 항목(비관계형 DB, 로그, DevSecOps)은 이름을 추정하지 않고 비워 두었다.
{% endhint %}

## 3. 동작 원리

1. 사용자는 IAM으로 인증하고 권한을 받는다.
2. 권한 범위 안에서 EC2, S3, Lambda 등 서비스를 호출한다.
3. 데이터는 S3 또는 DB 서비스에 저장한다.
4. 컨테이너 워크로드는 EKS에서 실행한다.
5. 로그와 보안 점검은 별도 서비스로 수집한다.

## 4. 약어·용어

| 약어 | 풀이 |
|---|---|
| S3 | Simple Storage Service |
| EC2 | Elastic Compute Cloud |
| RDS | Relational Database Service |
| EKS | Elastic Kubernetes Service |
| 버킷 | S3에서 객체를 담는 최상위 저장 단위 |
| 서버리스 | 서버 관리를 사용자가 하지 않는 실행 방식 |
