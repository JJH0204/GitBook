## 1. 목적

[AWS 아키텍처 다이어그램](aws.md)(CLD-AWS-001-DO)은 보안 그룹과 네트워크 ACL을 다루지만, 그것이 놓이는 네트워크 구조(VPC)는 다루지 않는다. 이 문서는 그 구조를 정리한다.

## 2. 구성 요소

| 번호 | 구성 요소 | 역할 | 비고 |
|---|---|---|---|
| 1 | VPC(Virtual Private Cloud) | 계정 안에 만드는 논리적으로 격리된 가상 네트워크다 | 리전 단위. IPv4 CIDR 블록(예: `10.0.0.0/16`)을 가진다. 계정에는 리전마다 기본 VPC가 있을 수 있다 |
| 2 | 서브넷(Subnet) | VPC의 주소 범위를 나눈 구간이다 | 가용 영역(AZ) 하나에 속한다. 서브넷마다 처음 4개와 마지막 1개 주소는 AWS가 예약한다 |
| 3 | 라우팅 테이블 | 목적지 주소별로 트래픽의 다음 경로를 정한다 | 서브넷마다 하나가 연결된다 |
| 4 | 인터넷 게이트웨이(IGW) | VPC와 인터넷을 연결한다 | VPC에 연결해 쓴다 |
| 5 | NAT 게이트웨이 | 프라이빗 서브넷의 인스턴스가 인터넷으로 나가게 한다. 밖에서 들어오는 연결은 받지 않는다 | 퍼블릭 서브넷에 둔다. 시간당 요금과 처리 데이터 요금이 부과된다 |
| 6 | 보안 그룹, 네트워크 ACL | 트래픽 허용 규칙 | CLD-AWS-001-DO 참조 |

### 퍼블릭 서브넷과 프라이빗 서브넷

| 구분 | 라우팅 테이블 | 인스턴스의 공인 IP | 용도 |
|---|---|---|---|
| 퍼블릭 서브넷 | `0.0.0.0/0` 경로가 인터넷 게이트웨이를 가리킨다 | 필요(퍼블릭 IP 또는 탄력적 IP) | 웹 서버, 로드 밸런서, NAT 게이트웨이 |
| 프라이빗 서브넷 | 인터넷 게이트웨이로 가는 경로가 없다. 외부 접속이 필요하면 `0.0.0.0/0`을 NAT 게이트웨이로 보낸다 | 없음 | 데이터베이스, 내부 애플리케이션 |

서브넷의 이름이 아니라 라우팅 테이블의 경로가 퍼블릭 여부를 정한다.

## 3. 동작 원리

1. 인스턴스가 목적지로 패킷을 보내면 서브넷의 라우팅 테이블이 가장 구체적인(접두사가 긴) 경로를 골라 다음 경로를 정한다.
2. VPC 안의 주소(`local` 경로)는 같은 VPC 안에서 직접 전달된다.
3. 퍼블릭 서브넷의 인스턴스가 인터넷과 통신하려면 인터넷 게이트웨이 경로와 공인 IP가 모두 필요하다.
4. 프라이빗 서브넷의 인스턴스가 업데이트를 내려받으려면 NAT 게이트웨이를 거친다.
5. 일반적인 구성은 AZ를 둘 이상 쓰고, AZ마다 퍼블릭·프라이빗 서브넷을 둔다. 웹 계층은 퍼블릭, 데이터베이스는 프라이빗에 둔다.

{% hint style="warning" %}
CAUTION: NAT 게이트웨이와 연결되지 않은 탄력적 IP는 요금이 부과될 수 있다. 실습 후 삭제한다. 요금 기준은 변경될 수 있으므로 AWS 요금 페이지에서 확인이 필요하다.
{% endhint %}

## 4. 약어·용어

| 용어 | 뜻 |
|---|---|
| VPC | Virtual Private Cloud |
| CIDR | Classless Inter-Domain Routing. `10.0.0.0/16` 같은 주소 범위 표기 |
| AZ | Availability Zone. 가용 영역 |
| IGW | Internet Gateway |
| NAT | Network Address Translation |
