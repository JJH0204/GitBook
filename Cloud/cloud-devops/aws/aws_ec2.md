## 3. 안전 사항

{% hint style="warning" %}
CAUTION: EC2 인스턴스, EBS 볼륨, 탄력적 IP는 만들면 과금이 시작된다. 실습이 끝나면 7절의 복구 절차로 반드시 삭제한다. 실행 중이 아니어도 EBS 볼륨과 연결되지 않은 탄력적 IP는 요금이 부과될 수 있다.
{% endhint %}

{% hint style="danger" %}
WARNING: 키 페어의 `.pem` 파일은 한 번만 내려받을 수 있고, 이 파일을 가진 사람은 인스턴스에 접속할 수 있다. 다른 사람과 공유하거나 저장소에 올리지 않는다. 분실하면 복구되지 않는다.
{% endhint %}

## 4. 준비

| 번호 | 항목 | 확인 방법 |
|---|---|---|
| 1 | 콘솔에 로그인한다 | 콘솔 대시보드가 보인다 |
| 2 | 리전을 확인한다 | 화면 오른쪽 위에 사용할 리전(원본은 서울)이 표시된다 |
| 3 | 사용할 이름과 보안 그룹 규칙을 정한다 | 인스턴스 이름과 허용할 접속 IP 범위를 적어 둔다 |

## 5. 절차

### A. 인스턴스 시작

1. (5-A-01) 콘솔에서 EC2 서비스를 연다. → 결과: EC2 대시보드가 보인다.
2. (5-A-02) `인스턴스 시작`을 누른다. → 결과: 인스턴스 생성 화면이 열린다.
3. (5-A-03) 인스턴스 이름을 입력한다: `<인스턴스 이름>`
4. (5-A-04) 소프트웨어 이미지(AMI, 운영체제 이미지)를 선택한다. → 결과: 이미지 정보가 표시된다.
5. (5-A-05) 인스턴스 유형(사양)을 선택한다. 실습에는 프리 티어 대상 유형을 고른다.
6. (5-A-06) 키 페어를 선택한다. 새로 만들려면 `새 키 페어 생성`을 누른다.
7. (5-A-07) 새 키 페어는 이름을 입력하고 `.pem` 형식으로 만든다. → 결과: `<키 이름>.pem` 파일이 내려받아진다.

{% hint style="info" %}
NOTE: 키 페어는 로그인에 필수다. 이미 만든 키를 등록해 쓸 수도 있다. 키를 S3 스토리지에 저장하는 것은 권장되는 방법이 아니라고 원본에 적혀 있다. 원본의 "비밀번호 작성" 항목은 키 방식과 별개이며 운영체제 설정에 따라 다르다. 확인이 필요하다.
{% endhint %}

8. (5-A-08) 네트워크 설정에서 보안 그룹(방화벽)을 정한다. SSH(22번 포트)는 본인 IP 주소 `<IP 주소>/32`만 허용한다. → 결과: 규칙이 목록에 보인다.

{% hint style="warning" %}
CAUTION: SSH 22번 포트를 `0.0.0.0/0`(모든 곳)으로 열지 않는다. 인터넷 전체에 접속을 허용하게 된다.
{% endhint %}

9. (5-A-09) 저장 공간을 설정한다. 실습에는 기본 크기를 쓴다. 암호화는 필요하면 선택한다.
10. (5-A-10) 인스턴스 개수를 1로 둔다.
11. (5-A-11) 오른쪽의 요금 부가 정보를 확인한다. → 결과: 예상 비용이 표시된다.

{% hint style="warning" %}
CAUTION: 다음 단계부터 과금이 시작된다. 원본은 "IP를 설정하면 비용이 발생하므로 연습할 때는 만들기만 하고 사용하지 않는다"고 적었다. 탄력적 IP는 실습에서 만들지 않는다.
{% endhint %}

12. (5-A-12) `인스턴스 시작`을 누른다. → 결과: 인스턴스가 목록에 나타나고 상태가 `실행 중`이 된다.

### B. 연결 정보 확인

1. (5-B-01) 인스턴스 목록에서 만든 인스턴스를 선택한다.
2. (5-B-02) 공인 IP 주소를 확인한다. → 결과: `<IP 주소>`가 표시된다. 이 주소는 동적이라 인스턴스를 중지하고 다시 시작하면 바뀐다.
3. (5-B-03) 기본 사용자 이름을 확인한다. AMI마다 다르다(예: Amazon Linux는 `ec2-user`, Ubuntu는 `ubuntu`).

### C. 접속

1. (5-C-01) `.pem` 파일의 권한을 제한한다: `chmod 400 <키 이름>.pem` → 결과: 오류 없이 끝난다.
2. (5-C-02) SSH로 접속한다: `ssh -i <키 이름>.pem <사용자 이름>@<IP 주소>` → 결과: 셸 프롬프트가 나타난다.

### D. 모니터링

1. (5-D-01) 인스턴스를 선택하고 `모니터링` 탭을 연다. → 결과: CPU 사용률 등 머신 사용량 그래프가 보인다.

## 6. 기능 확인

| 번호 | 확인 동작 | 기대 결과 | 합격 기준 |
|---|---|---|---|
| 1 | 인스턴스 상태 확인 | `실행 중` | 상태 검사 2/2 통과 |
| 2 | SSH 접속 | 셸 프롬프트 | 접속 거부 없이 로그인 |
| 3 | 모니터링 탭 | 사용량 그래프 | 그래프가 표시된다 |

## 7. 복구

{% hint style="warning" %}
CAUTION: 이 절을 수행하지 않으면 과금이 계속된다. 인스턴스를 `중지`만 하면 컴퓨팅 요금은 멈추지만 EBS 볼륨 요금은 계속 부과된다. 삭제는 `종료`로 한다.
{% endhint %}

1. (7-01) 인스턴스를 선택하고 `인스턴스 상태 > 인스턴스 종료`를 누른다. → 결과: 상태가 `종료됨`이 된다.
2. (7-02) EBS `볼륨` 목록에 남은 볼륨이 없는지 확인한다. → 결과: 이 인스턴스의 볼륨이 목록에 없다. 있으면 삭제한다.
3. (7-03) 탄력적 IP를 만들었다면 `탄력적 IP`에서 연결을 해제하고 릴리스한다. → 결과: 목록이 비어 있다.
4. (7-04) 쓰지 않는 보안 그룹과 키 페어를 삭제한다. 내려받은 `.pem` 파일도 삭제한다.
5. (7-05) 결제 대시보드에서 다음 날 발생 요금이 0인지 확인한다.
