## 1. 목적

클라우드 컴퓨팅(cloud computing)은 서버, 스토리지, 네트워크 같은 컴퓨팅 자원을 인터넷으로 빌려 쓰는 방식이다. 사용자는 시간과 장소에 구애받지 않고 자원을 빠르게 만들고 없앤다. 이 문서는 클라우드의 기반 기술, 온프레미스와의 차이, 배포 방식, 서비스 모델, 보안 책임 범위를 정리한다.

## 2. 구성 요소

### 2.1 가상화

가상화(virtualization)는 서버, 스토리지, 네트워크 같은 물리 자원을 소프트웨어로 나눠 가상 자원으로 보여 주는 기술이다. 클라우드의 기반이다. 얻는 효과는 다음과 같다.

* 개발 환경을 직접 구축하지 않아 준비 시간이 줄어든다.
* 물리 장비 구매 투자가 줄어든다.
* 자원을 필요한 만큼 늘리고 줄일 수 있어 유연성이 커진다.

### 2.2 온프레미스와 클라우드 비교

온프레미스(on-premises)는 조직이 자체 시설에 장비를 두고 직접 운영하는 방식이다.

| 항목 | 온프레미스 | 클라우드 |
|---|---|---|
| 초기 비용 | 장비 구매 비용이 크다 | 사용한 만큼 지불한다 |
| 유지 보수 | 직접 한다 | 물리 장비 유지 보수는 제공업체가 맡는다 |
| 장애 대응 | 직접 원인을 찾아 즉시 조치한다 | 제공업체 영역의 장애는 제공업체가 해결할 때까지 기다려야 한다 |
| 책임 구분 | 조직이 전부 진다 | 제공업체와 이용자가 나눠 진다. 기준은 약관에 있다 |

### 2.3 배포 방식

배포 방식은 클라우드를 누가 운영하느냐로 나뉜다.

| 방식 | 설명 |
|---|---|
| 사설 클라우드(private) | 조직이 직접 구축하고 관리하거나 전용 환경을 제공받는다 |
| 공공 클라우드(public) | 외부 업체가 제공하는 서비스를 빌려 쓴다. 예: AWS, Microsoft Azure, Naver Cloud |
| 하이브리드 클라우드(hybrid) | 사설과 공공을 함께 쓰며 둘의 장점을 취한다 |
| 멀티 클라우드(multi) | 서비스 분산을 위해 둘 이상의 클라우드를 쓴다 |

{% hint style="info" %}
NOTE: 사설 클라우드와 온프레미스는 같은 말이 아니다. 사설 클라우드는 클라우드 기술(가상화, 자원 풀)을 쓰는 사설 환경이고, 온프레미스는 장비의 위치와 소유를 가리킨다.
{% endhint %}

### 2.4 서비스 모델

아래 표에서 이용자가 관리하는 계층은 "이용자"로 표시한다. 나머지는 제공업체가 관리한다.

| 계층 | 온프레미스 | IaaS | PaaS | SaaS |
|---|---|---|---|---|
| 애플리케이션(Application) | 이용자 | 이용자 | 이용자 | 제공업체 |
| 데이터(Data) | 이용자 | 이용자 | 이용자 | 이용자(주로 입력·설정) |
| 런타임(Runtime) | 이용자 | 이용자 | 제공업체 | 제공업체 |
| 미들웨어(Middleware) | 이용자 | 이용자 | 제공업체 | 제공업체 |
| 운영체제(OS) | 이용자 | 이용자 | 제공업체 | 제공업체 |
| 가상화(Virtualization) | 이용자 | 제공업체 | 제공업체 | 제공업체 |
| 서버(Servers) | 이용자 | 제공업체 | 제공업체 | 제공업체 |
| 스토리지(Storage) | 이용자 | 제공업체 | 제공업체 | 제공업체 |
| 네트워킹(Networking) | 이용자 | 제공업체 | 제공업체 | 제공업체 |

* IaaS(Infrastructure as a Service): 인프라를 빌린다. OS부터 이용자가 원하는 대로 구축한다.
* PaaS(Platform as a Service): 개발·실행 플랫폼을 빌린다.
* SaaS(Software as a Service): 완성된 소프트웨어를 쓴다. 예: Microsoft Office 온라인 서비스.
* 원본에 DaaS(Data as a Service)가 나열돼 있다. DaaS는 문맥에 따라 Desktop as a Service를 뜻하기도 해 정의를 확인해야 한다(확인 필요).

## 3. 동작 원리

클라우드 보안 책임은 서비스 모델에 따라 이용자와 제공업체가 나눠 진다. 이를 공유 책임 모델(shared responsibility model)이라 부른다. 핵심은 다음과 같다.

1. 이용자가 관리하는 계층의 보안은 이용자 책임이다. 서비스 종류에 따라 관리 대상 계층은 달라도 관리해야 한다는 점은 같다.
2. 제공업체가 관리하는 계층의 보안은 제공업체 책임이다. 이용자는 그 내용을 약관과 인증 현황으로 확인한다.
3. 클라우드에 구축하는 보안 시스템은 로컬에 구축하던 보안 시스템과 구성이 다르지 않다. 제공업체와 서비스 종류에 따라 이름과 구현 방식만 다르다.
4. 책임 구분과 보상 기준이 불명확하면 사고 후 분쟁이 생긴다. 서비스를 고르기 전에 책임 구분 약관을 읽는다.
5. 성능 등급에 따라 비용 차이가 크다. 서비스 선택 전에 요금 체계를 확인한다.

보안 인증 기관과 교육은 다음과 같다.

* 클라우드 보안 단체 CSA(Cloud Security Alliance)가 클라우드 보안 지침과 자격을 제공한다.
* 한국인터넷진흥원(KISA)이 정보보호 및 개인정보보호 관리체계(ISMS-P) 인증을 운영하고, 온라인 교육과 재직자 대상 강의를 제공한다. 일부 과정은 수료증을 발급한다.

## 4. 약어·용어

| 용어 | 뜻 |
|---|---|
| 온프레미스(On-premises) | 조직 자체 시설에서 직접 운영하는 방식 |
| 가상화(Virtualization) | 물리 자원을 소프트웨어로 나눠 가상 자원으로 만드는 기술 |
| IaaS | 인프라를 서비스로 제공하는 모델 |
| PaaS | 개발·실행 플랫폼을 서비스로 제공하는 모델 |
| SaaS | 소프트웨어를 서비스로 제공하는 모델 |
| 공유 책임 모델 | 클라우드 보안 책임을 제공업체와 이용자가 나눠 지는 원칙 |
| ISMS-P | 정보보호 및 개인정보보호 관리체계 인증 |
