| 개정 | R1 (2026-11-18) |

## 1. 목적

컨테이너는 도커 이미지로 만든 실행 인스턴스다. 호스트 운영체제 위에서 분리된 프로세스처럼 동작한다. 이 문서는 컨테이너의 정의와 특성을 정리한다.

## 2. 구성 요소

| 번호 | 항목 | 설명 |
|---|---|---|
| 1 | 정의 | 이미지로부터 만들어진 실행 가능한 인스턴스다. 실행 중인 이미지를 컨테이너라고 부른다 |
| 2 | 결정 요소 | 이미지와, 컨테이너를 시작할 때 지정한 옵션(포트, 볼륨, 환경 변수 등)이 컨테이너를 정한다 |
| 3 | 격리 | 컨테이너는 실행 중에 자신만의 분리된 파일 시스템을 쓴다 |
| 4 | 경량성 | 새 운영체제를 설치하지 않고 호스트 커널을 공유하므로 가상 머신보다 가볍다 |

## 3. 동작 원리

1. 가상 머신은 하이퍼바이저 위에 게스트 운영체제를 통째로 올린다. VirtualBox가 그 예다.
2. 컨테이너는 호스트 커널을 공유하고, 프로세스 단위로 파일 시스템과 자원을 분리한다.
3. 따라서 컨테이너는 가상 머신보다 시작이 빠르고 자원을 적게 쓴다.
4. 컨테이너를 삭제하면 컨테이너 안에서 바뀐 파일은 사라진다. 이미지는 영향을 받지 않는다.

{% hint style="info" %}
NOTE: 원본은 컨테이너를 "VirtualBox 등으로 다른 운영체제 환경을 구축하는 것과 유사하다"고 적었다. 사용 목적은 비슷하지만 컨테이너는 게스트 운영체제 없이 호스트 커널을 공유하는 점이 다르다.
{% endhint %}

## 4. 약어·용어

| 용어 | 뜻 |
|---|---|
| 컨테이너(Container) | 이미지로 만든 격리된 실행 환경 |
| 인스턴스(Instance) | 이미지를 바탕으로 만든 실행 개체 |
| 호스트(Host) | 도커 엔진이 설치된 실제 컴퓨터 |
