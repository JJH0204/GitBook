## 1. 점검 항목

### A. Dockerfile

| 번호 | 점검 항목 | 기준 | 합격 |
|---|---|---|---|
| 1 | 기본 이미지 태그 | `latest`가 아니라 버전 태그를 쓴다. 더 엄격하게는 다이제스트(`@sha256:...`)로 고정한다 | [ ] |
| 2 | 기본 이미지 크기 | 필요한 최소 이미지(예: slim, alpine 계열)를 쓴다 | [ ] |
| 3 | 실행 사용자 | `USER <비루트 사용자>`로 root가 아닌 사용자로 실행한다 | [ ] |
| 4 | 비밀값 | `ENV`, `ARG`, `COPY`로 비밀번호·키를 이미지에 넣지 않는다. 이미지 레이어에 남는다 | [ ] |
| 5 | `.dockerignore` | `.git`, `.env`, 키 파일을 빌드 컨텍스트에서 제외한다 | [ ] |
| 6 | 멀티 스테이지 | 빌드 도구는 빌드 단계에만 두고 최종 이미지에는 결과물만 복사한다 | [ ] |
| 7 | 패키지 캐시 | 패키지 설치와 같은 `RUN`에서 캐시를 지운다 (예: `rm -rf /var/lib/apt/lists/*`) | [ ] |

### B. 컨테이너 실행

| 번호 | 점검 항목 | 기준 | 합격 |
|---|---|---|---|
| 1 | 특권 모드 | `--privileged`를 쓰지 않는다 | [ ] |
| 2 | 도커 소켓 | `/var/run/docker.sock`을 컨테이너에 마운트하지 않는다. 마운트하면 호스트 전체를 제어할 수 있다 | [ ] |
| 3 | 권한(capability) | `--cap-drop ALL` 후 필요한 것만 `--cap-add`한다 | [ ] |
| 4 | 쓰기 | 가능하면 `--read-only`로 실행하고 쓸 경로만 볼륨·tmpfs로 둔다 | [ ] |
| 5 | 포트 게시 | 외부에 열 포트만 게시한다. 내부 서비스는 `127.0.0.1`로 제한한다 | [ ] |
| 6 | 자원 제한 | `--memory`, `--cpus`로 상한을 둔다 | [ ] |

### C. 이미지 취약점 검사

| 번호 | 점검 항목 | 기준 | 합격 |
|---|---|---|---|
| 1 | 검사 도구 실행 | Trivy 같은 도구로 이미지를 검사한다: `trivy image <이미지:태그>` | [ ] |
| 2 | 결과 처리 | 심각도 HIGH 이상 취약점은 기본 이미지 갱신 또는 패키지 갱신으로 해결하거나 예외 사유를 기록한다 | [ ] |
| 3 | 재검사 주기 | 배포 시와 정기(예: 주 1회)로 다시 검사한다 | [ ] |

{% hint style="warning" %}
CAUTION: 이 표는 일반적인 기준이다. 서비스에 따라 `--read-only` 등이 동작하지 않을 수 있다. 적용 후 서비스가 정상 동작하는지 확인한다. Trivy 명령은 이 환경에서 실행하지 않았다.
{% endhint %}
