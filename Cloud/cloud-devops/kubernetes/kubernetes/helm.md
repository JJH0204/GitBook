## 1. 목적

앱 하나를 배포하는 데 디플로이먼트, 서비스, 컨피그맵, 인그레스 등 YAML 여러 개가 필요하다. 환경(개발·운영)마다 값만 다른 YAML을 복사해 관리하면 오류가 늘어난다. Helm은 이 YAML 묶음을 하나의 패키지(차트)로 만들고, 값만 바꿔 설치한다.

## 2. 구성 요소

| 번호 | 요소 | 설명 |
|---|---|---|
| 1 | 차트(Chart) | 매니페스트 템플릿과 기본값을 담은 패키지 |
| 2 | 릴리스(Release) | 차트를 클러스터에 설치한 한 번의 인스턴스. 이름이 있다 |
| 3 | 저장소(Repository) | 차트를 모아 둔 곳 |
| 4 | `values.yaml` | 템플릿에 들어갈 설정 값. 설치할 때 덮어쓸 수 있다 |
| 5 | 리비전(Revision) | 릴리스를 설치·갱신할 때마다 늘어나는 번호 |

### 2.1 차트 디렉터리

| 경로 | 설명 |
|---|---|
| `Chart.yaml` | 차트 이름, 버전 등 메타데이터 |
| `values.yaml` | 기본 설정 값 |
| `templates/` | 값을 채워 YAML로 만들 템플릿 |
| `charts/` | 의존하는 하위 차트 |

## 3. 동작 원리

1. Helm 클라이언트가 차트의 템플릿과 값을 합쳐 매니페스트를 만든다.
2. 만든 매니페스트를 쿠버네티스 API로 적용한다.
3. 릴리스 정보(리비전별 매니페스트와 값)는 클러스터 안에 `Secret` 개체로 저장된다.
4. 갱신하면 새 리비전이 생기고, 이전 리비전으로 되돌릴 수 있다.

Helm 3는 클러스터에 서버 구성 요소(Tiller)를 두지 않는다. 클라이언트가 `kubectl`과 같은 kubeconfig 권한으로 동작한다.

## 4. 주요 명령

| 명령 | 설명 |
|---|---|
| `helm repo add <이름> <저장소URL>` | 저장소를 등록한다 |
| `helm repo update` | 저장소 목록을 갱신한다 |
| `helm search repo <키워드>` | 차트를 찾는다 |
| `helm show values <차트>` | 차트의 기본 값을 본다 |
| `helm template <릴리스> <차트> -f values.yaml` | 클러스터에 적용하지 않고 만들어질 YAML만 출력한다 |
| `helm install <릴리스> <차트> -n <네임스페이스> -f values.yaml` | 설치한다 |
| `helm install ... --dry-run` | 서버 검증까지만 하고 적용하지 않는다 |
| `helm list -n <네임스페이스>` | 설치된 릴리스 목록 |
| `helm upgrade <릴리스> <차트> -f values.yaml` | 값이나 차트 버전을 바꿔 갱신한다 |
| `helm history <릴리스>` | 리비전 이력을 본다 |
| `helm rollback <릴리스> <리비전>` | 이전 리비전으로 되돌린다 |
| `helm uninstall <릴리스>` | 릴리스가 만든 자원을 삭제한다 |

{% hint style="warning" %}
CAUTION: 외부 저장소의 차트는 임의의 자원을 만들 수 있다. 설치 전에 `helm show values`, `helm template`으로 만들어질 내용을 읽고, 신뢰할 수 있는 저장소만 등록한다.
{% endhint %}

{% hint style="info" %}
NOTE: `--set`으로 비밀번호를 넘기면 셸 기록에 남는다. 비밀 값은 별도 값 파일이나 시크릿 관리 도구로 넘긴다.
{% endhint %}

## 5. 약어·용어

| 용어 | 뜻 |
|---|---|
| 차트 | Helm 패키지 |
| 릴리스 | 설치된 차트 인스턴스 |
| 템플릿 | 값을 넣어 YAML로 바뀌는 파일 (Go 템플릿 문법) |
| 오버라이드 | 기본 값 위에 `-f`나 `--set`으로 값을 덮어쓰는 것 |
