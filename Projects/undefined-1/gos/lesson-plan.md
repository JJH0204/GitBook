# 수업 진행안: 코드 없이 기믹 만들기 (GOS)

대상은 유니티를 처음 다루는 기획자이고, 목표는 GOS 노드를 조합해 기믹을 직접 구성하고 원인을 찾아 고치는 것이다. 교재는 [guide-for-designers.md](guide-for-designers.md)와 [examples.md](examples.md)다.

{% hint style="warning" %}
이 진행안은 GOS를 수업에서 쓰는 강사를 위한 참고용 제안이다. 시간 배분과 동작 설명은 코드를 읽고 짠 것이며 실제 수업과 에디터 실행으로 검증하지 않았다(unverified). 수업 전에 강사가 모든 예제를 한 번 따라 해 보고 시간을 조정한다.
{% endhint %}

## 수업 전 강사 준비

- 수강생 PC의 Unity 버전을 통일한다(GOS는 2022.3.62f1로 만들어졌다). 다른 버전은 확인하지 못했다.
- Cinemachine 2.10.x 설치 가능 여부(네트워크)를 확인한다. 어렵다면 `CameraControl.cs`를 빼고 예제 4를 시연으로 대체한다.
- 시작용 프로젝트(`Assets/Scripts` 복사 완료, Ground와 Player 준비)를 미리 만들어 배포하면 설치 시간을 줄일 수 있다.
- [examples.md](examples.md)의 `PlayerMove.cs`를 준비한다. 새 Input System만 활성화된 프로젝트에서는 동작하지 않을 수 있다.
- 강사 시연용 완성본 씬을 만들어 둔다.

## 시간 배분 예시 (120분)

| 시간 | 단계 | 목표 | 활동 |
|---|---|---|---|
| 0~10분 | 도입 | 도구의 쓰임을 이해한다 | 완성 시연(문 열림, 컷씬). 입력·처리·출력 설명 |
| 10~25분 | 설치 | 환경을 갖춘다 | Cinemachine 설치, 스크립트 복사, 메뉴 확인 |
| 25~45분 | 첫 기믹 | 노드 연결의 원리를 익힌다 | 예제 1을 강사와 함께 단계별로 구성. `Is On` 확인법 |
| 45~55분 | 휴식 | | |
| 55~75분 | 시간·결과 | 순서 있는 기믹을 만든다 | 예제 2 실습. `Timer`가 시작되는 방식 설명 |
| 75~95분 | 선택 실습 | 조건을 조합한다 | 예제 3과 예제 5 중 선택, 짝 실습 |
| 95~110분 | 컷씬 | 연출 노드를 다룬다 | 예제 4 시연 후 실습 또는 시연으로 대체 |
| 110~120분 | 마무리 | 이해를 점검한다 | 미니 과제 안내, 평가표로 자기 점검, 질의 |

90분으로 줄일 때는 예제 3·5 중 하나와 예제 4를 시연으로 대체하고, 설치는 배포 프로젝트로 건너뛴다.

## 단계별 지도 요점

1. 도입: "코드를 한 줄도 쓰지 않는다"를 먼저 보여 준다. 세 종류(입력·처리·출력)를 신호등 비유처럼 "센서, 판단, 행동"으로 설명한다.
2. 설치: 콘솔 빨간 오류부터 확인시킨다. 오류가 있으면 다음 단계로 가지 않는다.
3. 첫 기믹: 노드를 하나씩 만들고 칸에 끌어다 놓게 한다. 문이 열리지 않을 때 `Is On`을 보는 습관을 만든다.
4. 시간·결과: `Timer`는 스스로 시작하지 않으므로 `Conditional`이 필요하다는 점을 질문으로 유도한다.
5. 조합: `Logic`(And/Or)과 `Is Not`으로 조건을 바꿔 본다.
6. 컷씬: 컷씬 카메라의 Priority를 메인보다 낮게 두는 규칙을 강조한다.

## 흔한 오류와 대처

| 증상 | 원인 | 대처 |
|---|---|---|
| 컴파일 오류가 많이 남 | Cinemachine 미설치 또는 3.x 설치 | 2.10.x 설치, 어렵다면 `CameraControl.cs` 삭제 |
| 우클릭 메뉴에 VisualScripting이 없음 | 컴파일 오류, 또는 `Editor` 폴더 위치 오류 | 콘솔 오류 해결, 폴더 구조 확인 |
| 트리거가 반응하지 않음 | 태그 불일치, Rigidbody 없음, `Is Trigger` 해제 | 태그·Rigidbody·Is Trigger 순으로 확인 |
| `NullReferenceException` | 비어 있는 연결 칸 | 오류 클릭으로 노드를 찾아 칸을 채움 |
| Is On은 켜지는데 결과 없음 | `Conditional`의 출력 목록이 비었거나 대상 칸이 빈 상태 | 출력 목록과 대상 확인 |
| 문이 한 번만 열림 | `Rotate Once`가 켜져 있음 | 의도한 동작임을 설명, 끄면 다시 실행 가능 |
| `Timer`가 작동하지 않음 | 시작시키는 `Conditional`이 없음 | 시작 노드 연결 |
| `Destroy`를 메뉴에서 못 찾음 | 메뉴 미등록 | Add Component로 추가 |
| 컷씬 카메라가 전환되지 않음 | 컷씬 카메라 Priority가 메인 이상, Brain 미지정 | Priority를 낮추고 Brain 지정 |
| 노드가 동작하지 않음(꺼진 부모) | 노드가 비활성 오브젝트 아래에 있음 | `GOS` 루트 아래로 이동 |

## 수강생 실습 체크리스트

- [ ] 설치를 마쳤고 우클릭 메뉴에서 노드를 만들 수 있다.
- [ ] `Is On` 체크박스로 노드 상태를 확인하며 동작을 추적할 수 있다.
- [ ] 예제 1을 완성했다.
- [ ] 예제 2를 완성했다.
- [ ] 예제 3·4·5 중 하나 이상을 완성했다.
- [ ] 오류가 났을 때 콘솔 메시지를 읽고 원인 칸을 찾아 고쳤다.
- [ ] 미니 과제: 자신이 정한 기믹 하나를 구성해 시연했다.

## 평가 기준

| 항목 | 우수 | 보통 | 미흡 |
|---|---|---|---|
| 구조 이해 | 입력·처리·출력 역할을 자기 말로 설명한다 | 역할은 알지만 연결에 도움이 필요하다 | 노드의 역할을 구분하지 못한다 |
| 구성 능력 | 예제 3개 이상을 스스로 구성한다 | 예제 2개를 구성한다 | 예제 1개 이하 |
| 디버깅 | `Is On`과 콘솔로 스스로 원인을 찾는다 | 힌트를 받아 해결한다 | 해결하지 못한다 |
| 응용 | 자신만의 기믹을 설계해 구현한다 | 예제를 일부 변형한다 | 예제를 그대로 따라 한다 |

## 실습 후 과제 아이디어

- 두 가지 조건(And)으로 열리는 문과, 열린 뒤 일정 시간 뒤에 닫히는 연출을 설계해 본다(닫힘은 `Rotate Once`를 끈 `RotateObject`와 `Timer` 조합 등을 검토).
- 자신이 기획한 게임의 기믹 한 개를 노드 구성도(입력→처리→출력)로 그린 뒤 구현한다.
