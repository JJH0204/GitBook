# 바다 (Bada)

어촌 마을에서 하루를 보내는 낚시·생활 시뮬레이션 게임의 프로토타입 기록이다. 수온과 물때에 따라 조황이 달라지고, 낚은 고기를 손질해 먹고 파는 하루 루프를 만든다.

## 개요

| 항목 | 내용 |
|---|---|
| 형태 | 개인 프로토타입(PC) |
| 기간 | 2026년 10월(웹 목업에서 Godot 이식판까지 약 일주일) |
| 사용 기술 | three.js(웹 목업), Unity 6 URP(낚시 슬라이스), Godot 4 .NET(C#) |
| 아트 | 3D 로우폴리를 저해상도로 그려 정수 배로 키우는 픽셀 아트 후처리 |
| 한 일 | 목업 설계, 규칙 이식, 렌더링과 UI 재현, 확장 기능 구현, 자동 테스트, Windows 빌드 |
| 관련 레포 | 비공개 |
| 상태 | 프로토타입. 직접 플레이로 재미를 확인하는 단계 |

## 진행 과정

1. **웹 목업(three.js)** 으로 하루 루프를 먼저 검증했다. 배 몰기, 찌를 던져 두고 다른 일 하기, 손질, 요리, 식사와 버프를 정했다. 이후 모든 이식의 기준이 된다.
2. **Unity 낚시 슬라이스**로 낚시 한 판(출항, 닻, 낚시, 싸움)을 만들고, 규칙 메모와 수용 기준, 데이터 표를 정리했다. 왼손 좌표계 때문에 화면이 뒤집혀 보인 문제가 있어 Unity는 참고용으로 남겼다.
3. **Godot 이식**: 게임 규칙을 엔진과 분리한 순수 C# 코드로 옮기고, 데이터 표는 JSON에서 자동 생성했다. 목업의 골든 값을 테스트로 맞췄다.
4. **확장 기능**: 공공 수온 데이터 연동(평년값 위에 실제 편차를 얹는 혼합 방식), 금어기와 금지 체장, 마을 행사와 바다 이벤트, 도감, 횟집, 이웃 부탁, 휴대폰 UI.
5. **Windows 실행 파일**: 배포용 템플릿을 받을 수 없는 환경이라 소스에서 크로스 컴파일하는 스크립트를 만들었다.

## 주요 결정

- **규칙과 엔진 분리.** 난수를 한 곳으로 모으면 테스트에서 값을 고정할 수 있다. 엔진 없이도 규칙 테스트가 돈다.
- **목업을 기준으로 삼는다.** 수치가 다르면 목업을 따른다는 원칙으로 이식 중 논쟁을 줄였다.
- **UI 배치는 나중에.** 기능을 먼저 넣고 화면 배치는 미룬다.
- **복셀 대신 로우폴리 + 후처리.** 모델링 부담을 줄이면서 픽셀 아트 느낌을 낸다.
- **외부 데이터는 끊겨도 돌아가야 한다.** 실제 수온을 못 받으면 평년값으로 진행한다.

## 검증 방법

규칙 테스트, 중계 서버 테스트, 하루 전체를 키와 마우스로 플레이하는 자동 테스트를 두고 빌드 경고 0을 유지했다. 화면은 목업과 나란히 스크린샷을 찍어 비교했다. 자동 테스트가 통과해도 재미는 직접 플레이해야 알 수 있다는 것이 남은 숙제다.

## 배운 점

- 먼저 가장 싼 도구(웹 목업)로 재미를 검증하고, 엔진 이식은 규칙이 확정된 뒤에 한다.
- 수용 기준(A1~A16처럼 번호를 붙인 검증 항목)을 먼저 써 두면 이식이 맞게 됐는지 기계로 판단할 수 있다.
- 실제 환경(Windows 실제 PC)에서 돌려 보지 않은 빌드는 "확인됨"이 아니다. 이 프로젝트의 실행 파일은 Wine에서만 확인한 상태라 한계를 문서에 적어 두었다.
- 수치가 초안인 항목(횟집, 부탁, 이벤트)은 초안이라고 표시해 두어야 이후에 믿고 쓰지 않는다.
- 실제 법령 기반 요소(금어기, 금지 체장)는 출시 전에 현행 기준으로 다시 확인해야 한다.
