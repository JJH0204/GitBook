## 1. 목적

팀 DevSecOps에 외주 의뢰가 도착했다는 설정으로, 사옥 이전 회사의 내부 인프라와 보안 체계를 설계하고 구축하는 프로젝트의 요구사항과 역할 분담을 정리한다.

## 2. 의뢰 개요

| 항목 | 내용 |
|---|---|
| 의뢰사 | 신생 게임·소프트웨어 개발 회사 G.G.M. 모회사 KoreaIT에서 독립해 새 프로젝트를 진행한다 |
| 건물 | 지하 1층부터 7층까지 건물 전체를 사용한다. 건물 위치는 원본에 있으나 공개 문서이므로 적지 않는다 |
| 외부 회선 | 통신사에서 공인 IP를 할당받았다. 값은 `<공인 IP 생략>`이다 |
| 근무 형태 | 사내 근무와 재택 근무를 선택한다. 업체는 타 지역 인력을 위해 100% 재택근무 제도를 시행하려 한다 |
| 서비스 | 지하 서버실에서 회사 인트라넷과 회사 홈페이지, 웹 서비스 2종을 운영한다 |

## 3. 요구사항

| 번호 | 요구사항 | 세부 내용 |
|---|---|---|
| 1 | 보안 최우선 | 프로젝트 정보 유출을 극도로 경계한다. 회사에서 외부로 나가는 모든 데이터를 점검·관리하고 모든 엔드포인트 장치를 관리한다 |
| 2 | 재택근무 보안 | 효과적인 VPN을 구축한다. 외부 네트워크에서 들어오는 요청을 안전하게 방어·관리하는 시스템을 만든다 |
| 3 | 자체 서버실 운영 | 지하 서버실과 웹 서비스가 이미 운영 중이다. 소프트웨어 개발 서버와 보안 서버를 추가로 구축한다 |
| 4 | 웹 서비스 보안 점검 | 모회사의 자회사였을 때 구축한 웹 서버·서비스를 점검한다. 모의해킹 결과 보고서 1종과 점검·관리 스크립트를 제작한다 |
| 5 | DDoS 방어 | 과거 게임 서버와 웹 서버에 DoS 공격을 받은 적이 있다. 사옥 이전 시 최소한의 DDoS 방어 대책을 적용한다 |

시나리오 단계별 요청은 다음과 같다.

| 단계 | 내용 |
|---|---|
| 요청 1 | 건물 전체를 층별 용도에 맞게 쓴다. 사내 네트워크 접속 보안을 위해 VPN을 설치한다 |
| 요청 2 | 층끼리 서로 통신할 필요는 없다. 지하 서버실의 웹 서비스에는 모든 층에서 접속할 수 있어야 한다. 서버실에 보안 설비를 추가하고, 사내 PC에 보안 솔루션을 적용해 점검·관제한다 |
| 2차 시나리오 | 서버실에서 회사 인트라넷과 회사 홈페이지 2종을 운영한다. 두 서비스는 로컬 환경에서 구동하므로 로컬 서버 보안 솔루션을 최적화한다 |

## 4. 건물 구성과 네트워크 구상

층별 구성은 원본에 층 번호와 용도가 나란히 나열돼 있어 순서대로 맞춰 정리했다. 대응 관계는 추정이다. 확인 필요.

| 층 | 용도 |
|---|---|
| B1 | 서버실 |
| 1F | 출입 관리 시스템 |
| 2F | 서버팀 사무실 |
| 3F | 기획/디자인팀 사무실 |
| 4F | 클라이언트팀 사무실 |
| 5F | 인사팀 사무실 |
| 6-7F | 휴식 공간 |

1차 토폴로지의 구성 요소는 다음과 같다. 연결 순서는 원본에 없다.

| 구성 요소 | 비고 |
|---|---|
| ISP, WWW | 외부 회선 |
| 재택 | VPN으로 접속한다 |
| Cisco ASAv | 방화벽·VPN 장비(가상 어플라이언스) |
| Main Router, L3 Switch | 코어 구간 |
| L2-Server | 서버실 스위치 |
| 1~7F-Switch | 층별 스위치 |

## 5. 보안 솔루션 구상

| 솔루션 | 구상 내용(원본 기록) |
|---|---|
| Snort | 서비스가 동작하는 같은 머신에 설치해야 공격·그 외 패킷을 탐지할 수 있다고 기록했다. 웹 서비스만 탐지한다 |
| Wazuh | 다른 머신에 설치해도 탐지에 문제가 없다. 에이전트를 등록해 작업자 PC를 보안 관리한다. 가상머신으로 구동한 Windows에 에이전트를 등록할 수 있음을 확인했다 |
| DDoS 탐지 스크립트 | 같은 출발지 IP에서 분당 n회 이상 요청이 들어오는 패킷을 스크립트로 탐지한다 |

{% hint style="info" %}
NOTE: Snort는 미러링(SPAN) 포트로 복사한 트래픽도 분석할 수 있다. "같은 머신에 설치해야 한다"는 원본 서술은 해당 실습 구성에서의 결과로 읽는다. 일반 원칙은 미검증이다.
{% endhint %}

## 6. 팀 역할 구성

팀은 네트워크팀, 블루팀(보안), 레드팀(모의해킹)으로 나뉜다. 팀원 이름은 공개 문서에서 제외했다.

| 팀 | 주 업무 |
|---|---|
| 블루팀(보안) | 보안 스크립트와 공격 시뮬레이션용 스크립트 작성, 악성코드 분석, IDS 구축·관리와 관리용 스크립트 작성 |
| 레드팀(모의해킹) | 취약한 웹 서버 구축과 취약점 시나리오 설계, 모의해킹과 결과보고서 작성, 블루팀 협업 |
| 네트워크팀 | GNS3 네트워크 토폴로지 구성, 방화벽 설정과 네트워크 보안 업무, 관리용 스크립트 작성 |

## 7. 약어·용어

| 용어 | 뜻 |
|---|---|
| VPN | Virtual Private Network. 외부에서 사내망에 암호화된 통신로로 접속하는 기술 |
| IDS | Intrusion Detection System. 침입 탐지 시스템 |
| WAN | Wide Area Network. 통신사 회선을 통한 외부망 |
| DDoS | Distributed Denial of Service. 여러 출발지에서 서비스를 마비시키는 공격 |
| Snort | 오픈소스 네트워크 침입 탐지 도구 |
| Wazuh | 에이전트 기반 오픈소스 보안 관제 플랫폼 |
| GNS3 | 네트워크 토폴로지 시뮬레이터 |
| Cisco ASAv | Cisco의 가상 방화벽 어플라이언스 |
