## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 명칭 | DevSecOps 도입 프로젝트 |
| 목적 | 개발·운영·보안을 통합한다. 개발 속도와 보안성을 함께 강화한다. 취약점 탐지·대응을 자동화해 운영 비용을 줄인다 |
| 배경 | 기존 DevOps 환경에 보안 프로세스가 부족했다. 반복되는 수동 보안 작업으로 추가 비용이 발생했다 |

## 2. 현재 상황과 문제점

| 구분 | 내용 |
|---|---|
| 현황 | 기존 CI/CD 파이프라인에 보안 검증 단계가 미흡하다. 취약점 스캐닝과 코드 검토를 수동으로 한다. 운영 단계에서 발견된 보안 문제로 출시가 지연된다 |
| 주요 문제 | 보안 팀과 개발 팀의 협업이 부족하다. 신속한 취약점 대응 체계가 없다 |

## 3. 목표

| 구분 | 내용 |
|---|---|
| 단기 | CI/CD 파이프라인에 자동화된 보안 도구를 통합한다. 코드·이미지 스캔 프로세스를 구축한다 |
| 장기 | DevSecOps 프로세스를 정착시키고 보안 의식을 강화한다. 보안 이슈 탐지부터 수정까지 걸리는 평균 시간(MTTR, Mean Time To Repair)을 줄인다 |

## 4. 주요 작업과 범위

| 영역 | 작업 |
|---|---|
| CI/CD 파이프라인 강화 | SAST와 DAST 도구 통합. 컨테이너 이미지 스캔과 레지스트리 보안 검증 |
| 인프라 보안 자동화 | IaC(Infrastructure as Code) 보안 도구 도입. 취약점 스캔 자동화와 실시간 경고 시스템 구축 |
| 정책·가이드라인 | 웹 보안 관련 개발·운영 가이드 수립. DevSecOps 프로세스 구축 가이드 문서 작성 |

## 5. 기대 효과

| 항목 | 내용 |
|---|---|
| 효율 증가 | 자동화된 보안 프로세스로 개발 속도를 유지한다 |
| 보안 강화 | 보안 문제를 조기에 발견·수정해 서비스 품질을 높인다 |
| 비용 절감 | 운영 단계의 보안 사고 비용을 줄인다 |

## 6. 주요 도구와 기술 스택

| 분류 | 도구 |
|---|---|
| SAST(정적 분석) | SonarQube |
| DAST(동적 분석) | OWASP ZAP, Burp Suite |
| CI/CD | Jenkins, Docker Hub, GitHub |

원본은 그 외 도구가 추가되면 문서에 즉시 반영하도록 적었다.

{% hint style="info" %}
NOTE: Docker Hub는 컨테이너 이미지 저장소(레지스트리)이며 CI/CD 서버가 아니다. 원본은 CI/CD 항목 아래에 함께 적었다. Burp Suite는 주로 수동 점검용 프록시 도구이고 자동 스캔은 유료판 기능이다. 미검증.
{% endhint %}

## 9. 약어·용어

| 용어 | 뜻 |
|---|---|
| SAST | Static Application Security Testing. 소스 코드를 실행하지 않고 분석하는 보안 테스트 |
| DAST | Dynamic Application Security Testing. 실행 중인 애플리케이션을 시험하는 보안 테스트 |
| IaC | Infrastructure as Code. 인프라를 코드로 선언해 관리하는 방식 |
| MTTR | Mean Time To Repair. 이슈 탐지부터 수정까지 걸리는 평균 시간 |
