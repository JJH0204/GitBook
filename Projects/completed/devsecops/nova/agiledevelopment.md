## 1. 목적

기획과 개발이 동시에 이루어지며 제한된 개발 시간을 효율적으로 쓰는 업무 프로세스를 애자일 개발(Agile Development) 또는 애자일 방법론(Agile Methodology)이라고 한다. 이 프로젝트는 부족한 작업 기간을 대응하기 위해 이 방식을 도입했다. 근거는 [데브섹옵스 도입 계획](devsecopsplan.md)의 리스크 관리 절이다.

## 2. 애자일 개발의 특징

| 특징 | 내용 |
|---|---|
| 동시다발적 진행 | 기획, 디자인, 개발, 테스트가 분리된 단계가 아니라 병렬로 이루어진다. 협업으로 빠른 피드백을 반영한다 |
| 짧은 개발 주기(Sprint) | 보통 1~4주 동안 할 수 있는 작업을 나눠 진행한다. 주기마다 결과물을 내 완성도를 높인다 |
| 피드백 중심 | 기획이 완벽히 정리되지 않아도 작업을 시작하고 피드백으로 수정·보완한다 |
| 우선순위 기반 | 중요도와 긴급도에 따라 작업 우선순위를 나눈다 |

## 3. 비슷한 업무 프로세스

| 이름 | 설명 |
|---|---|
| Lean Development(린 개발) | 최소 자원으로 최대 효율을 내는 방법론 |
| Scrum(스크럼) | 애자일 방법론의 대표적인 구현 방식. 팀 내 역할과 의사소통을 강조한다 |
| Kanban(칸반) | 시각적 업무 관리 도구로 작업 흐름을 효율화한다 |
| DevOps | 개발(Development)과 운영(Operations)을 통합해 프로세스를 효율화한다 |

{% hint style="info" %}
NOTE: DevOps는 애자일 방법론 자체가 아니라 개발과 운영의 협업 문화·실천이다. 위 표는 원본의 분류를 그대로 옮겼다.
{% endhint %}

## 4. 약어·용어

| 용어 | 뜻 |
|---|---|
| Sprint | 한 번에 처리할 작업량을 정해 진행하는 짧은 개발 주기 |
| 피드백 | 결과물에 대한 평가를 받아 다음 작업에 반영하는 것 |
