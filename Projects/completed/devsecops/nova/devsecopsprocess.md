# 데브섹옵스 프로세스 (DevSecOps)

## 작업 식별

| 항목 | 내용 |
|---|---|
| Task ID | PRJ-NOV-001-DO |
| 유형 | D&O (프로세스 개념) |
| 목적 | 코드 변경에서 서비스 노출까지 이어지는 CI/CD 파이프라인의 단계를 설명한다 |
| 확인 상태 | 미검증 (원본 메모를 정리한 것이며 파이프라인을 실행해 확인하지 않았다) |
| 개정 | R1 (2026-11-18) |

## 1. 구성 요소

| 구성 요소 | 역할 |
|---|---|
| GitHub | 소스 저장소. 변경이 생기면 웹훅(Webhook)으로 Jenkins에 알린다 |
| Jenkins | 파이프라인을 실행하는 CI/CD 서버 |
| SonarQube | 정적 분석(SAST). 버그, 취약점, 코드 스타일을 검사한다 |
| Docker, Docker Hub | 이미지를 빌드하고 저장하는 컨테이너 이미지 저장소(레지스트리) |
| Kubernetes | 컨테이너를 배포하고 실행하는 오케스트레이션 플랫폼 |

## 2. 동작 원리

개발자가 코드를 커밋·푸시하면 GitHub가 변경 사항을 Jenkins에 알리고, Jenkins가 아래 단계를 순서대로 실행한다.

| 단계 | 이름 | 하는 일 |
|---|---|---|
| 0 | 코드 변경 감지 | 개발자의 커밋·푸시를 GitHub 웹훅으로 Jenkins에 전달한다 |
| 1 | SonarQube 검사 | 코드 품질을 검사한다(버그 찾기, 취약점 검사, 코드 스타일 검사) |
| 2 | Docker 이미지 빌드 | 애플리케이션과 필요한 모든 것(코드, 실행 환경, 설정)을 하나의 패키지로 만든다. 만든 이미지는 주로 Docker Hub에 저장한다 |
| 3 | Kubernetes 매니페스트 업데이트 | 애플리케이션 실행 설계도를 갱신한다(노드 수, 자원량, 네트워크 구성 등 설정) |
| 4 | Kubernetes 배포 | 실제 애플리케이션을 실행한다(컨테이너 시작, 네트워크 연결, 부하 분산 설정 등) |
| 5 | 서비스 노출 | 외부에서 접근할 수 있게 한다(도메인 연결, 보안 설정, 트래픽 라우팅 등) |

{% hint style="info" %}
NOTE: 원본의 Jenkins 단계에 "관리자 역할"이라는 문구가 붙어 있다. 의미는 원본에 없다. 확인 필요.
{% endhint %}

{% hint style="info" %}
NOTE: 원본 파이프라인에는 동적 분석(DAST) 단계가 없다. 계획 문서([데브섹옵스 도입 계획](devsecopsplan.md))는 OWASP ZAP과 Burp Suite를 DAST 도구로 적었으나 파이프라인 어느 단계에 넣는지는 원본에 없다. 확인 필요.
{% endhint %}

## 3. 약어·용어

| 용어 | 뜻 |
|---|---|
| CI/CD | Continuous Integration / Continuous Delivery. 빌드·테스트·배포 자동화 |
| SAST | Static Application Security Testing. 실행하지 않고 소스 코드를 분석하는 보안 테스트 |
| DAST | Dynamic Application Security Testing. 실행 중인 애플리케이션을 공격자 관점으로 시험하는 보안 테스트 |
| 매니페스트 | 쿠버네티스 리소스를 선언한 YAML 파일 |
| 웹훅 | 이벤트 발생 시 지정한 주소로 HTTP 요청을 보내는 기능 |
