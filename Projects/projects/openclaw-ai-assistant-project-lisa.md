## 3. 동작 원리

모델 구성 전략은 다음과 같다.

1. 평소에는 클라우드 모델(Ollama Cloud)로 요청한다.
2. 클라우드 한도(HTTP 429)에 걸리면 로컬 모델로 전환한다(Fallback).
3. 로컬 모델은 8GB RAM에서 4B급까지만 실용 범위다.

설정 참고 사항이다.

| 증상 | 조치 | 상태 |
|---|---|---|
| `command not found: compdef` | `.zshrc`에 `autoload -Uz compinit && compinit`를 추가한다 | 원본 기록, 미검증 |
| iMessage 연동 실패: 메시지 DB(`chat.db`) 접근 권한 문제, 환경 변수·경로 불일치 | 새 기기에서 전체 디스크 접근 권한(Full Disk Access)을 다시 부여한다 | 미완료 |
| 세션·게이트웨이 재시작 시 기억 초기화 | mem0 플러그인으로 자체 DB를 구축한다 | 원본: 모델 사용량 제한 때문에 테스트를 끝내지 못함 |

## 4. 회고

### 4.1 성능 병목과 하드웨어 결론

- 8GB RAM의 한계: M1 통합 메모리 구조상 4B 이상 모델은 스왑이 발생해 반응 속도가 크게 느려졌다.
- LLM 지능의 임계점: 비서로서 지능적인 반응을 얻으려면 로컬 70B 이상 모델 또는 안정적인 클라우드 API(1티어 이상)가 필요하다고 판단했다.
- 최종 결론: 64GB RAM 이상 M-Max 칩셋 기기로 바꿀 때까지 현재 워크플로우와 로직을 보존한다.

### 4.2 외부 API 사용 경험

- Linux 서버에서 Gemini API를 호출했을 때 높은 지능을 확인했다(원본 표현: "자비스급 경험").
- 1티어 요금제의 사용량 한도가 2~3일 안에 소진됐다. 이 경험으로 고티어 요금제 또는 로컬 대용량 모델 전환이 필요하다고 판단했다.

### 4.3 다음에 적용할 것

- 로컬에서 양자화 모델을 돌릴 수 있는 고성능 하드웨어(M4, RAM 64GB 이상)를 먼저 준비한다. 수익이 생기면 구매한다.
- 클라우드 모델(Ollama Cloud, Gemini API 등)을 쓸 때는 Fallback 모델을 반드시 추가해 응답이 끊기지 않게 한다. 외출 중 테스트에서 입력해도 응답이 없었던 경험에서 나온 결론이다.
- 외부 호출 채널은 가능하면 iMessage를 쓴다(앞으로도 Mac을 쓴다는 전제).
- 텔레그램은 기능이 제한적이었고, 텔레그램·왓츠앱은 별도 메신저 서버를 거치며 봇 설정 실수 시 중요한 자료가 유출될 수 있어 선택하지 않았다.

{% hint style="warning" %}
CAUTION: 외부 메신저 봇에 비서를 연결할 때는 봇이 접근하는 데이터 범위를 먼저 정한다. 원본이 지적한 유출 위험은 설정 실수에서 발생한다.
{% endhint %}

## 6. 약어·용어

| 용어 | 뜻 |
|---|---|
| LLM | Large Language Model, 대규모 언어 모델 |
| Fallback | 기본 모델이 실패하거나 한도에 걸렸을 때 대신 쓰는 모델 |
| HTTP 429 | 요청 한도 초과 응답 |
| 양자화 | 모델 가중치의 정밀도를 낮춰 메모리 사용량을 줄이는 방법 |
| mem0 | OpenClaw 플러그인으로 쓴 기억 저장 DB |
