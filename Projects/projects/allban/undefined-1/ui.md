# 대시보드 실시간 로깅 및 UI 가시성 개선

**1. '보이지 않는 에러'와의 싸움**

* 문제: 파이썬 스니퍼가 백그라운드(윈도우 서비스 또는 자식 프로세스)에서 돌다 보니, 패킷을 못 잡는 것인지, 코드가 죽은 것인지, 권한 문제인지 대시보드만 봐서는 알 수 없었음.
* 해결: 터미널, 텍스트 파일, 실시간 UI 로그를 유기적으로 연결하여 어디서든 에러의 흔적을 찾을 수 있게 설계함.

***

**2. 3중 로깅 레이어 구축 상세**

① 1단계: 실시간 터미널 및 표준 출력 (Standard I/O)

* 방식: 파이썬 실행 시 `-u` (Unbuffered) 옵션을 주어 즉시 데이터를 방출하고, Dart에서 이를 실시간 리스닝함.
* 특이사항: `LineSplitter`를 도입해 바이너리 데이터가 섞여 들어와도 로그 문장이 깨지지 않게 함.
* 가치: 개발 단계에서 즉각적인 피드백을 받는 '가장 빠른' 로깅.

② 2단계: 영구 저장을 위한 로컬 텍스트 파일 (File Logging)

* 방식: 파이썬 내부와 Dart 서버 양쪽에서 `sniffer.log`, `server.log`를 생성하여 모든 이벤트를 시간 순으로 기록함.
* 구현:
  * Python: `logging` 모듈을 사용해 `FileHandler` 구성.
  * Dart: `logFile.writeAsStringSync(..., mode: FileMode.append)` 사용.
* 가치: 대시보드를 끄거나 서버가 크래시(Crash) 났을 때, 사후 분석(Post-mortem)을 가능하게 하는 '가장 확실한' 기록.

③ 3단계: 사용자 중심의 대시보드 UI 로깅 (Dashboard Visibility)

* 방식: 서버 관리자 화면에 로그 창을 배치하고, 중요도(\[INFO], \[DEBUG], \[ERROR])에 따라 색상을 구분하여 표시.
* 구현: 웹소켓 또는 내부 스트림을 통해 UI 위젯에 로그 데이터 전달.
* 가치: 현장에서 관리자가 시스템의 정상 작동 여부를 '한눈에' 확인하게 하는 UX의 핵심.

***

**3. 로깅 개선의 결정적 순간 (Troubleshooting)**

* 사례 1: 스니퍼 무반응 현상
  * 터미널 로그에는 "Sniffer Started"만 찍혔으나, 텍스트 파일 로그를 확인한 결과 `TsharkNotFound` 에러가 수백 번 찍혀 있는 것을 발견. 이를 통해 시스템 환경 변수(Path) 문제임을 확신함.
* 사례 2: CPU 100% 점유 현상
  * 서버 종료 시 로그 파일에 "Process Exit Code: null"이 찍히는 것을 보고, 자식 프로세스가 정상 종료되지 않았음을 인지. 이를 계기로 `taskkill /T` 명령을 도입함.

***

**4. 향후 활용을 위한 시사점**

> 로깅은 단순히 `print`를 찍는 것이 아니라, <mark style="color:$success;">'나중에 내가 이 코드를 모를 때 나에게 보내는 구조 신호'</mark>

1. 시간(Timestamp): 모든 로그에는 반드시 밀리초 단위까지 시간을 기록할 것.
2. 문맥(Context): 단순 에러 메시지뿐 아니라, 에러 발생 당시의 변수 값(예: `adapterGuid`)을 함께 남길 것.
3. 구분(Leveling): 불필요한 정보는 `DEBUG`로, 시스템 장애는 `ERROR`로 확실히 구분하여 로그 오염을 방지할 것.
