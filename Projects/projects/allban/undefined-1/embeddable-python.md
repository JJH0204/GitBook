# 임베디드 파이썬(Embeddable Python) 도입 및 런타임 최적화

**1. 배경 및 문제 의식: 가상 환경(venv)의 한계**

* 초기 구성: `python -m venv`를 통해 가상화된 환경에서 의존성(`pyshark`, `requests`)을 관리함.
* 직면한 문제:
  * 배포 오버헤드: 설치 대상 PC에 파이썬이 반드시 설치되어 있어야 하며, 버전 불일치나 환경 변수(Path) 충돌 리스크가 상존함.
  * 사용자 부담: "프로그램 실행을 위해 파이썬을 먼저 설치해 주세요"라는 요구사항은 주방 현장의 실제 사용성을 저해하는 치명적인 요소로 작용함.
  * 권한 이슈: 윈도우 실행 정책(Execution Policy)으로 인해 `activate.ps1` 스크립트 실행이 차단되는 등 초기 런타임 구성이 불안정함.

**2. 해결책: 임베디드 파이썬(Embeddable Python) 도입**

배포의 불확실성을 완전히 제거하기 위해, 파이썬을 시스템에 설치하는 대신 프로그램 폴더 내에 전용 파이썬 엔진을 내장하는 방식을 채택함.

가. 임베디드 파이썬의 핵심 이점

* Zero-Dependency: 사용자 PC의 파이썬 설치 여부와 관계없이 즉시 실행 가능.
* 버전 격리(Isolation): 개발 시 검증된 특정 버전(3.11 등)의 파이썬 엔진을 그대로 배포하여 "내 컴퓨터에선 되는데 사용자 PC에선 안 되는" 현상 방지.
* 포터블 구조: 단순 폴더 복사만으로 실행 준비가 완료되어 Inno Setup 패키징 및 배포 프로세스가 획기적으로 단순화됨.

**3. 기술적 최적화 및 트러블슈팅 (핵심 구현)**

임베디드 파이썬은 일반 설치판과 달리 보안을 위해 외부 라이브러리 참조가 차단된 '최소 환경'입니다. 이를 정상화하기 위해 다음의 최적화 작업을 수행함.

① `._pth` 설정을 통한 외부 라이브러리(site-packages) 활성화

* 문제: 임베디드 엔진은 기본적으로 현재 폴더 외의 라이브러리를 무시함.
* 해결: `python311._pth` 파일을 수정하여 `#import site` 주석을 제거. 이를 통해 `Lib/site-packages`에 설치된 `pyshark` 등의 의존성을 엔진이 로드할 수 있도록 경로를 개방함.

② 런타임 절대 경로 동적 바인딩 (Dart-Python 연동)

* 문제: 배포 후 설치 경로가 사용자마다 달라져 상대 경로 참조가 깨지는 문제 발생.
* 해결: Dart 서버 코드에서 `Platform.resolvedExecutable`을 사용하여 실행 파일의 실제 위치를 찾고, 그 하위의 `python_runtime/python.exe`를 절대 경로로 호출하도록 리팩터링함.

③ 표준 입출력 버퍼링 문제 해결

* 문제: 파이썬 로그가 Dart 대시보드에 실시간으로 전달되지 않고 프로세스 종료 시 한꺼번에 찍히거나 멈춰 있는 현상.
* 해결: 파이썬 실행 옵션에 `-u` (Unbuffered) 플래그를 추가하여, 주문 탐지 패킷 로그가 발생하는 즉시 서버 대시보드에 실시간 출력되도록 개선함.

**4. 최종 성과 및 배포 시나리오**

* 배포 무결성: 사용자는 `Allben_Setup.exe` 하나만 실행하면 파이썬 설치 없이도 실시간 MySQL 패킷 스니핑 기능이 즉시 가동됨.
* 유지보수 용이성: 모든 의존성 패키지가 한 폴더 내에 있어 업데이트 시 해당 폴더만 교체하면 되는 깔끔한 구조 확보.
