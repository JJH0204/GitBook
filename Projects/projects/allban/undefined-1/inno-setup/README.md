# 배포 자동화 및 인스톨러(Inno Setup) 구축 문제

**1. 배경: 엔터프라이즈급 배포 환경 구축**

* 목적: 주방 현장의 다양한 PC 환경에서 사용자의 개입 없이 서버와 패킷 스니퍼가 즉시 가동되도록 패키징함.
* 도구: Inno Setup(인스톨러 제작), NSSM(윈도우 서비스 등록).
* 핵심 요구사항:
  * 윈도우 시작 시 자동 실행 (백그라운드 서비스).
  * 필수 런타임(Npcap, Tailscale, VC++ Redist) 자동 체크 및 안내.
  * 임베디드 파이썬 및 에셋의 무결성 유지.

**2. NSSM 도입 시 직면했던 주요 문제 (Critical Issues)**

NSSM은 일반 실행 파일을 서비스로 만들어주는 훌륭한 도구이지만, 이번 프로젝트의 특수한 환경(임베디드 파이썬 호출 등)에서 다음과 같은 문제가 발생했습니다.

가. AppDirectory 및 상대 경로 인식 오류

* 문제: NSSM으로 서비스를 등록했을 때, 서버 프로그램(`AllbenServer.exe`)이 자신이 위치한 폴더를 인식하지 못해 하위의 `python_assets`를 찾지 못하는 현상 발생.
* 원인: 서비스로 실행될 경우 작업 디렉토리가 `C:\Windows\System32`로 고정되는 윈도우 서비스의 특성 때문임.
* 해결: Inno Setup의 `[Run]` 섹션에서 NSSM의 `AppDirectory` 파라미터를 명시적으로 설정함.
  * `nssm set AllbenServer AppDirectory "{app}"`

나. 서비스 중복 등록 및 삭제 시 잔류 문제

* 문제: 업데이트 설치 시 기존 서비스가 제대로 중지되지 않거나, 삭제 후에도 서비스 목록에 남아 재설치를 방해함.
* 해결: `[UninstallRun]` 섹션에서 `remove` 명령을 사용하기 전 반드시 `stop` 명령을 선행하고, `confirm` 플래그를 통해 사용자 개입 없이 완벽히 제거되도록 로직을 강화함.

**3. Inno Setup 스크립트 고도화 상세**

① 필수 외부 도구(Npcap, Tailscale) 검증 로직 단순히 파일을 복사하는 것에 그치지 않고, 시스템 레지스트리를 전수 조사하여 필수 인프라가 갖춰졌는지 확인하는 기능을 구현함.

* 구현: `InitializeSetup` 이벤트를 활용해 `SOFTWARE\Npcap` 등 레지스트리 키 존재 여부 확인.
* 성과: 미설치 시 공식 다운로드 페이지로 연결하여 설치 실패율을 획기적으로 낮춤.

② 임베디드 파이썬 에셋의 동적 배치 빌드된 Flutter 결과물과 파이썬 런타임, 스니핑 스크립트를 계층 구조에 맞춰 배치함.

* 구조: `{app}\AllbenServer.exe`, `{app}\python_runtime\`, `{app}\python_assets\`.

**4. 시행착오 및 디버깅 기록**

* 이슈: 서비스 실행 시 파이썬 로그가 남지 않음.
  * 원인: NSSM 서비스는 콘솔 창이 없으므로 표준 출력이 공중에 뜸.
  * 해결: NSSM의 `AppStdout` 및 `AppStderr` 파라미터를 활용하여 로그 파일을 특정 경로에 강제로 남기도록 설정함.
* 이슈: 관리자 권한 부족으로 인한 서비스 등록 실패.
  * 해결: Inno Setup 설정에 `PrivilegesRequired=admin`을 명시하여 인스톨러 실행 시점부터 권한을 확보함.

***

**5. 향후 활용을 위한 시사점**

이 기록은 단순한 설치 파일 제작을 넘어, \*\*"배포 후 운영 단계"\*\*의 안정성을 확보하기 위한 가이드입니다.

1. 서비스 안정화: NSSM은 강력하지만 경로(`AppDirectory`) 설정이 누락되면 모든 상대 경로 로직이 깨진다는 점을 명심할 것.
2. 의존성 가시성: 사용자가 무엇이 부족해서 실행이 안 되는지 모르는 상황을 방지하기 위해 반드시 사전 체크 로직을 포함할 것.
3. 클린 언인스톨: 서비스 등록만큼 중요한 것은 서비스의 완벽한 제거임.
