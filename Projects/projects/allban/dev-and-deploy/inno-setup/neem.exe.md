# NSSM 서비스 관리 전환 (NSSM)

## 작업 식별

| 항목 | 내용 |
|---|---|
| Task ID | PRJ-ALB-013-DO |
| 유형 | D&O (결정 기록) |
| 목적 | 서비스 등록 도구 NSSM을 배포에서 제외하고 Dart 서버가 스니퍼를 직접 관리하게 바꾼 이유를 설명한다 |
| 확인 상태 | 미검증 (원본 기록을 정리한 것이다. NSSM 업데이트 이력은 이 환경에서 확인하지 않았다) |
| 개정 | R1 (2026-11-18) |

## 1. 배경

- 초기 목적: 주방 관리 서버를 Windows 서비스로 등록해 백그라운드에서 상시 구동하려고 NSSM 도입을 검토했다.
- 전환점: NSSM 오픈소스 프로젝트의 업데이트가 수년간 중단된 것을 확인했다. 장기적인 보안 취약점 노출과 최신 Windows(11 등) 호환성 결여 가능성이 배포 안정성에 위협이라고 판단했다.

## 2. 결정 이유

| 번호 | 이유 | 내용 |
|---|---|---|
| 1 | 유지보수 중단 | NSSM의 공식 릴리스가 2017년 이후 정체돼 있다. 실시간 패킷 스니핑과 데이터 서버가 함께 도는 복잡한 구조에서, 관리되지 않는 외부 도구를 서비스 제어의 핵심에 두는 것은 위험하다고 판단했다 |
| 2 | 서비스 제어의 불투명성 | NSSM으로 등록한 서비스는 자식 프로세스(Python)가 예외로 죽을 때 부모 서버 프로세스와 상태가 완전히 동기화되지 않는다. Dart/Flutter의 프로세스 제어 능력을 믿고 외부 도구 의존을 줄이기로 했다 |

## 3. 변경된 배포 방식

| 구분 | 이전 | 이후 |
|---|---|---|
| 서비스 등록 | NSSM으로 서버를 Windows 서비스로 등록 | 서비스 등록을 하지 않는다. 프로그램 실행 시 서버가 직접 파이썬 스니퍼를 실행하고 관리한다 |
| 설치 패키지 | `nssm.exe` 포함 | `nssm.exe`를 포함하지 않아 용량이 줄고, 외부 도구 실행으로 생길 수 있는 백신 오탐지 위험이 없다 |
| 스니퍼 감시 | 서비스 수준 | 서버 UI(대시보드)에서 스니퍼 생존 여부를 더 정밀하게 감시하고 제어한다 |
| 동작 방식 | 외부 도구 의존 | Windows 표준 API에 가까운 방식으로 동작한다 |

프로세스 생성과 종료 방식은 [프로세스 통합 및 생명주기 관리 (Dart-Python)](../dart-python.md)(PRJ-ALB-011-DO), 변경 전 설치 설정은 [인스톨러 구축 및 배포 자동화 (Inno Setup)](README.md)(PRJ-ALB-012-REF)에 있다.

## 4. 서비스 등록 도구를 다시 검토할 때 점검 항목

| 번호 | 점검 항목 | 기준 |
|---|---|---|
| 1 | 오픈소스 생명주기 | 마지막 업데이트 날짜가 운영체제 대규모 업데이트(Windows 10 → 11) 주기와 맞는가 |
| 2 | 보안성 | 관리되지 않는 바이너리가 관리자 권한으로 실행되는 위험을 감당할 수 있는가 |
| 3 | 대체 기술 | 더 최신이고 활발히 관리되는 대안(원본: `WinSW`, `Windows Service Wrapper`)이 있는가 |

{% hint style="info" %}
NOTE: 원본이 `WinSW`와 `Windows Service Wrapper`를 별개 대안처럼 적었다. 같은 도구의 다른 이름일 가능성이 있다. 확인이 필요하다. NSSM의 마지막 릴리스 연도(2017년)도 이 환경에서 확인하지 않았다.
{% endhint %}

## 5. 약어·용어

| 용어 | 뜻 |
|---|---|
| NSSM | Non-Sucking Service Manager, 실행 파일을 Windows 서비스로 등록하는 도구 |
| Windows 서비스 | 로그인 없이 백그라운드에서 상시 실행되는 프로그램 |
| 오탐지 | 정상 파일을 악성으로 잘못 판단하는 백신의 오류 |
| 오케스트레이션 | 여러 프로세스의 실행과 종료를 한 곳에서 조율하는 일 |
