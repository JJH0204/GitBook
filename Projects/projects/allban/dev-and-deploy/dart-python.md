# 프로세스 통합 및 생명주기 관리 (Dart-Python)

## 작업 식별

| 항목 | 내용 |
|---|---|
| Task ID | PRJ-ALB-011-DO |
| 유형 | D&O (설계 회고, 문제 해결 포함) |
| 목적 | Dart 서버가 파이썬 스니퍼와 그 하위 프로세스(Tshark)를 생성하고 종료하는 방식을 설명한다 |
| 적용 환경 | Windows, Dart(Flutter), Python, Tshark |
| 확인 상태 | 미검증 (원본 기록을 정리한 것이며 이 환경에서 실행하지 않았다) |
| 개정 | R1 (2026-11-18) |

## 1. 배경

UI와 메인 비즈니스 로직을 맡는 Dart(Flutter) 서버가, 백그라운드에서 패킷을 분석하는 파이썬 스니퍼를 자식 프로세스로 만들어 관리한다. 핵심 과제는 부모(서버)가 종료될 때 자식(파이썬)과 그 자식(Tshark)까지 모두 없애 시스템 자원 누수를 막는 것이다.

## 2. 구성 요소

| 프로세스 | 역할 | 부모 |
|---|---|---|
| Dart(Flutter) 서버 | UI와 메인 로직 | 없음 |
| 파이썬 스니퍼 | 패킷 분석 | Dart 서버 |
| `Tshark.exe` | 패킷 캡처 | 파이썬 스니퍼 |

## 3. 기술적 난제와 해결

| 번호 | 난제 | 현상·원인 | 해결 |
|---|---|---|---|
| 1 | 프로세스 트리 고립 | Dart의 `process.kill()`은 직계 자식인 파이썬만 종료한다. 파이썬이 실행한 `Tshark.exe`가 좀비 프로세스로 남아 CPU 점유율이 100%까지 오른다 | Windows `taskkill`로 트리 전체를 종료한다: `Process.run('taskkill', ['/PID', pid.toString(), '/T', '/F'])`. `/T`는 자식 프로세스까지, `/F`는 응답 없는 프로세스까지 강제 종료한다 |
| 2 | 표준 입출력 스트림 병목 | 파이썬 `print()` 로그가 Dart 대시보드에 즉시 안 오고 프로세스가 죽을 때 쏟아진다. 원인은 파이썬 출력 버퍼링과 Dart 스트림 리스너의 동기화 문제다 | 파이썬 실행 인자에 `-u`를 추가해 버퍼링을 끈다. Dart에서 `LineSplitter`와 `utf8.decoder`를 결합해 조각난 데이터를 문장 단위 로그로 복원한다 |
| 3 | 실행 경로 불안정 | `runInShell: true`에서는 Windows 쉘(CMD)의 간섭으로 임베디드 파이썬의 실행 경로가 꼬인다 | 쉘을 거치지 않고 실행 파일의 절대 경로를 직접 호출한다(`runInShell: false`). 경로 신뢰성과 실행 속도가 좋아진다 |

## 4. 동작 원리

1. Dart 서버가 임베디드 파이썬을 `runInShell: false`, `-u` 옵션으로 실행한다.
2. 파이썬 출력은 `utf8.decoder`와 `LineSplitter`를 거쳐 줄 단위로 로그에 들어간다.
3. 서버가 종료될 때 `taskkill /T /F`로 파이썬과 `Tshark.exe`를 함께 종료한다.

{% hint style="warning" %}
CAUTION: `/F`는 프로세스를 강제 종료한다. 종료 전 정리 작업(파일 쓰기, 연결 해제)이 실행되지 않는다. 로그 파일 마무리가 필요하면 먼저 정상 종료 신호를 보내는 단계를 둔다. 이 제안은 원본에 없다.
{% endhint %}

## 5. 활용 시점

원본은 이 작업이 현재 프로젝트의 메인 로직에서는 제외됐다고 적었다. 다음 상황에서 참고한다.

1. FFmpeg, ImageMagick 같은 외부 실행 파일(.exe)을 서버에서 제어할 때.
2. 자식 프로세스가 또 다른 하위 프로세스를 만드는 복합 시스템을 만들 때.
3. 서버 종료 후에도 백그라운드 작업이 CPU를 점유해 시스템이 느려지는 현상을 막아야 할 때.

{% hint style="info" %}
NOTE: [NSSM 서비스 관리 전환 (NSSM)](inno-setup/neem.exe.md)(PRJ-ALB-013-DO)은 "서버가 직접 파이썬 스니퍼를 실행하고 관리하는 방식을 채택했다"고 적었다. 이 문서의 "메인 로직에서 제외"와 어긋난다. 최종 채택 여부는 확인이 필요하다.
{% endhint %}
