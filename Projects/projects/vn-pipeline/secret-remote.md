## 동작 원리

### A. 시크릿 모드

#### 켜는 동안

| 층 | 동작 | 위치 |
|---|---|---|
| 상태 | 서버 메모리에만 있다. 재시작하면 꺼진 채로 시작한다 | `Secret.enabled` |
| 작업 | `job["secret"] = True`로 기록한다 | `JobManager.submit` |
| 파일 | 저장 접두사를 `_secret/<원래 경로>`로 바꿔 `output/_secret/` 아래에 쓴다 | `secret_prefix` |
| 화면 | 갤러리·캐릭터 탭·작업 탭에 평소처럼 보이고 "시크릿" 표시가 붙는다 | `classify`가 `_secret/` 접두사를 떼고 같은 규칙으로 판정 |
| 로그 | 시크릿 작업의 프롬프트·오류를 로그에 남기지 않는다 | `JobManager._finish` |

#### 끄거나 종료할 때: 삭제 순서

```
 disable() / cleanup()
   1. _stop_jobs      진행·대기 중 시크릿 작업을 취소하고 최대 25초 기다린다
   2. _forget_comfy_history   엔진의 실행 기록(프롬프트·파일 이름)을 /history 삭제 요청으로 지운다
   3. purge_secret_records    작업 DB 기록과 메모리(미리보기·최근 작업)를 지운다
   4. purge_files             output/_secret/ 과 output/.trash/_secret/ 를 통째로 지운다
                              썸네일 캐시와 메타데이터 캐시도 함께 지운다
```

* **휴지통을 거치지 않는다.** 갤러리에서 시크릿 그림을 지워도 `.trash`로 옮기지 않고 바로 지운다.
* **DB에 흔적을 남기지 않는다.** `PRAGMA secure_delete=ON`으로 지운 내용을 덮어쓰고, `wal_checkpoint(TRUNCATE)`로 WAL 파일에서도 없앤 뒤 설정을 되돌린다.
* **시작 시 정리**: 비정상 종료(강제 종료, 전원 끊김)로 지우지 못했다면 다음 시작 때 `cleanup("지난 실행에서 남은 기록")`이 지운다. 남은 것이 있는지는 `leftovers`가 폴더와 DB 양쪽을 본다. 모르면 지우는 쪽으로 판단한다.
* **늦게 끝난 작업**: 취소를 기다리는 25초가 지나도 끝나지 않은 작업은 추적을 멈추고, 이후 끝나면 `notify_orphan`이 다시 정리를 건다.
* **종료 때**: `shutdown`이 DB를 닫기 전에 20초 제한으로 정리하고, 엔진이 끝난 뒤 마지막으로 파일을 한 번 더 지운다(엔진이 종료 직전에 쓴 그림 대비).

지우지 않는 것은 사람이 직접 저장한 설정(캐릭터, 프리셋, LoRA 메모, 저장한 포즈, 받은 모델)이다.

{% hint style="warning" %}
CAUTION: 시크릿 모드를 끄면 되돌릴 수 없다. 남길 그림은 끄기 전에 화면의 다운로드로 받아 둔다.
{% endhint %}

### B. 원격 접속: 층별 방어

전체 그림은 다음과 같다. 서버는 어떤 경우에도 로컬 루프백 주소에만 바인드하고, 바깥으로 나가는 문은 사설망 프록시(Tailscale Serve)가 맡는다.

```
 원격 기기 --(사설망, 암호화)--> 사설망 프록시 --(같은 PC 안)--> Studio (로컬 바인드)
                                      |                              |
                                      | 신원·원래 호스트 표지를 붙임   | guard: identify -> local_only -> check_origin
```

기능이 열리려면 아래가 **모두** 참이어야 한다. 하나라도 거짓이면 원격 요청은 403이다.

| 층 | 조건 | 거절 코드(`code`) |
|---|---|---|
| 1 | 설정 `remote_enabled`가 JSON `true`다 (이상한 값은 "꺼짐"으로 본다, fail closed) | `remote_disabled` |
| 2 | 서버가 앱 창(`--app`)으로 연 세션이다 | `remote_no_app` |
| 3 | 요청의 Host가 저장된 원격 호스트 이름 중 하나다 | `remote_host` |
| 4 | 사설망이 붙인 사용자 신원이 있고, 공개 인터넷 경로(Funnel) 요청이 아니다 | `remote_identity` |
| 5 | 그 사용자가 허용 목록에 있다 (정확한 로그인만, 대소문자 무시) | `remote_login` |
| 6 | 로컬 전용 동작이 아니다 | `local_only` |
| 7 | 변경 요청의 Origin이 같은 쪽이다 (Origin이 있을 때) | `origin` |

#### 설계 원칙

* **로컬 바인드 + 외부는 프록시.** 서버 포트를 직접 열지 않는다. 프록시를 붙이지 않으면 원격 접속은 존재하지 않는다.
* **원격 표지가 하나라도 있으면 원격 취급.** 프록시가 넣는 헤더(신원, 전달 주소, 전달 호스트)가 하나라도 보이면 Host가 로컬처럼 보여도 로컬로 취급하지 않는다. 로컬로 인정되는 조건은 "표지가 없고 Host가 로컬 주소·포트와 정확히 같음"뿐이다.
* **모르는 Host는 거절한다.** 로컬도 저장된 원격 호스트도 아니면 403이다(DNS 리바인딩 방지).
* **허용 목록은 정확 일치.** 와일드카드(`*`)를 허용하지 않고, 이메일 형태의 문자열만 받으며, 1~50개로 제한한다. 처음 켤 때 목록이 비어 있으면 사설망 사용자로 채운다.
* **fail closed.** 설정값 파싱이 이상하면 "꺼짐·빈 목록"으로 본다. 설정 파일이 바뀌면(inode·수정 시각·크기) 다시 읽는다.
* **원격 접속 설정은 원격에서 바꿀 수 없다.** 허용 목록·켜기·끄기·서버 종료·폴더 열기·Finder에서 보기는 로컬 전용이다. 비교는 요청 경로 문자열이 아니라 aiohttp가 고른 라우트로 한다.
* **일반 설정 저장 경로에서 원격 키를 막는다.** `PUT /api/settings`는 `remote_enabled`, `remote_allowed_logins`, `remote_hosts`를 바꾸지 않는다. 원격에서 스스로 허용 범위를 넓히지 못하게 하려는 설계다.
* **끄기는 "먼저 막고, 그다음 정리".** `disable`은 설정을 먼저 `false`로 저장한 뒤 프록시 설정을 걷는다. 프록시 설정 걷기가 실패해도 이미 요청이 거절된다.
* **남의 설정을 덮어쓰지 않는다.** 443 포트에 다른 대상이 이미 연결돼 있으면 켜기를 거절하고, 끌 때도 Studio가 만든 항목일 때만 걷어 낸다.

#### 앱 세션이라는 느슨한 경계

| 실행 방식 | 서버 인자 | 원격 요청 | 시작할 때 프록시 설정 |
|---|---|---|---|
| 앱 창으로 연 서버 (`studio.sh --open`) | `--app` | 위 7개 층을 통과하면 허용 | 원격이 켜져 있으면 붙임 |
| 터미널·자동 실행 | 없음 | 모두 403 (`remote_no_app`) | 남아 있는 Studio 설정을 걷음 |

앱을 닫아 서버가 끝나면 프록시 설정도 걷는다(`session_end`). 그래서 외부로 열리는 포트는 앱을 열어 둔 동안에만 존재한다. 원격이 켜져 있으면 `studio.sh`가 서버가 사는 동안 유휴 잠자기를 막는 보조 프로세스를 함께 띄운다.

#### 켜기 전 점검 (`Remote.enable`)

켜기는 아래를 순서대로 확인하고, 하나라도 맞지 않으면 409로 이유와 할 일을 돌려준다.

1. 앱 세션인가.
2. 사설망 클라이언트가 설치돼 있고 연결돼 있는가.
3. 이 기기의 사설망 이름(MagicDNS)이 있는가.
4. 사설망의 HTTPS 인증서가 켜져 있는가.
5. 프록시 설정을 읽을 수 있고, 443 포트에 다른 대상이 연결돼 있지 않은가.
6. 허용할 사용자가 한 명 이상 있는가.

통과하면 프록시 설정을 붙이고(20초 제한), 설정에 호스트 이름과 허용 목록을 저장한다.

#### 위협별 대응 요약

| 위협 | 대응 |
|---|---|
| 다른 웹사이트의 스크립트가 로컬 서버에 변경 요청을 보냄 | 변경 메서드에 Origin 검사 (로컬과 원격 각각 같은 출처만) |
| 모르는 호스트 이름으로 접근 (DNS 리바인딩) | 저장된 호스트 목록과 비교, 목록 밖이면 거절 |
| 같은 사설망의 허용되지 않은 계정 | 신원 헤더를 허용 목록과 비교 |
| 공개 인터넷으로의 노출 | Funnel 경로 요청 거절, 문서에서 Funnel 사용 금지 |
| 원격 사용자가 허용 범위를 스스로 넓힘 | 원격 설정 API 로컬 전용, 일반 설정 API가 원격 키를 무시 |
| 원격에서 서버를 꺼 다시 켤 방법이 없어짐 | 종료 API 로컬 전용 |
| 설정 파일 손상·오타 | fail closed(꺼짐·빈 목록) |
| 접속 기록 부재 | 거절과 변경 요청을 로그에 남김 (원격이면 로그인·전달 주소 표시) |

## 핵심 코드 해설

{% code title="studio/remote.py (identify, 발췌)" %}
```python
raw = (request.host or "").strip().lower()
name, _ = split_host(raw)
headers = request.headers
marked = any(h in headers for h in REMOTE_MARKERS)
if not marked and raw in (f"127.0.0.1:{port}", f"localhost:{port}"):
    return dict(LOCAL_CLIENT)  # 로컬: 기존 규칙 그대로
```
{% endcode %}

* 로컬 판정은 "표지 없음 + Host 정확 일치" 둘 다여야 한다. 하나만 맞아서는 로컬이 아니다.
* 이 함수는 로컬이 아니면 원격 규칙(설정 켜짐 → 앱 세션 → 호스트 → 신원 → 허용 목록) 순서로 내려가며 처음 어긋나는 곳에서 `Denied`를 던진다.

{% code title="studio/remote.py (local_only_reason)" %}
```python
resource = getattr(request.match_info.route, "resource", None)
path = getattr(resource, "canonical", None) or request.path
return LOCAL_ONLY.get((request.method, path))
```
{% endcode %}

* 로컬 전용 표는 `(메서드, 라우트 경로)` 쌍으로 만든다. 여기서 비교하는 것은 요청이 들어온 문자열이 아니라 라우터가 실제로 고른 라우트다.

{% code title="studio/secret.py (Secret._purge)" %}
```python
pids = await self._stop_jobs(wait)
await self._forget_comfy_history(pids)
n_jobs = self.jobs.purge_secret_records()
n_files, n_bytes = await asyncio.to_thread(self.purge_files)
```
{% endcode %}

* 순서가 중요하다. 작업을 먼저 멈춰야 새 파일이 생기지 않고, 엔진 기록을 지워야 프롬프트가 엔진 메모리에 남지 않는다.
* DB 호출은 `to_thread`로 보내지 않는다. SQLite 연결을 만든 스레드(이벤트 루프)에서만 쓰기 때문이다.

## 따라 만들기

시크릿 모드와 원격 접속을 각각 따로 만든다. 원격 접속은 접근 제어(5단계)를 먼저 끝낸 뒤에 외부에 연다.

1. 출력 접두사를 한 함수(`secret_prefix`)로 바꿔, 모든 저장 노드가 `_secret/` 아래에 쓰게 한다. → 결과: 시크릿 그림이 한 폴더에 모인다.
2. 작업 JSON에 `secret` 플래그를 넣는다. → 결과: DB에서 시크릿 작업만 골라낼 수 있다.
3. "작업 취소 → 엔진 기록 삭제 → DB 삭제 → 파일 삭제" 순서의 삭제 함수를 만든다. 삭제 후 DB 덮어쓰기와 WAL 정리를 넣는다. → 결과: 끄면 흔적이 남지 않는다.
4. 시작 시 정리와 종료 시 정리를 둘 다 건다. → 결과: 비정상 종료 뒤에도 다음 시작에 지워진다.
5. 서버는 로컬 루프백에만 바인드한다. → 결과: 바깥에서 직접 닿는 길이 없다.
6. 요청 판별 함수를 만든다. 설정 꺼짐, 모르는 Host, 신원 없음, 허용 목록 밖을 모두 거절한다. 설정 파싱 실패는 "꺼짐"으로 처리한다. → 결과: 설정이 깨져도 문이 열리지 않는다.
7. 변경 요청에 Origin 검사를 추가한다. → 결과: 다른 사이트의 스크립트가 변경 요청을 보낼 수 없다.
8. 서버 종료·폴더 열기·원격 설정 변경을 로컬 전용 표에 넣고 라우트 기준으로 비교한다. → 결과: 원격 사용자가 문 자체를 바꾸지 못한다.
9. 프록시를 붙이는 켜기 함수와 걷는 끄기 함수를 만든다. 끄기는 설정을 먼저 닫는다. → 결과: 끄기 도중 실패해도 요청이 거절된다.
10. 앱 세션에서만 프록시를 붙이고 서버 종료 때 걷는다. → 결과: 외부에 열리는 시간이 앱을 연 동안으로 한정된다.

## 알려진 한계·주의

* 원격 접속의 안전은 사설망 프록시가 신원 표지를 정직하게 붙인다는 전제 위에 있다. 서버를 프록시 없이 직접 외부에 바인드하면 이 전제가 깨진다. 레포의 설계는 그렇게 하지 않는다.
* 허용된 원격 사용자는 엔진 시작·중지, 생성, 삭제(휴지통), 다운로드, 설정 저장을 할 수 있다. 권한을 더 나누는 구조는 없다.
* 시크릿 모드는 "디스크에 안 쌓이게" 하는 기능이다. 화면 캡처, 브라우저 캐시, 다른 기기로 받은 파일은 지우지 못한다.
* 시크릿 모드는 서버 메모리 상태라 서버를 재시작하면 꺼진다. 켜 둔 채 재시작하면 다음 시작에서 잔여물만 정리한다.
* 확인 필요: `GET /api/settings`가 설정 파일 전체를 돌려주므로, 선택 입력인 다운로드 토큰 칸과 허용 목록이 원격 허용 사용자에게 보이는지 실행해 확인하지 않았다.
* 확인 필요: 원격 접속 로그에 허용되지 않은 요청의 로그인 이름과 전달 주소가 남는다. 로그 파일 보관 정책(`studio.log` 5MB 회전)이 개인 정보 관점에서 충분한지는 이 문서가 판단하지 않는다.
