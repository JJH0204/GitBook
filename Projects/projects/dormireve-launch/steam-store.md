# 스팀 상점 페이지

## 한 일

- 상점 페이지를 **임시 자산으로 먼저 신청해 승인**을 받고, 승인 뒤에 정식 스크린샷으로 교체하는 순서로 진행했다. 캡슐, 라이브러리 이미지, 아이콘은 정식 아트로 먼저 바꿨다.
- 자산 목록을 크기별로 표로 정리하고, 업로드 때 Steam이 확인하는 규칙(로고 비율, 로고 외 글자 금지, 히어로에는 로고 없음, 라이브러리 로고는 투명 배경)을 체크리스트로 만들었다.
- 설명 문구는 포지셔닝 순서(히로인과 서사 → 전투 → 시스템)대로 썼다.
- 콘텐츠 설문(폭력, 노출, 사행성 유사 요소, 생성형 AI 사용 범위)을 게임의 실제 내용 기준으로 답했다.
- 본편 상점 검토를 제출해 통과한 뒤 "출시 예정"으로 공개해 위시리스트를 받기 시작했다.

## 배운 점

- 임시 자산으로 먼저 승인을 받으면 검토 대기 시간 동안 정식 아트 제작이 병렬로 진행된다. 검토 기간은 보통 영업일 기준 며칠에서 그 이상이므로 일정에 여유를 둔다.
- 스크린샷은 에디터 화면으로 임시로 찍어 올릴 수 있지만, 정식본은 연출을 맞춰 다시 찍는다. 히로인이 크게 보이는 장면을 첫 장에 두고 UI 장면은 소수로 제한한다.
- 빌드에서 내부 에셋 이름이 화면에 노출되는 문제를 영상 검토 중에 발견했다. 빌드 검토 전에 숨겨야 한다.
- 지원 OS와 재배포 패키지 같은 빌드 정보를 빠뜨리면 출시 체크리스트가 완료되지 않는다.
- 가격은 출시 전에는 다시 제안할 수 있지만, 출시 후에는 변경과 할인에 제약이 있다는 점을 알아 둔다.
- Steamworks 웹 작업은 로그인한 브라우저에서 사람이 확인하며 진행하고, 빌드 업로드는 CI가 맡게 역할을 나눴다.
