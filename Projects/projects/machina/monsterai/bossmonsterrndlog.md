# 보스 몬스터 연구 개발 일지 (R&D)

## 작업 식별

| 항목 | 내용 |
|---|---|
| Task ID | PRJ-MAI-002-DO |
| 유형 | D&O (연구 개발 기록) |
| 목적 | 다중 개체(용 5마리 + 몸통) 보스의 행동 패턴을 행동 트리(BT)로 설계하며 남긴 메모를 정리한다 |
| 확인 상태 | 미검증 (작성자의 메모를 정리한 것이며 구현 결과를 확인하지 않았다) |
| 개정 | R1 (2026-11-18) |

{% hint style="info" %}
NOTE: 원본은 BT 다이어그램의 노드 이름이 순서 없이 남은 메모다. 노드의 부모·자식 관계(화살표)는 남아 있지 않아 이 문서는 노드를 묶음별 목록으로만 적는다.
{% endhint %}

## 1. 출발점

- 기존 소스 코드가 많이 꼬여 있다. 기능을 알 수 없고 없어도 될 객체가 많아 걷어내고 하나씩 수정해야 한다고 판단했다.
- 먼저 해야 할 일은 보스 몬스터의 행동 패턴을 만드는 것이다.
- 현재 체력을 확인해 상태 값(Death)을 바꾸는 것부터 시작한다.

## 2. 체력과 사망 판정 조사

| 번호 | 확인한 것 | 메모 |
|---|---|---|
| 1 | 몬스터의 체력을 어떻게 정의하는가 | 기존 코드에서 찾아본다 |
| 2 | 드래곤 체력 | 리스트로 관리하고, 임의 값으로 초기화하는 메서드가 있다 |
| 3 | 초기화 시점 | AI 컨트롤러가 BT를 초기화할 때 드래곤 체력도 함께 초기화한다 |
| 4 | 열린 질문 | 드래곤의 전체 체력은 몬스터의 체력인가. 보스는 언제 죽었다고 판단하는가 |
| 5 | 사망 판정 노드 | 특정 드래곤 타입을 선택해 그 드래곤의 사망 여부를 반환하는 노드 |
| 6 | 사망 처리 | 죽음 명령을 큐에 등록한다. 죽음 명령은 지정한 드래곤 타입의 모델 머티리얼을 죽음 상태로 바꾼다 |

## 3. 구조 결정

| 항목 | 결정 |
|---|---|
| BT 단위 | 용마다 BT를 하나씩 가진다 |
| Blackboard | 용마다 하나씩 두거나, 하나를 공유해도 된다고 보았다(미정) |
| 보스 구성 | 용 5마리를 보스의 하위 몬스터로 포함한다. 몸통이 따로 있다 |
| AI 컨트롤러 | 각 몬스터 객체가 자신의 컨트롤러를 가진다. 컨트롤러는 Global BT와 상태별 Sub BT로 구성한다 |

보스를 이루는 용 5마리의 별칭은 검둥이, 파랑이, 노랑이, 빨갱이, 초록이다.

## 4. BT 초안의 노드

### 4.1 몸통

| 구분 | 노드 |
|---|---|
| 시퀀스 | Death, Battle, Move, Idle |
| 조건 | CurrentHealth <= 0 → 상태를 Death로 설정 |
| 조건 | Player Is Ground == true |
| 조건 | 오른발에서 가까운지 검사(거리 값은 원본에서 `00`으로 비어 있다) |
| 조건 | Is Cooldown Time → 상태를 Battle로 설정 |
| 조건 | Player Is Alive → 상태를 Move로 설정 |

### 4.2 초록이, 노랑이

| 구분 | 노드 |
|---|---|
| 시퀀스 | Groggy, Battle, Idle |
| 조건 | CurrentHealth <= 0 → 상태를 Death로 설정 |
| 셀렉터 | 플레이어가 지면에 있는지, 왼발 반경 안에 있는지 검사 |
| 셀렉터 | 스킬 쿨타임 확인: 독 안개 스킬, 달려들기 스킬의 쿨타임 적용 여부 |
| 결과 | 조건이 맞으면 상태를 Battle로 설정 |

필요한 기능으로 스킬 캐스팅 시간을 적었다.

## 5. 열린 질문과 판단

| 번호 | 메모 |
|---|---|
| 1 | 벽과 부딪히는 상황은 무시하는가 |
| 2 | 투사체가 빠른 것인가, 발사 간 딜레이가 짧은 것인가 |
| 3 | 거리에 따라 피해량이 달라진다면 총알이 출발점에서 얼마나 날아왔는지 알아야 한다. 최대·최소 피해 값이 필요하고, 없다면 감소량을 정하는 별도 파라미터가 필요하다 |
| 4 | 구체 기믹: 빨강과 파랑을 나누는 이유를 따졌다. 플레이어는 보통 빨강을 나쁜 것, 파랑을 좋은 것으로 인식한다. 일단 던전 기믹으로 만들고 구체 색별 기능은 따로 설정하게 한다 |
| 5 | 보스 체력을 1페이즈와 2페이즈로 나눌 것인가. 1페이즈 시작 후 자동으로 전환되는 이유가 무엇인가 |

원본에는 3번 항목 뒤에 "무슨 말인지 모르겠다"는 메모와 "??"만 있는 메모가 있다. 맥락이 남아 있지 않아 위 표에 옮기지 않았다.
