# 모바일 최적화 적용 중 문제 기록

## 작업 식별

| 항목 | 내용 |
|---|---|
| Task ID | PRJ-MRD-005-TS |
| 유형 | TS (문제 해결 기록) |
| 목적 | 부트스트랩·영구 씬 구조를 적용하면서 나온 문제와 처리를 기록한다 |
| 확인 상태 | 미검증 (원본의 작업 메모를 정리한 것이며 이 환경에서 재현하지 않았다) |
| 개정 | R1 (2026-11-18) |

## 1. 문제와 처리

| 번호 | 증상 | 원인 또는 판단 | 처리 |
|---|---|---|---|
| 1 | 게임 씬에 있던 `UIManager`가 Game Scene에서만 정상 동작한다 | 이름은 매니저지만 매니저 역할을 하면 안 된다고 판단했다. 싱글톤이라 알지 못하는 다른 코드가 접근할 수 있다 | 기존 클래스를 `GameUIController`로 바꾸고 싱글톤 상속을 풀어 `MonoBehaviour`로 바꾼다. 컴파일 오류가 나는 스크립트는 새로 만들 싱글톤 `UIManager`가 `GameUIController`를 보유하게 하고 public으로 접근하도록 고친다 |
| 2 | 오디오 리스너를 Player 씬에서 생성해 타이틀 씬에서 "리스너 없음" 경고가 나고 BGM이 들리지 않는다 | 리스너가 플레이어 생성 전에는 없다 | `SoundManager` 아래에 리스너를 두고, 플레이어가 생성되면 리스너가 플레이어를 따라가게 한다 |
| 3 | 영상 리소스 로드에 문제가 있다 | 원인은 원본에 없다. 원본은 "이미지 소스"라고 적었으나 영상 문맥이라 영상으로 보인다 | 웹 최적화 인코딩 버전으로 다시 인코딩해 해결했다 |
| 4 | 프롤로그 재생 중 플레이어를 조작할 수 있다 | 입력 차단이 없었다 | 프롤로그 종료 후에 조작하도록 수정했다 |
| 5 | 플레이어 프리팹을 인스턴스할 때 메시가 비활성 상태로 로드되고 이동이 안 된다 | 초기화(필요한 컴포넌트 등록)가 필요했다 | 플레이어 씬 로드 시 Init 객체가 미리 등록한 프리팹을 동시에 인스턴스하고 초기화한다 |
| 6 | 플레이어를 프리팹으로 인스턴스하면서 Input System 문제가 생긴다. 마우스 회전이 적용되지 않는 원인으로 의심했다 | 원본에 확정 원인이 없다 | 미해결로 기록. 확인 필요 |
| 7 | 비활성 객체의 컴포넌트에 접근해 경고 메시지가 난다 | 원본에 원인이 없다 | 미해결로 기록 |
| 8 | 매니저 생성 시 `Awake`, `Start` 실행 순서로 의도하지 않은 null 오류가 난다 | 생성 순서 의존 | 각 매니저에 예외 처리를 추가했다 |
| 9 | 아이템 획득처(상자, 힐팩)를 사람이 일일이 관리해 휴먼 에러를 통제할 수 없다 | 팀원 A의 관리 이슈로 기록 | 해결 방안은 원본에 없다 |
| 10 | 같은 아이템을 중복 획득할 수 있다 | 버그에 가깝다. 허용할지, 시스템으로 막을지 유효성 점검이 필요하다고 기록 | 팀원 B와 확인하기로 했다. 결과는 원본에 없다 |

## 2. 결정과 결과

- 이벤트 버스(Event Bus)는 도입하지 않았다. 지금 도입하면 모바일 최적화 중에 일이 지나치게 커진다고 판단했고, 기존 코드를 가능한 한 수정하지 않는 방향을 택했다. (원본 표현: "초가삼간 다 태우는 꼴".)
- 동적 로딩용 트리거 설치와 오류 수정을 마쳤다. 다음 할 일은 PC 브랜치와 병합이었다.
- PC와 모바일 빌드 병합이 성공했다. 이후 Main 브랜치에서 작업을 이어간다.
- 플레이어 사용 여부를 ScriptableObject로 관리하고 영구 씬 매니저가 이를 구독해 오브젝트 로드 여부를 정하는 구상이 있었다. 채택 여부는 원본에 없다.

{% hint style="info" %}
NOTE: 1번의 `GameUIController`로 이름을 바꿀 때는 씬과 프리팹은 스크립트를 파일의 `.meta` GUID로 참조한다. 클래스 이름과 파일 이름이 다르면 `MonoBehaviour` 컴포넌트가 `Missing`이 된다. 파일 이름도 같이 바꾸고 참조가 유지되는지 확인한다. 확인 필요.
{% endhint %}
