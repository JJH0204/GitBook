## 던전 & 스테이지 관리 관련 메모

* 던전
  * 스테이지
    * 웨이브
* 던전메니저는 Stage 프리팹을 활용해 던전에서 사용된 스테이지를 n개 등록해 관리할 수 있다.
* 스테이지 프리팹은 (임시로) 플레이어와 몬스터의 전투가 이뤄질 장소로 사용.
* 몬스터가 플레이어 캐릭터를 추적해야 함으로 NavMesh를 추가해야 함.
* 스테이지 메니저를 통해 해당 스테이지에 등장할 웨이브를 세팅할 수 있다.
* 웨이브는 오름차순으로 등장 예정.
* 각 웨이브는 몬스터를 스폰할 위치를 지정해 둘 수 있다.
  * Add Spawn Point로 스폰포인트를 생성 (붉은색 박스)
  * 해당 위치에 스폰하고자 하는 몬스터 프리팹을 지정

버그: 네비메시를 포함한 프랍을 이동시키고 control + z로 되돌리면 네비메시를 사용할 수 없게 된다.

던전 생성기 v01 관련:

* 바닥마다 NavMesh를 깔아서 문제다. 서피스를 하나만 놔두고 한 번에 생성하고 지워야 됨.

## 몬스터 정의 / 스탯 / 스킬

* 몬스터란?
  * PC를 공격하여 피해를 입히는 던전에서 움직이는 NPC 오브젝트
* 공격 타입
  * 일반 공격: 근거리 / 원거리 (원거리 우선)
* 특수기(스킬)
  * 액티브 / 패시브 (없을 수도 있음)
* 기타 속성 예시
  * n 개 (여러 개의 스킬/속성)
  * 체력
  * 이동 속도

기술 타입

* 일반
  * 근거리
  * 원거리
* 특수
  * 액티브
  * 패시브

몬스터 분류 예시

* Monster Base
* Monster Normal
* Monster Boss

몬스터 시스템과 던전 시스템 관련 구성요소

* 스포너
* 던전 스테이트 메니저
* 던전 클리어 리워드 매니저
* 이벤트 매니저

이벤트 예시: 상호작용(입력/출력) 설계

* 스위치를 off하면 조명이 꺼진다.
* 트리거, 버튼, Idle, 몬스터에 의해서 스폰 등

## 설계 질문들 / 고려사항

* 언제까지? 얼마나?
* 캐릭터 기획서 항목
  * 기획의도, 목적, 방향성, 필수 기능
  * 캐릭터 컨셉, 스킬, 모션, 스토리보드(서사/세계관)
* 상세 기획서 작성
* 이해관계자 / 협업자: 프로그래밍 팀장 / 원화 팀장 / 모델 팀장 / 퍼블리셔 등

게임 모드 분리(예: 이지 / 노멀 / 하드)

* 난이도 관련: 몬스터 공략 난이도 + 플레이 편의성 기능 + 세이브 포인트 존재 여부 등
* 난이도 예시
  * 노말: 현재 방식
  * 하드: 세이브 포인트로 리스폰 방식, 전투 시 플레이어가 가진 정보 그대로 리스폰 (트리거 통과 당시 캐릭터 상태)
* 리스폰 포인트는 레벨 디자인에서 설치 가능하도록

씬을 다시 불러오는 방식 vs 던전 매니저 방식 비교

1. 씬을 다시 불러오는 방식: 죽을 때마다 화면을 가리고 로딩 — 리소스 많이 사용
2. 던전 매니저: 씬을 불러오지 않고, 씬에서 생성된 몬스터 + 상호작용 오브젝트를 매니저가 관리 — 리소스 적음, 버그 가능성 존재

플레이어 리스폰 / 저장소 설계

* 세이브 포인트 GOS 방식으로 기획자가 원하는 지점에 설치
* 던전 매니저에서 세이브 포인트에 플레이어 데이터 저장
* 모바일 브렌치: 리소스 사이즈 줄이기 (PC보다 작게)
* 플레이어 리스폰 시 파츠 착용 정보 초기화 + 최대 체력으로 스폰
* 사망 안내 UI(단순 암전도 괜찮음)

## 클래스 / 컴포넌트 예시 (의사코드 / 구조)

DungeonManager

* List Stage
* bool isDungeonCleared
* int currentStageIndex

StageController

* GameObject playerSpawnPoint
* GameObject player
* Player 게임 오브젝트를 던전 시작점으로 이동
* 게임 매니저에게 던전 클리어 여부를 전달
* List waves
* int currentWaveIndex
* bool isPlayerInStage
* bool isStageCleared
* bool isSpawned

Stage 동작 관련:

* 씬 동작 시 Waves\[0]의 몬스터 스포너를 미리 실행할지 결정
* 플레이어가 트리거를 통과하면 true -> 스테이지 컨트롤러 동작
* 스테이지의 모든 웨이브의 모든 몬스터가 처치되면 스테이지 동작 종료

WaveController

* List monsterSpawners
* bool isWaveActive
* bool isCleared

동작 흐름 요약 (의사흐름)

* 동작 중인 웨이브는 스포너에 몬스터 스폰 명령을 내리지 않는다.
* (스포너들이 생성한 모든 몬스터들이 처치되어) 리스트의 모든 스포너의 cleared 값이 true가 되면 웨이브 클리어
* Func\_SpawnMonsters 호출: isWaveActive 체크 후 반복적으로 spawner.Func\_Spawn 호출
* Func\_ClearWave 호출: isWaveActive 및 isCleared 체크 후 모든 spawner의 IsAllMonstersDead를 확인하여 isCleared 설정

MonsterSpawner

* List spawnedMonster
* GameObject monsterPrefab
* int spawnCount
* GameObject targetPlayer
* bool isCleared

스포너 동작 요약

* 몬스터 스폰 로직, spawnedMonster 관리, targetPlayer 지정, 모든 몬스터가 죽었는지 체크하여 isCleared 설정
