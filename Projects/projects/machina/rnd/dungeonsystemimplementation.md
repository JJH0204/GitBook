# 던전 시스템 구현 (Dungeon)

## 작업 식별

| 항목 | 내용 |
|---|---|
| Task ID | PRJ-MRD-002-DO |
| 유형 | D&O (설계 기록) |
| 목적 | 던전 매니저, 스테이지, 웨이브, 몬스터 스포너의 구조와 설계 중 나온 질문을 기록한다 |
| 확인 상태 | 미검증 (설계 메모를 정리한 것이며 구현 결과를 이 환경에서 확인하지 않았다) |
| 개정 | R1 (2026-11-18) |

## 1. 설계 질문

### 1.1 던전 매니저가 관리할 것

- 몬스터의 작동 여부
- 던전을 구성하는 오브젝트의 작동 여부
- 특수 기믹 제어
- 플레이어 스폰 위치
- 미정: 던전 에디터가 필요한가

### 1.2 몬스터 동작

- 던전에서 스폰되면 바로 동작을 시작한다.
- 플레이어를 타겟으로 움직인다.
- 공격 범위에 도달하면 공격한다.
- 스폰은 던전이 관리한다.

### 1.3 던전, 스테이지, 웨이브 구조

| 단계 | 내용 |
|---|---|
| 던전 | 스테이지 1, 2, 3, 4를 가진다 |
| 스테이지 | 웨이브 01, 02, ...를 가진다 |
| 웨이브 | 몬스터 스포너 목록을 가진다 |

웨이브 타입 예시는 다음과 같다.

| 타입 | 클리어 조건 |
|---|---|
| type1 | 모든 몬스터를 처치한다 |
| type2 | 특정 몬스터를 처치한다 |
| type3 | 미정 |

## 2. 구성 요소

| 구성 요소 | 필드 | 역할 |
|---|---|---|
| DungeonManager | `List<Stage>`, `isDungeonCleared`, `currentStageIndex` | 스테이지 관리, 보스 몬스터 관리 |
| StageController | 플레이어 스폰 지점, 플레이어, 웨이브 목록, `currentWaveIndex`, `isPlayerInStage`, `isStageCleared`, `isSpawned` | 웨이브 관리, 플레이어 감지, 스테이지 상태 관리, 플레이어를 시작점으로 이동, 클리어 여부를 게임 매니저에 전달 |
| WaveController | 몬스터 스포너 목록, `isWaveActive`, `isCleared` | 스포너에 스폰 명령, 웨이브 클리어 판정 |
| MonsterSpawner | 스폰한 몬스터 목록, 몬스터 프리팹, `spawnCount`, 타겟 플레이어, `isCleared` | 몬스터 스폰, 생성 몬스터 관리, 타겟 지정, 전원 사망 시 `isCleared` 설정 |

던전과 몬스터 시스템에 필요한 구성 요소로 스포너, 던전 스테이트 매니저, 던전 클리어 리워드 매니저, 이벤트 매니저를 꼽았다.

## 3. 동작 원리

### 3.1 스테이지

- 씬이 시작될 때 `Waves[0]`의 스포너를 미리 실행할지 결정한다.
- 플레이어가 트리거를 통과하면 `isPlayerInStage`가 `true`가 되고 스테이지 컨트롤러가 동작한다.
- 스테이지의 모든 웨이브의 모든 몬스터를 처치하면 스테이지가 종료된다.

### 3.2 웨이브 (의사 흐름)

- 동작 중인 웨이브는 스포너에 몬스터 스폰 명령을 다시 내리지 않는다.
- 목록의 모든 스포너의 `isCleared`가 `true`이면 웨이브가 클리어된다.
- `Func_SpawnMonsters`는 `isWaveActive`를 확인한 뒤 스포너마다 `Func_Spawn`을 호출한다.
- `Func_ClearWave`는 `isWaveActive`, `isCleared`를 확인한 뒤 모든 스포너의 `IsAllMonstersDead`를 확인해 `isCleared`를 설정한다.

### 3.3 스테이지 등록과 스폰 지점

- 던전 매니저는 Stage 프리팹을 사용해 스테이지 n개를 등록한다.
- 스테이지 프리팹은 임시로 플레이어와 몬스터의 전투 장소로 쓴다.
- 몬스터가 플레이어를 추적하므로 NavMesh가 필요하다.
- 스테이지 매니저로 해당 스테이지의 웨이브를 설정한다. 웨이브는 오름차순으로 등장한다.
- 웨이브마다 스폰 위치를 지정한다. `Add Spawn Point`로 스폰 포인트(붉은 박스)를 만들고 그 위치에 스폰할 몬스터 프리팹을 지정한다.

## 4. 몬스터 정의

- 몬스터는 PC를 공격해 피해를 주는, 던전에서 움직이는 NPC 오브젝트다.
- 공격 타입은 일반 공격(근거리 또는 원거리, 원거리 우선)이다.
- 특수기(스킬)는 액티브 또는 패시브이며 없을 수도 있다.
- 기타 속성은 체력, 이동 속도, 여러 개의 스킬 등이다.
- 분류 예시는 Monster Base, Monster Normal, Monster Boss다.

## 5. 이벤트와 맵 용어

- 이벤트(입력과 출력) 예시: 스위치를 끄면 조명이 꺼진다. 트리거, 버튼, 유휴(Idle), 몬스터에 의한 스폰이 이벤트 원인이 된다.
- 맵 용어: 전투 공간, 복도, 개폐식 문, 버튼식 스포너.

## 6. 난이도와 리스폰

게임 모드를 분리한다(예: 이지, 노멀, 하드). 난이도는 몬스터 공략 난이도, 플레이 편의 기능, 세이브 포인트 유무로 구분한다.

| 모드 | 방식 |
|---|---|
| 노멀 | 현재 방식 |
| 하드 | 세이브 포인트에서 리스폰한다. 전투 중 플레이어 정보는 트리거 통과 당시 상태로 되돌린다 |

리스폰 방식 비교는 다음과 같다.

| 방식 | 장점 | 단점 |
|---|---|---|
| 씬을 다시 불러온다 | 상태 초기화가 단순하다 | 죽을 때마다 화면을 가리고 로딩한다. 리소스를 많이 쓴다 |
| 던전 매니저가 관리한다 | 씬을 불러오지 않아 리소스를 적게 쓴다 | 매니저가 몬스터와 상호작용 오브젝트를 모두 관리해야 해 버그 가능성이 있다 |

플레이어 리스폰과 저장 설계는 다음과 같다.

- 세이브 포인트는 기획자가 원하는 지점에 설치한다. (원본 표기는 "GOS 방식"이며 의미는 원본에 없다. 확인 필요.)
- 던전 매니저가 세이브 포인트에 플레이어 데이터를 저장한다.
- 리스폰 시 파츠 착용 정보를 초기화하고 최대 체력으로 스폰한다.
- 사망 안내 UI를 둔다(단순 암전도 허용).
- 모바일 브랜치는 리소스 크기를 PC보다 줄인다.

## 7. 알려진 문제

| 번호 | 문제 | 상태 |
|---|---|---|
| 1 | NavMesh를 포함한 프랍을 이동한 뒤 `Ctrl+Z`로 되돌리면 NavMesh를 쓸 수 없게 된다 | 안전한 복원 워크플로우 필요 |
| 2 | 던전 생성기 v01이 바닥마다 NavMesh를 깐다 | 서피스를 하나만 두고 한 번에 생성·삭제해야 한다 |

{% hint style="info" %}
NOTE: 서피스 단위 NavMesh는 AI Navigation 패키지(`com.unity.ai.navigation`)의 `NavMeshSurface` 컴포넌트로 만든다. 패키지 버전에 따라 베이크 API와 컴포넌트 구성이 다르다. 버전 확인 필요.
{% endhint %}

## 8. 기획 메모

- 기획서 항목: 기획 의도, 목적, 방향성, 필수 기능, 캐릭터 컨셉, 스킬, 모션, 스토리보드(서사, 세계관). 상세 기획서를 작성한다.
