## 1. 목적

Git은 파일의 변경 이력을 커밋 단위로 기록하는 분산 버전 관리 도구다. 명령어를 외우기 전에 파일이 어느 영역에 있는지를 알아야 `add`, `commit`, `restore`의 차이가 이해된다. 설치와 사용자 설정은 DEV-GIT-002-MP를 따른다.

## 2. 구성 요소

| 번호 | 영역 | 위치 | 역할 |
|---|---|---|---|
| 1 | 작업 트리 (working tree) | 저장소 폴더의 일반 파일 | 지금 편집하는 파일이다 |
| 2 | 스테이징 영역 (index) | `.git/index` | 다음 커밋에 넣을 변경을 모아 두는 곳이다 |
| 3 | 저장소 (repository) | `.git/` 폴더 | 커밋 이력이 저장된다 |
| 4 | 커밋 (commit) | 저장소 안의 객체 | 스테이징한 내용의 스냅샷이다. 해시, 작성자, 메시지, 부모 커밋을 가진다 |
| 5 | 브랜치 (branch) | 커밋을 가리키는 이름 | `main` 등. 커밋하면 가리키는 위치가 앞으로 이동한다 |
| 6 | `HEAD` | 현재 브랜치를 가리키는 포인터 | 지금 어느 커밋 위에서 작업하는지를 나타낸다 |

## 3. 동작 원리

### 3.1 변경이 커밋이 되는 흐름

```text
작업 트리 --git add--> 스테이징 영역 --git commit--> 저장소
   ^                        |
   +----git restore --------+ (스테이징 취소는 git restore --staged)
```

### 3.2 파일 상태 확인

임시 저장소에서 `a.txt`를 만들고 `git status -s`(짧은 출력)로 확인한 결과다.

| 동작 | `git status -s` 출력 | 뜻 |
|---|---|---|
| 새 파일 생성 | `?? a.txt` | 추적하지 않는 파일(untracked) |
| `git add a.txt` | `A  a.txt` | 스테이징됨(왼쪽 열) |
| 커밋 후 파일 수정 | ` M a.txt` | 작업 트리만 변경됨(오른쪽 열) |
| 수정 후 `git add` | `M  a.txt` | 변경이 스테이징됨 |

짧은 출력의 왼쪽 열은 스테이징 영역, 오른쪽 열은 작업 트리의 상태다.

### 3.3 커밋은 스냅샷이다

커밋은 파일의 차이(diff)가 아니라 그 시점 전체 내용의 스냅샷으로 저장된다. `git diff`와 `git show`가 보여 주는 차이는 두 스냅샷을 비교해 계산한 값이다. 커밋은 부모 커밋을 가리키므로 `git log`로 이력을 거슬러 올라갈 수 있다. 병합 커밋은 부모가 둘이다. 내용이 같은 파일은 저장소 안에서 같은 객체를 공유한다.

### 3.4 커밋 하나 만들기

```bash
git init demo
cd demo
echo hello > a.txt
git add a.txt
git commit -m "first"
git log --oneline
```

실행 결과 일부다. 해시 값은 실행마다 다르다.

```text
[main (root-commit) ae1f3c0] first
 1 file changed, 1 insertion(+)
 create mode 100644 a.txt
ae1f3c0 first
```

{% hint style="info" %}
NOTE: 첫 브랜치 이름은 설정에 따라 `main` 또는 `master`다. `git config --global init.defaultBranch main`으로 정한다. 이 환경에서는 `main`으로 설정했다.
{% endhint %}

## 4. 약어·용어

| 용어 | 뜻 |
|---|---|
| untracked | Git이 아직 추적하지 않는 파일 |
| staged | 다음 커밋에 포함되도록 `git add`한 상태 |
| `HEAD~1` | `HEAD`의 바로 앞 커밋(부모) |
| 해시 | 커밋을 식별하는 40자리(SHA-1 저장소 기준) 값. 보통 앞 7자리로 줄여 쓴다 |
