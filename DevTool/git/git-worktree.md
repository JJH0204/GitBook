## 3. 안전 사항

{% hint style="warning" %}
CAUTION: 같은 브랜치를 두 worktree에서 동시에 체크아웃할 수 없다. 이미 열린 브랜치를 지정하면 거부된다.
{% endhint %}

## 4. 준비

| 번호 | 항목 | 확인 방법 |
|---|---|---|
| 1 | 저장소 폴더에 있다 | `git status` |

## 5. 절차

1. (SUBTASK 5-A-01) 새 브랜치와 새 폴더를 함께 만든다: `git worktree add ../<폴더> -b <새 브랜치>` → 결과: `Preparing worktree (new branch '<새 브랜치>')`, `HEAD is now at <해시> <제목>`
2. (SUBTASK 5-A-02) 목록을 확인한다: `git worktree list` → 결과: `<경로>/<원래 폴더> <해시> [main]`, `<경로>/<새 폴더> <해시> [<새 브랜치>]` 두 줄이 나온다.
3. (SUBTASK 5-A-03) 새 폴더로 이동해 작업·커밋한다. → 결과: 원래 폴더의 작업 트리는 바뀌지 않는다. 두 폴더가 같은 `.git` 이력과 브랜치를 공유한다.
4. (SUBTASK 5-A-04) 이미 있는 브랜치를 열려면 `git worktree add ../<폴더> <기존 브랜치>`를 실행한다. → 결과: 그 브랜치가 새 폴더에 체크아웃된다.

## 6. 기능 확인

| 번호 | 확인 동작 | 기대 결과 | 합격 기준 |
|---|---|---|---|
| 1 | `ls ../<폴더>` | 저장소 파일이 있다 | 파일이 보인다 |
| 2 | `git branch` | 새 브랜치 앞에 `+`가 붙는다 | 다른 worktree에서 열려 있다는 표시다 |

## 7. 복구

1. (7-01) 폴더를 제거한다: `git worktree remove ../<폴더>` → 결과: 폴더가 삭제되고 `git worktree list`가 한 줄이 된다. 커밋하지 않은 변경이 있으면 거부된다.
2. (7-02) 브랜치가 더 필요 없으면 지운다: `git branch -d <새 브랜치>` → 결과: `Deleted branch <새 브랜치> (was <해시>).`
3. (7-03) 폴더를 직접 지워 목록만 남았다면 `git worktree prune`을 실행한다. 실행하지 않았으므로 미검증이다.
