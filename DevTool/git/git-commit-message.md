## 메시지 구조

```text
<제목: 한 줄>
<빈 줄>
<본문: 무엇을, 왜 바꿨는지>
```

제목은 `git log --oneline`과 `git log --format=%s`에 나온다. 본문은 `git log --format=%b`에 나온다.

실행 예: `git commit -m "feat: add login" -m "body line 1"` 처럼 `-m`을 두 번 쓰면 첫 번째가 제목, 두 번째가 본문(문단 사이는 빈 줄)이 된다. `git log -1 --format='%s|%b'`는 `feat: add login|body line 1`을 출력한다.

## 접두어(Conventional Commits 방식)

형식은 `<유형>: <설명>`이다. 아래 유형은 널리 쓰이는 관례이며 팀마다 다를 수 있다.

| 유형 | 의미 |
|---|---|
| `feat` | 새 기능 |
| `fix` | 버그 수정 |
| `docs` | 문서만 변경 |
| `refactor` | 동작 변화 없는 코드 정리 |
| `test` | 테스트 추가·수정 |
| `chore` | 빌드·설정 등 기타 |

형식을 자동으로 검사하려면 DEV-GIT-021-MP의 `commit-msg` 훅을 쓴다.

## 고치기

| 상황 | 명령 | 주의 |
|---|---|---|
