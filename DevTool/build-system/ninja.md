## 1. 목적

Ninja는 빠른 응답 시간을 목표로 하는 작은 빌드 시스템이다. 주로 큰 소프트웨어 프로젝트를 위해 설계되었다. Google의 크롬 브라우저 같은 대규모 소프트웨어 프로젝트에서 쓰인다. C, C++ 같은 언어로 작성된 프로젝트에 특히 잘 맞는다.

## 2. 구성 요소

| 번호 | 이름 | 역할 |
|---|---|---|
| 1 | `ninja` 프로그램 | 빌드 파일을 읽어 컴파일러를 호출한다 |
| 2 | 빌드 파일 (`build.ninja`) | 무엇을 어떤 순서로 빌드할지 적은 파일이다. 보통 다른 도구가 자동으로 만든다 |
| 3 | 빌드 파일 생성 도구 | CMake, Meson 등. 소스 코드의 의존성을 분석해 Ninja용 빌드 파일을 만든다 |

## 3. 동작 원리

### 주요 특징

1. **고성능.** 다시 빌드할 때 특히 빠르다. 변경이 없는 부분은 빌드 과정을 건너뛰기 때문이다.
2. **간결한 설정.** 설정 파일이 매우 간단하고 구조가 명확하다. 이 파일은 보통 다른 빌드 시스템이 자동으로 만든다.
3. **명확한 로깅과 진단.** 빌드 중 무슨 일이 일어나는지 이해하기 쉽도록 로그와 진단 정보를 제공한다.

### CMake와의 관계

Ninja는 자체적으로 빌드를 구성하는 기능을 제공하지 않는다. 대신 CMake, Meson 같은 빌드 구성 도구와 함께 쓰는 경우가 많다. 이 도구들은 소스 코드의 의존성을 분석하고 그 결과로 Ninja용 빌드 파일을 만든다.

CMake를 쓰는 순서는 다음과 같다.

1. [CMakeLists.txt](cmakelists.txt.md)에 프로젝트 설정을 적는다.
2. CMake로 Ninja용 빌드 파일을 만든다.
3. 만들어진 빌드 파일로 Ninja가 프로젝트를 빌드하게 한다.

실제 명령은 DEV-BLD-005-MP를 따른다.

## 4. 약어·용어

| 용어 | 뜻 |
|---|---|
| 빌드 시스템 | 소스 코드를 컴파일해 실행 파일로 만드는 과정을 실행하는 프로그램 |
| 생성기 (generator) | CMake가 만들어 내는 빌드 파일의 종류. Ninja는 그 한 종류다 |
