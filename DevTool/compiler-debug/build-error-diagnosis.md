# [생성형 AI] 컴파일·링크 오류 진단

## 작업 식별

| 항목 | 내용 |
|---|---|
| Task ID | DEV-CMP-007-TS |
| 유형 | TS (문제 해결) |
| 목적 | gcc가 출력하는 대표 오류 다섯 가지의 원인을 구분하고 고친다 |
| 작성 | 생성형 AI 초안 (사람 검토 전) |
| 확인 상태 | 검증됨 (gcc 15.2.0, Linux x86-64, 2026-11-19에서 각 오류를 일부러 만들어 메시지를 확인했다. 메시지 문구는 gcc 버전에 따라 다를 수 있다) |
| 개정 | R1 (2026-11-19) |

## 1. 증상

`gcc`가 `rc=1`(종료 코드 1)로 끝나고 실행 파일이 만들어지지 않는다. 메시지 형태로 단계를 먼저 구분한다.

| 메시지 형태 | 단계 |
|---|---|
| `파일:줄:열: error: ...` | 컴파일 단계 |
| `... undefined reference to ...`, `ld returned 1 exit status` | 링크 단계 |

## 2. 가능 원인

| 번호 | 메시지(실제 출력) | 단계 | 원인 |
|---|---|---|---|
| 1 | `fatal error: nope.h: No such file or directory` | 전처리 | 헤더 파일이 없거나 검색 경로에 없다 |
| 2 | `error: expected ',' or ';' before 'return'` | 컴파일 | 앞 줄의 세미콜론 누락 등 문법 오류 |
| 3 | `error: implicit declaration of function 'foo'` | 컴파일 | 선언하지 않은 함수를 호출했다 |
| 4 | `undefined reference to 'add'` | 링크 | 함수 정의가 든 `.o`·`.c`를 링크에 넣지 않았다 |
| 5 | `multiple definition of 'add'` | 링크 | 같은 함수가 둘 이상의 파일에 정의돼 있다 |
| 6 | `warning: 'x' is used uninitialized [-Wuninitialized]` | 경고 | 값을 넣지 않은 지역 변수를 읽었다. 오류는 아니어서 `rc=0`이다 |

{% hint style="info" %}
NOTE: 이 환경의 gcc 15에서 3번(암묵적 함수 선언)은 오류로 처리됐다. 오래된 gcc나 `-std=gnu89` 계열에서는 경고에 그치는 경우가 있다.
{% endhint %}

## 3. 격리 절차

1. (3-01) 메시지의 첫 줄만 읽는다. 첫 오류가 나머지 오류를 만드는 경우가 많다.
2. (3-02) `파일:줄:열` 위치로 간다. 오류가 앞 줄에서 시작된 경우가 많다(원인 2에서 보듯 지적된 줄 바로 앞에서 문제가 있다).
3. (3-03) 링크 오류면 파일 목록을 확인한다. `.o`로 단계를 나눠 확인한다: `gcc -c main.c util.c` 가 성공하면 컴파일은 정상이다.
4. (3-04) `nm <파일>.o`로 정의(`T`)와 미정의(`U`) 심볼을 본다 → 결과: 미정의 심볼 `add`에 대응하는 `T add`가 어느 `.o`에도 없으면 원인 4다.

## 4. 시정 조치

| 원인 | 조치 | 확인한 결과 |
|---|---|---|
| 1 | 철자를 고치거나 `-I<폴더>`로 헤더 폴더를 알려 준다 | |
| 2 | 지적된 줄과 그 앞 줄의 문법을 고친다 | |
| 3 | 함수 선언이 든 헤더를 `#include`하거나 선언을 추가한다 | 헤더 없이 호출하면 위 메시지 |
| 4 | 정의가 있는 파일을 명령에 추가한다: `gcc main.c util.c -o app` | 소스를 넣으면 링크가 성공하고 `./app`이 `5`를 출력했다 |
| 5 | 중복 정의를 하나만 남긴다. 헤더에 함수 본문을 쓰면 여러 파일에 중복되므로 `.c`로 옮긴다 | 소스 세 개 중 두 개가 `add`를 정의했을 때 발생했다 |
| 6 | 변수를 초기화한다. 이 경고는 `-Wall`로 켜졌다 | |

{% hint style="warning" %}
CAUTION: 경고를 무시하고 넘기지 않는다. 6번의 미초기화 변수는 실행할 때마다 결과가 달라지는 버그가 된다.
{% endhint %}
