## 1. 목적

디버거(debugger)는 프로그램의 버그를 찾아 제거할 때 쓰는 도구다. 프로그램을 멈추고 한 단계씩 실행하면서 내부 상태를 확인한다.

## 2. 구성 요소

디버거가 보여 주는 대상은 아래와 같다.

| 번호 | 대상 | 확인하는 내용 | gdb 명령 (DEV-CMP-005-REF) |
|---|---|---|---|
| 1 | 어셈블리 코드 | 실행 중인 기계어 명령 | `disas` |
| 2 | 레지스터 (Register) | CPU 레지스터의 현재 값 | `info registers` |
| 3 | 메모리 (Memory) | 특정 주소의 값 | `x` |
| 4 | 스택 (Stack) | 함수 호출 순서와 지역 변수 | `bt`, `info locals` |
| 5 | 변수 | 소스 코드 변수의 현재 값 | `print` |

## 3. 동작 원리

디버거는 아래 기능으로 프로그램을 제어한다.

| 기능 | 설명 |
|---|---|
| 중단점 (breakpoint) | 지정한 위치에서 프로그램을 멈춘다 |
| 단계 실행 (step) | 한 줄 또는 한 명령씩 실행한다 |
| 계속 실행 (continue) | 다음 중단점까지 실행한다 |
| 감시점 (watchpoint) | 변수 값이 바뀌면 프로그램을 멈춘다 |
| 상태 조회 | 멈춘 시점의 레지스터, 메모리, 스택을 읽는다 |

사용 순서는 아래와 같다.

1. 디버그 정보(`-g`)를 넣어 프로그램을 컴파일한다.
2. 디버거로 프로그램을 연다.
3. 중단점을 설정한다.
4. 프로그램을 실행한다. 중단점에서 멈춘다.
5. 상태를 확인하고 단계 실행으로 진행한다.

{% hint style="info" %}
NOTE: 소스 코드 줄 단위로 디버깅하려면 디버그 정보가 필요하다. 디버그 정보가 없으면 gdb는 `(No debugging symbols found in ...)`를 출력하고 어셈블리 단위로만 볼 수 있다.
{% endhint %}

## 4. 약어·용어

| 용어 | 뜻 |
|---|---|
| 레지스터 (Register) | CPU 안의 작고 빠른 저장 공간 |
| 스택 (Stack) | 함수 호출과 지역 변수를 쌓아 두는 메모리 영역 |
| 디버그 정보 | 기계어와 소스 코드 줄을 연결하는 정보. `gcc -g`로 넣는다 |
| 심볼 (symbol) | 함수·변수 이름과 주소를 연결하는 정보 |
