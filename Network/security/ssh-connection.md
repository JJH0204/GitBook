# SSH 원격 서버 접속

## 작업 식별

| 항목 | 내용 |
|---|---|
| Task ID | NET-NSC-007-MP |
| 목적 | SSH 클라이언트로 원격 서버에 패스워드 또는 개인 키로 접속하고 세션을 종료한다 |
| 적용 대상 | OpenSSH 클라이언트가 있는 Windows 10/11, macOS, Linux |
| 소요 시간 | 약 5분 |
| 확인 상태 | 미검증 (원본 페이지의 명령을 정리한 것이며 이 환경에서 실행해 확인하지 않았다) |
| 개정 | R1 (2026-11-18) |

## 2. 필요 장비와 자재

| 번호 | 이름 | 사양 | 비고 |
|---|---|---|---|
| 1 | SSH 클라이언트 | OpenSSH (`ssh` 명령) | |
| 2 | 접속 정보 | `<사용자명>`, `<호스트>`, `<포트>` | 서버 관리자에게 받는다 |
| 3 | 개인 키 파일 | 구역 B에서만 필요하다 | 서버에 공개 키가 등록돼 있어야 한다 |

## 3. 안전 사항

{% hint style="danger" %}
WARNING: 허가받은 서버에만 접속한다. 허가 없는 서버에 접속하거나 비밀번호를 반복 시도하는 것은 불법이다.
{% endhint %}

{% hint style="warning" %}
CAUTION: 첫 접속 때 나오는 호스트 지문을 서버 관리자가 알려준 값과 비교한다. 다르면 접속을 중단한다.
{% endhint %}

## 4. 준비

| 번호 | 항목 | 확인 방법 |
|---|---|---|
| 1 | 터미널을 연다 | 프롬프트가 나타난다 |
| 2 | SSH 클라이언트가 있는지 확인한다: `ssh -V` | 버전 문자열이 출력된다 |
| 3 | 서버의 주소와 포트에 연결할 수 있는지 확인한다 | 서버 관리자에게 접속 허용 여부를 확인한다 |

## 5. 절차

### A. 패스워드로 접속

{% hint style="warning" %}
CAUTION: 패스워드 인증은 무차별 대입 공격에 약하다. 가능하면 구역 B의 개인 키 인증을 쓴다.
{% endhint %}

1. (5-A-01) 접속 명령을 입력한다: `ssh <사용자명>@<호스트>` (22번이 아닌 포트는 `-p <포트>`를 붙인다) → 결과: 비밀번호 입력 요청이 나온다.
2. (5-A-02) 비밀번호를 입력한다. → 결과: 입력한 글자는 화면에 표시되지 않는다. 인증에 성공하면 원격 서버의 쉘 프롬프트가 나온다.

### B. 개인 키로 접속

1. (5-B-01) 개인 키 파일의 권한을 제한한다: `chmod 600 <개인 키 파일 경로>` (Windows는 이 단계를 건너뛴다) → 결과: 오류 없이 끝난다.
2. (5-B-02) 접속 명령을 입력한다: `ssh <사용자명>@<호스트> -p <포트> -i <개인 키 파일 경로>` → 결과: 비밀번호 입력 없이 원격 서버의 쉘 프롬프트가 나온다. (키에 암호가 설정돼 있으면 키 암호 입력을 요구한다.)

### C. 접속 종료

1. (5-C-01) 세션을 종료한다: `exit` → 결과: 원격 연결이 닫히고 로컬 프롬프트로 돌아온다.

## 6. 기능 확인

| 번호 | 확인 동작 | 기대 결과 | 합격 기준 |
|---|---|---|---|
| 1 | 접속 후 `hostname` 입력 | 원격 서버의 호스트 이름이 출력된다 | 로컬 PC 이름과 다르다 |
| 2 | 접속 후 `whoami` 입력 | 접속한 계정 이름이 출력된다 | `<사용자명>`과 같다 |

## 7. 복구

이 작업은 서버 설정을 바꾸지 않는다. 접속이 실패하면 아래를 확인한다.

1. (7-01) `Permission denied`가 나오면 사용자명, 비밀번호, 키 파일 경로를 확인한다.
2. (7-02) `Connection timed out`이 나오면 호스트 주소, 포트, 방화벽 허용 여부를 확인한다.
3. (7-03) 개인 키 권한 오류(`UNPROTECTED PRIVATE KEY FILE`)가 나오면 5-B-01을 수행한다.
