## 1. 목적

ACL(Access Control List)은 규칙을 위에서 아래로 나열한 목록이다. 라우터 인터페이스에 적용해 지나가는 패킷을 허용(permit)하거나 차단(deny)한다. 방화벽이 없는 구간에서도 기본적인 접근 통제를 할 수 있다.

## 2. 구성 요소

| 구분 | 표준 ACL | 확장 ACL |
|---|---|---|
| 판단 기준 | 출발지 IP 주소만 | 출발지·목적지 IP, 프로토콜, 포트 |
| Cisco 번호 대역 | 1~99, 1300~1999 | 100~199, 2000~2699 |
| 적용 위치 권장 | 목적지에 가까운 인터페이스 | 출발지에 가까운 인터페이스 |
| 세밀도 | 낮음 | 높음 |

| 요소 | 설명 |
|---|---|
| 규칙(ACE) | permit 또는 deny와 조건 한 줄 |
| 와일드카드 마스크 | 서브넷 마스크와 반대 표기. `/24`는 `0.0.0.255` |
| 적용 방향 | 인터페이스의 in(들어올 때) 또는 out(나갈 때) |
| 암묵적 deny | 목록 끝에 보이지 않는 `deny any`가 있다 |

## 3. 동작 원리

1. 패킷이 ACL이 적용된 인터페이스·방향에 도착한다.
2. 위에서부터 규칙을 하나씩 비교한다.
3. 처음 일치한 규칙의 동작(permit 또는 deny)을 적용하고 나머지 규칙은 보지 않는다.
4. 일치하는 규칙이 없으면 암묵적 deny로 버린다.

그래서 규칙 순서가 결과를 바꾼다. 범위가 좁은 규칙을 위에, 넓은 규칙을 아래에 둔다.

### 3.1 설정 형태 예시 (개념 설명용)

```
ip access-list extended WEB-ONLY
 permit tcp 192.168.10.0 0.0.0.255 any eq 80
 permit tcp 192.168.10.0 0.0.0.255 any eq 443
interface GigabitEthernet0/1
 ip access-group WEB-ONLY in
```

192.168.10.0/24에서 나가는 웹(80, 443) 트래픽만 허용하고 나머지는 암묵적 deny로 막는 예다.

{% hint style="warning" %}
CAUTION: 원격 접속(SSH) 중인 인터페이스에 ACL을 잘못 적용하면 접속이 끊긴다. 실제 장비에서는 콘솔 접속을 확보한 뒤 적용한다.
{% endhint %}

## 4. 약어·용어

| 용어 | 뜻 |
|---|---|
| ACE | Access Control Entry. ACL의 규칙 한 줄 |
| 와일드카드 마스크 | 일치 비교에서 무시할 비트를 1로 표시하는 마스크 |
