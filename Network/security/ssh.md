## 1. 목적

SSH(Secure Shell)는 원격 서버에 안전하게 접속하게 해 주는 암호화 네트워크 프로토콜이다. 원격 Linux 서버에 접속하는 가장 일반적인 방식이다. 클라이언트가 원격 서버의 터미널에 명령을 입력하면 서버가 실행 결과를 클라이언트에 돌려준다. 통신은 암호화되어 도청과 변조를 막는다.

## 2. 구성 요소

### 2.1 구성

| 구성 요소 | 역할 | 비고 |
|---|---|---|
| SSH 클라이언트 | 서버에 접속해 명령을 보낸다 | `ssh` 명령 |
| SSH 서버 | 접속을 받아 인증하고 명령을 실행한다 | 보통 `sshd`, 기본 포트 22/tcp |
| 호스트 키 | 서버가 자신이 맞음을 증명하는 키 | 첫 접속 시 지문(fingerprint) 확인을 요구한다 |
| 사용자 키 쌍 | 클라이언트를 인증하는 공개 키·개인 키 | `ssh-keygen`으로 만든다 |

### 2.2 접속 명령의 형식

```shell
ssh <사용자명>@<호스트> -p <포트> -i <개인 키 파일 경로>
```

| 요소 | 의미 |
|---|---|
| `<사용자명>` | 원격 서버에 존재하는 계정 이름 |
| `<호스트>` | 접속할 서버의 IP 주소 또는 도메인 |
| `-p <포트>` | 22가 아닌 포트로 접속할 때 쓴다 |
| `-i <개인 키 파일 경로>` | 키 인증에 쓸 개인 키 파일 |

### 2.3 인증 방식 비교

| 방식 | 동작 | 장점 | 단점 |
|---|---|---|---|
| 패스워드 | 계정 비밀번호를 입력한다 | 설정이 필요 없다 | 짧거나 단순한 비밀번호는 무차별 대입 공격으로 알아낼 수 있어 권장하지 않는다 |
| 개인 키 | 서버에 공개 키를 등록하고 클라이언트가 개인 키로 증명한다 | 비밀번호를 네트워크로 보내지 않는다. 무차별 대입이 사실상 불가능하다 | 개인 키 파일 관리가 필요하다 |

{% hint style="warning" %}
CAUTION: 개인 키 파일은 타인에게 공유하지 않는다. 키 파일의 권한은 소유자만 읽도록 제한한다(Linux·macOS는 `chmod 600`).
{% endhint %}

## 3. 동작 원리

1. 클라이언트가 서버의 SSH 포트(기본 22/tcp)로 연결한다.
2. 서버가 호스트 키를 제시하고, 클라이언트가 처음 보는 호스트라면 지문 확인을 요구한다.
3. 양쪽이 키 교환으로 세션 키를 만들어 이후 통신을 암호화한다.
4. 서버가 클라이언트를 인증한다(패스워드 또는 개인 키).
5. 인증에 성공하면 서버가 쉘을 열어 클라이언트가 명령을 입력할 수 있다.
6. 클라이언트가 `exit`를 입력하면 세션이 끝난다.

## 4. 약어·용어

| 용어 | 뜻 |
|---|---|
| SSH | Secure Shell. 원본은 Secure Socket Shell이라고도 부른다고 썼으나 공식 명칭은 Secure Shell이다 |
| 호스트 키 | 서버의 신원을 증명하는 키 |
| 지문 | 키를 해시한 짧은 식별 값 |
| 무차별 대입 공격 | Brute-force Attack. 가능한 비밀번호를 계속 시도하는 공격 |
