# RAID 레벨 비교

## 작업 식별

| 항목 | 내용 |
|---|---|
| Task ID | NET-NSV-003-REF |
| 유형 | REF (표) |
| 목적 | 주요 RAID 레벨(0, 1, 5, 6, 10)의 최소 디스크 수, 가용 용량, 내결함성을 비교한다 |
| 확인 상태 | 미검증 (일반 스토리지 지식으로 작성했으며 제품별 구현은 확인하지 않았다) |
| 개정 | R1 (2026-11-18) |

{% hint style="info" %}
NOTE: 원본에 없던 문서다. RAID 개념은 NET-NSV-002-DO에 있다. 이 표는 같은 크기의 디스크 N개를 쓴다고 가정하며, 디스크 1개 용량을 S로 쓴다.
{% endhint %}

## 1. 레벨 비교

| 레벨 | 구성 | 최소 디스크 | 가용 용량 | 견딜 수 있는 고장 | 특징 |
|---|---|---|---|---|---|
| RAID 0 | 스트라이핑 | 2 | N x S | 0개 | 가장 빠르다. 디스크 1개만 고장 나도 전체 데이터를 잃는다 |
| RAID 1 | 미러링 | 2 | S | N-1개 | 복사본이 있어 안전하다. 용량 효율이 낮다 |
| RAID 5 | 스트라이핑 + 분산 패리티 | 3 | (N-1) x S | 1개 | 용량과 안정성의 균형. 쓰기가 느린 편이다 |
| RAID 6 | 스트라이핑 + 이중 패리티 | 4 | (N-2) x S | 2개 | RAID 5보다 안전하다. 쓰기가 더 느리다 |
| RAID 10 | 미러 묶음을 스트라이핑 | 4(짝수) | N/2 x S | 미러 쌍마다 1개(쌍 하나가 모두 고장 나면 손실) | 빠르고 안전하다. 용량 효율이 50%다 |

## 2. 사용 예

| 상황 | 선택 레벨 | 이유 |
|---|---|---|
| 임시 작업 파일, 영상 편집 캐시 | RAID 0 | 속도가 중요하고 데이터를 잃어도 된다 |
| 운영체제 디스크 | RAID 1 | 구성이 단순하고 안전하다 |
| 일반 파일 서버 | RAID 5 또는 6 | 용량 효율과 안정성을 함께 얻는다. 큰 디스크에서는 RAID 6을 권장한다 |
| 데이터베이스 서버 | RAID 10 | 쓰기 성능이 높고 재구축이 빠르다 |
