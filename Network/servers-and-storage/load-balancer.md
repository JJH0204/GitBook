## 1. 목적

로드 밸런서는 들어오는 요청을 여러 서버에 나눠 보내 처리량을 늘리고, 서버 한 대가 멈춰도 서비스가 계속되게 한다.

## 2. 구성 요소

| 요소 | 설명 |
|---|---|
| VIP | 클라이언트가 접속하는 대표 주소 |
| 서버 풀 | 요청을 실제로 처리하는 서버 묶음 |
| 상태 확인 | 서버가 살아 있는지 주기적으로 검사한다. 응답 없는 서버는 풀에서 제외한다 |

| 구분 | L4 로드 밸런서 | L7 로드 밸런서 |
|---|---|---|
| 판단 기준 | IP, 포트 | URL, 헤더, 쿠키 등 응용 계층 내용 |
| 특징 | 빠르고 단순 | 경로별·호스트별 분배 가능. 처리 비용이 크다 |

## 3. 동작 원리

1. 클라이언트가 VIP로 요청을 보낸다.
2. 로드 밸런서가 분산 알고리즘으로 풀의 서버 하나를 고른다.
3. 요청을 그 서버에 전달하고 응답을 클라이언트에 돌려보낸다.
4. 상태 확인에 실패한 서버는 복구될 때까지 제외한다.

### 3.1 분산 방식

| 방식 | 설명 |
|---|---|
| 라운드 로빈 | 서버를 순서대로 돌아가며 선택 |
| 최소 연결 | 현재 연결 수가 가장 적은 서버 선택 |
| 해시(IP 등) | 클라이언트 주소로 서버를 고정해 같은 서버로 보냄 |
| 가중치 | 성능이 높은 서버에 더 많이 배정 |

### 3.2 세션 유지

로그인 상태를 서버 메모리에 두면 요청이 다른 서버로 가는 순간 상태가 없어진다. 쿠키·해시 기반 고정(sticky session)을 쓰거나 세션을 공유 저장소로 옮겨 해결한다.

{% hint style="info" %}
NOTE: 로드 밸런서 자체가 단일 장애점이 되지 않도록 보통 이중화한다.
{% endhint %}
