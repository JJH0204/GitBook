## 1. 목적

RAID(Redundant Array of Independent Disks, 한국어로 복수 배열 독립 디스크)는 2개 이상의 디스크를 묶어 하나의 논리 디스크로 쓰는 기술이다. 성능과 안정성을 높인다.

- 과거에는 작은 용량의 디스크를 묶어 큰 용량을 만들려고 썼다.
- 최근에는 디스크 오류와 데이터 손실에 대비하는 용도로 쓴다.

{% hint style="warning" %}
CAUTION: RAID는 디스크 고장에 대한 대비책이지 백업이 아니다. 파일 삭제, 랜섬웨어, 컨트롤러 고장, 화재에서는 데이터를 지키지 못한다. 별도 백업이 필요하다.
{% endhint %}

## 2. 구성 요소

### 2.1 기본 기법

| 기법 | 동작 | 효과 |
|---|---|---|
| 스트라이핑(Striping) | 데이터를 조각내 여러 디스크에 나눠 쓴다 | 읽기·쓰기 속도가 올라간다. 중복이 없다 |
| 미러링(Mirroring) | 같은 데이터를 두 디스크 이상에 복제한다 | 디스크가 고장 나도 복사본으로 계속 쓴다. 가용 용량이 줄어든다 |
| 패리티(Parity) | 데이터에서 계산한 복구용 값을 함께 저장한다 | 디스크가 고장 나면 남은 데이터와 패리티로 복구한다. 쓰기 때 계산 비용이 든다 |

### 2.2 구현 방식

| 방식 | 설명 |
|---|---|
| 하드웨어 RAID | RAID 컨트롤러 카드가 처리한다 |
| 소프트웨어 RAID | 운영체제가 처리한다(Linux `mdadm` 등) |

## 3. 동작 원리

RAID 5(스트라이핑 + 분산 패리티) 예시는 다음과 같다.

1. 쓰기 요청이 오면 데이터를 조각으로 나눠 디스크 여러 개에 나눠 쓴다.
2. 각 조각 묶음의 패리티를 계산해 조각이 없는 다른 디스크에 쓴다. 패리티 위치는 디스크마다 돌아가며 바뀐다.
3. 디스크 1개가 고장 나면 남은 디스크의 데이터와 패리티로 빠진 조각을 계산해 읽는다.
4. 새 디스크로 교체하면 계산한 내용을 새 디스크에 다시 쓴다(재구축).

{% hint style="warning" %}
CAUTION: 재구축 중에는 성능이 떨어지고, 같은 시기에 쓴 다른 디스크가 함께 고장 날 위험이 있다. RAID 5는 디스크 2개가 동시에 고장 나면 데이터를 잃는다.
{% endhint %}

## 4. 약어·용어

| 용어 | 뜻 |
|---|---|
| RAID | Redundant Array of Independent Disks. 원래는 Inexpensive Disks로 불렀다 |
| 논리 디스크 | 운영체제가 하나로 보는 RAID 볼륨 |
| 재구축 | 고장 난 디스크의 데이터를 새 디스크에 복원하는 과정 |
| 핫 스페어 | 고장에 대비해 미리 꽂아 둔 예비 디스크 |
