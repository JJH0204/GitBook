# 게이트웨이 설정 (Gateway Setup)

## 작업 식별

| 항목 | 내용 |
|---|---|
| Task ID | NET-IPN-008-MP |
| 목적 | 라우터를 설치하고 LAN 쪽 인터페이스에 게이트웨이 IP(`192.168.10.254/24`)를 설정해 LAN이 외부 네트워크로 나가는 통로를 연다 |
| 적용 대상 | 스위치가 연결된 라우터 1대 (Cisco IOS 계열 CLI, 인터페이스 `GigabitEthernet0/0`) |
| 소요 시간 | 약 20분 |
| 확인 상태 | 미검증 (원본의 명령은 이미지에만 있었고 본문에 없었다. 아래 명령은 원본 요약문을 바탕으로 작성한 것이며 장비에서 실행해 확인하지 않았다) |
| 개정 | R1 (2026-11-18) |

{% hint style="info" %}
NOTE: 원본의 "Gateway란?" 절은 비어 있었다. 아래 정의는 추가한 내용이다. 게이트웨이(gateway)는 LAN의 장치가 다른 네트워크로 나갈 때 패킷을 보내는 출입구이며, 보통 라우터의 LAN 쪽 인터페이스 IP다. 호스트가 이 주소를 "기본 게이트웨이"로 설정한다.
{% endhint %}

## 2. 필요 장비와 자재

| 번호 | 이름 | 사양·버전 | 비고 |
|---|---|---|---|
| 1 | 라우터 | `GigabitEthernet0/0` 인터페이스가 있는 모델 | |
| 2 | 스위치 | 라우터와 연결할 포트가 있는 모델 | |
| 3 | 케이블 | 이더넷 케이블 | |
| 4 | 콘솔 접속 수단 | 콘솔 케이블과 터미널 프로그램 | 이 PC가 네트워크 경유 접속(SSH, Telnet)이 아닌 콘솔로 접속한다 |
| 5 | 확인용 PC | `192.168.10.0/24`에 속한 주소를 가진 PC | 6절에서 사용 |

## 3. 안전 사항

{% hint style="danger" %}
WARNING: 이미 네트워크로 접속 중인 인터페이스(SSH, Telnet 경로)의 IP를 바꾸거나 `shutdown` 하면 접속이 끊겨 원격으로 복구하지 못한다. 반드시 콘솔 케이블로 접속해 작업한다.
{% endhint %}

## 4. 준비

| 번호 | 항목 | 확인 방법 |
|---|---|---|
| 1 | 콘솔로 라우터에 접속한다 | 프롬프트 `Router>`가 나타난다 |
| 2 | 설정할 주소를 정한다 | `192.168.10.254/24` (서브넷 마스크 `255.255.255.0`) |
| 3 | 같은 서브넷의 다른 장치가 `192.168.10.254`를 쓰지 않는지 확인한다 | 주소 충돌이 없다 |

## 5. 절차

### A. 라우터 설치

1. (5-A-01) 라우터를 설치 위치에 놓는다.
2. (5-A-02) 라우터의 `GigabitEthernet0/0` 포트와 스위치 포트를 케이블로 연결한다. → 결과: 케이블 양쪽 커넥터가 고정된다.
3. (5-A-03) 라우터 전원을 켠다. → 결과: 전원 표시등이 켜진다.
4. (5-A-04) 기본 연결 상태를 확인한다. → 결과: 포트 표시등이 켜진다.

### B. 라우터 확장 모듈 설치 (모듈이 필요할 때만)

{% hint style="danger" %}
WARNING: 모듈은 반드시 전원을 끈 상태에서 설치한다. 전원을 켠 채로 설치하면 장비가 손상될 수 있다.
{% endhint %}

1. (5-B-01) 라우터 전원을 끈다. → 결과: 모든 표시등이 꺼진다.
2. (5-B-02) 빈 슬롯에 모듈을 끝까지 밀어 넣는다. → 결과: 모듈이 고정된다.
3. (5-B-03) 라우터 전원을 켠다. → 결과: 전원 표시등이 켜진다.

### C. 게이트웨이 IP 설정

게이트웨이 IP 설정은 LAN에서 라우터를 거쳐 외부로 나가는 통로를 여는 단계다. 라우터는 스위치와 달리 연결만으로 외부와 통신하지 못한다.

1. (5-C-01) 관리자 모드로 들어간다: `enable` → 결과: 프롬프트가 `Router#`로 바뀐다.
2. (5-C-02) 설정 모드로 들어간다: `configure terminal` → 결과: 프롬프트가 `Router(config)#`로 바뀐다.
3. (5-C-03) 인터페이스를 선택한다: `interface GigabitEthernet0/0` → 결과: 프롬프트가 `Router(config-if)#`로 바뀐다.
4. (5-C-04) IP를 설정한다: `ip address 192.168.10.254 255.255.255.0` → 결과: 오류 메시지 없이 다음 프롬프트가 나온다.
5. (5-C-05) 인터페이스를 켠다: `no shutdown` → 결과: `changed state to up` 메시지가 나온다.
6. (5-C-06) 설정 모드를 나간다: `end`
7. (5-C-07) 설정을 저장한다: `copy running-config startup-config` → 결과: 저장 완료 메시지가 나온다.

{% hint style="info" %}
NOTE: 5-C-07의 저장 단계는 원본에 없던 내용이다. 저장하지 않으면 재부팅 후 설정이 사라진다. 일정 시간 뒤 연결된 포트의 표시등이 초록색으로 바뀌면 연결된 것이다.
{% endhint %}

### D. 호스트의 기본 게이트웨이 지정 (원본에 없던 단계)

1. (5-D-01) 확인용 PC의 IP를 `192.168.10.10`, 서브넷 마스크를 `255.255.255.0`으로 설정한다.
2. (5-D-02) 같은 PC의 기본 게이트웨이를 `192.168.10.254`로 설정한다. → 결과: 설정 화면에 값이 저장된다.

## 6. 기능 확인

| 번호 | 확인 동작 | 기대 결과 | 합격 기준 |
|---|---|---|---|
| 1 | 라우터에서 `show ip interface brief` 실행 | `GigabitEthernet0/0`의 주소가 `192.168.10.254`다 | Status `up`, Protocol `up` |
| 2 | 확인용 PC에서 `ping 192.168.10.254` | 응답이 온다 | 손실 0% |

## 7. 복구

1. (7-01) 설정 모드에서 인터페이스를 선택한다: `configure terminal`, `interface GigabitEthernet0/0`
2. (7-02) IP를 제거한다: `no ip address` → 결과: 인터페이스에 IP가 없다.
3. (7-03) 인터페이스를 끈다: `shutdown`
4. (7-04) 설정 모드를 나가 저장한다: `end`, `copy running-config startup-config`
