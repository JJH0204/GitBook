## 1. 목적

IPv4와 IPv6는 직접 통신할 수 없다. 전환 기간 동안 두 체계를 함께 쓰거나 변환하기 위한 방식이 필요하다.

## 2. 구성 요소

| 방식 | 핵심 | 설명 |
|---|---|---|
| 듀얼 스택 | 병행 | 장치가 IPv4와 IPv6 주소를 모두 가지고 상대가 쓰는 쪽으로 통신한다 |
| 터널링 | 캡슐화 | IPv6 패킷을 IPv4 패킷 안에 넣어 IPv4 망을 통과시킨다 |
| 변환(NAT64/DNS64) | 변환 | IPv6 전용 클라이언트가 IPv4 서버에 접근하도록 주소를 변환한다 |

## 3. 동작 원리

### 3.1 듀얼 스택

1. 장치가 두 주소를 모두 설정한다.
2. 이름 풀이 결과에 AAAA(IPv6)와 A(IPv4) 레코드가 모두 있으면 보통 IPv6를 먼저 시도한다.
3. 실패하면 IPv4로 시도한다.

### 3.2 터널링

1. 터널 시작점이 IPv6 패킷을 IPv4 헤더로 감싼다. 프로토콜 번호 41을 쓰는 방식이 대표적이다.
2. IPv4 망은 일반 IPv4 패킷으로 전달한다.
3. 터널 끝점이 IPv4 헤더를 벗겨 IPv6 패킷을 꺼낸다.

### 3.3 NAT64/DNS64

1. DNS64가 IPv4 서버 주소를 IPv6 형식 주소로 합성해 클라이언트에 알려 준다.
2. 클라이언트가 합성 주소로 보내면 NAT64 장비가 IPv4 패킷으로 바꿔 서버에 전달한다.
3. 응답은 반대 방향으로 변환한다.

{% hint style="info" %}
NOTE: 터널을 쓰면 헤더가 늘어 MTU가 줄어든다. 방화벽이 프로토콜 41을 막으면 터널이 동작하지 않는다.
{% endhint %}

## 4. 약어·용어

| 용어 | 뜻 |
|---|---|
| 듀얼 스택 | IPv4·IPv6 동시 운영 |
| AAAA 레코드 | 이름에 대응하는 IPv6 주소를 담는 DNS 레코드 |
| NAT64 | IPv6와 IPv4 사이 주소 변환 |
