# 서브넷팅 계산 (Subnetting)

## 작업 식별

| 항목 | 내용 |
|---|---|
| Task ID | NET-IPN-005-MP |
| 목적 | 필요한 호스트 수로 서브넷 마스크를 정하고, 각 서브넷의 네트워크 주소·브로드캐스트 주소·사용 가능 범위를 계산한다 |
| 적용 대상 | IPv4, 마스크 /24~/30 범위의 계산 |
| 소요 시간 | 약 15분 |
| 확인 상태 | 미검증 (예제 계산은 문서 작성 중 손으로 검산했으며 장비에서 확인하지 않았다) |
| 개정 | R1 (2026-11-18) |

{% hint style="info" %}
NOTE: 원본의 공식 설명을 정정했다. 원본은 "서브 네트워크의 수 = 2^n (n = 1 비트의 개수)"라 적었다. 서브넷 수는 기존 프리픽스에서 호스트 비트를 빌려 온 비트 수를 n으로 해 2^n이다. 호스트 수 공식은 2^h - 2 (h = 0 비트의 개수)로 같다.
{% endhint %}

{% endhint %}

## 4. 준비

| 번호 | 항목 | 확인 방법 |
|---|---|---|
| 1 | 나눌 네트워크를 정한다. 이 문서의 예는 `192.168.10.0/24`다 | 주소와 프리픽스를 적어 둔다 |
| 2 | 서브넷마다 필요한 장치 수를 정한다. 게이트웨이도 한 개로 센다 | 이 문서의 예는 50개다(단말 49대 + 게이트웨이 1개) |

## 5. 절차

### A. 필요한 호스트 수로 마스크 정하기

1. (5-A-01) 필요한 호스트 수 `N`을 적는다. → 결과: `N = 50`
2. (5-A-02) `2^h - 2 >= N`을 만족하는 가장 작은 `h`를 찾는다. `h = 5`이면 30이고 `h = 6`이면 62다. → 결과: `h = 6` (사용 가능 호스트 62개)
3. (5-A-03) 프리픽스 길이를 구한다: `32 - h`. → 결과: `32 - 6 = 26`, 즉 `/26`
4. (5-A-04) 마스크를 2진수로 쓴다. 앞 26비트가 1이다. → 결과: `11111111.11111111.11111111.11000000`
5. (5-A-05) 마지막 옥텟을 십진수로 바꾼다. `128 + 64 = 192`. → 결과: `255.255.255.192`
6. (5-A-06) 블록 크기를 구한다: `2^h`. → 결과: `2^6 = 64` (`256 - 192 = 64`와 같다)

참고 표(마지막 옥텟 기준):

| 프리픽스 | 마스크 | 블록 크기 | 사용 가능 호스트 수 |
|---|---|---|---|
| `/25` | `255.255.255.128` | 128 | 126 |
| `/26` | `255.255.255.192` | 64 | 62 |
| `/27` | `255.255.255.224` | 32 | 30 |
| `/28` | `255.255.255.240` | 16 | 14 |
| `/29` | `255.255.255.248` | 8 | 6 |
| `/30` | `255.255.255.252` | 4 | 2 |

### B. 서브넷 목록과 사용 가능 범위 계산하기

1. (5-B-01) 서브넷 수를 구한다: `2^(새 프리픽스 - 기존 프리픽스)`. → 결과: `2^(26 - 24) = 4`
2. (5-B-02) 첫 서브넷의 네트워크 주소를 적는다. 호스트 부분이 모두 0이다. → 결과: `192.168.10.0`
3. (5-B-03) 다음 서브넷의 네트워크 주소는 이전 주소에 블록 크기 64를 더한다. 같은 방법으로 4개를 적는다. → 결과: `.0`, `.64`, `.128`, `.192`
4. (5-B-04) 각 서브넷의 브로드캐스트 주소를 구한다: 다음 네트워크 주소 - 1. → 결과: `.63`, `.127`, `.191`, `.255`
5. (5-B-05) 사용 가능 범위를 구한다: 네트워크 주소 + 1 부터 브로드캐스트 주소 - 1 까지. → 결과: 아래 표

| 서브넷 | 네트워크 주소 | 사용 가능 범위 | 브로드캐스트 주소 |
|---|---|---|---|
| 1 | `192.168.10.0/26` | `192.168.10.1` ~ `192.168.10.62` | `192.168.10.63` |
| 2 | `192.168.10.64/26` | `192.168.10.65` ~ `192.168.10.126` | `192.168.10.127` |
| 3 | `192.168.10.128/26` | `192.168.10.129` ~ `192.168.10.190` | `192.168.10.191` |
| 4 | `192.168.10.192/26` | `192.168.10.193` ~ `192.168.10.254` | `192.168.10.255` |

{% hint style="danger" %}
WARNING: 네트워크 주소(호스트 부분이 모두 0)와 브로드캐스트 주소(호스트 부분이 모두 1)는 장치에 할당하지 않는다. 할당하면 그 장치는 통신하지 못하거나 다른 장치의 통신을 방해한다.
{% endhint %}

### C. 주어진 IP가 속한 네트워크 찾기 (AND 연산)

1. (5-C-01) IP 주소와 마스크의 마지막 옥텟을 2진수로 쓴다. 예: `192.168.10.100/26` → 결과: `100 = 01100100`, `192 = 11000000`
2. (5-C-02) 두 값을 비트별로 AND 한다. 둘 다 1인 자리만 1이다. → 결과: `01100100 AND 11000000 = 01000000`
3. (5-C-03) 결과를 십진수로 바꿔 네트워크 주소를 완성한다. → 결과: `01000000 = 64`, 네트워크 주소 `192.168.10.64`
4. (5-C-04) 호스트 비트를 모두 1로 바꿔 브로드캐스트 주소를 구한다. → 결과: `01111111 = 127`, 브로드캐스트 주소 `192.168.10.127`

같은 방법으로 비교한 원본 예(`/24`와 `/25`):

| IP | 마스크 | AND 결과 | 같은 네트워크 여부 |
|---|---|---|---|
| `192.168.100.100` | `255.255.255.0` | `192.168.100.0` | 아래 `.200`과 같은 네트워크다 |
| `192.168.100.200` | `255.255.255.0` | `192.168.100.0` | 위 `.100`과 같은 네트워크다 |
| `192.168.100.100` | `255.255.255.128` | `192.168.100.0` | 아래 `.200`과 다른 네트워크다 |
| `192.168.100.200` | `255.255.255.128` | `192.168.100.128` | 위 `.100`과 다른 네트워크다 |

`/25`에서 `.200`은 `200 = 11001000`이고 `11001000 AND 10000000 = 10000000 = 128`이다.

## 6. 기능 확인

| 번호 | 확인 동작 | 기대 결과 | 합격 기준 |
|---|---|---|---|
| 1 | 서브넷 수 × 블록 크기를 계산한다 | 기존 네트워크의 주소 수와 같다 | `4 × 64 = 256` |
| 2 | 각 서브넷의 사용 가능 호스트 수를 센다 | `62`다 | `.1`~`.62` 범위가 62개다 |
| 3 | 사용 가능 호스트 수와 `N`을 비교한다 | 호스트 수가 `N` 이상이다 | `62 >= 50` |
| 4 | 5-C의 결과를 5-B 표와 대조한다 | `.100`이 서브넷 2의 사용 가능 범위 안에 있다 | `.65` ~ `.126` 안이다 |

## 7. 복구

이 작업은 계산이며 장비 설정을 바꾸지 않는다. 복구 단계는 없다. 계산을 잘못했으면 5-A부터 다시 한다.
