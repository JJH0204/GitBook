## 1. 목적

"192.168.0.10은 정확히 무엇인가?"라는 질문에 답한다. 1일차에 IP 주소는 결국 2진수라고 배웠다. → [어디로 보낼까: IP 주소](../day-01/lesson-4.md)

오늘은 그 구조를 뜯어본다. 2진수 감각은 1일차 [Bit, Byte, 문자 코드](../day-01/lesson-3.md)에서 다진 것을 그대로 쓴다.

## 2. 구성 요소

### IPv4 주소의 구조

```
   192   .   168   .    0    .   10
11000000 . 10101000 . 00000000 . 00001010
```

| 번호 | 구성 요소 | 설명 |
|---|---|---|
| 1 | 전체 길이 | 32비트. 8비트씩 4덩어리(옥텟, octet)이다 |
| 2 | 옥텟 하나 | 8비트이며 0~255(2⁸ = 256가지)를 표현한다 |
| 3 | 표기 | 점(.)으로 구분해 사람이 읽기 쉽게 쓴다. 이를 점 10진법(dotted decimal)이라 한다 |
| 4 | 전체 주소 수 | 2³² 약 43억 개 |

{% hint style="info" %}
NOTE: 옥텟의 최댓값이 255인 이유는 8비트로 표현할 수 있는 가장 큰 값이 `11111111` = 255이기 때문이다. 1일차에 배운 비트 이야기 그대로다.
{% endhint %}

## 3. 동작 원리

### IPv4의 한계와 IPv6의 등장

1. 인터넷, 스마트폰, IoT 기기가 폭증해 43억 개로는 부족해졌다(주소 고갈).
2. 임시 처방으로 사설 IP와 NAT를 쓴다. → [공인 IP와 사설 IP](lesson-3.md)
3. 근본 해결책은 128비트 주소를 쓰는 IPv6다.

### 비교표

| 구분 | IPv4 | IPv6 |
|---|---|---|
| 길이 | 32비트 | 128비트 |
| 표기 | 점 10진법 `192.168.0.10` | 콜론 16진법 `2001:0db8:...:7334` |
| 주소 수 | 약 43억 | 사실상 무한(2¹²⁸) |
| 구분자 | 점(.) | 콜론(:) |

IPv6는 16진수를 쓴다. 1일차에서 16진수를 배운 이유다. → [Bit, Byte, 문자 코드](../day-01/lesson-3.md)

### IPv6 축약 규칙

128비트를 모두 쓰면 너무 길어서 줄여 쓰는 규칙이 있다. 위 비교표의 `...` 자리가 이 규칙이 적용된 부분이다.

```
원본             2001:0db8:0000:0000:0000:ff00:0042:8329
                 └─ 16비트(4자리) × 8묶음 = 128비트

① 각 묶음 앞의 0 떼기   2001:db8:0:0:0:ff00:42:8329
② 0만 연속된 구간 → ::  2001:db8::ff00:42:8329
```

- `::`는 한 주소에 한 번만 쓸 수 있다. 두 번 쓰면 어느 쪽이 몇 묶음인지 복원할 수 없기 때문이다.
- 실제로 보는 IPv6는 짧아 보이지만 속은 언제나 128비트다.

자주 마주치는 IPv6 주소는 다음과 같다.

| 주소 | 이름 | IPv4로 치면 |
|---|---|---|
| `::1` | 루프백(나 자신) | `127.0.0.1` |
| `fe80::`로 시작 | 링크 로컬(같은 망 안에서만) | `169.254.x.x` → [공인 IP와 사설 IP](lesson-3.md) |
| `::` | 미지정 | `0.0.0.0` |

{% hint style="info" %}
NOTE: `ipconfig` 출력에 `fe80::`로 시작하는 줄이 이미 보인다. IPv6는 이미 내 PC에 켜져 있다.
{% endhint %}

IPv6의 실제 사용과 설정은 8일차에서 다룬다. → [8일차 · 무선랜과 IPv6 맛보기](../day-08/lesson-5.md)

## 4. 연습 문제

1. 윈도우에서 `ipconfig`(또는 `ipconfig /all`)로 내 IPv4 주소와 IPv6 주소를 찾는다.
   - `fe80::`로 시작하는 줄을 찾아 "링크 로컬 IPv6"임을 짚는다.
2. `192.168.0.10`을 2진수로 바꾼다. 각 옥텟을 8비트로 쓴다.
3. 축약 연습: `2001:0db8:0000:0000:0011:0000:0000:0001`을 줄인다.
   - 답: `2001:db8::11:0:0:1`
   - 0 구간(3~4번째, 6~7번째 묶음)의 길이가 2로 같으면 앞쪽 구간에 `::`를 쓴다(RFC 5952의 표기 권고). `2001:db8:0:0:11::1`도 같은 주소이며 올바른 표기다.

## 5. 약어·용어

| 용어 | 뜻 |
|---|---|
| 옥텟(octet) | 8비트 묶음. IPv4 주소의 한 덩어리 |
| 점 10진법 | 옥텟을 10진수로 쓰고 점으로 구분하는 표기 |
| IPv4 / IPv6 | 32비트 / 128비트 인터넷 프로토콜 주소 체계 |
| 링크 로컬 | 같은 링크(망) 안에서만 유효한 주소 |

## 6. 강의 메모

- 옥텟 하나 = 8비트 = 0~255를 확실히 각인한다. 서브넷 마스크와 서브넷팅의 토대다.
- IPv6는 "존재와 이유"와 축약 읽는 법까지만 다룬다. 서브넷팅과 설정 상세는 7일차로 넘긴다.
- `::` 한 번 제한은 이유(복원 불가)와 함께 설명한다. 규칙 암기가 아니라 납득이 목표다.
