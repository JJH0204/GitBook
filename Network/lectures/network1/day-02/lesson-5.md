## Q1. 서브넷 마스크와 호스트 수 — [2_IP클래스와_서브넷마스크](lesson-2.md)

A subnet uses the mask **255.255.255.224**.
How many **usable host** addresses are available in each subnet?
(마스크가 255.255.255.224일 때, 서브넷당 사용 가능한 호스트는 몇 개인가?)

- A. 14
- B. 30
- C. 62
- D. 126

{% hint style="success" %}
**정답 및 해설**

**정답: B**
- `224` = `11100000` → 1이 3개 → 24 + 3 = **/27**
- 남은 호스트 비트 5개 → 2⁵ = 32개, 여기서 **네트워크 주소 + 브로드캐스트 2개를 빼면 30개**
- 오답도 같은 방식으로: A(14)=/28, C(62)=/26, D(126)=/25 → **표를 만들어 보여주면 한 번에 정리된다**
- 되짚기: 마스크에 나오는 8개 숫자(128·192·224·240·248·252) → [2_IP클래스와_서브넷마스크](lesson-2.md)
{% endhint %}

## Q2. 네트워크 주소 구하기 — [4_서브넷팅](lesson-4.md)

A host is configured with **172.16.5.4/20**.
What is the **network address** of this host?
(172.16.5.4/20 호스트가 속한 네트워크 주소는?)

- A. 172.16.0.0
- B. 172.16.4.0
- C. 172.16.5.0
- D. 172.16.16.0

{% hint style="success" %}
**정답 및 해설**

**정답: A**
- `/20` → 마스크 `255.255.240.0` → 경계는 **세 번째 옥텟**에 있다
- 블록 크기 = 256 − 240 = **16** → 세 번째 옥텟 경계: 0, 16, 32, 48 …
- `5`는 **0 ~ 15** 블록에 속한다 → 네트워크 주소 **172.16.0.0**, 브로드캐스트 **172.16.15.255**
- 흔한 실수: 마스크가 `/24`인 줄 알고 C(172.16.5.0)를 고르는 것 → **경계가 몇 번째 옥텟인지 먼저 확인**
- 되짚기: 손계산 4단계 → [4_서브넷팅](lesson-4.md)
{% endhint %}

## Q3. 같은 네트워크인가? — [4_서브넷팅](lesson-4.md)

PC1 = `192.168.1.10/26`, PC2 = `192.168.1.100/26`.
Both are connected to the **same switch**, and **no router** is configured.
What is the result of `ping` from PC1 to PC2?
(같은 스위치에 연결돼 있고 라우터는 없다. PC1에서 PC2로 ping하면?)

- A. 성공한다 — 같은 스위치에 있으므로
- B. 실패한다 — 서로 다른 서브넷이라 라우터가 필요하다
- C. 성공한다 — 스위치가 대신 라우팅해준다
- D. 실패한다 — IP 주소가 중복되었다

{% hint style="success" %}
**정답 및 해설**

**정답: B**
- 블록 크기 64 → 경계 0 / 64 / 128 / 192
- PC1(.10) → 네트워크 `192.168.1.0` · PC2(.100) → 네트워크 `192.168.1.64` → **다른 동네**
- 물리적으로 같은 스위치에 꽂혀 있어도, **논리적으로는 다른 네트워크**라 직접 통신 불가 → **라우터(기본 게이트웨이)** 필요
- C가 오답인 이유: 스위치는 2계층 장비라 **IP를 보고 동네를 넘겨주지 못한다** ([6_프로토콜_OSI7계층](../day-01/lesson-6.md))
- 핵심 한 줄: **IP만으로는 부족하다, IP + 마스크가 한 세트** → 3일차 ping 실습에서 직접 확인 → [3_ICMP와_ping](../day-03/lesson-3.md)
{% endhint %}

## Q4. 주소를 못 받은 PC — [3_공인IP와_사설IP](lesson-3.md)

A user reports no network access. `ipconfig` shows the address **169.254.12.33**.
What is the **most likely** cause?
(인터넷이 안 된다는 PC의 IP가 169.254.12.33이다. 가장 유력한 원인은?)

- A. 정상적인 사설 IP이므로 문제는 다른 곳에 있다
- B. DHCP 서버로부터 주소를 받지 못했다
- C. 공인 IP가 잘못 할당되었다
- D. 루프백 주소가 잘못 설정되었다

{% hint style="success" %}
**정답 및 해설**

**정답: B**
- `169.254.x.x` = **APIPA(링크로컬)** → "주소를 달라고 요청했는데 **응답이 없어서** 혼자 임시로 붙인 주소"
- 랜선 빠짐 / 공유기·DHCP 꺼짐 / 와이파이 연결 실패를 먼저 확인 → `ipconfig /release` → `ipconfig /renew`
- A가 오답인 이유: 사설 대역은 `10.x` · `172.16~31.x` · `192.168.x` **3개뿐**이고 `169.254`는 여기에 없다
- 되짚기: 특수 주소 표(`127.0.0.1` / `0.0.0.0` / `255.255.255.255` / `169.254.x.x`) → [3_공인IP와_사설IP](lesson-3.md)
{% endhint %}

## Q5. 필요한 만큼 나누기 — [4_서브넷팅](lesson-4.md)

A department needs **56 usable host addresses**.
What is the **smallest** subnet that satisfies this requirement?
(호스트 56대가 필요하다. 이를 만족하는 **가장 작은** 서브넷은?)

- A. /25
- B. /26
- C. /27
- D. /28

{% hint style="success" %}
**정답 및 해설**

**정답: B**
- 필요 56 → **+2**(네트워크·브로드캐스트) = **58 이상** 필요
- `/27` = 32개(사용 30) → **부족** / `/26` = 64개(사용 **62**) → 충분 → 정답
- `/25`(126개)도 되지만 **"가장 작은"** 조건에 어긋난다 → 주소 낭비
- 이 "필요 + 2 → 넉넉한 2의 거듭제곱" 절차가 **VLSM 설계의 전부**다 → [4_서브넷팅](lesson-4.md)
{% endhint %}
