## 1. 목적

한 동네가 너무 크면 생기는 문제를 풀기 위해 큰 네트워크를 작게 쪼갠다. 클래스 C 하나(`/24`)는 호스트가 254개다. 부서가 4개인 회사가 전부 한 네트워크에 있으면 다음 문제가 생긴다.

- 브로드캐스트가 254대 전체로 퍼져 성능이 떨어진다. → [캐스트: 유니, 브로드, 멀티](../day-01/lesson-7.md)의 브로드캐스트 도메인
- 부서 간 분리와 보안이 어렵다.

이렇게 큰 네트워크를 작게 쪼개는 것이 서브넷팅이다.

## 2. 구성 요소

### 서브넷팅의 이점

| 번호 | 이점 | 설명 |
|---|---|---|
| 1 | 브로드캐스트 도메인 축소 | 트래픽과 혼잡이 줄어든다 |
| 2 | 보안·관리 분리 | 부서·용도별로 나눈다 |
| 3 | 주소 낭비 감소 | 필요한 만큼만 배분한다 |

### 계산 공식

| 값 | 공식 |
|---|---|
| 서브넷 개수 | 2^(빌린 비트 수) |
| 서브넷당 전체 주소 | 2^(남은 호스트 비트 수) |
| 사용 가능 호스트 | 전체 − 2 (네트워크 주소와 브로드캐스트 주소는 예약) |

예: `/26`은 호스트 비트가 6개이므로 2⁶ = 64개, 사용 가능 호스트는 62개다.

## 3. 동작 원리

### 어떻게 나누나: 호스트 비트를 "빌린다"

서브넷 마스크를 오른쪽으로 늘려(호스트 비트를 네트워크 비트로 바꿔) 네트워크를 쪼갠다. `/24`에서 2비트를 빌리면 `/26`이 되고 서브넷은 2² = 4개가 된다.

### 손계산 4단계: 블록 크기(매직 넘버)

표를 외우지 말고 만들어 낸다. 순서는 어떤 문제든 같다.

```
① 마스크를 10진수로       /26  →  255.255.255.192
                          (자릿값 표: 11000000 = 128+64 = 192)

② 블록 크기 = 256 - 192 = 64      ← 이게 매직 넘버

③ 0부터 블록 크기씩 뛴다          0, 64, 128, 192
                                  = 각 서브넷의 네트워크 주소

④ 다음 네트워크 바로 앞 번호      63, 127, 191, 255
                                  = 각 서브넷의 브로드캐스트
```

{% hint style="info" %}
NOTE: "256 빼기 마스크" 한 줄만 기억하면 된다. `/28`은 256 − 240 = 16이므로 0, 16, 32, 48, 64 ... 이다. `/27`은 256 − 224 = 32이므로 0, 32, 64, 96 ... 이다.
{% endhint %}

- 네트워크 주소와 브로드캐스트 사이에 낀 번호들이 실제로 장비에 줄 수 있는 주소다.
- 마스크 값과 자릿값 표는 [IP 클래스와 서브넷 마스크](lesson-2.md)를 참고한다.

### 예제: `192.168.1.0/24`를 `/26`으로 나누기

위 4단계를 그대로 적용한 결과다(블록 크기 = 64).

| 서브넷 | 네트워크 주소 | 사용 가능 호스트 | 브로드캐스트 |
|---|---|---|---|
| 1 | 192.168.1.0/26 | .1 ~ .62 | .63 |
| 2 | 192.168.1.64/26 | .65 ~ .126 | .127 |
| 3 | 192.168.1.128/26 | .129 ~ .190 | .191 |
| 4 | 192.168.1.192/26 | .193 ~ .254 | .255 |

### 통신 가능 여부 판별: "둘이 서로 통신될까?"

서브넷팅이 숫자 놀이가 아닌 진짜 이유다. 나누는 순간 통신 가능 여부가 바뀐다.

질문: `192.168.1.10/26`과 `192.168.1.100/26`은 서로 ping이 될까?

판별법은 각자의 네트워크 주소를 구해서 비교하는 것이다. 블록 크기 64이므로 경계는 0, 64, 128, 192다.

| 호스트 | 속한 블록 | 네트워크 주소 |
|---|---|---|
| 192.168.1.10 | 0 ~ 63 | `192.168.1.0` |
| 192.168.1.100 | 64 ~ 127 | `192.168.1.64` |

- 네트워크 주소가 다르다. 서로 다른 동네이므로 직접 통신할 수 없다.
- 두 동네를 이어 줄 장치가 필요하다. 라우터이며, 각 PC 입장에서는 기본 게이트웨이다.
- 둘 다 `/24`였다면 네트워크 주소가 둘 다 `192.168.1.0`이다. 같은 동네이므로 스위치만으로 바로 통신된다.

{% hint style="info" %}
NOTE: 똑같은 IP 두 개인데 `/24`이면 통하고 `/26`이면 통하지 않는다. IP만 맞으면 되는 것이 아니라 IP와 서브넷 마스크가 한 세트여야 의미가 생긴다.
{% endhint %}

- 현장에서 "핑이 안 나가요"의 상당수가 마스크를 잘못 준 경우다. 나 혼자 다른 동네에 서 있는 셈이다.
- 이 판별은 3일차 ping 실습에서 눈으로 확인한다. → [ICMP와 ping](../day-03/lesson-3.md)

### VLSM

앞의 `/26` 4개는 똑같이 62개씩 자른 것이다. 현실에서는 부서마다 크기가 다르다.

질문: 영업 50대, 개발 20대, 총무 10대, 회의실 5대를 `192.168.1.0/24` 하나로 어떻게 나눌까?

균등하게 `/26` 4개로 자르면 영업(50대)은 맞지만 회의실도 62개를 받아 57개가 낭비된다. 필요한 만큼만 서로 다른 크기로 자르는 것이 VLSM(가변 길이 서브넷 마스크)이다.

규칙: 큰 것부터 순서대로 배정한다.

| 부서 | 필요 | +2 | 넉넉한 2의 거듭제곱 | 마스크 | 배정 대역 |
|---|---|---|---|---|---|
| 영업 | 50대 | 52 | 64 | /26 | `192.168.1.0` ~ `.63` |
| 개발 | 20대 | 22 | 32 | /27 | `192.168.1.64` ~ `.95` |
| 총무 | 10대 | 12 | 16 | /28 | `192.168.1.96` ~ `.111` |
| 회의실 | 5대 | 7 | 8 | /29 | `192.168.1.112` ~ `.119` |

- `+2`를 잊지 않는다. 네트워크 주소와 브로드캐스트는 쓸 수 없다. 50대이면 50짜리가 아니라 52 이상이 필요해서 64(/26)로 올라간다.
- 각 대역은 앞 대역이 끝난 바로 다음 번호에서 시작한다(0 → 64 → 96 → 112).
- 남은 `.120 ~ .255`는 여유분이다. 나중에 부서가 늘어도 대응할 수 있다.

큰 것부터 배정하는 이유: 블록은 자기 크기의 배수 자리에서만 시작할 수 있다. 작은 것부터 넣으면 중간에 어중간한 틈이 생겨 큰 블록이 들어갈 자리를 잃는다. 짐을 쌀 때 큰 짐부터 넣는 것과 같다.

실무 설계는 사실상 전부 VLSM이다. 자세한 설계는 라우팅과 함께 다룬다. → [5일차 · 라우팅 프로토콜](../day-05/README.md)

## 4. 연습 문제

### 연습 문제 1: 개수 세기

1. `192.168.10.0/24`를 `/28`로 나누면 서브넷 몇 개, 서브넷당 호스트 몇 개인가? 답: 16개 / 14개
2. `10.0.0.5/16`의 네트워크 주소와 브로드캐스트는? 답: 10.0.0.0 / 10.0.255.255

### 연습 문제 2: 블록 크기로 손계산

1. `192.168.1.0/27`의 블록 크기와 네트워크 주소들을 모두 적는다.
   - 답: 256−224 = 32 → 0, 32, 64, 96, 128, 160, 192, 224 → 8개 서브넷, 각 30호스트
2. `172.16.5.4/20`의 네트워크 주소와 브로드캐스트는?
   - 답: 마스크 255.255.240.0 → 블록 16 → 5는 0~15 블록 → `172.16.0.0` / `172.16.15.255`

### 연습 문제 3: 통신될까

1. `192.168.1.200/26`과 `192.168.1.130/26`은 서로 통신될까?
   - 답: 200은 192~255 블록, 130은 128~191 블록이다. 네트워크가 다르므로 직접 통신할 수 없다.
2. 위 두 IP를 그대로 두고 마스크만 `/24`로 바꾸면? 답: 둘 다 192.168.1.0이므로 통신할 수 있다.

### 연습 문제 4: VLSM 설계

`192.168.5.0/24`를 A 100대, B 50대, C 25대, D 10대에 나눠 배정한다.

- 답: A `/25` = .0~.127 / B `/26` = .128~.191 / C `/27` = .192~.223 / D `/28` = .224~.239, 여유 .240~.255

## 5. 약어·용어

| 용어 | 뜻 |
|---|---|
| 서브넷팅 | 큰 네트워크를 여러 작은 네트워크로 나누는 일 |
| 블록 크기(매직 넘버) | 256 − 마스크의 해당 옥텟 값. 서브넷 네트워크 주소의 간격 |
| 브로드캐스트 주소 | 서브넷의 마지막 주소. 그 서브넷 전체에게 보낸다 |
| VLSM | Variable Length Subnet Mask. 서브넷마다 마스크 길이를 달리하는 방식 |
| 브로드캐스트 도메인 | 브로드캐스트가 도달하는 범위 |

## 6. 강의 메모

- "호스트 비트를 빌려 네트워크를 늘린다"를 그림으로 반복한다.
- 블록 크기 = 256 − 마스크를 주문처럼 반복시키고, 예제마다 ①~④ 4단계를 소리 내어 밟게 한다.
- 표를 먼저 보여 주지 않는다. 4단계로 학생이 표를 만들게 한 뒤 답을 공개한다.
- "통신될까?" 문제는 매번 네트워크 주소부터 구하는 습관으로 유도한다(감으로 찍지 않게).
- VLSM은 개념과 순서(큰 것부터, +2)까지만 다룬다. 학생이 지치면 연습 문제 4는 과제로 돌려도 된다.
- 손계산 후 `subnet_calc.py`로 즉시 채점하는 흐름이 이해에 효과적이다.
- 다음 시간(3일차): 이렇게 나눈 네트워크를 실제 장비로 연결하고, 오늘의 "통신될까?"를 ping으로 확인한다. → [3일차 · 네트워크 장비와 네트워크 토폴로지](../day-03/README.md)
