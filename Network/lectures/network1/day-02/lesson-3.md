## 📖 공인 IP vs 사설 IP

| 구분 | 공인 IP (Public) | 사설 IP (Private) |
|------|------------------|-------------------|
| 범위 | 인터넷 전체에서 **유일** | 내부망 안에서만 유일 |
| 할당 | 통신사(ISP) | 공유기·관리자가 자유롭게 |
| 접근 | 인터넷에서 직접 도달 | 내부에서만, 외부 직접 접근 불가 |
| 예 | `211.45.x.x` | `192.168.0.10` |

## 📖 사설 IP 대역 (외워둘 것)

| 클래스 | 사설 대역 |
|--------|-----------|
| A | `10.0.0.0` ~ `10.255.255.255` (10.0.0.0/8) |
| B | `172.16.0.0` ~ `172.31.255.255` (172.16.0.0/12) |
| C | `192.168.0.0` ~ `192.168.255.255` (192.168.0.0/16) |

- 집 공유기가 보통 `192.168.0.x` 또는 `192.168.1.x`를 쓰는 이유가 이것!

## 📖 그럼 어떻게 인터넷에 나가지? → NAT (맛보기)

- 사설 IP는 인터넷에 직접 못 나감 → 공유기가 나갈 때 **공인 IP로 바꿔줌** = **NAT(Network Address Translation)**
- 덕분에 집 안 여러 기기가 **공인 IP 하나를 공유**해서 인터넷 사용 → 주소 절약(IPv4 고갈 대응, [1_IP주소체계_IPv4와IPv6](lesson-1.md))

> 💡 비유: **회사 대표번호(공인) + 내선번호(사설)**. 외부에서는 대표번호로 걸고, 내부에서 내선으로 연결. 나갈 땐 대표번호로 표시.

- NAT의 실제 설정·동작은 서버 파트에서 → [10일차 · 서버 기초](../../network2/day-10/README.md)

## 📖 내 PC 설정 3종 세트 — IP · 마스크 · 게이트웨이

`ipconfig`를 치면 항상 **세 줄이 같이** 나온다. 따로 노는 게 아니라 한 세트다.

| 항목 | 예 | 역할 (한 줄) | 잘못되면 |
|------|-----|------------|----------|
| **IPv4 주소** | `192.168.0.10` | 나는 누구인가 | 통신 자체가 안 됨 |
| **서브넷 마스크** | `255.255.255.0` | 내 동네의 경계는 어디까지인가 | 같은 동네인지 **판단을 틀림** |
| **기본 게이트웨이** | `192.168.0.1` | 동네 **밖으로 나가는 출구** | 내부는 되는데 **인터넷만 안 됨** |

- 데이터를 보낼 때 PC는 매번 판단한다: 목적지가 **같은 동네면 직접**, **다른 동네면 일단 게이트웨이에게** 넘긴다
  - 이 "같은 동네인가?" 판단이 바로 [4_서브넷팅](lesson-4.md)의 판별법 — 그래서 마스크가 중요하다
- 집에서 **게이트웨이 = 공유기** = 방금 배운 NAT를 하는 그 장비 = 우리 집 대문
- 그래서 게이트웨이는 보통 그 대역의 **첫 번째 주소**(`.1`)를 쓴다 (관례)

> 💡 비유: **아파트 정문 경비실.** 같은 동 사람에게는 직접 걸어가고, 단지 **밖으로** 나갈 땐 반드시 정문을 지난다. 정문이 막히면 단지 안은 멀쩡한데 외출만 불가능하다.

**증상으로 원인 좁히기** (실습 때 계속 쓸 것)

| 증상 | 의심 |
|------|------|
| 아무것도 안 됨 | IP·마스크 |
| 옆자리 PC는 되는데 인터넷만 안 됨 | **게이트웨이** |
| IP는 되는데 주소창 이름이 안 열림 | DNS (8일차) |

## 📖 알아두면 좋은 특수 주소

| 주소 | 이름 | 뜻 |
|------|------|-----|
| `127.0.0.1` | 루프백 | **나 자신** (localhost) — 랜선 없어도 동작 |
| `0.0.0.0` | 미지정 | "아직 주소 없음" |
| `255.255.255.255` | 제한 브로드캐스트 | 같은 네트워크 **전체**에게 ([7_캐스트_유니_브로드_멀티](../day-01/lesson-7.md)) |
| `169.254.x.x` | **APIPA**(링크로컬) | IP를 **못 받았을 때** 자동으로 붙는 주소 |

### ⚠️ `169.254.x.x` 가 보이면 = 고장 신호

실습 중에 **가장 자주 만나게 될** 주소다. 미리 알아두면 당황하지 않는다.

- **뜻**: "IP를 주는 장비한테 요청했는데 **아무 대답이 없어서**, 어쩔 수 없이 혼자 임시 주소를 붙였다"
- **증상**: 인터넷은 물론 옆자리 PC ping도 안 됨 (나 혼자 엉뚱한 동네에 서 있는 셈)
- **원인**: 랜선 빠짐 / 공유기·DHCP 꺼짐 / 와이파이 연결 실패
- **조치**: 연결 확인 후 아래 실행

```bash
ipconfig /release
ipconfig /renew
```

> 💡 "IP가 169로 시작한다 = 아무한테서도 주소를 못 받았다"만 기억하면 절반은 해결이다.

## 🗣️ 그런데 내 IP는 누가 정해준 거지?

- 직접 입력한 적이 없는데 `192.168.0.10`이 붙어 있다 → 누군가 **자동으로 나눠준 것**
- 그 역할을 하는 게 **DHCP**(Dynamic Host Configuration Protocol) — 집에서는 보통 **공유기가 겸한다**
- DHCP는 IP만 주는 게 아니라 위의 **3종 세트 + DNS까지 한 번에** 내려준다

| 방식 | 누가 정하나 | 쓰는 곳 |
|------|-----------|---------|
| **고정 IP** | 사람이 직접 입력 | 서버·프린터·네트워크 장비 (주소가 변하면 안 되는 것) |
| **유동 IP** | DHCP가 자동 배정 | 일반 PC·스마트폰 |

- DHCP 서버를 **직접 구축**하는 건 8일차 → [2_DHCP와_DNS](../day-08/lesson-2.md)

## 🧪 실습 / 질문

- 내 **사설 IP** 확인: `ipconfig` → `192.168.x.x`
- 내 **공인 IP** 확인: 브라우저에서 "내 아이피 확인" 검색 → 둘이 다름을 확인!
- 카페 와이파이와 집 와이파이의 사설 IP가 겹쳐도 되는 이유는? (내부망끼리는 서로 몰라도 됨)
- **3종 세트 읽기**: `ipconfig` 화면에서 IPv4 주소 / 서브넷 마스크 / 기본 게이트웨이 세 줄을 짚어본다
  - 내 게이트웨이 주소가 `.1`로 끝나는지 확인 → 옆 사람과 비교
  - `ping <내 게이트웨이>` 를 해보자 → 응답이 오면 "대문까지는 정상"
- **루프백 확인**: `ping 127.0.0.1` → 랜선을 뽑고 해도 되는 이유는? (내 안에서만 도는 주소니까)
- 질문: 게이트웨이 주소를 일부러 `192.168.0.99`(없는 주소)로 바꾸면 어떻게 될까?
  - (답: 같은 동네 PC끼리는 되는데 **인터넷만** 안 된다)

## 📝 강의 메모

- "사설 = 우리 집 안 규칙, 공인 = 세상에 하나뿐" 대비로 각인
- NAT는 개념만, 상세는 서버 파트로 위임
- **게이트웨이는 반드시 4번 노트 판별법과 묶어서** 설명 — "같은 동네면 직접, 아니면 대문" 한 문장
- `169.254`는 실습 사고 대비용으로 **미리** 심어두기 → 3일차 PT 실습에서 반드시 나온다
- DHCP는 "내 IP는 누가 줬나?" 질문 회수까지만, 구축은 8일차로 위임
