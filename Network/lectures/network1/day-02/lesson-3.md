- 공인 IP와 사설 IP의 차이를 이해한다.
- 사설 IP 대역을 안다.
- 집 공유기의 `192.168.x.x`가 왜 그런지, NAT의 개념을 맛본다.
- IP, 마스크, 게이트웨이 3종 세트를 `ipconfig`에서 읽는다.
- `169.254.x.x` 등 특수 주소를 알아보고, 내 IP를 누가 주는지(DHCP) 이해한다.

## 1. 목적

"내 IP가 두 개로 보이는 이유"에 답한다. 1일차 실습에서 "집에서 보는 IP(192.168.x.x)와 인터넷에 보이는 IP가 다르다"는 질문을 남겼다. → [어디로 보낼까: IP 주소](../day-01/lesson-4.md)

그 이유는 주소가 공인 IP와 사설 IP로 나뉘어 있기 때문이다.

## 2. 구성 요소

### 공인 IP와 사설 IP

| 구분 | 공인 IP (Public) | 사설 IP (Private) |
|---|---|---|
| 범위 | 인터넷 전체에서 유일하다 | 내부망 안에서만 유일하다 |
| 할당 | 통신사(ISP) | 공유기·관리자가 자유롭게 정한다 |
| 접근 | 인터넷에서 직접 도달한다 | 내부에서만 쓰며 외부에서 직접 접근할 수 없다 |
| 예 | `203.0.113.25`(문서용 예제 주소) | `192.168.0.10` |

### 사설 IP 대역 (외워 둘 것)

| 클래스 | 사설 대역 |
|---|---|
| A | `10.0.0.0` ~ `10.255.255.255` (10.0.0.0/8) |
| B | `172.16.0.0` ~ `172.31.255.255` (172.16.0.0/12) |
| C | `192.168.0.0` ~ `192.168.255.255` (192.168.0.0/16) |

집 공유기가 보통 `192.168.0.x` 또는 `192.168.1.x`를 쓰는 이유가 이것이다.

### 내 PC 설정 3종 세트: IP, 마스크, 게이트웨이

`ipconfig`를 입력하면 항상 세 줄이 같이 나온다. 따로 노는 값이 아니라 한 세트다.

| 항목 | 예 | 역할 | 잘못되면 |
|---|---|---|---|
| IPv4 주소 | `192.168.0.10` | 나는 누구인가 | 통신 자체가 안 된다 |
| 서브넷 마스크 | `255.255.255.0` | 내 동네의 경계는 어디까지인가 | 같은 동네인지 판단을 틀린다 |
| 기본 게이트웨이 | `192.168.0.1` | 동네 밖으로 나가는 출구 | 내부는 되는데 인터넷만 안 된다 |

증상으로 원인을 좁히는 표다. 실습에서 계속 쓴다.

| 증상 | 의심 |
|---|---|
| 아무것도 안 된다 | IP, 마스크 |
| 옆자리 PC는 되는데 인터넷만 안 된다 | 게이트웨이 |
| IP는 되는데 주소창 이름이 안 열린다 | DNS (8일차) |

### 특수 주소

| 주소 | 이름 | 뜻 |
|---|---|---|
| `127.0.0.1` | 루프백 | 나 자신(localhost). 랜선이 없어도 동작한다 |
| `0.0.0.0` | 미지정 | 아직 주소가 없다는 뜻 |
| `255.255.255.255` | 제한 브로드캐스트 | 같은 네트워크 전체에게 보낸다 → [캐스트: 유니, 브로드, 멀티](../day-01/lesson-7.md) |
| `169.254.x.x` | APIPA(링크 로컬) | IP를 받지 못했을 때 자동으로 붙는 주소 |

### 고정 IP와 유동 IP

| 방식 | 누가 정하나 | 쓰는 곳 |
|---|---|---|
| 고정 IP | 사람이 직접 입력한다 | 서버, 프린터, 네트워크 장비(주소가 변하면 안 되는 것) |
| 유동 IP | DHCP가 자동 배정한다 | 일반 PC, 스마트폰 |

## 3. 동작 원리

### NAT (맛보기)

- 사설 IP는 인터넷에 직접 나갈 수 없다. 공유기가 나갈 때 공인 IP로 바꿔 준다. 이것이 NAT(Network Address Translation)다.
- 덕분에 집 안 여러 기기가 공인 IP 하나를 공유해 인터넷을 쓴다. 주소가 절약된다(IPv4 고갈 대응, [IP 주소 체계](lesson-1.md)).

비유: 회사 대표번호(공인)와 내선번호(사설). 외부에서는 대표번호로 걸고, 내부에서는 내선으로 연결한다. 나갈 때는 대표번호로 표시된다.

NAT의 실제 설정과 동작은 서버 파트에서 다룬다. → [10일차 · 서버 기초](../../network2/day-10/README.md)

### 3종 세트가 통신을 결정하는 방식

- PC는 데이터를 보낼 때마다 판단한다. 목적지가 같은 동네이면 직접 보내고, 다른 동네이면 일단 게이트웨이에게 넘긴다.
- 이 "같은 동네인가?" 판단이 [서브넷팅](lesson-4.md)의 판별법이다. 그래서 마스크가 중요하다.
- 집에서 게이트웨이는 공유기이며, 방금 배운 NAT를 하는 그 장비다. 우리 집 대문에 해당한다.
- 게이트웨이는 관례상 그 대역의 첫 번째 주소(`.1`)를 쓴다.

비유: 아파트 정문 경비실. 같은 동 사람에게는 직접 걸어가고, 단지 밖으로 나갈 때는 반드시 정문을 지난다. 정문이 막히면 단지 안은 멀쩡한데 외출만 불가능하다.

### `169.254.x.x`가 보이면 고장 신호

실습 중에 가장 자주 만나게 될 주소다. 미리 알아 두면 당황하지 않는다.

| 항목 | 내용 |
|---|---|
| 뜻 | IP를 주는 장비에 요청했는데 대답이 없어서 혼자 임시 주소를 붙였다 |
| 증상 | 인터넷은 물론 옆자리 PC에 ping도 안 된다(혼자 엉뚱한 동네에 서 있는 셈이다) |
| 원인 | 랜선 빠짐, 공유기·DHCP 꺼짐, 와이파이 연결 실패 |
| 조치 | 연결을 확인한 뒤 아래 명령을 실행한다 |

```bash
ipconfig /release
ipconfig /renew
```

{% hint style="info" %}
NOTE: "IP가 169로 시작한다 = 아무한테서도 주소를 받지 못했다"만 기억하면 절반은 해결이다.
{% endhint %}

### DHCP: 내 IP는 누가 정해 주었나

- 직접 입력한 적이 없는데 `192.168.0.10`이 붙어 있다면 누군가 자동으로 나눠 준 것이다.
- 그 역할을 하는 것이 DHCP(Dynamic Host Configuration Protocol)이며, 집에서는 보통 공유기가 겸한다.
- DHCP는 IP만 주지 않는다. 위의 3종 세트와 DNS까지 한 번에 내려 준다.

DHCP 서버를 직접 구축하는 것은 8일차에서 다룬다. → [DHCP와 DNS](../day-08/lesson-2.md)

## 4. 연습 문제

1. 카페 와이파이와 집 와이파이의 사설 IP가 겹쳐도 되는 이유는? 답: 내부망끼리는 서로 알 필요가 없기 때문이다.
2. `ping 127.0.0.1`은 랜선을 뽑고 해도 되는 이유는? 답: 내 안에서만 도는 주소이기 때문이다.
3. 게이트웨이 주소를 일부러 `192.168.0.99`(없는 주소)로 바꾸면 어떻게 될까? 답: 같은 동네 PC끼리는 되는데 인터넷만 안 된다.

## 5. 약어·용어

| 용어 | 뜻 |
|---|---|
| 공인 IP / 사설 IP | 인터넷에서 유일한 주소 / 내부망에서만 쓰는 주소 |
| NAT | Network Address Translation. 사설 주소와 공인 주소를 바꿔 주는 기능 |
| 기본 게이트웨이 | 다른 네트워크로 나가는 출구 장비의 주소 |
| APIPA | Automatic Private IP Addressing. DHCP 실패 시 `169.254.0.0/16`에서 자동으로 정하는 주소 |
| DHCP | Dynamic Host Configuration Protocol. 주소와 설정을 자동 할당하는 프로토콜 |
| 루프백 | 자기 자신을 가리키는 주소(`127.0.0.1`) |

## 6. 강의 메모

- "사설 = 우리 집 안 규칙, 공인 = 세상에 하나뿐"의 대비로 각인시킨다.
- NAT는 개념만 다루고 상세는 서버 파트로 넘긴다.
- 게이트웨이는 반드시 4번 노트의 판별법과 묶어서 설명한다. "같은 동네면 직접, 아니면 대문" 한 문장이다.
- `169.254`는 실습 사고에 대비해 미리 심어 둔다. 3일차 패킷 트레이서 실습에서 반드시 나온다.
- DHCP는 "내 IP는 누가 줬나?" 질문을 회수하는 데까지만 다루고, 구축은 8일차로 넘긴다.
