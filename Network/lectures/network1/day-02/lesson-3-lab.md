## 4. 준비

| 번호 | 항목 | 확인 방법 |
|---|---|---|
| 1 | 터미널을 연다 | 프롬프트가 나타난다 |

## 5. 절차

### A. 사설 IP와 3종 세트 확인

1. (5-A-01) 터미널에서 `ipconfig`를 입력한다. → 결과: 어댑터별 설정이 출력된다.
2. (5-A-02) 사용 중인 어댑터에서 `IPv4 주소`를 찾는다. → 결과: `192.168.x.x`, `10.x.x.x`, `172.16~31.x.x` 중 하나가 보인다.
3. (5-A-03) 같은 어댑터에서 `서브넷 마스크`를 찾는다. → 결과: 예) `255.255.255.0`
4. (5-A-04) 같은 어댑터에서 `기본 게이트웨이`를 찾는다. → 결과: 예) `192.168.0.1`
5. (5-A-05) 게이트웨이 주소가 `.1`로 끝나는지 확인하고 옆 사람과 비교한다. → 결과: 같은 공유기이면 게이트웨이가 같다.

### B. 공인 IP 확인

1. (5-B-01) 브라우저에서 "내 아이피 확인"을 검색해 결과 페이지를 연다.
2. (5-B-02) 표시된 IP를 5-A-02의 사설 IP와 비교한다. → 결과: 두 주소가 다르다.

### C. 게이트웨이와 루프백 ping

1. (5-C-01) 터미널에서 `ping <5-A-04의 기본 게이트웨이>`를 입력한다. → 결과: `Reply from <게이트웨이>` 응답이 온다. 응답이 오면 "대문까지는 정상"이다.
2. (5-C-02) 터미널에서 `ping 127.0.0.1`을 입력한다. → 결과: `Reply from 127.0.0.1` 응답이 온다.
3. (5-C-03) 랜선을 뽑거나 와이파이를 끈 뒤 5-C-02를 다시 실행한다. → 결과: 여전히 응답이 온다. 루프백은 자기 안에서만 도는 주소이기 때문이다.
4. (5-C-04) 랜선을 다시 꽂거나 와이파이를 켠다. → 결과: 5-C-01의 ping이 다시 성공한다.

## 6. 기능 확인

| 번호 | 확인 동작 | 기대 결과 | 합격 기준 |
|---|---|---|---|
| 1 | 5-A-02의 IPv4 주소가 사설 대역인지 확인 | 사설 대역에 속한다 | `10.`, `172.16~31.`, `192.168.` 중 하나로 시작 |
| 2 | 5-B-02의 공인 IP와 사설 IP 비교 | 두 주소가 다르다 | 서로 다름 |
| 3 | `ping <기본 게이트웨이>` | 응답이 온다 | 손실 0% |
| 4 | `ping 127.0.0.1` | 응답이 온다 | 손실 0% |

IPv4 주소가 `169.254.x.x`이면 DHCP 응답을 받지 못한 상태다. 연결(랜선, 공유기, 와이파이)을 확인한 뒤 `ipconfig /release`, `ipconfig /renew`를 차례로 실행하고 5-A를 다시 수행한다.

## 7. 복구

이 실습은 설정을 바꾸지 않으므로 별도 복구 절차가 없다. 5-C-03에서 끈 연결은 5-C-04로 되돌린다.
