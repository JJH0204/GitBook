## 🎯 학습 목표

- 새 파일에 **RIP 구역과 OSPF 구역이 섞인 망**을 구성한다
- 재분배 **전에 왜 안 되는지**를 라우팅 테이블로 확인한다
- 경계 라우터 한 대에서 **양방향 재분배**를 설정한다
- **seed metric 이 없으면 왜 실패하는지**를 직접 겪는다
- 재분배된 **external 경로(`O E2`)** 를 읽는다

## 🌉 다리 놓기: "통역을 직접 걸어보자"

원리([2_재분배_원리와_주의점](lesson-2.md))를 배웠으니, 이제 RIP 구역과 OSPF 구역을
**경계 라우터에서** 이어본다.

> 📌 **오늘도 새 파일에 처음부터 만든다.** 5일차 파일을 고쳐 쓰지 않는다.
> 그림과 주소는 5일차와 **완전히 같다** — 세 번째라 손이 기억하고 있을 것이다.
> 바뀌는 건 **어느 구간이 무슨 말을 쓰는가** 뿐이다.

## 🗺 오늘의 토폴로지 — 5일차와 같은 그림, 언어만 둘로

```
      ◀────── RIP 구역 ──────▶   ◀───── OSPF 구역 ─────▶
[PC0]──[SW1]──[R1]══════[R2]══════[R3]──[SW2]──[PC2]
 .10.1        20.0/24    ▲   50.0/24        .30.1
                         │
                  RIP + OSPF 를 둘 다 도는 라우터
                  = 통역사 = ASBR = 오늘의 주인공
```

| 장비 | 도는 프로토콜 | 오늘 설정하는가 |
|------|---------------|------------------|
| R1 | RIP 만 | 구역 나눌 때만 |
| **R2** ⭐ | **RIP + OSPF** | **재분배는 전부 여기서** |
| R3 | OSPF 만 | 구역 나눌 때만 |

| 장비 | G0/0 | G0/1 |
|------|------|------|
| R1 | 192.168.10.254 | 192.168.20.1 |
| R2 | 192.168.50.1 | 192.168.20.2 |
| R3 | 192.168.30.254 | 192.168.50.2 |

## 🧪 ① 구역 나누기 — 무대 만들기

인터페이스 설정이 끝난 상태에서, **어느 구간이 무슨 말을 쓸지** 정해준다.

| 장비 | 하는 일 |
|------|---------|
| R1 | 자기 네트워크 둘(10.0 · 20.0)을 **RIP** 으로 |
| R3 | 자기 네트워크 둘(50.0 · 30.0)을 **OSPF** 로 |
| **R2** | **왼쪽(20.0)은 RIP, 오른쪽(50.0)은 OSPF** |

**🔎 봐야 할 것 — `show ip protocols`**

| 장비 | 나와야 할 것 |
|------|--------------|
| R1 | `rip` 만 |
| **R2** | **`rip` 과 `ospf` 둘 다** ⭐ |
| R3 | `ospf` 만 |

**🔎 R2 의 라우팅 테이블 — 오늘의 핵심 장면**

```
R    192.168.10.0/24 [120/1] via 192.168.20.1     ← RIP 으로 배웠다
C    192.168.20.0/24 is directly connected
C    192.168.50.0/24 is directly connected
O    192.168.30.0/24 [110/2] via 192.168.50.2     ← OSPF 로 배웠다
```

> 🗣 **"R2 한 대에 `R` 과 `O` 가 같이 있죠? 이 라우터가 오늘의 통역사입니다."**

---

## 🧪 ② 재분배 **전** — 왜 안 되는지 먼저 본다

케이블도 다 붙었고 라우터도 다 살아 있다. **그런데 PC0 → PC2 ping 이 실패한다.**

**🔎 세 라우터의 테이블을 나란히 비교**

| 장비 | 10.0 | 20.0 | 50.0 | 30.0 |
|------|:----:|:----:|:----:|:----:|
| R1 | ✅ C | ✅ C | ❌ | ❌ |
| **R2** | ✅ R | ✅ C | ✅ C | ✅ O |
| R3 | ❌ | ❌ | ✅ C | ✅ C |

**🗣 물어볼 것 — 오늘 수업의 핵심 질문**

- "가운데 R2 는 다 아는데 왜 통신이 안 될까요?"
  → **혼자만 알고 있다.** 왼쪽 소식을 오른쪽에 **옮겨주지 않는다**
- "한 장비 안에 RIP 과 OSPF 가 같이 있는데, 서로 대화하지 않나요?"
  → **하지 않는다.** 프로세스는 각자 자기 언어권하고만 → [1_재분배란_무엇인가](lesson-1.md)

> 💡 이 실패를 **꼭 먼저 보여준다.** 성공부터 보면 재분배가 왜 필요한지 안 와닿는다.

---

## 🧪 ③ 양방향 재분배 ⭐ 오늘의 핵심

> **모든 명령은 R2 한 대에서만.** R1·R3 는 끝까지 손대지 않는다.

### RIP → OSPF (먼저 한 방향만)

```bash
router ospf 1
 redistribute rip subnets metric 20
```

**🔎 R3 에서 확인**

```
O E2 192.168.10.0/24 [110/20] via 192.168.50.1, 00:00:09, GigabitEthernet0/1
──┬─                  ─┬─
  External             재분배할 때 준 seed metric 20 이 그대로
```

- 🗣 **"`O` 뒤에 `E` 가 왜 붙었을까요?"** → **밖에서 온 경로**라는 표식

### OSPF → RIP — **일부러 틀리게 먼저** ⭐ 오늘의 명장면

```bash
router rip
 redistribute ospf 1              ← metric 을 일부러 안 준다
```

⏳ 30초를 기다려도 **R1 에는 아무것도 생기지 않는다.**

- 🗣 **"명령은 분명히 쳤는데 왜 안 올까요?"**
  → RIP 은 **홉 수로 말한다.** 몇 홉인지 안 알려줬다 → **무한대(∞) 취급 → 광고 안 함**
  → [2_재분배_원리와_주의점](lesson-2.md)

### seed metric 을 준다 — 한 단어 차이

```bash
router rip
 redistribute ospf 1 metric 3
```

**🔎 R1 에서 확인 (⏳ 30초)**

```
R    192.168.30.0/24 [120/3] via 192.168.20.2
R    192.168.50.0/24 [120/3] via 192.168.20.2
```

- 🗣 **"이 `3` 은 실제 거리일까요?"** → **아니다. 우리가 정해준 값**
- 🗣 **"30.0 과 50.0 은 실제 거리가 다른데 왜 똑같이 3일까요?"**
  → **원래 메트릭 정보가 사라졌다** = **차선 경로**의 근본 원인 ([2_재분배_원리와_주의점](lesson-2.md))

### 최종 확인

PC0 → `ping 192.168.30.1` **성공** · `tracert` 로 R1 → R2 → R3 경유 확인

**✅ 체크** — R1·R3 에는 **재분배 설정을 하지 않았다.** 통역은 R2 한 대에서만.

## 🧪 ④ `E1` vs `E2` · `default-metric` (여유 있으면)

`metric-type 1` 을 붙여 **표시와 숫자가 둘 다 바뀌는 것**을 확인한다.

| | 표시 | 코스트 |
|---|---|---|
| 기본 | `O E2` | **[110/20]** — 어디서 보든 **항상 20** |
| `metric-type 1` | `O E1` | **[110/21…]** — 20 + **여기까지 오는 내부 비용** |

> 💡 **E2 = 준 값 그대로 / E1 = 준 값 + 오는 길 비용.**
> 통역사가 여럿이면 **가까운 통역사를 골라야** 하니 E1 이 유리하다. 기본값은 **E2**.

마지막으로 `default-metric` 으로 설정을 정리하고, 되돌린 뒤에도 **ping 이 여전히 성공**하는지 확인한다.

## ⚠️ 실습 중 막히면 — 오늘판 5대 원인

| 증상 | 원인 |
|------|------|
| 재분배했는데 경로가 안 온다 (RIP 쪽) | **`metric` 을 안 줬다** (1위) |
| ⏳ 아무 변화가 없다 | RIP 은 **30초** — 한 번 더 `show ip route` |
| 한쪽 방향만 된다 | **재분배도 왕복.** 두 방향을 각각 설정했나 |
| `redistribute` 가 안 먹는다 | **받는 프로세스** 안에서 쳤나 → 부록 C 공식 |
| R2 만 잘 된다 | 정상. **재분배 전** 상태다 |
