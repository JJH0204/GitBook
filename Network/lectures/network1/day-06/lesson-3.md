## 학습 목표

- 새 파일에 RIP 구역과 OSPF 구역이 섞인 망을 구성한다.
- 재분배 전에 왜 안 되는지를 라우팅 테이블로 확인한다.
- 경계 라우터 한 대에서 양방향 재분배를 설정한다.
- seed metric이 없으면 왜 실패하는지를 직접 겪는다.
- 재분배된 external 경로(`O E2`)를 읽는다.

## 2. 필요 장비와 자재

오늘의 무대는 5일차와 같은 그림이며 어느 구간이 무슨 프로토콜을 쓰는지만 다르다.

```
      ◀────── RIP 구역 ──────▶   ◀───── OSPF 구역 ─────▶
[PC0]──[SW1]──[R1]══════[R2]══════[R3]──[SW2]──[PC2]
 .10.1        20.0/24    ▲   50.0/24        .30.1
                         │
                  RIP + OSPF 를 둘 다 도는 라우터
                  = 통역사 = ASBR = 오늘의 주인공
```

| 번호 | 이름 | 사양·버전 | 비고 |
|---|---|---|---|
| 1 | R1 | 라우터. G0/0 `192.168.10.254`, G0/1 `192.168.20.1` | RIP만 돈다 |
| 2 | R2 | 라우터. G0/0 `192.168.50.1`, G0/1 `192.168.20.2` | RIP + OSPF. 재분배는 전부 여기서 한다 |
| 3 | R3 | 라우터. G0/0 `192.168.30.254`, G0/1 `192.168.50.2` | OSPF만 돈다 |
| 4 | SW1, SW2 | 스위치 각 1대 | 설정 없음 |
| 5 | PC0 | `192.168.10.1`, 마스크 `255.255.255.0`, 게이트웨이 `192.168.10.254` | |
| 6 | PC2 | `192.168.30.1`, 마스크 `255.255.255.0`, 게이트웨이 `192.168.30.254` | |
| 7 | 케이블 | 라우터끼리 크로스오버, 나머지 다이렉트 | |

| 장비 | 도는 프로토콜 | 설정하는 시점 |
|---|---|---|
| R1 | RIP만 | 구역 나눌 때만 |
| R2 | RIP + OSPF | 재분배는 전부 여기서 |
| R3 | OSPF만 | 구역 나눌 때만 |

## 5. 절차

### A. 구역 나누기 (① 무대 만들기)

R1은 RIP, R3은 OSPF, R2는 왼쪽(20.0)은 RIP, 오른쪽(50.0)은 OSPF로 설정한다.

1. (SUBTASK 5-A-01) R1에서 RIP을 설정한다: `router rip`, `version 2`, `no auto-summary`, `network 192.168.10.0`, `network 192.168.20.0`. → 결과: `show ip protocols`에 `rip`만 나온다.
2. (SUBTASK 5-A-02) R3에서 OSPF를 설정한다: `router ospf 1`, `network 192.168.50.0 0.0.0.255 area 0`, `network 192.168.30.0 0.0.0.255 area 0`. → 결과: `show ip protocols`에 `ospf`만 나온다.
3. (SUBTASK 5-A-03) R2에서 왼쪽 구간을 RIP으로 설정한다: `router rip`, `version 2`, `no auto-summary`, `network 192.168.20.0`.
4. (SUBTASK 5-A-04) R2에서 오른쪽 구간을 OSPF로 설정한다: `router ospf 1`, `network 192.168.50.0 0.0.0.255 area 0`. → 결과: `show ip protocols`에 `rip`과 `ospf`가 둘 다 나온다.
5. (SUBTASK 5-A-05) 30초 기다린 뒤 R2에서 `show ip route`를 입력한다. → 결과: 아래와 같이 `R`과 `O`가 같이 보인다.

```
R    192.168.10.0/24 [120/1] via 192.168.20.1     ← RIP 으로 배웠다
C    192.168.20.0/24 is directly connected
C    192.168.50.0/24 is directly connected
O    192.168.30.0/24 [110/2] via 192.168.50.2     ← OSPF 로 배웠다
```

R2 한 대에 `R`과 `O`가 같이 있다. 이 라우터가 오늘의 통역사다.

| 장비 | `show ip protocols`에서 나와야 할 것 |
|---|---|
| R1 | `rip`만 |
| R2 | `rip`과 `ospf` 둘 다 |
| R3 | `ospf`만 |

### B. 재분배 전 확인 (② 왜 안 되는지)

케이블도 다 붙었고 라우터도 다 살아 있는데 통신은 되지 않는다. 성공부터 보면 재분배가 왜 필요한지 와닿지 않으므로 이 구역을 건너뛰지 않는다.

1. (SUBTASK 5-B-01) PC0에서 `ping 192.168.30.1`을 입력한다. → 결과: 실패한다.
2. (SUBTASK 5-B-02) R1에서 `show ip route`를 입력한다. → 결과: `30.0`과 `50.0`이 없다(보낼 곳을 모른다).
3. (SUBTASK 5-B-03) R3에서 `show ip route`를 입력한다. → 결과: `10.0`과 `20.0`이 없다.
4. (SUBTASK 5-B-04) R2에서 `show ip route`를 입력한다. → 결과: `10.0`, `20.0`, `50.0`, `30.0`이 전부 있다.

| 장비 | 10.0 | 20.0 | 50.0 | 30.0 |
|---|:---:|:---:|:---:|:---:|
| R1 | C | C | 없음 | 없음 |
| R2 | R | C | C | O |
| R3 | 없음 | 없음 | C | C |

질문과 답:

- "가운데 R2는 다 아는데 왜 통신이 안 되는가?" → 혼자만 알고 있다. 왼쪽 소식을 오른쪽에 옮겨 주지 않는다.
- "한 장비 안에 RIP과 OSPF가 같이 있는데 서로 대화하지 않는가?" → 하지 않는다. 프로세스는 자기 언어권하고만 대화한다. → [1. 재분배란 무엇인가](lesson-1.md)

### C. 양방향 재분배 (③ 핵심)

모든 명령은 R2 한 대에서만 친다.

**C-1. RIP에서 OSPF로 (한 방향씩)**

1. (SUBTASK 5-C-01) R2에서 OSPF 설정으로 들어가 RIP 경로를 넘긴다: `router ospf 1`, `redistribute rip subnets metric 20`. → 결과: R2 자신의 테이블은 변하지 않는다(원래 다 알고 있었다).
2. (SUBTASK 5-C-02) R3에서 `show ip route ospf`를 입력한다. → 결과: 몇 초 안에 `O E2` 항목이 새로 생긴다.

```
O E2 192.168.10.0/24 [110/20] via 192.168.50.1, 00:00:09, GigabitEthernet0/1
──┬─                  ─┬─
  External             재분배할 때 준 seed metric 20 이 그대로
```

"`O` 뒤에 `E`가 왜 붙었는가?" → 밖에서 온 경로라는 표식이다.

**C-2. OSPF에서 RIP으로 (일부러 틀리게 먼저)**

3. (SUBTASK 5-C-03) R2에서 RIP 설정으로 들어가 메트릭 없이 재분배한다: `router rip`, `redistribute ospf 1`. → 결과: 오류 없이 끝난다.
4. (SUBTASK 5-C-04) 30초 기다린 뒤 R1에서 `show ip route`를 입력한다. → 결과: `30.0`과 `50.0`이 생기지 않는다. 30초를 더 기다려도 같다.

"명령은 분명히 쳤는데 왜 안 오는가?" → RIP은 홉 수로 말하는데 몇 홉인지 알려 주지 않았다. 무한대(∞)로 취급해 광고하지 않는다. → [2. 재분배의 원리와 주의점](lesson-2.md)

**C-3. seed metric을 준다 (한 단어 차이)**

5. (SUBTASK 5-C-05) R2에서 RIP 설정으로 들어가 메트릭을 준다: `router rip`, `redistribute ospf 1 metric 3`. → 결과: 오류 없이 끝난다.
6. (SUBTASK 5-C-06) 30초 기다린 뒤 R1에서 `show ip route rip`를 입력한다. → 결과: 아래와 같이 `R` 경로 2개가 보인다.

```
R    192.168.30.0/24 [120/3] via 192.168.20.2
R    192.168.50.0/24 [120/3] via 192.168.20.2
```

- "이 `3`은 실제 거리인가?" → 아니다. 우리가 정해 준 값이다.
- "30.0과 50.0은 실제 거리가 다른데 왜 똑같이 3인가?" → 원래 메트릭 정보가 사라졌다. 이것이 차선 경로의 근본 원인이다. → [2. 재분배의 원리와 주의점](lesson-2.md)

**C-4. 최종 확인**

7. (SUBTASK 5-C-07) PC0에서 `ping 192.168.30.1`을 입력한다. → 결과: 성공한다.
8. (SUBTASK 5-C-08) PC0에서 `tracert 192.168.30.1`을 입력한다. → 결과: R1, R2, R3을 거쳐 간다.
9. (SUBTASK 5-C-09) 세 라우터에서 `copy running-config startup-config`를 입력하고 파일을 `Ctrl + S`로 저장한다. → 결과: 저장이 끝난다.

### D. `E1`과 `E2`, `default-metric` (④ 여유 있으면)

시간이 부족하면 이 구역 전체를 생략한다. ③까지가 필수다.

1. (SUBTASK 5-D-01) R2에서 E1로 바꾼다: `router ospf 1`, `redistribute rip subnets metric 20 metric-type 1`. → 결과: 오류 없이 끝난다.
2. (SUBTASK 5-D-02) R3에서 `show ip route ospf`를 입력한다. → 결과: 표시가 `O E1`로, 코스트가 `[110/21]` 이상으로 바뀐다.

| 구분 | 표시 | 코스트 |
|---|---|---|
| 기본 | `O E2` | `[110/20]`. 어디서 보든 항상 20 |
| `metric-type 1` | `O E1` | `[110/21]` 이상. 20 + 여기까지 오는 내부 비용 |

3. (SUBTASK 5-D-03) R2에서 E1 설정을 지운다: `router ospf 1`, `no redistribute rip subnets metric 20 metric-type 1`.
4. (SUBTASK 5-D-04) R2에서 OSPF 쪽을 `default-metric`으로 정리한다: `default-metric 20`, `redistribute rip subnets`.
5. (SUBTASK 5-D-05) R2에서 RIP 쪽을 정리한다: `router rip`, `default-metric 3`, `redistribute ospf 1`. → 결과: 오류 없이 끝난다.
6. (SUBTASK 5-D-06) R2에서 `show running-config | section router`를 입력한다. → 결과: 설정이 짧아졌다.
7. (SUBTASK 5-D-07) PC0에서 `ping 192.168.30.1`을 입력한다. → 결과: 되돌린 뒤에도 성공한다.

E2는 준 값 그대로, E1은 준 값에 오는 길 비용을 더한 값이다. 통역사가 여럿이면 가까운 통역사를 골라야 하므로 E1이 유리하다. 기본값은 E2다.

## 6. 기능 확인

| 번호 | 확인 동작 | 기대 결과 | 합격 기준 |
|---|---|---|---|
| 1 | R3 `show ip route ospf` | `O E2` 경로가 있다 | `192.168.10.0`, `192.168.20.0` 2개 |
| 2 | R1 `show ip route rip` | RIP 경로가 있다 | `192.168.30.0`, `192.168.50.0`, 메트릭 `[120/3]` |
| 3 | PC0 `ping 192.168.30.1` | 응답이 온다 | 손실 0% |
| 4 | R1과 R3의 `show running-config` | 재분배 명령이 없다 | `redistribute`가 R2에만 있다 |

### 막혔을 때: 오늘판 5대 원인

| 증상 | 원인 |
|---|---|
| 재분배했는데 경로가 안 온다(RIP 쪽) | `metric`을 안 줬다(1위) |
| 아무 변화가 없다 | RIP은 30초가 걸린다. 한 번 더 `show ip route`를 입력한다 |
| 한쪽 방향만 된다 | 재분배도 왕복이다. 두 방향을 각각 설정했는지 확인한다 |
| `redistribute`가 안 먹는다 | 받는 프로세스 안에서 쳤는지 확인한다([commands.md](commands.md)의 부록 C 공식) |
| R2만 잘 된다 | 정상이다. 재분배 전 상태다 |

전체 점검표는 [commands.md](commands.md)의 부록 D를 본다.

## 7. 복구

1. (SUBTASK 7-01) R2에서 OSPF 쪽 재분배를 취소한다: `router ospf 1`, `no redistribute rip`. → 결과: 오류 없이 끝난다. 옵션이 남아 취소되지 않으면 `show running-config | section router`로 실제 줄을 확인해 그대로 앞에 `no`를 붙인다.
2. (SUBTASK 7-02) R2에서 RIP 쪽 재분배를 취소한다: `router rip`, `no redistribute ospf 1`. → 결과: 30초 뒤 R1과 R3의 테이블에서 재분배 경로가 사라진다.
3. (SUBTASK 7-03) 구성 전체를 처음 상태로 돌리려면 새 파일에서 5-A부터 다시 한다.

## 강의 메모

- ②(실패 확인)를 절대 건너뛰지 않는다. 오늘 수업의 동기가 거기서 나온다.
- ③의 "메트릭 없이 먼저 쳐 보기"가 오늘의 명장면이다. 성공만 보여 주면 seed metric이 왜 필요한지 기억에 남지 않는다.
- 단방향씩 차근차근 간다. 먼저 OSPF로 RIP을 넘기고 R3에서 확인한 뒤 반대 방향으로 간다.
- `O E2` 표기를 꼭 짚어 "밖에서 온 경로"임을 각인시킨다.
- 그림 만들기가 세 번째이므로 20분 안에 끝나야 정상이다. 오래 걸리는 학생은 5일차 대본의 준비 절차를 따르게 한다.
- 시간이 부족하면 ④를 통째로 생략한다(③까지가 필수).
- 1단계 라우팅(4~6일차) 마무리. 다음(7일차): 스위칭 심화 → [7일차 · 스위칭 심화](../day-07/README.md)
