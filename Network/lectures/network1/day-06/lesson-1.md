## 🎯 학습 목표

- 프로토콜이 **자기 언어끼리만 통한다**는 사실을 이해한다
- 재분배(Redistribution)의 개념을 한 문장으로 설명한다
- 재분배가 필요한 **현실 상황**을 안다
- 재분배가 일어나는 위치(**경계 라우터 = ASBR**)를 이해한다

## 🌉 다리 놓기: "한 회사 안에 OSPF 구역과 RIP 구역이 섞이면?"

5일차에 RIP·OSPF·EIGRP 를 배웠고, 마지막 **AD 대결**에서 한 라우터에 RIP 과 OSPF 를 동시에 켜봤다.
→ [3_OSPF와_EIGRP](../day-05/lesson-3.md)

그때는 **세 라우터 전부**가 두 프로토콜을 다 돌고 있었다. 그런데 현실은 다르다.

> **상황극.** A사는 오래된 장비라 **RIP** 만 돈다. B사는 **OSPF** 를 쓴다.
> 두 회사가 **합병**해서 가운데 라우터 한 대로 연결했다.
> 케이블도 붙었고, 라우터도 다 살아 있다. **그런데 통신이 안 된다.**

## 📖 왜 안 될까 — 프로토콜은 자기 언어끼리만 통한다

```
      ◀── RIP 구역 ──▶       ◀── OSPF 구역 ──▶
   [R1]════════[R2]════════[R3]
   RIP 만        RIP+OSPF        OSPF 만
```

| 라우터 | 아는 것 | 모르는 것 |
|--------|---------|-----------|
| **R1** (RIP) | 10.0 · 20.0 | 50.0 · 30.0 |
| **R2** (둘 다) | **전부** | — |
| **R3** (OSPF) | 50.0 · 30.0 | 10.0 · 20.0 |

> 🗣 **"가운데 R2 는 다 아는데, 왜 통신이 안 될까요?"**

- R2 는 RIP 으로 배운 것을 **RIP 이웃에게만** 말한다
- R2 는 OSPF 로 배운 것을 **OSPF 이웃에게만** 말한다
- **RIP 프로세스와 OSPF 프로세스는 같은 장비 안에 있어도 서로 대화하지 않는다** ⭐

즉 R2 는 **혼자만 알고 있다.** 왼쪽 소식을 오른쪽에 **옮겨주지 않는다.**

> 💡 **비유 — 통역사.**
> 한국어(RIP)만 아는 조직과 영어(OSPF)만 아는 조직 사이에, **양쪽 말을 다 하는 사람**이 있다.
> 그런데 그 사람이 **가만히 있으면** 회의는 진행되지 않는다.
> **"통역해 주세요" 라고 시켜야** 비로소 말이 오간다 — 그 지시가 **재분배**다.

## 📖 재분배란?

> **재분배(Redistribution) = 한 라우팅 프로토콜이 학습한 경로를
> 다른 프로토콜(또는 정적·직접연결)로 넘겨주는 것**

- OSPF 가 아는 경로를 → **RIP 에게도 알려주기**
- 정적 경로를 → **OSPF 에 주입하기**
- 이렇게 하면 서로 다른 도메인의 장비들이 **끝까지 통신**할 수 있다

**중요한 성질 두 가지**

| | 내용 |
|---|---|
| **어디서** | **양쪽 프로토콜을 다 도는 라우터 한 대에서만** 설정한다 |
| **방향** | **한 방향씩** 따로 지정한다 (A→B 와 B→A 는 별개 명령) |

> 🧪 실습에서 **R1·R3 에는 한 글자도 치지 않는다.** 모든 명령은 R2 한 대에서.

## 📖 언제 필요한가 — 현실의 4가지 상황

| 상황 | 예 |
|------|-----|
| **회사 합병** | A사(OSPF) + B사(EIGRP) 를 하나의 망으로 |
| **멀티벤더** | 시스코 구역(EIGRP) + 타사 구역(OSPF) 혼용 |
| **프로토콜 마이그레이션** | RIP → OSPF 로 **점진적** 전환 (하루에 다 못 바꾼다) |
| **정적/직접연결 주입** | 특정 정적 경로·인터넷 나가는 길을 동적 프로토콜에 광고 |

> 💡 **가장 흔한 실무 사례는 마지막 줄이다.**
> "인터넷으로 나가는 디폴트 경로"를 OSPF 전체에 뿌리는 것 —
> `default-information originate` → [부록 A](commands.md)

## 📖 어디서 일어나나 — 경계 라우터 (ASBR)

- **두 프로토콜을 동시에 도는 라우터**에서 설정한다. 이 라우터가 양쪽 언어를 다 알기 때문
- OSPF 에서는 이런 라우터를 **ASBR(Autonomous System Boundary Router)** 이라 부른다
  - **AS 경계 라우터** = 우리 OSPF 구역 **바깥 세상과 닿아 있는** 라우터

| 이름 | 위치 | 하는 일 |
|------|------|---------|
| 내부 라우터 | 한 Area 안 | 평범한 OSPF |
| ABR (Area Border Router) | **Area 와 Area 사이** | 영역 간 경로 전달 |
| **ASBR** | **OSPF 와 바깥(RIP·정적 등) 사이** | **재분배** ⭐ |

> ⚠️ **ABR ↔ ASBR 혼동 주의.** ABR 은 **OSPF 안의 영역 경계**, ASBR 은 **OSPF 밖과의 경계**다.
> CCNA 단골 함정.

## 📖 재분배된 경로는 표시가 다르다

넘겨받은 경로에는 **"이건 밖에서 온 것"** 이라는 꼬리표가 붙는다.

| 라우팅 테이블 표시 | 뜻 |
|---|---|
| `O` | OSPF 가 **자기 구역 안에서** 배운 경로 |
| **`O E2`** / `O E1` | **밖에서 재분배돼 들어온** 경로 (**E** = External) |
| `D` / `D EX` | EIGRP 내부 / **EIGRP 외부**(재분배) |
| `R` | RIP 경로 (RIP 은 내부·외부 구분 표시가 없다) |

> 🧪 실습에서 R3 의 테이블에 **`O E2 192.168.10.0`** 이 뜨는 것을 확인한다.
> `E` 를 보는 순간 **"아, 이건 OSPF 세상 밖에서 온 손님이구나"** 를 알 수 있다.

## 🧪 질문

- 🗣 "RIP 만 아는 라우터와 OSPF 만 아는 라우터를 그냥 케이블로 이으면 통신될까?"
  → **안 된다.** 서로의 경로를 모른다 → 경계 라우터의 재분배 필요
- 🗣 "재분배는 어느 라우터에 설정하나?" → **양쪽 프로토콜을 다 도는** 라우터 **한 대**
- 🗣 "한 장비 안의 RIP 프로세스와 OSPF 프로세스는 서로 대화하나?" → **하지 않는다** ⭐
- 🗣 "ABR 과 ASBR 의 차이는?" → ABR = **영역 경계**, ASBR = **OSPF 밖과의 경계**
- 🗣 "`O E2` 의 `E` 는?" → **External, 재분배돼 들어온 경로**
