## 1. 목적

"한 회사 안에 OSPF 구역과 RIP 구역이 섞이면 어떻게 되는가"에 답한다.

5일차에 RIP, OSPF, EIGRP를 배웠고, 마지막 AD 대결에서 한 라우터에 RIP과 OSPF를 동시에 켜 봤다. → [3. OSPF와 EIGRP](../day-05/lesson-3.md)

그때는 세 라우터 모두 두 프로토콜을 다 돌렸다. 현실은 다르다.

상황극: A사는 오래된 장비라 RIP만 돈다. B사는 OSPF를 쓴다. 두 회사가 합병해 가운데 라우터 한 대로 연결했다. 케이블도 붙었고 라우터도 모두 살아 있다. 그런데 통신이 안 된다.

## 2. 구성 요소

### 왜 안 되는가: 프로토콜은 자기 언어끼리만 통한다

```
      ◀── RIP 구역 ──▶       ◀── OSPF 구역 ──▶
   [R1]════════[R2]════════[R3]
   RIP 만        RIP+OSPF        OSPF 만
```

| 라우터 | 아는 것 | 모르는 것 |
|---|---|---|
| R1 (RIP) | 10.0, 20.0 | 50.0, 30.0 |
| R2 (둘 다) | 전부 | 없음 |
| R3 (OSPF) | 50.0, 30.0 | 10.0, 20.0 |

(표의 "10.0" 등은 `192.168.<값>.0/24` 네트워크의 약칭이다.)

핵심 질문: 가운데 R2는 다 아는데 왜 통신이 안 되는가?

- R2는 RIP으로 배운 것을 RIP 이웃에게만 말한다.
- R2는 OSPF로 배운 것을 OSPF 이웃에게만 말한다.
- RIP 프로세스와 OSPF 프로세스는 같은 장비 안에 있어도 서로 대화하지 않는다.

즉 R2는 혼자만 알고 있다. 왼쪽 소식을 오른쪽에 옮겨 주지 않는다.

비유(통역사): 한국어(RIP)만 아는 조직과 영어(OSPF)만 아는 조직 사이에 양쪽 말을 다 하는 사람이 있다. 그 사람이 가만히 있으면 회의는 진행되지 않는다. "통역해 주세요"라고 시켜야 말이 오간다. 그 지시가 재분배다.

### 필요한 상황

| 상황 | 예 |
|---|---|
| 회사 합병 | A사(OSPF)와 B사(EIGRP)를 하나의 망으로 잇는다 |
| 멀티벤더 | 시스코 구역(EIGRP)과 타사 구역(OSPF)을 함께 쓴다 |
| 프로토콜 마이그레이션 | RIP에서 OSPF로 점진적으로 전환한다(하루에 다 바꾸지 못한다) |
| 정적·직접연결 주입 | 특정 정적 경로나 인터넷으로 나가는 길을 동적 프로토콜에 광고한다 |

가장 흔한 실무 사례는 마지막 줄이다. 인터넷으로 나가는 디폴트 경로를 OSPF 전체에 뿌리는 것이며 `default-information originate`를 쓴다. → [6일차 실습 명령어](commands.md)의 부록 A

### 경계 라우터 (ASBR)

- 두 프로토콜을 동시에 도는 라우터에서 설정한다. 이 라우터가 양쪽 언어를 다 알기 때문이다.
- OSPF에서는 이런 라우터를 ASBR(Autonomous System Boundary Router)이라 부른다. 우리 OSPF 구역 바깥 세상과 닿아 있는 라우터다.

| 이름 | 위치 | 하는 일 |
|---|---|---|
| 내부 라우터 | 한 Area 안 | 평범한 OSPF |
| ABR (Area Border Router) | Area와 Area 사이 | 영역 간 경로 전달 |
| ASBR | OSPF와 바깥(RIP, 정적 등) 사이 | 재분배 |

{% hint style="warning" %}
CAUTION: ABR과 ASBR을 혼동하기 쉽다. ABR은 OSPF 안의 영역 경계, ASBR은 OSPF 밖과의 경계다. CCNA 단골 함정이다.
{% endhint %}

### 경로 표시

재분배돼 들어온 경로에는 "밖에서 온 것"이라는 꼬리표가 붙는다.

| 라우팅 테이블 표시 | 뜻 |
|---|---|
| `O` | OSPF가 자기 구역 안에서 배운 경로 |
| `O E2` / `O E1` | 밖에서 재분배돼 들어온 경로(E = External) |
| `D` / `D EX` | EIGRP 내부 / EIGRP 외부(재분배) |
| `R` | RIP 경로(RIP은 내부·외부 구분 표시가 없다) |

실습에서 R3의 테이블에 `O E2 192.168.10.0`이 뜨는 것을 확인한다. `E`를 보면 OSPF 세상 밖에서 온 손님임을 알 수 있다. → [3. 재분배 실습](lesson-3.md)

## 3. 동작 원리

### 재분배의 정의

재분배(Redistribution)는 한 라우팅 프로토콜이 학습한 경로를 다른 프로토콜(또는 정적, 직접연결)로 넘겨주는 것이다.

- OSPF가 아는 경로를 RIP에게도 알려 준다.
- 정적 경로를 OSPF에 주입한다.
- 이렇게 하면 서로 다른 도메인의 장비들이 끝까지 통신한다.

성질 두 가지:

| 구분 | 내용 |
|---|---|
| 어디서 | 양쪽 프로토콜을 다 도는 라우터 한 대에서만 설정한다 |
| 방향 | 한 방향씩 따로 지정한다(A→B와 B→A는 별개 명령) |

실습에서 R1과 R3에는 재분배 명령을 치지 않는다. 모든 명령은 R2 한 대에서 친다.

## 4. 약어·용어

| 용어 | 뜻 |
|---|---|
| 재분배(Redistribution) | 한 프로토콜의 경로를 다른 프로토콜로 넘겨주는 기능 |
| ASBR | Autonomous System Boundary Router. OSPF 밖과 닿아 있는 경계 라우터 |
| ABR | Area Border Router. OSPF 영역 사이의 경계 라우터 |
| E (External) | 재분배돼 들어온 외부 경로 표시 |

## 강의 메모

- 상황극(회사 합병)으로 시작한다. "케이블은 붙었는데 왜 안 되죠?"가 오늘의 출발점이다.
- "R2는 다 아는데 왜 안 될까?" 이 질문 하나로 30분을 끌 수 있다. 학생이 스스로 "옮겨 주지 않아서"라고 말하게 만드는 것이 목표다.
- 통역사 비유를 칠판에 그려 두고 수업 내내 참조한다. "가만히 있는 통역사", "통역해 주세요(재분배)", "그런데 단위가 다르다" 순이다. → [2. 재분배의 원리와 주의점](lesson-2.md)
