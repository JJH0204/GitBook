## 🎯 학습 목표

- **메트릭 불일치** 문제와 **seed metric** 의 필요성을 이해한다
- 재분배 명령을 **어느 프로세스 안에서** 치는지 헷갈리지 않는다
- 단방향 · 양방향(상호) 재분배를 구분한다
- 재분배의 위험(**루프 · 차선 경로**)이 왜 생기는지 안다
- `O E1` 과 `O E2` 의 차이를 안다

## 🌉 다리 놓기: "통역이 왜 까다로울까 — 단위가 다르다"

프로토콜마다 최적 경로를 재는 **자(尺)가 다르다.**
→ [1_라우팅프로토콜_개요](../day-05/lesson-1.md)

| 프로토콜 | 무엇으로 재나 | 값의 예 |
|---|---|---|
| RIP | **홉 수** | 3 |
| OSPF | **코스트**(대역폭) | 20 |
| EIGRP | **대역폭 + 지연** | 28160 |

> ❓ RIP 의 **"3홉"** 을 OSPF 에게 그대로 넘기면?
> OSPF 는 **"3" 이 무슨 뜻인지 모른다.** 코스트 3? 홉 3? 단위가 없으니 판단이 안 된다.
>
> 💡 **비유.** "여기서 3정거장이에요" 라는 말을 **거리(km)로만 말하는 사람**에게 전하려면?
> "3정거장"을 그대로 옮기면 안 된다. **받는 쪽 단위로 바꿔줘야 한다.**

## 📖 Seed Metric (씨앗 메트릭) — 오늘의 핵심 개념 ⭐

> **Seed Metric = 재분배할 때, 넘겨받는 프로토콜이 쓸 메트릭 값을 관리자가 정해주는 것**

- 원래 메트릭을 **변환하는 게 아니다.** **버리고 새로 정한다**
- 그래서 **거리 정보가 사라진다** → 나중에 볼 부작용(차선 경로)의 근본 원인

```bash
router rip
 redistribute ospf 1 metric 3        ← "이 경로들은 RIP 세상에서 3홉짜리로 쳐라"
```

### 안 주면 어떻게 되나 — 프로토콜마다 다르다 ⚠️

| 넘겨받는 쪽 | 기본 seed metric | 지정 필요? | 안 주면 |
|-------------|------------------|-----------|---------|
| **RIP** | **무한대(∞)** | ✅ **필수** | **아예 광고되지 않는다** |
| **EIGRP** | **무한대(∞)** | ✅ **필수** | **아예 광고되지 않는다** |
| **OSPF** | **20** | 선택 | 20 으로 동작한다 |
| BGP | IGP 메트릭 승계 | 선택 | 그대로 |

> 🚨 **"재분배 명령은 분명히 쳤는데 경로가 안 온다"** 의 1위 원인 —
> **RIP·EIGRP 로 넘길 때 `metric` 을 안 줬다.**
> 무한대 = 도달 불가 → 광고 자체를 하지 않는다 → 상대는 **아무 소식도 못 받는다.**

> 🧪 실습 **③** 에서 **일부러 메트릭 없이 먼저 쳐서 실패를 보고**,
> 그다음 `metric 3` 을 붙여 성공시킨다. → [0_실습_명령어_모음](commands.md)

### `default-metric` — 여러 줄을 한 번에

```bash
router rip
 default-metric 3          ← 이 프로세스로 들어오는 모든 재분배의 기본값
 redistribute ospf 1
 redistribute static
```

- 재분배 줄이 여러 개일 때 **매번 `metric` 을 쓰지 않아도 된다**
- 실무 습관: **`default-metric` 한 줄로 몰아쓰기**

## 📖 명령을 어디서 치나 — 헷갈리면 이 공식 ⭐

```
① 넣고 싶은 곳(받는 프로토콜)으로 들어간다     router ospf 1
② 어디서 가져올지 말한다                        redistribute rip subnets metric 20
```

> 🚨 **가장 흔한 실수: 주는 쪽에 들어가서 친다.**
> **"받는 집에 들어가서, 어디서 가져올지 말한다"** 로 외운다.

| 하고 싶은 것 | 들어가는 곳 | 치는 명령 |
|---|---|---|
| RIP 경로를 **OSPF 에** 넣기 | `router ospf 1` | `redistribute rip subnets metric 20` |
| OSPF 경로를 **RIP 에** 넣기 | `router rip` | `redistribute ospf 1 metric 3` |
| 정적 경로를 **OSPF 에** 넣기 | `router ospf 1` | `redistribute static subnets metric 20` |
| 직접연결을 **RIP 에** 넣기 | `router rip` | `redistribute connected metric 3` |

### `subnets` 키워드는 뭔가

- **OSPF 로 재분배할 때만** 쓰는 키워드다
- 없으면 **클래스풀 경로(A/B/C 기본 마스크)만** 넘어가고 **서브넷팅된 경로는 누락**된다
  - 예: `172.16.1.0/24` 는 B클래스를 쪼갠 것 → `subnets` 없으면 **안 넘어간다**
- 우리 실습은 `192.168.x.0/24`(C클래스 기본 마스크)라 **없어도 넘어간다.**
  하지만 **항상 붙이는 습관**을 들일 것 — 실무의 대부분은 서브넷팅되어 있다

> 💡 최신 IOS(15.1 이후)에서는 `subnets` 가 기본 동작이 되었다. 그래도 **CCNA 시험에는 나온다.**

## 📖 방향: 단방향 vs 양방향(상호)

| | 설명 | 위험도 |
|---|------|--------|
| **단방향** | A → B 로만 넘긴다 | 낮음 |
| **양방향(상호, mutual)** | A ↔ B 서로 넘긴다 | **높음** |

- 끝단끼리 **ping 이 되려면 결국 양방향**이 필요하다 (라우팅은 왕복! → 4일차 회수)
- 실습에서도 **두 방향을 각각** 설정한다 → 명령이 **두 줄**인 이유

> ⚠️ 위험한 것은 "양방향" 자체가 아니라, **양방향 재분배 지점이 두 곳 이상**일 때다.

## 📖 ⚠️ 재분배의 위험 3가지

### ① 라우팅 루프

```
        ┌──[R2]──┐
[RIP]───┤        ├───[OSPF]
        └──[R4]──┘
     경계 라우터가 두 곳!
```

- R2 가 RIP → OSPF 로 넘긴 경로가, R4 를 통해 **다시 RIP 으로 되돌아온다**
- 되돌아온 경로가 원래 것보다 **AD 가 낮아 보이면** 라우터가 그걸 믿는다 → **빙빙 돈다**
- 대응: **재분배 지점을 한 곳으로** · route-map 으로 걸러내기 · AD 조정(`distance`)

### ② 차선 경로 (Suboptimal Routing)

- seed metric 은 **원래 거리를 버리고 새로 매긴 값**이다
- 넘겨받는 쪽 입장에선 **어느 목적지가 더 가까운지 구분이 안 된다** (전부 같은 값)
- 그래서 **더 먼 길을 고를 수 있다**

> 🧪 실습에서 R1 이 30.0 과 50.0 을 **둘 다 `[120/3]`** 으로 보게 된다.
> 실제로는 **거리가 다른데도** 똑같이 3홉으로 보인다 — 이게 정보 손실의 실물.

### ③ AD 충돌

- 같은 목적지를 여러 출처로 배우면 **AD 가 낮은 쪽만** 테이블에 오른다
- 그런데 **내가 원한 경로가 아닐 수 있다**
- 대응: `distance` 명령으로 AD 를 손으로 조정 (심화 — 이름만)

> 📌 실무 3원칙: **① 재분배 지점 최소화 ② 필터(route-map)로 통제 ③ 필요시 AD 조정**
> 셋 다 CCNP 급 주제다. **오늘은 "왜 위험한지"만** 알고 넘어간다.

## 📖 `O E1` vs `O E2` — 숫자 하나의 차이

OSPF 로 재분배된 경로에는 **타입 번호**가 붙는다.

| | `O E2` (**기본값**) | `O E1` |
|---|---|---|
| 코스트 계산 | **seed metric 그대로** (어디서 보든 같다) | **seed metric + 내부 코스트** |
| 예 | 항상 `[110/20]` | `[110/21]`, `[110/23]` … 위치마다 다름 |
| 언제 좋은가 | 경계 라우터가 **한 곳**일 때 | 경계 라우터가 **여러 곳** — 가까운 쪽을 고르고 싶을 때 |

> 💡 **E2 = 외부까지의 거리만 / E1 = 외부까지의 거리 + 거기까지 가는 내 거리.**
> 통역사가 여럿이면 **가까운 통역사를 골라야** 하니 **E1** 이 유리하다.

> 🧪 실습 **④** 에서 `metric-type 1` 로 바꿔 **표시와 숫자가 둘 다 변하는 것**을 확인한다.

## 🧪 질문

- 🗣 "OSPF 로 재분배했는데 경로가 안 보인다. 뭘 의심?" → `subnets` 누락 · 인접 관계 확인
- 🗣 "RIP 으로 재분배했는데 경로가 안 온다. 뭘 의심?" → **`metric` 누락**(무한대 취급) ⭐
- 🗣 "재분배 명령은 어느 프로세스 안에서 치나?" → **받는 쪽** (`router <받는 것>`)
- 🗣 "상호 재분배가 편한데 왜 조심?" → **루프 · 차선 경로**
- 🗣 "R1 이 본 `[120/3]` 의 3 은 실제 홉 수인가?" → **아니다. 우리가 정해준 값**
- 🗣 "`O E1` 과 `O E2` 의 차이는?" → **내부 코스트를 더하느냐 마느냐**

## 📝 강의 메모

- **"단위가 다르다 → 통역할 땐 새 단위를 정해줘야 한다(seed metric)"** 한 문장으로 각인
- **RIP·EIGRP 는 필수 / OSPF 는 기본 20** — 이 비대칭을 반드시 짚을 것.
  "OSPF 쪽은 안 줘도 되던데요?" 라는 질문이 반드시 나온다
- ⚠️ **명령 위치 혼동**이 실습 최대 병목 → **"받는 집에 들어가서"** 를 구호처럼 반복
- 위험 3가지는 **"왜 위험한지"만.** route-map·distance 는 **이름만 예고**하고 선을 그을 것
- 차선 경로는 실습 결과(`[120/3]` 두 줄)를 가리키며 설명하면 **말 없이도 전달된다**
