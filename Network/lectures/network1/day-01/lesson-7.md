## 학습 목표

- 전송 방식(캐스트) 세 가지를 구분한다.
- 각 방식이 실제로 쓰이는 상황을 이해한다.
- 브로드캐스트 도메인의 개념을 잡는다.

## 1. 목적

### 1.1 다리 놓기: 꼭 한 명에게만 보내는 것은 아니다

앞에서 IP 주소로 특정 한 대를 콕 집어 데이터를 보낸다고 했다. → [4. 데이터는 어디로 갈까 — IP 주소](lesson-4.md)(LEC-N1-01-004-DO)

이렇게 1:1로 보내는 방식이 유니캐스트다. 늘 한 명에게만 보내지는 않는다.

- 동네 사람 전부에게 알릴 일이 있다(전체).
- 관심 있는 몇 명에게만 보낼 일도 있다(그룹).

카톡에 비유하면 1:1 채팅, 공지 전체 발송, 단톡방이다. 이 세 가지가 각각 유니캐스트, 브로드캐스트, 멀티캐스트다.

## 2. 구성 요소

### 2.1 전송 방식(Cast)의 종류

| 방식 | 수신 대상 | 비유 | 예시 |
|---|---|---|---|
| 유니캐스트(Unicast) | 1 → 1 (특정 한 대) | 1:1 전화 | 웹서핑, 파일 전송 대부분 |
| 브로드캐스트(Broadcast) | 1 → 전체 (같은 네트워크 모두) | 확성기 방송 | ARP 요청, DHCP Discover |
| 멀티캐스트(Multicast) | 1 → 그룹 (구독한 대상만) | 단체 채팅방 | 실시간 스트리밍, 라우팅 프로토콜(OSPF) |
| (참고) 애니캐스트(Anycast) | 1 → 가장 가까운 하나 | 가장 가까운 지점 안내 | DNS 루트 서버, CDN |

### 2.2 방식별 상세

- 유니캐스트: 목적지 IP가 특정 한 대다. [4. IP 주소](lesson-4.md)에서 배운 "주소로 한 대 찾기"가 이것이다. 인터넷 트래픽의 대부분이다.
- 브로드캐스트: 목적지 MAC이 `FF:FF:FF:FF:FF:FF`다. 같은 네트워크 전체가 수신한다. 이 네트워크가 [5. LAN · WAN 과 네트워크 토폴로지](lesson-5.md)의 "LAN 동네"다. 남발하면 성능이 떨어진다.
- 멀티캐스트: 특정 그룹 주소를 구독한 장비만 수신한다. 대역폭을 절약한다.

### 2.3 브로드캐스트 도메인

- 브로드캐스트가 전달되는 범위이며 하나의 "동네"다.
- 스위치(2계층)는 브로드캐스트를 통과시킨다. 같은 도메인이다.
- 라우터(3계층)는 브로드캐스트를 막는다. 도메인이 분리된다. → [6. 프로토콜 · OSI 7계층](lesson-6.md)(LEC-N1-01-006-DO)의 계층 관점
- VLAN으로 브로드캐스트 도메인을 논리적으로 나눌 수 있다(이후 심화).
- 장비별 동작은 3일차에서 다룬다. → [3일차 · 네트워크 장비와 네트워크 토폴로지](../day-03/README.md)

## 3. 동작 원리: ARP가 브로드캐스트로 시작하는 이유

1. 호스트가 이웃의 MAC 주소를 모른다.
2. 모르는 상대를 콕 집을 수 없으므로 같은 동네 전체에 묻는다(브로드캐스트).
3. 해당 장치가 응답한다.

MAC과 ARP의 상세는 3일차에서 이어진다.

## 4. 약어·용어

| 용어 | 뜻 |
|---|---|
| Cast | 데이터 전송 대상 범위에 따른 전송 방식 |
| ARP | Address Resolution Protocol. IP에 해당하는 MAC을 묻는 프로토콜 |
| DHCP Discover | 주소를 받으려는 호스트가 보내는 브로드캐스트 메시지 |
| OSPF | Open Shortest Path First. 멀티캐스트를 쓰는 라우팅 프로토콜 |
| VLAN | Virtual LAN. 브로드캐스트 도메인을 논리적으로 나누는 기술 |
