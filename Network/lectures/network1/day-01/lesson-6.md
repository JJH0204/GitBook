## 📖 프로토콜이란?

- 서로 다른 장비가 통신하기 위해 미리 정한 **통신 규약(약속)**
- 예: 언어가 다르면 대화가 안 되듯, 규약이 같아야 데이터 교환 가능
- 대표: TCP/IP, HTTP, FTP, Ethernet …

## 📖 OSI 7계층

통신이라는 복잡한 과정을 **7단계로 나눈 표준 참조 모델**. 문제 발생 시 "몇 계층 문제인지" 진단하는 기준.

| 계층  | 이름               | 역할          | 대표 프로토콜/기술             | 장비           | 데이터 단위(PDU) |
| --- | ---------------- | ----------- | ---------------------- | ------------ | ----------- |
| 7   | 응용(Application)  | 사용자 서비스     | HTTP, FTP, DNS, SMTP   | -            | Data        |
| 6   | 표현(Presentation) | 인코딩·암호화·압축  | SSL/TLS, JPEG          | -            | Data        |
| 5   | 세션(Session)      | 연결 관리·동기화   | 세션 관리                  | -            | Data        |
| 4   | 전송(Transport)    | 신뢰성·포트·흐름제어 | **TCP, UDP**           | -            | Segment     |
| 3   | 네트워크(Network)    | 논리 주소·경로 결정 | **IP**, ICMP, 라우팅      | **라우터**      | Packet      |
| 2   | 데이터링크(Data Link) | 물리 주소·오류 검출 | Ethernet, **MAC**, ARP | **스위치**, 브리지 | Frame       |
| 1   | 물리(Physical)     | 전기·신호 전송    | 케이블, 전압                | **허브**, 리피터  | Bit         |

> 암기 팁(상→하): **A**ll **P**eople **S**eem **T**o **N**eed **D**ata **P**rocessing

### 🔗 우리가 배운 게 여기 다 있다

- **1계층(물리) = 0과 1 신호** → [3_Bit_Byte_문자코드](lesson-3.md)의 그 비트가 전선을 타는 지점
- **3계층(네트워크) = IP 주소·경로 결정** → [4_어디로_보낼까_IP주소](lesson-4.md)가 바로 이 계층
- **2계층(데이터링크) = MAC 주소** → 물리 주소, 3일차에서 자세히
- 즉 오늘 배운 개념들이 **계층이라는 서랍**에 정리되는 셈

## 📖 OSI 7 vs TCP/IP 모델

| OSI 7계층 | TCP/IP 4계층 |
|-----------|--------------|
| 7·6·5 응용/표현/세션 | 응용(Application) |
| 4 전송 | 전송(Transport) |
| 3 네트워크 | 인터넷(Internet) |
| 2·1 데이터링크/물리 | 네트워크 접근(Network Access) |

- OSI = 교육·진단용 참조 모델 / TCP/IP = 실제 인터넷이 쓰는 모델

## 📖 캡슐화 (Encapsulation)

- 데이터가 상위→하위 계층으로 내려가며 각 계층의 **헤더가 덧붙는** 과정
- Data → (L4)Segment → (L3)Packet → (L2)Frame → (L1)Bit
- 받는 쪽은 반대로 **역캡슐화(Decapsulation)**

> 💡 [2_네트워크란_무엇인가](lesson-2.md)·[4_어디로_보낼까_IP주소](lesson-4.md)의 **편지 비유** 확장:
> 편지(Data)에 → 주소 봉투(IP) → 다시 겉봉투(MAC) 를 겹겹이 씌워 보내고, 받는 쪽은 겉에서부터 하나씩 벗겨 읽는다.
