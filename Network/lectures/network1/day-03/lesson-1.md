## 학습 목표

- 대표 네트워크 장비 4가지를 구분한다.
- 각 장비가 OSI 몇 계층에서 무엇을 기준으로 동작하는지 이해한다.
- 충돌 도메인과 브로드캐스트 도메인을 구분하고, 어느 장비가 무엇을 나누는지 안다.
- 장비를 잇는 케이블 종류를 고르고 인터페이스 이름(`G0/0` 등)을 읽는다.

## 1. 목적

1일차 OSI 7계층에서 1계층은 허브, 2계층은 스위치, 3계층은 라우터라고 예고했다. [1일차 프로토콜 OSI 7계층](../day-01/lesson-6.md)을 본다. 2일차에는 IP로 네트워크를 나눴다. 이 문서는 그 네트워크를 실제로 연결하는 장비를 설명한다.

## 2. 구성 요소

### 2.1 계층별 대표 장비

| 장비 | 계층 | 판단 기준 | 하는 일 | 한계 |
|---|---|---|---|---|
| 리피터(Repeater) | 1 물리 | 없음 | 약해진 신호를 재생성해 거리를 늘린다 | 신호만 늘린다 |
| 허브(Hub) | 1 물리 | 없음 | 받은 신호를 모든 포트로 그대로 뿌린다 | 충돌이 많고 비효율적이라 요즘 쓰지 않는다 |
| 스위치(Switch) | 2 데이터링크 | MAC 주소 | MAC을 보고 해당 포트로만 전달한다(똑똑한 허브) | 브로드캐스트는 통과시킨다 |
| 라우터(Router) | 3 네트워크 | IP 주소 | 서로 다른 네트워크를 연결하고 경로를 정한다 | 상대적으로 느리고 비싸다 |

한 줄 정리: 허브는 무조건 다 뿌리고, 스위치는 MAC을 보고 골라 전달하고, 라우터는 IP를 보고 다른 망으로 보낸다.

### 2.2 허브와 스위치

- 허브는 아무나 말해도 전원에게 들린다. 시끄럽고 충돌이 생긴다(확성기 방송과 같다).
- 스위치는 받는 사람에게만 전달한다. 효율적이고 안전하다(1대1 전달).
- 그래서 현대 LAN은 스위치 중심(스타형)이다. [1일차 LAN, WAN, 토폴로지](../day-01/lesson-5.md)를 본다.

{% hint style="warning" %}
CAUTION: 스위치도 처음에는 모른다. 켜진 직후 MAC 테이블이 비어 있으면 일단 모든 포트로 뿌린다(플러딩). 오가는 프레임을 보며 "이 MAC은 3번 포트에 있다"를 학습해 테이블을 채운다. 그래서 오늘 실습에서 첫 ping만 유독 느리다. 자세한 학습 과정은 [4일차 스위치와 라우터](../day-04/README.md)에서 다룬다.
{% endhint %}

### 2.3 스위치와 라우터의 브로드캐스트 경계

- 스위치는 같은 네트워크 안을 연결한다. 브로드캐스트를 통과시키므로 같은 브로드캐스트 도메인이다.
- 라우터는 네트워크와 네트워크를 연결한다. 브로드캐스트를 차단하므로 도메인이 분리된다.
- 브로드캐스트 도메인은 [1일차 캐스트](../day-01/lesson-7.md)에서 배운 그것이며, 2일차 서브넷팅으로 나눈 단위다.

### 2.4 두 가지 도메인

시험과 실무에 계속 나오는 구분이다. 말이 부딪히는 범위와 소리가 퍼지는 범위는 다르다.

| 구분 | 충돌 도메인(Collision Domain) | 브로드캐스트 도메인(Broadcast Domain) |
|---|---|---|
| 뜻 | 동시에 말하면 부딪히는 범위 | "전체 공지"가 닿는 범위 |
| 비유 | 한 사람씩만 말할 수 있는 좁은 회의실 | 방송이 들리는 건물 전체 |
| 나누는 장비 | 스위치(포트마다 분리) | 라우터(인터페이스마다 분리) |

장비별로 세어 보면 다음과 같다.

| 장비 | 충돌 도메인 | 브로드캐스트 도메인 |
|---|---|---|
| 허브(8포트) | 1개(전부 공유해 충돌이 발생한다) | 1개 |
| 스위치(8포트) | 8개(포트마다 따로) | 1개(브로드캐스트는 통과) |
| 라우터(2포트) | 2개 | 2개(인터페이스마다 분리) |

- 스위치는 충돌을 없애 주지만 브로드캐스트는 막지 못한다. 그래서 2일차에 서브넷팅으로 나눴다.
- 브로드캐스트 도메인을 나누려면 라우터를 쓴다. VLAN으로도 나눈다(4일차 이후).

한 줄 정리: 스위치는 충돌을, 라우터는 브로드캐스트를 끊는다.

### 2.5 케이블과 포트

장비를 골랐으면 선을 고른다. 오늘 PT에서 가장 많이 틀리는 부분이다.

| 케이블 | 언제 쓰나 | 예 |
|---|---|---|
| 다이렉트(Straight-Through) | 다른 종류 장비끼리 | PC와 스위치, 스위치와 라우터 |
| 크로스오버(Crossover) | 같은 종류 장비끼리 | PC와 PC, 스위치와 스위치, PC와 라우터 |
| 콘솔(Console, 하늘색) | 장비를 설정하러 접속할 때 | PC와 스위치/라우터 관리 포트 |
| 시리얼(Serial) | 라우터끼리 WAN 연결 | 라우터와 라우터(5일차) |

고르는 기준은 외우지 말고 두 그룹으로 묶는다.

```
그룹 A : PC, 라우터     (끝단에서 '말하는' 쪽)
그룹 B : 허브, 스위치   (가운데서 '이어주는' 쪽)

같은 그룹끼리   -> 크로스오버
다른 그룹끼리   -> 다이렉트
```

- PC와 라우터를 직접 연결하면 크로스오버다(둘 다 그룹 A). 헷갈리기 쉬운 조합이다.
- 요즘 실제 장비는 Auto-MDIX로 케이블 종류를 알아서 맞춘다. 그러나 PT의 구형 모델은 구분한다.
- 케이블 목록 맨 위의 번개 모양(Automatically Choose)을 쓰면 알아서 골라 준다. 학습 중에는 직접 고른다.

### 2.6 인터페이스 이름

실습에서 갑자기 나오는 이름이다. 규칙은 다음과 같다.

```
GigabitEthernet 0 / 0
|--- 속도/종류 ---| |   |--- 포트 번호
                    |------ 슬롯 번호
```

| 표기 | 원래 이름 | 속도 |
|---|---|---|
| `Fa0/1` | FastEthernet0/1 | 100 Mbps |
| `G0/0`, `Gi0/0` | GigabitEthernet0/0 | 1 Gbps |
| `S0/0/0` | Serial0/0/0 | WAN 회선 |

- 라우터 인터페이스와 슬롯 번호는 0부터 시작한다. 스위치 포트 번호는 보통 1부터 시작한다(`Fa0/1`).
- 장비에 실제로 몇 번 포트가 있는지는 `show ip interface brief`로 확인한다(4일차).
- PC의 랜카드는 NIC(Network Interface Card)다. MAC 주소가 새겨진 부품이며, 다음 문서에서 다룬다. [2. MAC 주소와 ARP](lesson-2.md)를 본다.

## 3. 동작 원리

장비별 전달 방식을 순서로 보면 다음과 같다.

1. 허브가 신호를 받는다. 모든 포트로 그대로 뿌린다. 판단하지 않는다.
2. 스위치가 프레임을 받는다. 출발지 MAC을 보고 "이 MAC은 이 포트에 있다"를 MAC 테이블에 학습한다.
3. 스위치가 목적지 MAC을 테이블에서 찾는다. 있으면 해당 포트로만 전달한다. 없으면 받은 포트를 제외한 모든 포트로 뿌린다(플러딩).
4. 라우터가 패킷을 받는다. 목적지 IP를 보고 다른 네트워크의 경로를 정해 내보낸다. 브로드캐스트는 넘기지 않는다.

## 4. 약어·용어

| 용어 | 풀이 |
|---|---|
| NIC | Network Interface Card, 랜카드 |
| MAC | Media Access Control, 2계층 물리 주소 |
| 플러딩(flooding) | MAC 테이블에 없는 목적지의 프레임을 모든 포트로 뿌리는 동작 |
| Auto-MDIX | 케이블 종류(다이렉트/크로스오버)를 장비가 자동으로 맞추는 기능 |
| WAN | Wide Area Network, 넓은 지역을 잇는 망 |

## 연습 문제

- PC 10대를 허브로 연결할 때와 스위치로 연결할 때, 무엇이 다른가? → 충돌과 효율이 다르다.
- 다른 네트워크(다른 서브넷)와 통신하려면 꼭 필요한 장비는? → 라우터.
- 도메인 세기: 24포트 스위치 1대에 PC 24대를 물리면 충돌 도메인은 24개, 브로드캐스트 도메인은 1개다.
- 케이블 고르기:
  - PC와 스위치는 다이렉트, 스위치와 스위치는 크로스오버다.
  - 스위치와 라우터는 다이렉트, PC와 라우터는 크로스오버다.
- 라우터를 처음 설정하려면 무슨 케이블로 접속하나? → 콘솔 케이블.
