## 3. 안전 사항

{% hint style="warning" %}
CAUTION: `arp -d *`는 ARP 테이블을 전부 지운다. 지운 직후 잠시 통신이 느려질 수 있다. 테이블은 통신하면 자동으로 다시 채워진다.
{% endhint %}

## 4. 준비

| 번호 | 항목 | 확인 방법 |
|---|---|---|
| 1 | 관리자 권한으로 명령 프롬프트를 연다 | 제목 표시줄에 `관리자`가 보인다 |
| 2 | 네트워크에 연결돼 있다 | `ipconfig`에 IPv4 주소가 보인다 |

## 5. 절차

### A. 내 MAC 주소 확인

1. (5-A-01) `ipconfig /all`을 입력한다. → 결과: 어댑터별 정보가 출력된다.
2. (5-A-02) 사용 중인 어댑터의 `물리적 주소`(Physical Address)를 찾는다. → 결과: `00-1A-2B-3C-4D-5E`와 같은 12자리 16진수가 보인다. Windows는 구분자로 `-`를 쓴다.
3. (5-A-03) 앞 3바이트(OUI)를 검색해 제조사를 찾는다. → 결과: 제조사 이름이 나온다.

### B. ARP 테이블 확인

1. (5-B-01) `arp -a`를 입력한다. → 결과: 내 PC가 알고 있는 IP와 MAC의 짝이 출력된다.
2. (5-B-02) 게이트웨이 주소가 목록에 있는지 확인한다. → 결과: 인터넷을 쓰고 있다면 반드시 있다.

### C. 캐시 비우고 다시 채우기

1. (5-C-01) `arp -d *`를 입력한다. → 결과: 오류 없이 끝난다.
2. (5-C-02) `arp -a`를 입력한다. → 결과: 목록이 비어 있다.
3. (5-C-03) `ping <게이트웨이 주소>`를 입력한다. → 결과: 응답이 온다.
4. (5-C-04) `arp -a`를 다시 입력한다. → 결과: 게이트웨이 항목이 다시 생겼다.

### D. 질문

- 옆자리 PC와 나는 서로 ARP로 찾을 수 있는데, 구글 서버의 MAC은 왜 못 찾을까? → 다른 네트워크라 브로드캐스트가 닿지 않는다. 대신 게이트웨이 MAC만 알면 된다.
- 패킷트레이서 Simulation으로 ARP 요청과 응답을 관찰하는 실습은 [4. 본 실습](lesson-4.md)과 [0. 복습 실습 Lab 6](lesson-0.md)에 있다.

## 6. 기능 확인

| 번호 | 확인 동작 | 기대 결과 | 합격 기준 |
|---|---|---|---|
| 1 | `ipconfig /all` | 물리적 주소가 보인다 | 12자리 16진수 |
| 2 | `arp -d *` 후 `arp -a` | 목록이 비어 있다 | 항목 없음 |
| 3 | `ping <게이트웨이 주소>` 후 `arp -a` | 게이트웨이 항목이 생긴다 | 게이트웨이 IP가 목록에 있다 |

## 7. 복구

별도의 복구는 필요 없다. ARP 테이블은 통신하면 자동으로 다시 채워진다.
