## 🎯 학습 목표

- MAC 주소가 무엇이고 IP 주소와 어떻게 다른지 이해한다
- IP를 알아도 실제 전달엔 MAC이 필요함을 안다
- ARP가 IP → MAC을 알아내는 과정을 설명한다
- **다른 네트워크로 보낼 때는 누구의 MAC을 찾는지** 설명한다
- **IP는 끝까지 그대로, MAC은 구간마다 바뀐다**는 것을 이해한다

## 🌉 다리 놓기: "IP만 알면 배달 끝일까?"

1·2일차의 IP는 **논리 주소**(어느 네트워크의 몇 번). → [README](../day-02/README.md)
그런데 같은 네트워크 안에서 **실제로 프레임을 건네주는** 건 **물리 주소 = MAC**이다. IP는 아는데 MAC을 모르면? → 그걸 알아내는 게 **ARP**.

## 📖 MAC 주소란?

- **48비트(6바이트)**, 16진수 표기 → 예 `00:1A:2B:3C:4D:5E`
- 네트워크 카드(NIC)에 **공장에서 새겨진 고유 번호**
- 앞 24비트 = 제조사(OUI), 뒤 24비트 = 일련번호

### IP vs MAC

| | IP 주소 | MAC 주소 |
|---|---------|----------|
| 성격 | 논리 주소(3계층) | 물리 주소(2계층) |
| 변경 | 위치·망 따라 **바뀜** | 장비에 **고정** |
| 비유 | 현재 사는 집 주소 | 주민등록번호 |

> 💡 택배 비유: **IP**로 "어느 동네·건물"까지 가고, 마지막엔 **MAC**으로 "바로 그 사람"에게 건넨다.

## 📖 ARP — IP로 MAC 물어보기

같은 네트워크에서 상대 IP는 아는데 MAC을 모를 때:

```
① ARP 요청 (브로드캐스트)
   "192.168.0.20 쓰는 분? MAC 좀 알려주세요!"  → 네트워크 전체에 뿌림
② ARP 응답 (유니캐스트)
   "저요! 제 MAC은 00:1A:2B:3C:4D:5E 입니다."  → 물어본 PC에게만
③ 알아낸 MAC을 ARP 테이블에 저장(캐시)하고, 이제 프레임 전달
```

- **요청은 브로드캐스트, 응답은 유니캐스트** → 1일차 캐스트가 여기서 실제로 쓰인다! ([7_캐스트_유니_브로드_멀티](../day-01/lesson-7.md))
- 그래서 "ARP가 왜 브로드캐스트로 시작?" = **누구 MAC인지 모르니 동네 전체에 물어봄**

## 📖 다른 네트워크로 보낼 때는? — 게이트웨이의 MAC을 찾는다

여기가 오늘의 **핵심**이다. 2일차에서 "다른 동네면 게이트웨이에게 맡긴다"고 했던 그 이야기.

> ❓ `192.168.10.1` 인 내 PC가 `192.168.20.5` 로 보내려 한다. 누구의 MAC을 물어볼까?

**답: 목적지가 아니라 기본 게이트웨이(라우터)의 MAC.**

```
① 마스크로 판단     "192.168.20.5 는 내 동네가 아니네" (2일차 판별법!)
② 그럼 대문으로     → 기본 게이트웨이 192.168.10.254 에게 맡긴다
③ ARP 요청          "192.168.10.254 쓰는 분 MAC 좀!"   ← 게이트웨이를 찾는다
④ 프레임 전송        목적지 MAC = 라우터,  목적지 IP = 192.168.20.5
```

- **브로드캐스트는 라우터를 못 넘는다.** 애초에 다른 동네에 ARP를 보낼 수도 없다 → [1_네트워크장비](lesson-1.md)의 브로드캐스트 도메인
- 그래서 게이트웨이가 잘못 설정되면 **다른 망 통신만** 실패한다 → [3_공인IP와_사설IP](../day-02/lesson-3.md)

### 그래서 — IP는 끝까지, MAC은 구간마다

편지에 비유하면 **최종 주소(IP)는 봉투에 그대로 적혀 있고**, 매 구간의 **집배원(MAC)만 바뀐다.**

```
[PC1] ──구간 1──▶ [라우터] ──구간 2──▶ [PC2]

구간 1   출발 MAC: PC1     목적지 MAC: 라우터 G0/0
구간 2   출발 MAC: 라우터 G0/1   목적지 MAC: PC2
──────────────────────────────────────────────
IP 는 두 구간 모두   출발 192.168.10.1  →  목적지 192.168.20.5   (그대로!)
```

- 라우터는 도착한 프레임의 **껍데기(MAC)를 벗기고, 다음 구간용으로 새로 씌워** 보낸다
- 그래서 라우터를 지날 때마다 **ARP가 새로 일어난다**

> 💡 한 줄: **IP = 최종 목적지(안 바뀜) / MAC = 바로 다음 장비(구간마다 바뀜)**
> 오늘 실습의 Simulation 모드에서 패킷을 클릭해 **이 두 줄이 다른 것**을 직접 확인한다.

## 📖 프레임 안을 들여다보면

1일차 **캡슐화**([6_프로토콜_OSI7계층](../day-01/lesson-6.md))가 여기서 실물로 보인다.

```
┌────────── 2계층 프레임 ──────────────────────────────────┐
│ 목적지 MAC │ 출발지 MAC │ 타입 │ ┌── 3계층 패킷 ──────┐ │ FCS │
│            │            │      │ │ 출발 IP │ 목적 IP │ │     │
└──────────────────────────────────┴────────────────────┴─────┘
       ↑ 구간마다 바뀜                        ↑ 끝까지 그대로
```

- **FCS**: 전송 중 깨졌는지 확인하는 검사값
- 브로드캐스트 프레임의 목적지 MAC은 `FF:FF:FF:FF:FF:FF` (1일차 캐스트에서 본 그것)

## 📖 ARP 테이블(캐시) 관리

- 한 번 알아낸 IP↔MAC은 **몇 분간 저장**해 둔다 → 매번 물어보면 낭비니까
- 시간이 지나면 사라진다(장비가 바뀔 수 있으므로) → 그래서 **한참 뒤 첫 ping이 또 느려진다**

```bash
arp -a          # 내 PC의 ARP 테이블 보기
arp -d *        # 전부 지우기 (관리자 권한 필요)
```

> ⚠️ **보안 예고**: ARP는 "제가 그 IP예요!"라는 응답을 **검증 없이 믿는다**.
> 이걸 악용하는 것이 **ARP 스푸핑**이다 → 2단계 서버 보안에서 → [11일차 · 서버 보안](../../network2/day-11/README.md)

## 🧪 실습 / 질문

- `ipconfig /all` → 내 **물리적 주소(MAC)** 찾기
  - 앞 3바이트(OUI)를 검색해 **제조사 맞히기** (예: `00:1A:2B` → 어느 회사?)
- `arp -a` → 내 PC가 알고 있는 IP↔MAC 매핑 확인
  - **게이트웨이 주소가 목록에 있는지** 확인해보자 (인터넷을 쓰고 있다면 반드시 있다)
- **캐시 비우고 다시 채우기**: `arp -d *` → `arp -a`(비었나?) → `ping 게이트웨이` → `arp -a`(다시 생겼나?)
- 질문: 옆자리 PC와 나는 서로 ARP로 찾을 수 있는데, **구글 서버의 MAC은 왜 못 찾을까?**
  - (답: 다른 네트워크라 브로드캐스트가 닿지 않는다. 대신 **게이트웨이 MAC**만 알면 된다)
- 오늘 실습에서 패킷트레이서 Simulation으로 ARP 요청·응답 패킷 관찰 → [4_패킷트레이서_실습](lesson-4.md)

## 📝 강의 메모

- "IP=어디까지, MAC=바로 그 사람" 대비로 각인
- ARP 3단계(브로드캐스트 요청 → 유니캐스트 응답 → 캐시)를 그림으로
- **"다른 망이면 게이트웨이 MAC"이 오늘의 하이라이트** — 2일차 판별법의 회수 지점이니 시간을 넉넉히
- Simulation 모드에서 패킷을 클릭해 **MAC은 바뀌고 IP는 그대로**인 것을 반드시 눈으로 보여줄 것
- OUI 검색은 학생들이 재미있어함 → 흥미 유발용으로 짧게
