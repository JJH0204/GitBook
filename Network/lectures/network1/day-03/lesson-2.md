## 학습 목표

- MAC 주소가 무엇이고 IP 주소와 어떻게 다른지 이해한다.
- IP를 알아도 실제 전달에는 MAC이 필요함을 안다.
- ARP가 IP를 MAC으로 알아내는 과정을 설명한다.
- 다른 네트워크로 보낼 때 누구의 MAC을 찾는지 설명한다.
- IP는 끝까지 그대로, MAC은 구간마다 바뀐다는 것을 이해한다.

## 1. 목적

1·2일차의 IP는 논리 주소다(어느 네트워크의 몇 번). [2일차 IP와 서브넷](../day-02/README.md)을 본다. 같은 네트워크 안에서 실제로 프레임을 건네주는 것은 물리 주소인 MAC이다. IP는 아는데 MAC을 모를 때 알아내는 프로토콜이 ARP다. 택배로 비유하면 IP로 "어느 동네, 어느 건물"까지 가고, 마지막에는 MAC으로 "바로 그 사람"에게 건넨다.

## 2. 구성 요소

### 2.1 MAC 주소

- 48비트(6바이트)이며 16진수로 표기한다. 예: `00:1A:2B:3C:4D:5E`
- 네트워크 카드(NIC)에 공장에서 새겨진 고유 번호다.
- 앞 24비트는 제조사(OUI), 뒤 24비트는 일련번호다.

| 구분 | IP 주소 | MAC 주소 |
|---|---|---|
| 성격 | 논리 주소(3계층) | 물리 주소(2계층) |
| 변경 | 위치와 망에 따라 바뀐다 | 장비에 고정된다 |
| 비유 | 현재 사는 집 주소 | 주민등록번호 |

### 2.2 ARP

ARP(Address Resolution Protocol)는 같은 네트워크에서 상대 IP는 아는데 MAC을 모를 때 쓴다.

| 단계 | 이름 | 전달 방식 | 내용 |
|---|---|---|---|
| 1 | ARP 요청 | 브로드캐스트 | "192.168.0.20 쓰는 분? MAC을 알려 주세요." 네트워크 전체에 뿌린다 |
| 2 | ARP 응답 | 유니캐스트 | "저입니다. 제 MAC은 `00:1A:2B:3C:4D:5E`입니다." 물어본 PC에게만 보낸다 |
| 3 | 캐시 저장 | – | 알아낸 MAC을 ARP 테이블에 저장하고 프레임을 전달한다 |

- 요청은 브로드캐스트, 응답은 유니캐스트다. 1일차 캐스트가 여기서 실제로 쓰인다. [1일차 캐스트](../day-01/lesson-7.md)를 본다.
- ARP가 브로드캐스트로 시작하는 이유는 누구의 MAC인지 모르니 동네 전체에 물어보기 때문이다.

### 2.3 프레임 구조

1일차 캡슐화([1일차 프로토콜 OSI 7계층](../day-01/lesson-6.md))가 여기서 실물로 보인다. 2계층 프레임은 3계층 패킷을 감싼다.

| 순서 | 필드 | 계층 | 바뀌는 시점 |
|---|---|---|---|
| 1 | 목적지 MAC | 2 | 구간마다 바뀐다 |
| 2 | 출발지 MAC | 2 | 구간마다 바뀐다 |
| 3 | 타입 | 2 | – |
| 4 | 출발 IP | 3 | 끝까지 그대로다 |
| 5 | 목적 IP | 3 | 끝까지 그대로다 |
| 6 | (데이터) | 4 이상 | – |
| 7 | FCS | 2 | 전송 중 깨졌는지 확인하는 검사값 |

- 브로드캐스트 프레임의 목적지 MAC은 `FF:FF:FF:FF:FF:FF`다(1일차 캐스트에서 본 그것).

### 2.4 ARP 테이블(캐시)

- 한 번 알아낸 IP와 MAC의 짝은 몇 분간 저장한다. 매번 물어보면 낭비이기 때문이다.
- 시간이 지나면 사라진다(장비가 바뀔 수 있기 때문이다). 그래서 한참 뒤의 첫 ping이 다시 느려진다.

| 명령 | 뜻 |
|---|---|
| `arp -a` | 내 PC의 ARP 테이블을 본다 |
| `arp -d *` | 전부 지운다(Windows는 관리자 권한이 필요하다) |

{% hint style="warning" %}
CAUTION: ARP는 "내가 그 IP다"라는 응답을 검증 없이 믿는다. 이것을 악용하는 공격이 ARP 스푸핑이다. 방어는 2단계 서버 보안에서 다룬다. [11일차 서버 보안](../../network2/day-11/README.md)을 본다.
{% endhint %}

## 3. 동작 원리

### 3.1 같은 네트워크로 보낼 때

2.2절의 3단계를 따른다. 요청은 브로드캐스트, 응답은 유니캐스트이며 결과는 캐시에 저장된다.

### 3.2 다른 네트워크로 보낼 때: 게이트웨이의 MAC을 찾는다

오늘의 핵심이다. 2일차에서 "다른 동네면 게이트웨이에게 맡긴다"고 한 내용이다.

질문: `192.168.10.1`인 PC가 `192.168.20.5`로 보내려 한다. 누구의 MAC을 물어볼까? 답은 목적지가 아니라 기본 게이트웨이(라우터)의 MAC이다.

1. 마스크로 판단한다. "192.168.20.5는 내 동네가 아니다"(2일차 판별법).
2. 기본 게이트웨이 `192.168.10.254`에게 맡기기로 한다.
3. ARP 요청을 보낸다. "192.168.10.254 쓰는 분 MAC을 알려 주세요." 게이트웨이를 찾는다.
4. 프레임을 보낸다. 목적지 MAC은 라우터, 목적지 IP는 `192.168.20.5`다.

- 브로드캐스트는 라우터를 넘지 못한다. 애초에 다른 동네에는 ARP를 보낼 수 없다. [1. 네트워크 장비](lesson-1.md)의 브로드캐스트 도메인을 본다.
- 그래서 게이트웨이가 잘못 설정되면 다른 망 통신만 실패한다. [2일차 공인 IP와 사설 IP](../day-02/lesson-3.md)를 본다.

### 3.3 IP는 끝까지, MAC은 구간마다

편지에 비유하면 최종 주소(IP)는 봉투에 그대로 적혀 있고, 구간마다 집배원(MAC)만 바뀐다.

```
[PC1] --구간 1--> [라우터] --구간 2--> [PC2]
```

| 구간 | 출발 MAC | 목적지 MAC | 출발 IP | 목적지 IP |
|---|---|---|---|---|
| 구간 1 | PC1 | 라우터 G0/0 | 192.168.10.1 | 192.168.20.5 |
| 구간 2 | 라우터 G0/1 | PC2 | 192.168.10.1 | 192.168.20.5 |

- 라우터는 도착한 프레임의 껍데기(MAC)를 벗기고, 다음 구간용으로 새로 씌워 보낸다.
- 그래서 라우터를 지날 때마다 ARP가 새로 일어난다.

한 줄 정리: IP는 최종 목적지(안 바뀜), MAC은 바로 다음 장비(구간마다 바뀜)다. 실습의 Simulation 모드에서 패킷을 클릭해 이 두 줄이 다른 것을 직접 확인한다. [4. 본 실습](lesson-4.md)을 본다.

## 4. 약어·용어

| 용어 | 풀이 |
|---|---|
| MAC | Media Access Control, 2계층 물리 주소 |
| OUI | Organizationally Unique Identifier, MAC 앞 24비트의 제조사 식별자 |
| NIC | Network Interface Card, 랜카드 |
| ARP | Address Resolution Protocol, IP를 MAC으로 알아내는 프로토콜 |
| FCS | Frame Check Sequence, 프레임 검사값 |
| 기본 게이트웨이 | 다른 네트워크로 나가는 문이 되는 라우터 주소 |

## 강의 메모

- "IP는 어디까지, MAC은 바로 그 사람"의 대비로 각인한다.
- ARP 3단계(브로드캐스트 요청, 유니캐스트 응답, 캐시)를 그림으로 설명한다.
- "다른 망이면 게이트웨이 MAC"이 오늘의 하이라이트다. 2일차 판별법의 회수 지점이니 시간을 넉넉히 쓴다.
- Simulation 모드에서 패킷을 클릭해 MAC은 바뀌고 IP는 그대로인 것을 반드시 눈으로 보여 준다.
- OUI 검색은 학생들이 재미있어한다. 흥미 유발용으로 짧게 한다.
