## 🧪 Lab 7 — 라우터로 두 네트워크 잇기

**시작** — `03_스위치.pkt` 를 열고 **다른 이름으로 저장** → `03_라우터.pkt`
(복습 파일은 Lab 9 에서 다시 쓴다)

**구성**: `PC0 — SW1 — Router — SW2 — PC2` (서로 다른 두 네트워크)

| 장비 | IP 주소 | 마스크 | 게이트웨이 |
|------|---------|--------|-----------|
| PC0 | 192.168.10.1 | /24 | **192.168.10.254** |
| PC2 | 192.168.20.1 | /24 | **192.168.20.254** |
| 라우터 G0/0 | 192.168.10.254 | /24 | — |
| 라우터 G0/1 | 192.168.20.254 | /24 | — |

**만드는 순서**

1. 기존 `PC1` 을 지우고, 스위치 1대 · 라우터 1대 · PC 1대를 추가한다
2. 라우터 ↔ 스위치는 **다이렉트 케이블** → [1_네트워크장비](lesson-1.md)
3. 각 PC 의 `IP Configuration` 에서 **`Default Gateway` 칸까지** 채운다 ← 복습 때는 비워뒀던 칸

> 💡 서로 **다른 네트워크**(10.x ↔ 20.x)라 스위치만으로는 안 된다. **라우터**가 있어야 한다.

### 라우터 설정하기 — `Config` 탭

라우터는 사자마자 쓸 수 없다. **인터페이스에 IP 를 주고, 전원을 켜듯 활성화**해야 한다.

1. 라우터 클릭 → **`Config` 탭**
2. 왼쪽에서 **`GigabitEthernet0/0`** 선택
3. `IPv4 Address` `192.168.10.254` · `Subnet Mask` `255.255.255.0` 입력
4. 🚨 위쪽 **`Port Status` 를 `On`** 으로 체크 ← **가장 많이 빠뜨린다**
5. `GigabitEthernet0/1` 에 `192.168.20.254` 로 같은 작업

> 💡 같은 일을 **명령어(CLI)로 하는 방법은 4일차**에 제대로 배운다. 오늘은 GUI 로 충분하다.
> → [3_CLI기초와_실습](../day-04/lesson-3.md)

### 설정이 됐는지 확인

라우터 → `CLI` 탭 → `enable` → 아래 한 줄

```
show ip interface brief
```

| 보이는 것 | 뜻 |
|-----------|-----|
| `up` / `up` | ✅ 정상 |
| `administratively down` | ❌ `Port Status` 를 켜지 않았다 |
| `down` / `down` | ❌ 케이블이 안 꽂혔거나 종류가 틀렸다 |

> ⚠️ 라우터 모델에 따라 인터페이스 이름이 `G0/0` 이 아니라 `G0/0/0` 일 수 있다.
> 이 명령으로 **실제로 뭐가 있는지 먼저 확인**하면 된다.

### 테스트 — 3일차에 배운 순서 그대로

[3_ICMP와_ping](lesson-3.md) 의 **5단계**를 그대로 따라간다. 한 번에 목적지를 치지 말 것.

1. `ping 192.168.10.254` — 내 게이트웨이(대문)까지 되는가
2. `ping 192.168.20.1` — 그 너머 PC2 까지 되는가

**✅ 여기까지 확인하고 넘어가기**

- [ ] `show ip interface brief` 에서 두 인터페이스 모두 `up`/`up`
- [ ] PC0 → 게이트웨이 ping 성공
- [ ] PC0 → PC2 ping 성공
- [ ] PC0 에서 `arp -a` → 목록에 **PC2 가 아니라 게이트웨이(192.168.10.254)** 가 있는가?
  - 왜 그런지 설명할 수 있는가? → [2_MAC주소와_ARP](lesson-2.md)

## 🧪 Lab 8 — 라우터 구간 관찰: MAC 은 바뀌고 IP 는 그대로 ⭐

복습 Lab 6 에서는 **스위치 구간**만 봤다. 이번엔 **라우터를 지나는 구간**을 본다.
[2_MAC주소와_ARP](lesson-2.md) 의 핵심을 눈으로 확인하는 순간이다.

**순서**

1. `Simulation` 모드 · 필터는 ARP·ICMP (복습 Lab 6 과 같은 설정)
2. PC0 → `ping 192.168.20.1`
3. 봉투를 클릭 → **`Inbound PDU Details`** 를 **두 구간에서 각각** 열어본다

| 어디서 | 목적지 MAC | 목적지 IP |
|--------|-----------|-----------|
| PC0 → 라우터 구간 | **라우터 G0/0** 의 MAC | 192.168.20.1 |
| 라우터 → PC2 구간 | **PC2** 의 MAC | 192.168.20.1 |

- **MAC 은 구간마다 바뀌는데 IP 는 끝까지 같다**
- 두 화면을 나란히 띄워 **직접 비교**하게 할 것

**🗣 물어볼 것**

- "왜 PC0 는 PC2 의 MAC 을 모를까요?" → 브로드캐스트가 **라우터를 못 넘으니까**
- "그럼 PC0 는 누구의 MAC 을 찾았을까요?" → **게이트웨이** (`arp -a` 로 확인했던 그것)

## 🧪 Lab 9 — 마스크만 바꿔서 통신 끊어보기 (2일차 회수)

**시작** — `03_스위치.pkt` 를 다시 연다 (라우터 없는 구성)

2일차에 **"IP + 마스크가 한 세트"** 라고 했던 것을 **실제로** 확인한다.
→ [4_서브넷팅](../day-02/lesson-4.md)

| 단계 | PC0 | PC1 | ping 결과 |
|------|-----|-----|-----------|
| ① | `192.168.10.1` **/24** | `192.168.10.100` **/24** | ✅ 성공 |
| ② | `192.168.10.1` **/26** | `192.168.10.100` **/26** | ❌ **실패** |

- **IP 는 하나도 안 건드렸다. 마스크만 바꿨다.** 그런데 통신이 끊긴다
- 왜? 블록 크기 64 → `.1` 은 `192.168.10.0` 동네, `.100` 은 `192.168.10.64` 동네 → **다른 동네**
- 같은 스위치에 꽂혀 있어도 소용없다 → 라우터(게이트웨이)가 필요하다

**🗣 물어볼 것**

- "ping 메시지가 뭐라고 뜨나요?" → [3_ICMP와_ping](lesson-3.md) 의 메시지 표로 원인 짚기
- "Lab 3 에서 클래스가 자동으로 채워준 마스크를, 왜 직접 바꿔야 할까요?" → 필요한 만큼 나누려고

## ⚠️ 자주 나는 오류 — 이것부터 확인

| 증상 | 유력한 원인 | 해결 |
|------|-----------|------|
| 링크에 **빨간 점** | 케이블 종류 · 포트 비활성 | 다이렉트/크로스오버 확인, `Port Status On` |
| 링크에 **주황 점** | 스위치 포트 준비 중 | **30초 기다린다** (이유는 4일차) |
| 첫 ping 만 실패 | ARP · 플러딩 (**정상**) | 한 번 더 실행 |
| 같은 망인데 실패 | IP·마스크 오타 | 두 PC 의 마스크가 같은지 |
| **다른 망만** 실패 | **게이트웨이 미설정** | PC 의 `Default Gateway` 칸 |
| `Destination host unreachable` | 게이트웨이 오타 · 인터페이스 down | `show ip interface brief` |
| 라우터에 IP 를 줬는데 안 됨 | **`Port Status` Off** | `administratively down` 인지 확인 |
| IP 가 `169.254.x.x` | DHCP 로 되어 있다 | `Static` 으로 전환 (복습 Lab 5) |
