## 5. 절차

### A. Lab 7. 라우터로 두 네트워크 잇기

구성은 `PC0 - SW1 - Router - SW2 - PC2`다(서로 다른 두 네트워크).

| 장비 | IP 주소 | 마스크 | 게이트웨이 |
|---|---|---|---|
| PC0 | `192.168.10.1` | `/24`(`255.255.255.0`) | `192.168.10.254` |
| PC2 | `192.168.20.1` | `/24`(`255.255.255.0`) | `192.168.20.254` |
| 라우터 G0/0 | `192.168.10.254` | `/24`(`255.255.255.0`) | 없음 |
| 라우터 G0/1 | `192.168.20.254` | `/24`(`255.255.255.0`) | 없음 |

**구성을 만든다.**

1. (5-A-01) `03_스위치.pkt`를 연다.
2. (5-A-02) 다른 이름으로 저장한다: `03_라우터.pkt`. → 결과: 제목 표시줄에 `03_라우터.pkt`가 보인다. 복습 파일은 Lab 9에서 다시 쓴다.
3. (5-A-03) 기존 `PC1`을 지운다.
4. (5-A-04) 스위치 1대, 라우터 1대, PC 1대를 추가한다. → 결과: 장비가 작업 화면에 나타난다.
5. (5-A-05) 라우터와 스위치를 다이렉트 케이블로 연결한다. → 결과: 링크 점이 초록이 된다. 케이블 선택은 [1. 네트워크 장비](lesson-1.md)를 따른다.
6. (5-A-06) 각 PC의 `IP Configuration`에서 `Default Gateway` 칸까지 위 표대로 채운다. → 결과: 복습 때 비워 둔 칸이 채워진다.

{% hint style="info" %}
NOTE: 서로 다른 네트워크(10.x와 20.x)라 스위치만으로는 통신할 수 없다. 라우터가 있어야 한다.
{% endhint %}

**라우터를 설정한다(`Config` 탭).** 라우터는 사자마자 쓸 수 없다. 인터페이스에 IP를 주고 활성화해야 한다.

7. (5-A-07) 라우터를 클릭하고 `Config` 탭을 연다.
8. (5-A-08) 왼쪽에서 `GigabitEthernet0/0`을 선택한다.
9. (5-A-09) `IPv4 Address`에 `192.168.10.254`, `Subnet Mask`에 `255.255.255.0`을 입력한다. → 결과: 값이 저장된다.

{% hint style="warning" %}
CAUTION: 다음 단계의 `Port Status` 체크를 빠뜨리면 인터페이스가 `administratively down`으로 남는다.
{% endhint %}

10. (5-A-10) 위쪽 `Port Status`를 `On`으로 체크한다. → 결과: 링크 점이 초록이 된다.
11. (5-A-11) `GigabitEthernet0/1`을 선택하고 `192.168.20.254` / `255.255.255.0`으로 같은 작업을 한다. → 결과: 두 인터페이스 모두 설정된다.

**설정을 확인한다.**

12. (5-A-12) 라우터의 `CLI` 탭에서 `enable`을 입력한다.
13. (5-A-13) `show ip interface brief`를 입력한다. → 결과: 인터페이스 목록이 출력된다. 아래 표로 읽는다.

| 보이는 것 | 뜻 |
|---|---|
| `up` / `up` | 정상 |
| `administratively down` | `Port Status`를 켜지 않았다 |
| `down` / `down` | 케이블이 안 꽂혔거나 종류가 틀렸다 |

{% hint style="info" %}
NOTE: 라우터 모델에 따라 인터페이스 이름이 `G0/0`이 아니라 `G0/0/0`일 수 있다. 이 명령으로 실제로 무엇이 있는지 먼저 확인한다.
{% endhint %}

**테스트한다.** [3. ICMP와 ping](lesson-3.md)의 5단계를 따른다. 한 번에 목적지를 치지 않는다.

14. (5-A-14) PC0의 `Command Prompt`에서 `ping 192.168.10.254`를 입력한다(내 게이트웨이). → 결과: 성공한다.
15. (5-A-15) `ping 192.168.20.1`을 입력한다(그 너머 PC2). → 결과: 성공한다.
16. (5-A-16) `arp -a`를 입력한다. → 결과: 목록에 PC2가 아니라 게이트웨이(`192.168.10.254`)가 있다. 이유는 [2. MAC 주소와 ARP](lesson-2.md)에서 설명한다.
17. (5-A-17) `Ctrl + S`를 눌러 `03_라우터.pkt`로 저장한다. → 결과: 파일이 저장된다. 4일차 Lab 11, 12에서 이어 쓴다.

**여기까지 확인하고 넘어간다.**

- [ ] `show ip interface brief`에서 두 인터페이스 모두 `up`/`up`

### B. Lab 8. 라우터 구간 관찰: MAC은 바뀌고 IP는 그대로

복습 Lab 6에서는 스위치 구간만 봤다. 이번에는 라우터를 지나는 구간을 본다. [2. MAC 주소와 ARP](lesson-2.md)의 핵심을 눈으로 확인한다.

1. (5-B-01) `Simulation` 모드로 전환한다. 필터는 ARP와 ICMP로 한다(복습 Lab 6과 같은 설정). → 결과: 시뮬레이션 패널이 나타난다.
2. (5-B-02) PC0에서 `ping 192.168.20.1`을 입력한다. → 결과: 봉투 아이콘이 생긴다.
3. (5-B-03) `Capture / Forward`로 봉투를 진행시킨다.
4. (5-B-04) PC0과 라우터 사이 구간의 봉투를 클릭하고 `Inbound PDU Details`를 연다. → 결과: 목적지 MAC과 목적지 IP가 보인다.
5. (5-B-05) 라우터와 PC2 사이 구간의 봉투를 클릭하고 `Inbound PDU Details`를 연다. → 결과: 목적지 MAC과 목적지 IP가 보인다.
6. (5-B-06) 두 화면을 나란히 놓고 비교한다. → 결과: 아래 표와 같다.

| 어디서 | 목적지 MAC | 목적지 IP |
|---|---|---|
| PC0에서 라우터 구간 | 라우터 G0/0의 MAC | `192.168.20.1` |
| 라우터에서 PC2 구간 | PC2의 MAC | `192.168.20.1` |

- MAC은 구간마다 바뀌는데 IP는 끝까지 같다.
- 화면 하나만 보면 의미가 없다. 두 화면을 직접 비교한다.

**질문과 답**

- PC0는 왜 PC2의 MAC을 모를까? → 브로드캐스트가 라우터를 넘지 못하기 때문이다.
- 그러면 PC0는 누구의 MAC을 찾았을까? → 게이트웨이다(`arp -a`로 확인한 것).

### C. Lab 9. 마스크만 바꿔서 통신 끊어 보기

2일차의 "IP와 마스크는 한 세트"를 실제로 확인한다. [2일차 서브넷팅](../day-02/lesson-4.md)을 본다.

1. (5-C-01) `03_스위치.pkt`를 다시 연다. → 결과: 라우터 없는 구성이 열린다.
2. (5-C-02) PC0을 `192.168.10.1` / `/24`(`255.255.255.0`)로, PC1을 `192.168.10.100` / `/24`로 설정한다.
3. (5-C-03) PC0에서 `ping 192.168.10.100`을 입력한다. → 결과: 성공한다.
4. (5-C-04) PC0을 `192.168.10.1` / `/26`(`255.255.255.192`)로, PC1을 `192.168.10.100` / `/26`으로 바꾼다. IP는 건드리지 않는다.
5. (5-C-05) PC0에서 `ping 192.168.10.100`을 다시 입력한다. → 결과: 실패한다. 어떤 메시지가 뜨는지 기록한다.

| 단계 | PC0 | PC1 | ping 결과 |
|---|---|---|---|
| 1 | `192.168.10.1` /24 | `192.168.10.100` /24 | 성공 |
| 2 | `192.168.10.1` /26 | `192.168.10.100` /26 | 실패 |

- IP는 하나도 건드리지 않았다. 마스크만 바꿨는데 통신이 끊긴다.
- 이유: 블록 크기가 64이므로 `.1`은 `192.168.10.0` 동네, `.100`은 `192.168.10.64` 동네다. 서로 다른 동네다.
- 같은 스위치에 꽂혀 있어도 소용없다. 라우터(게이트웨이)가 필요하다.

**질문과 답**

- ping 메시지가 무엇이라고 뜨는가? → [3. ICMP와 ping](lesson-3.md)의 메시지 표로 원인을 짚는다.
- Lab 3에서 클래스가 자동으로 채워 준 마스크를 왜 직접 바꿔야 하는가? → 필요한 만큼 나누려고 한다.

{% endhint %}

### 자주 나는 오류

| 증상 | 유력한 원인 | 해결 |
|---|---|---|
| 링크에 빨간 점 | 케이블 종류, 포트 비활성 | 다이렉트/크로스오버 확인, `Port Status On` |
| 링크에 주황 점 | 스위치 포트 준비 중 | 30초 기다린다(이유는 4일차) |
| 첫 ping만 실패 | ARP와 플러딩(정상) | 한 번 더 실행한다 |
| 같은 망인데 실패 | IP, 마스크 오타 | 두 PC의 마스크가 같은지 확인한다 |
| 다른 망만 실패 | 게이트웨이 미설정 | PC의 `Default Gateway` 칸을 채운다 |
| `Destination host unreachable` | 게이트웨이 오타, 인터페이스 down | `show ip interface brief`로 확인한다 |
| 라우터에 IP를 줬는데 안 됨 | `Port Status`가 Off | `administratively down`인지 확인한다 |
| IP가 `169.254.x.x` | DHCP로 되어 있다 | `Static`으로 전환한다(복습 Lab 5) |
