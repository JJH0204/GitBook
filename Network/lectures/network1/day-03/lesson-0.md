### A. Lab 1. 화면 익히기와 구성 만들기

| 위치 | 내용 |

| 오른쪽 아래 | `Realtime`(실제처럼 동작)과 `Simulation`(한 걸음씩 관찰) 전환 |

링크 점 색깔은 오늘 내내 가장 먼저 본다.

| 점 색 | 뜻 | 할 일 |
|---|---|---|
| 초록 | 정상 | 없음 |
| 주황 | 스위치 포트가 준비 중 | 30초쯤 기다리면 초록이 된다 |

{% hint style="info" %}
NOTE: 주황 점은 고장이 아니다. 이유(STP)는 4일차에서 다룬다. [4일차 스위치 동작 원리](../day-04/lesson-1.md)를 본다.

### B. Lab 2. IP가 없으면 아무것도 안 된다

이 Lab은 1일차 [데이터는 어디로 갈까](../day-01/lesson-4.md)를 되짚는다. "봉투에 주소가 없으면 배달되지 않는다."

**주소 없이 먼저 확인한다.**

1. (5-B-01) `PC0`을 클릭하고 `Desktop` > `Command Prompt`를 연다.
2. (5-B-02) `ipconfig`를 입력한다. → 결과: IP 주소가 `0.0.0.0`이다.
3. (5-B-03) `ping 192.168.10.2`를 입력한다. → 결과: 실패한다.

**주소를 준다.**

| 장비 | IPv4 Address | Subnet Mask |
|---|---|---|
| PC0 | `192.168.10.1` | `255.255.255.0` |
| PC1 | `192.168.10.2` | `255.255.255.0` |

4. (5-B-04) 각 PC에서 `Desktop` > `IP Configuration`을 열고 `Static`을 선택한다.
5. (5-B-05) 위 표의 값을 입력한다. → 결과: 입력한 값이 유지된다.
6. (5-B-06) PC0의 `Command Prompt`에서 `ping 192.168.10.2`를 다시 입력한다. → 결과: 성공한다. 첫 번째 ping은 실패할 수 있다.

{% hint style="info" %}
NOTE: 첫 ping이 한 번쯤 실패하는 이유는 오늘 2교시(ARP, 스위치)에서 밝혀진다.
{% endhint %}

**질문과 답**

- 선은 그대로였는데 아까는 왜 안 됐을까? → 주소가 없어서다.
- 선만 이으면 통신이 되는 것이 아니라는 뜻인가? → 그렇다. 연결과 주소가 둘 다 필요하다.

**확인**: ping 4번 중 3~4번이 성공한다(첫 번째 실패는 정상이다).

### C. Lab 3. 클래스가 기본 마스크를 정한다

이 Lab은 2일차 [IP 클래스와 서브넷 마스크](../day-02/lesson-2.md)를 되짚는다. PT는 IP를 입력하고 `Tab`을 누르면 첫 옥텟을 보고 기본 마스크를 자동으로 채운다.

| 입력한 IP | 자동으로 채워지는 마스크 | 클래스 |
|---|---|---|
| `10.0.0.1` | `255.0.0.0` | A |
| `172.16.0.1` | `255.255.0.0` | B |
| `192.168.0.1` | `255.255.255.0` | C |

1. (5-C-01) `PC0`의 `IP Configuration`을 연다.
2. (5-C-02) IP 칸에 위 표의 첫 번째 값 `10.0.0.1`을 입력하고 `Tab`을 누른다. → 결과: 마스크 칸이 `255.0.0.0`으로 바뀐다.
3. (5-C-03) 두 번째 값 `172.16.0.1`로 같은 동작을 반복한다. → 결과: 마스크 칸이 `255.255.0.0`으로 바뀐다.
4. (5-C-04) 세 번째 값 `192.168.0.1`로 같은 동작을 반복한다. → 결과: 마스크 칸이 `255.255.255.0`으로 바뀐다.
5. (5-C-05) 설정을 `192.168.10.1` / `255.255.255.0`(Lab 2 상태)으로 되돌린다. → 결과: Lab 2의 값과 같다.

**질문과 답**

- 프로그램이 어떻게 알았을까? → 첫 옥텟만 보고 안다(10은 A, 172는 B, 192는 C).
- `/26` 같은 마스크는 어떻게 되나? → 자동으로 채워지지 않는다. 직접 입력해야 한다. 클래스는 옛 방식이고, 요즘은 마스크를 자유롭게 정한다. 직접 해 보는 실습은 [본 실습 Lab 9](lesson-4.md)다.

### D. Lab 4. 사설 IP 세 대역 다 써 보기

이 Lab은 2일차 [공인 IP와 사설 IP](../day-02/lesson-3.md)를 되짚는다. 사설 대역 3개를 실제로 써 보고, 아무 대역을 써도 내부에서는 잘 된다는 것을 확인한다.

| 조 | PC0 | PC1 | 마스크 |
|---|---|---|---|
| 1 | `10.0.0.1` | `10.0.0.2` | `255.0.0.0` |
| 2 | `172.16.0.1` | `172.16.0.2` | `255.255.0.0` |
| 3 | `192.168.0.1` | `192.168.0.2` | `255.255.255.0` |

1. (5-D-01) PC0과 PC1을 표의 1조 값으로 바꾼다.
2. (5-D-02) PC0에서 `ping 10.0.0.2`를 입력한다. → 결과: 성공한다.
3. (5-D-03) 2조 값으로 바꾸고 `ping 172.16.0.2`를 입력한다. → 결과: 성공한다.
4. (5-D-04) 3조 값으로 바꾸고 `ping 192.168.0.2`를 입력한다. → 결과: 성공한다.
5. (5-D-05) PC0을 `192.168.10.1`, PC1을 `192.168.10.2`로 되돌린다(마스크 `255.255.255.0`). → 결과: Lab 2 상태다.

- 옆 조와 똑같은 주소를 써도 각자의 내부망이라 문제가 없다. 카페 와이파이와 집 와이파이를 떠올리면 된다.

**질문과 답**

- 아무 주소나 써도 되나? → 내부에서는 그렇다. 단, 인터넷에 나갈 때는 공인 IP로 바뀐다(NAT).
- 집 공유기는 왜 `192.168.0.x`일까? → C 클래스 사설 대역이라 소규모 망에 맞기 때문이다.

### E. Lab 5. 주소를 못 받으면 `169.254`가 뜬다

이 Lab은 2일차 [특수 주소와 APIPA](../day-02/lesson-3.md)를 되짚는다. 오늘 본 실습 중에 반드시 마주치는 화면이므로 미리 한 번 겪어 둔다.

**일부러 실패시킨다.**

1. (5-E-01) `PC0`의 `IP Configuration`에서 `DHCP`를 선택한다.
2. (5-E-02) 잠시 기다린다. → 결과: `DHCP request failed`와 같은 메시지가 나온다.
3. (5-E-03) `Command Prompt`에서 `ipconfig`를 입력한다. → 결과: 주소가 `169.254.x.x`다.
4. (5-E-04) `ping 192.168.10.2`를 입력한다. → 결과: 실패한다(혼자 다른 동네에 서 있기 때문이다).

**원인.**

- DHCP를 선택하면 "누가 주소를 주세요"라고 요청한 것이다.
- 이 망에는 주소를 나눠 줄 장비(DHCP 서버)가 없어 대답이 없다.
- 그러면 PC가 혼자 임시 주소를 붙인다. 이것이 APIPA다.

**원래대로 되돌린다.**

5. (5-E-05) `Static`으로 되돌리고 `192.168.10.1` / `255.255.255.0`을 다시 입력한다.
6. (5-E-06) `ping 192.168.10.2`를 입력한다. → 결과: 성공한다.

**질문과 답**

- `169.254`로 시작하면 무슨 뜻인가? → 아무한테서도 주소를 받지 못했다는 뜻이다.
- 실무에서는 무엇을 확인하나? → 랜선, 공유기(DHCP), 와이파이 연결을 확인한다.
- 집에서는 누가 주소를 주나? → 공유기다. 직접 구축은 8일차에서 다룬다. [8일차 DHCP와 DNS](../day-08/lesson-2.md)를 본다.

### F. Lab 6. 브로드캐스트와 캡슐화를 눈으로 보기

이 Lab은 1일차 [캐스트](../day-01/lesson-7.md)와 [OSI 7계층](../day-01/lesson-6.md)을 되짚는다. 말로만 설명한 두 가지를 화면에서 확인한다.

**준비: 기억을 지운다.**

1. (5-F-01) `PC0`의 `Command Prompt`에서 `arp -d *`를 입력한다. → 결과: PC0의 ARP 테이블이 비워진다.
2. (5-F-02) 오른쪽 아래에서 `Simulation` 모드로 전환한다. → 결과: 시뮬레이션 패널이 나타난다.
3. (5-F-03) `Edit Filters`에서 ARP와 ICMP만 체크한다. → 결과: 나머지 프로토콜은 표시되지 않아 보기 편하다.

**브로드캐스트가 퍼지는 모습을 본다.**

4. (5-F-04) PC0에서 `ping 192.168.10.2`를 입력한다. → 결과: 봉투 아이콘이 생긴다.
5. (5-F-05) `Capture / Forward`를 한 번씩 누르며 진행한다. 자동 재생은 쓰지 않는다. → 결과: 아래 표와 같이 보인다.

| 보이는 것 | 뜻 |
|---|---|
| 첫 봉투가 스위치를 거쳐 모든 PC로 퍼진다 | 브로드캐스트(1대 다수) |
| 답장은 PC1에서 PC0 하나로만 온다 | 유니캐스트(1대1) |
| 그다음부터 봉투가 곧장 오간다 | 이제 상대를 안다 |

**캡슐화: 봉투 안을 연다.**

6. (5-F-06) 이동 중인 봉투를 클릭한다.

|---|---|

| 겉에서부터 한 겹씩 싸인 구조 | 캡슐화 |

**질문과 답**

- 편지를 봉투에 넣고 또 봉투에 넣는다고 한 것이 이것이다. → 캡슐화를 회수한다.
- 목적지 MAC이 `FFFF.FFFF.FFFF`인 것이 보이는가? → 브로드캐스트 주소다.
- PC가 254대라면 저 봉투가 전부에게 퍼진다. → 그래서 서브넷팅을 배웠다.
