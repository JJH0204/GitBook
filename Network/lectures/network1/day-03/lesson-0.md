## 🧪 Lab 1. 화면 익히기 + 오늘 계속 쓸 구성 만들기

**Cisco Packet Tracer** — 실제 장비 없이 네트워크를 구성·시뮬레이션하는 무료 학습 도구.

### 화면에서 찾아야 할 곳 (처음이라면 여기부터)

| 위치 | 무엇 |
|------|------|
| **왼쪽 아래** | 장비 상자 — `End Devices`(PC) · `Switches` · `Network Devices > Routers` · `Connections`(케이블) |
| **오른쪽 아래** | **Realtime**(실제처럼 동작) / **Simulation**(한 걸음씩 관찰) 전환 |
| 장비를 클릭하면 | `Physical`(모습) · `Config`(GUI 설정) · `CLI`(명령어) · `Desktop`(PC만) |

### 링크 점 색깔 — 오늘 내내 이것부터 본다

| 점 색 | 뜻 | 할 일 |
|-------|-----|------|
| 🟢 초록 | 정상 | — |
| 🟠 주황 | 스위치 포트가 **준비 중** | **30초쯤 기다리면** 초록이 된다 |
| 🔴 빨강 | 링크 없음 | **케이블 종류**가 틀렸거나 포트가 꺼져 있다 |

> 💡 주황 점은 고장이 아니다. 그 이유(**STP**)는 4일차에 밝혀진다 → [1_스위치_동작원리](../day-04/lesson-1.md)

### 구성 만들기

1. `End Devices` 에서 **PC 2대** → `PC0`, `PC1`
2. `Switches` 에서 **스위치 1대** (2960 등)
3. `Connections` → **Copper Straight-Through**(다이렉트)로 PC ↔ 스위치 연결
4. 링크 점이 **주황 → 초록**으로 바뀔 때까지 기다린다

**✅ 체크** — 링크 양 끝이 초록인가?
**💾 저장** — `Ctrl + S` → **`03_스위치.pkt`** (Lab 6·9, 4일차 Lab 10 까지 쓴다)

## 🧪 Lab 2. IP 가 없으면 아무것도 안 된다

> 되짚기: [1일차 — 데이터는 어디로 갈까](../day-01/lesson-4.md)
> *"봉투에 주소가 없으면 배달되지 않는다"*

**① 주소 없이 먼저 해본다**

1. `PC0` 클릭 → `Desktop` → `Command Prompt`
2. `ipconfig` → IP 주소가 어떻게 되어 있나? (`0.0.0.0`)
3. `ping 192.168.10.2` → **실패**

**② 주소를 준다**

| 장비 | IPv4 Address | Subnet Mask |
|------|--------------|-------------|
| PC0 | `192.168.10.1` | `255.255.255.0` |
| PC1 | `192.168.10.2` | `255.255.255.0` |

- 각 PC → `Desktop` → `IP Configuration` → **`Static`** 선택 후 입력
- 다시 `ping 192.168.10.2` → **성공**

> 💡 첫 ping 은 한 번쯤 실패할 수 있다. **왜 그런지는 오늘 2교시(ARP·스위치)에서 밝혀진다.**

**🗣 물어볼 것**

- "선은 그대로였는데 왜 아까는 안 됐을까요?" → **주소가 없어서**
- "선만 이으면 통신이 되는 게 아니라는 거네요?" → 그렇다. **연결 + 주소** 둘 다 필요

**✅ 체크** — `ping` 4번 중 3~4번 성공인가? (첫 번째 실패는 정상)

## 🧪 Lab 3. 클래스가 기본 마스크를 정한다 ⭐

> 되짚기: [2일차 — IP 클래스와 서브넷 마스크](../day-02/lesson-2.md)

패킷트레이서에는 **클래스를 눈으로 보여주는 기능**이 있다. IP 를 입력하고 `Tab` 을 누르면
**첫 옥텟을 보고 기본 마스크를 자동으로 채워준다.**

`PC0` → `IP Configuration` 에서 아래를 차례로 입력하고, **마스크 칸이 어떻게 바뀌는지** 본다.

| 입력한 IP | 자동으로 채워지는 마스크 | 클래스 |
|-----------|------------------------|--------|
| `10.0.0.1` | `255.0.0.0` | **A** |
| `172.16.0.1` | `255.255.0.0` | **B** |
| `192.168.0.1` | `255.255.255.0` | **C** |

**🗣 물어볼 것**

- "프로그램이 어떻게 알았을까요?" → **첫 옥텟**만 보고 (10 → A, 172 → B, 192 → C)
- "그럼 `/26` 같은 건요?" → 자동으로는 안 나온다. **직접 입력**해야 한다
  - → 클래스는 **옛 방식**이고, 요즘은 마스크를 자유롭게 정한다 (**Lab 9** 에서 직접 해본다)

> ⚠️ 확인이 끝나면 **`192.168.10.1` / `255.255.255.0`** 로 되돌려 놓자 (Lab 2 상태)

## 🧪 Lab 4. 사설 IP 세 대역 다 써보기

> 되짚기: [2일차 — 공인 IP와 사설 IP](../day-02/lesson-3.md)

사설 대역 **3개**를 실제로 써보고, **아무거나 써도 내부에서는 잘 된다**는 것을 확인한다.

| 조 | PC0 | PC1 | 마스크 |
|----|-----|-----|--------|
| 1 | `10.0.0.1` | `10.0.0.2` | `255.0.0.0` |
| 2 | `172.16.0.1` | `172.16.0.2` | `255.255.0.0` |
| 3 | `192.168.0.1` | `192.168.0.2` | `255.255.255.0` |

- 세 조 모두 `ping` **성공**한다
- 옆 조와 **똑같은 주소를 써도** 각자의 내부망이라 문제없다 → 카페 와이파이와 집 와이파이 이야기

**🗣 물어볼 것**

- "그럼 아무 주소나 써도 되나요?" → 내부에서는 그렇다. 단 **인터넷에 나갈 때** 공인 IP 로 바뀐다(NAT)
- "우리 집 공유기는 왜 하필 `192.168.0.x` 일까요?" → C 클래스 사설 대역이라 소규모 망에 딱 맞아서

> ⚠️ 끝나면 다시 `192.168.10.1` / `192.168.10.2` 로 되돌린다

## 🧪 Lab 5. 주소를 못 받으면 `169.254` 가 뜬다 ⭐

> 되짚기: [2일차 — 특수 주소 · APIPA](../day-02/lesson-3.md)

**오늘 실습 중 반드시 마주칠 화면**이다. 미리 한 번 겪어두면 당황하지 않는다.

**① 일부러 실패시켜 본다**

1. `PC0` → `IP Configuration` → **`DHCP`** 선택
2. 잠시 기다린다 → **"DHCP request failed"** 같은 메시지
3. `Command Prompt` → `ipconfig` → 주소가 **`169.254.x.x`** 로 붙어 있다
4. `ping 192.168.10.2` → **실패** (혼자 다른 동네에 서 있으니까)

**② 왜 그런가**

- DHCP 를 선택했다 = "누가 주소 좀 주세요" 라고 **요청**했다는 뜻
- 그런데 이 망에는 **주소를 나눠줄 장비(DHCP 서버)가 없다** → 대답이 없다
- 그래서 PC 가 **혼자 임시 주소**를 붙인다 = **APIPA**

**③ 원래대로** — `Static` 으로 되돌리고 `192.168.10.1` 재입력 → `ping` 성공

**🗣 물어볼 것**

- "`169.254` 로 시작하면 무슨 뜻이죠?" → **아무한테서도 주소를 못 받았다**
- "실무에서는 뭘 확인해야 할까요?" → 랜선 · 공유기(DHCP) · 와이파이 연결
- "그럼 집에서는 누가 주소를 주나요?" → **공유기** → 직접 구축은 **8일차** → [2_DHCP와_DNS](../day-08/lesson-2.md)

## 🧪 Lab 6. 브로드캐스트와 캡슐화를 눈으로 ⭐

> 되짚기: [1일차 — 캐스트](../day-01/lesson-7.md) · [1일차 — OSI 7계층](../day-01/lesson-6.md)

1일차에 **말로만** 설명했던 두 가지를 화면에서 확인한다.

**① 준비 — 기억을 지운다**

1. `PC0` → `Command Prompt` → `arp -d *`
2. 오른쪽 아래 **`Simulation`** 모드로 전환
3. `Edit Filters` 에서 **ARP 와 ICMP 만** 체크 (나머지 끄면 보기 편하다)

**② 브로드캐스트가 퍼지는 모습**

`PC0` 에서 `ping 192.168.10.2` 실행 → **`Capture / Forward`** 를 한 번씩 누르며 진행

| 무엇을 보나 | 무슨 뜻 |
|------------|---------|
| 첫 봉투가 **스위치를 거쳐 모든 PC 로** 퍼진다 | **브로드캐스트** — 1대 다수 |
| 답장은 **PC1 → PC0 하나로만** 온다 | **유니캐스트** — 1대1 |
| 그다음부터는 봉투가 **곧장 오간다** | 이제 상대를 아니까 |

**③ 캡슐화 — 봉투 안을 열어본다**

이동 중인 봉투를 **클릭** → **`OSI Model`** 탭 / **`PDU Details`** 탭

| 보이는 것 | 1일차에 배운 것 |
|-----------|----------------|
| Ethernet II 헤더의 **DEST MAC / SRC MAC** | 2계층 — 프레임 |
| IP 헤더의 **SRC IP / DST IP** | 3계층 — 패킷 |
| 겉에서부터 한 겹씩 싸여 있는 구조 | **캡슐화** |

**🗣 물어볼 것**

- "편지를 봉투에 넣고 또 봉투에 넣는다고 했던 게 이거예요" → 캡슐화 회수
- "목적지 MAC 이 `FFFF.FFFF.FFFF` 인 게 보이나요?" → 그게 **브로드캐스트 주소**
- "PC 가 254대라면 저게 전부에게 퍼집니다" → 그래서 **서브넷팅**을 배웠다

> 🔮 **여기서 멈추고 예고한다.**
> *"그런데 저 첫 봉투는 대체 뭘 물어본 걸까요? 왜 전부에게 뿌렸을까요?"*
> → **정체는 `ARP`. 바로 다음 시간에 배운다** → [2_MAC주소와_ARP](lesson-2.md)

**💾 저장** — `Ctrl + S` (`03_스위치.pkt` 덮어쓰기)
