# 8일차 · 네트워크 장비에서의 서버 설정

> 1단계 · 네트워크 기초와 구성 — 상위: [네트워크 1](../README.md)

## 개요

7일차에 회사망을 깔았다. 영업(VLAN 10)과 개발(VLAN 20), 층을 잇는 트렁크, 부서를 잇는 Router-on-a-stick, 두 줄을 묶은 EtherChannel이다. → [7일차 · 스위칭 심화](../day-07/README.md)

그런데 이 회사망은 아직 맨땅이다. 스위치에 들어가려면 장비 앞까지 걸어가야 하고, PC마다 IP를 손으로 넣고, 서버는 숫자로 불러야 하고, 빈자리 랜선에 아무나 꽂아도 된다. 오늘은 이 회사망 위에 서비스를 올린다.

| 필요 | 서비스 | 노트 |
|---|---|---|
| 장비 앞에 가지 않고 관리 | Telnet에서 SSH로 (+ 스위치 관리 IP) | 1 |
| IP를 자동으로, 서버가 다른 VLAN이어도 | DHCP (+ 릴레이) | 2 |
| 숫자 말고 이름으로 | DNS | 2 |
| 감시, 중계, 파일 전송 | SNMP, Proxy, FTP | 3 |
| 아무나 꽂지 못하게 | 포트 보안 | 4 |
| 선 없는 손님, 새 주소 | 무선랜, IPv6 (맛보기) | 5 |

이 서비스들은 2단계에서 리눅스 서버로 다시 구축한다(12_리눅스서버구축). 오늘은 1단계와 2단계를 잇는 다리다.

## 오늘의 목표

- L2 스위치에 관리용 IP(SVI)와 기본 게이트웨이를 주고, Telnet과 SSH의 차이를 알고 SSH로 접속한다.
- DORA를 설명하고 VLAN별 DHCP 풀을 만든다.
- 브로드캐스트는 라우터를 못 넘으므로 DHCP 릴레이(`ip helper-address`)로 해결한다.
- 서버에 DNS A 레코드를 등록해 이름으로 통신하고 `no ip domain-lookup`의 의미를 안다.
- SNMP, Proxy, FTP의 역할과 포트 번호, 보안 대안을 구분한다.
- 포트 보안(sticky, violation)으로 낯선 기기를 막고 err-disabled를 복구한다.
- (맛보기) 무선랜을 VLAN에 붙이고 IPv6 주소를 읽고 축약한다.

## 오늘의 실습 — 7일차 파일을 이어 쓴다 (오늘만 예외)

```
                        [R1]  .10.254 / .20.254
                         │    DHCP 풀 → helper-address · SNMP
                         │ trunk
  PC0 ──Fa0/1──┐         │         ┌──Fa0/1── PC2
  PC1 ──Fa0/2──┤       [SW1]═Po1═[SW2]       ├──Fa0/2── PC3
  Server0 ─Fa0/3┘   관리 IP .10.253          └──Fa0/3── (AP)
  192.168.10.10 — DNS · 웹 · FTP · DHCP
```

- 새로 놓는 장비는 Server0 한 대다(+ 포트 보안용 Laptop, 선택으로 AP).
- 7일차 파일이 없는 학생은 [대본 부록 A](commands.md)의 복붙 블록으로 5분 복구한다.
- 오늘은 GUI(서버 Services 탭)와 CLI가 섞인다. 대본의 "마우스" 표시를 따른다.

## 강의 메모

- "7일차 회사망은 맨땅이다"로 연다. 걸어가야 하고, 손으로 IP를 넣고, 숫자로 부르고, 아무나 꽂는다.
- 각 서비스는 "무엇을, 왜, 포트, 보안 대안" 4가지로 정리한다.
- 오늘의 핵심 질문: "DHCP 요청은 브로드캐스트인데, VLAN 20 PC는 어떻게 받았을까?" 답을 이해하면 릴레이(helper-address)가 따라온다. 4일차 원칙의 예외다.
- 비유 4종: Telnet/SSH = 엽서/봉인된 편지, DHCP = 호텔 체크인, 릴레이 = 관리실 전화, 포트 보안 = 사원증 출입문.
- 최대 병목은 세 가지다.
  1. 스위치 `ip default-gateway` 누락: "같은 VLAN에서만 된다"
  2. helper-address를 서버 쪽에 입력한다: "외침이 들어오는 문에"
  3. 포트 보안 복구 시 범인을 안 치우고 `no shutdown`을 한다
- PT 버전 차이: 서버 DHCP 다중 풀, MIB Browser, AP 설정 화면은 버전마다 조금 다르다. 수업 전 리허설이 필수다.
- 오늘의 회수 지점은 다섯이다.
  1. 2일차 `169.254` = 고장 신호 → DHCP 실패의 증거
  2. 3일차 "IP는 되는데 이름은 안 된다" → DNS
  3. 4일차 `no ip domain-lookup` 주문의 정체 → DNS에게 묻지 말라
  4. 4일차 "라우터는 브로드캐스트를 막는다" → 그 예외가 helper-address
  5. 7일차 L3 스위치 SVI → 오늘은 관리용 SVI
- 커리큘럼 7일차 주제(무선랜, IPv6)는 7일차를 스위칭 심화로 쓰면서 5번 노트에 압축했다. 무선랜은 10일차에 다시 다룬다. → [10일차 · 서버 기초](../../network2/day-10/README.md)
- 1단계 마무리: 3일차(장비), 4일차(스위치·라우터), 5·6일차(라우팅), 7일차(스위칭), 8일차(서비스). 2단계는 이 서비스들을 리눅스 서버로 직접 구축한다. → [네트워크 2](../../network2/README.md)
