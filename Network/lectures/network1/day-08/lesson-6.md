# 6. 서버 설정 실습 — 회사망에 서비스를 올린다

> 상위: [8일차 · 네트워크 장비에서의 서버 설정](README.md)
> 🖐 **실습 중에는 이 노트 대신** → [8일차 실습 명령어 대본 (따라치기)](commands.md)
> 이 노트는 **왜 그렇게 하는지 · 무엇을 봐야 하는지**를 설명한다.

## 🎯 학습 목표

- L2 스위치에 **관리용 IP** 를 주고, **Telnet → SSH** 로 원격 접속한다
- 라우터에 **VLAN 별 DHCP 풀**을 만들고, 서버 DHCP 로 옮기며 **릴레이**를 건다
- 서버에 **DNS A 레코드**를 등록해 이름으로 통신한다
- **포트 보안**으로 낯선 기기를 차단하고 복구한다
- (선택) FTP · SNMP · 무선 · IPv6 를 맛본다

## 🌉 다리 놓기: "7일차 회사망을 그대로 쓴다"

7일차에 **VLAN 10(영업) · 20(개발) · 트렁크 · Router-on-a-stick · EtherChannel** 로 회사망을 깔았다.
오늘은 그 위에 **서비스**를 올린다. 새 그림은 없다 — **서버 한 대**만 추가한다.
→ [4_스위칭_실습](../day-07/lesson-4.md)

## 🗺 오늘의 토폴로지

```
                        [R1]  .10.254 / .20.254
                         │    DHCP 풀 → (STEP 3) helper-address
                         │ trunk
  PC0 ──Fa0/1──┐         │         ┌──Fa0/1── PC2
  PC1 ──Fa0/2──┤       [SW1]═Po1═[SW2]       ├──Fa0/2── PC3
  Server0 ─Fa0/3┘   관리 IP .10.253          └──Fa0/3── (AP)
  192.168.10.10 — DNS · 웹 · FTP · (STEP 3) DHCP
```

| **②** | 라우터 **DHCP** | `169.254` | ✅ | 20분 |

## 🧪 ① 원격 접속 — "스위치의 주소는?"

**흐름**: IP 없음 → SVI 로 IP → VTY 잠김 → Telnet 열기 → SSH 로 갈아타기

| 시도 | 결과 | 배우는 것 |
|------|------|-----------|
| SVI 전 `telnet 192.168.10.253` | 응답 없음 | L2 스위치는 **원래 IP 가 없다** |
| SVI 후, VTY 설정 전 | `Password required, but none set` | VTY 는 **비밀번호 없으면 잠김** |
| Telnet 성공 후 `enable` (secret 없을 때) | `% No password set` | 원격 사용자는 **enable secret** 이 있어야 올라간다 |
| 도메인 없이 키 생성 | `% Please define a domain-name first.` | SSH 키는 **이름 + 도메인**이 이름표 |
| SSH 설정 후 Telnet | 거절 | `transport input ssh` |
| **PC1(VLAN 20)** 에서 SSH | ✅ | 스위치의 **`ip default-gateway`** 덕분 |

- 🗣 **"PC1 은 다른 VLAN 인데 어떻게 스위치에 들어갔죠?"** → 스위치도 **PC 처럼 게이트웨이**가 필요하다
- (여유) `ip default-gateway` 를 `no` 로 지워보면 → **PC0(VLAN 10)은 되고 PC1(VLAN 20)은 안 된다**

## 🧪 ② 라우터 DHCP — "169.254 는 고장 신호"

- 풀 전에 PC 를 DHCP 로 → **`169.254.x.x`** (2일차 회수)
- **VLAN 마다 풀 하나**: `default-router` 가 VLAN 마다 다르다 (`.10.254` / `.20.254`)
- `excluded-address` 는 **풀보다 먼저** — 서버(.10) · 게이트웨이(.254) · 스위치(.253) 보호

**🔎 봐야 할 것**

| 어디서 | 무엇 |
|--------|------|
| PC `IP Configuration` | IP `.11` 대 · 게이트웨이 · **DNS `192.168.10.10`** 까지 자동으로 |
| R1 `show ip dhcp binding` | 받아간 IP ↔ MAC 목록 |

> 🗣 **오늘의 핵심 질문**: **"DHCP 요청은 브로드캐스트인데, VLAN 20 PC 는 어떻게 R1 에게 받았을까?"**
> → R1 의 `g0/0.20` 이 **VLAN 20 동네 안에** 있어서 외침이 들린다. → 그럼 서버가 다른 동네면? → ③

## 🧪 ③ DHCP 릴레이 ⭐ — "원칙과 예외"

**무대 바꾸기**: 라우터 풀을 지우고 **Server0(VLAN 10)** 이 배급을 맡는다. 풀은 VLAN 마다 하나 (시작 `.101`).

| | 릴레이 전 | 릴레이 후 |
|---|---|---|
| PC2 (VLAN 10 — 서버와 같은 동네) | ✅ `.10.101` | ✅ |
| PC3 (VLAN 20 — 다른 동네) | ❌ `169.254` | ✅ `.20.101` |
| R1 `show ip dhcp binding` | — | **비어 있다** (서버가 줬다) |

- **원칙** (4일차): 라우터는 브로드캐스트를 **넘기지 않는다**
- **예외**: `ip helper-address` — 이 인터페이스로 들어온 **DHCP 외침만** 서버에게 **유니캐스트 편지로** 전달
- 릴레이는 편지에 **"20.0 동네에서 왔어요"(g0/0.20 의 주소)** 를 적는다 → 서버가 **VLAN20 풀**을 고른다
- 🚨 helper 는 **클라이언트 쪽**(`g0/0.20`)에 친다. 서버 쪽(`g0/0.10`)에 치면 소용없다

> 💡 **"R1 은 배급소에서 우체국이 됐다."** — 이 한 문장으로 정리

## 🧪 ④ DNS — "IP 는 되는데 이름은 안 된다"

- `ping 192.168.10.10` ✅ / `ping www.student.local` ❌ → **3일차 떡밥 그대로**
- Server0 `DNS` On + **A 레코드** 두 개 (`www` → 서버, `sw1` → 스위치 관리 IP)
- PC 의 DNS 주소는 **DHCP 가 이미 줬다** — 앞 단계가 뒷 단계를 받쳐주는 구조
- 웹 브라우저로 `http://www.student.local` → **이름 → IP → 웹 페이지** 한 번에

> 🗣 **"4일차부터 친 `no ip domain-lookup` — 이제 DNS 서버가 생겼습니다."** → 부록 B 실험으로 풀어보기

## 🧪 ⑤ FTP · SNMP (선택)

| | 해보는 것 | 느낄 것 |
|---|---|---|
| **FTP** | PC0 `ftp 192.168.10.10` (cisco/cisco) → `dir` | 로그인이 **평문** — Telnet 과 같은 운명 |
| **SNMP** | R1 `snmp-server community public ro` → PC MIB Browser 로 `sysName` Get | **로그인 없이** 장비 정보를 읽는다 → 커뮤니티 = 비밀번호 |

## 🧪 ⑥ 포트 보안 ⭐ — "사원증 출입문"

**4컷**: 주인 등록 → 침입 → 범인 찾기 → 복구

| 컷 | 무엇 | 🔎 |
|----|------|-----|
| 1 | Fa0/1 에 port-security + **sticky** → PC0 한 번 ping | `Sticky MAC Addresses : 1` · running-config 에 PC0 MAC |
| 2 | PC0 선을 빼고 **Laptop** 을 Fa0/1 에 | 🚨 링크 **빨간색** |
| 3 | `show port-security interface fa0/1` | `Secure-shutdown` · **`Last Source Address` = Laptop MAC** |
| 4 | **Laptop 먼저 치우고** PC0 연결 → `shutdown` / `no shutdown` | PC0 ping ✅ |

- 🗣 **"오늘 만든 DHCP 가 침입자에게도 IP 를 줄 뻔했습니다."** → 편리함과 보안은 한 쌍
- ⚠️ 침입자를 꽂은 채 `no shutdown` → **즉시 다시 꺼진다**

| 증상 | 원인 |

## 📝 강의 메모

- **실패 먼저** 리듬은 오늘도 유지: IP 없음 · VTY 잠김 · `169.254` · VLAN 20 만 실패 · 이름 실패 · 침입
- ③(릴레이)은 **오늘의 고급 스킬**이지만 시간이 부족하면 **개념 설명만** 하고 넘어가도 ②④가 성립한다

- 각 서비스는 **"무엇을 · 왜 · 포트 · 보안 대안"** 4가지로 정리 → [3_SNMP_Proxy_FTP](lesson-3.md)의 포트표
