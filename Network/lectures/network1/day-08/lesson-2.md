# 2. DHCP와 DNS — 주소는 자동으로, 이름으로 부르기

> 상위: [8일차 · 네트워크 장비에서의 서버 설정](README.md)

## 🎯 학습 목표

- DHCP 가 IP 를 나눠주는 **DORA 4단계**를 설명한다
- 라우터에 **VLAN 마다 DHCP 풀**을 만든다
- **브로드캐스트는 라우터를 못 넘는다** → 그래서 **DHCP 릴레이(`ip helper-address`)** 가 필요하다는 것을 안다
- DNS 가 **이름 ↔ IP** 를 바꿔주는 원리를 알고, 서버에 **A 레코드**를 등록한다
- 4일차부터 쳐온 **`no ip domain-lookup`** 의 정체를 안다

## 🌉 다리 놓기: "PC 가 100대면 IP 를 손으로?"

7일차 실습에서 PC 4대에 IP · 마스크 · 게이트웨이를 **손으로** 넣었다. 부서가 둘이라 게이트웨이도 둘이었다.
PC 가 **100대**라면? 한 명이 옆 부서로 자리를 옮기면? → 사람이 손으로 하면 **오타와 중복**이 반드시 난다.
→ **DHCP 가 자동으로 나눠준다.**

그리고 우리는 서버를 `192.168.10.10` 으로 부르고 있다. 인터넷 사이트를 전부 숫자로 외울 수 있을까? → **DNS 가 이름을 숫자로 바꿔준다.**

## 📖 ① DHCP — 주소 자동 배급소

- **DHCP** (Dynamic Host Configuration Protocol): **IP · 서브넷 마스크 · 게이트웨이 · DNS 서버** 를 한 번에 자동 배포
- 포트 UDP **67**(서버) / **68**(클라이언트)
- 주소를 **영원히 주지 않고 빌려준다(임대, Lease)** → 기간이 지나면 회수해서 재활용

### DORA 4단계

```
PC(아직 IP 없음)                               DHCP 서버
   │ ① Discover  "DHCP 서버 계세요?"   ──────▶  (브로드캐스트 📢)
   │ ② Offer     "192.168.10.11 어때요?" ◀──────
   │ ③ Request   "그걸로 할게요"       ──────▶  (브로드캐스트 📢)
   │ ④ Ack       "확정, 8일간 쓰세요"   ◀──────
```

- **①이 브로드캐스트인 이유**: PC 는 아직 **자기 IP 도, 서버 IP 도 모른다** → 동네 전체에 외칠 수밖에 없다 (1일차 캐스트 [7_캐스트_유니_브로드_멀티](../day-01/lesson-7.md))
- ③도 브로드캐스트 — 서버가 여러 대일 때 **"저 서버 걸로 정했어요"** 를 다른 서버들도 듣게 하려고

> 💡 **비유: 호텔 프런트.** 체크인하러 가면(Discover) 방을 제안하고(Offer), 손님이 고르면(Request) 키를 준다(Ack).
> 방은 **체크아웃하면 회수**된다(임대 만료). 손님은 방 번호를 외워 올 필요가 없다.

### 받지 못하면 — `169.254.x.x`

DHCP 서버가 응답하지 않으면 PC 는 스스로 **`169.254.x.x`** 를 붙인다 (APIPA).
→ 2일차에 배운 **"169.254 = 고장 신호"** 가 바로 이것이다. → [3_공인IP와_사설IP](../day-02/lesson-3.md)

### 라우터에 DHCP 풀 만들기 — VLAN 마다 하나씩

7일차 회사망은 **VLAN 이 둘 = 서브넷이 둘** → 풀도 **둘**이다.

```bash
ip dhcp excluded-address 192.168.10.1 192.168.10.10      # 서버·장비용으로 남겨둔다
ip dhcp excluded-address 192.168.10.250 192.168.10.254   # 게이트웨이·스위치 관리 IP
ip dhcp excluded-address 192.168.20.1 192.168.20.10
ip dhcp excluded-address 192.168.20.250 192.168.20.254
ip dhcp pool VLAN10
 network 192.168.10.0 255.255.255.0       # 나눠줄 범위
 default-router 192.168.10.254            # 게이트웨이
 dns-server 192.168.10.10                 # DNS 서버
 exit
ip dhcp pool VLAN20
 network 192.168.20.0 255.255.255.0
 default-router 192.168.20.254
 dns-server 192.168.10.10
```

| 줄 | 왜 |
|----|-----|
| `excluded-address` | **고정 IP 를 쓰는 장비**(서버 · 게이트웨이 · 스위치 관리 IP)와 겹치지 않게 → **풀보다 먼저** 친다 |
| `default-router` | PC 의 게이트웨이. VLAN 마다 **다르다** (R1 의 서브인터페이스 주소) |
| `dns-server` | 두 VLAN 이 **같은 DNS 서버**를 쓴다 |

> ⚠️ **`excluded-address` 를 빼먹으면** DHCP 가 `.254`(게이트웨이)나 `.10`(서버)을 PC 에 줘버릴 수 있다 → **IP 충돌**

- 🔎 누가 어떤 IP 를 받았나: `show ip dhcp binding`

> 🗣 **"DHCP Discover 는 브로드캐스트입니다. 브로드캐스트는 라우터를 못 넘죠(4일차). 그런데 VLAN 20 PC 는 어떻게 R1 에게 받았을까요?"**
> → R1 의 **g0/0.20 이 VLAN 20 동네 안에 있다.** 같은 브로드캐스트 도메인이라 외침이 들린다.
> → 그럼 DHCP 서버가 **다른 동네**에 있으면? ↓

### DHCP 릴레이 — 브로드캐스트를 대신 전해주는 우체국 ⭐

실무에서는 라우터가 아니라 **전용 DHCP 서버 한 대**가 회사 전체에 주소를 준다. 서버는 **한 VLAN 에** 산다.

```
 VLAN 20 PC ── 📢 "DHCP 서버 계세요?" ──▶ R1 g0/0.20   ✋ 브로드캐스트는 여기서 끝
                                                        (서버는 VLAN 10 에 있다)
```

**해결**: 서버가 없는 쪽 게이트웨이(서브인터페이스)에 **"DHCP 외침이 들리면 이 서버에게 편지로 전해줘"** 라고 시킨다.

```bash
interface g0/0.20
 ip helper-address 192.168.10.10          # 브로드캐스트 → 서버 주소로 유니캐스트 전달
```

```
 VLAN 20 PC ── 📢 Discover ──▶ R1 g0/0.20 ── ✉ (유니캐스트) ──▶ Server 192.168.10.10
                                "20.0 동네에서 온 요청입니다"          │
                                                                     ▼ 20.0 용 풀에서 골라 응답
```

- 릴레이는 **"어느 동네(g0/0.20 = 192.168.20.254)에서 온 요청인지"** 를 편지에 적어 보낸다 → 서버가 **그 동네에 맞는 풀**을 고른다
- 그래서 서버에는 **VLAN 마다 풀**이 있어야 한다
- 서버와 **같은 VLAN(10)** 의 PC 들은 원래 외침이 들리니 릴레이가 필요 없다

> 💡 **비유: 아파트 관리실 방송.** 101동 방송(브로드캐스트)은 102동에 안 들린다.
> 102동 경비실(게이트웨이)에 **"DHCP 찾는 방송 나오면 101동 관리사무소로 전화해줘"** 라고 부탁해 두는 것 = helper-address.

> 📌 이름이 헷갈리지만 **`ip helper-address` 는 DHCP 릴레이 명령**이다. 반드시 **클라이언트 쪽 인터페이스**(서버가 없는 쪽)에 친다.

## 📖 ② DNS — 이름을 숫자로

- **DNS** (Domain Name System): 사람이 읽는 **이름** ↔ 장비가 쓰는 **IP** 변환
- 포트 UDP/TCP **53**
- 인터넷의 **전화번호부**: 이름만 알면 번호(IP)를 찾아준다

```
PC ── "www.student.local 의 IP 가 뭐예요?" ──▶ DNS 서버 (192.168.10.10)
PC ◀── "192.168.10.10 입니다" ────────────────
PC ── 그 IP 로 ping / 웹 접속 ──▶
```

### 레코드 — 전화번호부의 한 줄

| 레코드   | 뜻                  | 예                                   |
| ----- | ------------------ | ----------------------------------- |
| **A** | 이름 → **IPv4**      | `www.student.local → 192.168.10.10` |
| AAAA  | 이름 → **IPv6**      | (쿼드 A — [5_무선랜과_IPv6](lesson-5.md))            |
| CNAME | 이름 → **다른 이름**(별명) | `web → www.student.local`           |
| MX    | 메일 서버              | (12일차 메일 서버에서)                      |

- 오늘은 **A 레코드**만 만든다. 나머지는 2단계 리눅스 DNS 서버에서 → 12_리눅스서버구축
- 실제 인터넷 DNS 는 **루트(.) → TLD(.com) → 권한 서버** 로 물어물어 찾아간다 (계층 구조) — 이름만

> 💡 3일차에서 흘린 떡밥 회수: **`ping 8.8.8.8` 은 되는데 `ping google.com` 은 안 된다** → **IP 는 되는데 DNS 가 문제!**
> → [3_ICMP와_ping](../day-03/lesson-3.md)

### `no ip domain-lookup` 의 정체 🔍

4일차부터 장비마다 첫 줄로 쳐온 명령 → [0_실습_명령어_모음](../day-04/commands.md)

- 시스코 장비는 **모르는 단어를 치면 "장비 이름인가?" 하고 DNS 에 물어본다**
- 그런데 DNS 서버가 없으니 **30초 동안 온 동네에 외치다(브로드캐스트) 포기**한다 → 화면이 멈춘 것처럼 보였다
- `no ip domain-lookup` = **"이름 물어보지 마"** → 오타를 쳐도 바로 에러

```
R1# shwo ip route
Translating "shwo"...domain server (255.255.255.255)     ← 온 동네에 "shwo 가 누구예요?"
```

> 🗣 **"4일차부터 주문처럼 쳤던 한 줄, 오늘 이유를 알았습니다 — DNS 에게 묻지 말라는 뜻이었어요."**

## 📝 강의 메모

- **"7일차에 IP 몇 번 쳤죠? 100대면?"** 으로 연다
- DORA 는 **호텔 체크인**으로. ①③이 **브로드캐스트**라는 걸 꼭 짚어야 릴레이가 이해된다
- 🗣 **오늘의 핵심 질문**: "브로드캐스트는 라우터를 못 넘는데, VLAN 20 PC 는 어떻게 받았을까?"
  → 답(같은 동네에 R1 이 있다)을 이해하면 릴레이는 저절로 따라온다
- 4일차 **"라우터는 브로드캐스트를 막는다"** 원칙의 **예외 처리**가 helper-address 다 → 원칙과 예외를 한 쌍으로
- `no ip domain-lookup` 회수는 **짧고 재밌게** — "주문의 정체"
