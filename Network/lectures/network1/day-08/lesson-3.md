| 필요 | 서비스 |

## 1. 구성 요소

### SNMP — 관제실의 계기판

- SNMP(Simple Network Management Protocol)는 장비 상태(트래픽, 오류, CPU, 포트 up/down)를 원격으로 모니터링한다.
- 구성은 매니저(관제 서버)와 에이전트(각 장비)이며, 에이전트가 들고 있는 정보 창고를 MIB라고 한다.
- 포트는 UDP 161(매니저가 묻는다)과 UDP 162(트랩: 장비가 먼저 "나 이상해!"라고 알린다)다.

| 버전 | 인증 | 평가 |
|---|---|---|
| v1, v2c | 커뮤니티 문자열(사실상 평문 비밀번호, 기본 `public`) | 취약. 실습용 |
| v3 | 사용자 인증 + 암호화 | 실무 권장 |

- 비유는 관제실이다. 관제실(매니저)이 각 장비(에이전트)의 계기판(MIB)을 원격으로 들여다본다. 평소에는 관제실이 물어보고(161), 사고가 나면 장비가 먼저 비상벨(트랩, 162)을 누른다.

```bash
snmp-server community public ro          # "public" 을 아는 사람에게 읽기(ro)만 허락
```

{% hint style="warning" %}
CAUTION: `rw`(읽기·쓰기)로 열면 커뮤니티 문자열을 아는 누구나 설정을 바꿀 수 있다. 실습에서도 `ro`로 설정한다.
{% endhint %}

### Proxy — 대신 다녀오는 심부름꾼

- Proxy는 클라이언트를 대신해 요청을 중계하는 서버다.

| 용도 | 설명 |
|---|---|
| 캐싱 | 자주 가는 페이지를 저장해 두 번째부터 빠르게 한다 |
| 필터링 | 유해하거나 업무와 무관한 사이트를 차단한다 |
| 접근 제어, 기록 | 누가 어디에 갔는지 남긴다 |
| 익명화 | 바깥에서는 프록시의 IP만 보인다 |

| 종류 | 누구를 대신하나 | 예 |
|---|---|---|
| 포워드 프록시 | 클라이언트(직원) | 회사 인터넷 필터 |
| 리버스 프록시 | 서버 | 웹서버 앞의 문지기 |

- 비유는 심부름꾼이다. 직원이 직접 가게에 가지 않고 심부름꾼(프록시)에게 부탁한다. 심부름꾼은 금지된 가게는 가지 않고, 자주 사 오는 물건은 창고에 쟁여 둔다(캐시).

{% hint style="info" %}
NOTE: 패킷트레이서에는 프록시 장비가 없다. 개념만 다룬다. 실제 구축은 2단계 리눅스에서 한다. → 12_리눅스서버구축
{% endhint %}

### FTP — 파일 전송

- FTP(File Transfer Protocol)는 파일 업로드(put)와 다운로드(get)를 한다.
- 포트는 TCP 21(제어: 명령이 오가는 길)과 TCP 20(데이터: 파일이 오가는 길)이다.

{% hint style="danger" %}
WARNING: FTP는 평문이다. 아이디, 비밀번호, 파일 내용이 그대로 흐른다.
{% endhint %}

| 평문 | 보안 대안 | 관계 |
|---|---|---|
| Telnet (23) | SSH (22) | [1_원격접속_Telnet과SSH](lesson-1.md) |
| FTP (20/21) | SFTP(SSH 위에서), FTPS(TLS) | Telnet과 SSH와 같은 구도 |
| SNMP v2c | SNMP v3 | 위와 같다 |

- 네트워크 장비에서 FTP/TFTP는 설정 파일 백업과 IOS 이미지 업로드에 쓴다. `copy running-config tftp` 같은 명령이 있다(이름만 소개).

패킷트레이서 Server는 FTP가 기본으로 켜져 있다(기본 계정 `cisco`, 비밀번호는 `<password>`로 표기한다).

```bash
C:\> ftp 192.168.10.10
Username: cisco
Password: <password>
ftp> dir                 # 서버에 있는 파일 목록
ftp> quit
```

## 2. 동작 원리

### 오늘의 서비스와 포트 정리

| 서비스 | 포트 | 역할 | 보안 대안 |
|---|---|---|---|
| FTP | TCP 20/21 | 파일 전송 (평문) | SFTP / FTPS |
| SSH | TCP 22 | 원격 접속 (암호화) | 없음 |
| Telnet | TCP 23 | 원격 접속 (평문) | SSH |
| DNS | UDP/TCP 53 | 이름과 IP 변환 | 없음 |
| DHCP | UDP 67/68 | IP 자동 할당 | 없음 |
| HTTP | TCP 80 | 웹 (평문) | HTTPS 443 |
| SNMP | UDP 161/162 | 감시, 트랩 | v3 |

- 20, 21, 22, 23, 53, 67/68, 80, 161/162는 네트워크관리사와 CCNA 단골이다. 번호 순서대로 외우면 편하다.
- TCP와 UDP의 차이는 2단계 10일차에서 다룬다. → [10일차 · 서버 기초](../../network2/day-10/README.md)

## 4. 강의 메모

- 세 서비스는 "운영에 필요한 것"이라는 한 줄로 묶어서 짧게 다룬다. 오늘의 주연은 SSH, DHCP, 포트 보안이다.
- "평문 대 암호화" 짝(Telnet/SSH, FTP/SFTP, v2c/v3, HTTP/HTTPS)을 표 하나로 반복해 보안 감각을 각인시킨다.
- 포트 번호표는 시험 단골이다. 칠판에 번호순으로 적어 두고 CCNA 시간에 다시 짚는다.
- 프록시는 PT에 없으므로 개념만 다룬다. 12일차 리눅스에서 직접 구축한다.
- 이 서비스들의 리눅스 서버 구축은 2단계 12일차 12_리눅스서버구축에서 한다.

## 5. 약어·용어

| 용어 | 뜻 |
|---|---|
| SNMP | Simple Network Management Protocol. 장비 감시 프로토콜 |
| MIB | Management Information Base. 에이전트가 가진 관리 정보 창고 |
| 트랩(Trap) | 장비가 매니저에게 먼저 보내는 이상 알림 (UDP 162) |
| 커뮤니티 문자열 | SNMP v1/v2c의 사실상 평문 비밀번호 |
| Proxy | 클라이언트 또는 서버를 대신해 요청을 중계하는 서버 |
| FTP | File Transfer Protocol. 파일 전송 프로토콜 |
| SFTP / FTPS | SSH 위의 파일 전송 / TLS를 입힌 FTP |
| TFTP | Trivial FTP. 인증 없는 단순 파일 전송(UDP 69) |
