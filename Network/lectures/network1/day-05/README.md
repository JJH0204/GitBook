4일차에는 라우팅 테이블을 손으로 채웠다. 라우터 2대에 `ip route` 두 줄이었다. 마지막에 "라우터가 10대면 이것을 손으로 다 넣을 수 있을까?"를 물었다. → [4일차](../day-04/README.md)

5일차는 그 답이다. 라우터끼리 정보를 주고받아 테이블을 자동으로 채우는 동적 라우팅을 다룬다. 문서 번호(Task ID)는 `LEC-N1-05-<번호>-<유형>` 형식이다.

## 학습 목표

- 정적 라우팅의 한계를 숫자로 이해하고 동적 라우팅의 필요성을 안다.
- 메트릭(같은 프로토콜 안)과 AD(프로토콜 사이)의 역할 차이를 구분한다.
- 수렴(Convergence)의 뜻을 알고 회선 장애 시 자동 복구를 관찰한다.
- RIP, OSPF, EIGRP의 차이를 관점 차이로 설명한다.
- 패킷트레이서에서 RIPv2와 OSPF를 직접 설정하고 자동 학습된 경로를 확인한다.
- 와일드카드 마스크를 계산한다.

## 실습 구성

실습마다 새 파일에 처음부터 만든다. 앞 회차 파일을 고쳐 쓰지 않는다. 설정이 섞이지 않아 원인을 찾기 쉽고 처음부터 만드는 과정 자체가 연습이 된다.

```
[PC0]──[SW1]──[R1]══════[R2]══════[R3]──[SW2]──[PC2]
 .10.1        20.0/24       50.0/24        .30.1
 192.168.10.0/24                       192.168.30.0/24
```

| 실습 | 단계 | 이 단계의 목적 | 시간 |
|---|---|---|---|
| RIPv2 | 그림 만들기 | 라우터 3대, PC 2대, 인터페이스까지 | 25분 |
| | 먼저 실패 확인 | 경로가 없으면 못 간다(동기 부여) | 5분 |
| | R1·R2에 RIP | "내 것만 신고"로 길이 생긴다 | 20분 |
| | R3에 RIP | 손 안 댄 R1에 경로가 저절로 생긴다 | 25분 |
| | 끊었다 잇기 | 자동 수렴 관찰 | 10분 |
| OSPF | 새 파일에 같은 그림 | 두 번째라 빠르다 | 15분 |
| | OSPF 설정 | 와일드카드, 빠른 수렴 | 20분 |
| (부록) | AD 대결 | RIP을 얹으면 누가 이기나 | 15분 |

- 두 실습의 그림과 주소가 같다. 바뀌는 것은 프로토콜 하나뿐이라 차이가 그대로 드러난다.
- 그림을 두 번 만드는 것을 부담스러워하는 학생에게는 "두 번째는 5분"이라고 미리 말한다.

{% hint style="warning" %}
CAUTION: 실습은 기다리는 실습이다. 실습 시작 전에 반드시 공지한다. RIP은 30초 주기라 명령을 입력해도 경로가 즉시 생기지 않는다. 공지하지 않으면 학생들이 "안 되는데요?" 하며 설정을 지우고 다시 입력하느라 시간을 다 쓴다.
{% endhint %}

## 진행 메모

- "정적은 손으로, 동적은 라우터가 알아서"의 대비로 시작한다.
- 첫 5분에 `n × (n-1)` 표를 칠판에서 학생이 직접 세어 보게 한다. 숫자로 체감시키는 것이 가장 빠르다.
- 최대 함정: `network`에 목적지를 적는 실수. "정적은 가는 길, 동적은 내 것 신고"를 반복해서 각인시킨다.
- 두 번째 함정: OSPF의 와일드카드 마스크. 손으로 계산시켜 본다(255 − 마스크).
- 세 프로토콜은 암기보다 디스턴스 벡터 vs 링크 스테이트의 큰 그림으로 다룬다.
- 오늘의 회수 지점:
  1. 4일차 "한쪽만 넣으면 실패" → 동적은 양쪽이 자동이다.
  2. 4일차 CCNA Q4(AD) → AD 대결에서 RIP을 켜도 `O`만 남는 장면.
  3. 2일차 서브넷 마스크 → 와일드카드 마스크.
- 세 번째 라우터가 합류하는 장면에 시간을 몰아준다. 오늘 수업의 값어치가 거기에 있다.
- 시간이 부족하면 수렴 관찰을 생략하고 OSPF 실습을 살린다. AD가 6일차의 전제다.
- 6일차 예고: "라우터마다 쓰는 말이 다르면 어떻게 될까?" → [6일차 · 라우팅 프로토콜 심화](../day-06/README.md)
