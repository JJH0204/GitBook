## 🌉 다리 놓기: "홉만 세면 부족하다"

RIP 은 **1Mbps 1홉**을 **1Gbps 2홉**보다 좋다고 판단했다. → [2_RIP](lesson-2.md)
게다가 **15홉**을 못 넘고, 소식이 도는 데 **30초씩** 걸린다.

> ❓ 그럼 어떻게 해야 할까?
> ① **대역폭까지 보고** 판단해야 한다
> ② 이웃 말만 믿지 말고 **내가 직접 지도를 보고** 계산해야 한다
> ③ 변화가 생기면 **30초 기다리지 말고 즉시** 알려야 한다

이 셋을 해결한 것이 **OSPF**(그리고 **EIGRP**)다.

## 📖 OSPF — 링크 스테이트 (전체 지도를 그린다)

**OSPF = Open Shortest Path First** (개방형 최단 경로 우선)

### 동작 3단계

| 단계 | 하는 일 | 만드는 것 |
|------|---------|-----------|
| ① **이웃 맺기** | `Hello` 패킷을 **10초마다** 주고받는다 | 이웃 테이블 |
| ② **지도 공유** | 내 링크 상태(LSA)를 **모두에게** 퍼뜨린다 | **LSDB (지도)** |
| ③ **길 계산** | 지도를 놓고 **다익스트라(SPF)** 로 최단 경로 계산 | 라우팅 테이블 |

> 💡 **비유 — 지도를 펴고 직접 계산한다.**
> RIP 은 "옆집이 3정거장이래" 였다. OSPF 는 **모두가 같은 지도를 갖고**,
> 각자 그 지도 위에서 **자기 기준 최단 경로**를 계산한다.

- **핵심: 영역 안의 모든 라우터가 똑같은 지도(LSDB)를 갖는다.** 그래서 판단이 일관된다
- 소식은 **주기적으로 전부 보내는 게 아니라**, **변화가 있을 때만** 보낸다 → 대역폭 절약 + 빠름
- 이웃이 죽었는지는 **Dead 타이머(기본 40초)** 로 판단 → RIP 의 180초보다 훨씬 빠르다

### 메트릭 = 코스트(Cost) — 대역폭으로 계산한다

> **코스트 = 기준 대역폭(100Mbps) ÷ 인터페이스 대역폭** (작을수록 좋다)

| 회선 | 대역폭 | 코스트 |
|------|--------|--------|
| 시리얼 | 1.544Mbps | **64** |
| 이더넷 | 10Mbps | **10** |
| 패스트이더넷 | 100Mbps | **1** |
| 기가비트 | 1Gbps | 1 (기본 계산으로는 구분 못 함 ※) |

- 경로 전체의 코스트는 **거쳐 가는 인터페이스 코스트의 합**
- ※ 기본 기준값이 100Mbps 라서 기가 이상은 전부 1이 된다 → 실무에선 `auto-cost reference-bandwidth` 로 기준을 올린다 (참고)

> ⭐ **RIP 이라면 홉이 적은 쪽, OSPF 는 코스트가 낮은 = 빠른 쪽**을 고른다.

### Area(영역) — 큰 망을 쪼개는 방법

- 라우터가 수백 대면 지도가 너무 커지고 계산이 무거워진다
- 그래서 망을 **Area 로 쪼개고**, 영역 안에서만 상세한 지도를 공유한다
- **Area 0 = 백본(중심)** — 다른 모든 영역은 Area 0 에 붙어야 한다

> 🧪 우리 실습은 규모가 작으니 **전부 `area 0`** 하나로 쓴다. 영역 설계는 CCNA 심화 주제.

### ⚠️ 와일드카드 마스크 — 오늘 최대의 함정

```bash
router ospf 1
 network 192.168.10.0 0.0.0.255 area 0
```

- 여기 들어가는 건 **서브넷 마스크가 아니다.** **와일드카드 마스크**다
- **계산법: 255 에서 서브넷 마스크를 뺀다**

| 서브넷 마스크 | 와일드카드 |
|---|---|
| 255.255.255.0 (/24) | **0.0.0.255** |
| 255.255.255.128 (/25) | 0.0.0.127 |
| 255.255.255.252 (/30) | **0.0.0.3** |
| 255.255.0.0 (/16) | **0.0.255.255** |

- **`0` = 반드시 같아야 하는 자리 / `255` = 아무거나 괜찮은 자리**
- 서브넷 마스크와 **정확히 반대**로 읽으면 된다 (0↔1 뒤집기)

> 🚨 `network 192.168.10.0 255.255.255.0 area 0` 이라고 치면 **동작하지 않는다.**
> 실습에서 이웃이 안 맺어지는 원인 1위.

### `router ospf 1` 의 `1` 은 무엇인가

- **프로세스 ID.** 이 장비 **안에서만** 의미가 있는 번호다
- **이웃과 같을 필요가 없다.** (R1 이 1, R2 가 5여도 이웃이 맺어진다)
- 반면 **`area` 번호는 반드시 같아야** 이웃이 된다 ⚠️

## 📖 EIGRP — 시스코의 고급 방식 (하이브리드)

**EIGRP = Enhanced Interior Gateway Routing Protocol**

- 시스코가 개발 (2013년 일부 공개 표준화). **시스코 장비 위주 환경**에서 강력하다
- 성격은 **고급 디스턴스 벡터**(하이브리드) — 이웃에게 배우지만, RIP 보다 훨씬 똑똑하다
- 메트릭 = **대역폭 + 지연**(기본). 대역폭·지연·신뢰도·부하를 조합할 수 있다
- **DUAL 알고리즘** — **미리 계산해 둔 백업 경로**(Feasible Successor)가 있어
  주 경로가 죽으면 **재계산 없이 즉시 전환** → 셋 중 **수렴이 가장 빠르다**
- **AD 90** (셋 중 가장 신뢰) · 내부 90 / 외부 170
- 설정이 OSPF 보다 간단하다 (`router eigrp 100` + `network`)

> 💡 **비유.** RIP = 옆집에 물어보기 / OSPF = 지도 펴고 계산하기 /
> EIGRP = **자주 가는 길의 우회로를 미리 외워둔 베테랑 기사**

> ⚠️ EIGRP 의 `router eigrp 100` 에서 **100 = AS 번호**. 이것은 **이웃과 반드시 같아야** 한다.
> (OSPF 프로세스 ID 와 헷갈리기 쉬운 지점 — 시험 단골)

## 📖 세 프로토콜 비교 ⭐ 오늘의 핵심 표

| | RIP | OSPF | EIGRP |
|---|-----|------|-------|
| 방식 | 디스턴스 벡터 | **링크 스테이트** | 하이브리드 |
| 비유 | 옆집에 물어보기 | 지도 펴고 계산 | 우회로 외운 기사 |
| 메트릭 | **홉 수** | **코스트(대역폭)** | 대역폭+지연 |
| 최대 규모 | 15홉 | 사실상 제한 없음 | 매우 큼 |
| 표준 | 개방형 | **개방형(표준)** | 시스코(일부 공개) |
| 규모 | 소 | **대** | 중·대 |
| 수렴 | 느림 | 빠름 | **매우 빠름** |
| 갱신 | 30초마다 전체 | **변화 시에만** | 변화 시에만 |
| **AD** | **120** | **110** | **90** |
| 설정 | 가장 쉬움 | 와일드카드가 까다로움 | 쉬움 |

> 💡 **한 줄 요약**
> **RIP = 단순·소규모 / OSPF = 표준·대규모 / EIGRP = 시스코·빠름**

### 어떤 걸 고를까 — 실무 판단

| 상황 | 선택 |
|------|------|
| 여러 회사 장비가 섞인 큰 망 | **OSPF** (표준이라 어디서나 된다) |
| 전부 시스코 장비 | **EIGRP** (설정 쉽고 수렴 빠름) |
| 라우터 2~3대 소규모 | **정적**도 충분 |
| 인터넷 사업자 간 연결 | **BGP** (7·8일차 이후 범위 밖, 이름만) |

## 📝 강의 메모

- 암기보다 **"홉만 보나 / 대역폭까지 보나 / 지도를 그리나"** 의 **관점 차이**로 설명
- 비유 3종(옆집·지도·베테랑 기사)을 칠판에 나란히 써두면 비교표가 저절로 채워진다
- ⚠️ **와일드카드 마스크는 반드시 손으로 계산시켜 볼 것** (255 − 마스크). 실습 최대 병목
- Area 는 "**Area 0 가 중심**" 정도만. 영역 설계는 CCNA 심화라고 선을 그어줄 것
- EIGRP 는 **패킷트레이서 실습 없이 표로만** 다룬다 (시간 관계 + 시스코 전용)
  → 궁금해하는 학생에겐 `router eigrp 100` + `network` 만 보여줘도 충분
