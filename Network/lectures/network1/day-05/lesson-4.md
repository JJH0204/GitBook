## 학습 목표

- 새 파일에 라우터 3대짜리 망을 처음부터 구성한다.
- RIPv2로 경로가 자동으로 채워지는 것을 확인한다.
- 세 번째 라우터가 합류할 때 손대지 않은 라우터에도 경로가 생기는 것을 본다.
- 회선을 끊었다 이어 자동 수렴을 관찰한다.
- 같은 망을 OSPF로 다시 구성해 두 프로토콜을 몸으로 비교한다.

## 1. 구성 요소

### 1.1 토폴로지 — 두 실습이 똑같다

```
[PC0]──[SW1]──[R1]══════[R2]══════[R3]──[SW2]──[PC2]
 .10.1         20.0/24       50.0/24        .30.1
 192.168.10.0/24                        192.168.30.0/24
```

| 장비 | G0/0 | G0/1 |
|---|---|---|
| R1 | 192.168.10.254 | 192.168.20.1 |
| R2 | 192.168.50.1 | 192.168.20.2 |
| R3 | 192.168.30.254 | 192.168.50.2 |

- PC0: 192.168.10.1, 게이트웨이 192.168.10.254
- PC2: 192.168.30.1, 게이트웨이 192.168.30.254

두 실습의 그림과 주소가 같은 것은 의도한 것이다. 바뀌는 것은 라우팅 프로토콜 하나뿐이라 두 프로토콜의 차이가 그대로 드러난다. 두 번째 구성은 손이 익어 훨씬 빨리 끝난다.

| 실습 | 단계 | 이 단계의 목적 | 시간 | 문서 |
|---|---|---|---|---|

## 2. 동작 원리 — 각 실습에서 봐야 할 것

### 2.1 RIPv2

**단계 1. 먼저 실패를 확인한다.** 인터페이스까지만 설정한 상태에서 PC0 → PC2로 ping한다.

- `ping 192.168.10.254`(내 게이트웨이)는 성공한다.
- `ping 192.168.30.1`(그 너머)은 실패한다.
- 각 라우터의 `show ip route`에는 `C`와 `L`만 있다.

**단계 2. R1·R2에만 RIP을 켠다.**

- 30초를 기다려야 경로가 생긴다. 학생 대부분이 여기서 "안 되는데요?"라고 한다.
- R1에 새로 생긴 줄: `R 192.168.50.0/24 [120/1] via 192.168.20.2`
- 아직 30.0은 없다. R3이 아직 아무 말도 하지 않기 때문이다.

**단계 3. R3에 RIP을 켠다. 오늘의 하이라이트다.** R3에서만 명령을 입력하고 R1은 보기만 한다.

```
R1의 라우팅 테이블 (R1에는 아무것도 입력하지 않았다)

R    192.168.50.0/24 [120/1] via 192.168.20.2   ← 아까 있던 것
R    192.168.30.0/24 [120/2] via 192.168.20.2   ← 새로 생겼다
```

**단계 4. 끊었다 잇기(자동 수렴).** R3의 LAN 인터페이스를 `shutdown`하면 잠시 뒤 R1에서 그 경로가 저절로 사라진다. `no shutdown`하면 최대 30초 안에 저절로 돌아온다.

| 시점 | R1의 30.0 경로 | 사람이 한 일 |
|---|---|---|
| 정상 | `R [120/2]` | - |
| R3 인터페이스 죽음 | 사라짐 | 없음 |
| 되살림 | 다시 생김 | 없음 |

오늘의 한 문장: "사람이 고친 게 아니라, 라우터들이 서로 알려서 고쳤다."

구성이 일렬이라 우회할 다른 길이 없다. 실제 망에서는 이때 다른 경로로 자동 우회한다. 이것이 진짜 의미의 수렴이다. RIP은 최악의 경우 3~4분이 걸린다. OSPF가 나온 이유다.

### 2.2 OSPF

- 설정하는 순간 이웃이 맺어졌다는 로그 메시지가 뜬다.
- `show ip ospf neighbor`에서 이웃 상태가 `FULL`이다.
- 경로가 몇 초 만에 생긴다. RIP은 30초를 기다렸다.

```
O    192.168.30.0/24 [110/3] via 192.168.20.2
─┬─                   ─┬─ ─┬─
 OSPF                  AD  코스트 — 홉 수가 아니다
```

### 2.3 AD 대결 (부록)

OSPF 실습 파일에서 OSPF를 지우지 않고 RIP을 함께 켠다.

```
RIP을 켜기 전:  O    192.168.30.0/24 [110/3] via 192.168.20.2
RIP을 켠 뒤:    O    192.168.30.0/24 [110/3] via 192.168.20.2   ← 그대로다
```

- `show ip protocols`에는 rip과 ospf가 둘 다 돌고 있다.
- 그런데 테이블에는 `O`만 있다.

## 3. 확인 질문

| 단계 | 질문 | 답 |
|---|---|---|
| RIPv2 실패 확인 | 라우터들은 지금 무엇을 알고 있나? | 자기에게 붙은 것만. 남의 네트워크는 하나도 모른다 |
| RIPv2 R1·R2 | `network` 뒤에 적은 것은 목적지인가, 내 것인가? | 내 것. → [2. RIP](lesson-2.md) |
| RIPv2 R1·R2 | `[120/1]`을 읽어 보라 | AD 120(RIP), 1홉 |
| RIPv2 R1·R2 | R1은 50.0을 어떻게 알았나? | R2가 알려 줬다. 아무도 `ip route`를 입력하지 않았다 |
| RIPv2 R3 | R3을 설정하는 동안 R1에 무엇을 입력했나? | 아무것도 입력하지 않았다 |
| RIPv2 R3 | 30.0의 홉은 왜 2인가? | 라우터를 두 번 거치기 때문이다 |
| RIPv2 R3 | 정적이었다면 몇 대를 고쳤을까? | 세 대 전부 |
| OSPF | RIP은 30초를 기다렸는데 OSPF는 왜 금방 됐나? | RIP은 주기적으로, OSPF는 변화가 있을 때 바로 보낸다. → [3. OSPF와 EIGRP](lesson-3.md) |
| OSPF | 뒤 숫자 3은 홉 수인가? | 아니다. 코스트(대역폭 기반)다 |
| OSPF | 와일드카드 0.0.0.255는 어떻게 나왔나? | 255에서 서브넷 마스크를 뺀다 |
| AD 대결 | RIP을 켰는데 왜 `R` 경로가 하나도 없나? | AD가 낮은 쪽만 테이블에 오른다(110 < 120). 4일차 CCNA Q4 회수. → [4. 오늘의 CCNA](../day-04/lesson-4.md) |

## 4. 강의 메모

- 세 번째 라우터가 합류하는 장면에 시간을 몰아준다. 오늘 수업의 값어치가 그 한 장면에 있다.
- "기다리는 실습"이라는 것을 실습 시작 전에 반드시 공지한다. 하지 않으면 학생들이 설정을 지우고 다시 입력하느라 시간을 다 쓴다.
- 그림을 두 번 만드는 것을 부담스러워하는 학생이 있다. "두 번째는 5분이면 되고, 이것이 시험에 나오는 그 과정이다"라고 미리 말한다.
- 수렴 관찰 중 대기 시간에는 RIP 타이머 4개를 칠판에 설명하면 맞는다.
- AD 대결은 OSPF를 지우지 않는 것이 핵심이다. 미리 지우면 볼 수 없다.
- 시간이 부족하면 수렴 관찰을 생략하고 OSPF 실습을 살린다. AD가 6일차의 전제다.
- 다음 시간(6일차)은 서로 다른 라우팅 프로토콜을 잇는 재분배(Redistribution)다. → [6일차 · 라우팅 프로토콜 심화](../day-06/README.md)
