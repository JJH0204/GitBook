## 🎯 학습 목표

- 새 파일에 라우터 3대짜리 망을 **처음부터** 구성한다
- **RIPv2** 로 경로가 자동으로 채워지는 것을 확인한다
- 세 번째 라우터가 합류할 때 **손대지 않은 라우터에도 경로가 생기는 것**을 본다
- 회선을 끊었다 이어 **자동 수렴**을 관찰한다
- 같은 망을 **OSPF** 로 다시 구성해 두 프로토콜을 몸으로 비교한다

## 🗺 오늘의 토폴로지 — 두 실습이 똑같다

```
[PC0]──[SW1]──[R1]══════[R2]══════[R3]──[SW2]──[PC2]
 .10.1         20.0/24       50.0/24        .30.1
 192.168.10.0/24                        192.168.30.0/24
```

| 장비 | G0/0 | G0/1 |
|------|------|------|
| R1 | 192.168.10.254 | 192.168.20.1 |
| R2 | 192.168.50.1 | 192.168.20.2 |
| R3 | 192.168.30.254 | 192.168.50.2 |

- **PC0** 192.168.10.1 / 게이트웨이 192.168.10.254
- **PC2** 192.168.30.1 / 게이트웨이 192.168.30.254

> 💡 **두 실습의 그림과 주소가 같은 것은 의도한 것이다.** 바뀌는 건 **라우팅 프로토콜 하나뿐**이라
> 두 프로토콜의 차이가 그대로 드러난다. 두 번째 구성은 손이 익어 훨씬 빨리 끝난다.

## 🧪 실습 흐름 한눈에

| 실습 | 단계 | 이 단계의 목적 | 시간 |
|------|------|----------------|------|
| **RIPv2** | 그림 만들기 | 라우터 3대 · PC 2대 · 인터페이스 설정 | 25분 |
| | 먼저 실패 확인 | 경로가 없으면 못 간다 (동기 부여) | 5분 |
| | R1·R2 에 RIP | "내 것만 신고" 로 길이 생긴다 | 20분 |
| | R3 에 RIP ⭐ | **손 안 댄 R1 에 경로가 저절로** | 25분 |
| | 끊었다 잇기 | **자동 수렴** 관찰 | 10분 |
| **OSPF** | 새 파일에 같은 그림 | 두 번째라 빠르다 | 15분 |
| | OSPF 설정 ⭐ | 와일드카드 · 빠른 수렴 | 20분 |
| (부록) | AD 대결 | RIP 을 얹으면 누가 이기나 | 15분 |

## 🧪 RIPv2 실습 — 라우터끼리 알아서 채우게 하기

### ① 먼저 실패를 확인한다

인터페이스까지만 설정한 상태에서 PC0 → PC2 로 ping 을 쳐본다.

**🔎 봐야 할 것**

- `ping 192.168.10.254`(내 게이트웨이) → **성공**
- `ping 192.168.30.1`(그 너머) → **실패**
- 각 라우터의 `show ip route` 에는 **`C` 와 `L` 만** 있다

**🗣 물어볼 것** — "라우터들은 지금 무엇을 알고 있나요?"
→ **자기에게 붙은 것만.** 남의 네트워크는 하나도 모른다.

### ② R1 · R2 에만 RIP 을 켠다

```bash
router rip
 version 2
 no auto-summary
 network 192.168.10.0
 network 192.168.20.0
```

**🔎 봐야 할 것**

- ⏳ **30초를 기다려야** 경로가 생긴다 (학생 대부분이 여기서 "안 되는데요?" 라고 한다)
- R1 에 새로 생긴 줄: `R 192.168.50.0/24 [120/1] via 192.168.20.2`
- **아직 30.0 은 없다** — R3 이 아직 아무 말도 안 하고 있으니까

**🗣 물어볼 것**

- "`network` 뒤에 적은 건 목적지인가요, 내 것인가요?" → **내 것** ([2_RIP](lesson-2.md))
- "`[120/1]` 을 읽어보세요" → **AD 120(RIP), 1홉**
- "R1 은 50.0 을 어떻게 알았죠?" → **R2 가 알려줬다.** 아무도 `ip route` 를 안 쳤다

### ③ R3 에 RIP 을 켠다 ⭐ 오늘의 하이라이트

R3 에서만 명령을 친다. **R1 은 쳐다보기만 한다.**

**🔎 봐야 할 것 — 이 장면이 오늘의 전부다**

```
R1 의 라우팅 테이블 (R1 에는 아무것도 치지 않았다)

R    192.168.50.0/24 [120/1] via 192.168.20.2   ← 아까 있던 것
R    192.168.30.0/24 [120/2] via 192.168.20.2   ← 새로 생겼다
```

**🗣 물어볼 것**

- "R3 을 설정하는 동안 R1 에 뭘 쳤죠?" → **아무것도**
- "30.0 의 홉은 왜 2일까요?" → 라우터를 **두 번** 거치니까 ([2_RIP](lesson-2.md))
- "정적이었다면 몇 대를 고쳤을까요?" → **세 대 전부**

### ④ 끊었다 잇기 — 자동 수렴 관찰

R3 의 LAN 인터페이스를 `shutdown` → 잠시 뒤 R1 에서 그 경로가 **저절로 사라진다.**
`no shutdown` → **최대 30초 안에 저절로 돌아온다.**

**🔎 봐야 할 것**

| 시점 | R1 의 30.0 경로 | 사람이 한 일 |
|------|------------------|--------------|
| 정상 | `R [120/2]` | — |
| R3 인터페이스 죽음 | **사라짐** | **없음** |
| 되살림 | **다시 생김** | **없음** |

**🗣 오늘의 한 문장** — **"사람이 고친 게 아니라, 라우터들이 서로 알려서 고쳤다."**

> 💡 우리 구성은 **일렬**이라 우회할 다른 길이 없다. 실제 망에서는 이때
> **다른 경로로 자동 우회**한다 — 이것이 진짜 의미의 **수렴**이다.
> RIP 은 최악의 경우 **3~4분**이 걸린다 → OSPF 가 나온 이유

## 🧪 OSPF 실습 — 지도를 보고 계산하게 하기

**새 파일**에 같은 그림을 다시 만든다. 인터페이스 설정까지 마친 뒤 OSPF 만 얹는다.

```bash
router ospf 1
 network 192.168.10.0 0.0.0.255 area 0    ← ⚠️ 와일드카드 마스크
 network 192.168.20.0 0.0.0.255 area 0
```

**🔎 봐야 할 것**

- 설정하는 순간 **`ADJACENCY ESTABLISHED`** 메시지가 뜬다 — 이웃이 맺어지는 순간
- `show ip ospf neighbor` → 이웃이 **`FULL`**
- 경로가 **몇 초 만에** 생긴다 (RIP 은 30초를 기다렸다)

```
O    192.168.30.0/24 [110/3] via 192.168.20.2
─┬─                   ─┬─ ─┬─
 OSPF                  AD  코스트 — 홉 수가 아니다
```

**🗣 물어볼 것**

- "RIP 은 30초를 기다렸는데 OSPF 는 왜 금방 됐죠?"
  → RIP 은 **주기적으로**, OSPF 는 **변화가 있을 때 바로** 보낸다 ([3_OSPF와_EIGRP](lesson-3.md))
- "뒤 숫자 3 은 홉 수인가요?" → 아니다. **코스트**(대역폭 기반)다
- "와일드카드 0.0.0.255 는 어떻게 나왔죠?" → **255에서 서브넷 마스크를 뺀다**

## 🧪 부록 · AD 대결 (여유 있으면)

OSPF 실습 파일에서 **OSPF 를 지우지 않고** RIP 을 함께 켠다.

**🔎 봐야 할 것**

```
RIP 을 켜기 전:  O    192.168.30.0/24 [110/3] via 192.168.20.2
RIP 을 켠 뒤:    O    192.168.30.0/24 [110/3] via 192.168.20.2   ← 그대로다!
```

- `show ip protocols` → **rip 과 ospf 가 둘 다 돌고 있다**
- 그런데 테이블에는 **`O` 만** 있다

**🗣 물어볼 것**

- "RIP 을 켰는데 왜 `R` 경로가 하나도 없죠?"
  → **AD 가 낮은 쪽만 테이블에 오른다** (110 < 120)
- 4일차 CCNA Q4 회수 → [4_오늘의_CCNA](../day-04/lesson-4.md)

## ⚠️ 실습 중 막히면 — 오늘판 5대 원인

| 증상 | 원인 |
|------|------|
| 경로가 안 생긴다 | ⏳ **30초를 안 기다렸다** (1위) |
| 경로가 이상하게 뭉쳐 보인다 | `version 2` · `no auto-summary` 누락 |
| `network` 가 무시된다 | **목적지**를 적었다 → 내게 연결된 네트워크를 적을 것 |
| OSPF 이웃이 안 맺어진다 | **area 번호 불일치** · 와일드카드 오류 |
| `C` 가 없다 | `no shutdown` 안 했다 |

> 전체 점검표는 → [부록 E · 안 될 때 30초 점검](commands.md)

## 📝 강의 메모

- **세 번째 라우터가 합류하는 장면에 시간을 몰아준다.** 오늘 수업의 값어치가 그 한 장면에 다 있다
- ⏳ **"기다리는 실습"** 이라는 걸 실습 시작 전에 **꼭 공지**할 것.
  안 하면 학생들이 설정을 지우고 다시 치느라 시간을 다 쓴다
- **그림을 두 번 만드는 것을 부담스러워하는 학생이 있다.** "두 번째는 5분이면 된다,
  그리고 이게 시험에 나오는 그 과정이다" 라고 미리 말해줄 것
- 수렴 관찰 중 대기 시간에는 **RIP 타이머 4개**를 칠판에 설명하면 딱 맞는다
- AD 대결은 **OSPF 를 지우지 않는 것**이 핵심 — 미리 지워버리면 볼 수 없다
- 시간이 부족하면 **수렴 관찰을 생략**하고 OSPF 실습을 살릴 것 (AD 가 6일차의 전제)
