## Q1. `network` 는 무슨 뜻인가 — [2_RIP](lesson-2.md)

A router is configured with `router rip` and `network 192.168.10.0`.
What does this command actually do?
(`network 192.168.10.0` 은 실제로 무엇을 하는 명령인가?)

- A. 192.168.10.0 **으로 가는 경로**를 만든다
- B. 192.168.10.0 에 속한 **내 인터페이스에서 RIP 을 켜고, 그 네트워크를 이웃에게 광고**한다
- C. 192.168.10.0 에서 오는 트래픽만 허용한다
- D. 192.168.10.0 을 기본 게이트웨이로 지정한다

{% hint style="success" %}
**정답 및 해설**

**정답: B**
- **정적은 "가는 길", 동적은 "내 것 신고"** — 방향이 정반대다
- `network` 는 두 가지 일을 동시에 한다: ① 해당 인터페이스로 **RIP 을 켠다**
  ② 그 네트워크를 **이웃에게 광고**한다
- A 가 오답인 이유: 그건 4일차의 **`ip route`** 다 → [2_라우터_동작원리](../day-04/lesson-2.md)
- 그래서 `network` 뒤에는 **반드시 내게 직접 연결된(Connected)** 네트워크를 적는다
- 실습에서 가장 많이 틀리는 지점 → [RIPv2 실습](commands.md)
{% endhint %}

## Q2. RIP 은 왜 느린 길을 고르나 — [2_RIP](lesson-2.md)

Path A crosses **one 1 Mbps link**. Path B crosses **two 1 Gbps links**.
Which path does **RIP** choose, and why?
(RIP 은 어느 길을 고르며, 그 이유는?)

- A. Path B — 대역폭이 크니까
- B. Path A — **홉 수만 세기 때문에**
- C. 둘을 번갈아 쓴다(부하 분산)
- D. 관리자가 지정한 쪽

{% hint style="success" %}
**정답 및 해설**

**정답: B**
- RIP 의 메트릭은 **홉 카운트뿐**이다. **대역폭을 아예 보지 않는다**
- Path A = 1홉, Path B = 2홉 → RIP 은 **1홉인 A** 를 고른다. **1000배 느린데도.**
- 이 한계 때문에 **대역폭을 보는 OSPF(코스트)** 가 나왔다 → [3_OSPF와_EIGRP](lesson-3.md)
- 함께 외울 RIP 3종 세트: **15홉 · 30초 · AD 120**
- 참고: 16홉 = **무한대 = 도달 불가**를 뜻하는 약속값
{% endhint %}

## Q3. 누구 말을 믿을까 (동적 편) — [1_라우팅프로토콜_개요](lesson-1.md)

A router learns the **same network** via RIP (AD 120) and OSPF (AD 110).
RIP reports **1 hop**; OSPF reports a path of **3 routers**.
Which route is installed in the routing table?
(RIP 은 1홉, OSPF 는 3대를 거친다고 한다. 테이블에 오르는 것은?)

- A. RIP — 홉이 더 적으니까
- B. **OSPF — AD 가 더 낮으니까**
- C. 둘 다 올라간다
- D. 메트릭 숫자가 작은 쪽

{% hint style="success" %}
**정답 및 해설**

**정답: B**
- **출처가 다르면 메트릭을 비교하지 않는다.** 단위가 달라서 비교 자체가 불가능하다
  (홉 1 과 코스트 3 은 **같은 자로 잰 값이 아니다**)
- 출처가 다를 땐 **AD 먼저** → OSPF **110** < RIP **120** → **OSPF 승**
- A·D 가 오답인 이유: 메트릭은 **같은 프로토콜 안에서만** 쓰는 기준
- 되짚기: **AD 대결**에서 RIP 을 켰는데도 `R` 경로가 하나도 안 생긴 그 장면
- 순서 정리: **① Longest Prefix Match → ② AD → ③ Metric**
{% endhint %}

## Q4. OSPF 가 안 켜진다 — [3_OSPF와_EIGRP](lesson-3.md)

An engineer types `network 192.168.10.0 255.255.255.0 area 0` under `router ospf 1`
and OSPF does not work. What is wrong?
(OSPF 가 동작하지 않는다. 무엇이 잘못됐나?)

- A. area 번호가 0이면 안 된다
- B. 프로세스 ID 가 이웃과 달라서
- C. **서브넷 마스크를 썼다 — 와일드카드 마스크(`0.0.0.255`)를 써야 한다**
- D. `no auto-summary` 를 안 했다

{% hint style="success" %}
**정답 및 해설**

**정답: C**
- OSPF 의 `network` 뒤에는 **와일드카드 마스크**가 온다
- 계산: **255 에서 서브넷 마스크를 뺀다** → 255.255.255.0 → **0.0.0.255**
- `0` = 반드시 같아야 하는 자리 / `255` = 아무거나 괜찮은 자리
- A 가 오답인 이유: **Area 0 은 오히려 백본**으로, 반드시 있어야 하는 영역이다
- B 가 오답인 이유: **프로세스 ID 는 이웃과 달라도 된다**(장비 내부용).
  반대로 **`area` 번호와 EIGRP 의 AS 번호는 반드시 같아야** 한다 ⚠️ 시험 단골
- D 가 오답인 이유: `no auto-summary` 는 **RIP·EIGRP** 쪽 이야기
{% endhint %}

## Q5. 이 한 줄을 읽어라 — [1_라우팅프로토콜_개요](lesson-1.md)

```
O    192.168.30.0/24 [110/3] via 192.168.20.2, 00:00:14, GigabitEthernet0/1
```

What do **110** and **3** represent?
(110 과 3 은 각각 무엇인가?)

- A. 110 = 메트릭, 3 = 홉 수
- B. **110 = AD(관리 거리), 3 = 메트릭(코스트)**
- C. 110 = 포트 번호, 3 = 우선순위
- D. 110 = 대역폭, 3 = 지연

{% hint style="success" %}
**정답 및 해설**

**정답: B**
- 대괄호는 항상 **`[AD / 메트릭]`** 순서다
- **앞 숫자 = 출처의 신뢰도** — 110 이므로 **OSPF**(맨 앞의 `O` 와 일치)
- **뒤 숫자 = 그 프로토콜의 자로 잰 거리** — OSPF 니까 **코스트**
- 나머지도 읽어보자: `via 192.168.20.2` = **다음 홉** ·
  `00:00:14` = 이 정보를 안 지 14초 · `GigabitEthernet0/1` = **나가는 문**
- 코드 정리: **`C`** 직접연결 · **`L`** 로컬 · **`S`** 정적 · **`R`** RIP ·
  **`O`** OSPF · **`D`** EIGRP
- 💡 `D` 가 EIGRP 인 이유는 알고리즘 이름이 **DUAL** 이라서 (E 는 이미 `E`xternal 이 씀)
{% endhint %}

## 📝 강의 메모

- Q1(개념) → Q2(RIP) → Q3(AD) → Q4(OSPF 설정) → Q5(테이블 읽기) 순으로 **오늘 흐름 그대로**
- **Q3 과 Q5 가 오늘의 중핵**이다. 시간이 없으면 이 둘만이라도
- Q3 은 **"단위가 다르면 비교할 수 없다"** 를 말로 꺼내게 할 것 —
  이 감각이 **6일차 재분배(seed metric)** 의 전제가 된다
- Q4 는 실습에서 직접 겪은 오류라 정답률이 높다 → 자신감 주기 좋은 문제
- Q5 는 **실제 출력 한 줄을 화면에 띄워놓고** 손가락으로 짚어가며 읽힐 것
- 마무리 예고: **"라우터마다 쓰는 말이 다르면 어떻게 될까?"** → 6일차 재분배
