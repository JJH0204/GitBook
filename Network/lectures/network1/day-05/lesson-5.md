## 1. 점검 방법

수업 마무리로 오늘 배운 내용에 맞춘 CCNA 실전형 문제를 함께 푼다. CCNA 실제 시험은 영어이므로 핵심 용어는 영문을 함께 적었다.

1. 문제를 먼저 각자 풀어 본다.
2. `정답 및 해설` 상자를 보고 함께 확인한다.
3. 해설의 링크로 그날 배운 문서를 되짚는다.

5일차는 `[AD/메트릭]` 대괄호 한 줄이 주인공이다. 답을 고르기 전에 "앞 숫자 이야기인가, 뒤 숫자 이야기인가?"부터 묻는다.

## 2. 점검 항목

### Q1. `network`는 무슨 뜻인가

관련 문서: [2. RIP](lesson-2.md)(LEC-N1-05-002-DO)

A router is configured with `router rip` and `network 192.168.10.0`.
What does this command actually do?
(`network 192.168.10.0`은 실제로 무엇을 하는 명령인가?)

- A. 192.168.10.0으로 가는 경로를 만든다
- B. 192.168.10.0에 속한 내 인터페이스에서 RIP을 켜고, 그 네트워크를 이웃에게 광고한다
- C. 192.168.10.0에서 오는 트래픽만 허용한다
- D. 192.168.10.0을 기본 게이트웨이로 지정한다

{% hint style="info" %}
**정답 및 해설**

**정답: B**
- 정적은 "가는 길", 동적은 "내 것 신고"다. 방향이 정반대다.
- `network`는 두 가지 일을 동시에 한다. 해당 인터페이스로 RIP을 켜고, 그 네트워크를 이웃에게 광고한다.
- A가 오답인 이유: 그것은 4일차의 `ip route`다. → [2. 라우터는 어떻게 동작하나](../day-04/lesson-2.md)
- 그래서 `network` 뒤에는 반드시 내게 직접 연결된(Connected) 네트워크를 적는다.
- 실습에서 가장 많이 틀리는 지점이다. → [LEC-N1-05-007-MP](lesson-4-lab-ripv2.md)
{% endhint %}

### Q2. RIP은 왜 느린 길을 고르나

관련 문서: [2. RIP](lesson-2.md)(LEC-N1-05-002-DO)

Path A crosses **one 1 Mbps link**. Path B crosses **two 1 Gbps links**.
Which path does **RIP** choose, and why?
(RIP은 어느 길을 고르며, 그 이유는?)

- A. Path B — 대역폭이 크니까
- B. Path A — 홉 수만 세기 때문에
- C. 둘을 번갈아 쓴다(부하 분산)
- D. 관리자가 지정한 쪽

{% hint style="info" %}
**정답 및 해설**

**정답: B**
- RIP의 메트릭은 홉 카운트뿐이다. 대역폭을 아예 보지 않는다.
- Path A는 1홉, Path B는 2홉이므로 RIP은 1홉인 A를 고른다. 1000배 느린데도 그렇다.
- 이 한계 때문에 대역폭을 보는 OSPF(코스트)가 나왔다. → [3. OSPF와 EIGRP](lesson-3.md)
- 함께 외울 RIP 3종 세트: 15홉, 30초, AD 120.
- 참고: 16홉은 무한대, 즉 도달 불가를 뜻하는 약속값이다.
{% endhint %}

### Q3. 누구 말을 믿을까 (동적 편)

관련 문서: [1. 라우팅 프로토콜 개요](lesson-1.md)(LEC-N1-05-001-DO)

A router learns the **same network** via RIP (AD 120) and OSPF (AD 110).
RIP reports **1 hop**; OSPF reports a path of **3 routers**.
Which route is installed in the routing table?
(RIP은 1홉, OSPF는 3대를 거친다고 한다. 테이블에 오르는 것은?)

- A. RIP — 홉이 더 적으니까
- B. OSPF — AD가 더 낮으니까
- C. 둘 다 올라간다
- D. 메트릭 숫자가 작은 쪽

{% hint style="info" %}
**정답 및 해설**

**정답: B**
- 출처가 다르면 메트릭을 비교하지 않는다. 단위가 달라서 비교할 수 없다(홉 1과 코스트 3은 같은 자로 잰 값이 아니다).
- 출처가 다를 때는 AD가 먼저다. OSPF 110 < RIP 120이므로 OSPF가 이긴다.
- A, D가 오답인 이유: 메트릭은 같은 프로토콜 안에서만 쓰는 기준이다.
- 되짚기: AD 대결에서 RIP을 켰는데도 `R` 경로가 하나도 생기지 않은 장면. → [LEC-N1-05-009-MP](lesson-4-lab-ad.md)
- 순서 정리: 1. Longest Prefix Match, 2. AD, 3. Metric.
{% endhint %}

### Q4. OSPF가 켜지지 않는다

관련 문서: [3. OSPF와 EIGRP](lesson-3.md)(LEC-N1-05-003-DO)

An engineer types `network 192.168.10.0 255.255.255.0 area 0` under `router ospf 1`
and OSPF does not work. What is wrong?
(OSPF가 동작하지 않는다. 무엇이 잘못됐나?)

- A. area 번호가 0이면 안 된다
- B. 프로세스 ID가 이웃과 달라서
- C. 서브넷 마스크를 썼다 — 와일드카드 마스크(`0.0.0.255`)를 써야 한다
- D. `no auto-summary`를 입력하지 않았다

{% hint style="info" %}
**정답 및 해설**

**정답: C**
- OSPF의 `network` 뒤에는 와일드카드 마스크가 온다.
- 계산: 255에서 서브넷 마스크를 뺀다. 255.255.255.0 → 0.0.0.255.
- `0`은 반드시 같아야 하는 자리, `255`는 아무거나 괜찮은 자리다.
- A가 오답인 이유: Area 0은 오히려 백본으로, 반드시 있어야 하는 영역이다.
- B가 오답인 이유: 프로세스 ID는 이웃과 달라도 된다(장비 내부용). 반대로 `area` 번호와 EIGRP의 AS 번호는 반드시 같아야 한다. 시험 단골이다.
- D가 오답인 이유: `no auto-summary`는 RIP·EIGRP 쪽 이야기다.
{% endhint %}

### Q5. 이 한 줄을 읽어라

관련 문서: [1. 라우팅 프로토콜 개요](lesson-1.md)(LEC-N1-05-001-DO)

```
O    192.168.30.0/24 [110/3] via 192.168.20.2, 00:00:14, GigabitEthernet0/1
```

What do **110** and **3** represent?
(110과 3은 각각 무엇인가?)

- A. 110 = 메트릭, 3 = 홉 수
- B. 110 = AD(관리 거리), 3 = 메트릭(코스트)
- C. 110 = 포트 번호, 3 = 우선순위
- D. 110 = 대역폭, 3 = 지연

{% hint style="info" %}
**정답 및 해설**

**정답: B**
- 대괄호는 항상 `[AD / 메트릭]` 순서다.
- 앞 숫자는 출처의 신뢰도다. 110이므로 OSPF다(맨 앞의 `O`와 일치한다).
- 뒤 숫자는 그 프로토콜의 자로 잰 거리다. OSPF이므로 코스트다.
- 나머지도 읽는다. `via 192.168.20.2`는 다음 홉, `00:00:14`는 이 정보를 안 지 14초, `GigabitEthernet0/1`은 나가는 인터페이스다.
- 코드 정리: `C` 직접 연결, `L` 로컬, `S` 정적, `R` RIP, `O` OSPF, `D` EIGRP.
{% endhint %}

## 강의 메모

- Q1(개념), Q2(RIP), Q3(AD), Q4(OSPF 설정), Q5(테이블 읽기) 순으로 오늘 흐름 그대로 푼다.

- Q4는 실습에서 직접 겪은 오류라 정답률이 높다. 자신감을 주기 좋은 문제다.
- Q5는 실제 출력 한 줄을 화면에 띄워 놓고 손가락으로 짚어 가며 읽힌다.
- 마무리 예고: "라우터마다 쓰는 말이 다르면 어떻게 될까?" → 6일차 재분배.
