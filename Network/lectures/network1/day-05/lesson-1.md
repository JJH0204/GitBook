## 🎯 학습 목표

- 정적 라우팅의 한계와 동적 라우팅의 필요성을 **숫자로** 설명한다
- 라우터끼리 **무엇을 주고받는지**(내 네트워크 목록) 이해한다
- **메트릭**과 **AD(관리 거리)** 의 역할 차이를 구분한다
- **수렴(Convergence)** 이라는 말의 뜻을 안다
- 라우팅 프로토콜의 분류(IGP/EGP, 디스턴스 벡터/링크 스테이트)를 안다

## 🌉 다리 놓기: "라우터가 100대라면, 표를 손으로 다 넣을까?"

4일차에 라우팅 테이블을 채우는 3가지 — **직접 연결 · 정적 · 동적** 중
**동적은 5일차**라고 예고했다. → [2_라우터_동작원리](../day-04/lesson-2.md)

그리고 4일차 Lab 12 에서 이런 걸 겪었다.

- 라우터를 **한 대 끼워 넣었더니**, 양쪽 라우터에 `ip route` 를 **각각** 넣어야 했다
- 한쪽만 넣었더니 **ping 이 실패**했다 (라우팅은 왕복)
- 한 줄 지웠더니 **바로 통신이 끊겼다**

라우터 2대에서도 이 정도다. **그럼 10대면? 100대면?**

## 📖 정적 라우팅의 한계 — 손으로 넣는 줄의 개수

> ❓ 라우터 `n` 대가 각각 자기 LAN 을 하나씩 갖고 일렬로 이어져 있다면,
> 손으로 넣어야 하는 `ip route` 줄은 몇 개일까?

| 라우터 수 | 손으로 넣을 정적 경로 (대략) |
|-----------|------------------------------|
| 2대 | 2줄 |
| 3대 | 6줄 |
| 5대 | 20줄 |
| **10대** | **90줄** |
| 100대 | 약 9,900줄 |

- 각 라우터가 **자기를 뺀 나머지 전부**로 가는 길을 알아야 하니 대략 `n × (n-1)`
- 게다가 **네트워크를 하나 추가할 때마다** 전 장비를 다시 손봐야 한다
- 회선이 하나 끊기면? **사람이 알아차리고 사람이 고쳐야** 한다 (새벽 3시에도)

> 💡 **비유 — 종이 지도 vs 내비게이션.**
> 정적 = 길이 바뀔 때마다 내가 지도에 직접 고쳐 그리기.
> 동적 = 도로 상황이 바뀌면 내비가 **알아서 새 길을 알려주는 것.**

## 📖 그래서 동적 라우팅 — "내 것만 알려주면, 길은 자기들끼리"

동적 라우팅에서 관리자가 하는 일은 **딱 하나**다.

> **"내가 직접 가지고 있는 네트워크는 이것들입니다"** 라고 신고하는 것.

- **목적지로 가는 길을 적는 게 아니다.** (정적과 정반대!)
- 신고를 받은 라우터들이 **서로 소식을 주고받아** 나머지를 알아서 채운다

|           | 정적(Static)                               | 동적(Dynamic)            |
| --------- | ---------------------------------------- | ---------------------- |
| 관리자가 적는 것 | **목적지로 가는 길**                            | **내가 가진 네트워크**         |
| 명령 예      | `ip route 192.168.30.0 ... 192.168.20.2` | `network 192.168.10.0` |
| 설정        | 관리자가 수동                                  | 프로토콜이 자동               |
| 규모        | 소규모 (라우터 몇 대)                            | 중·대규모                  |
| 장애 대응     | **사람이 수동 수정**                            | **자동 우회(수렴)**          |
| 부하        | 없음                                       | 약간의 CPU·대역폭            |
| 예측 가능성    | 높다 (내가 적은 대로)                            | 상황에 따라 바뀐다             |

> ⚠️ **동적이 항상 정답은 아니다.** 라우터 2~3대짜리 작은 망, 또는 **경로를 반드시 고정**해야
> 하는 보안 구간에서는 정적이 더 낫다. 실무에선 **둘을 섞어 쓴다.**

## 📖 수렴(Convergence) — 오늘 꼭 가져갈 단어

> **수렴 = 망에 변화가 생긴 뒤, 모든 라우터의 라우팅 테이블이 다시 일치하게 되는 것.**
> 그때까지 걸린 시간이 **수렴 시간**.

- 회선이 끊겼다 → 그 소식이 퍼진다 → 모두가 새 경로로 합의한다 → **수렴 완료**
- **수렴 중에는 통신이 불안정**하다 (어떤 라우터는 옛날 정보로 판단하니까)
- 그래서 라우팅 프로토콜의 성능은 **수렴이 얼마나 빠른가**로 평가한다

> 💡 오늘 실습에서 회선을 끊었다 이었을 때, 경로가 사라졌다 다시 생기기까지
> 기다린 그 시간이 바로 **수렴 시간**이다.

## 📖 경로를 고르는 두 기준 — 메트릭과 AD

> 🚨 **오늘 시험에 반드시 나오는 구분.** 둘 다 "경로를 고르는 기준"인데 **쓰이는 층이 다르다.**

### ① 메트릭(Metric) — **같은 프로토콜 안에서** 여러 길 중 최적 고르기

| 프로토콜 | 메트릭 = 무엇으로 재나 |
|----------|------------------------|
| RIP | **홉 수** (거쳐 가는 라우터 수) |
| OSPF | **코스트** (대역폭 기반, 빠를수록 작다) |
| EIGRP | **대역폭 + 지연** (복합) |

- **작을수록 좋은 길.** 같은 프로토콜끼리만 비교 가능하다
- `show ip route` 의 `[120/2]` 에서 **뒤 숫자 `2`** 가 메트릭

### ② AD(Administrative Distance, 관리 거리) — **출처가 다를 때** 누구 말을 믿을까

| 경로 출처 | AD | 뜻 |
|-----------|----|-----|
| 직접 연결(Connected) | **0** | 내 눈으로 본 것 |
| 정적(Static) | **1** | 관리자가 직접 적어준 것 |
| EIGRP | **90** | |
| OSPF | **110** | |
| RIP | **120** | 소문으로 들은 것 |
| (알 수 없음) | 255 | 절대 쓰지 않음 |

- **낮을수록 신뢰**. `show ip route` 의 `[120/2]` 에서 **앞 숫자 `120`** 이 AD
- 순서 기억법: **"내 눈 > 관리자 > EIGRP > OSPF > RIP"**

> 💡 **한 문장 구분법**
> **메트릭 = 같은 팀 안에서 누가 더 빠른가 / AD = 다른 팀끼리 누구 말을 믿을까**

### 두 기준이 적용되는 순서

```
① 목적지와 가장 잘 맞는 경로들을 고른다   → Longest Prefix Match (4일차)
② 출처가 여럿이면 AD 가 낮은 쪽만 남긴다   → AD
③ 남은 것 중 메트릭이 작은 것을 고른다     → Metric
```

> 🧪 오늘 실습 마지막의 **AD 대결**에서 RIP 과 OSPF 를 동시에 켜도 `O` 만 테이블에 오른다.
> 이유는 ②. **110 < 120** 이라서. (RIP 을 지운 게 아니다!)

## 📖 라우팅 프로토콜의 분류

### ① 사는 곳으로 — IGP vs EGP

| | IGP (내부 게이트웨이 프로토콜) | EGP (외부) |
|---|---|---|
| 범위 | **한 조직(AS) 안** | **조직과 조직 사이** |
| 예 | **RIP · OSPF · EIGRP** ← 오늘 | **BGP** ← 인터넷 백본 |
| 목표 | 가장 빠른 길 | 정책(계약·비용)에 맞는 길 |

> **AS(Autonomous System, 자율 시스템)** = 하나의 관리 주체가 운영하는 네트워크 덩어리.
> 예: KT 전체가 하나의 AS, 우리 회사 전체가 하나의 AS.

### ② 일하는 방식으로 — 디스턴스 벡터 vs 링크 스테이트

| | 디스턴스 벡터 | 링크 스테이트 |
|---|---------------|---------------|
| 아는 것 | **이웃이 해준 말**만 | **망 전체 지도** |
| 보내는 것 | 내 라우팅 테이블 전체 | 내 링크 상태 정보 |
| 비유 | **소문 듣고 판단** | **지도 보고 계산** |
| 예 | **RIP** | **OSPF** |
| 계산 | 이웃 값 + 1 | 다익스트라(SPF) 최단 경로 |
| 수렴 | 느림 | 빠름 |
| 부하 | CPU 낮음 | CPU·메모리 높음 |

- **EIGRP** 는 둘의 성격을 섞은 **하이브리드**(고급 디스턴스 벡터)

> 💡 **비유 — 길 물어보기 vs 지도 펴기.**
> 디스턴스 벡터는 "저기 사거리에서 물어보니 강남은 저쪽이래" (이웃 말을 믿는다).
> 링크 스테이트는 **지도를 펴고 내가 직접 최단 경로를 계산**한다.

## 📝 강의 메모

- **먼저 실패를 보여주는 것부터 시작**한다. 불편함을 겪어야 동적이 반갑다
- `n × (n-1)` 표를 칠판에 **직접 세어보게** 할 것 — 숫자로 체감시키는 게 제일 빠르다
- ⚠️ 최대 함정: **`network` 에 목적지를 적는 실수.** "정적은 **가는 길**, 동적은 **내 것 신고**" 를
  반복해서 각인시킬 것
- 메트릭 vs AD 는 **`[120/2]` 한 줄을 읽히는 것**으로 정리하면 한 번에 잡힌다
