## 3. 안전 사항

{% hint style="danger" %}
WARNING: `debug`는 실습 장비에서만 쓴다. 실제 운영 장비에서는 CPU를 많이 써서 위험하다.
{% endhint %}

{% hint style="warning" %}
CAUTION: `debug`를 켠 뒤에는 반드시 `undebug all`로 끈다. 끄지 않으면 화면이 계속 흘러 다른 작업을 할 수 없다.
{% endhint %}

## 4. 준비

| 번호 | 항목 | 확인 방법 |
|---|---|---|
| 1 | 라우터에 RIP이 동작 중이다 | `show ip protocols`에 rip이 표시된다 |

## 5. 절차

### A. 갱신 관찰

1. (5-A-01) 라우터의 `CLI` 탭에서 `enable`을 입력한다. → 결과: 프롬프트가 `#`로 바뀐다.
2. (5-A-02) `debug ip rip`을 입력한다. → 결과: 디버그가 켜진다.
3. (5-A-03) 30초 기다린다. → 결과: 갱신을 보내고 받는 내용이 화면에 표시된다.
4. (5-A-04) `undebug all`을 입력한다. → 결과: 화면 출력이 멈춘다.

## 6. 기능 확인

| 번호 | 확인 동작 | 기대 결과 | 합격 기준 |
|---|---|---|---|
| 1 | `debug ip rip` 후 30초 대기 | 갱신 내용이 표시된다 | 화면에 RIP 갱신 출력 |
| 2 | `undebug all` | 출력이 멈춘다 | 새 출력이 더 이상 나오지 않는다 |

## 7. 복구

1. (7-01) `undebug all`을 입력한다. → 결과: 모든 디버그가 꺼진다.
