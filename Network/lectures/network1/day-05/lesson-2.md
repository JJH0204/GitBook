## 학습 목표

- 디스턴스 벡터, 즉 "소문으로 라우팅"의 동작을 단계로 설명한다.
- RIP의 메트릭(홉 수)과 15홉, 30초 한계를 안다.
- RIPv1과 RIPv2의 차이를 알고 왜 `version 2`를 꼭 입력하는지 안다.
- `network` 명령이 무엇을 뜻하는지 정확히 안다.

## 이전 학습과의 연결

가장 단순한 동적 라우팅부터 시작한다. 동적 라우팅의 입문 격이 RIP(Routing Information Protocol)다. → [1. 라우팅 프로토콜 개요](lesson-1.md)(LEC-N1-05-001-DO)

RIP는 1988년에 표준이 된 오래된 프로토콜이라 실무에서는 거의 쓰지 않는다. 그래도 배우는 이유는 세 가지다.

1. 동작이 눈에 보일 만큼 단순해서 동적 라우팅의 개념을 잡기에 가장 좋다.
2. CCNA 시험에 나온다(특히 15홉, AD 120, 30초).
3. 6일차 재분배에서 "메트릭 단위가 다른 상대"로 계속 등장한다.

## 1. 구성 요소

### 1.1 RIP의 특징

| 항목 | 내용 |
|---|---|
| 방식 | 디스턴스 벡터 |
| 메트릭 | 홉 카운트(거쳐 가는 라우터 수) |
| 최대 | 15홉(16 = 무한대 = 도달 불가) |
| 갱신 주기 | 30초마다 테이블 전체를 전송 |
| 규모 | 소규모 |
| AD | 120 |
| 전송 | v1은 브로드캐스트, v2는 멀티캐스트 `224.0.0.9` |

{% hint style="danger" %}
WARNING: CCNA 3종 세트는 15홉, 30초, AD 120이다. 외운다.
{% endhint %}

**왜 15홉에서 멈추는가**

- 16을 "무한대(도달 불가)"로 약속했다. 그래야 "이 길은 죽었다"를 표현할 수 있다.
- 덕분에 루프가 영원히 도는 것을 막는다(count to infinity를 16에서 끊는다).
- 대신 16홉 이상 떨어진 네트워크는 통신할 수 없다. 큰 망에 쓸 수 없는 결정적 이유다.

### 1.2 홉만 세는 것의 함정

질문: 두 길이 있다. RIP은 어느 쪽을 고르는가.

| 경로 | 홉 수 | 실제 속도 |
|---|---|---|
| A: 1Mbps 회선 하나 | 1홉 | 느리다 |
| B: 1Gbps 회선 두 개 | 2홉 | 1000배 빠르다 |

RIP은 A를 고른다. 홉만 세므로 대역폭을 전혀 모른다. 이 장면이 OSPF가 태어난 이유다. → [3. OSPF와 EIGRP](lesson-3.md)(LEC-N1-05-003-DO)

### 1.3 RIPv1 vs RIPv2

| | RIPv1 | RIPv2 |
|---|---|---|
| 발표 | 1988 | 1994 |
| 클래스 | Classful. 서브넷 마스크를 보내지 않는다 | Classless. 마스크를 함께 보낸다 |
| VLSM | 불가 | 가능 |
| 전송 | 브로드캐스트(`255.255.255.255`) | 멀티캐스트 `224.0.0.9` |
| 인증 | 불가 | 가능 |
| 실무 | 거의 쓰지 않는다 | 이쪽을 쓴다 |

**마스크를 보내지 않으면 왜 문제인가**

- v1은 `192.168.10.0`만 보낸다. 받는 쪽은 "C클래스니까 /24겠지"라고 추측한다.
- 실제가 `/26`이었다면 틀린 경로가 만들어진다.
- 2일차에 배운 서브넷팅을 자유롭게 쓰려면 v2가 필수다. → [4. 서브넷팅](../day-02/lesson-4.md)

**`no auto-summary`**

- RIP은 기본적으로 서로 다른 주 네트워크 경계에서 경로를 클래스 단위로 뭉쳐서(요약) 보낸다.
- 예: `172.16.1.0/24`와 `172.16.2.0/24`를 `172.16.0.0/16` 한 줄로 합친다.
- 합쳐지면 어느 쪽으로 보내야 할지 구분되지 않아 통신 장애가 생긴다.

{% hint style="danger" %}
WARNING: 실습에서는 `version 2`와 `no auto-summary`를 항상 세트로 입력한다. 하나라도 빠뜨리면 원인 찾기에 20분을 잃는다.
{% endhint %}

### 1.4 RIP 타이머 4개 (이름만)

| 타이머 | 기본값 | 하는 일 |
|---|---|---|
| Update | 30초 | 이 주기로 테이블을 전송한다 |
| Invalid | 180초 | 이 시간 동안 소식이 없으면 "의심스럽다"로 표시한다 |
| Hold-down | 180초 | 그동안 나쁜 정보를 받아들이지 않는다 |
| Flush | 240초 | 이 시간이 지나면 테이블에서 삭제한다 |

- 최악의 경우 경로가 사라지는 데 3~4분이 걸린다. "RIP이 느리다"는 말의 실체다.
- 실습의 단순한 일렬 구성에서는 즉시 알림(triggered update) 덕에 훨씬 빨리 반응한다. 느림이 본격적으로 드러나는 곳은 길이 여러 갈래인 큰 망이다.

### 1.5 루프를 막는 장치들 (이름만, CCNA 단골)

| 기법 | 한 줄 설명 |
|---|---|
| 최대 홉 15 | 16을 무한대로 정해 무한 순환을 끊는다 |
| 스플릿 호라이즌 | 들은 쪽으로는 되돌려 말하지 않는다 |
| 라우트 포이즈닝 | 죽은 경로를 16홉(무한대)으로 광고해 확실히 죽인다 |
| 홀드다운 타이머 | 한동안 새 정보를 받아들이지 않아 흔들림을 막는다 |
| 트리거드 업데이트 | 30초를 기다리지 않고 변화 즉시 알린다 |

스플릿 호라이즌은 감을 잡아 둔다. "너한테 들은 얘기를 너한테 다시 해 주면, 둘이 서로를 믿으며 영원히 헛돈다."

## 2. 동작 원리

### 2.1 디스턴스 벡터 = "소문으로 라우팅(Routing by Rumor)"

각 라우터가 하는 일은 다음뿐이다.

1. 30초마다 자기 라우팅 테이블 전체를 이웃에게 통째로 보낸다.
2. 받은 라우터는 거기에 홉 1을 더해 자기 테이블에 넣는다.
3. 이웃 말을 검증하지 않는다. 전체 지도를 보지 않는다.

비유: 옆집에 길 물어보기. "강남 어떻게 가요?" → "저기 사거리에서 물어봐요, 거기서 3정거장이래요." 나는 사거리까지 1정거장 + 3 = 4정거장이라고 적는다. 직접 가 본 적은 없다. 옆집 말을 믿었을 뿐이다.

**눈으로 따라가기 — 실습 구성 그대로**

```
[R1]══════[R2]══════[R3]──192.168.30.0
    20.0/24   50.0/24
```

| 시점 | R1이 아는 30.0 | 어떻게 알았나 |
|---|---|---|
| 처음 | 모름 | - |
| 30초 뒤 | 모름 | R2도 아직 모른다 |
| R3이 알림 | (R2가 `[120/1]`로 안다) | R3 → R2로 "내 것"이라고 알린다 |
| 그다음 주기 | R1이 `[120/2]`로 안다 | R2 → R1로 "1홉이래" + 1 |

실습에서 R3이 합류하는 순간 R1에 `30.0 [120/2]`가 생기는 것을 확인한다. R2에게 1홉인 경로가 R1에게는 2홉이다. 라우터를 한 번 더 거치기 때문이다.

### 2.2 `network` 명령의 정확한 뜻

```
router rip
 network 192.168.10.0
```

이 줄의 뜻은 다음과 같다. 가장 많이 틀리는 지점이다.

| 오해 | 실제 뜻 |
|---|---|
| "192.168.10.0으로 가라" | "나는 192.168.10.0을 갖고 있다" |
| 목적지 지정 | 내 인터페이스 신고 |

정확히는 두 가지 일을 한꺼번에 한다.

1. 해당 네트워크에 속한 내 인터페이스에서 RIP을 켠다(그 포트로 소식을 주고받는다).
2. 그 네트워크를 이웃에게 광고한다("내가 갖고 있어요").

{% hint style="danger" %}
WARNING: `network` 뒤에는 반드시 내게 직접 연결된(Connected) 네트워크를 적는다. 4일차 `ip route`는 가는 길, 5일차 `network`는 내 것 신고다. 정반대다.
{% endhint %}

- RIP의 `network`는 클래스 단위로 적는다. 서브넷 마스크를 쓰지 않는다.
- OSPF는 와일드카드 마스크를 쓴다. → [3. OSPF와 EIGRP](lesson-3.md)

## 3. 확인 질문

| 질문 | 답 |
|---|---|
| 홉이 적은데 실제로 더 느린 경로를 RIP이 고르는 상황은? | 저속 1홉 vs 고속 2홉 |
| RIP에서 16홉이 뜻하는 것은? | 무한대. 도달 불가 |
| `network 192.168.10.0`은 어디로 가라는 뜻인가? | 아니다. 내가 가진 것을 신고하는 것이다 |
| `version 2`를 입력하지 않으면? | 마스크를 보내지 않아 서브넷팅한 망에서 오작동한다 |

실습으로 확인한다. `router rip` → `version 2` → `no auto-summary` → `network` 순서다. → [LEC-N1-05-007-MP](lesson-4-lab-ripv2.md). `debug ip rip`으로 30초마다 오가는 대화를 확인한다. → [LEC-N1-05-010-MP](lesson-4-lab-debug.md)

## 4. 강의 메모

- "소문으로 라우팅"이 오늘의 키워드다. 옆집에 길 물어보기 비유로 시작한다.
- 15홉, 30초, AD 120은 칠판에 크게 써 두고 수업 내내 남겨 둔다.
- 홉만 세는 함정(1Mbps 1홉 vs 1Gbps 2홉)은 표를 그려 놓고 학생이 답하게 한다. "그럼 어떻게 해야 하죠?"가 나오면 [3. OSPF와 EIGRP](lesson-3.md)로 넘어간다.
- `network` 오해는 반드시 한 번 짚고 넘어간다. 실습에서 가장 많이 막히는 지점이다.
- `debug ip rip`은 반응이 좋다. 단 `undebug all`을 함께 각인시킨다.

## 5. 약어·용어

| 용어 | 뜻 |
|---|---|
| RIP | Routing Information Protocol. 홉 수를 메트릭으로 쓰는 디스턴스 벡터 프로토콜 |
| 홉(hop) | 목적지까지 거치는 라우터 한 대 |
| Classful / Classless | 마스크를 보내지 않는 방식 / 보내는 방식 |
| VLSM | Variable Length Subnet Mask. 서브넷마다 다른 길이의 마스크를 쓰는 것 |
| 자동 요약(auto-summary) | 주 네트워크 경계에서 경로를 클래스 단위로 합치는 동작 |
| 스플릿 호라이즌 | 경로를 들은 인터페이스로 되돌려 광고하지 않는 규칙 |
| 라우트 포이즈닝 | 죽은 경로를 무한대 메트릭으로 광고하는 것 |
| triggered update | 변화가 생기면 주기를 기다리지 않고 즉시 보내는 갱신 |
