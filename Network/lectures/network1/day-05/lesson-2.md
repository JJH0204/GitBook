## 🎯 학습 목표

- 디스턴스 벡터 = **"소문으로 라우팅"** 의 동작을 단계로 설명한다
- RIP 의 메트릭(홉 수)과 **15홉 · 30초** 한계를 안다
- RIPv1 과 RIPv2 의 차이를 알고, **왜 `version 2` 를 꼭 치는지** 안다
- `network` 명령이 **무엇을 뜻하는지** 정확히 안다

## 🌉 다리 놓기: "가장 단순한 동적 라우팅부터"

동적 라우팅([1_라우팅프로토콜_개요](lesson-1.md))의 입문격이 **RIP(Routing Information Protocol)** 이다.
1988년에 표준이 된 아주 오래된 프로토콜이라 **실무에선 거의 안 쓴다.**

> ❓ 그럼 왜 배울까?
> ① 동작이 **눈에 보일 만큼 단순**해서 "동적 라우팅이란 게 이런 거구나"를 잡기에 최고
> ② **CCNA 시험에 나온다** (특히 15홉 · AD 120 · 30초)
> ③ **6일차 재분배**에서 "메트릭 단위가 다른 상대"로 계속 등장한다

## 📖 디스턴스 벡터 = "소문으로 라우팅(Routing by Rumor)"

각 라우터가 하는 일은 딱 이것뿐이다.

1. **30초마다** 자기 라우팅 테이블 **전체**를 이웃에게 통째로 보낸다
2. 받은 라우터는 거기에 **홉 1을 더해** 자기 테이블에 넣는다
3. 이웃 말을 **검증하지 않는다.** 전체 지도를 보지 않는다

> 💡 **비유 — 옆집에 길 물어보기.**
> "강남 어떻게 가요?" → "저기 사거리에서 물어봐요, 거기서 3정거장이래요."
> 나는 **사거리까지 1정거장 + 3 = 4정거장** 이라고 적는다.
> **직접 가본 적은 없다. 옆집 말을 믿었을 뿐이다.**

### 눈으로 따라가기 — 오늘 실습 구성 그대로

```
[R1]══════[R2]══════[R3]──192.168.30.0
    20.0/24   50.0/24
```

| 시점 | R1 이 아는 30.0 | 어떻게 알았나 |
|------|-----------------|---------------|
| 처음 | 모름 | — |
| 30초 뒤 | — | R2 도 아직 모름 |
| R3 이 알림 | R2 가 `[120/1]` | R3 → R2 로 "내 것" 이라고 |
| 그 다음 주기 | R1 이 **`[120/2]`** | R2 → R1 로 "1홉이래" + 1 |

> 🧪 실습에서 R3 이 합류하는 순간, R1 에 `30.0 [120/2]` 가 생기는 것을 확인한다.
> R2 에게는 1홉인 경로가 R1 에게는 **2홉**이다 — 라우터를 한 번 더 거치니까.

## 📖 RIP 의 특징 — 표 하나로

| 항목 | 내용 |
|------|------|
| 방식 | 디스턴스 벡터 |
| 메트릭 | **홉 카운트** (거쳐 가는 라우터 수) |
| 최대 | **15홉** (16 = 무한대 = 도달 불가) |
| 갱신 주기 | **30초**마다 테이블 전체를 뿌림 |
| 규모 | **소규모** |
| **AD** | **120** |
| 전송 | v1 브로드캐스트 / **v2 멀티캐스트 224.0.0.9** |

> 🚨 **CCNA 3종 세트: 15홉 · 30초 · AD 120.** 이건 외운다.

### 왜 15홉에서 멈출까

- 16 을 **"무한대(도달 불가)"** 로 약속했다 → 그래야 "이 길은 죽었다"를 표현할 수 있다
- 덕분에 **루프가 영원히 도는 것을 막는다**(count to infinity 를 16에서 끊는다)
- 대신 **16홉 이상 떨어진 네트워크는 아예 통신 불가** → 큰 망에 못 쓰는 결정적 이유

### 홉만 세는 것의 함정 ⭐

> ❓ 두 길이 있다. RIP 은 어느 쪽을 고를까?

| 경로 | 홉 수 | 실제 속도 |
|------|-------|-----------|
| A: 1Mbps 회선 하나 | **1홉** | 느리다 🐢 |
| B: 1Gbps 회선 두 개 | 2홉 | **1000배 빠르다** 🚀 |

**RIP 은 A 를 고른다.** 홉만 세기 때문에 **대역폭을 전혀 모른다.**

> 💡 이 한 장면이 **OSPF 가 태어난 이유**다. → [3_OSPF와_EIGRP](lesson-3.md)

## 📖 RIPv1 vs RIPv2 — 실습에서 `version 2` 를 꼭 치는 이유

| | RIPv1 | RIPv2 |
|---|-------|-------|
| 발표 | 1988 | 1994 |
| 클래스 | **Classful** — 서브넷 마스크를 **안 보냄** | **Classless** — **마스크를 함께 보냄** |
| VLSM | ❌ | ✅ |
| 전송 | 브로드캐스트 (255.255.255.255) | 멀티캐스트 **224.0.0.9** |
| 인증 | ❌ | ✅ |
| 실무 | 거의 안 씀 | 이걸 사용 |

**마스크를 안 보낸다는 게 왜 문제인가?**

- v1 은 `192.168.10.0` 만 보낸다 → 받는 쪽은 **"C클래스니까 /24겠지"** 라고 **추측**한다
- 그런데 실제가 `/26` 이었다면? → **틀린 경로가 만들어진다**
- 2일차에 배운 **서브넷팅을 자유롭게 쓰려면 v2 가 필수** → [4_서브넷팅](../day-02/lesson-4.md)

### `no auto-summary` 는 또 뭔가

- RIP 은 기본적으로 서로 다른 **주 네트워크 경계**에서 경로를 **클래스 단위로 뭉쳐서**(요약) 보낸다
- 예: `172.16.1.0/24` · `172.16.2.0/24` 를 **`172.16.0.0/16` 한 줄로** 뭉개버린다
- 뭉개지면 **어느 쪽으로 보내야 할지 구분이 안 된다** → 통신 장애

> 🚨 **실습에서는 `version 2` 와 `no auto-summary` 를 항상 세트로 친다.**
> 둘 중 하나라도 빠뜨리면 "왜 안 되지?" 로 20분을 잃는다.

## 📖 `network` 명령을 정확히 이해하기 ⭐ (가장 많이 틀린다)

```bash
router rip
 network 192.168.10.0
```

> ❓ 이 줄은 무슨 뜻일까?

| 오해 ❌ | 진짜 뜻 ✅ |
|---------|-----------|
| "192.168.10.0 으로 가라" | **"나는 192.168.10.0 을 갖고 있다"** |
| 목적지 지정 | **내 인터페이스 신고** |

정확히는 **두 가지 일**을 한꺼번에 한다.

1. **해당 네트워크에 속한 내 인터페이스로 RIP 을 켠다** (그 포트로 소식을 주고받는다)
2. **그 네트워크를 이웃에게 광고한다** ("내가 갖고 있어요")

> 🚨 그래서 `network` 뒤에는 **반드시 내게 직접 연결된(Connected) 네트워크**를 적는다.
> 4일차 `ip route` 는 **가는 길**, 5일차 `network` 는 **내 것 신고** — **정반대다.**

- RIP 의 `network` 는 **클래스 단위**로 적는다 → 서브넷 마스크를 쓰지 않는다
  (OSPF 는 와일드카드 마스크를 쓴다 → [3_OSPF와_EIGRP](lesson-3.md))

## 📖 RIP 의 타이머 4개 (참고 — 이름만)

| 타이머 | 기본값 | 하는 일 |
|--------|--------|---------|
| Update | **30초** | 이 주기로 테이블을 뿌린다 |
| Invalid | 180초 | 이 시간 소식이 없으면 "의심스럽다" 표시 |
| Hold-down | 180초 | 그동안 나쁜 정보를 받아들이지 않는다 |
| Flush | 240초 | 이 시간이 지나면 테이블에서 삭제 |

- 최악의 경우 **경로가 사라지는 데 3~4분** 걸린다 → **RIP 이 느리다**는 말의 실체
- 실습의 단순한 일렬 구성에서는 **즉시 알림(triggered update)** 덕에 훨씬 빨리 반응한다.
  느림이 본격적으로 드러나는 건 **길이 여러 갈래인 큰 망**이다

## 📖 루프를 막는 장치들 (이름만, CCNA 단골)

| 기법 | 한 줄 설명 |
|------|-----------|
| **최대 홉 15** | 16을 무한대로 정해 무한 순환을 끊는다 |
| **스플릿 호라이즌** | **들은 쪽으로는 되돌려 말하지 않는다** |
| **라우트 포이즈닝** | 죽은 경로를 **16홉(무한대)** 이라고 광고해 확실히 죽인다 |
| **홀드다운 타이머** | 한동안 새 정보를 안 받아들여 흔들림을 막는다 |
| **트리거드 업데이트** | 30초를 안 기다리고 **변화 즉시** 알린다 |

> 💡 **스플릿 호라이즌**만은 감을 잡아두자.
> "너한테 들은 얘기를 너한테 다시 해주면, 우리 둘이 서로를 믿으며 영원히 헛돈다."

## 🧪 질문 / 실습

- 🗣 "홉이 적은데 실제로 더 느린 경로를 RIP 이 고르는 상황은?" → 저속 1홉 vs 고속 2홉
- 🗣 "RIP 에서 16홉이 뜻하는 것은?" → **무한대 = 도달 불가**
- 🗣 "`network 192.168.10.0` 은 어디로 가라는 뜻인가요?" → **아니다. 내가 가진 것 신고**
- 🗣 "`version 2` 를 안 치면?" → 마스크를 안 보내 서브넷팅한 망에서 오작동
- 🧪 `router rip` → `version 2` → `no auto-summary` → `network` → [RIPv2 실습](commands.md)
- 🧪 `debug ip rip` 으로 **30초마다 오가는 대화를 직접 엿듣기** → [부록 B](commands.md)

## 📝 강의 메모

- "소문으로 라우팅" 이 오늘의 키워드. **옆집에 길 물어보기** 비유로 시작
- **15홉 · 30초 · AD 120** 은 칠판에 크게 써두고 수업 내내 남겨둘 것
- 홉만 세는 함정(1Mbps 1홉 vs 1Gbps 2홉)은 **표를 그려놓고 학생이 답하게** 할 것
  → 여기서 "그럼 어떻게 해야 하죠?" 가 나오면 [3_OSPF와_EIGRP](lesson-3.md) 로 자연스럽게 넘어간다
- ⚠️ `network` 오해는 **반드시 한 번 짚고 넘어간다.** 실습에서 제일 많이 막히는 지점
- `debug ip rip` 은 반응이 아주 좋다 — 단, **`undebug all` 을 함께 각인**시킬 것
