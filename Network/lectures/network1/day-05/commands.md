# 0. 5일차 실습 명령어 — 수업 흐름 그대로 (이어치기 대본)

> 상위: [5일차 · 라우팅 프로토콜](README.md) · 이론 설명은 [4_라우팅_실습](lesson-4.md)
> **위에서 아래로 그대로 따라 치면 오늘 실습이 끝난다.** 실습 중 화면에 띄워두거나 인쇄해 나눠줄 것.

## 📌 읽는 법 — 이 노트의 약속

- 블록 하나 = **한 장비에서 끊지 않고 이어 치는 한 덩어리**
- 블록 머리의 `🖥 PC0` / `🔁 R1` = **어느 장비의 어느 창**인지
- 블록 끝의 `👉` = **다음에 어디로 가는지**
- `# 뒤 회색 글씨` = 설명. 안 쳐도 된다
- 4일차 CLI 기본기는 → [4일차 실습 명령어 대본](../day-04/commands.md)

## 🧰 오늘은 실습이 둘, **각각 새 파일에 처음부터 만든다**

| | 실습 | 무엇을 보나 |
|---|------|------------|
| 1 | **RIPv2 실습** | 아무도 길을 안 알려줬는데 경로가 생긴다 |
| 2 | **OSPF 실습** | 같은 망을 더 빠르고 똑똑하게 |

> 📌 **두 실습의 그림과 주소는 완전히 같다.** 두 번째는 손이 익어 훨씬 빨리 만든다.
> 이전 파일을 고쳐 쓰지 않고 **매번 새로 만드는 것**이 오늘의 방식이다 — 설정이 섞이지 않고,
> 처음부터 만드는 과정 자체가 연습이 된다.

## ⏳ 오늘만의 새 규칙 — **기다리는 실습이다**

> ⚠️ **명령을 치자마자 경로가 생기지 않는다.** RIP 은 **30초마다** 정보를 주고받는다.
> 아무 일도 안 일어나 보여도 **30초는 기다렸다가** `show ip route` 를 다시 친다.
> 학생들이 가장 많이 하는 실수가 **"안 되네?" 하고 설정을 지우는 것**이다.

| 기다리는 시간 | 무엇 |
|---|---|
| **최대 30초** | RIP 경로가 새로 생기거나 사라질 때 |
| **몇 초** | OSPF 이웃이 맺어지고 경로가 생길 때 |

- `↑` 키로 `show ip route` 를 다시 부르면 편하다 (다시 타이핑하지 말 것)

## 🗺 두 실습에서 공통으로 만들 그림

```
[PC0]──[SW1]──[R1]══════[R2]══════[R3]──[SW2]──[PC2]
 .10.1         20.0/24       50.0/24        .30.1
 192.168.10.0/24                        192.168.30.0/24
```

| 장비 | G0/0 | G0/1 |
|------|------|------|
| **R1** | 192.168.10.254 (PC0 쪽) | 192.168.20.1 |
| **R2** | 192.168.50.1 | 192.168.20.2 |
| **R3** | 192.168.30.254 (PC2 쪽) | 192.168.50.2 |

- **PC0** IP `192.168.10.1` / 마스크 `255.255.255.0` / 게이트웨이 `192.168.10.254`
- **PC2** IP `192.168.30.1` / 마스크 `255.255.255.0` / 게이트웨이 `192.168.30.254`
- 케이블 — 라우터끼리는 **크로스오버**, 라우터↔스위치·PC↔스위치는 **다이렉트**

# ▶ 준비 · 그림 만들기 (두 실습 공통)

> 실습을 시작할 때마다 **새 파일**에서 이 과정을 먼저 한다. 두 번째는 훨씬 빠르다.

### 0-1 🖱 마우스로 (명령 아님)

1. 라우터 **3대** · 스위치 **2대** · PC **2대** 를 꺼내 위 그림처럼 배치
2. 케이블을 연결하고 **링크 점이 초록이 될 때까지** 기다린다
3. `PC0` → `Desktop` → `IP Configuration` 에 IP · 마스크 · **게이트웨이**를 넣는다
4. `PC2` 도 같은 방법으로

> 👉 배선과 PC 주소가 끝났으면, 이제부터 **끝까지 CLI 다.**

### 0-2 🔁 R1 CLI — 인터페이스 두 개 켜기

```bash
enable
configure terminal
no ip domain-lookup
hostname R1
interface g0/0
 ip address 192.168.10.254 255.255.255.0
 no shutdown
 exit
interface g0/1

 no shutdown
end
show ip interface brief         # 두 인터페이스가 up/up 인가
```

> ⚠️ `no shutdown` 을 빠뜨리면 `C` 경로가 안 생긴다. 3일차 `Port Status = On` 과 같은 뜻.
> 👉 다음: R2 로

### 0-3 🔁 R2 CLI

```bash
enable
configure terminal
no ip domain-lookup
hostname R2
interface g0/1
 ip address 192.168.20.2 255.255.255.0
 no shutdown
 exit
interface g0/0
 ip address 192.168.50.1 255.255.255.0
 no shutdown
end
show ip interface brief
```

> 👉 다음: R3 으로

### 0-4 🔁 R3 CLI

```bash
enable
configure terminal
no ip domain-lookup
hostname R3
interface g0/1
 ip address 192.168.50.2 255.255.255.0
 no shutdown
 exit
interface g0/0
 ip address 192.168.30.254 255.255.255.0
 no shutdown
end
show ip interface brief

```

**✅ 준비 체크** — 세 라우터 모두 `up/up` 2개 · 각자 `C` 경로 2개

# ▶ 실습 1 · RIPv2 — 라우터끼리 알아서 채우게 하기 ⭐

> 위 준비를 마친 **새 파일**에서 이어간다.

## STEP 1 · 먼저 실패를 확인한다 (5분)

### 1-1 🖥 PC0 (Desktop → Command Prompt)

```bash
ping 192.168.10.254             # ① 내 게이트웨이까지 — 성공해야 정상
ping 192.168.30.1               # ② 그 너머 PC2 — 실패한다. 메시지를 읽을 것
```

> 🗣 "왜 실패했나?" → **경로가 없다.** 라우터들은 자기에게 붙은 것만 안다
> 🗣 "4일차처럼 `ip route` 를 손으로 넣으면 되겠죠? 그런데 라우터가 100대면?" ← **오늘 수업의 이유**
> 👉 다음: R1 CLI 로

## STEP 2 · R1 · R2 에만 RIP 을 켠다 (20분)

> 이번엔 **"어디로 가라"** 가 아니라 **"내가 가진 네트워크는 이것들이다"** 만 알려준다.
> 길은 라우터끼리 알아서 주고받는다.

### 2-1 🔁 R1 CLI

```bash
configure terminal
router rip
 version 2                  # 반드시. 안 하면 서브넷 마스크를 안 보낸다
 no auto-summary            # 반드시. 클래스 단위로 뭉개지 않게
 network 192.168.10.0       # ★ 내게 직접 연결된 네트워크 (목적지가 아니다!)
 network 192.168.20.0
end
show ip protocols           # rip 이 돌고 있나 · 어떤 network 를 알렸나
```

> ⚠️ `network` 뒤에는 **내가 가진 네트워크**를 적는다. 4일차 `ip route` 와 정반대다.
> 👉 다음: R2 CLI 로 (한쪽만 켜면 아무 일도 안 일어난다)

### 2-2 🔁 R2 CLI

```bash
configure terminal
router rip
 version 2
 no auto-summary
 network 192.168.20.0
 network 192.168.50.0
end
show ip route               # ⏳ 30초 기다렸다가 · R 192.168.10.0 이 보이는가
```

> ⏳ **바로 안 보이면 30초 뒤에 `show ip route` 를 한 번 더.** (`↑` 키)
> 👉 다음: R1 로 돌아가 반대 방향도 확인

### 2-3 🔁 R1 CLI — 자동으로 생긴 경로 읽기

```bash
show ip route               # R 192.168.50.0 [120/1] via 192.168.20.2
show ip route rip           # RIP 로 배운 것만 골라 보기
```

**🔎 이 줄을 같이 읽는다**

```
R    192.168.50.0/24 [120/1] via 192.168.20.2, 00:00:12, GigabitEthernet0/1
─┬─                   ─┬─ ─┬─      ─────┬─────  ────┬───
 RIP 이 알려줌          AD  홉수       다음 홉      12초 전에 들었다
```

> 🗣 **"R1 은 50.0 을 어떻게 알았나?"** → R2 가 알려줬다. 아무도 `ip route` 를 안 쳤다
> ⚠️ 아직 **30.0 은 모른다.** R3 이 아직 아무 말도 안 하고 있으니까
> 👉 다음: R3 으로 — 여기가 오늘의 핵심 장면

## STEP 3 · R3 에 RIP 을 켠다 ⭐⭐ 오늘의 하이라이트 (25분)

### 3-1 🔁 R3 CLI

```bash
configure terminal
router rip
 version 2
 no auto-summary
 network 192.168.30.0
 network 192.168.50.0
end
show ip route               # ⏳ 30초 · R 192.168.10.0 · R 192.168.20.0 이 보이는가
```

> 👉 **R1 으로 간다. R1 에는 아무것도 치지 않는다 — 보기만 한다.**

### 3-2 🔁 R1 CLI — 손 안 댔는데 경로가 늘었다 ⭐

```bash
show ip route               # ⏳ 30~60초 · 30.0 이 새로 생겼는가
```

```
R    192.168.50.0/24 [120/1] via 192.168.20.2   ← 아까 있던 것
R    192.168.30.0/24 [120/2] via 192.168.20.2   ← 새로 생겼다. 홉이 2다
```

> 🗣 **"R3 을 설정하는 동안 R1 에 뭘 쳤나요?" → 아무것도 안 쳤다.**
> 🗣 **"30.0 의 홉은 왜 2일까요?"** → 라우터를 두 번 거치니까
> 🗣 "정적이었다면 R1·R2·R3 세 대를 다 고쳐야 했다." ← **오늘 배운 것의 값어치**
> 👉 다음: PC0 에서 최종 확인

### 3-3 🖥 PC0 — 이번엔 성공

```bash
ping 192.168.30.1
tracert 192.168.30.1        # 라우터 3대를 거쳐 가는 게 보인다
```

**💾 저장** — 세 라우터 모두 `copy running-config startup-config` · 패킷트레이서 파일은 `Ctrl + S`

**✅ 체크**

- [ ] R1 테이블에 `R` 경로 2개 (30.0 은 `[120/2]`)
- [ ] R3 테이블에 `R` 경로 2개
- [ ] PC0 → PC2 ping 성공 · `tracert` 에 거치는 라우터가 3대

## STEP 4 · 끊어보고, 다시 이어보기 (10분)

> 정적이었다면 **사람이 지우고 사람이 다시 넣어야** 했다. 동적은?

# ▶ 실습 2 · OSPF — 지도를 보고 계산하게 하기 ⭐ (35분)

> **새 파일**을 만들어 앞의 **`▶ 준비 · 그림 만들기`** 를 그대로 다시 한다.
> 그림도 주소도 실습 1과 **완전히 같다.** 두 번째라 훨씬 빠르다 — 이것도 연습이다.

## STEP 1 · 준비가 끝났는지 확인

```bash
show ip interface brief     # 세 라우터 모두 up/up 2개
show ip route               # C 2개 · L 2개뿐
```

> 🖥 PC0 `ping 192.168.30.1` → **실패**(아직 경로가 없다). 여기서 출발한다.
> 👉 다음: R1 CLI 로

## STEP 2 · 세 라우터에 OSPF 를 켠다

### 2-1 🔁 R1 CLI

```bash
configure terminal
router ospf 1                                   # 1 = 프로세스 번호(이 장비 안에서만 의미)
 network 192.168.10.0 0.0.0.255 area 0          # ⚠️ 0.0.0.255 는 와일드카드 마스크
 network 192.168.20.0 0.0.0.255 area 0
end
```

> ⚠️ **서브넷 마스크(255.255.255.0)를 쓰면 안 된다.** 계산법은 부록 D.
> 👉 R2 로 (혼자 켜면 이웃이 없다)

### 2-2 🔁 R2 CLI

```bash
configure terminal
router ospf 1
 network 192.168.20.0 0.0.0.255 area 0
 network 192.168.50.0 0.0.0.255 area 0
end
```

> 이 순간 화면에 **`ADJACENCY ESTABLISHED`** 같은 메시지가 뜬다 → 이웃이 맺어진 것
> 👉 R3 으로

### 2-3 🔁 R3 CLI

```bash
configure terminal
router ospf 1
 network 192.168.30.0 0.0.0.255 area 0
 network 192.168.50.0 0.0.0.255 area 0
end
show ip ospf neighbor       # 이웃이 FULL 상태인가
```

> 👉 R1 으로 돌아가 확인

## STEP 3 · 결과 읽기

### 3-1 🔁 R1 CLI

```bash
show ip route               # 몇 초 만에 O 경로가 생긴다
show ip ospf neighbor       # 이웃 1개가 FULL
show ip protocols           # ospf 가 돌고 있다
```

```
O    192.168.30.0/24 [110/3] via 192.168.20.2
─┬─                   ─┬─ ─┬─
 OSPF 가 알려줌         AD  코스트 — 홉 수가 아니다!
```

> 🗣 **"RIP 은 30초를 기다렸는데 OSPF 는 왜 금방 됐죠?"**
> → RIP 은 주기적으로 보내고, **OSPF 는 변화가 있을 때 바로** 보낸다
> 🗣 **"뒤 숫자 3 은 홉 수인가요?"** → 아니다. **코스트**(대역폭 기반)다

### 3-2 🖥 PC0 — 최종 확인

```bash
ping 192.168.30.1
tracert 192.168.30.1
```

**💾 저장** — 세 라우터 `copy run start` · 파일은 `Ctrl + S`

**✅ 최종 체크**

- [ ] 세 라우터 모두 `show ip route` 에 `O` 경로가 보인다
- [ ] `show ip ospf neighbor` 에 이웃이 `FULL`
- [ ] PC0 → PC2 ping 성공

# 📚 부록 A · 누가 이기나 — AD 대결 (여유 있으면, 아주 인상적)

> 실습 2 파일에서 **OSPF 를 지우지 않고** RIP 을 같이 켠다.
> 같은 목적지를 둘이 동시에 알려주는 상황 — **AD(신뢰도) 싸움**을 눈으로 본다.

**세 라우터 모두에서** (각자 자기 네트워크를 적는다)

```bash
configure terminal
router rip
 version 2
 no auto-summary
 network 192.168.10.0        # ← R1 의 예. R2 는 20.0/50.0, R3 은 50.0/30.0
 network 192.168.20.0
end
show ip route                # ⏳ 30초
show ip protocols            # rip 과 ospf 가 둘 다 돌고 있다
```

> 🗣 **"RIP 을 켰는데 왜 테이블에는 `O` 만 있죠?"**
> → **AD 가 낮은 쪽만 테이블에 오른다.** OSPF 110 < RIP 120
> → [1_라우팅프로토콜_개요](lesson-1.md) · 4일차 CCNA Q4 회수

**되돌리기** — 세 라우터에서 `configure terminal` → `no router rip` → `end`

# 📚 부록 B · RIP 이 주고받는 말을 엿듣기

```bash
enable
debug ip rip                # 30초마다 오가는 대화가 화면에 그대로 뜬다
                            # ⏳ 30초 기다린다
undebug all                 # 🚨 반드시 끈다! 안 끄면 화면이 계속 흐른다
```

> 🚨 **`undebug all` 을 꼭 칠 것.** 화면이 계속 흘러 아무것도 못 하게 된다.
> `debug` 는 **실습 장비에서만.** 실제 운영 장비에서는 CPU 를 잡아먹어 위험하다.

# 📚 부록 C · 명령 사전 (오늘 새로 나온 것)

| 무엇 | 명령 | 어느 모드 |
|------|------|-----------|
| RIP 시작 | `router rip` | `(config)#` |
| RIP 버전 2 | `version 2` | `(config-router)#` |
| 자동 요약 끄기 | `no auto-summary` | `(config-router)#` |
| 내 네트워크 알리기 | `network 192.168.10.0` | `(config-router)#` |
| OSPF 시작 | `router ospf 1` | `(config)#` |
| OSPF 네트워크 | `network 192.168.10.0 0.0.0.255 area 0` | `(config-router)#` |
| 프로토콜 끄기 | `no router rip` / `no router ospf 1` | `(config)#` |
| 학습된 경로만 보기 | `show ip route rip` / `show ip route ospf` | `#` |
| 어떤 프로토콜이 도나 | `show ip protocols` | `#` |

# 🧮 부록 D · 와일드카드 마스크 30초 계산법

> OSPF 의 `network` 뒤에 오는 건 **서브넷 마스크가 아니라 와일드카드 마스크**다.

**`255` 에서 각 자리를 빼면 된다** (255 − 서브넷 마스크)

| 서브넷 마스크 | 와일드카드 |
|---|---|
| 255.255.255.0 (/24) | **0.0.0.255** |
| 255.255.0.0 (/16) | **0.0.255.255** |
| 255.255.255.252 (/30) | **0.0.0.3** |
| 255.255.255.255 (딱 한 대) | **0.0.0.0** |

- `0` 인 자리 = **반드시 같아야 하는 자리**, `255` 인 자리 = **아무거나 괜찮은 자리**
- 2일차 서브넷 마스크의 응용 → [4_서브넷팅](../day-02/lesson-4.md)
