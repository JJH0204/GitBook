## 학습 목표

- 스위치 두 대에 같은 VLAN이 걸쳐 있을 때 트렁크가 왜 필요한지 안다.
- 802.1Q 태그가 하는 일을 이해한다.
- 네이티브 VLAN이 무엇인지 안다.
- VLAN끼리 통신하려면 라우터가 필요한 이유를 설명한다.
- Router-on-a-stick(서브인터페이스) 구성을 이해하고, L3 스위치 방식이 있다는 것을 안다.

## 이전 학습과의 연결

[1_VLAN](lesson-1.md)에서 스위치 한 대를 영업(10)·개발(20)으로 나눴다. 회사가 커져서 3층에 스위치를 한 대 더 놓았다. 3층에도 영업팀·개발팀이 있다.

```
 2층  [SW1]  영업10 · 개발20
        │
        │  ← 이 선 한 줄로 두 부서를 다 이어야 한다
        │
 3층  [SW2]  영업10 · 개발20
```

질문이 두 개 생긴다.

1. 스위치 사이의 선 한 줄로 VLAN 10과 20을 둘 다 나를 수 있을까? → 트렁크
2. 영업팀이 개발팀에게 파일을 보내려면? (VLAN이 다르면 벽이 있다) → VLAN 간 라우팅

## 1. 구성 요소

### 1-1. 트렁크 — 여러 VLAN을 한 선으로

#### 액세스로 이으면 안 되는 이유

스위치 사이 포트를 그냥 두면 VLAN 1 액세스 포트로 동작한다. VLAN 10 프레임은 VLAN 10 포트로만 나갈 수 있다. 그래서 VLAN 1 포트인 연결선을 건너가지 못한다.

질문: 2층 영업 PC0 → 3층 영업 PC2는 같은 VLAN 10인데 ping이 안 된다. 왜인가? 스위치 사이 선이 VLAN 1 전용 통로여서 VLAN 10이 지나갈 수 없기 때문이다.

부서마다 선을 하나씩 깔면(VLAN 10용, 20용 …) 되기는 한다. 하지만 VLAN이 50개면 선이 50줄이 필요하다.

#### 트렁크 = 여러 VLAN이 같이 타는 선

```
 [SW1] ══════════ 트렁크 ══════════ [SW2]
        [10|데이터]  [20|데이터]  [10|데이터]
         ──┬──
           꼬리표(태그)를 붙여서 보낸다 → 받는 쪽이 태그를 보고 해당 VLAN으로
```

- 보내는 스위치가 프레임에 "나는 VLAN 10" 꼬리표(태그)를 붙인다.
- 받는 스위치가 태그를 보고 그 VLAN 포트로 보내고, 태그를 떼어 PC에 준다.
- 이 태그 규격이 IEEE 802.1Q(닷원큐)다. 지금은 사실상 이것 하나다. 옛 시스코 전용 ISL이라는 것도 있었다(이름만 안다).

{% hint style="info" %}
NOTE: 비유는 택배 트럭이다. 트럭(트렁크) 하나에 여러 집 택배(VLAN)를 싣는다. 상자마다 송장(태그)이 붙어 있어서, 도착지 물류센터가 송장을 보고 제 집으로 나눠 보낸다. PC(받는 사람)는 송장을 볼 일이 없다. 액세스 포트에서 떼어 내고 준다.
{% endhint %}

| | 액세스 포트 | 트렁크 포트 |
|---|---|---|
| 태그 | 없음 (PC는 태그를 모른다) | 있음 (802.1Q) |
| VLAN 수 | 하나 | 여러 개 |
| 연결 대상 | PC · 서버 | 스위치 · 라우터 · (AP) |

```bash
interface fa0/23
 switchport mode trunk             # 이 포트는 트렁크다 (양쪽 스위치 모두)
end
show interfaces trunk              # 트렁크 상태 확인
```

{% hint style="warning" %}
CAUTION: L3 스위치(3560 등)는 태그 규격을 먼저 정해야 한다. `switchport trunk encapsulation dot1q`를 입력한 뒤 `switchport mode trunk`를 입력한다. 오늘 쓰는 2960은 802.1Q만 지원해서 이 줄이 필요 없다(입력하면 에러가 난다).
{% endhint %}

#### `show interfaces trunk` 읽기

```
Port        Mode         Encapsulation  Status        Native vlan
Fa0/23      on           802.1q         trunking      1

Port        Vlans allowed on trunk
Fa0/23      1-1005

Port        Vlans allowed and active in management domain
Fa0/23      1,10,20
```

| 칸 | 뜻 |
|---|---|
| Status `trunking` | 트렁크가 맺어졌다 |
| Native vlan 1 | 태그 없이 다니는 VLAN (아래) |
| allowed 1-1005 | 이 트렁크에 태울 수 있는 VLAN. 기본은 전부 |
| active 1,10,20 | 실제로 존재해서 다니는 VLAN |

{% hint style="info" %}
NOTE: 트렁크 포트는 `show vlan brief`에서 사라진다. 특정 VLAN 소속이 아니라 모든 VLAN의 통로이기 때문이다. "Fa0/23이 어디 갔나?"는 고장이 아니다. `show interfaces trunk`로 본다.
{% endhint %}

#### 네이티브 VLAN — 태그 없는 손님

- 트렁크 위에서 태그 없이 다니는 VLAN이 딱 하나 있다. 이것이 네이티브 VLAN이다(기본 VLAN 1).
- 양쪽 스위치가 같아야 한다. 다르면 `%CDP-4-NATIVE_VLAN_MISMATCH` 경고가 뜨고 프레임이 엉뚱한 VLAN으로 샌다.
- 실무에서는 보안상 안 쓰는 번호(예: 99)로 바꾸는 것이 관례다. → `switchport trunk native vlan 99` (양쪽 모두)
- 오늘은 기본값(1) 그대로 둔다. "태그 없는 손님이 하나 있고 양쪽이 같아야 한다"까지만 안다.

#### 트렁크 협상 (DTP)

- 시스코 스위치끼리는 트렁크를 알아서 맺자고 협상하는 기능(DTP)이 있다.
- 2960의 기본값은 `dynamic auto`다. 양쪽 다 auto면 트렁크가 되지 않는다(둘 다 상대가 먼저 말하기를 기다린다).
- 그래서 양쪽 모두 `switchport mode trunk`로 못 박는다. 오늘의 원칙이다.

### 1-2. VLAN 간 라우팅 — 벽 너머로 가려면

트렁크로 같은 VLAN끼리는 층을 넘어 통신한다. VLAN 10 → VLAN 20은 다르다.

- VLAN이 다르다 = 브로드캐스트 도메인이 다르다 = 네트워크가 다르다.
- 다른 네트워크로 가려면 라우터가 필요하다. 4일차: "라우터는 네트워크와 네트워크를 잇는다". → [2_라우터_동작원리](../day-04/lesson-2.md)
- PC 입장에서도 같다. 목적지가 다른 네트워크면 게이트웨이에게 보낸다(3일차).

#### 방법 1 — VLAN마다 라우터 포트 하나씩

```
        [R1]
       G0/0  G0/1         ← 포트 2개 = VLAN 2개
        │     │
        │10   │20         (각각 액세스 포트)
       [   SW1   ]
```

- 동작은 한다. 그러나 VLAN이 20개면 라우터 포트도 20개가 필요하다. 비싸고 선이 엉킨다.

#### 방법 2 — Router-on-a-stick (오늘 실습)

라우터 포트 하나를 트렁크로 잇고, 그 안을 VLAN 수만큼 쪼갠다.

```
        [R1]
         │ G0/0            물리 포트는 하나
         │  ├ G0/0.10  → 192.168.10.254  (VLAN 10의 게이트웨이)
         │  └ G0/0.20  → 192.168.20.254  (VLAN 20의 게이트웨이)
         │ trunk (태그 10 · 20이 같이 다닌다)
       [ SW1 ]
```

- 서브인터페이스는 물리 포트 하나 안에 만든 가상 포트다(`g0/0.10`). 점 뒤 숫자는 관례상 VLAN 번호다.
- `encapsulation dot1Q 10`은 "태그 10이 붙은 프레임은 내 담당"이라는 뜻이다.
- 막대기(stick) 하나에 라우터가 매달린 모양이어서 Router-on-a-stick이라 부른다.

```bash
interface g0/0
 no shutdown                          # 물리 포트는 켜기만 (IP 없음)
interface g0/0.10
 encapsulation dot1Q 10               # 1) 태그 번호 먼저
 ip address 192.168.10.254 255.255.255.0   # 2) 그다음 IP
interface g0/0.20
 encapsulation dot1Q 20
 ip address 192.168.20.254 255.255.255.0
```

{% hint style="warning" %}
CAUTION: 순서가 중요하다. `encapsulation`을 빼먹고 IP부터 입력하면 거부된다: `% Configuring IP routing on a LAN subinterface is only allowed if that subinterface is already configured as part of an IEEE 802.10, IEEE 802.1Q, or ISL vLAN.` 구호는 "태그 먼저, 주소 나중"이다.
{% endhint %}

{% hint style="warning" %}
CAUTION: 라우터와 연결된 스위치 포트도 트렁크여야 한다. 액세스로 두면 태그가 붙지 않아 라우터가 어느 VLAN의 프레임인지 알지 못한다.
{% endhint %}

PC0(VLAN 10) → PC1(VLAN 20) 패킷의 여행은 다음과 같다.

```
PC0 ──(태그 없음)──▶ SW1 ──(태그 10)──▶ R1 g0/0.10
                                          │ 라우팅: 20.0은 g0/0.20 쪽
PC1 ◀──(태그 없음)── SW1 ◀──(태그 20)──── R1 g0/0.20
```

질문: 같은 선을 올라갔다가 내려온다. 그래도 되는가? 된다. 태그가 달라서 다른 길로 취급된다. 대신 모든 부서 간 트래픽이 이 선 한 줄에 몰린다. 병목이 되며, 이것이 [3_EtherChannel과_STP](lesson-3.md)의 동기다.

#### 방법 3 — L3 스위치 (실무의 정답, 오늘은 소개만)

- 라우팅까지 하는 스위치가 L3 스위치다(패킷 트레이서의 3560).
- 라우터 없이 스위치 안에 VLAN마다 가상 인터페이스(SVI)를 만들어 게이트웨이로 쓴다.

```bash
ip routing                            # 라우팅 기능 켜기 (이게 없으면 그냥 스위치)
interface vlan 10
 ip address 192.168.10.254 255.255.255.0
 no shutdown
interface vlan 20
 ip address 192.168.20.254 255.255.255.0
 no shutdown
```

| | Router-on-a-stick | L3 스위치 (SVI) |
|---|---|---|
| 장비 | 라우터 + 스위치 | L3 스위치 한 대 |
| 속도 | 선 한 줄이 병목 | 스위치 내부에서 빠르다 |
| 쓰는 곳 | 소규모 · 학습용 | 회사 코어 |

`interface vlan 10`(SVI)은 8일차에 L2 스위치의 관리용 IP로 한 번 더 만난다. → [1_원격접속_Telnet과SSH](../day-08/lesson-1.md)

## 2. 동작 원리

1. 액세스 포트로 들어온 프레임은 태그가 없다. 스위치는 그 포트의 VLAN 번호를 기억한다.
2. 프레임이 트렁크로 나갈 때 스위치가 802.1Q 태그(VLAN 번호)를 붙인다. 네이티브 VLAN의 프레임만 태그 없이 나간다.
3. 받는 스위치는 태그의 VLAN 번호를 보고 같은 VLAN 포트로 내보낸다. 액세스 포트로 나갈 때 태그를 뗀다.
4. 목적지가 다른 VLAN(다른 서브넷)이면 PC는 게이트웨이로 프레임을 보낸다.
5. Router-on-a-stick에서는 트렁크로 들어온 태그 10 프레임을 `g0/0.10`이 받는다. 라우터가 라우팅 테이블로 `g0/0.20`을 골라 태그 20을 붙여 내보낸다.

## 3. 실습·질문 연결

- 실습 STEP 2(트렁크) · STEP 3(Router-on-a-stick) → [0_실습_명령어_모음](commands.md) · 실습 절차 [4_스위칭_실습](lesson-4.md)
- 트렁크를 만들기 전에 PC0 → PC2(같은 VLAN 10, 다른 층) ping은? → 실패한다. 선이 VLAN 1 통로여서다.
- 트렁크를 만들었다. 이제 PC0 → PC1(VLAN 20)은? → 여전히 실패한다. 트렁크는 같은 VLAN끼리의 통로일 뿐이고, 벽을 넘으려면 라우터가 필요하다.
- 라우터 물리 포트 `g0/0`에 IP를 줘야 하는가? → 아니다. 켜기만 한다. IP는 서브인터페이스에 준다.
- Fa0/23이 `show vlan brief`에서 사라졌다. → 트렁크가 된 것이며 정상이다.

## 4. 강의 메모

- 질문 두 개로 연다: 1) 한 선에 여러 VLAN? 2) 벽 너머로? 둘을 섞지 않도록 칠판에 번호를 매겨 나눠 푼다.
- 태그 = 택배 송장 비유 하나로 트렁크·네이티브 VLAN·액세스 포트가 다 설명된다. 네이티브 VLAN은 송장 없이 싣는 상자 하나다(양쪽이 "송장 없는 건 우리 것"이라고 합의해야 한다).
- Router-on-a-stick은 "올라갔다 내려온다"를 손으로 그려 준다. 병목에서 EtherChannel 동기로 연결한다.
- "태그 먼저, 주소 나중"을 구호처럼 쓴다. 순서 에러가 실습 병목 1위다.
- L3 스위치는 "실무에서는 이렇게 한다"는 소개만 한다. 명령은 부록에 있다. → [0_실습_명령어_모음](commands.md)
- VTP(VLAN 자동 배포)는 이름만 언급한다. "편하지만 사고가 잦아 실무에서는 끄고(transparent) 쓴다" 한 줄이면 된다.

## 5. 약어·용어

| 용어 | 뜻 |
|---|---|
| 802.1Q (dot1Q) | 트렁크에서 VLAN 번호를 프레임에 붙이는 IEEE 표준 태그 규격 |
| ISL | Inter-Switch Link. 옛 시스코 전용 트렁크 규격 |
| 네이티브 VLAN | 트렁크에서 태그 없이 다니는 VLAN. 기본 VLAN 1 |
| DTP | Dynamic Trunking Protocol. 트렁크 자동 협상 프로토콜 |
| 서브인터페이스 | 물리 포트 하나 안에 만든 가상 인터페이스 |
| Router-on-a-stick | 라우터 포트 하나를 트렁크로 연결해 서브인터페이스로 VLAN 간 라우팅을 하는 방식 |
| SVI | Switch Virtual Interface. L3 스위치의 VLAN 가상 인터페이스 |
| VTP | VLAN Trunking Protocol. VLAN 정보를 스위치 간에 배포하는 시스코 프로토콜 |
