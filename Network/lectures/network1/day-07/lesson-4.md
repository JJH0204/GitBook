# 4. 스위칭 실습 — VLAN · 트렁크 · Router-on-a-stick · EtherChannel

## 🎯 학습 목표

- 스위치 두 대에 **VLAN 10 · 20** 을 만들고 포트를 배정한다
- 트렁크 **전후**로 무엇이 되고 안 되는지 직접 확인한다
- **Router-on-a-stick** 으로 VLAN 간 통신을 연다
- 선을 두 줄 이었을 때 **STP 가 막는 포트**를 찾고, **EtherChannel** 로 둘 다 살린다
- (여유) **루트 브리지 지명**과 **PortFast** 를 적용한다

## 🗺 오늘의 토폴로지 — 코리아IT 2층 · 3층

```
                     [R1]
                      │ G0/0  (.10 · .20)
                      │ trunk
                      │ Gi0/1
  PC0 ──Fa0/1──┐      │      ┌──Fa0/1── PC2
             [SW1]════════════[SW2]
  PC1 ──Fa0/2──┘ Fa0/23 ═══ Fa0/23 └──Fa0/2── PC3
                 Fa0/24 ═══ Fa0/24   ← STEP 4
```

| | VLAN 10 영업 (192.168.10.0/24) | VLAN 20 개발 (192.168.20.0/24) |
|---|---|---|
| 2층 SW1 | PC0 `.10.1` (Fa0/1) | PC1 `.20.1` (Fa0/2) |
| 3층 SW2 | PC2 `.10.2` (Fa0/1) | PC3 `.20.2` (Fa0/2) |
| 게이트웨이 | R1 G0/0.10 `.10.254` | R1 G0/0.20 `.20.254` |

## 🧪 실습 흐름 한눈에

| 단계 | 무엇 | 먼저 볼 실패 | 시간 |
|------|------|--------------|------|
| **준비** | 그림 · PC IP (Fa0/24 는 안 꽂음) | — | 15분 |
| **①** | VLAN 만들기 | 나눴더니 **같은 VLAN 도 층을 못 넘는다** | 20분 |
| **②** | 트렁크 | 옆자리 **다른 VLAN 은 여전히 안 된다** | 15분 |
| **③** ⭐ | Router-on-a-stick | **"태그 먼저"** 를 어기면 거절 | 20분 |
| **④** ⭐ | 두 번째 선 → EtherChannel | 선이 둘인데 **하나는 논다** | 30분 |
| **⑤** | 루트 지명 · PortFast | (생략 가능) | 10분 |

## 🧪 ① VLAN — 나눴더니 오히려 안 된다

**나누기 전**: 모든 포트가 VLAN 1 → PC0 → PC2 ping ✅. 시뮬레이션으로 보면 PC0 의 ARP 가 **개발팀 PC1 · PC3 까지** 간다.

**나눈 뒤**: 두 스위치 모두 Fa0/1 = 10, Fa0/2 = 20.

| | 나누기 전 | 나눈 뒤 |
|---|:---:|:---:|
| PC0 → PC2 (같은 VLAN 10, 다른 층) | ✅ | ❌ |

- 🗣 **"같은 VLAN 10 인데 왜 안 될까요?"**
  → 스위치 사이 Fa0/23 은 여전히 **VLAN 1 액세스 포트**. VLAN 10 프레임은 그 문을 못 지나간다
- 이 실패가 **트렁크의 필요성** 그 자체다

## 🧪 ② 트렁크 — 같은 VLAN 은 넘고, 다른 VLAN 은 못 넘는다

Fa0/23 을 **양쪽 모두** `switchport mode trunk`.

| | 결과 | 이유 |
|---|:---:|---|
| PC0 → PC2 (10 → 10) | ✅ | 태그 10 을 달고 트렁크를 건넌다 |
| PC1 → PC3 (20 → 20) | ✅ | 태그 20 도 같은 선을 탄다 |
| PC0 → PC1 (10 → 20) | ❌ | **다른 네트워크** — 라우터가 없다 |

**🔎 봐야 할 것**

- `show interfaces trunk` → **`trunking`** · Native vlan **1**
- `show vlan brief` → **Fa0/23 이 목록에서 사라짐** (모든 VLAN 의 통로라서)
- 시뮬레이션: 이제 PC0 의 ARP 가 **PC1 · PC3 에게 가지 않는다** — ①의 관찰과 나란히 비교

> 🗣 **"바로 옆자리 PC1 과 통신이 안 됩니다. 같은 스위치인데요?"**
> → 이 질문에 학생이 **"라우터가 필요해요"** 라고 답하면 4일차가 제대로 남은 것이다.

## 🧪 ③ Router-on-a-stick — "태그 먼저, 주소 나중"

**스위치 쪽**: SW1 Gi0/1 을 **트렁크**로 (라우터에게 태그 10 · 20 을 둘 다 넘긴다)

**라우터 쪽**: 물리 `g0/0` 은 **`no shutdown` 만**, 서브인터페이스 두 개에 태그와 IP

```
interface g0/0.10  →  encapsulation dot1Q 10  →  ip address 192.168.10.254 …
interface g0/0.20  →  encapsulation dot1Q 20  →  ip address 192.168.20.254 …
```

**일부러 틀리게 먼저** — `g0/0.10` 에서 태그 없이 IP 부터 치면 거절 메시지가 나온다.
→ 서브인터페이스는 **자기가 어느 태그 담당인지** 알아야 주소를 받는다.

**🔎 R1 의 라우팅 테이블**

```
C    192.168.10.0/24 is directly connected, GigabitEthernet0/0.10
C    192.168.20.0/24 is directly connected, GigabitEthernet0/0.20
```

- 🗣 **"물리 포트는 하나인데 `C` 가 두 줄입니다."** → 선 하나에 **네트워크 두 개**가 붙어 있다

**결과**: PC0 → PC1 ✅ · PC0 → PC3 ✅ · `tracert` 첫 홉 = `192.168.10.254`

> 🗣 **"옆자리로 가는데 라우터를 들렀다 오네요."** → 모든 부서 간 통신이 **선 한 줄**에 몰린다 → ④로

## 🧪 ④ 두 번째 선 → STP → EtherChannel ⭐ 오늘의 핵심

### 선을 하나 더 꽂는다

Fa0/24 ↔ Fa0/24. 30초 뒤에도 **한쪽 끝이 주황**으로 남는다.

**🔎 `show spanning-tree vlan 10` — 두 스위치를 나란히**

| | 대장(루트) 쪽 | 대장 아닌 쪽 |
|---|---|---|
| 표시 | `This bridge is the root` | Root ID 에 **상대 MAC** |
| Fa0/23 | Desg FWD | **Root FWD** |
| Fa0/24 | Desg FWD | **Altn BLK** ⛔ |

- 대장은 **MAC 이 작은 쪽** — 옆 사람과 결과가 달라도 정상
- 🗣 **"선 두 줄인데 하나는 놀고 있다. 이게 4일차 STP 의 대가입니다."**

### 둘을 하나로 묶는다

양쪽 스위치에서 **"끄고, 똑같이, 묶고, 켠다"**

```
interface range fa0/23 - 24 → shutdown → switchport mode trunk
                            → channel-group 1 mode active → no shutdown
interface port-channel 1    → switchport mode trunk
```

**🔎 봐야 할 것**

| 명령 | 묶기 전 | 묶은 뒤 |
|------|---------|---------|
| `show etherchannel summary` | (없음) | **`Po1(SU)` · `Fa0/23(P) Fa0/24(P)`** |
| `show spanning-tree vlan 10` | Fa0/23 · Fa0/24 (하나 BLK) | **`Po1` 한 줄, FWD** |
| `show interfaces trunk` | Fa0/23 | **Po1** |

### 선 하나를 뽑아본다

PC0 에서 `ping -t 192.168.10.2` 를 돌리며 Fa0/24 선을 삭제 → **ping 이 끊기지 않는다.**

| | STP 만 있을 때 선이 끊기면 | EtherChannel 에서 선이 끊기면 |
|---|---|---|
| 동작 | 막아둔 선을 **다시 계산해서** 연다 | **Po1 은 그대로**, 남은 선으로 계속 |
| 끊김 | 최대 **30~50초** | 사실상 **없음** |

## 🧪 ⑤ 마무리 튜닝 (여유 있으면)

| 무엇 | 명령 | 확인 |
|------|------|------|
| 대장 지명 | `spanning-tree vlan 1,10,20 root primary` (SW1) | SW1 에 `This bridge is the root` · Priority **24586** |
| PortFast | PC 포트에 `spanning-tree portfast` | 선을 다시 꽂으면 **바로 초록** |

**PortFast 비교 실험**: Fa0/1 에만 먼저 켜고 PC0 · PC1 선을 동시에 다시 꽂는다 → **PC0 은 즉시 초록, PC1 은 주황 30초.**
3일차 → 4일차 → 오늘로 이어진 **"주황 점"** 이야기의 끝.

## ⚠️ 실습 중 막히면 — 오늘판 5대 원인

| 증상 | 원인 |
|------|------|
| 같은 VLAN 인데 층을 못 넘는다 | 스위치 사이가 **트렁크가 아니다** (1위) |
| 다른 VLAN 이 라우터를 거쳐도 안 된다 | SW1 **Gi0/1 이 액세스** 그대로 · R1 `g0/0` **shutdown** |
| 서브인터페이스 IP 거절 | **태그 먼저** (`encapsulation dot1Q`) |
| EtherChannel 이 안 묶인다 | **한쪽만** 설정했다 · 두 포트 설정이 다르다 |
| 두 번째 선이 계속 주황 | STP 가 막은 것 — **정상** |

## 📝 강의 메모

- 오늘은 **실패 4연속**이 설계다: ①같은 VLAN 도 안 됨 → ②다른 VLAN 은 안 됨 → ③태그 없이 IP 거절 → ④선 하나가 논다.
  **실패를 건너뛰고 정답부터 치게 두지 말 것** — 각 기술이 "왜" 있는지가 실패에서 나온다
- **①의 시뮬레이션 관찰(ARP 가 개발팀까지)** 과 **②의 관찰(이제 안 감)** 을 꼭 나란히 보여준다 — VLAN 을 눈으로 보는 유일한 장면
- ③은 스위치 쪽(Gi0/1 트렁크)을 **빼먹는 학생이 많다** → R1 만 보고 있으면 "스위치 쪽 문은 열었나요?"
- ④의 루트 브리지는 **사람마다 다르다** → 서로 화면을 비교시키면 "MAC 운" 이 자연스럽게 설명된다
- ⑤는 시간이 부족하면 **통째로 생략** — 단, PortFast 비교는 30초면 끝나니 가능하면 보여준다
