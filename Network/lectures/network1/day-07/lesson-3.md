# 3. 선 두 줄을 하나로 — STP 다시 보기와 EtherChannel

> 상위: [7일차 · 스위칭 심화](README.md)

## 🎯 학습 목표

- 스위치 사이에 선을 **두 줄** 이으면 STP 가 **하나를 막는다**는 것을 다시 확인한다
- **루트 브리지**가 어떻게 뽑히고, 어느 포트가 막히는지 `show spanning-tree` 로 읽는다
- **PortFast** 로 3일차의 "주황 점 30초"를 없앤다
- **EtherChannel** 이 여러 선을 **논리적으로 한 줄**로 묶어 STP 문제를 푸는 원리를 이해한다
- **LACP / PAgP / on** 모드 조합과, 묶이기 위한 **조건**을 안다

## 📖 ① STP 다시 보기 — 누가 막을지는 누가 정하나

### 루트 브리지 — 나무의 뿌리

STP 는 스위치들 중 **대장 하나(루트 브리지)** 를 뽑고, **대장에게 가는 가장 좋은 길만 남기고** 나머지를 막는다.

```
         [SW1] 👑 루트 브리지 (대장)
          ║  ║
   Fa0/23 ║  ║ Fa0/24          루트의 포트는 전부 FWD (지정 포트)
          ║  ║
         [SW2]
   Fa0/23 ✅ Root(FWD)          대장에게 가는 최선의 길 = 루트 포트
   Fa0/24 ⛔ Altn(BLK)          남는 길 = 대체 포트 → 막는다
```

**대장은 어떻게 뽑나 — Bridge ID 가 가장 작은 스위치**

```
Bridge ID  =  우선순위(Priority)  +  MAC 주소
              기본 32768 (+VLAN번호)   공장에서 박힌 값
```

1. 우선순위가 **작은** 쪽이 이긴다 (기본은 모두 32768 → 비긴다)
2. 비기면 **MAC 이 작은** 쪽이 이긴다 → 결국 **제일 오래된(=MAC 이 작은) 스위치가 대장**이 되기 쉽다

> 💡 **비유: 반장 선거.** 원래는 **추천(우선순위)** 으로 뽑는데, 아무도 추천을 안 하면
> **출석번호(MAC)가 빠른 사람**이 반장이 된다. 제일 느린 구형 스위치가 반장이 되는 사고가 여기서 난다.
> → 그래서 실무는 **반장을 직접 지명**한다: `spanning-tree vlan 10,20 root primary`

> ⚠️ **막히는 포트는 대장이 아닌 쪽 스위치에 있다.** 한쪽만 보고 "BLK 가 없는데요?" 하지 말고 **두 대 다** 확인.

### `show spanning-tree` 읽기 (루트가 아닌 SW2)

```
VLAN0010
  Spanning tree enabled protocol ieee
  Root ID    Priority    32778
             Address     0001.4295.1A01          ← 대장(루트)의 MAC
             Cost        19
             Port        23(FastEthernet0/23)    ← 대장에게 가는 내 포트

  Bridge ID  Priority    32778  (priority 32768 sys-id-ext 10)
             Address     000C.85B2.3C02          ← 나(SW2)의 MAC

Interface        Role Sts Cost      Prio.Nbr Type
---------------- ---- --- --------- -------- ----------
Fa0/1            Desg FWD 19        128.1    P2p
Fa0/23           Root FWD 19        128.23   P2p
Fa0/24           Altn BLK 19        128.24   P2p     ← ⛔ 막힌 선
```

| 읽을 곳 | 뜻 |
|---------|-----|
| **VLAN0010** | STP 는 **VLAN 마다 따로** 돈다 (PVST+). VLAN0001 · 0020 도 있다 |
| **Priority 32778** | 32768 + **VLAN 번호 10** |
| **This bridge is the root** | 이 문구가 있으면 **내가 대장** (SW1 쪽에서 보인다) |
| **Role** | `Root` 대장 가는 길 · `Desg` 내보내는 포트 · `Altn` 대체(대기) |
| **Sts** | `FWD` 통과 · `BLK` 막힘 · `LIS`/`LRN` 확인 중(주황 점) |

### PortFast — 3일차의 "주황 점 30초"를 없앤다

- 포트가 켜지면 STP 는 루프가 없는지 **Listening → Learning** 을 거친다 = 약 **30초** (4일차)
- 그런데 **PC 한 대만 꽂는 포트**에 루프가 생길 리가 없다 → **확인을 건너뛰자** = **PortFast**

```bash
interface range fa0/1 - 2
 spanning-tree portfast          # PC 포트만! 스위치끼리 잇는 포트엔 절대 금지
```

> 🚨 **PortFast 는 PC 포트에만.** 스위치를 잇는 포트에 켜면 STP 의 안전장치를 스스로 끄는 것이다.
> 실무에서는 누가 PortFast 포트에 스위치를 꽂으면 포트를 막아버리는 **BPDU Guard** 를 같이 켠다 (`spanning-tree bpduguard enable`) — 이름만.

> 💡 3일차 → 4일차 → 7일차로 이어지는 떡밥의 끝:
> **"주황 점은 고장이 아니다(3일차) → STP 가 확인하는 중이다(4일차) → PC 포트라면 건너뛸 수 있다(오늘)"**

## 📖 ② EtherChannel — 두 줄을 한 줄이라고 우긴다

### 아이디어

STP 가 막는 이유는 **"길이 두 개라서"** 다. 그럼 **두 선을 하나로 묶어서 "길은 하나"라고 신고**하면?

```
  묶기 전                             묶은 뒤
 [SW1] ─── Fa0/23 ─── [SW2]          [SW1] ═══ Po1 ═══ [SW2]
       ─── Fa0/24 ─── (⛔ BLK)             (Fa0/23 + Fa0/24)
  STP: "길이 둘이다, 하나 막아!"       STP: "길이 하나네, 통과"
```

- 여러 물리 선을 **논리 인터페이스 하나(Port-channel, `Po1`)** 로 묶는다
- STP 는 `Po1` 을 **포트 하나**로 본다 → 막을 이유가 없다 → **두 선이 다 일한다**

> 💡 **비유: 왕복 2차선 도로 두 개.** 교통경찰(STP)은 "길이 두 개면 차가 뱅뱅 돈다" 며 하나를 폐쇄한다.
> 두 도로를 **4차선 도로 하나**로 합쳐 신고하면 폐쇄할 이유가 없다. 차선 하나가 공사 중이어도 **도로는 계속 열려 있다.**

| 얻는 것 | 설명 |
|---------|------|
| **대역폭** ⬆ | 100M × 2 = **200M 급** 통로 |
| **이중화** | 선 하나가 끊겨도 `Po1` 은 **그대로 up** — STP 재계산(30초)도 없다 |
| **관리 편의** | 설정은 `Po1` 한 곳에서 |

> ⚠️ **"두 배 빨라진다"의 정확한 뜻**: 대화(흐름) 하나는 **선 하나**를 탄다.
> 파일 **하나**가 두 배 빨라지는 게 아니라, **여러 대화가 두 선에 나눠** 타서 전체가 넓어진다 (차선이 늘어난 도로와 같다).

### 묶는 방식 — 서로 "묶자"고 합의해야 한다

| 방식 | 누가 만들었나 | 모드 |
|------|---------------|------|
| **LACP** ⭐ | 국제 표준 (IEEE **802.3ad**) | `active`(먼저 제안) · `passive`(제안 오면 응함) |
| **PAgP** | 시스코 전용 | `desirable`(먼저 제안) · `auto`(제안 오면 응함) |
| **on** | — | **협상 없이** 무조건 묶음 |

**조합표 — 묶이나?**

| SW1 \ SW2 | active | passive | desirable | auto | on |
|-----------|:---:|:---:|:---:|:---:|:---:|
| **active** | ✅ | ✅ | ❌ | ❌ | ❌ |
| **passive** | ✅ | ❌ | ❌ | ❌ | ❌ |
| **desirable** | ❌ | ❌ | ✅ | ✅ | ❌ |
| **auto** | ❌ | ❌ | ✅ | ❌ | ❌ |
| **on** | ❌ | ❌ | ❌ | ❌ | ✅ |

- **둘 다 기다리기만 하면(passive–passive, auto–auto) 안 묶인다** — DTP 의 auto–auto 와 같은 이치 ([2_트렁크와_VLAN간_라우팅](lesson-2.md))
- **방식이 다르면(LACP–PAgP) 안 묶인다** — 서로 다른 언어
- **오늘의 원칙: 양쪽 다 `active`** (표준 · 확실)

> 🚨 **`on` 은 위험하다.** 협상이 없어서 한쪽만 `on` 이면 **묶인 줄 알고 보내는데 상대는 모른다** → 루프·장애.

### 묶이려면 양쪽 선의 설정이 **같아야** 한다

| 조건 | 예 |
|------|-----|
| 속도 · 듀플렉스 | 둘 다 100M / full |
| 포트 모드 | 둘 다 **트렁크** (하나만 액세스 ❌) |
| VLAN 설정 | 액세스면 같은 VLAN, 트렁크면 **같은 허용 VLAN · 네이티브 VLAN** |

> 💡 그래서 **`interface range` 로 두 포트를 한꺼번에** 설정한다 — 설정이 어긋날 틈이 없다.

### 설정 (양쪽 스위치에 똑같이)

```bash
interface range fa0/23 - 24
 shutdown                              # ① 묶는 동안 잠깐 끈다 (루프 방지)
 switchport mode trunk                 # ② 둘 다 트렁크로 똑같이
 channel-group 1 mode active           # ③ 1번 묶음에 넣는다 (LACP)
 no shutdown
 exit
interface port-channel 1               # ④ 만들어진 논리 포트
 switchport mode trunk
end
show etherchannel summary
```

### `show etherchannel summary` 읽기

```
Flags:  D - down        P - in port-channel
        I - stand-alone s - suspended
        S - Layer2      U - in use
...
Group  Port-channel  Protocol    Ports
------+-------------+-----------+------------------------------
1      Po1(SU)           LACP   Fa0/23(P) Fa0/24(P)
```

| 표시 | 뜻 | 좋은가 |
|------|-----|:------:|
| **Po1(SU)** | **S** 2계층 · **U** 사용 중 | ✅ |
| **Fa0/23(P)** | **P** = 묶음에 들어갔다 | ✅ |
| `(SD)` | 묶음이 **down** | ❌ 상대가 안 받아줌 |
| `(I)` / `(s)` | 혼자 놀거나(stand-alone) 정지(suspended) | ❌ 조건 불일치 |

> 🔎 묶은 뒤 `show spanning-tree` 를 보면 Fa0/23 · Fa0/24 가 사라지고 **`Po1` 한 줄**만 `FWD` 로 남는다.

## 🧪 실습 / 질문

- 실습 STEP 4(두 번째 선 → STP 확인 → EtherChannel) · STEP 5(PortFast · 루트 지명) → [0_실습_명령어_모음](commands.md) · 해설 [4_스위칭_실습](lesson-4.md)
- "선을 꽂았는데 한쪽 링크만 주황이다. 고장?" → 아니다. **STP 가 막은 것** (`Altn BLK`)
- "EtherChannel 을 한쪽 스위치만 설정했다" → 묶이지 않는다. **양쪽 다**
- "SW1 은 active, SW2 는 desirable" → ❌ LACP 와 PAgP 는 서로 모른다
- "묶은 뒤 선 하나를 뽑으면?" → `Po1` 은 **up 그대로**, 통신은 **끊기지 않는다**

## 📝 강의 메모

- **4일차 CCNA(STP 끈 채 두 줄 연결) 문제를 다시 띄우고 시작**하면 흐름이 산다
- 🗣 **"선 두 줄인데 속도는 그대로다"** — 이 불만이 EtherChannel 의 동기. 학생이 먼저 말하게 한다
- 루트 브리지는 **반장 선거**(추천 없으면 출석번호) — MAC 이 작은 **구형 스위치가 대장이 되는 사고**까지 말해줘야 `root primary` 가 와닿는다
- STP 는 **VLAN 마다 따로**(PVST+) — `show spanning-tree` 가 VLAN 수만큼 길게 나오는 이유
- PortFast 는 **3일차 주황 점 떡밥의 최종 회수** — 실습에서 "꽂자마자 초록" 을 꼭 보여줄 것
- EtherChannel 조합표는 **외우게 하지 말고**, "둘 다 기다리면 안 된다 · 언어가 다르면 안 된다 · on 은 위험" 3줄로
- ⚠️ 설정 순서 사고가 많다 → **"끄고, 똑같이, 묶고, 켠다"**
