## 오늘의 목표

- 스위치가 MAC 주소 테이블을 학습하고 프레임을 전달하는 원리를 이해한다.
- 에이징과 루프 방지(STP)가 왜 필요한지 안다.
- 라우터가 라우팅 테이블로 경로를 결정하는 원리를 이해한다.
- `show ip route` 출력을 읽는다(코드, AD, 메트릭).
- Cisco IOS CLI 기본 모드와 명령으로 테이블을 직접 확인하고 설정을 저장한다.
- 정적 경로를 설정해 직접 연결되지 않은 네트워크를 잇는다.

## 강의 메모

- 3일차 실습(연결·ping)에서 한 걸음 더 나아가 "왜 그렇게 전달됐는지"를 표로 설명한다.
- 오늘의 주인공은 표(테이블) 두 개다. MAC 테이블(2계층)과 라우팅 테이블(3계층)의 대비로 진행한다.
- CLI의 Tab, `?`, 축약을 첫 10분에 알려준다. 없으면 학생이 타이핑에 지친다.
- Lab 10·11은 빠르게 진행하고 Lab 12에 시간을 몰아준다.
- Lab 12는 먼저 실패를 보여주고 정적 경로로 성공시키는 순서가 효과적이다.
- 오늘의 회수 지점은 셋이다.
  1. 3일차 주황 점 30초 → STP
  2. 3일차 `Destination host unreachable` → 경로가 없으면 버린다
  3. 3일차 "MAC은 바뀌고 IP는 그대로" → 라우터의 패킷 처리 5단계
- 5일차 예고: "라우터가 10대면 이것을 손으로 다 넣을 수 있을까?"로 마무리한다.
