## 1. 구성 요소

### 라우팅 테이블 (목적지 네트워크 → 어디로 보낼지)

| 목적지 네트워크 | 나가는 방법 |
|---|---|
| 192.168.10.0/24 | 직접 연결(인터페이스 G0/0) |
| 192.168.20.0/24 | 직접 연결(인터페이스 G0/1) |
| 10.0.0.0/8 | 다음 홉 192.168.10.254 로 |
| 0.0.0.0/0 (그 외 전부) | 디폴트 라우트. ISP 쪽으로 |

- 라우터는 패킷의 목적지 IP를 테이블과 비교해 내보낼 인터페이스나 다음 홉을 고른다.
- 2일차에 IP를 네트워크 단위로 나눈 것이 여기서 판단 기준이 된다. → [4_서브넷팅](../day-02/lesson-4.md)

### 경로가 테이블에 들어오는 3가지 방법

| 종류 | 방법 | 특징 |
|---|---|---|
| 직접 연결 (Connected) | 인터페이스에 IP를 설정하면 자동 등록 | 바로 붙은 네트워크 |
| 정적 (Static) | 관리자가 수동으로 입력 | 작은 망에 적합. 정확하지만 손이 간다 |
| 동적 (Dynamic) | 라우터끼리 정보를 교환(프로토콜) | 큰 망에 적합. 자동 갱신. 5일차에서 다룬다 |

- 동적 라우팅(RIP/OSPF/EIGRP)은 다음 시간이다. → [5일차 · 라우팅 프로토콜](../day-05/README.md)

### `show ip route` 코드

```
R1# show ip route

Codes: C - connected, L - local, S - static,
       R - RIP, O - OSPF, D - EIGRP

Gateway of last resort is 203.0.113.1 to network 0.0.0.0

      192.168.10.0/24 is variably subnetted, 2 subnets, 2 masks
C       192.168.10.0/24 is directly connected, GigabitEthernet0/0
L       192.168.10.254/32 is directly connected, GigabitEthernet0/0
S       192.168.30.0/24 [1/0] via 192.168.20.2
S*   0.0.0.0/0 [1/0] via 203.0.113.1
```

왼쪽 글자 하나가 경로의 출신을 말해준다.

| 코드 | 뜻 | 어떻게 생겼나 |
|---|---|---|
| C | Connected. 직접 연결된 네트워크 | 인터페이스에 IP를 주면 자동 |
| L | Local. 그 인터페이스 자신의 주소(`/32`) | 자동 |
| S | Static. 관리자가 넣은 경로 | 수동 |
| S* | 디폴트 라우트 (`*`는 기본 경로 표시) | 수동 |
| R / O / D | RIP / OSPF / EIGRP가 알려준 경로 | 5일차 |

### AD와 메트릭 (`[1/0]`)

```
S    192.168.30.0/24 [1/0] via 192.168.20.2
                      ↑ ↑        ↑
                      │ │        └ 다음 홉 (이리로 넘겨라)
                      │ └ 메트릭 : 같은 방식끼리 비교할 때의 거리
                      └ AD      : 서로 다른 방식끼리 비교할 때의 신뢰도
```

AD(Administrative Distance)는 정보의 신뢰도이며 낮을수록 신뢰한다.

| 출처 | AD |
|---|---|
| 직접 연결 (C) | 0 |
| 정적 (S) | 1 |
| EIGRP (내부) | 90 |
| OSPF | 110 |
| RIP | 120 |

## 2. 동작 원리

### 여러 경로가 맞으면 (Longest Prefix Match)

목적지가 `172.16.5.10`이고 테이블에 아래 셋이 모두 있으면 어느 경로를 쓰는가?

| 경로 | 맞는가 | 얼마나 구체적인가 |
|---|---|---|
| `0.0.0.0/0` | 맞다 | 0비트 (아무거나) |
| `172.16.0.0/16` | 맞다 | 16비트 |
| `172.16.5.0/24` | 맞다 | 24비트. 선택된다 |

- 마스크가 긴(숫자가 큰) 쪽이 이긴다. "더 자세히 아는 사람의 말을 듣는다"는 뜻이다.
- 비유: `서울시`보다 `서울시 강남구 역삼동`이 배달에 더 유용하다.
- 그래서 `0.0.0.0/0`(디폴트)은 아무것도 맞지 않을 때만 쓰인다. 가장 덜 구체적이기 때문이다.

### AD로 신뢰도를 비교하는 방법

- 같은 목적지를 두 방식이 서로 다르게 알려주면 AD가 낮은 쪽을 테이블에 올린다.
- "내 눈으로 본 것(0) > 관리자가 알려준 것(1) > 남이 전해준 것(90~120)"이다.
- 이 개념이 6일차 재분배의 핵심이 된다. → [6일차](../day-06/README.md)

### 정적 경로 넣기

명령 형식은 다음 한 줄이다.

```
ip route <목적지 네트워크> <서브넷 마스크> <다음 홉 주소>
```

`192.168.30.0/24`로 가려면 `192.168.20.2`에게 넘기도록 설정하는 예시다.

```
R1(config)# ip route 192.168.30.0 255.255.255.0 192.168.20.2
```

- "어디로 가려면 / 누구에게 넘겨라" 두 부분이 전부다.
- 다음 홉은 바로 옆 라우터의 인터페이스 주소다. 멀리 있는 주소를 적으면 안 된다.
- 지울 때는 앞에 `no`를 붙인다.

```
R1(config)# no ip route 192.168.30.0 255.255.255.0 192.168.20.2
```

{% hint style="warning" %}
CAUTION: 라우팅은 왕복이다. 가는 길만 넣으면 요청은 가지만 답이 돌아오지 못한다. 양쪽 라우터에 서로를 향한 경로를 각각 넣어야 ping이 성공한다. 실습에서 가장 많이 막히는 지점이다.
{% endhint %}

### 기본 게이트웨이와 디폴트 라우트

- 기본 게이트웨이: PC가 "내 네트워크 밖으로 나갈 때 맡기는" 라우터 주소다. 3일차 실습에서 설정했다. → [4_패킷트레이서_실습](../day-03/lesson-4.md)
- 디폴트 라우트(0.0.0.0/0): 라우팅 테이블에 명시된 경로가 없을 때 "일단 이리로" 보내는 길이다.

```
R1(config)# ip route 0.0.0.0 0.0.0.0 203.0.113.1
```

- `0.0.0.0 0.0.0.0`은 "어떤 주소든"을 뜻한다. 마스크가 0비트라 Longest Prefix Match에서 항상 꼴찌다.
- 다른 경로가 있으면 그쪽이 이기고, 아무것도 없을 때만 이 길로 간다.
- 인터넷 방향(ISP)으로 나갈 때 쓴다. 전 세계 주소를 모두 적을 수 없기 때문이다.
- 비유: 우체국(라우터)이 행선지별 분류표(라우팅 테이블)를 보고 다음 우체국으로 넘긴다. 모르는 주소는 중앙 우체국(디폴트 라우트)으로 보낸다.

### 경로가 없으면 (버린다)

라우터는 모르는 주소를 추측하지 않는다.

```
① 목적지 IP를 테이블과 비교
② 맞는 경로가 하나도 없다 (디폴트도 없다)
③ 패킷을 버린다(drop)
④ 보낸 쪽에 ICMP "Destination unreachable"을 돌려준다
```

- 3일차에 본 `Destination host unreachable` 메시지의 정체가 이것이다. → [3_ICMP와_ping](../day-03/lesson-3.md)
- 즉 그 메시지는 "내가 그 동네로 가는 길을 모른다"는 라우터의 대답이다.

### 패킷 처리 순서

3일차의 "MAC은 바뀌고 IP는 그대로"가 라우터 안에서 실제로 일어나는 모습이다.

```
① 도착한 프레임의 껍데기(2계층 MAC)를 벗긴다
② 안에 있는 패킷의 목적지 IP를 본다
③ 라우팅 테이블 조회 → 나갈 인터페이스 / 다음 홉 결정
④ TTL을 1 줄인다   (0이 되면 버리고 "TTL expired" 회신)
⑤ 다음 구간용 MAC으로 새 껍데기를 씌워 내보낸다
```

- ④ 덕분에 traceroute가 동작하고, 루프에 빠진 패킷도 언젠가 사라진다.
- ⑤에서 다음 홉의 MAC을 모르면 라우터도 ARP를 한다. → [2_MAC주소와_ARP](../day-03/lesson-2.md)

## 3. 실습 연계와 확인 질문

- 패킷트레이서에서 `show ip route`로 라우팅 테이블을 확인한다. → [Lab 11. 라우터 라우팅 테이블 보기](lesson-3-lab-11.md)
- "PC가 다른 네트워크로 못 나갈 때 가장 먼저 확인할 것은?" → 기본 게이트웨이 설정이다.
- 경로 고르기: 목적지가 `10.1.5.7`이고 테이블에 `10.0.0.0/8`, `10.1.0.0/16`, `0.0.0.0/0`이 있다면?
  - 답: `10.1.0.0/16`. 맞는 것 중 마스크가 가장 길다.
- AD 고르기: 같은 네트워크를 정적(AD 1)과 RIP(AD 120)이 서로 다르게 알려주면?
  - 답: 정적. AD가 낮은 쪽이 테이블에 오른다.
- "정적 경로를 한쪽 라우터에만 넣으면 ping이 될까?" → 안 된다. 답이 돌아올 길이 없다.
- 실습에서 직접 설정한다. → [Lab 12. 정적 라우팅](lesson-3-lab-12.md)

## 4. 강의 메모

- 스위치=MAC 테이블(2계층), 라우터=라우팅 테이블(3계층) 대비로 각인시킨다.
- `show ip route` 화면을 띄워 놓고 코드(C/L/S/S*)를 하나씩 짚는다. 실습에서 매번 보게 될 화면이다.
- `[AD/메트릭]`은 AD만 확실히 다룬다. 메트릭은 5일차에 프로토콜별로 다시 나온다.
- "라우팅은 왕복"을 반복 강조한다. Lab 12에서 가장 많이 막히는 지점이다.
- `Destination host unreachable`은 3일차에서 넘어온 회수 지점이다. 그때 그 메시지를 다시 띄워 보여준다.
- 동적 라우팅은 "자동으로 표를 채워준다"는 것만 예고하고 상세는 5일차에서 다룬다.

## 5. 약어·용어

| 용어 | 뜻 |
|---|---|
| 다음 홉 (next hop) | 패킷을 넘길 바로 옆 라우터의 인터페이스 주소 |
| AD | Administrative Distance. 경로 출처의 신뢰도 값 (낮을수록 우선) |
| 메트릭 (metric) | 같은 방식으로 배운 경로끼리 비교하는 거리 값 |
| Longest Prefix Match | 일치하는 경로 중 마스크가 가장 긴 경로를 고르는 규칙 |
| 디폴트 라우트 | `0.0.0.0/0`. 일치하는 경로가 없을 때 쓰는 경로 |
| TTL | Time To Live. 라우터를 지날 때마다 1씩 줄어드는 패킷 수명 값 |
| ICMP | Internet Control Message Protocol. ping과 오류 회신에 쓰는 프로토콜 |
