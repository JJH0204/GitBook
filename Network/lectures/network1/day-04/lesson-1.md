## 학습 목표

- 스위치가 MAC 주소 테이블을 학습하는 과정을 이해한다.
- 플러딩·포워딩·필터링의 차이를 안다.
- MAC 테이블 출력을 읽고, 항목이 사라지는 이유(에이징)를 안다.

## 이전 학습과의 연결

3일차에 "스위치는 MAC을 보고 해당 포트로만 전달한다"고 했다. → [1_네트워크장비](../day-03/lesson-1.md)
그런데 스위치는 처음에 어느 MAC이 어느 포트에 있는지 모른다. 스위치는 이것을 스스로 배운다(learning).

## 1. 구성 요소

### MAC 주소 테이블 (CAM 테이블)

프레임의 출발지 MAC과 들어온 포트를 짝지어 기록한 표다.

### MAC 주소 테이블 출력

```
Switch# show mac address-table

          Mac Address Table
-------------------------------------------
Vlan    Mac Address       Type        Ports
----    -----------       --------    -----
   1    0001.4295.1a01    DYNAMIC     Fa0/1
   1    000c.85b2.3c02    DYNAMIC     Fa0/2
```

| 칸 | 뜻 |
|---|---|
| Vlan | 어느 VLAN 소속인지. 기본은 전부 `1`이다 |
| Mac Address | 학습한 MAC. 시스코는 `.`으로 4자리씩 끊어 쓴다(`0001.4295.1a01`) |
| Type | `DYNAMIC`은 스스로 배운 것, `STATIC`은 관리자가 고정한 것이다 |
| Ports | 그 MAC이 붙어 있는 포트 |

- 한 포트에 MAC이 여러 개 찍히면 그 포트에 스위치나 허브가 하나 더 물려 있다는 뜻이다.

### 스위치의 3대 임무

| 번호 | 임무 | 내용 |
|---|---|---|
| 1 | 학습 (Learning) | 출발지 MAC으로 표를 채운다 |
| 2 | 전달·차단 (Forwarding / Filtering) | 목적지 MAC으로 내보낼 포트를 고른다 |
| 3 | 루프 방지 (Loop Avoidance) | STP로 고리를 끊는다 |

## 2. 동작 원리

### MAC 주소 테이블 학습 (Learning)

프레임이 들어오면 출발지(source) MAC을 보고 "이 MAC은 이 포트에 있다"라고 표에 기록한다.

```
PC0(MAC AAAA) → 포트1로 들어옴  ⇒  테이블: AAAA = 포트1
PC1(MAC BBBB) → 포트2로 들어옴  ⇒  테이블: BBBB = 포트2
```

{% hint style="warning" %}
CAUTION: 배우는 것은 출발지이고 보내는 것은 목적지다. 방향이 반대다. 프레임이 들어오면 출발지 MAC으로 표를 채우고, 목적지 MAC으로 내보낼 포트를 고른다.
{% endhint %}

### 에이징 (Aging)

표에 한 번 올라간 항목은 영원히 남지 않는다.

- 그 MAC에서 프레임이 오지 않으면 기본 300초(5분) 뒤 항목을 자동으로 삭제한다.
- 삭제하는 이유는 장비가 다른 포트로 옮겨갈 수 있기 때문이다. 옛 정보를 붙들고 있으면 엉뚱한 포트로 보낸다.
- 그래서 오래 쉬었다가 다시 통신하면 플러딩부터 다시 시작한다.

```bash
clear mac address-table dynamic     # 배운 것 전부 지우기 (실습용)
```

### 프레임 전달 3가지

| 동작 | 언제 | 결과 |
|---|---|---|
| 플러딩 (Flooding) | 목적지 MAC을 아직 모를 때 | 들어온 포트를 뺀 전체 포트로 내보낸다 |
| 포워딩 (Forwarding) | 목적지 MAC을 테이블에서 알 때 | 해당 포트로만 전달한다 |
| 필터링 (Filtering) | 출발지·목적지가 같은 포트일 때 | 내보내지 않고 차단한다 |

{% hint style="info" %}
NOTE: 3일차 실습에서 첫 ping이 느린 이유는 둘이다. ARP 해석([2_MAC주소와_ARP](../day-03/lesson-2.md))과, 스위치가 아직 MAC을 몰라 플러딩하기 때문이다.
{% endhint %}

### 콜리전 도메인 분리 (허브와의 차이)

| 장비 | 콜리전 도메인 | 결과 |
|---|---|---|
| 허브 | 모든 포트가 하나 | 충돌이 잦다 |
| 스위치 | 포트마다 분리, 양방향 동시 통신(full-duplex) | 충돌이 거의 없다 |

- 브로드캐스트는 스위치를 통과한다. 따라서 스위치 전체가 하나의 브로드캐스트 도메인이다. → [7_캐스트_유니_브로드_멀티](../day-01/lesson-7.md)

### 반이중과 전이중

| 항목 | 반이중 (Half-duplex) | 전이중 (Full-duplex) |
|---|---|---|
| 동작 | 한 번에 한 방향만 | 보내기와 받기를 동시에 |
| 비유 | 무전기 ("오버!") | 전화 |
| 쓰는 곳 | 허브 연결 | 스위치 연결 (요즘 기본) |
| 충돌 | 발생 | 없음 |

- 요즘 장비는 속도와 듀플렉스를 자동 협상(auto-negotiation)한다.
- 한쪽만 수동으로 고정하면 듀플렉스 불일치가 생겨 "되기는 되는데 매우 느린" 증상이 나온다. 실무에서 흔한 장애다.

### 루프와 STP

스위치를 두 대 이상 연결할 때 안정성을 위해 선을 두 줄 잇는 경우가 있다. 그대로 두면 장애가 된다.

```
   ┌── 링크 A ──┐
[SW1]           [SW2]
   └── 링크 B ──┘      ← 고리(루프)가 생겼다
```

브로드캐스트 하나가 들어오면 다음 순서로 진행한다.

1. SW1이 플러딩한다. 링크 A와 B 양쪽으로 나간다.
2. SW2가 받아서 다시 플러딩한다. 프레임이 되돌아온다.
3. 끝나지 않는다. IP 패킷과 달리 2계층 프레임에는 TTL이 없어 영원히 돈다.

| 증상 | 이름 |
|---|---|
| 브로드캐스트가 무한 증식해 회선이 마비된다 | 브로드캐스트 스톰 |
| 같은 MAC이 이 포트 저 포트에서 보여 표가 요동친다 | MAC 테이블 불안정 |
| 같은 프레임을 여러 번 받는다 | 프레임 중복 |

#### STP (Spanning Tree Protocol)

- 스위치들이 서로 정보를 주고받아 한쪽 링크를 논리적으로 막는다(Blocking). 고리가 끊겨 나무(tree) 모양이 된다.
- 쓰던 길이 끊기면 막아둔 링크를 다시 열어 통신을 살린다. 이중화의 목적을 달성한다.
- 표준은 802.1D이고, 요즘은 더 빠른 RSTP(802.1w)를 쓴다.

{% hint style="info" %}
NOTE: 3일차 실습의 "주황 점 30초"가 STP다. 포트가 켜지면 STP가 "여기에 연결해도 루프가 생기지 않는가"를 확인하느라 `Blocking → Listening → Learning → Forwarding` 단계를 거친다. 그동안 통신이 되지 않는다. PC만 꽂는 포트는 루프 위험이 없어 PortFast로 즉시 통과시키기도 한다.
{% endhint %}

- STP 상세 설정은 이 과정 범위를 넘는다. 오늘은 "왜 기다리는가", "루프가 왜 위험한가"까지 다룬다.

### (예고) VLAN

- 스위치 하나를 논리적으로 여러 브로드캐스트 도메인으로 나누는 기술이 VLAN이다.
- 2일차 서브넷팅이 IP를 나눴다면 VLAN은 스위치를 나눈다. 심화 과정에서 다룬다.

## 3. 실습 연계와 확인 질문

- 패킷트레이서에서 `show mac address-table`로 학습된 표를 확인한다. → [Lab 10. 스위치 MAC 테이블 보기](lesson-3-lab-10.md)
- "스위치를 막 켰을 때 첫 통신은 왜 플러딩될까?" → 테이블이 비어 있기 때문이다.
- 비웠다 다시 채우기: `clear mac address-table dynamic` → `show`(비었나?) → `ping` → `show`(다시 찼나?)
- "표에 있는 MAC이 5분 뒤 사라지는 이유는?" → 에이징. 장비가 옮겨갈 수 있기 때문이다.
- "스위치 두 대를 선 두 줄로 연결하면?" → 루프, 브로드캐스트 스톰이 생긴다. 그래서 STP가 필요하다.
- "PC를 꽂았는데 30초쯤 통신이 안 된다. 고장일까?" → 아니다. STP가 확인 중이다.

## 4. 강의 메모

- Learning(출발지로 배움)과 Forwarding(목적지로 보냄)의 방향 차이를 강조한다.
- 콜리전 도메인(포트별 분리)과 브로드캐스트 도메인(전체 하나)을 구분한다.
- 에이징은 "잊어야 하는 이유"와 함께 설명한다. 5분이라고만 외우면 남지 않는다.
- STP는 3일차의 주황 점을 회수하는 자리다. "그때 기다렸던 것이 이것 때문이다"로 시작한다.
- 2계층 프레임에 TTL이 없다는 점을 짚어야 "왜 영원히 도는가"가 납득된다.

## 5. 약어·용어

| 용어 | 뜻 |
|---|---|
| CAM | Content Addressable Memory. MAC 테이블을 담는 메모리 |
| MAC | Media Access Control. 2계층 주소 |
| STP | Spanning Tree Protocol. 2계층 루프를 막는 프로토콜 |
| RSTP | Rapid STP (802.1w). 수렴이 빠른 STP |
| PortFast | 호스트 연결 포트를 STP 대기 없이 Forwarding으로 바로 전환하는 기능 |
| TTL | Time To Live. IP 패킷의 수명 값 |
| VLAN | Virtual LAN. 스위치를 논리적으로 나눈 브로드캐스트 도메인 |
