# Lab 12. 정적 라우팅 — 라우터 2대로 세 네트워크 잇기

> 상위: [4일차 · 스위치와 라우터](README.md)

## 작업 식별

| 항목 | 내용 |
|---|---|
| Task ID | LEC-N1-04-006-MP |
| 목적 | 라우터 2대 사이에 정적 경로를 양쪽에 넣어 직접 연결되지 않은 세 네트워크(`192.168.10.0/24`, `192.168.20.0/24`, `192.168.30.0/24`)를 잇는다 |
| 적용 대상 | Cisco Packet Tracer, Cisco IOS 라우터 2대(R1, R2), 스위치 2대, PC 2대 |
| 소요 시간 | 약 70분 |
| 확인 상태 | 미검증 (원본 강의 노트를 옮긴 것이며 Packet Tracer에서 다시 실행하지 않았다) |
| 개정 | R1 (2026-11-18) |

오늘의 핵심 실습이다. 라우터가 직접 연결되지 않은 네트워크로 보내려면 길을 알려줘야 한다. 3일차 파일을 확장해서 진행한다. 완전히 새로 만들지 않는다.

```
[PC0]──[SW1]──[R1]────────[R2]──[SW2]──[PC2]
  192.168.10.0/24   20.0/24    192.168.30.0/24
                (R1·R2 연결 구간)
```

| 장비 | 인터페이스 | IP | 게이트웨이 | 3일차 대비 |
|---|---|---|---|---|
| PC0 | — | 192.168.10.1 /24 | 192.168.10.254 | 그대로 |
| R1 | G0/0 | 192.168.10.254 /24 | — | 그대로 |

## 5. 절차

### A. 배선 바꾸기

1. (5-A-01) R1 ↔ SW2 케이블을 지운다. → 결과: 두 장비 사이 링크가 사라진다.
2. (5-A-02) 그 자리에 R2를 놓는다. → 결과: 캔버스에 R2가 보인다.
3. (5-A-03) R1 `G0/1`과 R2 `G0/1`을 크로스오버 케이블로 연결한다. → 결과: 링크가 연결된다.
4. (5-A-04) R2 `G0/0`과 SW2를 다이렉트 케이블로 연결한다. → 결과: 링크가 연결된다.

### B. 주소 설정

1. (5-B-01) PC2의 `IP Configuration`에서 IP `192.168.30.1`, 마스크 `255.255.255.0`, 게이트웨이 `192.168.30.254`를 입력한다.
2. (5-B-02) R1 CLI에서 `G0/1` 주소를 바꾼다.

```bash
enable
configure terminal
interface g0/1
 ip address 192.168.20.1 255.255.255.0
 no shutdown
end
show ip interface brief
```

→ 결과: `G0/1`이 `up/up`이고 주소가 `192.168.20.1`이다.

3. (5-B-03) R2 CLI에서 호스트 이름과 두 인터페이스를 설정한다.

```bash
enable
configure terminal
no ip domain-lookup
hostname R2
interface g0/1
 ip address 192.168.20.2 255.255.255.0
 no shutdown
 exit
interface g0/0
 ip address 192.168.30.254 255.255.255.0
 no shutdown
end
show ip interface brief
show ip route
```

→ 결과: 두 인터페이스가 `up/up`이다. `show ip route`에 `C` 2개만 있다. R2는 아직 `192.168.10.0`을 모른다.

### C. 먼저 실패 확인

1. (5-C-01) R1과 R2에서 각각 `show ip route`를 입력한다. → 결과: 각 라우터에 `C`만 2개씩 보인다. R1은 `30.0`을 모르고 R2는 `10.0`을 모른다.
2. (5-C-02) PC0의 `Command Prompt`에서 `ping 192.168.10.254`를 실행한다. → 결과: 성공한다(자기 게이트웨이).
3. (5-C-03) PC0에서 `ping 192.168.30.1`을 실행한다. → 결과: 실패한다. 메시지를 읽는다. → [3_ICMP와_ping](../day-03/lesson-3.md)

### D. 양쪽에 정적 경로 입력

1. (5-D-01) R1 CLI에서 `30.0`으로 가는 경로를 넣는다.

```bash
configure terminal
ip route 192.168.30.0 255.255.255.0 192.168.20.2
end
show ip route
copy running-config startup-config
```

→ 결과: `S 192.168.30.0/24 [1/0] via 192.168.20.2` 항목이 보인다.

2. (5-D-02) R2 CLI에서 `10.0`으로 돌아오는 경로를 넣는다.

```bash
configure terminal
ip route 192.168.10.0 255.255.255.0 192.168.20.1
end
show ip route
copy running-config startup-config
```

→ 결과: `S 192.168.10.0/24 [1/0] via 192.168.20.1` 항목이 보인다.

{% hint style="warning" %}
CAUTION: 5-D-01만 하고 5-D-02를 하지 않으면 ping이 실패한다.
{% endhint %}

### E. 확인과 저장

1. (5-E-01) 각 라우터에서 `show ip route`를 입력한다. → 결과: `S` 항목이 생겼다.
2. (5-E-02) PC0에서 `ping 192.168.30.1`을 실행한다. → 결과: 성공한다.
3. (5-E-03) 양쪽 라우터에서 `copy running-config startup-config`를 실행한다. (5-D에서 이미 실행했으면 건너뛴다.)
4. (5-E-04) `Ctrl+S`를 눌러 `04_정적라우팅.pkt`를 저장한다.

## 6. 기능 확인

| 번호 | 확인 동작 | 기대 결과 | 합격 기준 |
|---|---|---|---|
| 1 | R1, R2 각각 `show ip route` | `C` 2개와 `S` 1개 | 각 라우터에 `C` 2개 + `S` 1개 |
| 2 | PC0에서 `ping 192.168.30.1` | 응답이 온다 | 성공 |
| 3 | R2에서 `no ip route 192.168.10.0 255.255.255.0 192.168.20.1` 후 PC0에서 ping | 다시 실패한다 | 실패 확인 후 다음 절로 이동 |

3번은 "라우팅은 왕복"을 몸으로 확인하는 단계다. 확인이 끝나면 7절로 되돌린다.

## 7. 복구

1. (7-01) 6절 3번에서 R2의 경로를 지웠다면 다시 넣는다: `ip route 192.168.10.0 255.255.255.0 192.168.20.1` → 결과: R2 `show ip route`에 `S`가 다시 보인다.
2. (7-02) PC0에서 `ping 192.168.30.1`을 실행한다. → 결과: 성공한다.
3. (7-03) 양쪽 라우터에서 `copy running-config startup-config`를 실행한다.
4. (7-04) 실습 전체를 되돌리려면 `04_정적라우팅.pkt`를 닫고 `03_라우터.pkt`를 다시 연다. 3일차 파일은 변경하지 않았다.
