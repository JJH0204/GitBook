## 📖 Cisco IOS CLI 기본 모드

| 모드 | 프롬프트 | 들어가는 명령 | 할 수 있는 일 |
|------|----------|---------------|----------------|
| 사용자 모드 | `Switch>` | (접속 시 기본) | 기본 확인만 |
| 특권 모드 | `Switch#` | `enable` | 모든 확인 명령 |
| 전역 설정 | `Switch(config)#` | `configure terminal` | 장비 설정 변경 |
| 인터페이스 설정 | `Switch(config-if)#` | `interface g0/0` | 특정 포트 설정 |

- 빠져나오기: `exit`(한 단계) / `end` 또는 `Ctrl+Z`(설정 모드 전체 종료)

> 💡 **프롬프트만 보면 지금 어디 있는지 알 수 있다.**
> `>` 구경만 / `#` 뭐든 확인 / `(config)#` 장비 전체 설정 / `(config-if)#` 이 포트 설정

## 📖 손이 편해지는 3가지 — 다 외우지 않아도 된다

초보자와 숙련자의 속도 차이는 대부분 여기서 난다.

| 기능 | 방법 | 예 |
|------|------|-----|
| **자동완성** | `Tab` | `conf` + `Tab` → `configure` |
| **축약** | 헷갈리지 않을 만큼만 치면 됨 | `conf t` = `configure terminal`<br>`sh ip int br` = `show ip interface brief` |
| **도움말** | `?` | `show ?` (뒤에 뭐가 오나)<br>`sh ip ro?` (ro로 시작하는 것) |

- **위·아래 방향키** = 이전에 친 명령 다시 부르기
- **`no` 를 앞에 붙이면 취소** — `shutdown`(끄기) ↔ `no shutdown`(켜기)가 그래서 그 이름이다
- 화면이 `--More--` 에서 멈추면 → `Space`(다음 쪽) / `Enter`(한 줄) / `q`(중단)

## ⚠️ 초보자가 반드시 겪는 3가지 함정

**① 오타를 쳤더니 30초 동안 멈춘다**

```
Router# shw ip route
Translating "shw"...domain server (255.255.255.255)
```

- 장비가 오타를 **호스트 이름으로 착각**해 DNS 조회를 시도하는 것이다
- `Ctrl + Shift + 6` 로 중단할 수 있지만, 아예 꺼두는 게 편하다

```
Router(config)# no ip domain-lookup
```

**② `% Invalid input detected at '^' marker.`**

- **`^` 표시가 가리키는 위치**가 틀린 지점이다. 그 자리부터 다시 보자
- 명령 자체는 맞는데 이 오류가 난다면 → **모드가 틀렸을** 가능성이 크다
  (`>` 에서 설정 명령을 쳤거나, `(config)#` 에서 `show` 를 쳤거나)

**③ 타이핑 중에 장비 메시지가 끼어들어 줄이 엉킨다**

```
Router(config)# line console 0
Router(config-line)# logging synchronous
```

- 메시지가 떠도 **내가 치던 줄을 아래에 다시 그려준다**

## 📖 설정을 저장하지 않으면 사라진다

시스코 장비에는 **설정 파일이 두 개** 있다. 이걸 모르면 애써 한 작업이 날아간다.

| 이름 | 어디 있나 | 특징 |
|------|-----------|------|
| **running-config** | 메모리(RAM) | **지금 동작 중인** 설정 · 전원 끄면 **사라짐** |
| **startup-config** | NVRAM | 켤 때 불러오는 설정 · **살아남음** |

```bash
show running-config          # 지금 설정
copy running-config startup-config    # 저장! (running → startup)
write memory                 # 위와 같은 뜻 (짧은 옛 명령)
show startup-config          # 저장된 설정 확인
```

> 🚨 **실무 사고 1순위**가 저장 누락이다. 설정을 바꿨으면 **습관적으로 `copy run start`**.
> (패킷트레이서 파일 자체는 별도로 `Ctrl+S`)

## 📖 장비를 만나면 가장 먼저 하는 기본 설정

CCNA 기초이자, 8일차 원격 접속의 밑바탕이 된다. → [1_원격접속_Telnet과SSH](../day-08/lesson-1.md)

```bash
enable
configure terminal
 hostname R1                  # 장비 이름 (프롬프트가 R1# 로 바뀜)
 no ip domain-lookup          # 오타 시 멈춤 방지
 enable secret cisco123       # 특권 모드 비밀번호 (암호화되어 저장)
 banner motd #접속 시 표시할 경고 문구#
 line console 0
  logging synchronous         # 메시지가 입력을 방해하지 않게
  password cisco              # 콘솔 접속 비밀번호
  login                       # 비밀번호를 실제로 물어보게 함
 end
copy running-config startup-config
```

- **`enable secret`** vs `enable password` → **secret 을 쓴다**(암호화 저장). password 는 설정 파일에 그대로 보인다
- 여러 대를 다룰 때 `hostname` 이 없으면 **어느 장비에 명령을 치는지 헷갈린다** → 실습에서 꼭 지정

## 📖 자주 쓰는 명령

```bash
enable                       # 특권 모드로
show mac address-table       # 스위치: 학습된 MAC 테이블
show ip route                # 라우터: 라우팅 테이블
show running-config          # 현재 설정 전체
show ip interface brief      # 인터페이스 IP·상태 요약
```

> 💡 3일차에는 라우터 인터페이스를 **`Config` 탭(GUI)** 으로 설정했다.
> 같은 일을 **명령어로** 하면 아래와 같다. 오늘부터는 이쪽을 쓴다.

```bash
enable
configure terminal
interface gigabitEthernet 0/0
 ip address 192.168.10.254 255.255.255.0
 no shutdown                 # = 3일차의 Port Status On (기본은 꺼짐!)
end
```

### 🧪 Lab 12. 정적 라우팅 — 라우터 2대로 세 네트워크 잇기 ⭐ 오늘의 핵심

라우터가 **직접 연결되지 않은** 네트워크로 보내려면 길을 알려줘야 한다.

**시작** — `03_라우터.pkt` 를 열고 **다른 이름으로 저장** → `04_정적라우팅.pkt`

Lab 11 의 구성에 **라우터를 한 대 끼워 넣는** 것이다. 완전히 새로 만들지 않는다.

```
[PC0]──[SW1]──[R1]────────[R2]──[SW2]──[PC2]
  192.168.10.0/24   20.0/24    192.168.30.0/24
                (R1·R2 연결 구간)
```

**① 배선 바꾸기**

1. R1 ↔ SW2 케이블을 **지우고**, 그 사이에 **R2** 를 넣는다
2. R1 ↔ R2 는 **크로스오버**(둘 다 라우터) · R2 ↔ SW2 는 **다이렉트** → [1_네트워크장비](../day-03/lesson-1.md)

**② 주소 고치기** — 3일차에서 **무엇이 바뀌는지** 보며 진행한다

| 장비 | 인터페이스 | IP | 게이트웨이 | 3일차 대비 |
|------|-----------|-----|-----------|-----------|
| PC0 | — | 192.168.10.1 /24 | 192.168.10.254 | 그대로 |
| R1 | G0/0 | 192.168.10.254 /24 | — | 그대로 |
| R1 | G0/1 | **192.168.20.1** /24 | — | `.254` → `.1` 로 변경 |
| R2 | G0/1 | **192.168.20.2** /24 | — | 새로 |
| R2 | G0/0 | **192.168.30.254** /24 | — | 새로 |
| PC2 | — | **192.168.30.1** /24 | **192.168.30.254** | 20.1 → 30.1 로 변경 |

> 💡 R2 설정은 **오늘 배운 CLI 로** 한다. 3일차의 `Config` 탭과 결과가 같다는 것을 확인시켜 줄 것.

**③ 먼저 실패를 본다**

1. 각 라우터에서 `show ip route` → **`C` 가 2개씩**만 보인다
   - R1 은 `30.0` 을 모르고, R2 는 `10.0` 을 모른다
2. PC0 → `ping 192.168.30.1` → **실패**. 어떤 메시지인가? ([3_ICMP와_ping](../day-03/lesson-3.md))

**④ 양쪽에 정적 경로를 넣는다** (한쪽만 넣으면 안 된다!)

```bash
R1(config)# ip route 192.168.30.0 255.255.255.0 192.168.20.2
```

```bash
R2(config)# ip route 192.168.10.0 255.255.255.0 192.168.20.1
```

**⑤ 확인하고 저장**

1. `show ip route` → **`S` 항목**이 생겼는지 확인
2. PC0 → `ping 192.168.30.1` → **성공!**
3. `copy running-config startup-config` 로 **양쪽 라우터 다** 저장
4. `Ctrl + S` → `04_정적라우팅.pkt`

**✅ 체크포인트**

- [ ] R1·R2 각각 `show ip route` 에 `C` 2개 + `S` 1개
- [ ] PC0 → PC2 ping 성공
- [ ] **일부러 한쪽을 지워보기**: R2 에서 `no ip route 192.168.10.0 255.255.255.0 192.168.20.1`
  → ping 이 다시 실패한다 → **"라우팅은 왕복"** 을 몸으로 확인 (확인 후 되돌리기)

## ⚠️ 실습 중 막히면 — 라우팅·CLI 편

> 케이블 · 링크 점 색깔 · `Port Status` 같은 **패킷트레이서 조작 문제**는 3일차 표를 본다
> → [3일차 · 자주 나는 오류](../day-03/lesson-4.md)

| 증상 | 확인할 것 |
|------|----------|
| 인터페이스에 IP 를 줬는데 `C` 가 안 생김 | `no shutdown` 했나? → `show ip interface brief` 가 `up/up` 인가 |
| 게이트웨이까지는 되는데 그 너머가 안 됨 | 라우터에 **정적 경로**를 넣었나 |
| 한 방향만 되는 것 같다 | **반대쪽 라우터**에도 경로를 넣었나 |
| `Destination host unreachable` | 경로가 없다 → `show ip route` 확인 |
| `Request timed out` | 경로는 있는데 답이 안 온다 → **돌아오는 경로** 확인 |
| 명령을 쳤는데 멈춰 있다 | 오타 → DNS 조회 중 (`Ctrl+Shift+6`, `no ip domain-lookup`) |
| 껐다 켜니 설정이 사라졌다 | `copy running-config startup-config` 안 함 |

**✅ 체크포인트** — `C` 항목이 **2개** 보이는가? (인터페이스 2개에 IP를 줬으므로)
`show ip interface brief` 에서 둘 다 `up/up` 인가?

**C. 정적 라우팅 — 라우터 2대로 세 네트워크 잇기 ⭐ 오늘의 핵심**

라우터가 **직접 연결되지 않은** 네트워크로 보내려면 길을 알려줘야 한다.

**구성**

```
[PC0]──[SW]──[R1]────────[R2]──[SW]──[PC1]
192.168.10.0/24    192.168.20.0/24    192.168.30.0/24
                (R1·R2 사이 연결 구간)
```

| 장비 | 인터페이스 | IP | 게이트웨이 |
|------|-----------|-----|-----------|
| PC0 | — | 192.168.10.1 /24 | 192.168.10.254 |
| R1 | G0/0 | 192.168.10.254 /24 | — |
| R1 | G0/1 | 192.168.20.1 /24 | — |
| R2 | G0/1 | 192.168.20.2 /24 | — |
| R2 | G0/0 | 192.168.30.254 /24 | — |
| PC1 | — | 192.168.30.1 /24 | 192.168.30.254 |

> ⚠️ R1 ↔ R2 직접 연결은 **크로스오버 케이블** (둘 다 라우터) → [1_네트워크장비](../day-03/lesson-1.md)

**단계**

1. 두 라우터의 인터페이스에 IP 설정 + `no shutdown`
2. 각 라우터에서 `show ip route` → **`C` 가 2개씩**만 보인다
   - R1은 `30.0` 을 모르고, R2는 `10.0` 을 모른다 → **이대로는 PC0 ↔ PC1 ping 실패**
3. 먼저 실패를 확인해본다: PC0 → `ping 192.168.30.1` → 어떤 메시지? ([3_ICMP와_ping](../day-03/lesson-3.md))
4. **양쪽에 정적 경로를 넣는다** (한쪽만 넣으면 안 된다!)

```bash
R1(config)# ip route 192.168.30.0 255.255.255.0 192.168.20.2
```

```bash
R2(config)# ip route 192.168.10.0 255.255.255.0 192.168.20.1
```

5. `show ip route` → **`S` 항목**이 생겼는지 확인
6. PC0 → `ping 192.168.30.1` → **성공!**
7. `copy running-config startup-config` 로 양쪽 다 저장

**✅ 체크포인트**

- [ ] R1·R2 각각 `show ip route` 에 `C` 2개 + `S` 1개
- [ ] PC0 → PC1 ping 성공
- [ ] **일부러 한쪽을 지워보기**: R2에서 `no ip route 192.168.10.0 255.255.255.0 192.168.20.1`
  → ping이 다시 실패한다 → **"라우팅은 왕복"** 을 몸으로 확인 (확인 후 되돌리기)

| 인터페이스에 IP를 줬는데 `C` 가 안 생김 | `no shutdown` 했나? → `show ip interface brief` 가 `up/up` 인가 |
| 게이트웨이까지는 되는데 그 너머가 안 됨 | 라우터에 **정적 경로**를 넣었나 |
| 한 방향만 되는 것 같다 | **반대쪽 라우터**에도 경로를 넣었나 |
| `Destination host unreachable` | 경로가 없다 → `show ip route` 확인 |
| `Request timed out` | 경로는 있는데 답이 안 온다 → **돌아오는 경로** 확인 |
| 명령을 쳤는데 멈춰 있다 | 오타 → DNS 조회 중 (`Ctrl+Shift+6`, `no ip domain-lookup`) |
| 껐다 켜니 설정이 사라졌다 | `copy running-config startup-config` 안 함 |

## 📝 강의 메모

- 모드 이동(`enable` → `configure terminal` → `interface`)을 손에 익히도록 반복
- **Tab · `?` · 축약을 첫 10분에** 알려줄 것 — 이걸 모르면 학생이 타이핑에 지쳐 내용을 못 따라온다
- `no ip domain-lookup` 을 **실습 시작 전에 다 같이** 넣어두면 오타 사고가 줄어든다
- `show mac address-table`(2계층) vs `show ip route`(3계층)로 오늘의 두 주제를 마무리
- **Lab 12 가 오늘의 목표점**이다 → Lab 10·11 은 **각 10분** 안에 끝내고 시간을 몰아줄 것
- Lab 12 는 **새로 만들지 않고 3일차 파일을 확장**한다 → "무엇이 바뀌는지" 표를 보며 진행
- Lab 12 는 **먼저 실패를 보여주고** 정적 경로를 넣어 성공시키는 순서가 효과적
- "한쪽만 지워서 다시 실패시키기"까지 해봐야 **왕복** 개념이 남는다
