## Q1. 무엇을 나누는 장비인가 — [1_네트워크장비](lesson-1.md)

Which device is used to **separate broadcast domains**?
(브로드캐스트 도메인을 나누는 장비는?)

- A. Hub (허브)
- B. Switch (스위치)
- C. Router (라우터)
- D. Repeater (리피터)

{% hint style="success" %}
**정답 및 해설**

**정답: C**
- **라우터**는 브로드캐스트를 **차단**한다 → 인터페이스마다 브로드캐스트 도메인이 나뉜다
- B(스위치)는 **충돌** 도메인을 나눌 뿐, 브로드캐스트는 **그대로 통과**시킨다 → 흔한 함정
- A(허브)·D(리피터)는 1계층이라 아무것도 나누지 못한다 (오히려 전부 한 덩어리)
- 되짚기: **"스위치는 충돌을, 라우터는 브로드캐스트를 끊는다"** → [1_네트워크장비](lesson-1.md)
- 브로드캐스트 도메인을 나누는 또 다른 방법 = **VLAN** (4일차 이후 예고)
{% endhint %}

## Q2. 프레임의 목적지 MAC — [2_MAC주소와_ARP](lesson-2.md)

PC1 (`192.168.10.1/24`) sends data to PC2 (`192.168.20.5/24`) through a router.
What is the **destination MAC address** of the frame **leaving PC1**?
(PC1이 라우터 너머의 PC2로 보낼 때, PC1에서 나가는 프레임의 목적지 MAC은?)

- A. PC2의 MAC
- B. 라우터 인터페이스(기본 게이트웨이)의 MAC
- C. `FF:FF:FF:FF:FF:FF`
- D. PC1 자신의 MAC

{% hint style="success" %}
**정답 및 해설**

**정답: B**
- PC1은 마스크로 판단한다 → "20.5는 **내 동네가 아니다**" → 그럼 **대문(게이트웨이)** 으로 보낸다
- 그래서 ARP로 찾는 것도 **게이트웨이의 MAC**이다 (PC2의 MAC은 알 수도 없다 — 브로드캐스트가 라우터를 못 넘으니까)
- **목적지 IP는 그대로 `192.168.20.5`**, 목적지 MAC만 라우터 → **IP는 끝까지, MAC은 구간마다**
- C는 ARP **요청**을 보낼 때의 목적지 MAC이지 데이터 프레임이 아니다
- 되짚기: Lab 7 의 `arp -a` 에 PC2가 아니라 **게이트웨이**가 찍혔던 것 → [4_패킷트레이서_실습](lesson-4.md)
{% endhint %}

## Q3. 케이블 고르기 — [1_네트워크장비](lesson-1.md)

Which cable is required to connect a **PC directly to a router's Ethernet port**?
(PC를 라우터의 이더넷 포트에 **직접** 연결할 때 필요한 케이블은?)

- A. Straight-through (다이렉트)
- B. Crossover (크로스오버)
- C. Console (콘솔)
- D. Serial (시리얼)

{% hint style="success" %}
**정답 및 해설**

**정답: B**
- PC와 라우터는 **같은 그룹**(끝단에서 말하는 쪽)이다 → 같은 그룹끼리는 **크로스오버**
- A(다이렉트)는 **다른 그룹**끼리 — PC↔스위치, 스위치↔라우터
- C(콘솔)는 통신용이 아니라 장비를 **설정**하러 접속할 때
- D(시리얼)는 라우터끼리 **WAN** 연결 (5일차)
- 되짚기: `그룹 A = PC·라우터 / 그룹 B = 허브·스위치` → **같은 그룹 = 크로스** → [1_네트워크장비](lesson-1.md)
- 실무 장비는 Auto-MDIX로 알아서 되지만, **패킷트레이서에서는 구분한다**
{% endhint %}

## Q4. 어디가 문제일까 — [3_ICMP와_ping](lesson-3.md)

A PC cannot reach the Internet.
`ping 127.0.0.1` → **success**, `ping <own IP>` → **success**, `ping <default gateway>` → **fails**.
Where is the problem **most likely** located?
(루프백·내 IP는 되는데 게이트웨이 ping이 실패한다. 문제는 어디에 있을까?)

- A. DNS 설정
- B. 랜선·스위치 또는 게이트웨이 주소·서브넷 마스크
- C. 내 PC의 랜카드
- D. 인터넷 회선(ISP)

{% hint style="success" %}
**정답 및 해설**

**정답: B**
- 5단계 중 **③에서 처음 실패** → 원인은 "나"와 "대문" **사이**에 있다
- 랜선 빠짐 / 스위치 문제 / **게이트웨이 주소 오타** / 마스크를 잘못 줘서 게이트웨이가 다른 동네가 된 경우
- C가 오답인 이유: ②(내 IP ping)가 성공했으므로 **내 랜카드·IP 설정은 정상**
- A·D는 더 바깥 단계(④·⑤)라 아직 판단할 수 없다 — ③을 못 넘었으니
- 되짚기: **처음 실패하는 곳이 곧 원인의 위치** → [3_ICMP와_ping](lesson-3.md)의 5단계
{% endhint %}

## Q5. 도메인 세기 — [1_네트워크장비](lesson-1.md)

24 PCs are connected to a single **24-port switch**.
How many **collision domains** and **broadcast domains** exist?
(24포트 스위치 1대에 PC 24대를 연결했다. 충돌 도메인과 브로드캐스트 도메인은 각각 몇 개?)

- A. 충돌 1 / 브로드캐스트 1
- B. 충돌 24 / 브로드캐스트 1
- C. 충돌 1 / 브로드캐스트 24
- D. 충돌 24 / 브로드캐스트 24

{% hint style="success" %}
**정답 및 해설**

**정답: B**
- 스위치는 **포트마다 충돌 도메인을 분리**한다 → 24포트 = **24개**
- 하지만 브로드캐스트는 **전부 통과**시킨다 → 스위치 1대 = 브로드캐스트 도메인 **1개**
- A는 **허브** 24포트일 때의 답 (전부 한 덩어리라 충돌이 잦다)
- D처럼 되려면 **라우터**로 24개를 나눠야 한다 (현실적으로는 VLAN)
- 되짚기: 이 1개의 브로드캐스트 도메인이 너무 커서 **2일차에 서브넷팅**을 배운 것
{% endhint %}
