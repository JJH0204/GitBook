## 🌉 다리 놓기: "라우터는 그 경로를 어떻게 알까?"

3일차에 "라우터는 **IP를 보고 다른 네트워크로 경로 결정**"이라고 했다. → [1_네트워크장비](../day-03/lesson-1.md)
스위치가 MAC 테이블을 만들 듯, 라우터는 **라우팅 테이블**로 판단한다.

## 📖 라우팅 테이블 = "목적지 네트워크 → 어디로 보낼지"

| 목적지 네트워크 | 나가는 방법 |
|-----------------|-------------|
| 192.168.10.0/24 | 직접 연결(인터페이스 G0/0) |
| 192.168.20.0/24 | 직접 연결(인터페이스 G0/1) |
| 10.0.0.0/8 | 다음 홉 192.168.10.254 로 |
| 0.0.0.0/0 (그 외 전부) | 디폴트 라우트 → ISP 쪽으로 |

- 라우터는 패킷의 **목적지 IP**를 테이블과 비교해 내보낼 인터페이스/다음 홉을 고른다
- 2일차에서 IP를 **네트워크 단위로 나눈 것**이 여기서 판단 기준이 된다 → [4_서브넷팅](../day-02/lesson-4.md)

### 여러 경로가 맞으면? — 가장 구체적인 것 (Longest Prefix Match)

> ❓ 목적지가 `172.16.5.10` 이고 테이블에 아래 셋이 다 있다면?

| 경로 | 맞는가? | 얼마나 구체적? |
|------|--------|---------------|
| `0.0.0.0/0` | ✅ | 0비트 (아무거나) |
| `172.16.0.0/16` | ✅ | 16비트 |
| `172.16.5.0/24` | ✅ | **24비트 ← 선택!** |

- **마스크가 긴(= 숫자가 큰) 쪽이 이긴다.** "더 자세히 아는 사람 말을 듣는다"
- 비유: `서울시`보다 `서울시 강남구 역삼동`이 배달에 더 유용하다
- 그래서 `0.0.0.0/0`(디폴트)은 **아무것도 안 맞을 때만** 쓰인다 — 가장 덜 구체적이니까

## 📖 `show ip route` 읽는 법

실습에서 바로 마주치는 화면이다. **왼쪽 글자 하나**가 경로의 출신을 말해준다.

```
R1# show ip route

Codes: C - connected, L - local, S - static,
       R - RIP, O - OSPF, D - EIGRP

     192.168.10.0/24 is directly connected, GigabitEthernet0/0
C       192.168.10.0/24 is directly connected, GigabitEthernet0/0
L       192.168.10.254/32 is directly connected, GigabitEthernet0/0
S       192.168.30.0/24 [1/0] via 192.168.20.2
S*   0.0.0.0/0 [1/0] via 203.0.113.1
```

| 코드 | 뜻 | 어떻게 생겼나 |
|------|-----|--------------|
| **C** | Connected — 직접 연결된 네트워크 | 인터페이스에 IP를 주면 **자동** |
| **L** | Local — 그 인터페이스 **자신의 주소**(`/32`) | 자동 |
| **S** | Static — 관리자가 넣은 경로 | 수동 |
| **S\*** | 디폴트 라우트 | 수동 (`*` = 기본 경로 표시) |
| **R / O / D** | RIP / OSPF / EIGRP 가 알려준 경로 | **5일차** |

### `[1/0]` 이건 뭔가요 — AD / 메트릭

```
S    192.168.30.0/24 [1/0] via 192.168.20.2
                      ↑ ↑        ↑
                      │ │        └ 다음 홉 (이리로 넘겨라)
                      │ └ 메트릭 : 같은 방식끼리 비교할 때의 거리
                      └ AD      : 서로 다른 방식끼리 비교할 때의 신뢰도
```

**AD(Administrative Distance) = 정보의 신뢰도, 낮을수록 신뢰**

| 출처 | AD |
|------|-----|
| 직접 연결 (C) | **0** |
| 정적 (S) | **1** |
| EIGRP | 90 |
| OSPF | 110 |
| RIP | 120 |

- 같은 목적지를 **두 방식이 서로 다르게** 알려주면 → **AD가 낮은 쪽**을 테이블에 올린다
- "내 눈으로 본 것(0) > 관리자가 알려준 것(1) > 남이 전해준 것(90~120)"
- 이 개념이 **6일차 재분배**의 핵심이 된다 → [6일차](../day-06/README.md)

## 📖 경로가 테이블에 들어오는 3가지 방법

| 종류 | 방법 | 특징 |
|------|------|------|
| **직접 연결(Connected)** | 인터페이스에 IP 설정하면 자동 등록 | 바로 붙은 네트워크 |
| **정적(Static)** | 관리자가 수동으로 입력 | 작은 망, 정확하지만 손이 감 |
| **동적(Dynamic)** | 라우터끼리 정보 교환(프로토콜) | 큰 망, 자동 갱신 → **5일차** |

- 동적 라우팅(RIP/OSPF/EIGRP)은 다음 시간 → [5일차 · 라우팅 프로토콜](../day-05/README.md)

### 정적 경로 넣기 — 명령은 딱 한 줄

```
ip route <목적지 네트워크> <서브넷 마스크> <다음 홉 주소>
```

**예시**: `192.168.30.0/24` 로 가려면 `192.168.20.2` 에게 넘겨라

```
R1(config)# ip route 192.168.30.0 255.255.255.0 192.168.20.2
```

- **"어디로 가려면 / 누구에게 넘겨라"** 두 부분이 전부다
- 다음 홉은 **바로 옆 라우터의 인터페이스 주소** — 멀리 있는 주소를 적으면 안 된다
- 지울 때는 앞에 `no` 를 붙인다

```
R1(config)# no ip route 192.168.30.0 255.255.255.0 192.168.20.2
```

> ⚠️ **라우팅은 왕복이다.** 가는 길만 넣으면 요청은 가지만 **답이 못 돌아온다.**
> 양쪽 라우터에 **서로를 향한 경로를 각각** 넣어야 ping이 성공한다. 실습에서 가장 많이 막히는 지점.

## 📖 기본 게이트웨이 / 디폴트 라우트

- **기본 게이트웨이**: PC가 "내 네트워크 밖으로 나갈 때 맡기는" 라우터 주소 (3일차 실습에서 설정했던 것! [4_패킷트레이서_실습](../day-03/lesson-4.md))
- **디폴트 라우트(0.0.0.0/0)**: 라우팅 테이블에 명시된 경로가 없을 때 "일단 이리로" 보내는 길

```
R1(config)# ip route 0.0.0.0 0.0.0.0 203.0.113.1
```

- `0.0.0.0 0.0.0.0` = **"어떤 주소든"** → 마스크가 0비트라 Longest Prefix Match에서 **항상 꼴찌**
- 그래서 다른 경로가 있으면 그쪽이 이기고, **아무것도 없을 때만** 이 길로 간다
- 인터넷 방향(ISP)으로 나갈 때 쓴다 — 전 세계 주소를 다 적을 수는 없으니까

> 💡 비유: 우체국(라우터)이 **행선지별 분류표(라우팅 테이블)**를 보고 다음 우체국으로 넘긴다. 모르는 주소는 **중앙 우체국(디폴트 라우트)**으로.

## 📖 경로가 없으면 어떻게 되나 — 버린다

라우터는 모르는 주소를 **추측하지 않는다.**

```
① 목적지 IP 를 테이블과 비교
② 맞는 경로가 하나도 없다 (디폴트도 없다)
③ 패킷을 버린다(drop)
④ 보낸 쪽에 ICMP "Destination unreachable" 을 돌려준다
```

- 3일차에 본 **`Destination host unreachable`** 메시지의 정체가 이것이다 → [3_ICMP와_ping](../day-03/lesson-3.md)
- 즉 그 메시지는 **"내가 그 동네로 가는 길을 모른다"** 는 라우터의 대답이다

### 라우터가 패킷을 처리하는 순서

3일차의 **"MAC은 바뀌고 IP는 그대로"** 가 라우터 안에서 실제로 일어나는 모습이다.

```
① 도착한 프레임의 껍데기(2계층 MAC)를 벗긴다
② 안에 있는 패킷의 목적지 IP 를 본다
③ 라우팅 테이블 조회 → 나갈 인터페이스 / 다음 홉 결정
④ TTL 을 1 줄인다   (0 이 되면 버리고 "TTL expired" 회신)
⑤ 다음 구간용 MAC 으로 새 껍데기를 씌워 내보낸다
```

- ④ 덕분에 **traceroute** 가 동작하고, 루프에 빠진 패킷도 언젠가 사라진다
- ⑤에서 다음 홉의 MAC 을 모르면? → **라우터도 ARP를 한다** ([2_MAC주소와_ARP](../day-03/lesson-2.md))

## 📝 강의 메모

- 스위치=MAC 테이블(2계층) ↔ 라우터=라우팅 테이블(3계층) 대비로 각인
- **`show ip route` 화면을 띄워놓고** 코드(C/L/S/S*)를 하나씩 짚기 → 실습에서 매번 보게 될 화면
- `[AD/메트릭]` 은 **AD만** 확실히. 메트릭은 5일차에 프로토콜별로 다시 나온다
- **"라우팅은 왕복"** 을 반복 강조 → Lab 12 에서 가장 많이 막히는 지점
- `Destination host unreachable` 이 3일차에서 넘어온 회수 지점 → 그때 그 메시지를 다시 띄워 보여주기
- 동적 라우팅은 "자동으로 표를 채워준다"는 것만 예고, 상세는 5일차
