## 🧪 오늘의 실습 환경 — ⚠️ **WSL + Docker Engine**(apt 공식 저장소)

```
   🪟 Windows  ──localhost──▶  🐧 WSL (Ubuntu 24.04)
                                 ├─ nginx            : 80      ← 13일차에 세운 것 (그대로 둔다)
                                 └─ Docker Engine (29.x)
                                      ├─ web  : 8080 → 80      (내 포트폴리오)
                                      └─ db   : 포트 없음        (Compose 내부에서만)
```

> 📌 **Docker Desktop 을 쓰지 않는다.** 12일차부터 쓰던 **WSL 안에** Docker Engine 을 직접 설치한다 —
> 리눅스 서버에서 하는 모습 그대로이고, 12 · 13일차 환경(사용자 · SSH 키 · 저장소)을 그대로 쓸 수 있다.
> ⚠️ **13일차 nginx 가 80번을 쓰고 있다.** 컨테이너는 **8080** 으로 띄워 **포트 충돌**을 직접 보고 피한다.

### 🚨 수업 시작 전 점검 — 세 줄

```bash
ps -p 1 -o comm=                   # systemd 여야 한다 (아니면 /etc/wsl.conf 에 [boot] systemd=true)
ip route get 1.1.1.1 | head -1     # ⭐ src 뒤가 내 WSL 주소 — 오늘 검증에 쓴다
sudo ufw status numbered           # 22 · 80 (3번 절 대조 실험의 출발점)
```

### WSL 모드에 따른 차이 — 오늘은 **`curl` 로 통일**한다

| | NAT (`172.x`, 기본) | mirrored (`192.168.x`) |
|---|---|---|
| 🪟 `http://localhost:8080` (`-p 8080:80`) | ✅ | ✅ |
| 🙋 옆자리에서 | ❌ | ✅ |
| 🪟 `localhost:8080` (**`-p 127.0.0.1:8080:80`**) | ❌ 안 열린다 | **✅ 열릴 수 있다** ⚠️ |
| 🐧 `curl http://<내 IP>:8080` (**로컬 바인딩**) | ❌ refused | ❌ refused |

> 🚨 **mirrored 는 Windows 와 WSL 이 `127.0.0.1` 을 공유한다.** 그래서 "로컬에만 열었는데 Windows 에서 보이는" 것이 **정상**이다.
> 👉 **검증 기준은 `curl http://<내 IP>:8080`** — 두 모드에서 같은 결과가 나온다.

> 💾 **Docker 설치 전에** 🪟 `wsl --shutdown` 후 **WSL 백업**을 떠 두면 마음이 편하다
> `wsl --export Ubuntu D:\wsl-backup.tar` · 되돌릴 땐 `wsl --import`

## 🔎 자료 조사로 확인한 것 (2026-10-17 · 직접 실행 아님)

> 📌 교실 PC 에서 실행 검증은 **아직 안 했다.** 아래는 공식 문서 · 릴리스 노트 기준으로 맞춘 내용이다.

1. **설치 방식을 공식 저장소(apt)로 바꿨다** — 종전 대본의 `get.docker.com` 스크립트 대신.
   현재 Docker 공식 문서는 키를 `/etc/apt/keyrings/docker.asc` 에 두고 **`/etc/apt/sources.list.d/docker.sources`(deb822 형식)** 를 쓴다.
   패키지는 `docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin` — **Compose 는 이 플러그인에 포함**이라 따로 설치하지 않는다.
   지원 목록에 **Ubuntu 24.04(noble)** 가 있다. 🛑 `docker.io` · snap 은 쓰지 않는다
2. **버전** — Docker Engine 최신은 **29.x 계열**(2026-10 기준 29.9.1). 수업에서 `docker --version` 이 **29.x** 로 나오는 것이 정상이다
3. 🚨 **`ufw` 우회는 여전히 사실이고, 설계상 그렇다** — Docker 문서가 공개 포트의 트래픽이 **방화벽 규칙이 적용되기 전에 라우팅**된다고 명시한다.
   제대로 막는 자리는 **`DOCKER-USER` 체인**이고, 입문 단계의 답은 **`-p 127.0.0.1:…`** 또는 **`-p` 를 안 쓰는 것**(6번 절)
4. 🚨 **종전 노트의 오류를 고쳤다** — "`127.0.0.1` 바인딩 데모는 NAT · mirrored 둘 다 성립한다" 는 **틀렸다**.
   mirrored 모드는 **Windows 와 WSL 이 `127.0.0.1` 을 공유**한다(마이크로소프트 문서) → Windows 브라우저에서 **열린다**.
   👉 검증을 **`curl http://<내 IP>:8080`** 로 바꿨다 (두 모드 공통)
5. **MariaDB 이미지** — `MARIADB_ROOT_PASSWORD` 는 **필수**(없으면 컨테이너가 죽는다) · 클라이언트 명령은 **`mariadb`**(최근 이미지에서 `mysql` 이름 제거) · 초기화 중에는 접속이 안 되므로 **`ready for connections` 대기**가 필요
6. **Compose 파일에 `version:` 을 쓰지 않는다** — v2 에서 무의미해져 `version is obsolete` 경고만 난다. 파일명은 `compose.yaml`
7. ⚠️ **남은 미검증(교실 PC 에서 확인할 것)**
   - `apt` 설치 후 **데몬 기동** — WSL 에서 `systemctl is-active docker` 가 active 인지 (실패 시 `journalctl -u docker` · `ip_forward` 확인)
   - **ufw 대조 실험의 실제 결과** — 호스트 8000 이 막히고 컨테이너 8080 이 열리는지 (특히 mirrored 모드 PC)
   - `docker build` · `compose up` 실행, 옆자리 저장소 `clone` → 빌드
   - 📌 이번 준비에서 **명령 실행 검증은 하지 않았다**(자료 조사로 대체). 교실 전날 리허설을 권한다
