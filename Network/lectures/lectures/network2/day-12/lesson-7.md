# 7. Proxy 서버 (squid) — 대신 다녀오고, 기억하고, 막는다

> 상위: [12일차 · 리눅스 서버 구축](README.md)

> 🅿️ **12일차에는 다루지 않는다** (4시간 제약) → **13일차**로 넘겼다. 노트는 그대로 두니 미리 읽어 와도 좋다.

## 🎯 학습 목표

- **프록시**가 클라이언트를 **대신해** 요청하는 서버임을 설명한다
- **포워드 프록시**와 **리버스 프록시**를 구분한다
- **squid** 를 설치해 **캐시 동작(TCP_MISS → TCP_HIT)** 과 **사이트 차단**을 확인한다
- 프록시와 **NAT**의 차이를 **계층**으로 설명한다 ⭐

## 📖 ① 프록시 — 대신 다녀오는 심부름꾼

```
 [ 사내 PC ] ──"example.com 주세요"──▶ [ Proxy 3128 ] ──실제 요청──▶ [ 인터넷 ]
             ◀────── 받아다 준다 ──────               ◀── 응답 ──
                                         └ 기억해 둔다(캐시) · 기록한다(로그) · 막는다(필터)
```

| 얻는 것 | 설명 |
|---------|------|
| **캐시** | 같은 걸 또 요청하면 **밖에 안 나가고** 바로 준다 → 빠르고 회선을 아낀다 |
| **필터링** | 특정 사이트 · 카테고리 **차단** |
| **로그 · 감사** | 누가 · 언제 · 어디에 갔는지 남는다 |
| **익명성** | 상대 서버에는 **프록시 IP** 만 보인다 |

### 포워드 vs 리버스 ⭐

| | **포워드 프록시** | **리버스 프록시** |
|---|---|---|
| 누구 편 | **클라이언트** 편 | **서버** 편 |
| 위치 | 사내망 출구 | **웹서버 앞** |
| 아는 사람 | 클라이언트가 **설정해서 쓴다** | 클라이언트는 **모른다** (그냥 웹서버인 줄) |
| 목적 | 캐시 · 차단 · 감사 | 부하 분산 · HTTPS 처리 · 보호 |
| 예 | **squid** (오늘) | **nginx** · CDN · 로드밸런서 · **Ingress** → 14 · 16일차 |

> 💡 **비유: 회사 우편실(포워드) vs 건물 안내데스크(리버스).**
> 우편실은 **직원이 맡긴** 편지를 대신 부친다. 안내데스크는 **찾아온 손님**을 받아 알맞은 사무실로 보낸다. 손님은 그게 안내데스크인지 모른다.
> 📌 **리버스 프록시**는 16일차에 **Ingress** 라는 이름으로 다시 나온다 → [16일차](../day-16/README.md)

## 📖 ② 구축 — 여섯 단계 그대로

### ① 설치 · ④ 확인

```bash
sudo apt install squid -y
systemctl status squid
sudo ss -tulnp | grep 3128          # 프록시 표준 포트 3128
```

### ⑥ 검증 — 프록시를 거쳐 나가 본다

```bash
curl -I http://example.com                                  # 직접 나가기
curl -I -x http://127.0.0.1:3128 http://example.com         # 프록시 경유 ⭐ (-x)
sudo tail -f /var/log/squid/access.log                      # 기록이 남는다
```

```
... TCP_MISS/200 ...   ← 처음: 캐시에 없어서 밖에 다녀왔다
... TCP_HIT/200 ...    ← 두 번째: 기억해 둔 걸 바로 줬다 ⭐
```

> 🗣 **"두 번째 요청은 인터넷에 나가지도 않았습니다. 이게 캐시입니다."**
> ⚠️ `TCP_HIT` 는 사이트가 **캐시를 허용할 때만** 뜬다. 안 뜨면 응답 헤더의 `Cache-Control` 때문 — **"캐시는 서버가 허락해야 한다"** 는 좋은 설명 거리다.

### ② 설정 — 차단 규칙 만들기 ⭐

```bash
sudo cp /etc/squid/squid.conf /etc/squid/squid.conf.bak
sudo nano /etc/squid/squid.conf
```

```
acl blocked_sites dstdomain .example.com
http_access deny blocked_sites
```

```bash
sudo systemctl restart squid
curl -I -x http://127.0.0.1:3128 http://example.com     # 403 Forbidden ⭐
```

> 🗣 **"`acl` — 낯익죠? 11일차 라우터에서 쓴 그 단어입니다. `순서대로 읽고, 처음 맞는 규칙을 적용한다`는 원리까지 똑같습니다."**
> → [11일차 ACL](../day-11/README.md). 다만 **라우터 ACL 은 IP · 포트**로, **프록시 ACL 은 도메인 · URL** 로 막는다 — **계층이 다르다**

| 설정 | 뜻 |
|------|----|
| `acl localnet src 192.168.0.0/24` | **누가** 쓸 수 있나 (출발지) |
| `acl blocked_sites dstdomain .example.com` | **어디를** 막나 (목적지 도메인) |
| `http_access allow localnet` | 허용 |
| `http_access deny blocked_sites` | 차단 — **위에서부터 순서대로** |
| `http_port 3128` | 듣는 포트 |

### 클라이언트에 프록시를 설정한다는 것

| 어디 | 방법 |
|------|------|
| 리눅스 명령줄 | `export http_proxy=http://192.168.x.x:3128` (그 창에서만) |
| `curl` | `-x http://...:3128` |
| 브라우저 · 윈도우 | 설정 → 네트워크 → **프록시 서버** 칸 |

> ⚠️ **HTTPS 는 프록시가 내용을 볼 수 없다**(암호화). 그래서 `CONNECT` 로 **터널만** 뚫어주고, 도메인 이름 정도만 안다.
> 회사가 HTTPS 내용까지 보려면 **SSL 가로채기(인증서 설치)** 가 필요하다 — 프라이버시 논쟁이 여기서 시작된다

## 📖 ③ 프록시 vs NAT — 계층으로 구분한다 ⭐

| | **NAT** (10일차) | **프록시** (오늘) |
|---|---|---|
| 계층 | **3 · 4계층** (IP · 포트) | **7계층** (HTTP 등 **응용**) |
| 하는 일 | 주소 **바꿔치기** | 요청을 **대신 수행** |
| 클라이언트 설정 | **필요 없다** (모르고 지나간다) | **프록시 주소를 넣어야** 한다 (포워드) |
| 볼 수 있는 것 | IP · 포트 | **URL · 도메인 · 내용** |
| 캐시 | 못 한다 | **한다** |

> 🗣 **"'사내에서 유튜브만 막아 주세요' — NAT 로 될까요? 유튜브 IP 를 전부 알아야 하고 매일 바뀝니다. 그래서 프록시(또는 7계층 방화벽)를 씁니다."**
