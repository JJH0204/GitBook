# 8. 포트 번호와 소켓 — IP 는 건물, 포트는 호실

> 상위: [10일차 · 서버 기초](README.md)

## 🎯 학습 목표

- **포트 번호**가 "한 컴퓨터 안의 **어느 프로그램**" 을 가리킨다는 것을 안다
- 포트 범위(**Well-known · Registered · Dynamic**)를 구분한다
- 주요 서비스의 **포트 번호 + TCP/UDP** 를 짝지어 외운다
- **소켓 = IP + 포트** 를 이해하고, 한 서버가 여러 손님을 **동시에** 구분하는 원리를 안다

## 🌉 다리 놓기: "한 서버에 서비스가 여럿이면?"

[6_서버란_무엇인가](lesson-6.md) 에서 한 서버에 **sshd · DNS · 웹서버** 가 동시에 떠 있었다. IP 는 **`192.168.0.42` 하나**다.
요청 패킷이 `192.168.0.42` 에 도착했다. **SSH 에게 줄까, 웹서버에게 줄까?**
→ IP 는 **컴퓨터까지**만 데려다준다. 그 안의 **프로그램**을 고르는 번호가 필요하다 = **포트**

---

## 📖 ① 포트 — 건물 안의 호실 번호

```
            IP 192.168.0.42 (건물 주소)
 ┌────────────────────────────────────────┐
 │  22호  sshd        (SSH)               │
 │  53호  systemd-resolved (DNS 도우미)    │
 │  80호  (비어 있음 — 웹서버 없음)          │
 │  8080호 python3 http.server (오늘 만든 것) │
 └────────────────────────────────────────┘
      패킷: "192.168.0.42 의 8080호로 배달"
```

> 💡 **비유: IP = 건물 주소, 포트 = 호실 번호.** 택배 기사(IP)는 건물까지 오고, **호실 번호(포트)** 를 보고 문 앞에 둔다.
> 그 호실에 **아무도 없으면**(LISTEN 없음) → 반송 = `Connection refused`

- 포트는 **0 ~ 65535** (16비트 = 2^16) — 1일차 비트 계산 회수
- 포트는 **TCP 따로 · UDP 따로** 있다 → `TCP 53` 과 `UDP 53` 은 **다른 문** (DNS 는 둘 다 연다)

---

## 📖 ② 포트 범위

| 범위 | 이름 | 누가 쓰나 | 예 |
|------|------|----------|----|
| **0 ~ 1023** | **Well-known** (잘 알려진) | 표준 서비스 · **열려면 root 권한** | 22 · 53 · 80 · 443 |
| 1024 ~ 49151 | Registered (등록된) | 특정 프로그램 | 3306 (MySQL) · 8080 (웹 대체) |
| 49152 ~ 65535 | **Dynamic** (동적 · 임시) | **클라이언트가 잠깐** 쓰는 번호 | 브라우저가 매번 랜덤으로 |

- 오늘 웹서버를 **80 이 아니라 8080** 에 띄운 이유 → **1023 이하는 root(sudo) 만** 열 수 있어서 (오전 권한 회수)
- 📌 리눅스에서 실제 임시 포트 범위는 `cat /proc/sys/net/ipv4/ip_local_port_range` → `32768 60999` (OS 마다 조금 다르다)

---

## 📖 ③ 외워둘 포트 — 8일차 표에 **TCP/UDP** 를 더한다 ⭐

| 포트 | 서비스 | 전송 | 기억법 |
|------|--------|------|--------|
| **20 / 21** | FTP (데이터 / 제어) | TCP | 20번대 **연속 3형제** 시작 |
| **22** | **SSH** | TCP | 9일차 접속 |
| **23** | Telnet | TCP | SSH 바로 옆 (평문 형) |
| **25** | SMTP (메일 보내기) | TCP | 12일차 |
| **53** | **DNS** | **UDP** (+TCP) | |
| **67 / 68** | **DHCP** (서버 / 클라이언트) | **UDP** | 8일차 |
| **80** | **HTTP** | TCP | |
| 110 / 143 | POP3 / IMAP (메일 받기) | TCP | 12일차 |
| **161 / 162** | SNMP / Trap | **UDP** | 8일차 |
| **443** | **HTTPS** | TCP (HTTP/3 는 UDP) | 80 의 암호화판 |
| 3306 | MySQL | TCP | 14일차 |
| 3389 | RDP (Windows 원격 데스크톱) | TCP | |

- 리눅스에는 이 표가 **파일로** 있다 → `cat /etc/services` (오전 "리눅스는 모든 게 파일" 회수)
- **UDP 인 것만 따로** 외우면 쉽다: **DNS 53 · DHCP 67/68 · SNMP 161/162** (+ TFTP 69 · NTP 123) — 나머지 대부분은 TCP

## 📖 ④ 소켓 — IP + 포트 = 대화의 주소

```
 내 PC 브라우저 탭 ①  192.168.0.10 : 51001 ──┐
 내 PC 브라우저 탭 ②  192.168.0.10 : 51002 ──┼──▶  서버 203.0.113.5 : 443
 옆자리 PC            192.168.0.11 : 51001 ──┘
```

- **소켓 (Socket)** = **IP + 포트** 한 쌍 (`203.0.113.5:443`)
- 연결 하나는 **4개의 값**으로 구분된다: **출발 IP · 출발 포트 · 도착 IP · 도착 포트**
- 그래서 서버는 **443 하나로** 수천 명을 동시에 상대해도 **헷갈리지 않는다** — 출발 쪽이 전부 다르니까

> 💡 **비유: 콜센터 대표번호.** 모두가 **같은 번호(443)** 로 걸지만, 콜센터는 **발신자 번호(출발 IP:포트)** 로 누가 누군지 구분한다.

```bash
ss -tn            # 지금 맺어진 TCP 연결 — Local(내 쪽) · Peer(상대 쪽) 소켓이 보인다
```

```
State  Recv-Q Send-Q  Local Address:Port  Peer Address:Port
ESTAB  0      0       192.168.0.42:22     192.168.0.7:50514   ← 내 SSH 연결 (창 ①)
ESTAB  0      0       192.168.0.42:22     192.168.0.7:50522   ← 창 ② — 서버 포트는 같고, 상대 포트가 다르다
```

> 🗣 **"창 3개로 같은 서버의 22번에 붙었는데 안 섞이는 이유 — 상대 포트가 다 달라서입니다."**
> 🔎 **상대 IP 가 바로 내 Windows 주소**다 (`ipconfig` 로 확인). **브릿지**라서 중간에 바뀌는 게 없다.
> 그럼 **인터넷에 나갈 때는** 주소가 바뀔까? → [9_NAT와_포트포워딩](lesson-9.md)

## 📝 강의 메모

- **건물 · 호실** 비유가 제일 잘 먹힌다 — 칠판 그림 하나로
- 포트표는 **8일차 칠판 번호순 표에 "UDP" 도장만** 찍는 방식으로 — 새로 외우는 게 아니라 **추가**
- **"UDP 인 것만 외워라"** 가 시험 팁 — 나머지는 TCP
- 소켓의 **상대 주소가 내 Windows IP** 와 같은 것을 확인시킨다 → **브릿지**의 의미가 한 번 더 굳는다
