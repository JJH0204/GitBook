# 4. ACL ① 표준 — 누가 왔는지만 보고 막는다

> 상위: [11일차 · 서버 보안](README.md)

## 🎯 학습 목표

- **ACL** 이 무엇이고, 라우터에서 **위에서부터 차례로** 검사된다는 것을 안다
- **암묵적 deny any** 때문에 `permit` 을 하나도 안 쓰면 전부 막힌다는 것을 설명한다
- **와일드카드 마스크**를 읽고 쓴다 (5일차 OSPF 회수)
- **표준 ACL** 을 만들고 `ip access-group` 으로 적용하며, **왜 목적지 가까이** 두는지 안다

## 🌉 다리 놓기: "그 명령, 오늘 아침에 이미 썼다"

[3_왜_막아야_하나](lesson-3.md) 에서 통제가 걸리는 세 자리를 봤다. 먼저 **① 네트워크 장비**부터 간다.

그런데 사실 우리는 **오늘 아침에 이미 ACL 을 썼다.** 공유기 속을 시스코 CLI 로 열어 본 [대본 부록 A](commands.md) 에서다.

```
access-list 1 permit 192.168.0.0 0.0.0.255      ← 이것
ip nat inside source list 1 interface g0/1 overload
```

그때 `access-list 1` 은 **"NAT 로 변환할 대상을 고르는 목록"** 이었다.
오늘은 **똑같은 문법**으로 **"통과시킬 대상을 고르는 목록"** 을 만든다.

> 🗣 **"ACL 은 그냥 「주소를 골라내는 목록」입니다. 그 목록을 NAT 에 쓰면 변환 대상이 되고, 인터페이스에 붙이면 검문소가 됩니다."**

## 📖 ① ACL 이란 — 라우터의 검문소

> 📌 **ACL (Access Control List, 접근 제어 목록)** = 라우터를 **지나가려는 패킷**을 조건에 따라 **허용(permit) / 거부(deny)** 하는 규칙 목록.

```
   들어오는 패킷
        │
        ▼
   ┌─────────────────────────┐
   │ 1번 줄 — 조건에 맞나?    │ ─ 맞다 ─▶ permit/deny 하고 【끝】
   │ 2번 줄 — 조건에 맞나?    │ ─ 맞다 ─▶ permit/deny 하고 【끝】
   │ 3번 줄 — 조건에 맞나?    │ ─ 맞다 ─▶ permit/deny 하고 【끝】
   │ (보이지 않는 마지막 줄)   │
   │   deny any  ←─────────── 아무것도 안 맞으면 여기 ⭐
   └─────────────────────────┘
```

| 성질 | 뜻 | 실수하면 |
|------|-----|---------|
| **위에서부터 순서대로** | 처음 맞는 줄에서 **검사가 끝난다** | 넓은 규칙을 위에 두면 아래 줄은 **영원히 안 읽힌다** |
| **암묵적 deny any** ⭐ | 목록 맨 끝에 **보이지 않는 "나머지 전부 거부"** 가 있다 | `deny` 만 써 놓으면 **전부 막힌다** |
| **인터페이스에 붙여야 동작** | 만들기만 해서는 아무 일도 안 난다 | `ip access-group` 을 빠뜨린다 |

> 💡 **비유: 아파트 정문 경비 명단.** 명단을 위에서부터 훑다가 **이름을 찾는 순간 그대로 처리**하고 더 안 본다.
> 그리고 명단 맨 아래에는 **눈에 안 보이는 글씨**로 **"명단에 없으면 돌려보냄"** 이 적혀 있다.

> ⚠️ **오늘 1번 함정** — `deny` 규칙만 하나 쓰고 끝내면 **그 외 전부도 막힌다.** 암묵적 deny any 때문이다.
> **막고 싶은 것을 `deny` 했으면, 나머지를 살릴 `permit any` 를 반드시 붙인다.**

### 번호로 종류가 갈린다

| 종류 | 번호 | 무엇을 보나 | 노트 |
|------|------|-------------|------|
| **표준 (Standard)** | **1~99** (1300~1999) | **출발지 IP 만** | 오늘 이 노트 |
| **확장 (Extended)** | **100~199** (2000~2699) | 출발지 + **목적지 + 프로토콜 + 포트** | [5_ACL_확장](lesson-5.md) |

## 📖 ② 와일드카드 마스크 — 5일차의 그것

ACL 은 **서브넷 마스크가 아니라 와일드카드 마스크**를 쓴다. 5일차 OSPF 의 `network` 명령에서 이미 만났다.

```
서브넷 마스크   255.255.255.0     1 = "이 자리는 같아야 한다"
와일드카드      0.  0.  0.255     0 = "이 자리는 같아야 한다"  ⭐ 반대!
                                255 = "이 자리는 아무래도 좋다"
```

> 💡 **"와일드카드는 서브넷 마스크를 뒤집은 것"** — `255 - 각 자리` 로 바로 구한다.

| 쓰고 싶은 범위 | 서브넷 마스크 | 와일드카드 | 줄여 쓰기 |
|----------------|---------------|-----------|-----------|
| `192.168.20.0` 대역 전체 (/24) | `255.255.255.0` | `0.0.0.255` | |
| `192.168.20.10` **한 대만** | `255.255.255.255` | `0.0.0.0` | **`host 192.168.20.10`** |
| **모든 주소** | — | `255.255.255.255` | **`any`** |

```
255.255.255.0
255.255.255.255  -  255.255.255.0  =  0.0.0.255     ← 이렇게 구한다
```

## 📖 ③ 표준 ACL — 만들고 붙이기

### 만들기

```
Router(config)# access-list 10 deny   host 192.168.20.10
Router(config)# access-list 10 permit any
                        │      │       └── 대상
                        │      └── permit / deny
                        └── 번호 (1~99 = 표준)
```

### 붙이기 — 인터페이스에 적용해야 산다

```
Router(config)# interface g0/0
Router(config-if)# ip access-group 10 out
                                   │   └── in  = 인터페이스로 들어올 때 검사
                                   │       out = 인터페이스에서 나갈 때 검사
                                   └── ACL 번호
```

> 💡 **in / out 은 「라우터 입장」에서 본다.** 패킷이 라우터 **안으로** 들어오면 `in`, 라우터 **밖으로** 나가면 `out`.

### 확인 · 삭제

```
Router# show access-lists              # 규칙 목록 + 몇 번 걸렸는지(match 수) ⭐
Router# show ip interface g0/0         # 어느 ACL 이 붙어 있나
Router(config)# no access-list 10      # 삭제 — 번호 전체가 통째로 지워진다 ⚠️
```

## 📖 ④ 어디에 붙이나 — 표준은 **목적지 가까이** ⭐

표준 ACL 은 **출발지만 본다.** 그래서 출발지 근처에 두면 **그 PC 가 어디로 가든 전부 막힌다.**

```
[PC_인사 .20.10]──┐                            ┌── 서버 192.168.10.100
                  ├──[SW2]──[R1]──[SW1]────────┤
[PC_개발 .20.11]──┘         g0/1    g0/0
                           .20.254  .10.254

❌ g0/1 in  에 붙이면  : 인사 PC 는 인터넷도 · 다른 어디도 못 간다 (과잉 차단)
✅ g0/0 out 에 붙이면  : 인사 PC 가 "서버망으로 갈 때만" 막힌다
```

| 종류 | 붙이는 위치 | 이유 |
|------|------------|------|
| **표준** | **목적지 가까이** | 출발지만 보므로, 멀리 두면 **다른 통신까지 죽는다** |
| **확장** | 출발지 가까이 | 목적지·포트까지 보므로 **일찍 버려도 안전**하다 → [5_ACL_확장](lesson-5.md) |

> 🗣 **"표준은 목적지 가까이, 확장은 출발지 가까이."** 오늘 외울 한 줄이다.

## 🧪 실습 — 인사팀 PC 만 서버망에서 막기

> 🖐 자세한 클릭 순서는 [대본 STEP 4](commands.md) 참고

### 구성

| 장비 | 주소 |
|------|------|
| R1 `g0/0` (서버망) | `192.168.10.254` |
| R1 `g0/1` (사용자망) | `192.168.20.254` |
| 서버 | `192.168.10.100` |
| PC_인사 | `192.168.20.10` |
| PC_개발 | `192.168.20.11` |

### 순서

1. **먼저 되는 것을 확인한다** — 두 PC 모두 서버로 `ping` 성공 ✅
2. ACL 작성
   ```
   access-list 10 deny host 192.168.20.10
   access-list 10 permit any
   ```
3. 적용
   ```
   interface g0/0
    ip access-group 10 out
   ```
4. **다시 확인** — PC_인사 ❌ 실패 · PC_개발 ✅ 성공
5. `show access-lists` 로 **match 숫자가 올라가는 것**을 본다 ⭐

> ⚠️ **2단계에서 `permit any` 를 일부러 빼고 한 번 해 볼 것.** 두 PC 모두 막힌다 → **암묵적 deny any 를 눈으로 보는 순간**이다.

## 🧪 실습 / 질문

- `access-list 10 permit any` 를 **맨 위**에 쓰면 어떻게 될까? 왜 그럴까?
- `192.168.20.0 0.0.0.255` 와 `host 192.168.20.10` 중 더 구체적인 것은? 어느 쪽을 위에 써야 하나?
- 표준 ACL 을 `g0/1 in` 에 붙였더니 인사팀이 인터넷도 못 쓴다. 왜일까?
- `show access-lists` 의 match 숫자가 **0** 이면 무엇을 의심해야 하나?

## 📝 강의 메모

- 🗣 도입은 **"오늘 아침 NAT 에서 쓴 `access-list 1`, 그게 오늘의 주인공입니다"** — 이미 쓴 명령이라는 안도감부터 준다
- ⭐ **암묵적 deny any 는 반드시 실패로 체험**시킨다. `permit any` 빼고 한 번 → 전부 끊김 → 이유 설명 → 추가 → 복구
- 와일드카드는 **5일차 OSPF `network ... 0.0.0.255`** 회수. "그때 그 숫자" 라고 짚어 줄 것
- `show access-lists` 의 **match 카운터**가 디버깅의 핵심 — "규칙이 걸리고 있나?"를 숫자로 본다
- ⚠️ PT 에서 `no access-list 10` 은 **10번 전체**를 지운다. 한 줄만 고치려면 메모장에 전체를 적고 다시 넣는 편이 빠르다
- ⏱ 이 절 20분 + 실습 20분. 시간이 모자라면 **실습 2~4 만** 하고 질문은 다음 절로 넘긴다
