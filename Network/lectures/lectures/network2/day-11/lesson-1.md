# 1. 공유기 실습 — 우리 집 네트워크를 패킷트레이서로

> 상위: [11일차 · 서버 보안](README.md) · 명령 대본은 [0_실습_명령어_모음](commands.md) STEP 1 · 2

## 🎯 학습 목표

- **집 공유기 = 라우터 + NAT + 스위치 + DHCP** 가 한 상자에 들어 있음을 설명한다
- 공유기(WRT300N)에 **WAN(공인) · LAN(사설) · DHCP** 를 설정한다
- PC 들이 **DHCP 로 사설 IP** 를 받고 인터넷(가상)에 나가는 것을 확인한다
- **Simulation 모드**에서 **NAT 가 출발지 IP 를 바꾸는 구간**을 찾는다 ⭐
- (선택) **포트포워딩**으로 집 안 서버를 밖에 공개한다

## 🌉 다리 놓기: "배운 걸 한 상자에"

10일차에 배운 **DHCP · DNS · NAT · 포트포워딩** 을 전부 해주는 장비가 **우리 집에 하나씩** 있다. **공유기**다.
8일차에는 이 기능들을 패킷트레이서의 **Server0 에서 체크박스로** 하나씩 켰다. 오늘은 **그것들이 한 상자에 합쳐진 물건**을 뜯어본다.

---

## 📖 ① 공유기의 정체 — 네 장비가 한 상자에 ⭐

```
            ┌───────────────── 집 공유기 (한 상자) ─────────────────┐
 인터넷 ────┤ WAN 포트 ─ [라우터 + NAT] ── [스위치] ─ LAN 포트 1~4 ─┼── 유선 PC
 (공인 IP)  │                                                      │
            │  + DHCP 서버 (192.168.0.100~) + DNS 중계 + 방화벽     │
            └──────────────────────────────────────────────────────┘
```

| 부품 | 하는 일 | 배운 날 |
|------|---------|---------|
| **라우터** | 집 안(사설) ↔ 인터넷(공인) **경계** | 4 · 5일차 |
| **NAT** | 사설 → 공인 **바꿔치기** · 포트포워딩 | **10일차** [9_NAT와_포트포워딩](../day-10/lesson-9.md) |
| **스위치** | 뒷면 LAN 포트 4개 | 3 · 4일차 |
| **DHCP 서버** | 집 안 기기에 `192.168.0.x` 배포 | 8일차 · **10일차** [10_DNS와_DHCP_다시보기](../day-10/lesson-10.md) |

- 뒷면 포트 모양이 다르다: **WAN(인터넷) 1개** + **LAN 4개** — WAN 이 라우터 쪽, LAN 이 스위치 쪽
- 실제 제품에는 **AP(무선)** 도 함께 들어 있지만, 오늘은 **유선만** 다룬다

> 🗣 **"1단계에서 며칠에 걸쳐 배운 장비들이, 여러분 집 신발장 위 작은 상자 하나에 다 들어 있습니다."**

## 🗺 오늘의 토폴로지 — 전부 유선

```
  🖥 PC0 ──Eth──┐                                                  ┌── 🗄 Internet
  🖥 PC1 ──Eth──┤                                                  │    8.8.8.8
                ├── [HomeRouter WRT300N] ─Internet── G0/0 [ISP] G0/1 ┘    DNS · 웹
  🗄 HomeServer ─┘  LAN 192.168.0.1        203.0.113.2  .1       8.8.8.1
    (④ 선택)         DHCP .100~            └── /30 ──┘
  ◀────────── 사설 (우리 집) ──────────▶◀───────── 공인 (인터넷) ─────────▶
```

| 장비 | 주소 | 비고 |
|------|------|------|
| HomeRouter LAN | 192.168.0.1 /24 | = PC 들의 게이트웨이 · **관리자 페이지 주소** |
| HomeRouter WAN | 203.0.113.2 /30 | **공인** (통신사가 준 주소 역할) |
| ISP G0/0 · G0/1 | 203.0.113.1 /30 · 8.8.8.1 /24 | **`192.168.0.0` 경로 없음** (일부러) |
| Internet 서버 | 8.8.8.8 | DNS (`www.student.test` A 레코드) · HTTP |
| PC0 · PC1 | **DHCP** `192.168.0.100~` | 공유기 **LAN 포트**에 Copper Straight-Through |
| HomeServer (선택) | 192.168.0.10 **고정** | 포트포워딩 대상 |

> 📌 `203.0.113.0/24` 는 **문서 · 교육용으로 예약된** 공인 대역이다 (실제 누구의 것도 아니다). `/30` = 주소 2개짜리 — 2일차 서브넷팅 회수 (라우터끼리 연결할 때 쓰는 크기)

## 🧪 ① 공유기 설정 — "관리자 페이지" 에서

PT 의 WRT300N `GUI` 탭 = 실제 집 공유기의 **`192.168.0.1` 관리자 페이지**와 거의 같다.

| 설정 | 해석 | 관련 노트 |
|------|------|-----------|
| **Internet Setup = Static IP** `203.0.113.2` · GW `203.0.113.1` | 공유기의 **WAN = 공인** 쪽. 집에서는 보통 통신사가 **DHCP 로** 준다 | [9_NAT와_포트포워딩](../day-10/lesson-9.md) |
| **Router IP** `192.168.0.1` | 공유기의 **LAN = 사설** 쪽 = 집 안의 게이트웨이 | 2일차 |
| **DHCP Enabled** · Start `.100` · Max 50 | 집 안 기기에 `.100 ~ .149` 를 빌려준다 → `.1 ~ .99` 는 고정 IP 용 | 8일차 `excluded-address` 와 같은 발상 |
| **Static DNS 1** `8.8.8.8` | DHCP 로 **DNS 서버 주소도** 같이 나눠준다 | [10_DNS와_DHCP_다시보기](../day-10/lesson-10.md) |

> ⚠️ **Save Settings** 를 **화면마다** 눌러야 저장된다 — 가장 흔한 실수
> 📌 **Wireless 탭은 건드리지 않는다.** 오늘은 유선만 쓴다.

- 🔎 NAT 설정 칸은 **어디에도 없다** → 공유기는 **WAN · LAN 을 나눈 순간 NAT 를 자동으로** 켠다. 그래서 집에서 아무도 NAT 를 설정한 적이 없다

## 🧪 ② 확인 — "ISP 는 우리 집 경로를 모르는데 왜 되지?"

| 확인 | 결과 | 이유 |
|------|------|------|
| PC0 `ipconfig` | `192.168.0.100` · GW `.1` · DNS `8.8.8.8` | DHCP |
| PC1 `ipconfig` | `192.168.0.101` | **같은 LAN** (공유기 안의 스위치) |
| `ping 8.8.8.8` | ✅ | ↓ 🗣 |
| `ping www.student.test` · 웹 브라우저 | ✅ | DNS A 레코드 |
| Internet 서버에서 `ping 192.168.0.100` | ❌ | 인터넷은 사설 주소를 모른다 + NAT 는 **밖에서 먼저**를 막는다 |

> 🗣 **"ISP 라우터에는 `192.168.0.0` 으로 가는 경로가 없습니다. 5일차 기준이면 응답이 못 돌아와야 해요. 그런데 왜 ping 이 될까요?"**
> → ISP 가 보는 출발지는 `192.168.0.100` 이 아니라 **`203.0.113.2`** 다 → ISP 는 그건 안다 (직접 연결) → **NAT 덕분**
> → 👉 Simulation 으로 확인하러 간다

> 📌 마지막 줄(**밖에서 먼저는 안 된다**)은 [3_왜_막아야_하나](lesson-3.md) 의 출발점이 된다. 칠판에 남겨 둘 것

## 🧪 ③ Simulation — NAT 가 바꾸는 순간 ⭐

PC0 → 8.8.8.8 ICMP 를 **한 칸씩** 보내며 봉투를 연다.

| 구간 | Src IP | Dst IP | |
|------|--------|--------|---|
| PC0 → HomeRouter | **192.168.0.100** | 8.8.8.8 | 사설 |
| HomeRouter → ISP | **203.0.113.2** | 8.8.8.8 | 🎯 **바뀌었다** (NAT) |
| ISP → HomeRouter (응답) | 8.8.8.8 | **203.0.113.2** | |
| HomeRouter → PC0 | 8.8.8.8 | **192.168.0.100** | 🎯 **되돌렸다** (변환표) |

- 봉투 클릭 → **OSI Model** 탭에서 공유기의 **"In Layers / Out Layers"** 를 비교하면 3계층 IP 가 바뀐 게 보인다
- 🔎 PT 버전에 따라 ICMP 는 **ID 번호**가, TCP 는 **포트 번호**가 함께 바뀌는 것도 보인다 → **PAT**
- PC0 과 PC1 에서 **동시에** 보내면 공인 IP 는 하나인데 **포트로 구분**되는 것을 볼 수 있다 → **PAT 의 핵심**

> 💡 1단계에서 Simulation 으로 **ARP · ping 봉투**를 열어봤다 (3일차). 오늘은 그 봉투의 **주소가 공유기에서 바뀌는** 걸 본다.

## 🧪 ④ (선택) 포트포워딩 — 밖에서 들어오는 문을 뚫는다

③ 에서 봤듯 NAT 는 **나갈 때**는 알아서 해주지만, **밖에서 먼저 들어오는 것**은 막는다.
집 안 서버를 인터넷에 공개하려면 **구멍을 미리 뚫어** 둬야 한다.

| | 규칙이 없으면 | 규칙을 넣으면 |
|---|---|---|
| 밖에서 `203.0.113.2 : 80` 호출 | 🌐 안 열림 | ✅ HomeServer `192.168.0.10 : 80` 으로 전달 |

```
GUI → Applications & Gaming → Single Port Forwarding
  External Port 80 → Internal Port 80 → IP Address 192.168.0.10 → Enabled
```

- 포트포워딩 대상 서버는 **고정 IP** 여야 한다 → DHCP 로 주소가 바뀌면 규칙이 **엉뚱한 기기**를 가리킨다 ([6_서버란_무엇인가](../day-10/lesson-6.md) "서버는 고정 IP")
- 📌 PT 버전에 따라 메뉴 이름이 `Single Port Forwarding` / `Port Range Forwarding` 으로 다르다 → **리허설 필수**

> 💡 **우리 교실 VM 은 브릿지**라서 이 구멍을 뚫을 필요가 없었다 — 교실 망에 **직접** 주소를 받았으니까.
> 편한 만큼 **아무나 닿는다**는 뜻이기도 하다 → [3_왜_막아야_하나](lesson-3.md)

## ⚠️ 실습 중 막히면 — 오늘판 4대 원인

| 증상 | 원인 | 해결 |
|------|------|------|
| PC 가 `169.254.x.x` | 공유기 DHCP 꺼짐 · 케이블이 WAN 포트에 꽂힘 | DHCP **Enabled** + Save · **LAN 포트**에 연결 |
| IP 는 받았는데 `ping 8.8.8.8` 실패 | WAN **Static** 값 · Save 누락 · ISP `no shutdown` | GUI 재확인 · ISP `show ip interface brief` |
| IP 로는 되는데 이름으로 안 됨 | DHCP 의 **Static DNS 1** 비어 있음 · 서버 DNS Off | Static DNS 1 `8.8.8.8` → 클라이언트 **DHCP 다시** 받기 |
| 포트포워딩이 안 먹음 | 대상이 **DHCP 주소** · Enabled 체크 안 함 | HomeServer 를 **고정 IP** 로 · Save |

## 📝 강의 메모

- **"ISP 는 우리 집 경로를 모르는데 왜 되지?"** 가 오늘 PT 실습의 핵심 질문 — 5일차 라우팅 원칙과 충돌하는 것처럼 보이는 걸 NAT 로 푼다
- Simulation 은 **공유기 양쪽 구간의 Src IP 두 개**만 비교하게 한다 — 그 외의 필드는 보지 않아도 된다
- ⭐ PC0 · PC1 **동시 전송**으로 PAT 를 보여주면 [9_NAT와_포트포워딩](../day-10/lesson-9.md) 의 PAT 절을 여기서 회수할 수 있다
- 포트포워딩(④)은 **"밖에서 먼저는 막힌다"** 를 보여주는 게 목적 — 시간이 없으면 표만 보여주고 넘어간다
- 시스코 CLI NAT(`ip nat inside source ... overload`)는 대본 부록 A — CCNA 를 준비하는 학생에게 과제로
- 📌 **무선은 다루지 않는다.** WRT300N 을 쓰지만 Wireless 탭은 건너뛰고 LAN 포트에 유선으로만 붙인다
- 📌 WRT300N GUI 는 PT 버전마다 조금 다르다 → **수업 전 리허설**, 특히 **Static DNS** 칸 위치와 **포트포워딩 메뉴**
- ➡️ 이 절의 마지막(**밖에서 먼저는 막힌다**)이 [3_왜_막아야_하나](lesson-3.md) 의 도입이다. **브릿지인 우리 VM 은 그 보호가 없다**로 이어 간다
