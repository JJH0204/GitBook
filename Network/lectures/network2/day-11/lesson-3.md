## 학습 목표

## 1. 구성 요소

### 1.1 브릿지: 내 서버는 교실 한복판에 서 있다

9일차에 VM의 네트워크 어댑터를 브릿지(Bridged)로 두었다. 그 뜻은 다음과 같다.

```
        [ 교실 공유기 ]
              │
      ┌───────┼───────┬──────────┐
      │       │       │          │
  내 Windows  │   옆자리 PC   또 다른 PC
      │       │
      └── 내 Ubuntu VM  ←── 브릿지: 공유기에서 IP 를 "직접" 받는다
```

- 브릿지는 내 VM이 교실 공유기에 랜선을 직접 꽂은 것과 같다.
- VM은 `192.168.x.x` 같은 교실 망의 주소를 하나 차지한다.
- 내 Windows뿐 아니라 같은 교실의 모든 PC가 내 서버에 바로 닿을 수 있다.

비유: NAT는 회사 대표번호였다. 밖에서는 내선 번호를 모르니 함부로 걸지 못한다. 브릿지는 내 책상에 직통 번호를 하나 받은 것이다. 편하지만 아무나 걸 수 있다.

옆자리 PC에서 내 서버로 `ping`이 가고 SSH 로그인 창까지 뜬다. 방화벽을 켠 적이 없으므로 아무것도 막혀 있지 않다. 실습은 [옆자리에서 내 서버 두드리기](lesson-3-lab-exposure.md)에서 한다.

핵심 질문: 비밀번호 하나가 이 서버의 전부인가.

### 1.2 공격 표면: `ss`가 보여 준 목록

10일차에 서버를 "포트를 열고 기다리는 프로그램"이라고 `ss`로 확인했다. 그 출력에 이름을 붙이면 다음과 같다.

```bash
ss -tuln
```

```
Netid  State    Local Address:Port
tcp    LISTEN   0.0.0.0:22          ← SSH
tcp    LISTEN   0.0.0.0:21          ← FTP
tcp    LISTEN   0.0.0.0:8000        ← 연습용 웹서버
```

공격 표면(Attack Surface)은 바깥에서 두드릴 수 있는 지점 전부다. `LISTEN` 한 줄이 문 하나이며, 문이 많을수록 표면이 넓다.

| 주소 표기 | 뜻 | 위험도 |
|---|---|---|
| `0.0.0.0:22` | 모든 네트워크 인터페이스에서 받는다 | 넓다. 교실 전체가 닿는다 |
| `127.0.0.1:3306` | 자기 자신에서만 받는다 | 좁다. 밖에서 닿지 않는다 |

- 10일차에 본 `Server listening on 0.0.0.0 port 22`의 `0.0.0.0`이 이 뜻이었다.
- 가장 싼 보안은 안 쓰는 서비스를 끄는 것이다. 문이 없으면 두드릴 수도 없다.

```bash
sudo systemctl disable --now vsftpd    # 안 쓸 거면 끈다 = 표면을 줄인다
```

문을 열어 두는 것은 공짜가 아니다. 열어 둔 문은 누군가 계속 두드린다. 인터넷에 노출된 서버의 SSH 포트에는 하루에도 수천 번의 로그인 시도가 들어온다.

### 1.3 통제는 세 자리에서 걸린다

같은 "막는다"도 어디서 막느냐에 따라 이름과 도구가 다르다.

```
 [ 바깥 ] ──▶ ① 네트워크 장비 ──▶ ② 서버 자신 ──▶ ③ 서비스
                 라우터 · 방화벽       ufw              설정 파일
                 ACL                (호스트 방화벽)     (예: 허용 IP)
                 「단지 정문」         「우리 집 현관」    「집 안 금고」
```

| 자리 | 도구 | 누가 관리하나 | 문서 |
|---|---|---|---|
| ① 네트워크 장비 | 시스코 ACL, 방화벽 장비 | 망 관리자 | [4. ACL 표준](lesson-4.md), [5. ACL 확장](lesson-5.md) |
| ② 서버 자신 | 리눅스 ufw(호스트 방화벽) | 서버 관리자 | [6. 리눅스 방화벽 ufw](lesson-6.md) |
| ③ 서비스 설정 | `vsftpd.conf`, `sshd_config` 등 | 서비스 담당자 | 12일차 |

비유(아파트): ① 단지 정문 경비(ACL)가 1차로 거르고, ② 우리 집 현관문(ufw)이 2차로 거르고, ③ 금고(서비스 설정)가 마지막이다. 정문만 믿으면 같은 단지 주민은 아무나 우리 집에 들어온다. 지금 교실이 그 상태다.

- 이것을 다층 방어(Defense in Depth)라고 한다. 한 겹이 뚫려도 다음 겹이 남는다.
- 교실은 브릿지라서 ①이 사실상 없다. ②가 유일한 방어선이다. 그래서 ufw가 주인공이다.

## 2. 동작 원리

### 2.1 최소 권한 원칙 (Least Privilege)

"필요한 사람에게, 필요한 것만, 필요한 동안만."

- 10일차에 `chmod 777`이 왜 위험한지 배웠다. 그 생각을 네트워크로 옮긴 것이 11일차다.
- `chmod 777`은 모두에게 전부 허용이다. 방화벽 없음은 모두에게 모든 포트 허용이다. 같은 실수다.

### 2.2 기본 거부 (Default Deny)

"일단 다 막고, 필요한 것만 연다." (화이트리스트)

| 방식 | 규칙 | 새로운 위협이 생기면 |
|---|---|---|
| 기본 허용(블랙리스트) | 나쁜 것만 골라 막는다 | 놓친다. 목록에 없으니 통과한다 |
| 기본 거부(화이트리스트) | 허용할 것만 적고 나머지 전부 거부한다 | 자동으로 막힌다 |

- 시스코 ACL의 암묵적 `deny any`, ufw의 `default deny incoming`은 둘 다 이 원칙의 구현이다.
- 두 도구는 이름만 다르고 생각은 하나다.

## 3. 약어와 용어

| 용어 | 뜻 |
|---|---|
| 공격 표면(Attack Surface) | 바깥에서 두드릴 수 있는 지점 전부 |
| 브릿지(Bridged) | VM이 물리 망에 직접 붙어 같은 망의 주소를 받는 어댑터 방식 |
| 다층 방어(Defense in Depth) | 여러 겹의 통제로 한 겹이 뚫려도 막는 구조 |
| 최소 권한(Least Privilege) | 필요한 사람에게 필요한 것만 필요한 동안만 허용 |
| 기본 거부(Default Deny) | 허용한 것 외에는 모두 거부 |
