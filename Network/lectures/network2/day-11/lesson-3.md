# 3. 왜 막아야 하나 — 열어 둔 문의 값

> 상위: [11일차 · 서버 보안](README.md)

## 🎯 학습 목표

- **공격 표면(attack surface)** 이 무엇인지 말하고, `ss -tuln` 의 출력이 곧 그 목록임을 안다
- 우리 교실의 **브릿지 환경**에서 내 서버가 **옆자리 PC 에게 그대로 열려 있다**는 것을 직접 확인한다
- 통제가 걸리는 **세 자리**(네트워크 장비 · 호스트 · 서비스)를 구분한다
- **최소 권한 원칙**과 **기본 거부(default deny)** 를 한 문장으로 설명한다

## 🌉 다리 놓기: "지금까지 우리는 계속 열기만 했다"

지난 이틀을 돌아보자. 우리가 한 일은 **전부 여는 일**이었다.

| 언제     | 한 일                                           | 열린 것               |
| ------ | --------------------------------------------- | ------------------ |
| 9일차    | `apt install openssh-server` → `enable --now` | **22번**            |
| 10일차   | `python3 -m http.server`                      | **8000번**          |
| 10일차   | `apt install vsftpd`                          | **21번** (+ 데이터 연결) |
| 11일차 앞 | 공유기 포트포워딩 (PT)                                | 집 안 서버를 **밖에 공개**  |

그리고 방금 [1_공유기_실습](lesson-1.md) 에서 재미있는 걸 봤다. **Internet 서버에서 집 안으로 먼저 `ping` 을 보냈더니 실패**했다.
공유기가 막아 준 것이다. NAT 는 "주소를 바꾸는 기술"인데, 덤으로 **바깥에서 먼저 들어오는 것을 막아 주는** 효과가 있었다.

> 🗣 **"그럼 우리 우분투 서버도 안전한 거 아닌가요? 공유기 안에 있잖아요."**

여기서 오늘이 시작된다. **아니다.** 우리 교실 환경에서는 그렇지 않다.

## 📖 ① 브릿지 — 내 서버는 교실 한복판에 서 있다 ⭐

9일차에 VM 의 네트워크 어댑터를 **브릿지(Bridged)** 로 두었다. 이 한 줄의 뜻을 이제 정확히 보자.

```
        [ 교실 공유기 ]
              │
      ┌───────┼───────┬──────────┐
      │       │       │          │
  내 Windows  │   옆자리 PC   또 다른 PC
      │       │
      └── 내 Ubuntu VM  ←── 브릿지: 공유기에서 IP 를 "직접" 받는다
```

- **브릿지 = 내 VM 이 교실 공유기에 랜선을 직접 꽂은 것**과 같다
- 그래서 VM 은 `192.168.x.x` 같은 **교실 망의 주소**를 하나 차지한다
- 즉 **내 Windows 뿐 아니라, 같은 교실의 모든 PC 가 내 서버에 바로 닿을 수 있다**

> 💡 **비유.** NAT 는 **회사 대표번호**였다 — 밖에서는 내선 번호를 모르니 함부로 못 건다.
> 브릿지는 **내 책상에 직통 번호를 하나 받은 것**이다. 편하지만, **아무나 걸 수 있다.**

### 🧪 지금 해 보자 — 옆자리와 서로 두드리기

```bash
# 🐧 내 VM 에서 — 내 주소 확인
ip a                       # 192.168.x.x 를 찾는다

# 🪟 옆자리 사람의 Windows 에서 — 내 서버로
ping 192.168.x.x
ssh student@192.168.x.x    # ← 비밀번호만 알면 들어온다
```

- 옆자리에서 **내 서버에 `ping` 이 가고 SSH 로그인 창까지 뜬다**
- 우리는 방화벽을 켠 적이 없다. **아무것도 막혀 있지 않다**

> 🗣 **오늘의 핵심 질문** — **"그럼 비밀번호 하나가 이 서버의 전부입니까?"**

## 📖 ② 공격 표면 — `ss` 가 보여 준 그 목록

10일차에 "서버 = 포트를 열고 기다리는 프로그램"이라는 걸 `ss` 로 확인했다. 그 출력에 이름을 붙이면 이렇게 된다.

```bash
ss -tuln
```

```
Netid  State    Local Address:Port
tcp    LISTEN   0.0.0.0:22          ← SSH
tcp    LISTEN   0.0.0.0:21          ← FTP
tcp    LISTEN   0.0.0.0:8000        ← 연습용 웹서버
```

> 📌 **공격 표면(Attack Surface)** = **바깥에서 두드릴 수 있는 지점 전부.**
> `LISTEN` 한 줄 한 줄이 곧 **문 하나**다. 문이 많을수록 표면이 넓다.

| 주소 표기 | 뜻 | 위험도 |
|-----------|-----|--------|
| `0.0.0.0:22` | **모든** 네트워크 인터페이스에서 받는다 | 넓다 — 교실 전체가 닿는다 |
| `127.0.0.1:3306` | **자기 자신에서만** 받는다 | 좁다 — 밖에서 못 닿는다 |

- 10일차에 본 `Server listening on 0.0.0.0 port 22` 의 **`0.0.0.0`** 이 바로 이 뜻이었다
- 가장 싼 보안은 **안 쓰는 서비스를 끄는 것**이다. 문이 없으면 두드릴 수도 없다

```bash
sudo systemctl disable --now vsftpd    # 안 쓸 거면 끈다 = 표면을 줄인다
```

> 💡 **문 열어 두기 = 공짜가 아니다.** 열어 둔 문은 **누군가 계속 두드린다.** 실제 인터넷에 노출된 서버의 SSH 포트에는 **하루에도 수천 번**의 로그인 시도가 들어온다.

## 📖 ③ 통제는 세 자리에서 걸린다 ⭐

같은 "막는다"도 **어디서 막느냐**에 따라 이름과 도구가 다르다. 오늘 배울 두 가지가 각각 어디에 있는지 먼저 자리를 잡자.

```
 [ 바깥 ] ──▶ ① 네트워크 장비 ──▶ ② 서버 자신 ──▶ ③ 서비스
                 라우터 · 방화벽       ufw              설정 파일
                 ACL                (호스트 방화벽)     (예: 허용 IP)
                 「단지 정문」         「우리 집 현관」    「집 안 금고」
```

| 자리 | 도구 | 누가 관리하나 | 오늘 |
|------|------|---------------|------|
| ① **네트워크 장비** | 시스코 **ACL** · 방화벽 장비 | 망 관리자 | [4_ACL_표준](lesson-4.md) · [5_ACL_확장](lesson-5.md) |
| ② **서버 자신** | 리눅스 **ufw** (호스트 방화벽) | 서버 관리자 | [6_리눅스_방화벽_ufw](lesson-6.md) ⭐ |
| ③ **서비스 설정** | `vsftpd.conf` · `sshd_config` 등 | 서비스 담당자 | 12일차 |

> 💡 **비유: 아파트.** ① **단지 정문 경비**(ACL) 가 1차로 거르고 → ② **우리 집 현관문**(ufw) 이 2차로 거르고 → ③ **금고**(서비스 설정) 가 마지막이다.
> 정문만 믿으면 **같은 단지 주민은 아무나 우리 집에 들어온다. 지금 우리 교실이 그 상태다.**

- 이것을 **다층 방어(Defense in Depth)** 라고 한다. 한 겹이 뚫려도 다음 겹이 남는다
- 우리 교실은 **브릿지** 라서 ① 이 사실상 없다 → **② 가 유일한 방어선**이다. 그래서 오늘 ufw 가 주인공이다

## 📖 ④ 두 가지 원칙 — 오늘 가져갈 문장

### 최소 권한 원칙 (Least Privilege)

> **"필요한 사람에게, 필요한 것만, 필요한 동안만."**

- 10일차에 `chmod 777` 이 왜 위험한지 배웠다. **그 생각을 네트워크로 옮긴 것**이 오늘이다
- `chmod 777` = 모두에게 전부 허용 ↔ **방화벽 없음** = 모두에게 모든 포트 허용. **같은 실수다**

### 기본 거부 (Default Deny)

> **"일단 다 막고, 필요한 것만 연다."** (화이트리스트)

| 방식 | 규칙 | 새로운 위협이 생기면 |
|------|------|---------------------|
| 기본 허용 (블랙리스트) | 나쁜 것만 골라 막는다 | **놓친다** — 목록에 없으니 통과 |
| **기본 거부** (화이트리스트) | 허용할 것만 적고 나머지 전부 거부 | **자동으로 막힌다** ✅ |

- 시스코 ACL 의 **암묵적 deny any**, ufw 의 **`default deny incoming`** — **둘 다 이 원칙의 구현**이다
- 오늘 배울 두 도구가 **이름만 다르고 생각은 하나**라는 걸 계속 확인하게 된다

- 지금 내 서버의 공격 표면은 몇 개인가? `ss -tuln` 으로 세어 보자. 그중 **정말 필요한 것**은 몇 개인가?
- 옆자리 PC 에서 내 서버에 `ssh` 가 되는 것을 확인했다. 이게 왜 문제일까? 회사라면?
- `0.0.0.0:22` 와 `127.0.0.1:22` 중 더 안전한 것은? 그런데 왜 우리는 `0.0.0.0` 을 썼을까?
- 집 공유기는 바깥의 공격을 막아 줬다. 그런데 **집 안의 다른 기기**가 공격한다면 공유기가 막아 줄까?

## 📝 강의 메모

- 🗣 도입은 **"지금까지 우리는 계속 열기만 했습니다. 오늘은 처음으로 닫습니다."**
- ⭐ **옆자리와 서로 SSH 해 보기**가 오늘 전체의 동기다. 말로 설명하지 말고 **먼저 시키고** 놀라게 할 것
  - 비밀번호를 알려주지 말고 **로그인 프롬프트가 뜨는 것까지만** 확인시킨다 (실제 로그인 금지)
  - ⚠️ **교실 랩 안에서만.** "허가 없는 외부 장비 접속은 불법"을 여기서 한 번 못 박는다
- 회수 지점
  1. 10일차 **`chmod 777`** → 오늘 **방화벽 없음** = 같은 실수 (최소 권한)
  2. 10일차 **`ss` 의 LISTEN 목록** → 오늘 **공격 표면**
  3. 10일차 **`0.0.0.0:22`** → 오늘 "모든 인터페이스에서 받는다"의 의미
  4. 11일차 앞 **공유기가 밖에서 오는 ping 을 막은 것** → 오늘 **그건 NAT 의 부수 효과였을 뿐**
- 📌 **브릿지 전제**: 이 노트는 VM 어댑터가 **브릿지**라는 전제로 쓰였다. NAT 인 교실이라면 옆자리 실습이 안 되므로 **내 Windows → VM** 으로 대체한다
