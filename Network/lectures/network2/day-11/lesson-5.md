## 학습 목표

- 확장 ACL이 보는 다섯 가지(프로토콜, 출발지, 목적지, 포트, 조건)를 말한다.
- 10일차 포트 번호를 ACL 문장에 직접 써서 서비스 단위로 허용 또는 거부한다.
- 확장 ACL을 출발지 가까이 두는 이유를 설명한다.
- 규칙의 순서가 결과를 바꾼다는 것을 실패로 확인한다.

## 이전 학습과의 연결

[4. ACL 표준](lesson-4.md)(LEC-N2-11-007-DO)으로 인사팀 PC를 서버망에서 막았다. 현장에서는 이런 요구가 온다.

"인사팀도 그 서버의 웹페이지는 봐야 한다. 대신 SSH로 서버에 로그인하는 것은 개발팀만 되게 해 달라."

표준 ACL로는 불가능하다. 표준은 누가 왔는지만 보기 때문이다. 인사팀이 웹을 보러 왔는지 SSH로 들어오려는지 구분할 수 없다. 포트까지 보는 ACL이 필요하며, 포트는 10일차에 이미 배웠다.

| 10일차에 배운 것 | 이번에 쓰는 곳 |
|---|---|
| SSH = 22, HTTP = 80, FTP = 21 | ACL 문장의 `eq 22`, `eq 80`, `eq 21` |
| TCP인가 UDP인가 | ACL 문장의 `tcp`, `udp` |

## 1. 구성 요소

### 1.1 확장 ACL의 문장 구조

```
access-list 110 permit tcp 192.168.20.0 0.0.0.255 host 192.168.10.100 eq 22
             │     │     │       └── 출발지 + 와일드카드      └── 목적지      └── 포트
             │     │     └── 프로토콜 (ip / tcp / udp / icmp)
             │     └── permit / deny
             └── 번호 (100~199 = 확장)
```

한국어로 읽으면 다음과 같다. `permit`(허용한다) `tcp`(TCP 통신을) `192.168.20.0 0.0.0.255`(20번 대역에서 출발해서) `host 192.168.10.100`(이 서버로 가는) `eq 22`(22번 포트로 가는 것을).

| 자리 | 쓸 수 있는 것 |
|---|---|
| 프로토콜 | `ip`(전부), `tcp`, `udp`, `icmp` |
| 출발지·목적지 | `주소 와일드카드`, `host 주소`, `any` |
| 포트 조건 | `eq`(같다), `neq`(다르다), `gt`(초과), `lt`(미만), `range 시작 끝` |

{% hint style="warning" %}
CAUTION: 포트는 목적지 쪽에 붙인다. 서버의 서비스를 지정하는 것이므로 목적지 주소 뒤에 쓴다. 출발지 뒤에 쓰면 "출발 포트가 22인 것"이 되어 전혀 다른 뜻이 된다. 클라이언트의 출발 포트는 매번 임의의 값이다.
{% endhint %}

**자주 쓰는 형태**

```
access-list 110 permit tcp any host 192.168.10.100 eq 80     웹은 누구나
access-list 110 permit tcp host 192.168.20.11 host 192.168.10.100 eq 22   SSH 는 개발 PC 만
access-list 110 deny   icmp any any                           ping 금지
access-list 110 permit ip any any                             나머지는 통과
```

{% hint style="danger" %}
WARNING: 마지막 줄의 `permit ip any any`를 잊지 않는다. 확장 ACL에도 암묵적 deny any가 그대로 있다.
{% endhint %}

## 2. 동작 원리

### 2.1 순서가 결과를 바꾼다

ACL은 위에서부터 읽다가 처음 맞는 줄에서 멈춘다. 같은 규칙이라도 순서가 다르면 결과가 다르다.

```
잘못된 순서                                  올바른 순서
access-list 110 permit ip any any          access-list 110 deny tcp host .20.10 host .10.100 eq 22
access-list 110 deny tcp host .20.10 ...   access-list 110 permit ip any any
      ↑ 1번 줄에서 전부 통과 →                     ↑ 구체적인 것 먼저
        2번 줄은 영원히 읽히지 않는다                그 다음 넓은 것
```

구체적인 것은 위로, 넓은 것은 아래로 쓴다. 표준과 확장에 공통인 규칙이다.

- `show access-lists`의 match 숫자가 0인 줄이 있으면 위에서 이미 걸리고 있다는 신호다.

### 2.2 어디에 붙이나: 확장은 출발지 가까이

```
[PC_인사 .20.10]──┐                            ┌── 서버 192.168.10.100
                  ├──[SW2]──[R1]──[SW1]────────┤
[PC_개발 .20.11]──┘         g0/1    g0/0
                           .20.254  .10.254

g0/1 in 에 붙인다 : 들어오자마자 검사 → 막힐 패킷이 망을 돌아다니지 않는다
```

| 종류 | 위치 | 이유 |
|---|---|---|
| 표준 | 목적지 가까이 | 출발지만 보니까 멀면 과잉 차단 |
| 확장 | 출발지 가까이 | 목적지·포트까지 정확히 보므로 일찍 버려도 안전하다. 대역 낭비가 없다 |

비유: 표준은 "이 사람 출입 금지"라는 쪽지라서 가려는 건물 정문에 붙여야 한다. 확장은 "이 사람은 3층 회의실만 금지"라서 출발하는 로비에서 바로 걸러도 문제가 없다.

### 2.3 요구사항과 규칙

| 누가 | 서버 웹(80) | 서버 SSH(22) |
|---|---|---|
| PC_개발 `192.168.20.11` | 허용 | 허용 |
| PC_인사 `192.168.20.10` | 허용 | 거부 |

```
access-list 110 permit tcp host 192.168.20.11 host 192.168.10.100 eq 22
access-list 110 deny   tcp any                host 192.168.10.100 eq 22
access-list 110 permit ip  any any

interface g0/1
 ip access-group 110 in
```

같은 PC, 같은 서버인데 포트에 따라 결과가 다르다. 표준으로는 할 수 없던 일이다.

### 2.4 정리: 표준 vs 확장

| | 표준 ACL | 확장 ACL |
|---|---|---|
| 번호 | 1~99 | 100~199 |
| 보는 것 | 출발지 IP만 | 프로토콜, 출발지, 목적지, 포트 |
| 할 수 있는 말 | "저 사람 오지 마" | "저 사람, 그건 하지 마" |
| 붙이는 위치 | 목적지 가까이 | 출발지 가까이 |
| 암묵적 deny any | 있다 | 있다 |

## 3. 약어와 용어

| 용어 | 뜻 |
|---|---|
| 확장 ACL | 프로토콜, 출발지, 목적지, 포트까지 보는 ACL(번호 100~199) |
| `eq` | 포트가 같다 |
| `permit ip any any` | 나머지 모든 IP 통신을 허용하는 마지막 줄 |
