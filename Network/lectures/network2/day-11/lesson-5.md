# 5. ACL ② 확장 — 무엇을 하러 왔는지까지 본다

> 상위: [11일차 · 서버 보안](README.md)

## 🎯 학습 목표

- **확장 ACL** 이 보는 다섯 가지(프로토콜 · 출발지 · 목적지 · 포트 · 조건)를 말한다
- 10일차 **포트 번호**를 ACL 문장에 직접 써서 **서비스 단위로** 허용 · 거부한다
- 확장 ACL 을 **출발지 가까이** 두는 이유를 설명한다
- 규칙의 **순서**가 결과를 바꾼다는 것을 실패로 확인한다

## 🌉 다리 놓기: "들어오지 마" 와 "그건 하지 마"

[4_ACL_표준](lesson-4.md) 로 인사팀 PC 를 서버망에서 막았다. 그런데 현장에서 이런 요구가 온다.

> 🗣 **"인사팀도 그 서버의 **웹페이지**는 봐야 합니다. 대신 **SSH 로 서버에 로그인**하는 건 개발팀만 되게 해 주세요."**

표준 ACL 로는 **불가능**하다. 표준은 **"누가 왔는지"** 만 보기 때문이다. 인사팀이 웹을 보러 왔는지 SSH 로 들어오려는지 **구분할 수가 없다.**

여기서 필요한 것이 **포트까지 보는 ACL** 이다. 그리고 포트는 **10일차에 이미 다 외웠다.**

| 10일차에 배운 것 | 오늘 쓰는 곳 |
|------------------|-------------|
| SSH = **22** · HTTP = **80** · FTP = **21** | ACL 문장의 `eq 22` · `eq 80` · `eq 21` |
| TCP 냐 UDP 냐 | ACL 문장의 `tcp` / `udp` |

---

## 📖 ① 확장 ACL 의 문장 구조 ⭐

```
access-list 110 permit tcp 192.168.20.0 0.0.0.255 host 192.168.10.100 eq 22
             │     │     │       └── 출발지 + 와일드카드      └── 목적지      └── 포트
             │     │     └── 프로토콜 (ip / tcp / udp / icmp)
             │     └── permit / deny
             └── 번호 (100~199 = 확장)
```

**읽는 순서를 한국어로 그대로 옮기면 이렇다.**

> `permit` **(허용한다)** `tcp` **(TCP 통신을)** `192.168.20.0 0.0.0.255` **(20번 대역에서 출발해서)**
> `host 192.168.10.100` **(이 서버로 가는)** `eq 22` **(22번 포트로 가는 것을)**

| 자리 | 쓸 수 있는 것 |
|------|--------------|
| 프로토콜 | `ip` (전부) · `tcp` · `udp` · `icmp` |
| 출발지 / 목적지 | `주소 와일드카드` · `host 주소` · `any` |
| 포트 조건 | `eq`(같다) · `neq`(다르다) · `gt`(초과) · `lt`(미만) · `range 시작 끝` |

> ⚠️ **포트는 목적지 쪽에 붙인다.** 서버의 서비스를 지정하는 것이므로 **목적지 주소 뒤**에 쓴다.
> (출발지 뒤에 쓰면 "출발 포트가 22인 것"이 되어 전혀 다른 뜻이 된다 — 클라이언트의 출발 포트는 매번 랜덤이다)

### 자주 쓰는 형태

```
access-list 110 permit tcp any host 192.168.10.100 eq 80     웹은 누구나
access-list 110 permit tcp host 192.168.20.11 host 192.168.10.100 eq 22   SSH 는 개발 PC 만
access-list 110 deny   icmp any any                           ping 금지
access-list 110 permit ip any any                             ⭐ 나머지는 통과
```

> ⚠️ **마지막 줄의 `permit ip any any` 를 잊지 말 것.** 확장 ACL 에도 **암묵적 deny any 가 그대로 있다.**

---

## 📖 ② 순서가 결과를 바꾼다

ACL 은 **위에서부터 읽다가 처음 맞는 줄에서 멈춘다.** 그래서 **같은 규칙이라도 순서가 다르면 결과가 다르다.**

```
❌ 이렇게 쓰면                              ✅ 이렇게 써야
access-list 110 permit ip any any          access-list 110 deny tcp host .20.10 host .10.100 eq 22
access-list 110 deny tcp host .20.10 ...   access-list 110 permit ip any any
      ↑ 1번 줄에서 전부 통과 →                     ↑ 구체적인 것 먼저
        2번 줄은 영원히 안 읽힌다                     그 다음 넓은 것
```

> 🗣 **"구체적인 것 위로, 넓은 것 아래로."** 표준·확장 공통 규칙이다.

- `show access-lists` 의 **match 숫자가 0 인 줄**이 있으면 → **위에서 이미 걸리고 있다**는 신호다

---

## 📖 ③ 어디에 붙이나 — 확장은 **출발지 가까이** ⭐

```
[PC_인사 .20.10]──┐                            ┌── 서버 192.168.10.100
                  ├──[SW2]──[R1]──[SW1]────────┤
[PC_개발 .20.11]──┘         g0/1    g0/0
                           .20.254  .10.254

✅ g0/1 in  에 붙인다 : 들어오자마자 검사 → 막힐 패킷이 망을 돌아다니지 않는다
```

| 종류 | 위치 | 이유 |
|------|------|------|
| 표준 | 목적지 가까이 | 출발지만 보니까 멀면 **과잉 차단** |
| **확장** | **출발지 가까이** | 목적지·포트까지 **정확히** 보므로 일찍 버려도 안전 → **대역 낭비가 없다** |

> 💡 **비유.** 표준은 **"이 사람 출입 금지"** 라는 쪽지라 **그 사람 집 앞**이 아니라 **가려는 건물 정문**에 붙여야 한다.
> 확장은 **"이 사람은 3층 회의실만 금지"** 라서 **출발하는 로비**에서 바로 걸러도 문제가 없다.

## 🧪 실습 — 웹은 모두에게, SSH 는 개발팀만

> 🖐 자세한 순서는 [대본 STEP 5](commands.md) 참고. [4_ACL_표준](lesson-4.md) 의 구성을 그대로 쓴다.

### 먼저 치울 것

```
interface g0/0
 no ip access-group 10 out       ← 앞 절의 표준 ACL 떼기
```

### 요구사항

| 누가 | 서버 웹(80) | 서버 SSH(22) |
|------|------------|--------------|
| PC_개발 `.20.11` | ✅ | ✅ |
| PC_인사 `.20.10` | ✅ | ❌ |

### 규칙

```
access-list 110 permit tcp host 192.168.20.11 host 192.168.10.100 eq 22
access-list 110 deny   tcp any                host 192.168.10.100 eq 22
access-list 110 permit ip  any any

interface g0/1
 ip access-group 110 in
```

### 검증 — PT 에서

1. PC_개발 → 서버 **웹 브라우저** `http://192.168.10.100` ✅
2. PC_개발 → 서버 **`ssh -l student 192.168.10.100`** ✅
3. PC_인사 → 서버 **웹** ✅ *(막히지 않았다!)*
4. PC_인사 → 서버 **SSH** ❌ *(여기만 막혔다)* ⭐
5. `show access-lists` — **어느 줄의 match 가 올라갔는지** 확인

> ⭐ **오늘의 하이라이트**: 같은 PC · 같은 서버인데 **포트에 따라 결과가 다르다.** 표준으로는 절대 못 하던 일이다.

---

## 📖 ④ 정리 — 표준 vs 확장

| | 표준 ACL | 확장 ACL |
|---|---|---|
| 번호 | **1~99** | **100~199** |
| 보는 것 | **출발지 IP** 만 | 프로토콜 · 출발지 · **목적지 · 포트** |
| 할 수 있는 말 | "저 사람 오지 마" | "저 사람, 그건 하지 마" |
| 붙이는 위치 | **목적지 가까이** | **출발지 가까이** |
| 암묵적 deny any | **있다** | **있다** |

## 🧪 실습 / 질문

- `deny tcp any host 192.168.10.100 eq 22` 만 쓰고 `permit ip any any` 를 빠뜨리면 어떻게 되나?
- 규칙 1번과 2번의 순서를 바꾸면 PC_개발 은 SSH 가 될까, 안 될까? 왜?
- `eq 80` 대신 `eq www` 라고 써도 된다. 그런데 **숫자로 쓰는 쪽이 나은 이유**는?
- DNS 를 막으려면 `tcp` 와 `udp` 중 무엇을 써야 하나? (10일차 회수)

## 📝 강의 메모

- 🗣 도입은 요구사항 한 줄로 — **"웹은 되고 SSH 만 막아 주세요. 표준으로 되나요?"** → 안 된다 → 그래서 확장
- ⭐ **같은 출발지인데 포트에 따라 갈리는 장면**이 이 절의 전부다. 4번 검증(인사팀 웹 ✅ / SSH ❌)을 **반드시 두 눈으로** 보게 할 것
- 10일차 **포트 번호표**가 여기서 쓰인다 — "외운 걸 오늘 처음 써먹는 날"이라고 짚어 줄 것
- 순서 함정은 **일부러 틀리게 넣고** match 0 을 보여 준 뒤 고치는 흐름이 가장 잘 남는다
- ⚠️ PT 라우터는 `ssh` 클라이언트 지원이 버전마다 다르다 → **리허설 필수**. 안 되면 **Telnet(23)** 으로 바꿔서 같은 실습을 한다 (평문 이야기는 12일차와 연결)
