## 학습 목표

- 집 공유기 = 라우터 + NAT + 스위치 + DHCP가 한 상자에 들어 있음을 설명한다.
- 공유기(WRT300N)에 WAN(공인), LAN(사설), DHCP를 설정하는 항목의 뜻을 안다.
- PC가 DHCP로 사설 IP를 받고 인터넷(가상)에 나가는 이유를 설명한다.
- Simulation 모드에서 NAT가 출발지 IP를 바꾸는 구간을 찾는다.
- (선택) 포트포워딩으로 집 안 서버를 밖에 공개하는 원리를 안다.

## 이전 학습과의 연결

10일차에 배운 DHCP, DNS, NAT, 포트포워딩을 전부 해주는 장비가 집마다 하나씩 있다. 공유기다.

8일차에는 이 기능들을 패킷트레이서의 `Server0`에서 체크박스로 하나씩 켰다. 11일차에는 그 기능들이 한 상자에 합쳐진 물건을 뜯어본다. → [10일차 NAT와 포트포워딩](../day-10/lesson-9.md), [10일차 DNS와 DHCP 다시 보기](../day-10/lesson-10.md)

## 1. 구성 요소

### 1.1 공유기의 정체: 네 장비가 한 상자에

```
            ┌───────────────── 집 공유기 (한 상자) ─────────────────┐
 인터넷 ────┤ WAN 포트 ─ [라우터 + NAT] ── [스위치] ─ LAN 포트 1~4 ─┼── 유선 PC
 (공인 IP)  │                                                      │
            │  + DHCP 서버 (192.168.0.100~) + DNS 중계 + 방화벽     │
            └──────────────────────────────────────────────────────┘
```

| 부품 | 하는 일 | 배운 날 |
|---|---|---|
| 라우터 | 집 안(사설)과 인터넷(공인)의 경계 | 4일차, 5일차 |
| NAT | 사설 주소를 공인 주소로 바꿔치기, 포트포워딩 | 10일차 [NAT와 포트포워딩](../day-10/lesson-9.md) |
| 스위치 | 뒷면 LAN 포트 4개 | 3일차, 4일차 |
| DHCP 서버 | 집 안 기기에 `192.168.0.x` 배포 | 8일차, 10일차 [DNS와 DHCP 다시 보기](../day-10/lesson-10.md) |

- 뒷면 포트 모양이 다르다. WAN(인터넷) 1개와 LAN 4개이며, WAN이 라우터 쪽이고 LAN이 스위치 쪽이다.
- 실제 제품에는 AP(무선)도 함께 들어 있다. 11일차는 유선만 다룬다.

"1단계에서 며칠에 걸쳐 배운 장비들이 여러분 집 신발장 위 작은 상자 하나에 다 들어 있다."

### 1.2 토폴로지 (전부 유선)

```
  PC0 ──Eth──┐                                                  ┌── Internet
  PC1 ──Eth──┤                                                  │    198.51.100.8
             ├── [HomeRouter WRT300N] ─Internet── G0/0 [ISP] G0/1 ┘    DNS · 웹
  HomeServer ─┘  LAN 192.168.0.1        203.0.113.2  .1       198.51.100.1
   (선택)         DHCP .100~            └── /30 ──┘
  ◀────────── 사설 (우리 집) ──────────▶◀───────── 공인 (인터넷) ─────────▶
```

| 장비 | 주소 | 비고 |
|---|---|---|
| HomeRouter LAN | `192.168.0.1/24` | PC의 게이트웨이이며 관리자 페이지 주소다 |
| HomeRouter WAN | `203.0.113.2/30` | 공인 주소 역할(통신사가 준 주소) |
| ISP G0/0, G0/1 | `203.0.113.1/30`, `198.51.100.1/24` | `192.168.0.0` 경로가 없다(일부러) |
| Internet 서버 | `198.51.100.8` | DNS(`www.student.test` A 레코드)와 HTTP |
| PC0, PC1 | DHCP `192.168.0.100~` | 공유기 LAN 포트에 Copper Straight-Through로 연결 |
| HomeServer (선택) | `192.168.0.10` 고정 | 포트포워딩 대상 |

{% hint style="info" %}
NOTE: `203.0.113.0/24`와 `198.51.100.0/24`는 문서와 교육용으로 예약된 공인 대역이다. 실제 누구의 주소도 아니다. `/30`은 주소 2개짜리이며 2일차 서브넷팅의 회수다. 라우터끼리 연결할 때 쓰는 크기다.
{% endhint %}

### 1.3 관리자 페이지 설정과 해석

PT의 WRT300N `GUI` 탭은 실제 집 공유기의 `192.168.0.1` 관리자 페이지와 거의 같다.

| 설정 | 해석 | 관련 노트 |
|---|---|---|
| Internet Setup = Static IP `203.0.113.2`, GW `203.0.113.1` | 공유기의 WAN, 즉 공인 쪽이다. 집에서는 보통 통신사가 DHCP로 준다 | [NAT와 포트포워딩](../day-10/lesson-9.md) |
| Router IP `192.168.0.1` | 공유기의 LAN, 즉 사설 쪽이며 집 안의 게이트웨이다 | 2일차 |
| DHCP Enabled, Start `.100`, Max 50 | 집 안 기기에 `.100`~`.149`를 빌려준다. `.1`~`.99`는 고정 IP용이다 | 8일차 `excluded-address`와 같은 발상 |
| Static DNS 1 `198.51.100.8` | DHCP로 DNS 서버 주소도 같이 나눠준다 | [DNS와 DHCP 다시 보기](../day-10/lesson-10.md) |

- NAT 설정 칸은 어디에도 없다. 공유기는 WAN과 LAN을 나눈 순간 NAT를 자동으로 켠다. 그래서 집에서 아무도 NAT를 설정한 적이 없다.

{% hint style="warning" %}
CAUTION: `Save Settings`를 화면마다 눌러야 저장된다. 가장 흔한 실수다. `Wireless` 탭은 건드리지 않는다.
{% endhint %}

## 2. 동작 원리

### 2.1 확인 결과와 이유

| 확인 | 결과 | 이유 |
|---|---|---|
| PC0 `ipconfig` | `192.168.0.100`, GW `.1`, DNS `198.51.100.8` | DHCP |
| PC1 `ipconfig` | `192.168.0.101` | 같은 LAN(공유기 안의 스위치) |
| `ping 198.51.100.8` | 성공 | 아래 질문 참조 |
| `ping www.student.test`, 웹 브라우저 | 성공 | DNS A 레코드 |
| Internet 서버에서 `ping 192.168.0.100` | 실패 | 인터넷은 사설 주소를 모른다. NAT는 밖에서 먼저 시작하는 통신을 막는다 |

질문: ISP 라우터에는 `192.168.0.0`으로 가는 경로가 없다. 5일차 기준이면 응답이 돌아오지 못해야 한다. 그런데 왜 ping이 되는가.

- ISP가 보는 출발지는 `192.168.0.100`이 아니라 `203.0.113.2`다.
- ISP는 `203.0.113.2`를 안다(직접 연결).
- NAT 덕분이다. 그 증거는 Simulation으로 확인한다.

마지막 줄(밖에서 먼저는 안 된다)은 [3. 왜 막아야 하나](lesson-3.md)(LEC-N2-11-005-DO)의 출발점이다.

### 2.2 Simulation: NAT가 바꾸는 순간

PC0에서 `198.51.100.8`로 ICMP를 한 칸씩 보내며 봉투를 연다.

| 구간 | Src IP | Dst IP | 비고 |
|---|---|---|---|
| PC0 → HomeRouter | `192.168.0.100` | `198.51.100.8` | 사설 |
| HomeRouter → ISP | `203.0.113.2` | `198.51.100.8` | 바뀌었다(NAT) |
| ISP → HomeRouter (응답) | `198.51.100.8` | `203.0.113.2` | |
| HomeRouter → PC0 | `198.51.100.8` | `192.168.0.100` | 되돌렸다(변환표) |

- 봉투를 클릭하고 `OSI Model` 탭에서 공유기의 `In Layers`와 `Out Layers`를 비교하면 3계층 IP가 바뀐 것이 보인다.
- PT 버전에 따라 ICMP는 ID 번호가, TCP는 포트 번호가 함께 바뀌는 것이 보인다. 이것이 PAT다.
- PC0과 PC1에서 동시에 보내면 공인 IP는 하나인데 포트로 구분되는 것이 보인다. 이것이 PAT의 핵심이다.

1단계에서 Simulation으로 ARP와 ping 봉투를 열어봤다(3일차). 11일차에는 그 봉투의 주소가 공유기에서 바뀌는 것을 본다.

### 2.3 포트포워딩: 밖에서 들어오는 문을 뚫는다

NAT는 나갈 때는 알아서 처리하지만 밖에서 먼저 들어오는 통신은 막는다. 집 안 서버를 인터넷에 공개하려면 구멍을 미리 뚫어 둬야 한다.

| | 규칙이 없으면 | 규칙을 넣으면 |
|---|---|---|
| 밖에서 `203.0.113.2:80` 호출 | 열리지 않는다 | HomeServer `192.168.0.10:80`으로 전달된다 |

```
GUI → Applications & Gaming → Single Port Forwarding
  External Port 80 → Internal Port 80 → IP Address 192.168.0.10 → Enabled
```

- 포트포워딩 대상 서버는 고정 IP여야 한다. DHCP로 주소가 바뀌면 규칙이 엉뚱한 기기를 가리킨다. → [10일차 서버란 무엇인가](../day-10/lesson-6.md)
- PT 버전에 따라 메뉴 이름이 `Single Port Forwarding`, `Port Range Forwarding`으로 다르다. 수업 전에 리허설한다.

{% hint style="info" %}
NOTE: 교실 VM은 브릿지라서 이 구멍을 뚫을 필요가 없었다. 교실 망에서 주소를 직접 받았기 때문이다. 편한 만큼 아무나 닿는다는 뜻이기도 하다. → [3. 왜 막아야 하나](lesson-3.md)
{% endhint %}

## 3. 약어와 용어

| 용어 | 뜻 |
|---|---|
| WAN | 인터넷 쪽 포트. 공인 주소를 쓴다 |
| LAN | 집 안 쪽 포트. 사설 주소를 쓴다 |
| NAT | 사설 주소와 공인 주소를 바꿔치기하는 기능 |
| PAT | 공인 IP 하나를 포트 번호로 나눠 쓰는 NAT |
| 포트포워딩 | 밖에서 온 특정 포트의 통신을 안쪽 서버로 전달하도록 미리 적어 두는 규칙 |
| APIPA | DHCP 응답이 없을 때 스스로 붙이는 `169.254.x.x` 주소 |
