# 7. 최소 개방 설계 — 얼마나 열 것인가

> 상위: [11일차 · 서버 보안](README.md)

## 🎯 학습 목표

- 서비스별로 **꼭 필요한 포트만** 골라 규칙을 설계한다
- **누구에게 열 것인가**(Anywhere / 특정 대역 / 특정 호스트)를 나눠 정한다
- 종이 위에서 **규칙표를 먼저 쓰고** 명령으로 옮기는 습관을 들인다
- 열어 둔 것을 **주기적으로 점검**해야 하는 이유를 안다

## 🌉 다리 놓기: "그래서 몇 개를 열어야 하나"

[6_리눅스_방화벽_ufw](lesson-6.md) 에서 도구는 다 배웠다. `allow` · `deny` · `from` · `delete`. 남은 질문은 하나다.

> 🗣 **"그래서 우리 서버는 뭘 열어야 합니까?"**

여기에 정답표는 없다. **쓰임에 따라 다르다.** 그래서 오늘은 **고르는 방법**을 익힌다.

---

## 📖 ① 두 가지를 따로 정한다 ⭐

방화벽 규칙 한 줄은 늘 **두 개의 질문**에 답한다.

```
sudo ufw allow from 192.168.0.0/24 to any port 22 proto tcp
                   └──── ① 누구에게? ────┘      └─ ② 무엇을? ─┘
```

| 질문 | 선택지 | 좁은 쪽 ← → 넓은 쪽 |
|------|--------|---------------------|
| **① 누구에게** | 특정 호스트 → 특정 대역 → Anywhere | `from 192.168.0.50` ← `from 192.168.0.0/24` ← (생략) |
| **② 무엇을** | 특정 포트 → 포트 범위 → 전체 | `22/tcp` ← `40000:40010/tcp` ← `allow all` |

> 💡 **둘 다 좁히는 게 최선이지만, 한쪽만 좁혀도 크게 낫다.**
> 관리용 포트(SSH)는 **① 을 좁히고**, 공개 서비스(웹)는 **② 만 좁힌다**는 것이 일반적인 감각이다.

---

## 📖 ② 서비스별 최소 개방표

10일차 포트표를 **"누구에게 열 것인가"** 관점으로 다시 쓴 것이다.

| 서비스 | 포트 | 보통 누구에게 | 메모 |
|--------|------|---------------|------|
| **SSH** | 22/tcp | **관리자 대역만** ⭐ | 전 세계에 열면 하루 수천 번 두드려 맞는다 |
| HTTP | 80/tcp | Anywhere | 공개가 목적이니까 |
| HTTPS | 443/tcp | Anywhere | 가능하면 80 대신 이쪽 |
| **FTP** | 21/tcp + 패시브 범위 | 내부망만 | **평문**이다. 가능하면 SFTP 로 → 12일차 |
| NFS | 2049/tcp | **내부망만** | 파일 공유 — 밖에 열 이유가 없다 |
| DNS | 53/**udp**(+tcp) | 내부망 / 용도에 따라 | 10일차 "UDP 인 것" 회수 |
| 메일 | 25 · 110 · 143 | 용도별로 | 25번을 아무에게나 열면 **스팸 중계**가 된다 |
| MySQL | 3306/tcp | **절대 Anywhere 금지** | 가능하면 `127.0.0.1` 만 듣게 |

> ⚠️ **데이터베이스 포트를 인터넷에 여는 것**은 사고의 단골이다. DB 는 **웹서버만** 접근하면 된다.
> 가장 좋은 건 방화벽 이전에 **서비스가 `127.0.0.1` 만 듣게** 하는 것이다 → [3_왜_막아야_하나](lesson-3.md) 의 **③ 서비스 설정** 자리.

## 📖 ③ 종이 먼저, 명령은 나중 ⭐

> 🗣 **"방화벽은 치면서 생각하면 늦습니다. 끊기고 나서 생각하게 되거든요."**

**규칙표를 먼저 쓴다.** 세 칸이면 충분하다.

| 누구에게 | 무엇을 | 왜 |
|----------|--------|-----|
| 관리자 PC `192.168.0.50` | 22/tcp | 내가 관리해야 하니까 |
| 교실 대역 `192.168.0.0/24` | 8000/tcp | 실습 결과를 서로 봐야 하니까 |
| (나머지 전부) | — | 기본 거부 |

**이제 그대로 옮긴다.**

```bash
sudo ufw allow from 192.168.0.50 to any port 22 proto tcp
sudo ufw allow from 192.168.0.0/24 to any port 8000 proto tcp
sudo ufw enable                      # 22 를 먼저 열었으니 안전 ⭐
sudo ufw status numbered             # 적은 대로 들어갔나 확인
```

- **표의 줄 수 = 규칙 수.** 표에 없는 줄이 `status` 에 있으면 **누가 왜 넣었는지 모르는 규칙**이다 → 지운다

## 🧪 실습 — 우리 서버의 규칙표 만들기

> 🖐 [대본 STEP 7](commands.md)

### 1단계 — 지금 열려 있는 것을 센다

```bash
ss -tuln                 # 공격 표면 목록
sudo ufw status numbered # 지금 방화벽 규칙
```

### 2단계 — 표를 손으로 쓴다 (3분, 짝과 함께)

| 누구에게 | 무엇을 | 왜 |
|----------|--------|-----|
| | | |

- **"왜" 칸을 못 채우는 줄은 열지 않는다.** 이게 최소 권한이다

### 3단계 — 명령으로 옮기고 검증한다

1. 규칙 입력 → `sudo ufw status numbered` 로 **표와 대조**
2. **옆자리에게 부탁** — 열어 준 포트는 ✅, 안 연 포트는 ❌ 인지 확인
3. 의도와 다르면 `sudo ufw delete <번호>` 로 고친다

### 4단계 — 쓸모없는 문 닫기

```bash
sudo systemctl disable --now vsftpd     # 안 쓰는 서비스는 아예 끈다
ss -tuln                                # 21번이 사라졌나
```

> ⭐ **방화벽으로 막는 것보다 서비스를 끄는 게 낫다.** 문이 아예 없으면 규칙도 필요 없다.

## 📖 ④ 열어 둔 것은 썩는다

규칙은 **만든 날이 가장 정확하고, 그 뒤로는 계속 낡는다.**

| 흔한 일 | 결과 |
|---------|------|
| 테스트하려고 잠깐 열고 **안 닫음** | 몇 달 뒤 아무도 이유를 모르는 구멍 |
| 퇴사한 담당자의 **집 IP** 가 허용 목록에 남음 | 관리되지 않는 통로 |
| 서비스는 껐는데 **규칙은 남음** | 나중에 그 포트를 다른 서비스가 쓰면 **의도치 않게 공개** |

```bash
sudo ufw status numbered         # 정기 점검: 이 줄, 아직 필요한가?
```

> 🗣 **"방화벽 점검은 여는 일이 아니라 지우는 일입니다."**

## 📝 강의 메모

- 🗣 **"종이 먼저"** 를 오늘의 습관으로 심는다. 실제로 **표를 손으로 쓰게** 한 뒤 명령을 치게 할 것
- ⭐ 2단계의 **"왜 칸을 못 채우면 열지 않는다"** 가 최소 권한 원칙의 가장 실용적인 형태다
- DB 포트 이야기는 **겁을 주되 짧게**. 실제 사고 사례로 한 문장이면 충분
- 4단계(서비스 끄기)는 **방화벽보다 상위 해법**이라는 점을 분명히 — 학생들은 방화벽만 생각한다
- 🔁 회수: 10일차 **포트표** → 오늘 **"누구에게 열 것인가"** 로 한 겹 더
- ⚠️ 12일차를 위해 **vsftpd 를 껐다면 12일차 FTP 절에서 다시 켠다**는 것을 메모해 둘 것 (그때 ① 설치는 건너뛰고 ③ 기동부터)
- ⏱ 15분. 시간이 모자라면 **2단계 표 쓰기만** 하고 명령은 12일차 ⑤ 단계로 넘긴다
