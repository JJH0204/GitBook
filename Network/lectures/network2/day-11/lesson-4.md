## 이전 학습과의 연결

[3. 왜 막아야 하나](lesson-3.md)(LEC-N2-11-005-DO)에서 통제가 걸리는 세 자리를 봤다. ① 네트워크 장비부터 다룬다.

그때 `access-list 1`은 NAT로 변환할 대상을 고르는 목록이었다. 이번에는 같은 문법으로 통과시킬 대상을 고르는 목록을 만든다.

ACL은 주소를 골라내는 목록이다. 그 목록을 NAT에 쓰면 변환 대상이 되고, 인터페이스에 붙이면 검문소가 된다.

## 1. 구성 요소

### 1.1 ACL: 라우터의 검문소

ACL(Access Control List, 접근 제어 목록)은 라우터를 지나가려는 패킷을 조건에 따라 허용(permit) 또는 거부(deny)하는 규칙 목록이다.

```
   들어오는 패킷
        │
        ▼
   ┌─────────────────────────┐
   │ 1번 줄 — 조건에 맞나?    │ ─ 맞다 ─▶ permit/deny 하고 【끝】
   │ 2번 줄 — 조건에 맞나?    │ ─ 맞다 ─▶ permit/deny 하고 【끝】
   │ 3번 줄 — 조건에 맞나?    │ ─ 맞다 ─▶ permit/deny 하고 【끝】
   │ (보이지 않는 마지막 줄)   │
   │   deny any  ←─────────── 아무것도 안 맞으면 여기
   └─────────────────────────┘
```

| 성질 | 뜻 | 실수하면 |
|---|---|---|
| 위에서부터 순서대로 | 처음 맞는 줄에서 검사가 끝난다 | 넓은 규칙을 위에 두면 아래 줄은 영원히 읽히지 않는다 |
| 암묵적 deny any | 목록 맨 끝에 보이지 않는 "나머지 전부 거부"가 있다 | `deny`만 써 놓으면 전부 막힌다 |
| 인터페이스에 붙여야 동작 | 만들기만 해서는 아무 일도 일어나지 않는다 | `ip access-group`을 빠뜨린다 |

비유(아파트 정문 경비 명단): 명단을 위에서부터 훑다가 이름을 찾는 순간 그대로 처리하고 더 보지 않는다. 명단 맨 아래에는 눈에 보이지 않는 글씨로 "명단에 없으면 돌려보냄"이 적혀 있다.

{% hint style="danger" %}
WARNING: `deny` 규칙만 하나 쓰고 끝내면 그 외 전부도 막힌다. 암묵적 deny any 때문이다. 막고 싶은 것을 `deny`했으면 나머지를 살릴 `permit any`를 반드시 붙인다.
{% endhint %}

**번호로 종류가 갈린다**

| 종류 | 번호 | 무엇을 보나 | 문서 |
|---|---|---|---|
| 표준(Standard) | 1~99(1300~1999) | 출발지 IP만 | 이 문서 |
| 확장(Extended) | 100~199(2000~2699) | 출발지 + 목적지 + 프로토콜 + 포트 | [5. ACL 확장](lesson-5.md) |

### 1.2 와일드카드 마스크: 5일차의 그것

ACL은 서브넷 마스크가 아니라 와일드카드 마스크를 쓴다. 5일차 OSPF의 `network` 명령에서 이미 만났다.

```
서브넷 마스크   255.255.255.0     1 = "이 자리는 같아야 한다"
와일드카드      0.  0.  0.255     0 = "이 자리는 같아야 한다"  ← 반대
                                255 = "이 자리는 아무래도 좋다"
```

와일드카드는 서브넷 마스크를 뒤집은 것이다. `255 - 각 자리`로 바로 구한다.

| 쓰고 싶은 범위 | 서브넷 마스크 | 와일드카드 | 줄여 쓰기 |
|---|---|---|---|
| `192.168.20.0` 대역 전체(/24) | `255.255.255.0` | `0.0.0.255` | |
| `192.168.20.10` 한 대만 | `255.255.255.255` | `0.0.0.0` | `host 192.168.20.10` |
| 모든 주소 | - | `255.255.255.255` | `any` |

```
255.255.255.0
255.255.255.255  -  255.255.255.0  =  0.0.0.255     ← 이렇게 구한다
```

## 2. 동작 원리

### 2.1 표준 ACL: 만들고 붙이기

**만들기**

```
Router(config)# access-list 10 deny   host 192.168.20.10
Router(config)# access-list 10 permit any
                        │      │       └── 대상
                        │      └── permit / deny
                        └── 번호 (1~99 = 표준)
```

**붙이기: 인터페이스에 적용해야 산다**

```
Router(config)# interface g0/0
Router(config-if)# ip access-group 10 out
                                   │   └── in  = 인터페이스로 들어올 때 검사
                                   │       out = 인터페이스에서 나갈 때 검사
                                   └── ACL 번호
```

`in`과 `out`은 라우터 입장에서 본다. 패킷이 라우터 안으로 들어오면 `in`, 라우터 밖으로 나가면 `out`이다.

**확인과 삭제**

```
Router# show access-lists              # 규칙 목록 + 몇 번 걸렸는지(match 수)
Router# show ip interface g0/0         # 어느 ACL 이 붙어 있나
Router(config)# no access-list 10      # 삭제. 번호 전체가 통째로 지워진다
```

{% hint style="warning" %}
CAUTION: `no access-list 10`은 10번 ACL 전체를 지운다. 한 줄만 고치려면 전체를 메모장에 적어 두고 다시 입력하는 편이 빠르다.
{% endhint %}

### 2.2 어디에 붙이나: 표준은 목적지 가까이

표준 ACL은 출발지만 본다. 출발지 근처에 두면 그 PC가 어디로 가든 전부 막힌다.

```
[PC_인사 .20.10]──┐                            ┌── 서버 192.168.10.100
                  ├──[SW2]──[R1]──[SW1]────────┤
[PC_개발 .20.11]──┘         g0/1    g0/0
                           .20.254  .10.254

g0/1 in  에 붙이면 : 인사 PC 는 인터넷도 · 다른 어디도 못 간다 (과잉 차단)
g0/0 out 에 붙이면 : 인사 PC 가 "서버망으로 갈 때만" 막힌다 (올바른 위치)
```

| 종류 | 붙이는 위치 | 이유 |
|---|---|---|
| 표준 | 목적지 가까이 | 출발지만 보므로 멀리 두면 다른 통신까지 죽는다 |
| 확장 | 출발지 가까이 | 목적지·포트까지 보므로 일찍 버려도 안전하다 → [5. ACL 확장](lesson-5.md) |

"표준은 목적지 가까이, 확장은 출발지 가까이."

## 3. 약어와 용어

| 용어 | 뜻 |
|---|---|
| ACL | Access Control List. 패킷을 조건에 따라 허용 또는 거부하는 규칙 목록 |
| 암묵적 deny any | 모든 ACL 끝에 보이지 않게 붙어 있는 "나머지 전부 거부" |
| 와일드카드 마스크 | `0`은 같아야 하는 자리, `255`는 상관없는 자리인 마스크 |
| `host` | 와일드카드 `0.0.0.0`의 줄임말 |
| `any` | 와일드카드 `255.255.255.255`의 줄임말(모든 주소) |
| match 수 | `show access-lists`에서 규칙에 걸린 패킷 횟수 |
