## 개요

8일차에 회사망에 서비스를 올렸다. SSH, DHCP, DNS, FTP 모두 패킷 트레이서의 Server0에서 체크박스를 켜서 만들었다. 그런데 실제 회사 서버실의 서버에는 체크박스가 없다. 그 안에서 돌아가는 것은 대부분 리눅스다.

2단계는 그 서버를 직접 만든다. 첫날은 서버의 운영체제를 설치하고, 첫 서버(SSH)를 직접 구축하고, 접속하는 날이다.

| 질문 | 오늘의 답 | 노트 |
|---|---|---|
| 서버는 왜 리눅스를 쓰나? | 무료, 안정, 원격 관리, 화면이 필요 없다 | 1 |
| 내 PC에 서버를 어떻게 한 대 더 놓나? | 가상머신(VirtualBox) + 우분투 설치 | 2 |
| 첫 서버는? | `apt`로 openssh-server 설치, `systemctl`로 켜기, Windows에서 SSH 접속 | 2 |

NOTE: 실제 진행(2026-09-19)은 설치, SSH 서버 구축, 접속, 첫 명령 몇 개까지 했다. 원래 계획의 나머지(파일 시스템, 파일 다루기, 권한, 리눅스 네트워크, AI 검증, 퀴즈)는 10일차 오전으로 옮겼다. → [10일차](../day-10/README.md)

## 오늘의 목표

- 서버가 리눅스를 쓰는 이유와 커널, 쉘, 배포판을 구분한다.
- 호스트, 게스트, 하이퍼바이저를 구분하고, VirtualBox에 Ubuntu Server 24.04 LTS를 설치한다.
- 패키지 관리자(`apt`)로 openssh-server를 설치하고, `systemctl`로 켜기, 자동 시작, 상태 확인을 한다.
- Windows 터미널에서 SSH로 접속하고, 명령의 모양 `명령어 [옵션] [대상]`을 안다.

## 오늘의 실습 환경

```
┌──────────── 내 Windows PC (호스트) ────────────────────┐
│                                                        │
│  Windows 터미널 ── ssh student@192.168.x.x ──┐         │
│                                              │         │
│                   ┌──────────────▼───────────────┐     │
│                   │  VirtualBox VM (게스트)       │     │
│                   │  Ubuntu Server 24.04 LTS     │     │
│                   │  192.168.x.x (브릿지 어댑터)  │     │
│                   └──────────────────────────────┘     │
└────────────────────────────────────────────────────────┘
```

| 항목 | 값 |
|---|---|
| 가상화 | VirtualBox 7.x |
| OS | Ubuntu Server 24.04 LTS (화면 없는 서버판) |
| VM 사양 | CPU 2, RAM 2048MB, 디스크 25GB |
| 네트워크 | 브릿지 어댑터. 강의실 공유기에서 IP를 직접 받는다 |
| SSH | 설치 후 직접 구축한다(`apt install openssh-server`, `systemctl enable --now ssh`) |

{% hint style="warning" %}
CAUTION: 사양이 부족하거나 VirtualBox가 동작하지 않는 PC는 Plan B인 WSL을 쓴다. → [2. 가상머신과 설치](lesson-2.md)
{% endhint %}

## 강의 메모

- 도입 질문은 "8일차 Server0에서 DNS 체크박스를 켰다. 그 체크박스 뒤에는 무엇이 있었을까?"이다. 서비스는 프로그램이고, 그 프로그램이 도는 OS가 리눅스다.
- 오늘의 핵심 질문은 "서버에는 왜 모니터가 없을까?"이다. 서버는 멀리서(SSH) 관리한다.
- SSH를 설치 화면에서 체크하지 않고 설치 후 직접 구축했다. "첫 서버 구축" 경험이 목적이다. `status`의 `Server listening on 0.0.0.0 port 22`는 10일차 오후(포트, LISTEN)에서 회수한다.
- 비유: 커널은 엔진, 쉘은 운전대, 배포판은 완성차 브랜드, VM은 집 안의 원룸, apt는 앱스토어다.
- 떡밥: VM이 받은 `192.168.x.x`는 누가 줬는가. 10일차 DHCP에서 회수한다.
- 브릿지라서 VM 주소가 매주 바뀔 수 있다. 수업 시작마다 `ip a` 확인을 습관으로 들인다.
- 브릿지 선택이 11일차 서버 보안의 출발점이다. 교실의 다른 PC가 내 서버에 닿는다.
- VM은 끄지 말고 저장하거나 `sudo poweroff`로 종료한다. 다음 주에 같은 VM을 계속 쓴다(9, 10, 11, 12일차).
