12일차까지 우리는 **서버를 세우는 법**을 배웠다. 설치 · 설정 · 기동 · 확인 · 개방 · 검증.
그런데 그 서버에 **무엇을 올릴 것인가?** 올릴 **코드**는 어디에 두고, 어떻게 관리하고, 어떻게 서버로 보낼까?

오늘부터 네 번은 **"내가 만든 것을 세상에 올리는" 한 편**이다.

```
 13일차 Git/GitHub ──▶ 14일차 Docker ──▶ 15일차 클라우드·API ──▶ 16일차 배포 종합
   코드를 관리한다        한 덩어리로 묶는다    남의 서버를 빌린다(개념)   내 서버에 올린다
```

| 질문 | 오늘의 답 | 노트 |
|------|-----------|------|
| `최종_진짜_최종_v3.zip` 을 왜 그만둬야 하나? | **버전 관리** — 변경 이력을 도구가 기억한다 | 1 |

## 🎯 오늘의 목표

- **버전 관리**가 무엇이고 왜 필요한지 설명한다
- Git 의 **세 자리**(작업 디렉터리 · 스테이지 · 저장소)를 구분하고 `add` · `commit` 을 이해한다
- `git log` 로 **이력을 읽고**, `git diff` 로 **무엇이 바뀌었는지** 본다
- GitHub 에 **SSH 키로 인증**하고 `push` · `pull` 한다 (12일차 키 인증 회수)
- **브랜치**를 만들고 합치며, **충돌**을 한 번 내고 직접 푼다
- **서버에서 `git clone`** 으로 코드를 받아 웹으로 띄운다

### 🚨 수업 시작 전 — WSL 네트워크 모드부터 확인한다

WSL 은 모드에 따라 **밖에서 보이는 방식이 다르다.** 5번 절(배포 확인)이 여기에 걸린다.

```powershell
# 🪟 Windows PowerShell
Get-Content $env:USERPROFILE\.wslconfig    # networkingMode 줄이 있나
```

```bash
# 🐧 WSL
ip route get 1.1.1.1 | head -1     # ⭐ src 뒤가 내 WSL 주소 (가장 정확)
ip -br a | grep eth0               # 참고 — VPN 이 깔려 있으면 eth0 가 엉뚱할 수 있다
```

| 보이는 주소 | 모드 | 내 Windows 에서 `localhost` | **옆자리**에서 |
|-------------|------|------------------------------|----------------|
| `172.x.x.x` | **NAT** (기본) | ✅ 된다 (WSL 자동 포워딩) | ❌ **안 된다** |
| `192.168.x.x` (Windows 와 같음) | **mirrored** | ✅ 된다 | ✅ 된다 |

> 📌 **검증은 「내 Windows 브라우저 + `localhost`」를 기본**으로 한다. **두 모드 모두에서 동작**하기 때문이다.
> 옆자리에서 보여주는 건 **mirrored 일 때만 보너스**로.

<details><summary>mirrored 로 바꾸고 싶다면 (선택 · Windows 11 22H2 이상만)</summary>

```powershell
notepad $env:USERPROFILE\.wslconfig
```

```ini
[wsl2]
networkingMode=mirrored
```

```powershell
wsl --shutdown        # 끄고 다시 시작하면 적용
```

⚠️ **Windows 10 에서는 안 된다.** 학생 PC 버전이 섞여 있으면 **전환하지 말고 NAT 기준으로** 진행한다.
</details>

> ⚠️ **GitHub 계정이 필요하다.** 수업 전 공지해서 **미리 가입**해 오게 한다 (이메일 인증 때문에 시간을 먹는다).

## 📝 강의 메모

- 🗣 도입: **"12일차까지 서버를 세웠습니다. 그런데 그 서버에 뭘 올리죠?"**
- ⭐⭐ **오늘의 회수**
  1. 12일차 **SSH 키 인증(`ssh-keygen` · `authorized_keys`)** → **GitHub 에 공개키 등록** — *"지난주에 만든 그 키, 오늘 또 씁니다"*
  2. 10일차 **`nano`** → 커밋 메시지 편집 · `.gitignore` 작성
  3. 10일차 **파이프 · `grep`** → `git log --oneline | head`
  4. 12일차 **여섯 단계** → 5번에서 **"코드만 바꿔 넣으면 끝"** 을 체감
- ⚠️ 최대 병목
  1. **GitHub 가입·이메일 인증** → 반드시 사전 공지
  2. `git commit` 이 **에디터(vim)를 띄워서 못 빠져나온다** → `git config --global core.editor nano` 를 **STEP 1 에서 먼저** 설정
  3. **충돌(conflict)에서 멘붕** → 충돌 표시 `<<<<<<<` 를 칠판에 그려 두고 시작
- 📌 발표용 Excalidraw 드로잉은 **아직 없다** (세 자리 그림 · 브랜치 그림은 판서)
- ✅ **명령 실측 검증 (2026-10-16 · WSL Ubuntu 24.04 / git 2.43.0)** — STEP 1~4 전부 실행해 확인. 고친 것:
  1. 🚨 **STEP 4-2 충돌 실습 순서** — 원래 순서(main 커밋 → 브랜치)는 **Fast-forward 로 끝나 충돌이 안 난다**. 브랜치를 먼저 만드는 순서로 수정
  2. 🚨 **`apt install nginx` 는 80 이 막혀 있어도 에러 없이 끝난다** (설치 스크립트가 기동 실패를 삼킨다) → `is-active` · `journalctl` 로 확인하게 수정
  3. **주소 확인**은 `ip route get 1.1.1.1` 로 — `ip -br a | grep eth0` 는 VPN 환경에서 엉뚱한 주소를 준다(실측)
  4. nginx 1.24 · `/etc/nginx/sites-available/default` 경로 유효 확인
  - ⚠️ **남은 미검증**: nginx 실제 설치·기동, `git clone` 후 브라우저 확인은 **교실 PC 에서** (검증용 WSL 은 실서버라 설치하지 않았다)
