## 📖 ① 버전 관리가 푸는 문제 세 가지

| 문제 | 파일명으로 할 때 | 버전 관리 도구로 할 때 |
|------|------------------|------------------------|
| **이력** — 언제 · 누가 · 왜 고쳤나 | 파일명에 안 적힌다 | **커밋마다 기록**된다 |
| **되돌리기** — 어제 것으로 | 운 좋으면 복사본이 있다 | **아무 시점으로든** 돌아간다 |
| **협업** — 둘이 같은 파일을 고쳤다 | 한 사람 것이 **덮어써진다** | **합치고**, 겹치면 **충돌로 알려준다** |

> 📌 **Git** = 2005년에 리눅스 커널을 관리하려고 만든 **분산 버전 관리 시스템**.
> **Git ≠ GitHub.** Git 은 **도구**, GitHub 는 그 결과물을 올려 두는 **웹 서비스**다.

> 💡 **비유: 게임 세이브 파일.** 커밋 = **세이브 지점**. 보스전에서 죽으면 **마지막 세이브로** 돌아간다.
> 파일명에 날짜를 붙이는 건 **세이브 없이 스크린샷만 찍는 것**과 같다.

## 📖 ② Git 의 세 자리 ⭐ — 오늘 하루를 관통하는 그림

```
 ① 작업 디렉터리        ② 스테이지(Staging)        ③ 저장소(Repository)
   내가 고치는 곳    ──▶    "이번에 담을 것"    ──▶    확정된 이력
                   git add                    git commit

   파일을 고친다          장바구니에 담는다            영수증을 끊는다
```

| 자리 | 다른 이름 | 무슨 상태인가 | 확인 |
|------|-----------|---------------|------|
| ① **작업 디렉터리** | Working Directory | 고쳤지만 **아직 Git 이 모른다** | `git status` 에 빨강 |
| ② **스테이지** | Index · Staging Area | **이번 커밋에 넣겠다**고 고른 것 | `git status` 에 초록 |
| ③ **저장소** | Repository (`.git/`) | **확정된 이력** | `git log` |

> 💡 **비유: 장보기.** ① 매대에서 물건을 고르고(수정) → ② **장바구니에 담고**(`add`) → ③ **계산한다**(`commit`).
> 담지 않은 물건은 계산되지 않는다. **`add` 를 빠뜨리면 그 파일은 커밋에 안 들어간다.**

> 🗣 **"왜 두 단계죠? 그냥 저장하면 되잖아요."**
> → **고친 것 전부가 아니라, 의미가 맞는 것만 골라 묶기 위해서**다.
> 예) 로그인 기능 3개 파일 + 오타 수정 1개 파일을 고쳤다면 → **커밋 두 개**로 나누는 게 좋다.

## 📖 ③ 커밋 — 저장이 아니라 "의미 있는 한 묶음"

```
 커밋 = 변경 묶음 + 누가 + 언제 + 왜(메시지) + 고유 번호(해시)
```

```
commit a3f9c21e8b...          ← 해시 (지문)
Author: student <me@...>
Date:   2026-10-24

    로그인 폼 유효성 검사 추가       ← 메시지 = "왜"
```

**좋은 커밋 메시지**

| ❌ | ✅ |
|---|---|
| `수정` · `ㅇㅇ` · `asdf` | `로그인 폼 유효성 검사 추가` |
| `여러 가지 고침` | `nginx 설정에서 포트 8080 으로 변경` |

- 규칙 하나만 — **"무엇을 왜 했는지, 한 줄로"**
- 🤖 AI 에게 `git diff` 를 보여주고 **메시지 초안**을 받아도 된다. 단, **내가 읽고 고친다** → [10일차 AI 검증](../day-10/lesson-5.md)

> ⚠️ **커밋은 "자주, 작게".** 하루 종일 고치고 한 번에 커밋하면 **되돌릴 지점이 없다.**

## 📖 ④ 오늘 쓸 용어 정리

| 용어 | 뜻 |
|------|-----|
| **저장소 (Repository · repo)** | 이력이 담긴 프로젝트 폴더 (`.git/` 이 들어 있다) |
| **커밋 (Commit)** | 변경 한 묶음 = 세이브 지점 |
| **브랜치 (Branch)** | 갈라진 작업 줄기 → [4_브랜치와_협업](lesson-4.md) |

| **`push` / `pull`** | 내 것을 **올리기** / 남의 것을 **받기** |
| **`clone`** | 원격 저장소를 **통째로 복제** → [5_서버에_배포해보기](lesson-5.md) |

## 📝 강의 메모

- 🗣 도입은 **`최종_진짜_최종.docx` 스크린샷** 한 장이면 끝난다 — 모두 웃고, 모두 공감한다
- ⭐ **세 자리 그림을 칠판에 그리고 하루 종일 지우지 않는다.** `git status` 를 칠 때마다 **"지금 어느 자리죠?"**
- **Git ≠ GitHub** 를 여기서 못 박는다. 뒤에서 계속 헷갈린다
- 장바구니 비유가 가장 잘 먹힌다 — `add` 를 **"담는다"**, `commit` 을 **"계산한다"** 로 계속 부를 것
- ⏱ 이론 20분. 실습은 2번부터 — **여기서 오래 끌지 않는다**
