## 1. 목적

첫날 칠판에 이렇게 적었다. "네트워크란 무엇인가?" 그때는 두 대의 컴퓨터가 0과 1을 주고받는 이야기였다. 오늘 여러분은 내가 만든 것이 브라우저에 열리는 것을 보고 있다. 이 문서는 그 사이의 16일을 되짚는다.

## 2. 구성 요소

### 16일 지도

```
 1단계 — 네트워크가 무엇인가 (1~8일차)
 ──────────────────────────────────────────────────────────
  1  네트워크란 · 0과 1 · IP · LAN · 프로토콜 · 캐스트
  2~4 주소를 쪼갠다(서브넷) · 길을 찾는다(라우팅)
  5~6 라우터가 길을 배우는 법(RIP, OSPF)
  7~8 스위치를 나눈다(VLAN, 트렁크, STP) · 서버 설정

 2단계 — 그 위에 무엇을 세우는가 (9~16일차)
 ──────────────────────────────────────────────────────────
  9   리눅스를 만난다 · SSH로 들어간다
  10  파일 · 권한 · 포트 · 패킷을 들여다본다
  11  처음으로 닫는다(공격 표면, ACL)
  12  서버를 세우는 여섯 단계. 여섯 번 반복
  13  코드를 관리한다(Git) · 두 경로로 올린다(Pages, 내 서버)
  14  환경을 묶는다(Docker) · 파일에 적는다(Compose)
  15  원하는 상태를 적는다(쿠버네티스)
  16  내가 만든 것을 클러스터에 올리고 연다
```

1일차의 "0과 1"과 오늘의 "롤링 업데이트" 사이에 16일이 있다.

### 계속 나온 생각 다섯

16일 동안 도구는 계속 바뀌었다. 그런데 생각은 다섯 개뿐이었다.

**하나. 서버는 종류가 달라도 세우는 순서가 같다.**

```
 ① 설치  ② 설정  ③ 기동  ④ 확인  ⑤ 개방  ⑥ 검증
```

| 날 | 무엇을 세웠나 | ③ 기동 | ④ 확인 |
|---|---|---|---|
| 12일차 | SSH, FTP, Samba, DNS, 웹, DB | `systemctl enable --now` | `ss -tulnp` |
| 13일차 | nginx | 같다 | 설치 성공은 서비스 동작이 아니다 |
| 14일차 | 컨테이너 | `docker run -d` | `docker ps` |
| 15일차 | 클러스터 | `kind create cluster` | `kubectl get nodes` |

④ 확인을 빼먹지 않는다. 13일차 nginx가 조용히 뜨지 않은 일을 기억한다.

**둘. 열지 않은 것은 닫혀 있다(최소 개방).**

| 날 | 여는 방법 | 열지 않으면 |
|---|---|---|
| 11일차 | ACL `permit` | 암묵적 deny |
| 12일차 | `ufw allow` | 밖에서 타임아웃 |
| 14일차 | `-p` | 밖에서 보이지 않는다 |
| 16일차 | NodePort, Ingress | ClusterIP로 남는다 |

{% hint style="danger" %}
WARNING: 예외를 하나 봤다. 14일차 Docker는 `ufw`를 우회한다. 규칙을 아는 것과 규칙이 통하지 않는 자리를 아는 것은 다르다.
{% endhint %}

**셋. 되돌릴 수 있게 해 둔다.**

| 날 | 쌓아 두는 것 | 되돌리는 명령 |
|---|---|---|
| 13일차 | 커밋 | `git checkout` |
| 14일차 | 이미지 태그 | `docker run mysite:1.0` |
| 16일차 | 리비전 | `kubectl rollout undo` |

그래서 3초 멈춤 목록이 있었다. `rm -rf`, `git reset --hard`, `docker system prune -a`, `kind delete cluster`이다.

**넷. 기억하지 말고 적어 둔다.**

```
 13일차   코드를 Git에
 14일차   + 돌리는 방법 (Dockerfile, compose.yaml)
 15일차   + 원하는 상태 (매니페스트)
 16일차   + 클러스터 모양까지 (kind-config.yaml)
```

고치는 곳은 언제나 하나이다. 서버에서 직접 고치지 않고, `scale`로 바꾼 것을 파일에 반영하고, 비밀은 파일 바깥에 둔다.

**다섯. 한 포트에 한 프로그램.**

10일차 `python3 -m http.server` 두 번, 12일차 bind9와 `systemd-resolved`, 13일차 Apache와 nginx, 14일차 컨테이너 80번. 네 번 만났다. 같은 오류를 네 번 만나면 다섯 번째는 메시지만 보고 안다. 그것이 실력이다.

### 지금 할 수 있는 일

- 리눅스 서버에 SSH 키로 들어가 서비스를 세우고 확인하고 연다.
- 방화벽과 ACL로 필요한 것만 열고, 왜 안 되는지 네 단계로 좁힌다.
- Git으로 코드를 관리하고 충돌을 직접 푼다.
- Dockerfile로 환경째 묶어 어느 PC에서든 같은 결과를 낸다.
- Compose와 매니페스트로 환경 전체를 파일에 적어 재현한다.
- 쿠버네티스에 올리고, 끊김 없이 바꾸고, 되돌린다.

이력서에 적을 수 있는 결과물이 셋 남았다. GitHub 저장소, GitHub Pages 주소, Dockerfile과 매니페스트가 든 저장소이다.

| 방향 | 무엇을 | 왜 |
|---|---|---|
| 자격증 | CCNA, 리눅스마스터 | 1단계와 9~12일차가 그대로 범위이다 |
| 더 깊은 쿠버네티스 | Helm, Ingress 컨트롤러, 모니터링 | 오늘 개념까지만 본 것들 |
| 클라우드 | AWS, 네이버 클라우드 무료 티어 | ACG와 보안그룹이 11일차 ACL이다 |
| 자동화 | GitHub Actions(CI/CD) | 13일차의 `pull`을 자동으로 |
| 보안 | 정보보안 과정 | 11일차와 14일차에서 맛본 것을 제대로 |

어디로 가도 11일차와 12일차가 바닥에 깔린다. 클라우드의 보안그룹도, 쿠버네티스의 Service 타입도 "필요한 것만 연다"는 한 문장이다.

## 3. 동작 원리

이 문서는 절차가 아니라 요약이다. 읽는 순서는 다음과 같다.

1. 16일 지도를 보고 각 날이 어느 단계인지 짚는다.
2. 다섯 가지 생각을 번호로 적고, 각 생각이 나온 날을 학생이 말한다.
3. "지금 할 수 있는 일"은 학생이 자기 입으로 말한다.
4. "다음에 볼 것"에서 정보보안 과정을 안내한다.

## 4. 약어와 용어

| 용어 | 뜻 |
|---|---|
| 최소 개방 | 필요한 것만 열고 나머지는 닫아 두는 원칙 |
| 공격 표면(attack surface) | 밖에서 닿을 수 있는 입구의 총합 |
| CI/CD | 변경을 자동으로 검사하고(CI) 배포하는(CD) 방식 |
| ACG | 네이버 클라우드의 접근 제어 그룹. 방화벽 규칙 묶음 |

## 강의 메모

- 25분을 반드시 남긴다. 여기가 잘리면 과정이 흐지부지 끝난다. 4번 절을 줄여서라도 지킨다.
- 1일차 노트를 실제로 띄운다. 첫 장의 "네트워크란?"을 보여 주고 시작하면 공기가 달라진다.
- 다섯 가지를 칠판에 먼저 번호로 적고 하나씩 채운다. 학생이 사례를 말하게 하면 더 좋다. "여섯 단계는 어디서 또 나왔나?"라고 물으면 학생이 12, 13, 14, 15일차를 스스로 꿴다.
- "지금 할 수 있는 일"은 학생이 직접 말하게 한다. 자기가 할 수 있게 된 것을 자기 입으로 말하는 것이 수료식이다.
- "다음에 볼 것"에서 정보보안 과정을 자연스럽게 안내한다(11일차와 14일차가 맛보기였다).
- 마지막 한 줄은 읽지 않고 말한다. 짧게, 한 번만 한다. 내용은 다음과 같다. "16일 전에 여러분은 '네트워크란 무엇인가'를 물었다. 오늘 여러분이 만든 것이, 여러분이 세운 클러스터에서, 브라우저에 떴다. 그 사이를 전부 여러분 손으로 지었다."
