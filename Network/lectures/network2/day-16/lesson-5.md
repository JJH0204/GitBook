## 🌉 다리 놓기: 1일차 첫 질문

첫날 칠판에 이렇게 적었다.

> 🗣 **"네트워크란 무엇인가?"**

그때는 두 대의 컴퓨터가 **0 과 1** 을 주고받는 이야기였다. 오늘 여러분은 **내가 만든 것이 브라우저에 열리는 것**을 보고 있다.

## 📖 ① 16일 지도

```
 1단계 — 네트워크가 무엇인가 (1~8일차)
 ──────────────────────────────────────────────────────────
  1  네트워크란 · 0과 1 · IP · LAN · 프로토콜 · 캐스트
  2~4 주소를 쪼갠다 (서브넷) · 길을 찾는다 (라우팅)
  5~6 라우터가 길을 배우는 법 (RIP · OSPF)
  7~8 스위치를 나눈다 (VLAN · 트렁크 · STP) · 서버 설정

 2단계 — 그 위에 무엇을 세우는가 (9~16일차)
 ──────────────────────────────────────────────────────────
  9   리눅스를 만난다 · SSH 로 들어간다
  10  파일 · 권한 · 포트 · 패킷을 들여다본다
  11  처음으로 닫는다 (공격 표면 · ACL)
  12  ⭐ 서버를 세우는 여섯 단계 — 여섯 번 반복
  13  코드를 관리한다 (Git) · 두 경로로 올린다 (Pages · 내 서버)
  14  환경을 묶는다 (Docker) · 파일에 적는다 (Compose)
  15  원하는 상태를 적는다 (쿠버네티스)
  16  ⭐ 내가 만든 것을 클러스터에 올리고 연다
```

> 🗣 **"1일차의 '0과 1' 과 오늘의 '롤링 업데이트' 사이에, 16일이 있습니다."**

## 📖 ② 계속 나온 생각 다섯 ⭐

16일 동안 **도구는 계속 바뀌었다.** 그런데 **생각은 다섯 개뿐**이었다.

### 하나. 서버는 종류가 달라도 **세우는 순서가 같다**

```
 ① 설치  ② 설정  ③ 기동  ④ 확인  ⑤ 개방  ⑥ 검증
```

| 날 | 무엇을 세웠나 | ③ 기동 | ④ 확인 |
|----|---------------|--------|--------|
| 12일차 | SSH · FTP · Samba · DNS · 웹 · DB | `systemctl enable --now` | `ss -tulnp` |
| 13일차 | nginx | 같다 | **설치 성공 ≠ 서비스 동작** ⭐ |
| 14일차 | 컨테이너 | `docker run -d` | `docker ps` |
| 15일차 | 클러스터 | `kind create cluster` | `kubectl get nodes` |

> ⭐ **④ 확인을 빼먹지 않는다.** 13일차 nginx 가 **조용히 안 뜬** 일을 기억하라.

### 둘. **열지 않은 것은 닫혀 있다** (최소 개방)

| 날 | 여는 방법 | 안 열면 |
|----|-----------|---------|
| 11일차 | ACL `permit` | **암묵적 deny** |
| 12일차 | `ufw allow` | 밖에서 타임아웃 |
| 14일차 | **`-p`** | 밖에서 안 보인다 |
| 16일차 | **NodePort · Ingress** | ClusterIP 로 남는다 ⭐ |

> 🚨 그리고 **예외를 하나 봤다** — 14일차 **Docker 는 `ufw` 를 우회한다.** 규칙을 아는 것과, **규칙이 안 통하는 자리를 아는 것**은 다르다.

### 셋. **되돌릴 수 있게 해 둔다**

| 날 | 쌓아 두는 것 | 되돌리는 명령 |
|----|--------------|---------------|
| 13일차 | 커밋 | `git checkout` |
| 14일차 | 이미지 태그 | `docker run mysite:1.0` |
| 16일차 | 리비전 | **`kubectl rollout undo`** |

> 🛑 그래서 **3초 멈춤 목록**이 있었다 — `rm -rf` · `git reset --hard` · `docker system prune -a` · `kind delete cluster`.

### 넷. **기억하지 말고 적어 둔다**

```
 13일차   코드를 Git 에
 14일차   + 돌리는 방법 (Dockerfile · compose.yaml)
 15일차   + 원하는 상태 (매니페스트)
 16일차   + 클러스터 모양까지 (kind-config.yaml)  ⭐
```

> ⭐ **고치는 곳은 언제나 하나다.** 서버에서 직접 고치지 않고, `scale` 로 바꾼 것을 파일에 반영하고, 비밀은 파일 바깥에 둔다.

### 다섯. **한 포트에 한 프로그램**

10일차 `python3 -m http.server` 두 번 · 12일차 bind9 와 `systemd-resolved` · 13일차 Apache 와 nginx · 14일차 컨테이너 80번. **네 번 만났다.**

> 🗣 **"같은 에러를 네 번 만나면, 다섯 번째는 메시지만 보고 압니다. 그게 실력입니다."**

## 📖 ③ 여러분이 지금 할 수 있는 일

- 리눅스 서버에 **SSH 키로** 들어가 서비스를 **세우고 확인하고 연다**
- **방화벽과 ACL** 로 필요한 것만 열고, **왜 안 되는지** 네 단계로 좁힌다
- **Git** 으로 코드를 관리하고 **충돌을 직접 푼다**
- **Dockerfile** 로 환경째 묶어 **어느 PC 에서든 같은 결과**를 낸다
- **Compose** 와 **매니페스트**로 환경 전체를 **파일에 적어** 재현한다
- **쿠버네티스**에 올리고, **끊김 없이 바꾸고**, **되돌린다**

> 📌 이력서에 적을 수 있는 결과물이 **셋** 남았다 — GitHub 저장소 · GitHub Pages 주소 · **Dockerfile 과 매니페스트가 든 저장소**.

> ⭐ **어디로 가도 11 · 12일차가 바닥에 깔린다.** 클라우드의 보안그룹도, 쿠버네티스의 Service 타입도 **"필요한 것만 연다"** 한 문장이다.
