## 🎯 학습 목표

- 서비스마다 **TCP 를 쓸지 UDP 를 쓸지** 이유와 함께 고른다

## 📖 ① 한눈에 비교

| | **TCP** | **UDP** |
|---|---|---|
| 풀이 | Transmission **Control** Protocol | User **Datagram** Protocol |
| 연결 | **연결 먼저** (3-way handshake) | 연결 없이 **그냥 보낸다** |
| 신뢰성 | 잃어버리면 **다시 보낸다** (ACK · 재전송) | 잃어버리면 **끝** |
| 순서 | **번호표**로 순서대로 재조립 | 보장 안 함 |
| 속도 · 부담 | 느리고 무겁다 | **빠르고 가볍다** |
| 헤더 | 20 바이트~ | **8 바이트** |
| 잘 맞는 곳 | **하나라도 틀리면 안 되는 것** — 웹 · 파일 · 메일 · SSH | **늦으면 소용없는 것** — 영상통화 · 게임 · 스트리밍 · DNS 질문 |

> 💡 **비유: 등기우편 vs 전단지.**
> **TCP = 등기우편** — 받는 사람이 있는지 먼저 확인하고, **받았다는 서명(ACK)** 을 받고, 안 오면 **다시 보낸다.** 확실하지만 느리다.
> **UDP = 전단지** — 우편함에 **그냥 넣고 간다.** 받았는지 안 챙긴다. 대신 **매우 빠르게, 많이** 뿌릴 수 있다.

> 💡 **비유 2: 전화 vs 무전기.** TCP 는 "여보세요?" "네!" 하고 **연결된 뒤** 말한다. UDP 는 무전기처럼 **그냥 말한다.**

## 📖 ② 3-way handshake — TCP 의 "여보세요?" ⭐

TCP 는 데이터를 보내기 전에 **세 번 인사**한다.

```
 클라이언트                                       서버 (LISTEN 중)
     │ ① SYN        "연결해도 될까요?"     ─────▶  │
     │ ② SYN + ACK  "네, 저도 연결할게요"  ◀─────  │
     │ ③ ACK        "확인, 시작합니다"     ─────▶  │
     │ ════════════ 연결 완료 (ESTABLISHED) ════════ │
     │   데이터 ──▶  ◀── ACK (받았음)                │
```

| 단계 | 플래그 | tcpdump 표시 | 뜻 |
|------|--------|-------------|----|
| ① | **SYN** (synchronize) | `[S]` | 연결 요청 + "내 번호표는 여기서 시작" |
| ② | **SYN, ACK** | `[S.]` | 요청 받음(ACK) + 나도 연결 요청(SYN) |
| ③ | **ACK** (acknowledge) | `[.]` | 확인 |
| 끝 | **FIN** | `[F.]` | "이제 끊을게요" (정중한 종료) |
| 거절 | **RST** (reset) | `[R.]` | **"그 문 없어요"** — LISTEN 하는 프로그램이 없다 = `Connection refused` |

- `tcpdump` 에서 **`.` = ACK** 라는 것만 알면 읽을 수 있다
- 연결이 맺어지면 `ss -tn` 에 **`ESTAB`** (ESTABLISHED) 으로 보인다

> 🗣 **"9일차에 SSH 서버를 켜기 전 접속하면 나오던 `Connection refused` — 그게 바로 RST 입니다. 서버가 '그 문 없어요' 라고 답한 거예요."**

- UDP 는? → 인사가 **없다.** 첫 패킷부터 바로 데이터. 문이 없으면 (ICMP 로) 알려줄 뿐, **연결이라는 개념이 없다**

## 📖 ③ 누가 무엇을 쓰나

| 서비스 | 전송 | 이유 |
|--------|------|------|
| 웹 HTTP / HTTPS | **TCP** | 웹 페이지 글자 하나 빠지면 깨진다 |
| SSH · Telnet | **TCP** | 명령 한 글자가 빠지면 사고 (`rm -rf /tmp/x` → `rm -rf /`) |
| FTP · 메일 | **TCP** | 파일은 1 비트도 틀리면 안 된다 |
| **DNS 질문** | **UDP** (큰 응답 · 서버끼리 복사는 TCP) | 질문 하나 · 답 하나 — 인사하는 시간이 아깝다. 안 오면 **다시 물으면 된다** |
| **DHCP** | **UDP** | 아직 **IP 도 없다** → 연결을 맺을 수가 없다 (8일차 DORA 가 브로드캐스트였던 이유) |
| SNMP | **UDP** | 가벼운 감시 · 수백 대 장비에 뿌린다 |
| 영상통화 · 게임 · 스트리밍 | **UDP** | 0.5초 늦게 온 화면은 **버리는 게 낫다** |

> 📌 **"UDP 는 나쁜 TCP" 가 아니다.** "확실함" 보다 **"지금"** 이 중요한 곳에서는 UDP 가 정답이다.
> 요즘 웹의 **HTTP/3 (QUIC)** 는 오히려 **UDP 위에** 자기만의 신뢰성을 얹었다 — 이름만

## 📝 강의 메모

- **등기우편 / 전단지** 비유 하나로 표 전체를 설명할 수 있다 — 표는 비유 다음에
- 3-way handshake 는 **칠판 그림 → tcpdump 실물** 순서. `[S]` `[S.]` `[.]` 세 줄이 찍히는 순간이 오늘의 하이라이트
- `Connection refused` = **RST** 로 9일차 에러를 회수하면 "아!" 가 나온다
- DHCP 가 UDP 인 이유를 **8일차 DORA** 와 묶는다 — "IP 가 없어서 브로드캐스트 · IP 가 없어서 UDP"
- 시퀀스 번호 · 윈도우 크기 · 흐름 제어는 **이름만** — 네트워크관리사 필기 대비로 "있다" 정도
