# 4. 리눅스의 네트워크 — ipconfig 의 리눅스판

> 상위: [10일차 · 서버 기초](README.md)

## 🎯 학습 목표

- `ip a` 에서 **인터페이스 이름 · IP · 마스크(/24) · MAC** 을 찾는다
- `ip route` 에서 **기본 게이트웨이**를 찾는다
- `ping` · `resolvectl` 로 **인터넷 · DNS** 가 되는지 확인한다
- 1단계 Windows / 시스코 명령과 **리눅스 명령을 짝지어** 말한다

## 🌉 다리 놓기: "이 서버는 네트워크에서 어디에 사나?"

1단계 내내 장비를 만나면 제일 먼저 **"IP 가 뭐지? 게이트웨이는? 밖으로 나가지나?"** 를 확인했다.
리눅스 서버도 똑같다. 서버는 **네트워크로 서비스하는 컴퓨터**라서, 네트워크 확인이 **첫 번째 할 일**이다.
→ 2일차의 **IP · 마스크 · 게이트웨이 3종 세트**를 리눅스에서 찾아보자 → [3_공인IP와_사설IP](../../network1/day-02/lesson-3.md)

## 📖 ① 같은 질문, 다른 명령

| 알고 싶은 것 | Windows (1단계) | 시스코 (1단계) | **리눅스 (오늘)** |
|-------------|-----------------|----------------|------------------|
| 내 IP · MAC | `ipconfig /all` | `show ip interface brief` | **`ip a`** (`ip -br a` = 짧게) |
| 게이트웨이 · 경로 | `route print` | `show ip route` | **`ip route`** |
| 연결 확인 | `ping` (4번 하고 끝) | `ping` (5번) | **`ping`** (**무한** → Ctrl+C) · `ping -c 4` |
| 경로 추적 | `tracert` | `traceroute` | `tracepath` (또는 `traceroute`) |
| DNS 서버 | `ipconfig /all` | `show hosts` | **`resolvectl status`** |
| ARP 표 | `arp -a` | `show arp` | `ip neigh` |

> 📌 예전 책에는 `ifconfig` 가 나온다. 요즘 우분투에는 **기본으로 없다** → 표준은 **`ip`** 명령.

## 📖 ② `ip a` 읽기

```
1: lo: <LOOPBACK,UP,LOWER_UP> ...
    inet 127.0.0.1/8 scope host lo                ← 나 자신 (루프백)
2: enp0s3: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 ...
    link/ether 08:00:27:ab:cd:ef brd ff:ff:ff:ff:ff:ff       ← MAC 주소 (3일차)
    inet 192.168.0.42/24 metric 100 brd 192.168.0.255 scope global dynamic enp0s3
         ─────┬─── ┬                ─────┬────              ───┬───
              │    └ 마스크 /24 = 255.255.255.0                  └ DHCP 로 받았다 (8일차!)
              └ 내 IP (사설 — 2일차 10.0.0.0/8 대역)     브로드캐스트 주소 (1일차)
```

| 찾을 것 | 어디 | 1단계 연결 |
|---------|------|-----------|
| **인터페이스 이름** | `enp0s3` | 시스코 `g0/0` 같은 것. 리눅스는 이름이 길다 (`e`thernet · `p`ci `0` · `s`lot `3`) |
| **IP / 마스크** | `inet 192.168.0.42/24` | 2일차 **CIDR 표기** · **사설 IP** |
| **MAC** | `link/ether 08:00:27:...` | 3일차 MAC · `08:00:27` = VirtualBox 가상 랜카드 |
| **dynamic** | `scope global dynamic` | **DHCP 로 받은 주소** — 8일차 DORA 가 여기서도 일어났다 |
| **lo (127.0.0.1)** | 첫 줄 | **루프백 = 나 자신.** 네트워크 없이도 늘 있다 |

## 📖 ③ `ip route` 읽기 — 게이트웨이는?

```
default via 192.168.0.1 dev enp0s3 proto dhcp src 192.168.0.42 metric 100
192.168.0.0/24 dev enp0s3 proto kernel scope link src 192.168.0.42 metric 100
```

| 줄 | 뜻 | 시스코로 치면 |
|----|----|--------------|
| `default via 192.168.0.1` | **모르는 곳은 전부 192.168.0.1 로** = **기본 게이트웨이** | `S* 0.0.0.0/0 via ...` (5일차 기본 경로) |
| `192.168.0.0/24 dev enp0s3` | 이 동네는 **직접** 간다 | `C 192.168.0.0/24 is directly connected` |

> 💡 **1단계 그대로다.** 목적지가 **내 동네(/24)** 면 직접, **아니면 게이트웨이**로. 리눅스 서버도 **라우팅 테이블을 보고** 패킷을 보낸다.

- `192.168.0.1` 은 누구? → **강의실 공유기**. VM 이 **브릿지**라서 내 Windows 와 **같은 공유기**를 쓴다
- 🔎 **내 Windows 에서 `ipconfig`** 를 쳐 보자 — **게이트웨이가 똑같다.** 두 대가 같은 동네에 있다는 증거다
- 이 주소는 **누가 줬나?** → **DHCP** ([10_DNS와_DHCP_다시보기](lesson-10.md)) · 공유기가 밖으로 내보내는 방법은? → **NAT** ([9_NAT와_포트포워딩](lesson-9.md))

## 📖 ④ 밖으로 나가지나? — `ping` 과 DNS

```bash
ping -c 4 192.168.0.1         # ① 게이트웨이(공유기)까지
ping -c 4 8.8.8.8             # ② 인터넷(IP)까지
ping -c 4 google.com          # ③ 이름으로 → DNS 까지
```

| 결과 | 문제는 |
|------|--------|
| ① ❌ | 내 IP · 랜카드 · VM 네트워크 설정 |
| ① ✅ ② ❌ | 게이트웨이 너머 (공유기 · 인터넷) |
| ② ✅ ③ ❌ | **DNS** — 3일차 떡밥 "IP 는 되는데 이름은 안 된다" 와 똑같다 → [3_ICMP와_ping](../../network1/day-03/lesson-3.md) |

> 📌 이 **"가까운 곳부터 차례로"** 점검법은 1단계에서 배운 그대로다. 장비만 리눅스로 바뀌었다.
> ⚠️ 강의실 망 정책에 따라 `ping` 이 **막혀 있는 경우**가 있다 → 그때는 `curl -I https://google.com` 으로 확인

```bash
resolvectl status | grep "DNS Servers"      # 내 DNS 서버는?
```

- 리눅스에서 **DNS 설정 · `/etc/hosts` · `dig`** 는 오후에 자세히 → [10_DNS와_DHCP_다시보기](lesson-10.md)

## 📝 강의 메모

- **Windows · 시스코 · 리눅스 3단 비교표**가 오늘의 가장 큰 무기 — 새로 외우는 게 아니라 **"아는 걸 번역"** 한다는 느낌
- `ip a` 는 **스크린샷/칠판에 밑줄** — IP · 마스크 · MAC · dynamic 네 곳만 찾게 한다
- ⭐ **내 Windows `ipconfig` 와 나란히 비교**시키는 것이 이 절의 하이라이트 — 게이트웨이가 같다 = **브릿지의 의미**
- VM 주소는 **브릿지 + DHCP** 라 매주 바뀔 수 있다. 실제 값은 학생마다 다르므로 **칠판에 각자 적게** 한다
- 이 노트가 **오전과 오후를 잇는 다리** — 각자의 IP · 게이트웨이 · `dynamic` 을 남겨 두고 오후에 회수
