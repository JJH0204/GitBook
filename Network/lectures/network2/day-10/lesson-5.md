# 5. 🤖 AI 로 명령어 묻고 검증하기

> 상위: [10일차 · 서버 기초](README.md)
> 커리큘럼: **[AI 활용] 명령어 질의 후 출력 직접 해석 · 검증**

## 🎯 학습 목표

- AI 에게 리눅스 명령을 **좋은 질문**으로 묻는다 (환경 · 목적 · 제약 포함)
- AI 답을 **`--help` · `man` · 실제 실행 결과**로 검증한다
- **실행 전 멈춰야 하는 위험 명령**을 알아본다
- 명령의 **출력을 AI 에게 맡기지 않고 내가 먼저 해석**한 뒤 AI 와 비교한다

## 🌉 다리 놓기: "명령어를 다 외워야 하나?"

오전에만 명령어를 스무 개 넘게 배웠다. 현업 엔지니어도 **다 외우지 않는다.** 검색하고, 요즘은 **AI 에게 묻는다.**
문제는 AI 가 **그럴듯하게 틀린다**는 것이다. 그리고 [3_사용자_권한_sudo](lesson-3.md) 에서 봤듯, 서버에서 틀린 `sudo` 명령 하나는 **되돌릴 수 없다.**
→ 오늘의 규칙: **AI 는 물어보는 곳, 판단은 내가.**

## 📖 ① 좋은 질문 — 환경 · 목적 · 제약

| ❌ 나쁜 질문 | ✅ 좋은 질문 |
|-------------|-------------|
| "파일 찾는 법" | "**Ubuntu 24.04** 에서, **/etc 아래**에 이름에 **net** 이 들어간 **파일만** 찾는 명령을 알려줘. **각 옵션의 뜻**도 설명해줘." |
| "권한 바꿔줘" | "`run.sh` 를 **주인만 실행**할 수 있게 하고 싶어. **숫자 방식**으로 알려주고, 바뀐 뒤 `ls -l` 이 어떻게 보일지도 알려줘." |

- **환경**: OS · 버전 (`cat /etc/os-release` 로 확인) — Ubuntu 와 Rocky 는 설치 명령부터 다르다
- **목적**: 무엇을 하고 싶은지 한 문장
- **제약**: "sudo 없이" · "지우지 말고" · "한 줄로"
- **요청**: **옵션 하나하나의 뜻**을 같이 달라고 한다 → 검증의 재료가 된다

## 📖 ② 검증 3단계 — 믿지 말고 확인한다 ⭐

```
 AI 답 ──▶ ① 문서로 확인 ──▶ ② 안전한 곳에서 실행 ──▶ ③ 출력을 내가 해석 ──▶ ✅ 적용
             --help · man        ~/lab · /tmp · 스냅샷      AI 설명과 비교
```

| 단계 | 방법 | 예 |
|------|------|----|
| **① 문서** | `명령 --help` · `man 명령` (q 로 종료) | AI 가 `ls -h` 라고 했다 → `ls --help \| grep -- -h` 로 진짜 뜻 확인 |
| **② 안전 실행** | **`~/lab` 같은 실험용 폴더** · VM **스냅샷** 뒤에 | 지우는 명령은 먼저 **`ls` 로 대상만 확인** |
| **③ 해석** | 출력을 **내가 먼저** 읽고 → AI 설명과 **비교** | `ls -l` 권한을 내가 읽고 → AI 에게 "내 해석 맞아?" |

> 💡 **비유: 내비게이션.** 내비가 "우회전" 이라고 해도 **앞이 공사 중이면 안 꺾는다.** 운전대는 내가 잡는다.
> AI 는 **길을 알려주는 내비**, 서버의 **운전자는 나**다.

## 📖 ③ 멈춤 목록 — AI 가 이걸 주면 3초 멈춘다 🛑

| 모양 | 왜 위험 | 확인할 것 |
|------|--------|-----------|
| `rm -rf` · 특히 **`/` 나 `*` 와 함께** | 되돌릴 수 없다 | **경로가 정확히 어디인지** · 먼저 `ls 그경로` |
| `sudo` 가 붙은 모든 것 | 시스템 전체에 영향 | **이게 꼭 관리자여야 하나?** |
| `chmod 777` · `chmod -R` | 보안 구멍 · 한꺼번에 바뀜 | 필요한 최소 권한은? (755 · 644) |
| `> 파일` (특히 `/etc/...`) | **덮어쓰기** | `>>` 아닌가? 백업(`cp`) 했나? |
| `curl ... \| bash` | 인터넷 스크립트를 **읽지 않고 실행** | 출처 · 내용을 먼저 본다 |
| `dd` · `mkfs` | 디스크를 **통째로 덮어쓴다** | 입문 단계에서는 쓸 일 없다 |

> ⚠️ **AI 가 "안전합니다" 라고 해도** 이 목록은 멈춘다. AI 는 **내 서버의 상태를 모른다.**

## 📖 ④ 출력 해석 — 내가 먼저, AI 는 나중

AI 에게 출력을 붙여넣을 때의 순서:

1. **내가 먼저** 읽고 메모한다 — "IP 는 192.168.0.42, DHCP 로 받았고, 게이트웨이는 192.168.0.1"
2. 출력을 AI 에게 주고 **"내 해석이 맞는지, 놓친 게 있는지"** 묻는다
3. **다른 점**이 있으면 → 누가 맞는지 **문서/실험으로** 판정

> 📌 **붙여넣기 전 가리기**: 비밀번호 · 개인 키 · 공인 IP · 회사 서버 이름. 수업 VM 은 괜찮지만 **현업에서는 습관**이 되어야 한다.

## 📖 ⑤ 오늘의 AI 실습 과제

| # | AI 에게 묻기 | 검증 방법 | 확인 포인트 |
|---|-------------|-----------|-------------|
| 1 | "`ls -alh` 의 각 옵션 뜻은?" | `ls --help` | `-h` = **human-readable** (KB · MB) — 도움말(help) 아님! |
| 2 | 내 `ip a` 출력을 붙여넣고 "해석해줘" | 내 메모와 비교 | IP · 마스크 · MAC · `dynamic` 을 AI 도 짚었나 |
| 3 | "`/etc` 에서 `.conf` 로 끝나는 파일 개수를 세는 한 줄" | **실행해서** 숫자 확인 · 다른 방법으로 한 번 더 | 답이 여러 형태일 수 있다 (`find` · `ls \| grep`) → **둘 다 같은 숫자인가?** |
| 4 | 🕵 **틀린 답 찾기**: 강사가 준 AI 답변의 오류 찾기 ↓ | `--help` · 실행 | |

### 과제 4 — 이 AI 답변에서 틀린 곳은? (강사 제시용)

> **Q.** Ubuntu 에서 `run.sh` 를 **주인만 읽고 · 쓰고 · 실행**하게 하려면?
> **A (AI).** `chmod 777 run.sh` 를 입력하세요. 7 은 읽기 · 쓰기 · 실행을 뜻합니다. 그리고 `sudo apt-get install chmod` 로 chmod 를 먼저 설치해야 할 수도 있습니다.

{% hint style="success" %}
**정답**

- **`777` 은 주인 · 그룹 · 나머지 모두**에게 전부 허용 → 요구와 정반대. 정답은 **`chmod 700 run.sh`** (또는 `chmod u=rwx,go= run.sh`)
- **`chmod` 는 설치할 필요가 없다** — 기본 명령(coreutils)이다. `apt` 에 그런 패키지도 없다
- "7 = rwx" 설명 자체는 맞다 → **맞는 설명 속에 틀린 결론**이 섞인다는 게 AI 오류의 전형
- 검증법: `chmod 700 run.sh && ls -l run.sh` → `-rwx------` 확인
{% endhint %}
