## 학습 목표

- AI에게 리눅스 명령을 좋은 질문(환경, 목적, 제약 포함)으로 묻는다.
- AI 답을 `--help`, `man`, 실제 실행 결과로 검증한다.
- 실행 전에 멈춰야 하는 위험 명령을 알아본다.
- 명령의 출력을 AI에게 맡기지 않고 내가 먼저 해석한 뒤 AI와 비교한다.

## 이전 학습과의 연결

오전에만 명령어를 스무 개 넘게 배웠다. 현업 엔지니어도 다 외우지 않는다. 검색하고, 요즘은 AI에게 묻는다.

문제는 AI가 그럴듯하게 틀린다는 것이다. [3. 사용자 · 권한 · sudo](lesson-3.md)에서 봤듯 서버에서 틀린 `sudo` 명령 하나는 되돌릴 수 없다. 오늘의 규칙은 "AI는 물어보는 곳, 판단은 내가"다.

## 1. 좋은 질문 — 환경 · 목적 · 제약

| 나쁜 질문 | 좋은 질문 |
|---|---|
| "파일 찾는 법" | "Ubuntu 24.04에서, /etc 아래에 이름에 net이 들어간 파일만 찾는 명령을 알려줘. 각 옵션의 뜻도 설명해줘." |
| "권한 바꿔줘" | "`run.sh`를 주인만 실행할 수 있게 하고 싶어. 숫자 방식으로 알려주고, 바뀐 뒤 `ls -l`이 어떻게 보일지도 알려줘." |

- 환경: OS와 버전(`cat /etc/os-release`로 확인). Ubuntu와 Rocky는 설치 명령부터 다르다.
- 목적: 무엇을 하고 싶은지 한 문장
- 제약: "sudo 없이", "지우지 말고", "한 줄로"
- 요청: 옵션 하나하나의 뜻을 같이 달라고 한다. 검증의 재료가 된다.

## 2. 검증 3단계 — 믿지 말고 확인한다

```
 AI 답 ──▶ ① 문서로 확인 ──▶ ② 안전한 곳에서 실행 ──▶ ③ 출력을 내가 해석 ──▶ 적용
             --help · man        ~/lab · /tmp · 스냅샷      AI 설명과 비교
```

| 단계 | 방법 | 예 |
|---|---|---|
| ① 문서 | `<명령> --help`, `man <명령>`(q로 종료) | AI가 `ls -h`라고 했다 → `ls --help \| grep -- -h`로 진짜 뜻을 확인한다 |
| ② 안전 실행 | `~/lab` 같은 실험용 폴더, VM 스냅샷 뒤에 | 지우는 명령은 먼저 `ls`로 대상만 확인한다 |
| ③ 해석 | 출력을 내가 먼저 읽고 AI 설명과 비교한다 | `ls -l` 권한을 내가 읽고 AI에게 "내 해석이 맞나?"를 묻는다 |

{% hint style="info" %}
NOTE: 내비게이션에 비유한다. 내비가 "우회전"이라고 해도 앞이 공사 중이면 꺾지 않는다. 운전대는 내가 잡는다. AI는 길을 알려 주는 내비이고 서버의 운전자는 나다.
{% endhint %}

## 3. 멈춤 목록 — AI가 이것을 주면 3초 멈춘다

| 모양 | 왜 위험한가 | 확인할 것 |
|---|---|---|
| `rm -rf`, 특히 `/`나 `*`와 함께 | 되돌릴 수 없다 | 경로가 정확히 어디인지, 먼저 `ls <그 경로>` |
| `sudo`가 붙은 모든 것 | 시스템 전체에 영향 | 이것이 꼭 관리자여야 하는가 |
| `chmod 777`, `chmod -R` | 보안 구멍, 한꺼번에 바뀜 | 필요한 최소 권한은 무엇인가(755, 644) |
| `> 파일` (특히 `/etc/...`) | 덮어쓰기 | `>>`가 아닌가, 백업(`cp`)을 했는가 |
| `curl ... \| bash` | 인터넷 스크립트를 읽지 않고 실행 | 출처와 내용을 먼저 본다 |
| `dd`, `mkfs` | 디스크를 통째로 덮어쓴다 | 입문 단계에서는 쓸 일이 없다 |

{% hint style="danger" %}
WARNING: AI가 "안전합니다"라고 해도 이 목록은 멈춘다. AI는 내 서버의 상태를 모른다.
{% endhint %}

## 4. 출력 해석 — 내가 먼저, AI는 나중

AI에게 출력을 붙여넣을 때의 순서는 다음과 같다.

1. 내가 먼저 읽고 메모한다. 예: "IP는 192.168.0.42, DHCP로 받았고, 게이트웨이는 192.168.0.1"
2. 출력을 AI에게 주고 "내 해석이 맞는지, 놓친 것이 있는지"를 묻는다.
3. 다른 점이 있으면 누가 맞는지 문서나 실험으로 판정한다.

{% hint style="warning" %}
CAUTION: 붙여넣기 전에 비밀번호, 개인 키, 공인 IP, 회사 서버 이름을 가린다. 수업 VM은 괜찮지만 현업에서는 습관이 되어야 한다.
{% endhint %}

## 5. 오늘의 AI 실습 과제

| 번호 | AI에게 묻기 | 검증 방법 | 확인 포인트 |
|---|---|---|---|
| 1 | "`ls -alh`의 각 옵션 뜻은?" | `ls --help` | `-h`는 human-readable(KB, MB)이다. 도움말(help)이 아니다 |
| 2 | 내 `ip a` 출력을 붙여넣고 "해석해줘" | 내 메모와 비교 | IP, 마스크, MAC, `dynamic`을 AI도 짚었는가 |
| 3 | "`/etc`에서 `.conf`로 끝나는 파일 개수를 세는 한 줄" | 실행해서 숫자 확인, 다른 방법으로 한 번 더 | 답이 여러 형태일 수 있다(`find`, `ls \| grep`). 둘 다 같은 숫자인가 |
| 4 | 틀린 답 찾기: 강사가 준 AI 답변의 오류 찾기 | `--help`, 실행 | 아래 과제 4 |

### 과제 4 — 이 AI 답변에서 틀린 곳은? (강사 제시용)

> **Q.** Ubuntu에서 `run.sh`를 주인만 읽고, 쓰고, 실행하게 하려면?
> **A (AI).** `chmod 777 run.sh`를 입력하세요. 7은 읽기, 쓰기, 실행을 뜻합니다. 그리고 `sudo apt-get install chmod`로 chmod를 먼저 설치해야 할 수도 있습니다.

{% hint style="info" %}
**정답 및 해설**

- `777`은 주인, 그룹, 나머지 모두에게 전부 허용한다. 요구와 정반대다. 정답은 `chmod 700 run.sh`(또는 `chmod u=rwx,go= run.sh`)다.
- `chmod`는 설치할 필요가 없다. 기본 명령(coreutils)이다. `apt`에 그런 패키지도 없다.
- "7 = rwx" 설명 자체는 맞다. 맞는 설명 속에 틀린 결론이 섞이는 것이 AI 오류의 전형이다.
- 검증법: `chmod 700 run.sh && ls -l run.sh`를 실행해 `-rwx------`를 확인한다.
{% endhint %}

## 6. 확인 질문

- AI가 알려 준 명령이 에러 없이 끝났다. 그러면 맞는 것인가? → 아니다. 에러가 없는 것과 원하는 일을 한 것은 다르다. 결과를 `ls`, `cat`으로 확인한다.
- AI에게 `sudo` 비밀번호를 알려 줘도 되는가? → 절대 안 된다.

## 7. 약어·용어

| 용어 | 뜻 |
|---|---|
| `man` | 명령의 매뉴얼 페이지 |
| `--help` | 명령의 짧은 도움말 옵션 |
| coreutils | `ls`, `cp`, `chmod` 같은 기본 명령 묶음 |
| 스냅샷 | VM의 특정 시점 상태 저장본 |
| human-readable(`-h`) | 크기를 KB, MB처럼 읽기 쉬운 단위로 표시 |

## 진행 메모

- 사용하는 AI 도구는 학생이 자유롭게 고른다(ChatGPT, Claude, Gemini 등). 무료판으로 충분하다.
- 과제 4는 화면에 띄워 같이 푼다. "그럴듯한 설명과 틀린 결론"을 직접 보는 것이 핵심이다.
- 과제 3은 AI마다 답이 다르게 나온다. "답이 여러 개일 때 무엇을 믿나? → 실행 결과"로 마무리한다.
