## 학습 목표

- `mkdir`, `touch`, `cp`, `mv`, `rm`으로 파일과 디렉터리를 다룬다.
- `cat`, `less`, `head`, `tail`로 파일 내용을 읽는다.
- `nano`로 파일을 편집하고 저장·종료한다.
- 리다이렉션(`>`, `>>`), 파이프(`|`), `grep`으로 출력을 저장하고 걸러 낸다.
- `rm`에는 휴지통이 없다는 것을 안다.

## 이전 학습과의 연결

[1. 파일 시스템과 이동](lesson-1.md)에서 설정은 `/etc`에 파일로 있다고 했다. 8일차 Server0의 `Services > DNS`에서 칸을 채우던 일이, 리눅스에서는 설정 파일을 열어 한 줄 고치는 일이다.

그러려면 파일을 만들고, 복사해 백업하고, 열어서 고치고, 원하는 줄을 찾을 수 있어야 한다.

## 1. 만들기 · 복사 · 이동 · 삭제

| 명령 | 뜻 | 예 |
|---|---|---|
| `mkdir` | 디렉터리 만들기 | `mkdir lab`, `mkdir -p a/b/c` (중간까지 한 번에) |
| `touch` | 빈 파일 만들기 | `touch memo.txt` |
| `cp` | 복사(copy) | `cp memo.txt memo.bak`, `cp -r lab lab2` (디렉터리는 `-r`) |
| `mv` | 이동 또는 이름 바꾸기 | `mv memo.txt docs/`, `mv old.txt new.txt` |
| `rm` | 삭제 | `rm memo.bak`, `rm -r lab2` (디렉터리) |
| `rmdir` | 빈 디렉터리 삭제 | `rmdir empty` |

- 모양이 전부 같다: `명령 [옵션] 대상 [목적지]` → `cp  -r  lab  lab2`
- `mv`는 이름 바꾸기도 한다. 같은 곳으로 "이동"하면 이름 변경이다. 그래서 `rename`이 따로 필요 없다.

{% hint style="danger" %}
WARNING: `rm`에는 휴지통이 없다. 지우면 끝이다. 특히 `rm -rf`(강제, 하위까지)는 확인도 묻지 않는다. `sudo rm -rf /`는 서버 전체를 지운다. 서버 설정 파일을 고치기 전에는 항상 `cp`로 백업한다(`cp 설정 설정.bak`). 12일차에 매번 한다.
{% endhint %}

{% hint style="info" %}
NOTE: `cp`는 복사기, `mv`는 이삿짐, `rm`은 파쇄기다. 파쇄기에는 되돌리기 버튼이 없다.
{% endhint %}

## 2. 읽기 — 파일 크기에 따라 고른다

| 명령 | 언제 | 메모 |
|---|---|---|
| `cat` | 짧은 파일을 통째로 | `cat /etc/hostname` |
| `less` | 긴 파일을 넘겨 보기 | Space 다음, `b` 이전, `/단어` 검색, `q` 종료 |
| `head` | 앞부분만 | `head -n 5 <파일>` |
| `tail` | 뒷부분만 | `tail -n 5 <파일>`, `tail -f <로그>`(실시간으로 계속 보기) |

- 로그는 새 줄이 맨 아래에 붙는다. 로그를 볼 때는 `tail`을 쓴다(11일차 보안 로그에서 다시 쓴다).

## 3. 편집 — `nano`

```bash
nano memo.txt
```

```
  GNU nano 7.2                    memo.txt
안녕하세요 리눅스
(여기에 그냥 타이핑)

^G Help   ^O Write Out   ^W Where Is   ^K Cut   ^X Exit
```

| 키 | 뜻 |
|---|---|
| 그냥 타이핑 | 입력 (메모장처럼) |
| Ctrl + O → Enter | 저장 (Write **O**ut) |
| Ctrl + X | 종료. 저장하지 않았으면 묻는다 → `Y` + Enter |
| Ctrl + W | 찾기 |
| Ctrl + K / Ctrl + U | 줄 잘라내기 / 붙여넣기 |

- 화면 아래 `^`는 Ctrl 키다. 단축키가 항상 화면에 떠 있으므로 외울 필요가 없다.
- `vi`/`vim`은 현업에서 많이 쓰지만 입문자에게 어렵다. 이 수업은 `nano`를 쓴다. vim에 갇히면 `Esc` → `:q!` → Enter를 입력한다.
- 남의 설정 파일(`/etc/...`)을 고칠 때는 `sudo nano`가 필요하다. → [3. 사용자 · 권한 · sudo](lesson-3.md)

## 4. 출력 다루기 — 리다이렉션 · 파이프 · `grep`

명령의 결과는 보통 화면으로 나온다. 이 흐름을 돌릴 수 있다.

| 기호 | 뜻 | 예 |
|---|---|---|
| `>` | 출력을 파일에 덮어쓰기 | `ls -l > list.txt` |
| `>>` | 출력을 파일 끝에 이어쓰기 | `echo "둘째 줄" >> memo.txt` |
| `\|` (파이프) | 앞 명령의 출력을 뒤 명령의 입력으로 | `ls -l /etc \| less` |

`grep <단어>`는 그 단어가 들어간 줄만 보여 준다. `-i`는 대소문자 무시, `-n`은 줄 번호, `-v`는 그 단어가 없는 줄이다.

```bash
grep student /etc/passwd            # 파일에서 student가 들어간 줄만
ls /etc | grep net                  # /etc 목록 중 net이 들어간 것만
history | grep cp                   # 내가 입력했던 명령 중 cp가 들어간 것만
```

{% hint style="info" %}
NOTE: 파이프는 공장 컨베이어 벨트다. `ls`가 부품을 쏟아내면 `grep`이 불량만 골라내고 `less`가 포장한다. 작은 명령을 이어 붙여 큰 일을 하는 것이 리눅스의 철학이다.
{% endhint %}

{% hint style="info" %}
NOTE: 1단계 회수. 시스코에서도 같은 것을 썼다. `show running-config | include hostname`은 리눅스의 `cat 설정 | grep hostname`이다. 시스코 `| include`가 리눅스 `| grep`이다. 파이프 기호까지 같다.
{% endhint %}

{% hint style="danger" %}
WARNING: `>`는 덮어쓴다. `echo hi > 중요한파일` 한 번이면 내용이 사라진다. 붙이려면 `>>`를 쓴다.
{% endhint %}

## 5. 확인 질문

- `mv a.txt b.txt`는 무엇을 하나? → 이름을 바꾼다.
- `rm`으로 지운 파일을 복구하는 방법은? → 휴지통이 없다. 그래서 `cp` 백업을 먼저 한다.
- `echo test > a.txt`를 두 번 실행하면 `a.txt`는 몇 줄인가? → 1줄(덮어쓰기). `>>`였다면 2줄이다.
- 로그 파일의 마지막 20줄만 보려면? → `tail -n 20 <파일>`
- nano에서 저장하고 나가는 키는? → Ctrl+O, Enter, Ctrl+X

## 6. 약어·용어

| 용어 | 뜻 |
|---|---|
| 리다이렉션 | 명령의 출력을 화면 대신 파일로 보내는 것 |
| 파이프 | 앞 명령의 출력을 뒤 명령의 입력으로 잇는 `\|` |
| `grep` | 줄 단위로 패턴을 찾는 명령 |
| nano | 화면 아래에 단축키가 표시되는 텍스트 편집기 |
| `-r` | recursive. 하위 디렉터리까지 |

## 진행 메모

- `rm`에 휴지통이 없다는 점은 반드시 무섭게 한 번 짚는다. 이후 모든 설정 작업의 "백업부터" 습관의 근거가 된다.
- nano는 화면 아래 단축키를 읽게 한다. 외우게 하지 않는다.
- 파이프는 시스코 `| include`로 연결하면 "아, 그거!" 반응이 나온다. 오늘의 가장 반가운 회수다.
- 시간이 부족하면 `head`, `tail`, `less`는 `tail`만 남긴다. 11일차 로그에서 필수다.
