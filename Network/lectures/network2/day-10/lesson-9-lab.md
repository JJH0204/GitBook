## 5. 절차

### A. 나는 몇 번 변장하나

1. (5-A-01) 창 ②에서 `ip -br a | grep enp0s3`를 입력한다. → 결과: `192.168.x.x/24`(사설)가 보인다.
2. (5-A-02) 창 ②에서 `ip route | grep default`를 입력한다. → 결과: `default via 192.168.0.1`(강의실 공유기)이 보인다.
3. (5-A-03) 창 ②에서 `curl -s ifconfig.me ; echo`를 입력한다. → 결과: 인터넷이 본 나, 즉 공인 IP가 출력된다.
4. (5-A-04) Windows PowerShell에서 `ipconfig`를 입력한다. → 결과: `192.168.x.y`(사설)가 보이고 게이트웨이가 VM과 같다.
5. (5-A-05) 강의실 전원이 5-A-03의 명령을 입력해 공인 IP를 불러 본다. → 결과: 전원이 같은 IP다. PAT다.
6. (5-A-06) 아래 메모를 채운다. → 결과: 사설 IP와 공인 IP가 짝지어진다. 공인 IP는 문서나 공유 화면에 적지 않는다.

```
192.168.___.___ (사설) ──NAT──▶ ____.____.____.____ (공인)
```

### B. 안에서 밖으로는 되는데, 밖에서 안으로는?

1. (5-B-01) 창 ①에서 `cd ~/www && python3 -m http.server 8080`을 입력한다. → 결과: 서버가 시작된다.
2. (5-B-02) Windows 브라우저에서 `http://<VM IP>:8080`을 연다. → 결과: 열린다. 같은 동네(브릿지)다.
3. (5-B-03) 옆자리 PC에서 같은 주소를 연다. → 결과: 열린다. 같은 동네다.
4. (5-B-04) "집에서 휴대폰 데이터로 이 주소를 입력하면 될까?"를 질문한다.
5. (5-B-05) 휴대폰 데이터로 접속해 본다(선택). → 결과: 열리지 않는다. 강의실 공유기가 NAT로 안쪽을 숨기고 있다. 들어오려면 포트포워딩이 필요하다.
6. (5-B-06) 포트포워딩은 설정하지 않는다. 11일차 PT 공유기에서 설정해 본다.
7. (5-B-07) 창 ①에서 Ctrl + C를 눌러 서버를 끈다. → 결과: 프롬프트로 돌아온다.

## 6. 기능 확인

| 번호 | 확인 동작 | 기대 결과 | 합격 기준 |
|---|---|---|---|
| 1 | 사설 IP와 공인 IP 비교 | 서로 다르다 | 메모 칸을 채웠다 |
| 2 | 강의실 공인 IP 비교 | 전원이 같다 | PAT를 설명한다 |
| 3 | "나갈 때는 NAT, 들어올 때는 포트포워딩"을 설명한다 | 내 말로 설명한다 | 두 가지를 짝지어 말한다 |
