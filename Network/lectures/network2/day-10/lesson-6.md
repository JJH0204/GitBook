# 6. 서버란 무엇인가 — 기다렸다가 응답하는 프로그램

> 상위: [10일차 · 서버 기초](README.md)

## 🎯 학습 목표

- **클라이언트 · 서버** 를 "누가 먼저 말을 거나" 로 구분한다
- 서버가 **하드웨어**를 가리킬 때와 **프로그램(서비스)** 을 가리킬 때를 구분한다
- 서버 = **포트를 열고 기다리는(LISTEN) 프로그램** 임을 `ss` 로 확인한다
- 주요 서버의 종류와 2단계에서 **언제 만드는지** 안다

## 🌉 다리 놓기: "서버 컴퓨터는 뭐가 특별할까?"

9일차에 만든 VM 을 우리는 "서버" 라고 불렀다. 그런데 사실 **평범한 리눅스 컴퓨터**다. 특별한 부품은 없다.
그럼 무엇이 **서버**를 서버로 만들까? → **하는 일**이다.
8일차 Server0 도 모양은 PC 와 똑같았다. `Services` 에서 **DNS 를 켜는 순간** DNS **서버**가 됐다.

## 📖 ① 클라이언트와 서버 — 누가 먼저 말을 거나

```
 클라이언트 (요청하는 쪽)                          서버 (응답하는 쪽)
 브라우저 · 앱 · ssh 명령     ── ① 요청 ──▶      웹서버 · DNS · sshd
                            ◀── ② 응답 ──       (미리 문 열고 기다리고 있다)
```

| | 클라이언트 | 서버 |
|---|---|---|
| 역할 | **요청**한다 (먼저 말 건다) | **기다렸다가 응답**한다 |
| 켜져 있는 시간 | 필요할 때만 | **24시간** |
| 주소 | 바뀌어도 된다 (DHCP) | **고정**이어야 찾아온다 (8일차 Server0 는 고정 IP) |
| 예 | 크롬 · 카톡 앱 · `ssh` · `ping` | 네이버 웹서버 · 카톡 서버 · `sshd` |

> 💡 **비유: 가게와 손님.** 가게(서버)는 **문을 열고 점원이 기다린다.** 손님(클라이언트)이 와서 주문(요청)하면 음식(응답)을 준다.
> 가게는 **주소가 바뀌면 안 된다**(고정 IP) · **아무 때나 문을 닫으면 안 된다**(24시간) · **손님이 몰려도 버텨야 한다**(성능).

- 한 컴퓨터가 **동시에 둘 다** 일 수 있다 — 내 VM 은 `sshd`(서버)이면서 `apt update` 할 땐 클라이언트

## 📖 ② "서버" 라는 말의 두 가지 뜻

| 뜻 | 예 | 오늘 |
|----|----|------|
| **서버 하드웨어** | 서버실의 랙 장비 · 클라우드 VM | 9일차 VM |
| **서버 프로그램 (서비스)** | `sshd` · nginx · DNS 프로그램 | ⭐ 오늘의 주인공 |

- 리눅스에서 서버 프로그램은 보통 이름 끝에 **`d`** 가 붙는다 = **데몬(daemon)** — 뒤에서 조용히 기다리는 프로그램 (`sshd` · `httpd` · `named`)
- **서버 하나에 서비스 여러 개** 가 흔하다 → 그럼 요청이 왔을 때 **어느 프로그램에게?** → [8_포트번호와_소켓](lesson-8.md)

## 📖 ③ 서버 = 문 열고 기다리는 프로그램 — `ss` 로 보기 ⭐

"기다린다" 는 게 추상적으로 들리지만, 리눅스에서는 **눈으로 볼 수 있다.**

```bash
sudo ss -tulnp          # t=TCP u=UDP l=LISTEN(기다리는 중) n=숫자로 p=프로그램 이름
```

```
Netid State  Local Address:Port   Process
udp   UNCONN 127.0.0.53%lo:53     users:(("systemd-resolve",...))   ← DNS 도우미 (53)
tcp   LISTEN 127.0.0.53%lo:53     users:(("systemd-resolve",...))
tcp   LISTEN 0.0.0.0:22           users:(("sshd"... 또는 "systemd"...)) ← SSH 서버 (22) = 9일차에 직접 구축한 그것
```

| 칸 | 뜻 |
|----|----|
| **LISTEN** | **문 열고 기다리는 중** = 서버 |
| `0.0.0.0:22` | **모든** 랜카드의 22번 문에서 기다린다 |
| `127.0.0.53:53` | **나 자신(루프백)** 에게만 열린 문 → 밖에서는 못 들어온다 |
| Process | **누가** 기다리나 |

> 🗣 **"9일차에 `systemctl status ssh` 에서 본 `Server listening on 0.0.0.0 port 22` — 바로 이 한 줄(`:22 LISTEN`)입니다. 그래서 SSH 로 들어올 수 있었어요."**
> 이 프로그램을 끄면? → 문이 닫힌다 → `Connection refused`

### 내가 서버를 만들어 보기 — 1분 웹서버

```bash
mkdir -p ~/www && cd ~/www
echo "<h1>Hello from Ubuntu</h1>" > index.html
python3 -m http.server 8080       # 지금부터 8080 번 문을 열고 기다린다
```

- 다른 창에서 `ss -tln | grep 8080` → **LISTEN** 이 생겼다 = **이 순간 이 VM 은 웹서버**
- `curl localhost:8080` → 응답이 온다 · 서버 창에는 **요청 기록(로그)** 이 찍힌다
- 서버 창에서 **Ctrl+C** → 문이 닫힌다 → `curl` 은 **Connection refused**

> 💡 **서버의 정체 한 줄 요약**: **포트를 열고(LISTEN) · 요청을 기다리다 · 응답하는 프로그램.** 그게 전부다.
> nginx · DNS · 메일 서버(12일차)도 **규모만 클 뿐 똑같다.**

## 📖 ④ 서버의 종류 — 2단계 지도

| 서버 | 하는 일 | 포트 | 언제 만드나 |
|------|---------|------|-------------|
| **웹** | 웹 페이지 | TCP 80 / 443 | 오늘 체험 · 12 · 14 · 16일차 |
| **SSH / Telnet** | 원격 접속 | TCP 22 / 23 | **9일차 구축** (openssh-server) · 12일차 Telnet |
| **DNS** | 이름 → IP | UDP/TCP 53 | 12일차 |
| **DHCP** | IP 자동 배포 | UDP 67 / 68 | (8일차 PT · 오늘 리눅스에서 관찰) |
| **메일** | 메일 보내기 · 받기 | TCP 25 / 110 / 143 | 12일차 |
| **FTP · NFS** | 파일 전송 · 공유 | TCP 20/21 · 2049 | 12일차 |
| **DB** (DBMS) | 데이터 저장 · 검색 | TCP 3306 (MySQL) | 14일차 Docker |
| **Proxy** | 대신 요청 · 필터링 | TCP 3128 등 | 12일차 |

- "카톡으로 친구에게 메시지를 보낼 때 클라이언트와 서버는?" → 내 폰 · 친구 폰 = **클라이언트**, 카카오 = **서버** (폰끼리 직접 말하지 않는다)

- "서버는 왜 고정 IP 여야 하나?" → 주소가 바뀌면 **손님이 못 찾아온다** (DNS 가 옛 주소를 알려준다)

## 📝 강의 메모

- **"서버 컴퓨터는 뭐가 특별할까?" → "하는 일이 특별하다"** 로 연다
- `ss -tulnp` 는 **오늘 내내 쓰는 도구** — 포트 · NAT · DNS 에서 계속 다시 친다
- 📌 Ubuntu 24.04 는 SSH 를 **systemd 가 대신 문을 지키다 넘겨주는 방식**(소켓 활성화)이라 Process 칸에 `sshd` 대신 `systemd` 가 보일 수 있다 → "문지기가 대신 서 있다" 한 줄이면 충분
- `python3 -m http.server` 는 **Ctrl+C 로 끄면 서비스가 사라지는 것**까지 꼭 보여준다 → "서버는 켜져 있어야 서버"
