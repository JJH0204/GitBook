## 1. 증상, 원인, 조치

| 증상 | 가능 원인 | 조치 |
|---|---|---|
| `No such file or directory` | 오타, 대소문자, 위치 | `pwd`, `ls`로 위치를 확인한다. Tab을 쓴다 |
| `Permission denied` | 권한 없음 | 내 파일이면 `chmod`, 시스템 파일이면 `sudo`를 쓴다 |
| `Could not get lock /var/lib/dpkg/lock` | 백그라운드 자동 업데이트 중 | 1~2분 기다렸다 다시 시도한다 |
| 화면이 멈췄다(`ping`, `tail -f`, 서버) | 끝나지 않는 명령 | Ctrl + C를 누른다 |
| vim에 갇혔다 | `vi`로 열었다 | Esc → `:q!` → Enter를 입력한다 |
| 브라우저에서 `192.168.x.x:8080`이 열리지 않는다 | ① 창 ①의 서버가 꺼졌다 ② 주소를 잘못 봤다 | ① `ss -tln \| grep 8080`으로 확인한다 ② `ip a`로 주소를 다시 확인한다 |
| `Address already in use` | 그 포트에 이미 서버가 떠 있다 | 다른 창에서 떠 있는 서버를 Ctrl+C로 끄거나 다른 포트를 쓴다 |
| `tcpdump`에 아무것도 나오지 않는다 | 인터페이스 또는 포트가 틀렸다 | 루프백 실습은 `-i lo`를 쓰고 포트 번호를 확인한다 |
| `nc: command not found`, `dig: command not found` | 미설치 | 오후 준비의 `apt install` 명령을 입력한다 |
| `sudo nano /etc/hosts` 후 이상해졌다 | 오타 | `sudo cp /etc/hosts.bak /etc/hosts`로 백업에서 복구한다 |

## 2. 격리 순서

1. 오류 문구를 그대로 읽는다. 문구 첫 줄이 원인을 알려 주는 경우가 많다.
2. 위치 문제인지 확인한다: `pwd`, `ls`.
3. 권한 문제인지 확인한다: `ls -l <파일>`.
4. 서버 문제인지 확인한다: `ss -tln`에 해당 포트의 LISTEN이 있는가.
5. 네트워크 문제인지 확인한다: [LEC-N2-10-004-DO](lesson-4.md)의 "가까운 곳부터 차례로" 순서로 `ping`한다.
