## 5. 절차

### A. 3-way handshake 관찰

1. (5-A-01) 창 ③에서 `sudo tcpdump -i lo -n tcp port 5000`을 입력한다. → 결과: 대기 상태가 된다.
2. (5-A-02) 창 ①에서 `nc -l 5000`을 입력한다. TCP 서버가 5000번에서 기다린다. → 결과: 창 ①이 점유된다.
3. (5-A-03) 창 ②에서 `nc 127.0.0.1 5000`을 입력한다. 접속만 하고 아직 아무것도 입력하지 않는다. → 결과: 창 ③에 정확히 3줄이 찍힌다.

```
... 127.0.0.1.41234 > 127.0.0.1.5000: Flags [S],  ...     ① SYN
... 127.0.0.1.5000 > 127.0.0.1.41234: Flags [S.], ...     ② SYN+ACK
... 127.0.0.1.41234 > 127.0.0.1.5000: Flags [.],  ...     ③ ACK
```

### B. 채팅과 소켓 확인

1. (5-B-01) 창 ②에서 `안녕 서버`를 입력하고 Enter를 누른다. → 결과: 창 ①에 문장이 나타난다.
2. (5-B-02) 창 ①에서 답장을 입력하고 Enter를 누른다. → 결과: 창 ②에 답장이 나타난다.
3. (5-B-03) 창 ③을 확인한다. → 결과: `[P.]`(데이터)와 `[.]`(받았음 ACK)가 짝으로 찍힌다. 등기우편의 서명이다.
4. (5-B-04) 창 ③에서 Ctrl + C로 `tcpdump`를 멈춘다.
5. (5-B-05) 창 ③에서 `ss -tn | grep 5000`을 입력한다. → 결과: `ESTAB` 두 줄(양쪽 끝의 소켓)이 보인다.
6. (5-B-06) 창 ③에서 `sudo tcpdump -i lo -n tcp port 5000`을 다시 입력한다(↑ 두 번). → 결과: 관찰이 다시 시작된다.

### C. 끊기와 "문 없음"

1. (5-C-01) 창 ②에서 Ctrl + C를 누른다. → 결과: 창 ③에 `[F.]`(FIN, 정중한 종료)가 찍히고 창 ①의 `nc`도 끝난다.
2. (5-C-02) 창 ②에서 `nc 127.0.0.1 5000`을 입력한다. 이제 아무도 기다리지 않는다. → 결과: 조용히 즉시 종료된다.
3. (5-C-03) 창 ②에서 `nc -v 127.0.0.1 5000`을 입력한다. → 결과: `Connection refused`가 나온다.
4. (5-C-04) 창 ③을 확인한다. → 결과: `[S]` 다음 `[R.]`이 찍힌다. RST는 "그 문 없다"는 뜻이다. 9일차 `Connection refused`의 정체다.

### D. UDP는 인사가 없다

1. (5-D-01) 창 ③에서 Ctrl + C를 누른 뒤 `sudo tcpdump -i lo -n udp port 5001`을 입력한다. → 결과: 대기 상태가 된다.
2. (5-D-02) 창 ①에서 `nc -u -l 5001`을 입력한다. → 결과: UDP 서버가 대기한다.
3. (5-D-03) 창 ②에서 `nc -u 127.0.0.1 5001`을 입력하고 `hello`를 입력한 뒤 Enter를 누른다. → 결과: 창 ③에 handshake 없이 바로 `UDP, length 6` 한 줄이 찍힌다. ACK도 없다. 전단지다.
4. (5-D-04) 창 ①②③에서 모두 Ctrl + C를 누른다. → 결과: 모두 프롬프트로 돌아온다.

## 6. 기능 확인

| 번호 | 확인 동작 | 기대 결과 | 합격 기준 |
|---|---|---|---|
| 1 | TCP 접속 직후 창 ③ | `[S]`, `[S.]`, `[.]` | 3줄을 봤다 |
| 2 | 서버가 없을 때 접속 | `[S]` 다음 `[R.]` | RST를 봤다 |
| 3 | UDP 전송 | `UDP, length 6` 한 줄 | handshake가 없다 |

## 7. 복구

1. (7-01) 창 ①②③의 `nc`, `tcpdump`를 모두 Ctrl + C로 끈다.
2. (7-02) `ss -tuln | grep -E ':5000|:5001'`을 입력해 출력이 없는지 확인한다. → 결과: 열린 포트가 없다.
