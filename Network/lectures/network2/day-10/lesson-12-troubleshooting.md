## 1. 증상

수업 중 FileZilla로 FTP 접속을 시도했더니 `500`으로 시작하는 에러가 났다. 같은 서버에 Windows 터미널의 `ftp`는 접속됐다. 그래서 `ftp`로 바꿔 실습했다.

이것은 실패가 아니라 좋은 교재다. 외울 것은 원인이 아니라 로그를 읽는 습관이다.

## 2. FTP 응답 코드 읽기

FTP 서버의 대답은 세 자리 숫자로 온다. 첫 자리만 봐도 절반은 안다.

| 앞자리 | 뜻 |
|---|---|
| `2xx` | 성공(`230 Login successful`) |
| `3xx` | 더 필요함(`331 Password required`) |
| `4xx` | 일시적 실패. 다시 하면 될 수도 있다 |
| `5xx` | 영구적 실패. 무언가를 고쳐야 한다 |

`500` 대가 떴다는 것은 서버가 명령 자체를 거부했다는 뜻이다.

## 3. 가능 원인

같은 서버에 Windows `ftp`는 됐는데 FileZilla는 안 됐다. 두 프로그램의 차이에 답이 있다.

| 번호 | 후보 | 무슨 일인가 | Windows `ftp`는 왜 됐나 |
|---|---|---|---|
| ① | 패시브 모드 데이터 연결이 열리지 않는다 | FileZilla는 패시브(PASV)가 기본이다. 서버가 데이터용 포트를 새로 안내하는데 그 포트로 연결이 되지 않았다(서버 설정, 방화벽) | Windows `ftp`는 액티브(PORT)가 기본이다. 서버가 내 PC 쪽으로 연결해 온다. 방향이 반대라 이 문제를 비켜 간다 |
| ② | 암호화(`AUTH TLS`)를 거부한다 | FileZilla는 접속하자마자 "암호화가 되는가"부터 묻는다. 서버에 TLS 설정이 없으면 에러가 난다(`500 AUTH not understood`로 알려진 사례) | Windows `ftp`는 애초에 묻지 않는다 |

{% hint style="info" %}
NOTE: 결국 "FTP는 연결이 두 개"라는 이야기로 돌아온다. 제어 연결(21)은 됐는데 데이터 연결이 열리지 않은 것이다. 그래서 접속은 된 것 같은데 목록이 나오지 않는다. → [LEC-N2-10-012-REF](lesson-12.md)
{% endhint %}

## 4. 격리 절차

FileZilla는 위쪽 로그 창에 서버와 주고받은 대화가 전부 나온다. 추측하지 말고 읽는다.

1. FileZilla를 열고 접속을 다시 시도한다.
2. 위쪽 로그 창에서 `500`, `530`으로 시작하는 줄을 찾는다.
3. 그 줄 바로 위에 FileZilla가 보낸 명령이 있다. `AUTH TLS`인지 `PASV`인지 본다.

| 로그 | 판정 |
|---|---|
| `AUTH TLS` 직후에 `500` | 후보 ② |
| `PASV` 직후에 멈추거나 `425`, 타임아웃 | 후보 ① |

## 5. 시정 조치

| 후보 | 조치 |
|---|---|
| ① | 서버의 패시브 포트 범위 설정과 방화벽을 확인한다. 12일차 [vsftpd 설정](../day-12/lesson-3.md)에서 다룬다 |
| ② | 서버에 TLS를 설정하거나 클라이언트에서 암호화 없이 접속하는 옵션을 쓴다. 실무에서는 SFTP를 쓴다 |

## 6. 약어·용어

| 용어 | 뜻 |
|---|---|
| 액티브(PORT) 모드 | 서버가 클라이언트 쪽으로 데이터 연결을 여는 방식 |
| 패시브(PASV) 모드 | 클라이언트가 서버가 안내한 포트로 데이터 연결을 여는 방식 |
| `AUTH TLS` | FTP 연결을 TLS로 암호화하자는 요청 |
| 제어 연결 / 데이터 연결 | 명령용 21번 / 파일 내용용 20번 연결 |
