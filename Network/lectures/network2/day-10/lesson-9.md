## 학습 목표

- NAT가 사설 IP를 공인 IP로 바꾸는 이유와 원리를 설명한다.
- PAT(NAT Overload)가 포트 번호로 여러 기기를 구분한다는 것을 안다.
- NAT는 나가는 길만 열어 주므로 들어오려면 포트포워딩이 필요하다는 것을 안다.
- 강의실 전체가 공인 IP 하나를 나눠 쓴다는 것을 `curl ifconfig.me`로 확인한다.

## 이전 학습과의 연결

2일차에 사설 IP(`10.x`, `172.16~31.x`, `192.168.x`)는 인터넷에 직접 나갈 수 없다고 배웠다. → [3. 공인 IP와 사설 IP](../../network1/day-02/lesson-3.md) 그런데 우리 VM의 주소는 `192.168.x.x`, 사설이다. 그런데도 `apt update`로 인터넷에서 프로그램을 받았다. 어떻게 된 것인가?

[4. 리눅스의 네트워크](lesson-4.md)에서 본 게이트웨이 `192.168.0.1`(강의실 공유기)이 무언가를 해 주고 있다는 뜻이다. 2일차에 "회사 대표번호"로 맛만 본 NAT가 그 답이다.

## 1. NAT — 나갈 때 주소를 바꿔 준다

NAT(Network Address Translation)는 사설망과 인터넷의 경계(공유기, 라우터)에서 출발지 IP를 바꿔치기하는 것이다.

```
 집 안 (사설)                         공유기 (NAT)                      인터넷 (공인)
 PC 192.168.0.100 ── 출발 192.168.0.100 ──▶ [ 바꿔치기 ] ── 출발 203.0.113.2 ──▶ 서버 8.8.8.8
                                           │ 변환표에 적어둔다 │
 PC 192.168.0.100 ◀── 도착 192.168.0.100 ── [ 되돌리기 ] ◀── 도착 203.0.113.2 ── 응답
```

| 왜 | 설명 |
|---|---|
| 주소 절약 | 집 안 기기 20대가 공인 IP 1개를 나눠 쓴다. IPv4 고갈에 대응한다(2일차) |
| 숨김(부수 효과) | 밖에서는 공유기만 보인다. 안쪽 기기는 먼저 말을 걸지 않으면 보이지 않는다 |

{% hint style="info" %}
NOTE: 2일차의 회사 대표번호 비유 그대로다. 직원(내선 101, 102)이 밖으로 전화하면 상대 화면에는 대표번호가 뜬다. 상대가 다시 걸면 교환원이 "아까 102번이 건 거였지" 하고 기록(변환표)을 보고 연결해 준다.
{% endhint %}

### 내 눈으로 확인 — 주소가 몇 번 바뀌는가

```bash
ip -br a | grep enp0s3           # VM 안의 나:     192.168.x.x      (사설)
```
```powershell
ipconfig                         # Windows:        192.168.x.y      (사설 — 같은 공유기 뒤)
```
```bash
curl -s ifconfig.me ; echo       # 인터넷이 본 나: <공인 IP> (예: 203.0.113.x)
```

- 내 VM은 한 번 변장하고 나간다. `192.168.x.x` → (강의실 공유기 NAT) → 공인 IP
- 브릿지라서 VM과 내 Windows가 같은 동네에 있다. 게이트웨이가 똑같다.
- 강의실 모든 학생이 `curl ifconfig.me`를 입력하면 같은 공인 IP가 나온다. 한 대표번호를 30명이 나눠 쓴다.

## 2. PAT — 한 공인 IP를 여럿이 나누는 방법

공인 IP는 하나인데 집 안 기기는 여럿이다. 응답이 돌아왔을 때 누구에게 돌려줄지 어떻게 알까? 포트 번호까지 바꿔서 변환표에 적는다. 이것이 PAT(Port Address Translation, 시스코 용어로 NAT Overload)다.

| 안쪽 (사설 IP : 포트) | ⇄ | 바깥쪽 (공인 IP : 포트) | 목적지 |
|---|---|---|---|
| 192.168.0.100 : 51001 | ⇄ | 203.0.113.2 : 1024 | 8.8.8.8 : 80 |
| 192.168.0.101 : 51001 | ⇄ | 203.0.113.2 : 1025 | 8.8.8.8 : 80 |
| 192.168.0.102 : 49152 | ⇄ | 203.0.113.2 : 1026 | 8.8.8.8 : 53 |

- 응답이 `203.0.113.2 : 1025`로 오면 표를 보고 `192.168.0.101 : 51001`로 돌려준다.
- [8. 포트 번호와 소켓](lesson-8.md)의 "4개 값으로 연결 구분"을 공유기가 대신해 주는 것이다.
- 집 공유기, 회사 방화벽, 통신사, VirtualBox까지 요즘 NAT라고 하면 거의 다 PAT다.

| 종류 | 변환 | 쓰임 |
|---|---|---|
| Static NAT | 사설 1 ↔ 공인 1 (고정) | 서버를 밖에 공개할 때 |
| Dynamic NAT | 사설 여럿 ↔ 공인 풀에서 빌려줌 | 드물다 |
| PAT(Overload) | 사설 여럿 ↔ 공인 1 + 포트 | 집, 회사 등 대부분 |

## 3. NAT의 문제 — 밖에서는 들어올 수 없다

변환표는 안에서 먼저 나간 뒤에야 생긴다. 밖에서 먼저 들어오면 어떻게 되는가.

```
 인터넷 누군가 ── "203.0.113.2 : 22 에 SSH 할게요" ──▶ 공유기: "변환표에 없는데? 누구 거지?" → 버림
```

- 그래서 집에 서버(NAS, 게임 서버, CCTV)를 두면 밖에서 들어올 수 없다.
- NAT의 부수 효과인 보안이 바로 이것이다. 안쪽 기기는 기본적으로 숨겨져 있다(11일차 방화벽과 비교).

## 4. 포트포워딩 — 들어오는 문을 미리 뚫어 둔다

포트포워딩은 공유기에 "이 포트로 들어오는 것은 안쪽 이 기기의 이 포트로 보내라"고 미리 적어 두는 것이다(고정 변환표 한 줄).

```
 인터넷 ── 203.0.113.2 : 8080 ──▶ [공유기] 규칙: 8080 → 192.168.0.10 : 80 ──▶ 집 안 웹서버
```

{% hint style="info" %}
NOTE: 대표번호와 내선 자동 연결에 비유한다. "대표번호로 전화해서 내선 8080을 누르면 개발팀 10번 자리로 바로 연결"되는, 미리 설정해 둔 ARS다.
{% endhint %}

### 지금까지 본 것들의 정체

| 지금까지 본 것 | 정체 |
|---|---|
| VM 주소 `192.168.x.x` | 강의실 공유기가 DHCP로 준 사설 주소([10. DNS와 DHCP 다시 보기](lesson-10.md)) |
| 게이트웨이 `192.168.0.1` | 강의실 공유기 = NAT 라우터 |
| 사설인데 `apt update`는 됐다 | 안에서 먼저 나간 것이라 변환표가 생겼다 → NAT |
| 강의실 전체가 같은 공인 IP | 공인 하나를 포트로 나눠 쓴다 → PAT |
| 내 Windows에서 VM으로 바로 SSH가 됐다 | 브릿지라서 둘이 같은 동네다. NAT를 건널 일이 없다 |
| 그런데 집 밖에서 VM에 들어가려면? | NAT를 건너야 한다 → 포트포워딩이 필요하다 |

```
 인터넷 ──▶ [ 강의실 공유기 · 공인 IP ] ──▶ VM 192.168.x.x : 22
                    ▲ 규칙이 없으면 여기서 막힌다 (= NAT의 부수 효과)
```

{% hint style="info" %}
NOTE: 오늘의 핵심 질문의 답은 이렇다. 나갈 때는 NAT가 알아서 바꿔 주고, 들어올 때는 포트포워딩으로 문을 뚫어 준다. 한 쌍이다.
{% endhint %}

{% hint style="info" %}
NOTE: 우리는 브릿지라서 교실 안에서는 포트포워딩이 필요 없었다. 편한 만큼 교실의 누구나 내 서버에 닿는다. → [11일차](../day-11/lesson-3.md)
{% endhint %}

{% hint style="danger" %}
WARNING: 포트포워딩은 공유기에 구멍을 뚫는 것이다. 뚫은 구멍 뒤의 서버가 약하면 그대로 공격당한다. 11일차 서버 보안에서 다시 다룬다.
{% endhint %}

## 5. 확인 질문

- 강의실 30명이 `curl ifconfig.me`를 입력하면? → 모두 같은 공인 IP가 나온다(PAT).
- 집에 NAS를 뒀는데 밖에서 접속이 안 된다. → NAT가 막는다. 포트포워딩(또는 VPN)이 필요하다.
- PAT가 여러 기기를 구분하는 기준은? → 포트 번호
- 브릿지가 아니라 NAT로 뒀다면 내 Windows에서 VM에 어떻게 들어가야 하나? → 포트포워딩(예: 2222 → 22)

## 6. 약어·용어

| 용어 | 뜻 |
|---|---|
| NAT | Network Address Translation. 사설 IP와 공인 IP의 변환 |
| PAT / NAT Overload | 포트 번호까지 변환해 공인 IP 하나를 여럿이 공유 |
| 변환표 | NAT 장비가 안쪽 주소와 바깥 주소의 짝을 기록한 표 |
| 포트포워딩 | 바깥에서 들어오는 포트를 안쪽 특정 기기로 보내는 고정 규칙 |
| Static NAT | 사설 1개와 공인 1개를 고정으로 짝짓는 방식 |

## 진행 메모

- `curl ifconfig.me`로 강의실 전체가 같은 IP를 보는 순간이 NAT 설명의 절반이다. 학생들에게 IP를 불러 보게 한다.
- "변환표"라는 단어를 꼭 쓴다. PAT, 포트포워딩, "밖에서 못 들어옴"이 전부 이 표 하나로 설명된다.
- 회수 표는 9, 10일차에 칠판에 적어 둔 주소들을 지우면서 진행한다.
- 이 노트와 10번은 10일차에 진도가 나가지 않았다. 11일차 공유기 실습 앞에 붙인다. → [11일차](../day-11/README.md)
- 시스코 CLI로 NAT를 직접 설정하는 것은 대본 부록으로 다룬다. 시간이 남으면 진행한다. → [0. 10일차 실습 명령어](commands.md)
- IPv6는 주소가 넉넉해서 원래 NAT가 필요 없다. 한 줄로만 언급한다(8일차 맛보기 회수).
