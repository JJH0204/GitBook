# 9. NAT 와 포트포워딩 — 사설 IP 는 어떻게 밖에 나가나

> 상위: [10일차 · 서버 기초](README.md)

## 🎯 학습 목표

- **NAT** 가 사설 IP 를 공인 IP 로 바꾸는 이유와 원리를 설명한다
- **PAT(NAT Overload)** 가 **포트 번호**로 여러 기기를 구분한다는 것을 안다
- NAT 는 **나가는 길만** 열어준다 → 들어오려면 **포트포워딩**이 필요하다는 것을 안다
- **강의실 전체가 공인 IP 하나를 나눠 쓴다**는 것을 `curl ifconfig.me` 로 확인한다

## 🌉 다리 놓기: "사설 IP 는 인터넷에 못 나간다고 했는데?"

2일차에 **사설 IP(`10.x` · `172.16~31.x` · `192.168.x`)는 인터넷에 직접 못 나간다**고 배웠다. → [3_공인IP와_사설IP](../../network1/day-02/lesson-3.md)
그런데 우리 VM 의 주소는 `192.168.x.x` — **사설**이다. 그런데도 **`apt update` 로 인터넷에서 프로그램을 받았다.** 어떻게?
[4_리눅스의_네트워크](lesson-4.md) 에서 본 게이트웨이 **`192.168.0.1`(강의실 공유기)** 이 무언가를 해주고 있다는 뜻이다.
→ 2일차에 **"회사 대표번호"** 로 맛만 본 **NAT** 가 바로 그 답이다.

---

## 📖 ① NAT — 나갈 때 주소를 바꿔 준다

**NAT** (Network Address Translation) = 사설망과 인터넷의 **경계(공유기 · 라우터)** 에서 **출발지 IP 를 바꿔치기**

```
 집 안 (사설)                         공유기 (NAT)                      인터넷 (공인)
 PC 192.168.0.100 ── 출발 192.168.0.100 ──▶ [ 바꿔치기 ] ── 출발 203.0.113.2 ──▶ 서버 8.8.8.8
                                           │ 변환표에 적어둔다 │
 PC 192.168.0.100 ◀── 도착 192.168.0.100 ── [ 되돌리기 ] ◀── 도착 203.0.113.2 ── 응답
```

| 왜 | 설명 |
|----|------|
| **주소 절약** | 집 안 기기 20대가 **공인 IP 1개**를 나눠 쓴다 → IPv4 고갈 대응 (2일차) |
| **숨김 (부수 효과)** | 밖에서는 **공유기만** 보인다. 안쪽 기기는 **먼저 말 걸지 않으면** 보이지 않는다 |

> 💡 **비유: 회사 대표번호 (2일차 그대로).** 직원(내선 101 · 102)이 밖으로 전화하면 상대 화면에는 **대표번호**가 뜬다.
> 상대가 **다시 걸면** 교환원이 "아까 102번이 건 거였지" 하고 **기록(변환표)을 보고** 연결해 준다.

### 🔎 내 눈으로 확인 — 주소가 몇 번 바뀌나

```bash
ip -br a | grep enp0s3           # 🐧 VM 안의 나:     192.168.x.x      (사설)
```
```powershell
ipconfig                         # 🪟 Windows:        192.168.x.y      (사설 — 같은 공유기 뒤!)
```
```bash
curl -s ifconfig.me ; echo       # 🌐 인터넷이 본 나: 211.x.x.x 같은   (공인!)
```

> 🗣 **"내 VM 은 한 번 변장하고 나갑니다."** `192.168.x.x` → (강의실 공유기 NAT) → **공인 IP**
> 🔎 **브릿지라서 VM 과 내 Windows 가 같은 동네**에 있다 — 게이트웨이가 똑같다
> 강의실 **모든 학생이 `curl ifconfig.me` 를 치면 같은 공인 IP 가 나온다** — 한 대표번호를 30명이 나눠 쓴다!

## 📖 ② PAT — 한 공인 IP 를 어떻게 여럿이 나누나 ⭐

공인 IP 는 **하나**인데 집 안 기기는 여럿이다. 응답이 돌아왔을 때 **누구에게** 돌려줄지 어떻게 알까?
→ **포트 번호까지 바꿔서** 변환표에 적는다 = **PAT** (Port Address Translation, 시스코 용어로 **NAT Overload**)

| 안쪽 (사설 IP : 포트) | ⇄ | 바깥쪽 (공인 IP : 포트) | 목적지 |
|----------------------|---|------------------------|--------|
| 192.168.0.100 : 51001 | ⇄ | 203.0.113.2 : **1024** | 8.8.8.8 : 80 |
| 192.168.0.101 : 51001 | ⇄ | 203.0.113.2 : **1025** | 8.8.8.8 : 80 |
| 192.168.0.102 : 49152 | ⇄ | 203.0.113.2 : **1026** | 8.8.8.8 : 53 |

- 응답이 `203.0.113.2 : 1025` 로 오면 → 표를 보고 → **`192.168.0.101 : 51001`** 로 돌려준다
- [8_포트번호와_소켓](lesson-8.md) 의 **"4개 값으로 연결 구분"** 을 공유기가 대신 해 주는 것
- 집 공유기 · 회사 방화벽 · 통신사 · VirtualBox — **요즘 NAT 라고 하면 거의 다 PAT** 다

| 종류 | 변환 | 쓰임 |
|------|------|------|
| Static NAT | 사설 1 ↔ 공인 1 (고정) | 서버를 밖에 공개할 때 |
| Dynamic NAT | 사설 여럿 ↔ **공인 풀**에서 빌려줌 | 드물다 |
| **PAT (Overload)** | 사설 여럿 ↔ **공인 1 + 포트** | ⭐ 집 · 회사 · 대부분 |

---

## 📖 ③ NAT 의 문제 — 밖에서는 못 들어온다

변환표는 **안에서 먼저 나간 뒤에야** 생긴다. 밖에서 **먼저** 들어오면?

```
 인터넷 누군가 ── "203.0.113.2 : 22 에 SSH 할게요" ──▶ 공유기: "변환표에 없는데? 누구 거지?" → 🗑 버림
```

- 그래서 집에 서버(NAS · 게임 서버 · CCTV)를 두면 **밖에서 안 들어와진다**
- NAT 의 **부수 효과인 보안**이 바로 이것 — 안쪽 기기는 기본적으로 **숨겨져 있다** (11일차 방화벽과 비교)

---

## 📖 ④ 포트포워딩 — 들어오는 문을 미리 뚫어 둔다

**포트포워딩** = 공유기에 **"이 포트로 들어오는 건 안쪽 이 기기의 이 포트로 보내"** 라고 **미리 적어 두는 것** (고정 변환표 한 줄)

```
 인터넷 ── 203.0.113.2 : 8080 ──▶ [공유기] 규칙: 8080 → 192.168.0.10 : 80 ──▶ 집 안 웹서버
```

> 💡 **비유: 대표번호 + 내선 자동 연결.** "대표번호로 전화해서 **내선 8080 을 누르면** 개발팀 10번 자리로 바로 연결" — 미리 설정해 둔 ARS

### 🎯 그래서 지금까지 본 것들의 정체

| 지금까지 본 것 | 정체 |
|--------------|------|
| VM 주소 **`192.168.x.x`** | 강의실 공유기가 **DHCP 로 준** 사설 주소 ([10_DNS와_DHCP_다시보기](lesson-10.md)) |
| 게이트웨이 **`192.168.0.1`** | 강의실 **공유기 = NAT 라우터** |
| 사설인데 **`apt update` 는 됐다** | **안에서 먼저 나간 것**이라 변환표가 생겼다 → **NAT** |
| 강의실 전체가 **같은 공인 IP** | 공인 하나를 포트로 나눠 쓴다 → **PAT** |
| 내 Windows 에서 **VM 으로 바로 SSH** 가 됐다 | **브릿지**라서 둘이 같은 동네 — NAT 를 건널 일이 없다 |
| 그런데 **집 밖에서** VM 에 들어가려면? | NAT 를 건너야 한다 → **포트포워딩**이 필요 |

```
 🌐 인터넷 ──▶ [ 강의실 공유기 · 공인 IP ] ──▶ 🐧 VM 192.168.x.x : 22
                    ▲ 규칙이 없으면 여기서 막힌다 (= NAT 의 부수 효과)
```

> 🗣 **"오늘의 핵심 질문의 답 — 나갈 때는 NAT 가 알아서 바꿔 주고, 들어올 때는 포트포워딩으로 문을 뚫어 줍니다. 한 쌍이에요."**
> 📌 **우리는 브릿지라서 교실 안에서는 포트포워딩이 필요 없었다.** 편한 만큼 **교실의 누구나 내 서버에 닿는다** → [11일차](../day-11/lesson-3.md)

> ⚠️ 포트포워딩 = **공유기에 구멍을 뚫는 것** → 뚫은 구멍 뒤의 서버가 약하면 그대로 공격당한다 → 11일차 서버 보안

## 📝 강의 메모

- **`curl ifconfig.me` 로 강의실 전체가 같은 IP 를 보는 순간**이 NAT 설명의 절반이다 — 학생들에게 IP 를 불러보게 한다
- **"변환표"** 라는 단어를 꼭 쓴다 — PAT · 포트포워딩 · "밖에서 못 들어옴" 이 전부 이 표 하나로 설명된다
- 회수 표는 **9·10일차에 칠판에 적어 둔 주소들을 지우면서** 진행
