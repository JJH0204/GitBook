## 학습 목표

- 포트 번호가 한 컴퓨터 안의 어느 프로그램을 가리키는지 안다.
- 포트 범위(Well-known, Registered, Dynamic)를 구분한다.
- 주요 서비스의 포트 번호와 TCP/UDP를 짝지어 외운다.
- 소켓 = IP + 포트를 이해하고, 한 서버가 여러 손님을 동시에 구분하는 원리를 안다.

## 이전 학습과의 연결

[6. 서버란 무엇인가](lesson-6.md)에서 한 서버에 `sshd`, DNS, 웹서버가 동시에 떠 있었다. IP는 `192.168.0.42` 하나다. 요청 패킷이 `192.168.0.42`에 도착했다. SSH에게 줄까, 웹서버에게 줄까?

IP는 컴퓨터까지만 데려다준다. 그 안의 프로그램을 고르는 번호가 필요하다. 이것이 포트다.

## 1. 포트 — 건물 안의 호실 번호

```
            IP 192.168.0.42 (건물 주소)
 ┌────────────────────────────────────────┐
 │  22호  sshd        (SSH)               │
 │  53호  systemd-resolved (DNS 도우미)    │
 │  80호  (비어 있음 — 웹서버 없음)          │
 │  8080호 python3 http.server (오늘 만든 것) │
 └────────────────────────────────────────┘
      패킷: "192.168.0.42 의 8080호로 배달"
```

{% hint style="info" %}
NOTE: IP는 건물 주소이고 포트는 호실 번호다. 택배 기사(IP)는 건물까지 오고, 호실 번호(포트)를 보고 문 앞에 둔다. 그 호실에 아무도 없으면(LISTEN 없음) 반송된다. `Connection refused`다.
{% endhint %}

- 포트는 0~65535다(16비트 = 2^16). 1일차 비트 계산의 회수다.
- 포트는 TCP와 UDP가 따로 있다. `TCP 53`과 `UDP 53`은 다른 문이다(DNS는 둘 다 연다).

## 2. 포트 범위

| 범위 | 이름 | 누가 쓰나 | 예 |
|---|---|---|---|
| 0~1023 | Well-known(잘 알려진) | 표준 서비스. 열려면 root 권한 | 22, 53, 80, 443 |
| 1024~49151 | Registered(등록된) | 특정 프로그램 | 3306(MySQL), 8080(웹 대체) |
| 49152~65535 | Dynamic(동적, 임시) | 클라이언트가 잠깐 쓰는 번호 | 브라우저가 매번 임의로 |

- 오늘 웹서버를 80이 아니라 8080에 띄운 이유는 1023 이하는 root(`sudo`)만 열 수 있기 때문이다(오전 권한 회수).
- 리눅스의 실제 임시 포트 범위는 `cat /proc/sys/net/ipv4/ip_local_port_range`로 확인한다. 보통 `32768 60999`이며 OS마다 조금 다르다.

## 3. 외워 둘 포트 — 8일차 표에 TCP/UDP를 더한다

| 포트 | 서비스 | 전송 | 기억법 |
|---|---|---|---|
| 20 / 21 | FTP(데이터 / 제어) | TCP | 20번대 시작 번호 |
| 22 | SSH | TCP | 9일차 접속 |
| 23 | Telnet | TCP | SSH 바로 옆(평문 형) |
| 25 | SMTP(메일 보내기) | TCP | 12일차 |
| 53 | DNS | UDP (+TCP) | |
| 67 / 68 | DHCP(서버 / 클라이언트) | UDP | 8일차 |
| 80 | HTTP | TCP | |
| 110 / 143 | POP3 / IMAP(메일 받기) | TCP | 12일차 |
| 161 / 162 | SNMP / Trap | UDP | 8일차 |
| 443 | HTTPS | TCP (HTTP/3는 UDP) | 80의 암호화판 |
| 3306 | MySQL | TCP | 14일차 |
| 3389 | RDP(Windows 원격 데스크톱) | TCP | |

- 리눅스에는 이 표가 파일로 있다. `cat /etc/services`(오전 "리눅스는 모든 것이 파일" 회수)
- UDP인 것만 따로 외우면 쉽다. DNS 53, DHCP 67/68, SNMP 161/162(그리고 TFTP 69, NTP 123). 나머지 대부분은 TCP다.

## 4. 소켓 — IP + 포트 = 대화의 주소

```
 내 PC 브라우저 탭 ①  192.168.0.10 : 51001 ──┐
 내 PC 브라우저 탭 ②  192.168.0.10 : 51002 ──┼──▶  서버 203.0.113.5 : 443
 옆자리 PC            192.168.0.11 : 51001 ──┘
```

- 소켓(Socket)은 IP와 포트 한 쌍이다(`203.0.113.5:443`).
- 연결 하나는 4개의 값으로 구분된다: 출발 IP, 출발 포트, 도착 IP, 도착 포트.
- 그래서 서버는 443 하나로 수천 명을 동시에 상대해도 헷갈리지 않는다. 출발 쪽이 전부 다르기 때문이다.

{% hint style="info" %}
NOTE: 콜센터 대표번호에 비유한다. 모두가 같은 번호(443)로 걸지만 콜센터는 발신자 번호(출발 IP:포트)로 누가 누구인지 구분한다.
{% endhint %}

```bash
ss -tn            # 지금 맺어진 TCP 연결 — Local(내 쪽), Peer(상대 쪽) 소켓이 보인다
```

```
State  Recv-Q Send-Q  Local Address:Port  Peer Address:Port
ESTAB  0      0       192.168.0.42:22     192.168.0.7:50514   ← 내 SSH 연결 (창 ①)
ESTAB  0      0       192.168.0.42:22     192.168.0.7:50522   ← 창 ② — 서버 포트는 같고, 상대 포트가 다르다
```

- 창 3개로 같은 서버의 22번에 붙었는데 섞이지 않는 이유는 상대 포트가 다 다르기 때문이다.
- 상대 IP가 바로 내 Windows 주소다(`ipconfig`로 확인). 브릿지라서 중간에 바뀌는 것이 없다.
- 그러면 인터넷에 나갈 때는 주소가 바뀔까? → [9. NAT와 포트포워딩](lesson-9.md)

## 5. 확인 질문

- 웹서버를 80번에 띄우려는데 `Permission denied`가 난다. → 1023 이하는 root만 열 수 있다. `sudo`가 필요하다.
- DNS는 TCP인가 UDP인가? → 보통 UDP 53이다. 큰 응답과 서버 간 복사는 TCP 53이다.
- 같은 PC에서 크롬 탭 10개로 같은 사이트에 접속해도 안 섞이는 이유는? → 탭마다 출발 포트(임시 포트)가 다르다.
- `ss -tln`에 `0.0.0.0:3306`과 `127.0.0.1:3306`의 차이는? → 전자는 밖에서도, 후자는 나 자신만 접속할 수 있다. DB는 보통 후자다(11일차 보안).

## 6. 약어·용어

| 용어 | 뜻 |
|---|---|
| 포트 | 한 컴퓨터 안에서 프로그램을 구분하는 번호(0~65535) |
| Well-known 포트 | 0~1023. 표준 서비스용 |
| 임시 포트(ephemeral) | 클라이언트가 연결마다 임의로 받는 포트 |
| 소켓 | IP와 포트의 쌍 |
| `/etc/services` | 포트 번호와 서비스 이름 표 파일 |
| `0.0.0.0` | 모든 인터페이스를 뜻하는 주소 |

## 진행 메모

- 건물과 호실 비유가 제일 잘 먹힌다. 칠판 그림 하나로 설명한다.
- 포트표는 8일차 칠판의 번호순 표에 "UDP" 도장만 찍는 방식으로 다룬다. 새로 외우는 것이 아니라 추가다.
- "UDP인 것만 외워라"가 시험 팁이다. 나머지는 TCP다.
- 소켓의 상대 주소가 내 Windows IP와 같은 것을 확인시킨다. 브릿지의 의미가 한 번 더 굳는다.
