# 6. 메일 서버 — 편지는 어떻게 배달되나 (그리고 왜 직접 세우지 않나)

> 상위: [12일차 · 리눅스 서버 구축](README.md)

> 🅿️ **12일차에는 다루지 않는다** (4시간 제약) → **13일차**로 넘겼다. 노트는 그대로 두니 미리 읽어 와도 좋다.

## 🎯 학습 목표

- **SMTP(보내기)** 와 **POP3 / IMAP(가져오기)** 의 역할을 구분한다
- 메일이 배달되는 경로에서 **MX 레코드**가 하는 일을 설명한다
- `nc` 로 **SMTP 대화를 직접 타이핑**해서 메일 한 통을 보낸다 ⭐
- 오늘날 **메일 서버를 직접 운영하기 어려운 이유**(25번 차단 · SPF/DKIM/DMARC · 블랙리스트)를 안다

## 🌉 다리 놓기: "MX 레코드를 방금 적었는데요"

[5_DNS서버_bind9](lesson-5.md) 존 파일에 이 한 줄을 적었다.

```
@   IN  MX  10  mail.student.local.
```

> 🗣 **"`student.local` 로 오는 메일은 `mail.student.local` 이 받는다"** 는 선언이다. 그 서버는 무엇을 하길래?

1일차부터 우리는 네트워크를 **"편지 부치기"** 에 비유해 왔다. 오늘은 **진짜 편지**를 다룬다.

## 📖 ① 편지의 한살이 — 프로토콜 3개

```
 보내는 사람                                                         받는 사람
 📧 메일 앱 ──①SMTP(25/587)──▶ 보내는 쪽 메일서버
                                   │ ②MX 조회 (DNS!)
                                   ▼
                              받는 쪽 메일서버 ──③ 사서함에 저장
                                   │
 📧 메일 앱 ◀──④ POP3(110) / IMAP(143) ── "내 편지 주세요"
```

| 단계 | 프로토콜 | 포트 | 비유 |
|------|----------|------|------|
| ① 보내기 | **SMTP** | 25 · **587**(제출) · 465(암호화) | **우체통에 넣기** |
| ② 어디로? | **DNS MX 조회** | 53 | **주소록에서 우체국 찾기** ⭐ |
| ③ 서버→서버 | SMTP | 25 | **우체국 간 운송** |
| ④ 가져오기 | **POP3** / **IMAP** | 110 / 143 (암호화 995 / 993) | **우편함 열기** |

> 💡 **SMTP 는 '밀어 넣는' 프로토콜, POP3·IMAP 은 '꺼내 오는' 프로토콜.** 그래서 **보내기는 되는데 받기가 안 되는** 고장이 따로 존재한다.

| | **POP3** | **IMAP** ⭐ 요즘 |
|---|---|---|
| 방식 | 내려받고 **서버에서 지운다** | **서버에 두고 동기화**한다 |
| 여러 기기 | 불리하다 (한 기기에만 남는다) | 폰 · PC 가 **같은 상태** |
| 비유 | 우편함을 **비운다** | 우편함을 **같이 들여다본다** |

- 메일 서버 프로그램도 역할이 나뉜다: **MTA**(운송 · Postfix · Sendmail) / **MDA**(사서함에 넣기 · Dovecot) / **MUA**(사람이 쓰는 앱 · Outlook)

## 📖 ② 실습 — SMTP 대화를 손으로 친다 ⭐

메일 프로토콜은 사람이 읽을 수 있는 **평문 대화**다. 그래서 **손으로 타이핑할 수 있다.**

### ① 설치 — Postfix (Local only)

```bash
sudo apt install postfix mailutils -y
```

- 설치 중 파란 화면이 뜬다 → **`Local only`** 선택 · 시스템 메일 이름은 기본값
- ⚠️ **`Internet Site` 를 고르면 안 된다** — 바깥으로 메일을 보내려다 실패 로그만 쌓인다

### ④ 확인

```bash
systemctl status postfix
sudo ss -tulnp | grep :25          # 127.0.0.1:25 LISTEN — 나 자신에게만 열려 있다
```

> 🗣 **"`127.0.0.1:25` — 10일차에 배운 그 구분입니다. 이 서버는 밖에서는 아예 보이지 않습니다."**

### ⑥ 검증 — `nc` 로 우체통에 직접 말 걸기

```bash
nc localhost 25
```

```
220 ubuntu ESMTP Postfix              ← 서버가 먼저 인사한다
HELO student.local                    ← 내가 인사
250 ubuntu
MAIL FROM:<student@localhost>         ← 보내는 사람
250 2.1.0 Ok
RCPT TO:<student@localhost>           ← 받는 사람
250 2.1.5 Ok
DATA
354 End data with <CR><LF>.<CR><LF>
Subject: 12일차 첫 메일

리눅스 서버가 보낸 편지입니다.
.                                     ← 마침표 한 개만 있는 줄 = 끝 ⭐
250 2.0.0 Ok: queued as ...
QUIT
```

```bash
mail                      # 사서함 확인 (q 로 나가기)
cat /var/mail/student     # 파일로도 보인다
sudo tail -20 /var/log/mail.log      # 배달 기록 ⭐
```

> 🗣 **"방금 메일 클라이언트 없이, 손으로 메일을 보냈습니다. SMTP 는 이렇게 단순한 대화입니다."**
> ⚠️ 그래서 **`MAIL FROM` 에 아무 주소나 적을 수 있다** — 발신자 위조(스푸핑)가 쉬운 이유. 이 한 줄이 다음 절로 이어진다.

## 📖 ③ 왜 회사들은 메일 서버를 직접 안 세우나

이 절이 오늘 메일 파트의 **진짜 결론**이다.

| 장벽 | 내용 |
|------|------|
| **25번 포트 차단** | 대부분의 ISP·클라우드가 **아웃바운드 25 를 막는다** (스팸 방지). 집 회선에서는 아예 못 보낸다 |
| **발신자 인증 3종** | **SPF**(TXT 레코드: 이 IP 만 우리 메일 보냄) · **DKIM**(전자 서명) · **DMARC**(위반 시 정책) — 없으면 **스팸함 직행** |
| **역방향 DNS(PTR)** | 내 IP → 도메인이 되돌려 풀려야 받아준다 |
| **블랙리스트** | 한 번 오르면 배달이 통째로 막힌다 |
| **24시간 운영** | 메일은 **놓치면 안 되는** 서비스다 |

> 🗣 **"기술적으로는 오늘처럼 30분이면 세웁니다. 그런데 남이 받아주느냐가 진짜 문제입니다."**
> 그래서 현실은 **Google Workspace · 네이버웍스 · MS 365** 를 쓰고, 개발자는 **메일 발송 API**(SendGrid · SES 등)를 쓴다 → **API** 는 15일차에 `kubectl` 과 함께 다룬다 → [15일차](../day-15/README.md)

- 앞의 **SPF 가 TXT 레코드**라는 점을 강조: 어제 만든 **DNS 존 파일에 한 줄 추가**하는 일이다 → 메일은 **DNS 위에 서 있다**

```bash
dig +short MX gmail.com          # 진짜 도메인의 MX 를 구경한다
dig +short TXT gmail.com | head  # v=spf1 ... 이 보인다 ⭐
```
