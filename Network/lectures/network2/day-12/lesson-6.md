## 학습 목표

- SMTP(보내기)와 POP3, IMAP(가져오기)의 역할을 구분한다.
- 메일이 배달되는 경로에서 MX 레코드가 하는 일을 설명한다.
- `nc`로 SMTP 대화를 직접 타이핑해서 메일 한 통을 보낸다.
- 오늘날 메일 서버를 직접 운영하기 어려운 이유(25번 차단, SPF/DKIM/DMARC, 블랙리스트)를 안다.

## 1. 목적

[5. DNS 서버](lesson-5.md) 존 파일에 이 한 줄을 적었다.

```
@   IN  MX  10  mail.student.local.
```

"`student.local`로 오는 메일은 `mail.student.local`이 받는다"는 선언이다. 그 서버는 무엇을 하는가? 1일차부터 네트워크를 "편지 부치기"에 비유해 왔다. 오늘은 진짜 편지를 다룬다.

절차는 [Postfix와 SMTP 직접 입력 실습](lesson-6-lab.md)에 있다.

## 2. 구성 요소

### 편지의 한살이: 프로토콜 3개

```
 보내는 사람                                                         받는 사람
 메일 앱 ──①SMTP(25/587)──▶ 보내는 쪽 메일서버
                                   │ ②MX 조회 (DNS)
                                   ▼
                              받는 쪽 메일서버 ──③ 사서함에 저장
                                   │
 메일 앱 ◀──④ POP3(110) / IMAP(143) ── "내 편지 주세요"
```

| 단계 | 프로토콜 | 포트 | 비유 |
|---|---|---|---|
| ① 보내기 | SMTP | 25, 587(제출), 465(암호화) | 우체통에 넣기 |
| ② 어디로? | DNS MX 조회 | 53 | 주소록에서 우체국 찾기 |
| ③ 서버에서 서버로 | SMTP | 25 | 우체국 간 운송 |
| ④ 가져오기 | POP3 / IMAP | 110 / 143 (암호화 995 / 993) | 우편함 열기 |

SMTP는 밀어 넣는 프로토콜이고 POP3와 IMAP은 꺼내 오는 프로토콜이다. 그래서 보내기는 되는데 받기가 안 되는 고장이 따로 존재한다.

| | POP3 | IMAP(요즘) |
|---|---|---|
| 방식 | 내려받고 서버에서 지운다 | 서버에 두고 동기화한다 |
| 여러 기기 | 불리하다(한 기기에만 남는다) | 폰과 PC가 같은 상태 |
| 비유 | 우편함을 비운다 | 우편함을 같이 들여다본다 |

메일 서버 프로그램도 역할이 나뉜다.

| 구분 | 역할 | 예 |
|---|---|---|
| MTA | 운송 | Postfix, Sendmail |
| MDA | 사서함에 넣기 | Dovecot |
| MUA | 사람이 쓰는 앱 | Outlook |

### 여섯 단계로 본 구축(Postfix)

| 단계 | 내용 |
|---|---|
| ① 설치 | `sudo apt install postfix mailutils -y`. 설치 중 파란 화면에서 `Local only`를 고르고 시스템 메일 이름은 기본값으로 둔다 |
| ④ 확인 | `systemctl status postfix`, `sudo ss -tulnp \| grep :25` → `127.0.0.1:25 LISTEN`(나 자신에게만 열려 있다) |
| ⑥ 검증 | `nc localhost 25`로 SMTP 대화를 직접 친다 |

{% hint style="warning" %}
CAUTION: `Internet Site`를 고르면 안 된다. 바깥으로 메일을 보내려다 실패 로그만 쌓인다.
{% endhint %}

`127.0.0.1:25`는 10일차에 배운 그 구분이다. 이 서버는 밖에서는 아예 보이지 않는다.

## 3. 동작 원리

### SMTP 대화를 손으로 친다

메일 프로토콜은 사람이 읽을 수 있는 평문 대화다. 그래서 손으로 타이핑할 수 있다.

```
220 ubuntu ESMTP Postfix              ← 서버가 먼저 인사한다
HELO student.local                    ← 내가 인사
250 ubuntu
MAIL FROM:<student@localhost>         ← 보내는 사람
250 2.1.0 Ok
RCPT TO:<student@localhost>           ← 받는 사람
250 2.1.5 Ok
DATA
354 End data with <CR><LF>.<CR><LF>
Subject: 12일차 첫 메일

리눅스 서버가 보낸 편지입니다.
.                                     ← 마침표 한 개만 있는 줄 = 끝
250 2.0.0 Ok: queued as ...
QUIT
```

확인은 `mail`(사서함, `q`로 나가기), `cat /var/mail/student`, `sudo tail -20 /var/log/mail.log`(배달 기록)로 한다.

메일 클라이언트 없이 손으로 메일을 보냈다. SMTP는 이렇게 단순한 대화다.

{% hint style="warning" %}
CAUTION: `MAIL FROM`에 아무 주소나 적을 수 있다. 발신자 위조(스푸핑)가 쉬운 이유다. 이 한 줄이 다음 절로 이어진다.
{% endhint %}

### 왜 회사들은 메일 서버를 직접 안 세우나

이 절이 오늘 메일 파트의 진짜 결론이다.

| 장벽 | 내용 |
|---|---|
| 25번 포트 차단 | 대부분의 ISP와 클라우드가 아웃바운드 25를 막는다(스팸 방지). 집 회선에서는 아예 못 보낸다 |
| 발신자 인증 3종 | SPF(TXT 레코드: 이 IP만 우리 메일 보냄), DKIM(전자 서명), DMARC(위반 시 정책). 없으면 스팸함 직행 |
| 역방향 DNS(PTR) | 내 IP에서 도메인이 되돌려 풀려야 받아준다 |
| 블랙리스트 | 한 번 오르면 배달이 통째로 막힌다 |
| 24시간 운영 | 메일은 놓치면 안 되는 서비스다 |

기술적으로는 오늘처럼 30분이면 세운다. 그런데 남이 받아주느냐가 진짜 문제다. 그래서 현실은 Google Workspace, 네이버웍스, MS 365를 쓰고, 개발자는 메일 발송 API(SendGrid, SES 등)를 쓴다. API는 15일차에 `kubectl`과 함께 다룬다. → [15일차](../day-15/README.md)

SPF가 TXT 레코드라는 점에 주목한다. 앞서 만든 DNS 존 파일에 한 줄 추가하는 일이다. 메일은 DNS 위에 서 있다.

```bash
dig +short MX gmail.com          # 진짜 도메인의 MX를 구경한다
dig +short TXT gmail.com | head  # v=spf1 ... 이 보인다
```

## 5. 약어·용어

| 용어 | 뜻 |
|---|---|
| SMTP (Simple Mail Transfer Protocol) | 메일을 보내는 프로토콜. 25, 587, 465 |
| POP3 / IMAP | 메일을 가져오는 프로토콜. IMAP은 서버에 두고 동기화한다 |
| MX 레코드 | 도메인의 메일 받는 서버를 가리키는 DNS 레코드 |
| MTA / MDA / MUA | 운송 / 사서함 전달 / 사용자 앱 |
| Postfix | 대표적인 MTA |
| SPF / DKIM / DMARC | 발신자 인증 3종. IP 허용 목록 / 전자 서명 / 위반 시 정책 |
| PTR | IP에서 도메인으로 되돌려 푸는 역방향 DNS 레코드 |
| 스푸핑 (spoofing) | 발신자 등을 속이는 것 |

## 강의 메모

- 이론 위주로 간다. 실습은 `nc`로 한 통 보내는 것까지다(Dovecot까지 세우면 하루가 다 간다).
- 하이라이트는 `MAIL FROM`에 아무나 적을 수 있다는 장면이다. "그래서 피싱 메일이 존재한다"로 11일차 보안과 연결한다.
- Postfix 설치 중 파란 debconf 화면에서 학생들이 멈춘다. Tab으로 이동하고 Enter로 선택하는 것을 미리 안내한다(9일차 우분투 설치 화면과 같은 조작).
- 되짚기: 5번 MX 레코드, 10일차 `ss`의 `127.0.0.1` vs `0.0.0.0`, 3번 평문 프로토콜.
- 다음: 지금까지는 서버가 직접 응답했다. 중간에서 대신 다녀오는 서버도 있다. → [7. Proxy 서버](lesson-7.md)
