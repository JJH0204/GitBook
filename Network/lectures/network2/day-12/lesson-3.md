# 3. FTP 서버 (vsftpd) — 파일 전용 통로, 그리고 평문의 증거

> 상위: [12일차 · 리눅스 서버 구축](README.md)

## 🎯 학습 목표

- **vsftpd** 를 설치 · 설정 · 기동해 FTP 서버를 구축한다
- FTP 의 **제어 연결(21)** 과 **데이터 연결(20 / 패시브 포트)** 이 **왜 두 개**인지 설명한다
- **액티브 모드 vs 패시브 모드**를 그림으로 설명하고, 왜 요즘은 패시브인지 안다
- `tcpdump` 로 **FTP 비밀번호가 평문으로 흐르는 것을 직접 본다** ⭐

## 🌉 다리 놓기: "scp 가 있는데 왜 FTP 를?"

[2_SSH_다시보기와_파일전송](lesson-2.md) 에서 `scp` 로 이미 파일을 옮겨 봤다. 더 간단하고 더 안전한데, 왜 FTP 를 배울까?

1. **아직도 쓰인다** — 웹호스팅, 공공기관 자료실, 네트워크 장비의 **설정 백업 · IOS 업로드**(8일차) → [3_SNMP_Proxy_FTP](../../network1/day-08/lesson-3.md)
2. **네트워크 공부 교재로 최고다** — 연결을 **두 개** 쓰기 때문에 **방화벽 · NAT 와 정면으로 부딪친다.** 10 · 11일차에 배운 게 전부 튀어나온다
3. **"평문이 위험하다"를 말이 아니라 화면으로** 보여줄 수 있다 ⭐

## 📖 ① FTP 는 왜 연결이 두 개인가 ⭐

```
 클라이언트                                   FTP 서버
    │ ── ① 제어 연결 (TCP 21) ────────────▶   "로그인" "목록 줘" "이 파일 줘"
    │      명령과 응답만 오간다 · 계속 유지
    │
    │ ── ② 데이터 연결 (TCP 20 또는 임의 포트) ──  파일 내용 · 목록이 실제로 흐른다
    │      파일 하나 옮길 때마다 열었다 닫는다
```

| | 제어 연결 | 데이터 연결 |
|---|---|---|
| 포트 | **21** | **20**(액티브) 또는 **임의의 높은 포트**(패시브) |
| 흐르는 것 | 명령(`USER` `PASS` `LIST` `RETR`) | **파일 내용** |
| 수명 | 접속 내내 | 전송할 때마다 새로 |

> 💡 **비유: 전화로 주문하고, 택배로 받는다.** 통화(21번)로는 "그 물건 보내주세요"만 하고, 물건 자체는 **택배(데이터 연결)** 로 따로 온다.
> 그래서 **전화는 됐는데 택배가 안 오는** 일이 생긴다 = FTP 가 "연결은 됐는데 목록이 안 나오는" 바로 그 증상.

### 액티브 vs 패시브 — 누가 문을 여나

| | **액티브 (Active)** | **패시브 (Passive)** ⭐ 요즘 기본 |
|---|---|---|
| 데이터 연결을 **거는 쪽** | **서버** → 클라이언트 | **클라이언트** → 서버 |
| 서버가 쓰는 포트 | 20 | `pasv_min_port ~ pasv_max_port` |
| 막히는 이유 | 클라이언트가 **NAT · 방화벽 뒤**에 있으면 서버가 **들어올 수 없다** | 클라이언트가 걸므로 통과 |
| 명령 | `PORT` | `PASV` |

> 🗣 **"액티브 모드는 서버가 나에게 전화를 겁니다. 그런데 나는 공유기 뒤에 있죠. 10일차에 배웠듯 밖에서 안으로 먼저 거는 건 포트포워딩 없이는 불가능합니다."**
> → [10일차 NAT · 포트포워딩](../day-10/lesson-9.md) 이 여기서 바로 회수된다. **그래서 패시브가 표준이 됐다.**

- 패시브는 서버 쪽에 **포트 범위**를 열어야 한다 → 방화벽 규칙이 한 줄 더 필요하다 (아래 ⑤)

## 📖 ② 구축 — 여섯 단계 그대로

### ① 설치

```bash
sudo apt install vsftpd -y      # very secure FTP daemon
```

### ② 설정 — `/etc/vsftpd.conf`

```bash
sudo cp /etc/vsftpd.conf /etc/vsftpd.conf.bak
sudo nano /etc/vsftpd.conf
```

| 설정 | 값 | 뜻 |
|------|----|----|
| `anonymous_enable` | **`NO`** | 아무나(익명) 접속 금지 |
| `local_enable` | **`YES`** | **리눅스 계정**(student)으로 로그인 허용 |
| `write_enable` | **`YES`** | **업로드** 허용 (기본은 읽기만) |
| `chroot_local_user` | `YES` | 자기 홈 **위로 못 올라가게** 가둔다 🔒 |
| `allow_writeable_chroot` | `YES` | ⚠️ 위를 켜면 **이 줄이 없으면 접속이 실패**한다 |
| `pasv_min_port` / `pasv_max_port` | `40000` / `40010` | 패시브 데이터 포트 범위 |

> ⚠️ **오늘 1번 함정**: `chroot_local_user=YES` 만 켜고 `allow_writeable_chroot=YES` 를 빠뜨리면
> `500 OOPS: vsftpd: refusing to run with writable root inside chroot()` — 보안 장치가 작동한 것이지 고장이 아니다.

### ③ 기동 · ④ 확인

```bash
sudo systemctl restart vsftpd
systemctl status vsftpd                 # active (running)
sudo ss -tulnp | grep -E ':21|vsftpd'   # 0.0.0.0:21 LISTEN
```

### ⑤ 개방 (방화벽을 켠 경우)

```bash
sudo ufw allow 21/tcp
sudo ufw allow 40000:40010/tcp          # 패시브 범위 — 콜론 표기
```

### ⑥ 검증

```bash
sudo apt install ftp -y
ftp localhost                           # 계정 student · 비밀번호
# ftp> ls / put / get / bye
```

## 📖 ③ 평문의 증거 — 비밀번호를 눈으로 본다 ⭐⭐

10일차에 `tcpdump` 로 3-way handshake 를 봤다. 오늘은 **내용**을 본다.

```bash
# 🐧③ 관찰 창
sudo tcpdump -i lo -n -A 'tcp port 21'
```

```bash
# 🐧② 클라이언트 창
ftp localhost
```

관찰 창에 이런 줄이 뜬다.

```
...  USER student
...  331 Please specify the password.
...  PASS example-password4          ← ⚠️ 비밀번호가 그대로
```

> 🗣 **"방금 여러분의 비밀번호가 화면에 찍혔습니다. 지금은 내 컴퓨터 안(`lo`)이라 나만 봤지만, 이게 회사 스위치를 지나갔다면?"**
> 이것이 8일차부터 반복해 온 **평문 vs 암호화**의 실물 증거다. **Telnet 도 정확히 같다** — 그래서 오늘 Telnet 서버는 세우지 않았다.

### 대안 — 같은 일을 안전하게

| 평문 | 암호화 대안 | 포트 |
|------|-------------|------|
| FTP | **SFTP** (SSH 위에서) | 22 — **새로 열 게 없다** |
| FTP | FTPS (FTP + TLS) | 21 / 990 |
| Telnet | SSH | 22 |

```bash
sudo tcpdump -i lo -n -A 'tcp port 22'     # 같은 방법으로 sftp 를 엿보면? → 알아볼 수 없는 문자
```

> 🗣 **"똑같이 엿봤는데 글자가 안 보이죠. 이게 암호화입니다."** — 비교를 **연달아** 보여줘야 각인된다.

## 📝 강의 메모

- ⭐ **오늘의 하이라이트는 `tcpdump` 화면**이다. 여기서 수업이 한 번 조용해진다 — 충분히 뜸을 들일 것
- 순서 주의: **`ftp` 클라이언트를 먼저 깔아둬야** 검증이 매끄럽다 (`apt install ftp`)
- 📌 Windows 탐색기 · FileZilla 로 접속시키려면 **VirtualBox 포트포워딩** 에 `21→21` + `40000-40010` 이 필요하다 → 범위 포워딩은 규칙을 여러 개 만들어야 해서 번거롭다. **수업은 VM 안에서 `ftp localhost`** 로 하고, 원하면 대본 **부록 A** 로
  - ✅ **10일차(2026-09-20) 실전에서 이 메모가 적중했다** — FileZilla 접속이 `500` 대 에러로 실패해 급히 **윈도우 내장 `ftp`(액티브 모드)** 로 우회했다. 원인 후보(패시브 데이터 포트 미개방 / `AUTH TLS` 거부)와 로그 읽는 법은 [10일차 복습](../day-10/lesson-12.md) 🔧 절에 정리. **리허설에서 재현해 원인 확정할 것**
- 비유 정리: **전화(21) + 택배(20/패시브)** · **액티브 = 서버가 나에게 전화 걸기(NAT 뒤에서는 실패)**
