## 2. 구성 요소

### FTP는 왜 연결이 두 개인가

```
 클라이언트                                   FTP 서버
    │ ── ① 제어 연결 (TCP 21) ────────────▶   "로그인" "목록 줘" "이 파일 줘"
    │      명령과 응답만 오간다 · 계속 유지
    │
    │ ── ② 데이터 연결 (TCP 20 또는 임의 포트) ──  파일 내용 · 목록이 실제로 흐른다
    │      파일 하나 옮길 때마다 열었다 닫는다
```

| | 제어 연결 | 데이터 연결 |
|---|---|---|
| 포트 | 21 | 20(액티브) 또는 임의의 높은 포트(패시브) |
| 흐르는 것 | 명령(`USER`, `PASS`, `LIST`, `RETR`) | 파일 내용 |
| 수명 | 접속 내내 | 전송할 때마다 새로 |

비유: 전화로 주문하고 택배로 받는다. 통화(21번)로는 "그 물건 보내주세요"만 하고, 물건 자체는 택배(데이터 연결)로 따로 온다. 그래서 전화는 됐는데 택배가 안 오는 일이 생긴다. 이것이 "FTP에 연결은 됐는데 목록이 안 나오는" 바로 그 증상이다.

### 액티브 vs 패시브: 누가 문을 여나

| | 액티브(Active) | 패시브(Passive), 요즘 기본 |
|---|---|---|
| 데이터 연결을 거는 쪽 | 서버가 클라이언트로 | 클라이언트가 서버로 |
| 서버가 쓰는 포트 | 20 | `pasv_min_port` ~ `pasv_max_port` |
| 막히는 이유 | 클라이언트가 NAT나 방화벽 뒤에 있으면 서버가 들어올 수 없다 | 클라이언트가 걸므로 통과 |
| 명령 | `PORT` | `PASV` |

액티브 모드는 서버가 나에게 전화를 건다. 그런데 나는 공유기 뒤에 있다. 10일차에 배웠듯 밖에서 안으로 먼저 거는 것은 포트포워딩 없이는 불가능하다. → [10일차 NAT, 포트포워딩](../day-10/lesson-9.md) 그래서 패시브가 표준이 됐다.

패시브는 서버 쪽에 포트 범위를 열어야 한다. 방화벽 규칙이 한 줄 더 필요하다.

### vsftpd 설정 항목(`/etc/vsftpd.conf`)

| 설정 | 값 | 뜻 |
|---|---|---|
| `anonymous_enable` | `NO` | 아무나(익명) 접속 금지 |
| `local_enable` | `YES` | 리눅스 계정(student)으로 로그인 허용 |
| `write_enable` | `YES` | 업로드 허용(기본은 읽기만) |
| `chroot_local_user` | `YES` | 자기 홈 위로 못 올라가게 가둔다 |
| `allow_writeable_chroot` | `YES` | 위를 켜면 이 줄이 없을 때 접속이 실패한다 |
| `pasv_min_port` / `pasv_max_port` | `40000` / `40010` | 패시브 데이터 포트 범위 |

{% hint style="warning" %}
CAUTION: `chroot_local_user=YES`만 켜고 `allow_writeable_chroot=YES`를 빠뜨리면 `500 OOPS: vsftpd: refusing to run with writable root inside chroot()`로 접속이 거부된다. 보안 장치가 작동한 것이지 고장이 아니다.
{% endhint %}

### 여섯 단계로 본 구축

| 단계 | 내용 |
|---|---|
| ① 설치 | `sudo apt install vsftpd -y` (very secure FTP daemon) |
| ② 설정 | `/etc/vsftpd.conf` 백업 후 편집 |
| ③ 기동, ④ 확인 | `sudo systemctl restart vsftpd`, `systemctl status vsftpd`, `sudo ss -tulnp \| grep -E ':21\|vsftpd'` → `0.0.0.0:21 LISTEN` |
| ⑤ 개방 | `sudo ufw allow 21/tcp`, `sudo ufw allow 40000:40010/tcp`(패시브 범위는 콜론 표기) |
| ⑥ 검증 | `sudo apt install ftp -y` 후 `ftp localhost`(계정 student, 비밀번호) |

## 3. 동작 원리

### 평문의 증거: 비밀번호를 눈으로 본다

10일차에 `tcpdump`로 3-way handshake를 봤다. 오늘은 내용을 본다. 관찰 창에서 `sudo tcpdump -i lo -n -A 'tcp port 21'`을 켜고, 클라이언트 창에서 `ftp localhost`로 로그인하면 관찰 창에 다음 줄이 뜬다.

```
...  USER student
...  331 Please specify the password.
...  PASS <password>          ← 비밀번호가 그대로 보인다
```

방금 내 비밀번호가 화면에 찍혔다. 지금은 내 컴퓨터 안(`lo`)이라 나만 봤지만, 이것이 회사 스위치를 지나갔다면 누구나 볼 수 있다. 8일차부터 반복해 온 평문 vs 암호화의 실물 증거다. Telnet도 정확히 같다. 그래서 오늘 Telnet 서버는 세우지 않았다.

### 대안: 같은 일을 안전하게

| 평문 | 암호화 대안 | 포트 |
|---|---|---|
| FTP | SFTP(SSH 위에서) | 22. 새로 열 것이 없다 |
| FTP | FTPS(FTP + TLS) | 21 / 990 |
| Telnet | SSH | 22 |

같은 방법(`sudo tcpdump -i lo -n -A 'tcp port 22'`)으로 sftp를 엿보면 알아볼 수 없는 문자만 흐른다. 이것이 암호화다. 비교를 연달아 보여줘야 각인된다.

## 5. 약어·용어

| 용어 | 뜻 |
|---|---|
| FTP (File Transfer Protocol) | 파일 전송 프로토콜. 제어 21, 데이터 20 또는 패시브 포트 |
| vsftpd | very secure FTP daemon. 우분투의 FTP 서버 |
| 액티브 / 패시브 | 데이터 연결을 서버가 걸면 액티브, 클라이언트가 걸면 패시브 |
| chroot | 사용자가 자기 홈 폴더 밖으로 나가지 못하게 가두는 기능 |
| SFTP | SSH 위에서 동작하는 파일 전송(22번) |
| FTPS | FTP에 TLS 암호화를 더한 것 |
| `tcpdump` | 패킷을 캡처해 내용을 보는 명령 |

## 강의 메모

- 오늘의 하이라이트는 `tcpdump` 화면이다. 여기서 수업이 한 번 조용해진다. 충분히 뜸을 들인다.
- 순서 주의: `ftp` 클라이언트를 먼저 설치해 두어야 검증이 매끄럽다(`apt install ftp`).
- Windows 탐색기나 FileZilla로 접속시키려면 VirtualBox 포트포워딩에 `21→21`과 `40000-40010`이 필요하다. 범위 포워딩은 규칙을 여러 개 만들어야 해서 번거롭다. 수업은 VM 안에서 `ftp localhost`로 하고, 원하면 대본 부록 A를 쓴다.
  - 10일차(2026-09-20) 실전에서 이 메모가 적중했다. FileZilla 접속이 `500`대 에러로 실패해 급히 Windows 내장 `ftp`(액티브 모드)로 우회했다. 원인 후보(패시브 데이터 포트 미개방, `AUTH TLS` 거부)와 로그 읽는 법은 [10일차 복습](../day-10/lesson-12.md)에 정리돼 있다. 리허설에서 재현해 원인을 확정한다.
- 비유 정리: 전화(21)와 택배(20 또는 패시브), 액티브는 서버가 나에게 전화 걸기(NAT 뒤에서는 실패).
