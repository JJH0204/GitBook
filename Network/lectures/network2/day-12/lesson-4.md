# 4. NFS — 옮기지 않고, 폴더째 붙여 쓴다

> 상위: [12일차 · 리눅스 서버 구축](README.md)

> 🅿️ **12일차에는 다루지 않는다** (4시간 제약) → **13일차**로 넘겼다. 노트는 그대로 두니 미리 읽어 와도 좋다.

## 🎯 학습 목표

- **파일 전송(FTP·scp)** 과 **파일 공유(NFS)** 의 차이를 설명한다
- **`/etc/exports`** 로 공유할 폴더를 내보내고, 클라이언트에서 **`mount`** 로 붙인다
- **마운트(mount)** 가 "폴더에 다른 저장소를 끼워 넣는 것"임을 이해한다
- 리눅스의 **NFS** 와 윈도우의 **SMB(공유 폴더)** 를 구분한다

## 🌉 다리 놓기: "매번 옮기는 게 맞나?"

[3_FTP서버_vsftpd](lesson-3.md) 로 파일을 **복사**했다. 그런데 복사본은 곧 **원본과 달라진다.**
웹서버 3대가 같은 사진 폴더를 봐야 한다면? 매번 3번 업로드할 수는 없다.

> 🗣 **"파일을 보내는 대신, 폴더 자체를 빌려주면 어떨까요?"**

그게 **NFS** (Network File System) — 서버의 폴더를 **내 컴퓨터의 폴더인 것처럼** 붙여 쓰는 방식이다.

| | 파일 **전송** (FTP · scp) | 파일 **공유** (NFS · SMB) |
|---|---|---|
| 하는 일 | **복사본**을 만든다 | **원본을 같이 본다** |
| 수정하면 | 각자 따로 논다 | **모두에게 즉시** 반영 |
| 느낌 | 택배 | **USB 를 꽂은 것** |
| 대표 | FTP · SFTP · scp | **NFS**(리눅스) · **SMB/CIFS**(윈도우) |

> 💡 **비유: 사진을 카톡으로 보내기 vs 공유 앨범.** 보낸 사진은 내가 지워도 상대에겐 남는다(복사본). 공유 앨범은 **한 곳**을 같이 본다.

## 📖 ① 마운트 — 리눅스에 드라이브 문자가 없는 이유

윈도우는 저장 장치마다 `C:` `D:` 가 붙는다. 리눅스는 **하나의 나무(`/`)** 뿐이다(10일차).
그럼 USB 나 네트워크 폴더는 어디에? → **나무의 한 가지에 끼워 넣는다 = 마운트**

```
 /                                 🐧 서버가 내주는 폴더
 ├── home/student                  /srv/share
 ├── mnt
 │   └── share  ◀── 여기에 "끼운다" ────── (네트워크 너머)
 └── srv
```

```bash
df -h            # 지금 무엇이 어디에 끼워져 있나 ⭐
mount | tail -5
```

- **마운트 지점(mount point)** = 끼워 넣을 **빈 폴더**. 원래 그 폴더에 있던 내용은 **가려진다**(사라지는 게 아니다)
- `umount` 로 빼면 원래 폴더가 다시 보인다

## 📖 ② 구축 — 여섯 단계 그대로

> 📌 원래 NFS 는 **서버 1대 + 클라이언트 1대**가 필요하다. 수업에서는 **같은 VM 이 서버이자 클라이언트**로 동작하게 해서(루프백) 개념부터 잡는다.
> 📌 짝이 맞으면 **옆자리 VM 의 IP** 로 서로 붙어 보는 게 훨씬 재미있다 → 대본 부록 B

### ① 설치

```bash
sudo apt install nfs-kernel-server -y      # 서버
sudo apt install nfs-common -y             # 클라이언트 (보통 이미 있다)
```

### ② 설정 — 내줄 폴더와 `/etc/exports`

```bash
sudo mkdir -p /srv/share
echo "NFS 로 공유되는 파일" | sudo tee /srv/share/hello.txt
sudo chown nobody:nogroup /srv/share        # 누구나 읽고 쓰게 (수업용)
sudo nano /etc/exports
```

```
/srv/share  127.0.0.1(rw,sync,no_subtree_check)
```

| 칸 | 뜻 |
|----|----|
| `/srv/share` | **내줄 폴더** |
| `127.0.0.1` | **누구에게** 허용할지 — IP · 대역(`192.168.0.0/24`) 가능 ⭐ 여기가 접근 제어 |
| `rw` / `ro` | 읽기·쓰기 / 읽기 전용 |
| `sync` | 디스크에 **확실히 쓰고** 응답 |
| `no_subtree_check` | 성능 옵션 (권장) |

> 🗣 **"`/etc/exports` 한 줄이 곧 접근 제어 목록입니다. 11일차 ACL 의 아주 작은 친척이죠."** → [11일차](../day-11/README.md)

### ③ 기동 · ④ 확인

```bash
sudo exportfs -ra              # exports 를 다시 읽는다 (reload 에 해당)
sudo exportfs -v               # 지금 내주고 있는 목록
sudo systemctl status nfs-server
sudo ss -tulnp | grep 2049     # NFS 는 TCP 2049
showmount -e 127.0.0.1         # 밖에서 본 "이 서버가 내주는 목록"
```

### ⑤ 개방

```bash
sudo ufw allow 2049/tcp
```

### ⑥ 검증 — 붙여 본다 ⭐

```bash
sudo mkdir -p /mnt/share
sudo mount -t nfs 127.0.0.1:/srv/share /mnt/share
df -h | grep share                       # 목록에 나타난다!
ls /mnt/share                            # hello.txt 가 보인다
echo "클라이언트가 씀" | sudo tee -a /mnt/share/hello.txt
cat /srv/share/hello.txt                 # ⭐ 서버 쪽에도 즉시 반영
sudo umount /mnt/share                   # 빼기
```

> 🗣 **"`/mnt/share` 에 쓴 게 `/srv/share` 에 나타났습니다. 복사한 적이 없는데도요. 같은 파일이니까요."**

### 재부팅해도 붙어 있게 — `/etc/fstab`

```
127.0.0.1:/srv/share  /mnt/share  nfs  defaults  0  0
```

> ⚠️ `fstab` 오타는 **부팅 실패**로 이어질 수 있다. 수업에선 **읽고 설명만** 하고, 넣었으면 `sudo mount -a` 로 즉시 검증한다.

## 📖 ③ NFS vs SMB — 리눅스끼리냐, 윈도우까지냐

| | **NFS** | **SMB / CIFS** (Samba) |
|---|---|---|
| 태생 | 유닉스 · 리눅스 | 윈도우 |
| 포트 | **TCP 2049** | TCP **445** |
| 인증 | 기본은 **IP + UID 기반** (느슨하다) | 사용자 계정/암호 |
| 쓰는 곳 | 리눅스 서버끼리 · 클라우드 공유 스토리지 | 회사 **\\\\서버\\공유폴더** |
| 리눅스에서 만들려면 | `nfs-kernel-server` | `samba` |

> ⚠️ NFS 는 **"IP 를 믿는"** 프로토콜이다. 그래서 **인터넷에 열면 절대 안 된다** — 사내망 · 클라우드 내부망 전용.
> 이게 11일차 방화벽 · ACL 이 필요한 이유의 아주 좋은 예다.
