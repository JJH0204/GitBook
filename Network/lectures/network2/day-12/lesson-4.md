## 학습 목표

- 파일 전송(FTP, `scp`)과 파일 공유(NFS)의 차이를 설명한다.
- `/etc/exports`로 공유할 폴더를 내보내고, 클라이언트에서 `mount`로 붙인다.
- 마운트(mount)가 "폴더에 다른 저장소를 끼워 넣는 것"임을 이해한다.
- 리눅스의 NFS와 Windows의 SMB(공유 폴더)를 구분한다.

## 1. 목적

[3. FTP 서버](lesson-3.md)로 파일을 복사했다. 그런데 복사본은 곧 원본과 달라진다. 웹서버 3대가 같은 사진 폴더를 봐야 한다면 매번 3번 업로드할 수는 없다. 파일을 보내는 대신 폴더 자체를 빌려주는 방법이 NFS(Network File System)다. 서버의 폴더를 내 컴퓨터의 폴더인 것처럼 붙여 쓴다.

| | 파일 전송 (FTP, `scp`) | 파일 공유 (NFS, SMB) |
|---|---|---|
| 하는 일 | 복사본을 만든다 | 원본을 같이 본다 |
| 수정하면 | 각자 따로 논다 | 모두에게 즉시 반영 |
| 느낌 | 택배 | USB를 꽂은 것 |
| 대표 | FTP, SFTP, `scp` | NFS(리눅스), SMB/CIFS(Windows) |

비유: 사진을 카톡으로 보내기 대 공유 앨범이다. 보낸 사진은 내가 지워도 상대에게는 남는다(복사본). 공유 앨범은 한 곳을 같이 본다.

절차는 [NFS 공유와 마운트 실습](lesson-4-lab.md)에 있다.

## 2. 구성 요소

### 마운트: 리눅스에 드라이브 문자가 없는 이유

Windows는 저장 장치마다 `C:`, `D:`가 붙는다. 리눅스는 하나의 나무(`/`)뿐이다(10일차). USB나 네트워크 폴더는 나무의 한 가지에 끼워 넣는다. 이것이 마운트다.

```
 /                                 서버가 내주는 폴더
 ├── home/student                  /srv/share
 ├── mnt
 │   └── share  ◀── 여기에 "끼운다" ────── (네트워크 너머)
 └── srv
```

```bash
df -h            # 지금 무엇이 어디에 끼워져 있나
mount | tail -5
```

- 마운트 지점(mount point)은 끼워 넣을 빈 폴더다. 원래 그 폴더에 있던 내용은 가려진다(사라지는 것이 아니다).
- `umount`로 빼면 원래 폴더가 다시 보인다.

### 구성 요소와 설정

원래 NFS는 서버 1대와 클라이언트 1대가 필요하다. 수업에서는 같은 VM이 서버이자 클라이언트로 동작하게 해서(루프백) 개념부터 잡는다. 짝이 맞으면 옆자리 VM의 IP로 서로 붙어 보는 것이 훨씬 재미있다. → [0. 12일차 실습 명령어](commands.md)의 부록 B

| 단계 | 내용 |
|---|---|
| ① 설치 | `sudo apt install nfs-kernel-server -y`(서버), `sudo apt install nfs-common -y`(클라이언트, 보통 이미 있다) |
| ② 설정 | 공유 폴더 `/srv/share`를 만들고 `/etc/exports`에 한 줄 추가 |
| ③ 기동, ④ 확인 | `sudo exportfs -ra`, `sudo exportfs -v`, `sudo systemctl status nfs-server`, `sudo ss -tulnp \| grep 2049`, `showmount -e 127.0.0.1` |
| ⑤ 개방 | `sudo ufw allow 2049/tcp` |
| ⑥ 검증 | `sudo mount -t nfs 127.0.0.1:/srv/share /mnt/share`, `df -h \| grep share` |

`/etc/exports` 예:

```
/srv/share  127.0.0.1(rw,sync,no_subtree_check)
```

| 칸 | 뜻 |
|---|---|
| `/srv/share` | 내줄 폴더 |
| `127.0.0.1` | 누구에게 허용할지. IP나 대역(`192.168.0.0/24`)이 가능하다. 여기가 접근 제어다 |
| `rw` / `ro` | 읽기·쓰기 / 읽기 전용 |
| `sync` | 디스크에 확실히 쓰고 응답 |
| `no_subtree_check` | 성능 옵션(권장) |

`/etc/exports` 한 줄이 곧 접근 제어 목록이다. 11일차 ACL의 아주 작은 친척이다. → [11일차](../day-11/README.md)

### 재부팅해도 붙어 있게: `/etc/fstab`

```
127.0.0.1:/srv/share  /mnt/share  nfs  defaults  0  0
```

{% hint style="warning" %}
CAUTION: `fstab` 오타는 부팅 실패로 이어질 수 있다. 수업에서는 읽고 설명만 한다. 넣었으면 `sudo mount -a`로 즉시 검증한다.
{% endhint %}

### NFS vs SMB: 리눅스끼리냐, Windows까지냐

| | NFS | SMB / CIFS (Samba) |
|---|---|---|
| 태생 | 유닉스, 리눅스 | Windows |
| 포트 | TCP 2049 | TCP 445 |
| 인증 | 기본은 IP + UID 기반(느슨하다) | 사용자 계정과 암호 |
| 쓰는 곳 | 리눅스 서버끼리, 클라우드 공유 스토리지 | 회사 `\\서버\공유폴더` |
| 리눅스에서 만들려면 | `nfs-kernel-server` | `samba` |

{% hint style="danger" %}
WARNING: NFS는 IP를 믿는 프로토콜이다. 인터넷에 열면 안 된다. 사내망과 클라우드 내부망 전용이다. 11일차 방화벽과 ACL이 필요한 이유의 좋은 예다.
{% endhint %}

## 3. 동작 원리

1. 서버가 `/etc/exports`에 적힌 폴더를 허용된 IP에만 내준다(`exportfs -ra`로 적용).
2. 클라이언트가 `mount -t nfs <서버 IP>:<내준 폴더> <마운트 지점>`으로 서버 폴더를 자기 나무에 끼운다.
3. 클라이언트가 마운트 지점에 쓰면 서버의 원본 폴더에 바로 반영된다. 복사가 일어나지 않는다.
4. `umount`로 빼면 마운트 지점은 원래의 빈 폴더로 돌아온다.

## 5. 약어·용어

| 용어 | 뜻 |
|---|---|
| NFS (Network File System) | 서버 폴더를 네트워크로 붙여 쓰는 파일 공유. TCP 2049 |
| SMB / CIFS | Windows 파일 공유 프로토콜. TCP 445 |
| 마운트 (mount) | 저장소나 네트워크 폴더를 디렉터리 나무의 한 지점에 끼우는 일 |
| 마운트 지점 | 끼워 넣을 빈 폴더 |
| `/etc/exports` | NFS 서버가 내줄 폴더와 허용 대상을 적는 파일 |
| `/etc/fstab` | 부팅 때 자동으로 마운트할 목록 |
