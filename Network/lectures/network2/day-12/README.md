# 12일차 · 리눅스 서버 구축

> 2단계 · 서버 구축 및 활용. 상위: [네트워크 2](../README.md)
> 이전: [11일차 · 서버 보안](../day-11/README.md) · 다음: [13일차 · Git 과 GitHub](../day-13/README.md)

## 개요

9일차에 서버를 한 대 만들고 SSH 서버 하나를 세웠다. 10일차에 서버가 포트를 열고 기다리는 프로그램임을 `ss`로 확인했고, 11일차에 그 문을 지키는 법(방화벽, ACL)을 배웠다.

오늘은 문을 여러 개 연다. 8일차 패킷 트레이서 `Server0`에서 체크박스 하나로 켰던 DNS, FTP, Mail, Proxy를 리눅스에서 손으로 세운다.

오늘의 핵심 메시지는 "서버 종류는 달라도 세우는 순서는 똑같다"이다. ① 설치 ② 설정 ③ 기동 ④ 확인 ⑤ 개방 ⑥ 검증, 이 여섯 단계를 여섯 번 반복하는 날이다.

| 질문 | 오늘의 답 | 노트 |
|---|---|---|
| 서버를 세운다는 것은 무슨 일인가? | 여섯 단계. 오늘 하루의 뼈대 | 1 |
| 9일차 SSH는 설정도 안 보고 켰는데? | `sshd_config`, 공개키 인증, `scp`, `sftp` | 2 |
| `scp`가 있는데 왜 FTP를? | 연결이 둘이라 방화벽, NAT와 부딪친다. 평문의 증거 | 3 |
| 매번 복사하는 것이 맞나? | NFS. 폴더째 붙여 쓴다(마운트) | 4 |
| `/etc/hosts`를 PC 100대에 적을 건가? | DNS 서버(bind9). 이제 대답하는 쪽이 된다 | 5 |
| 방금 적은 MX 레코드는 무엇을 하나? | 메일의 한살이. SMTP, POP3, IMAP | 6 |
| 회사에서 특정 사이트는 왜 막히나? | 프록시. 7계층에서 보고 판단한다 | 7 |
| 안 되면 어디부터 볼까? | 표 한 장과 5단계 점검 | 8 |

## 오늘의 목표

- 리눅스 서버 구축의 여섯 단계를 순서대로 적용해 서비스를 세운다.
- `systemctl`, `ss`, `journalctl`을 세트로 써서 기동, 확인, 로그를 돌린다.
- `sshd_config`를 고쳐 SSH를 단단하게 하고, 공개키 인증으로 로그인한다.
- vsftpd로 FTP 서버를 세우고, 제어 연결과 데이터 연결, 패시브 모드를 설명한다.
- `tcpdump`로 평문 프로토콜의 비밀번호 노출을 직접 보고, SFTP와 비교한다.
- NFS로 폴더를 공유하고 마운트 개념을 잡는다.
- bind9로 내 도메인의 존 파일을 작성하고 `dig`로 검증한다.
- 메일의 한살이(SMTP, MX, POP3/IMAP)를 설명하고, `nc`로 메일 한 통을 보낸다.
- 프록시(포워드, 리버스)를 구분하고, squid로 캐시와 차단을 확인한다.
- 서비스가 안 될 때 "`localhost`는 되나요?"로 문제를 절반으로 쪼갠다.

```
 Windows ── 창① ② ③ ssh student@192.168.x.x ──▶ Ubuntu VM 192.168.x.x  (브릿지)
    ① 작업 창(설치·설정) · ② 클라이언트 창(검증) · ③ 관찰 창(tcpdump · tail -f)

 오늘 이 서버에 생기는 문:  22(SSH) · 21(FTP) · 2049(NFS) · 53(DNS) · 25(Mail) · 3128(Proxy)
```

## 강의 메모

- 선행 확인: 11일차에서 `ufw`를 못 했다(6, 7, 8번 미진행). → [11일차 실제 진행](../day-11/README.md)
  - 그래서 `ufw`를 오늘 1번 절(⑤ 개방)에서 처음 켠다. 11일차 6번 노트의 핵심이 [여기로 흡수](lesson-1.md)됐다.
  - 수업 시작 때 `sudo ufw status`는 `inactive`가 정상이다.
  - `ufw enable` 전에 `sudo ufw allow 22/tcp`를 한다. 순서를 바꾸면 SSH 창이 끊긴다. 복구 경로(VirtualBox 창에서 `sudo ufw disable`)를 칠판에 미리 적는다.
  - VM 어댑터는 브릿지다. 매 수업 IP가 바뀔 수 있다. `ip a`로 먼저 확인한다.
- 11일차 7, 8번(최소 개방 설계, 정리와 진단)은 13일차로 넘겼다.
- 진도가 하루씩 밀려 있다(9일차 실제 진행 기준). 11일차 뒷부분이 12일차로 넘어오면 오늘 6(메일), 7(프록시)을 이론으로 압축하고 3, 5를 지킨다.
- 칠판 왼쪽 위에 ① 설치 ② 설정 ③ 기동 ④ 확인 ⑤ 개방 ⑥ 검증을 적고 하루 종일 지우지 않는다. 서버 하나 끝낼 때마다 "몇 번까지 했죠?"라고 묻는다.
- 칠판 오른쪽에 "`localhost`는 되나요?"를 적고, 질문이 나올 때마다 이것부터 되묻는다.
- 오늘의 비유: 가게 여는 순서(6단계), 자물쇠와 열쇠(공개키), 전화(21)와 택배(데이터 연결), USB를 꽂는다(마운트), 우체통(SMTP)과 우편함(POP3/IMAP), 회사 우편실(포워드) 대 안내데스크(리버스).
- 최대 병목:
  1. 설정 파일을 고치고 `restart`를 안 한다. ③을 칠판에 크게 쓴다.
  2. SSH 설정을 고치며 접속 창을 닫는다. 시작 전에 "창 하나 더 열어 두세요"를 강제한다.
  3. DNS 존 파일의 끝점(`.`)과 Serial. 대본대로 복사하고 한 줄만 각자 추가한다.
  4. Postfix 설치 중 파란 debconf 화면에서 멈춘다. `Local only`와 Tab/Enter 조작을 안내한다.
  5. `named` 기동 실패(`Address already in use`)는 `listen-on`을 안 넣은 것이다.
