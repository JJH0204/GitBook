# 1. 왜 컨테이너인가 — 그리고 VM 과 무엇이 다른가 ⭐

> 상위: [14일차 · 도커 기초](README.md) · 대본 [STEP 1](commands.md)

## 🎯 학습 목표

- 13일차에 남은 **두 가지 한계**를 말하고, 컨테이너가 그 사이를 어떻게 메우는지 설명한다 ⭐
- 컨테이너를 쓰는 이유를 **네 가지**로 든다 (재현 · 속도 · 청소 · 공존)
- **가상머신과 컨테이너**의 차이를 **커널** 관점에서 설명한다 (9일차 회수)
- **이미지 · 컨테이너 · 레지스트리** 세 단어를 구분한다
- 컨테이너가 **만능이 아닌** 경우를 안다

## 🌉 다리 놓기: 13일차에 우리는 포트폴리오를 **두 군데**에 올렸다

지난 시간에 한 일을 떠올려 보자. 같은 포트폴리오를 **두 경로**로 올렸다.

| | 어디에 | 좋았던 점 | 그런데 |
|---|---|---|---|
| **①** | **GitHub Pages** | **주소가 생겼다.** 전 세계에서 열린다. 서버를 세울 필요도 없었다 | **HTML · CSS · JS 만** 올라간다 |
| **②** | **내 WSL 의 nginx** (`git clone` → `/var/www`) | **내가 세운 서버**다. 뭐든 올릴 수 있다 | 그 환경이 **내 PC 안에만** 있다 |

**①의 벽** — GitHub Pages 는 **정적 호스팅**이다. 게시판 · 로그인 · 방문자 수처럼 **서버에서 돌아가는 프로그램**과 **DB** 는 올릴 수 없다.
(GitHub 문서도 PHP · Ruby · Python 같은 서버측 언어를 지원하지 않는다고 못박고 있다.)

**②의 벽** — 내 WSL 에는 **12일차·13일차에 쌓은 환경**이 있다. Apache 를 끄고 nginx 를 올리고, 포트를 열고, 설정 파일을 고쳤다.
그 환경을 **옆자리 PC 에, 또는 진짜 서버에** 똑같이 만들려면?

> 🗣 **"12일차 여섯 단계를, 처음부터 전부 다시 하는 겁니다. 그리고 하나라도 다르게 하면 — 안 돕니다."**

```
 ① GitHub Pages        ② 내 WSL 서버
 올릴 곳은 준다          내 환경은 된다
 내 환경은 못 준다  ✗     옮길 방법이 없다  ✗
          └──────── 이 사이의 빈칸 ────────┘
                         ▼
        오늘: 환경을 코드로 적어 Git 에 넣고, 어디서든 한 줄로 되살린다
```

> 📌 **오늘의 한 문장** — **컨테이너는 "프로그램 + 그 프로그램이 돌 환경"을 한 덩어리로 묶어 옮기는 방법이다.**

## 📖 ① 왜 쓰나 — 네 가지 이유 ⭐

### 이유 1. **재현** — "제 컴퓨터에선 됐는데요" 가 사라진다 ⭐⭐

12일차를 떠올려 보자. 같은 명령을 쳤는데 **어떤 PC 는 되고 어떤 PC 는 안 됐다.**

| 우리가 실제로 겪은 일 | 왜 달랐나 |
|----------------------|-----------|
| bind9 가 `Address already in use` (12일차) | 그 PC 는 `systemd-resolved` 가 53 을 쓰고 있었다 |
| nginx 가 조용히 안 떴다 (13일차) | 그 PC 는 12일차에 **Apache** 를 세워 뒀다 |
| 옆자리는 되는데 나는 안 된다 | WSL **네트워크 모드**가 달랐다 |

**환경이 다르면 결과가 다르다.** 컨테이너는 그 환경을 **이미지 안에 함께 포장**한다.
→ 내 PC 에서 돌던 이미지가 **옆자리에서도, 진짜 서버에서도 똑같이** 돈다.

> 💡 **13일차와 이어서** — Git 은 **코드**를 똑같이 맞춰 줬다. 컨테이너는 **환경**을 똑같이 맞춰 준다.

### 이유 2. **속도와 무게** — 1초 · 수십 MB

9일차에 Ubuntu VM 을 하나 만드는 데 **거의 한 시간**, 디스크 **25GB** 를 떼 줬다.
컨테이너는 **1초**, **수십 MB** 다. 그래서 **부담 없이 만들고 부담 없이 버린다.**

### 이유 3. **청소** — 실험하고 흔적 없이 지운다

12일차에 서버 여섯 개를 세우며 `/etc` 안의 설정 파일을 여기저기 고쳤다.

> 🗣 **"그거 전부 원래대로 되돌릴 수 있나요?"**

컨테이너는 `docker rm` **한 줄**이면 끝이다. 호스트에는 아무것도 남지 않는다.

### 이유 4. **공존** — 같은 기계에 같은 프로그램 여러 개

13일차에 우리는 **Apache 와 nginx 중 하나를 골라야** 했다. 둘 다 80 번을 원했으니까.
컨테이너라면 **둘 다 띄워** 포트만 달리 줄 수 있다. 버전이 다른 PHP · DB 도 나란히 돈다.

| 이유 | 한 줄 | 오늘 확인하는 곳 |
|------|-------|------------------|
| **재현** | 환경을 함께 포장한다 | [5_Dockerfile](lesson-5.md) · [6_환경을_코드로](lesson-6.md) ⭐ |
| **속도** | 1초 만에 뜬다 | [2_첫_컨테이너](lesson-2.md) |
| **청소** | 지우면 흔적이 없다 | [4_데이터와_볼륨](lesson-4.md) |
| **공존** | 포트만 달리 주면 같이 산다 | [3_도커_핵심명령](lesson-3.md) |

## 📖 ② VM 과 컨테이너 — 두 그림을 나란히 ⭐

```
     [ 가상머신 (9일차) ]                  [ 컨테이너 (오늘) ]

  ┌─────┐ ┌─────┐ ┌─────┐            ┌─────┐ ┌─────┐ ┌─────┐
  │ 앱  │ │ 앱  │ │ 앱  │            │ 앱  │ │ 앱  │ │ 앱  │
  ├─────┤ ├─────┤ ├─────┤            └─────┘ └─────┘ └─────┘
  │ OS  │ │ OS  │ │ OS  │  ← 무겁다    ┌───────────────────┐
  └─────┘ └─────┘ └─────┘            │   Docker 엔진      │
  ┌───────────────────────┐          ├───────────────────┤
  │   하이퍼바이저         │          │   호스트 OS 커널   │ ← 하나를 나눠 쓴다
  ├───────────────────────┤          ├───────────────────┤
  │     호스트 OS         │          │     하드웨어       │
  ├───────────────────────┤          └───────────────────┘
  │      하드웨어          │
  └───────────────────────┘
```

9일차 용어를 다시 꺼내 보자 — **호스트**(진짜 PC) · **게스트**(그 안의 가상 PC) · **하이퍼바이저**(자원을 잘라 나눠 주는 프로그램).

> 📌 **결정적 차이 한 줄** — **VM 은 OS 를 통째로 하나씩 더 올리고, 컨테이너는 호스트의 커널을 공유한다.**

9일차에 배운 **커널 · 쉘** 구분이 여기서 쓰인다.
컨테이너 안에는 **쉘과 명령어 · 라이브러리**는 있지만 **커널은 없다.** 호스트 것을 빌려 쓴다.

| | 가상머신 | 컨테이너 |
|---|---|---|
| OS | **게스트 OS 통째로** | **커널은 호스트 것** |
| 크기 | 수 GB ~ 수십 GB | 수 MB ~ 수백 MB |
| 켜는 시간 | **수십 초 ~ 수 분** | **1초 이내** |
| 격리 수준 | **강하다** (완전히 다른 기계) | 보통 (커널을 공유) |
| 다른 OS | **된다** (Windows 위 Linux) | **안 된다** (리눅스 컨테이너는 리눅스 커널 필요) |

> 💡 **비유: 단독주택 vs 아파트.**
> **VM = 단독주택** — 땅 · 수도 · 전기를 **따로** 깐다. 튼튼하지만 짓는 데 오래 걸린다.
> **컨테이너 = 아파트 한 세대** — **건물 기반(커널)은 공유**하고 **내부만** 내 것. 빨리 들어가 산다.
> 그래서 아파트는 **건물에 문제가 생기면 전 세대가** 영향을 받는다 → 격리가 약하다는 뜻

> 🔎 **그런데 우리는 지금 WSL 안에 있다.** WSL 도 가벼운 VM 이다. 즉 오늘 우리는 **"VM 위에 컨테이너"** 를 올린다 —
> 실무 클라우드가 하는 모양이 정확히 이것이다. 둘은 경쟁이 아니라 **층**이다.

## 📖 ③ 세 단어만 구분하면 된다 — 이미지 · 컨테이너 · 레지스트리 ⭐

```
   레지스트리(Docker Hub)        내 PC 의 이미지              컨테이너
   "창고 · GitHub 같은 것"  ──pull──▶  "설계도 · 붕어빵 틀"  ──run──▶  "실체 · 구워진 붕어빵"
                                       읽기 전용                     돌아가고 있는 것
                                       하나로                        여러 개 만들 수 있다
```

| | 이미지 | 컨테이너 |
|---|---|---|
| 정체 | **읽기 전용 템플릿** | 이미지를 **실행한 것** |
| 개수 | `nginx` 이미지 **1개** | 그걸로 만든 컨테이너 **여러 개** |
| 비유 | 붕어빵 **틀** · 프로그램 **설치 파일** | 구워진 **붕어빵** · 실행 중인 **프로세스** |
| 명령 | `docker images` | `docker ps` |

> 💡 **9일차 비유로 바꾸면** — 이미지 = **Ubuntu ISO 파일**, 컨테이너 = **그걸로 만든 VM**.
> 다른 점은, ISO 는 설치에 한 시간이 걸리지만 **이미지는 1초**라는 것이다.

**레지스트리는 13일차 GitHub 와 같은 발상이다.**

| | 13일차 | 오늘 |
|---|---|---|
| 내 것을 올려두는 창고 | **GitHub** | **Docker Hub** (레지스트리) |
| 받아오기 | `git clone` · `git pull` | **`docker pull`** |
| 올리기 | `git push` | `docker push` |
| 받는 대상 | **소스 코드** | **환경째 묶인 이미지** |

> 📌 그래서 오늘 `docker run nginx` 를 치면 **"창고에서 받아서(pull) 굽는다(run)"** 두 일이 한 번에 일어난다.

<details><summary>🔎 한 걸음 더 — 이미지는 왜 가볍고 빠른가 (레이어)</summary>

이미지는 **레이어(층)** 가 쌓인 구조다. `nginx` 이미지는 「데비안 기본 + 라이브러리 + nginx + 설정」 같은 층으로 되어 있다.

- **공유된다** — `nginx:alpine` 과 `python:alpine` 이 같은 알파인 층을 쓰면 그 층은 **한 번만** 받는다
- **캐시된다** — [5_Dockerfile](lesson-5.md) 에서 한 줄만 고치면 **그 아래 층은 다시 굽지 않는다**
- **읽기 전용이다** — 그래서 실행 중에 쓴 것은 따로 쌓인다 → [4_데이터와_볼륨](lesson-4.md)

입문 단계에서는 **"층이 쌓여 있어서 같은 건 다시 안 받는다"** 정도만 알면 충분하다.
</details>

## 📖 ④ 만능은 아니다

| 상황 | 컨테이너가 불리한 이유 |
|------|------------------------|
| **다른 OS 가 필요하다** | 리눅스 커널을 공유하므로 **Windows 프로그램은 못 돌린다** |
| **강한 격리가 필요하다** | 커널을 공유 → **커널이 뚫리면 전부** 영향 (11일차 다층 방어 감각) |
| **상태(데이터)가 중요하다** | 컨테이너를 지우면 **안의 데이터도 사라진다** → [4_데이터와_볼륨](lesson-4.md) |
| **방화벽을 믿고 있었다** | 🚨 **Docker 는 `ufw` 를 우회한다** → [3_도커_핵심명령](lesson-3.md) |

> 📌 **VM 과 컨테이너는 경쟁 관계가 아니다.** 실무에서는 **VM(또는 클라우드 서버) 위에 Docker 를 올려서** 쓴다 — 오늘 우리가 하는 모양 그대로다.

## 📝 강의 메모

- ⭐⭐ **도입은 13일차 결과물로 시작한다.** 학생 각자 **① Pages 주소 ② `http://localhost`** 를 동시에 열어 놓고
  → **"①은 게시판을 못 올리고, ②는 옮길 수가 없습니다. 오늘은 그 사이를 메웁니다."**
- ⭐⭐ **두 그림을 칠판에 나란히** — 9일차 하이퍼바이저 그림을 **그대로 다시 그리고** 옆에 컨테이너를 붙인다
- **"커널을 공유한다"** 한 문장이 ②의 전부다. 나머지(빠름 · 가벼움 · 격리 약함)는 전부 여기서 파생된다
- ⭐ **이유 1(재현)** 을 말할 때는 **우리 반에서 실제로 난 사고**를 쓴다 — bind9 포트 충돌(12일차) · 조용히 안 뜬 nginx(13일차)
  - 추상적인 "환경 차이" 가 아니라 **"지난주 그 일"** 이라서 바로 꽂힌다
- 이미지 ↔ 컨테이너는 **붕어빵 틀 ↔ 붕어빵** 으로 하루 종일 같은 말로 부른다. 가장 헷갈리는 지점
- **레지스트리 ↔ GitHub 대응표**를 짚으면 13일차가 그대로 재활용된다 (`pull` 이라는 단어가 같다)
- 레이어(`<details>`)는 **질문이 나오면만** 펼친다. 안 나오면 생략해도 좋다
- ⏱ 이론 30분. **여기서 오래 끌지 않는다** — 2번에서 직접 띄워 보면 바로 이해된다
