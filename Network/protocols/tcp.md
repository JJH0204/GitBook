## 1. 목적

TCP(Transmission Control Protocol)는 전송 계층의 연결형 프로토콜이다. 데이터를 주고받기 전에 연결을 맺고(핸드셰이크), 전송 중에 확인 응답과 재전송으로 전송을 관리해 신뢰성을 제공한다. [UDP](udp.md)보다 지연이 크고 오버헤드가 많다.

## 2. 구성 요소

| 특징 | 설명 |
|---|---|
| 연결형 | 데이터 전송 전에 연결을 설정한다 |
| 신뢰성 | 순서 번호와 확인 응답(ACK)으로 유실을 감지하고 재전송한다 |
| 순서 보장 | 수신 측이 순서 번호로 데이터를 정렬한다 |
| 흐름 제어 | 수신 측 윈도우 크기로 송신량을 조절한다 |
| 전송 단위 | 세그먼트(segment) |

## 3. 동작 원리

### 3.1 연결 설정 (3-way 핸드셰이크)

```
클라이언트                 서버
   | ---- SYN ----------> |
   | <--- SYN + ACK ----- |
   | ---- ACK ----------> |
   |     연결 수립         |
```

1. 클라이언트가 SYN을 보낸다.
2. 서버가 SYN+ACK로 응답한다.
3. 클라이언트가 ACK를 보내면 연결이 수립된다.

### 3.2 연결 종료 (4-way 핸드셰이크)

```
한쪽(A)                    다른 쪽(B)
   | ---- FIN ----------> |
   | <--- ACK ----------- |
   | <--- FIN ----------- |
   | ---- ACK ----------> |
```

1. A가 FIN을 보낸다.
2. B가 ACK로 응답한다.
3. B가 남은 데이터를 보낸 뒤 FIN을 보낸다.
4. A가 ACK로 응답하면 연결이 종료된다.

{% hint style="info" %}
NOTE: B가 보낼 데이터가 없으면 2단계의 ACK와 3단계의 FIN을 한 패킷(FIN+ACK)으로 합칠 수 있다. 확인 필요.
{% endhint %}

## 4. 약어·용어

| 용어 | 뜻 |
|---|---|
| SYN | Synchronize. 연결 요청 플래그 |
| ACK | Acknowledgment. 확인 응답 플래그 |
| FIN | Finish. 연결 종료 플래그 |
| 핸드셰이크 (Handshake) | 데이터 전송 전후에 연결 상태를 합의하는 절차 |
