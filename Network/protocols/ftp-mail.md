## 1. 목적

응용 계층에서 파일을 옮기는 FTP와 메일을 주고받는 SMTP·POP3·IMAP의 역할 차이를 설명한다.

## 2. 구성 요소

### 2.1 FTP

| 항목 | 내용 |
|---|---|
| 전송 계층 | TCP |
| 제어 연결 | 서버 TCP 21. 로그인과 명령을 보낸다 |
| 데이터 연결 | 액티브 모드는 서버 TCP 20에서 시작, 패시브 모드는 서버가 알려 준 임시 포트로 클라이언트가 연결 |
| 보안 | 계정과 데이터를 암호화 없이 보낸다(평문) |
| 대안 | SFTP(SSH 위에서 동작, TCP 22), FTPS(FTP에 TLS 적용) |

FTP는 제어와 데이터 연결을 따로 쓰기 때문에 방화벽·NAT 환경에서 패시브 모드와 포트 범위 설정이 필요하다.

### 2.2 메일 프로토콜

| 프로토콜 | 역할 | 기본 포트 | 암호화 포트 |
|---|---|---|---|
| SMTP | 메일 보내기, 서버 사이 전달 | TCP 25 (서버 간), 587 (클라이언트 제출) | 465 |
| POP3 | 메일을 서버에서 내려받기 | TCP 110 | 995 |
| IMAP | 메일을 서버에 둔 채 열람·동기화 | TCP 143 | 993 |

| 구성 요소 | 설명 |
|---|---|
| MUA | 메일 사용자 프로그램(메일 앱) |
| MTA | 메일 전달 서버 |
| MDA | 받은 메일을 사용자 사서함에 넣는 구성 요소 |

## 3. 동작 원리

1. 보내는 사람의 MUA가 SMTP로 자기 쪽 메일 서버(MTA)에 메일을 제출한다.
2. 보내는 쪽 MTA가 받는 사람 도메인의 MX 레코드를 DNS로 조회한다.
3. 보내는 쪽 MTA가 받는 쪽 MTA에 SMTP로 전달하고, MDA가 사서함에 저장한다.
4. 받는 사람의 MUA가 POP3 또는 IMAP으로 메일을 가져온다.

POP3는 기본적으로 내려받은 메일을 서버에서 지우는 방식이라 한 기기에 맞고, IMAP은 서버를 기준으로 여러 기기가 같은 상태를 본다.

## 4. 약어·용어

| 용어 | 뜻 |
|---|---|
| MX 레코드 | 도메인의 메일 서버를 가리키는 DNS 레코드 |
| SMTP | Simple Mail Transfer Protocol |
| POP3 | Post Office Protocol version 3 |
| IMAP | Internet Message Access Protocol |
