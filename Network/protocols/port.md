## 1. 목적

포트(port)는 한 호스트 안에서 통신하는 프로세스(프로그램)를 구분하는 번호다. 항구에서 이름을 따왔다. 클라이언트가 서버의 포트에 데이터를 내려놓고 서버가 보낼 데이터를 실어 돌려보내는 과정이 항구의 물류와 비슷해서 붙은 이름이다. 포트로 데이터를 교환하는 방식은 [전송 계층 프로토콜](transport-layer.md)을 따른다.

## 2. 구성 요소

### 2.1 포트 범위

TCP와 UDP 헤더의 포트 필드는 16비트라서 번호는 0~65535, 총 65536개다.

| 범위 | 이름 | 설명 |
|---|---|---|
| 0~1023 | 잘 알려진 포트 (Well-known) | 대표 서비스에 배정돼 있다 |
| 1024~49151 | 등록된 포트 (Registered) | IANA에 등록된 응용 프로그램용 |
| 49152~65535 | 동적·임시 포트 (Dynamic/Private) | 클라이언트가 임시로 쓴다 |

{% hint style="info" %}
NOTE: 원본은 "포트 개수는 운영체제가 정의하기 나름"이라 적었다. 포트 필드가 16비트로 규정돼 있어 OS와 무관하게 0~65535이므로 정정했다. 동적 포트의 실제 범위는 OS 설정에 따라 다르다(예: Linux 기본은 32768~60999). 확인 필요.
{% endhint %}

### 2.2 대표 서비스 포트

| 포트 | 프로토콜 | 서비스 |
|---|---|---|
| 20, 21 | TCP | FTP (20 데이터, 21 제어) |
| 22 | TCP | SSH |
| 23 | TCP | TELNET |
| 25 | TCP | SMTP |
| 53 | UDP, TCP | DNS |
| 67, 68 | UDP | DHCP (67 서버, 68 클라이언트) |
| 80 | TCP | HTTP |
| 443 | TCP | HTTPS |

{% hint style="info" %}
NOTE: 원본은 22, 80, 443만 예로 들었다. 나머지 행은 일반 규격 지식으로 추가했다. 포트 번호 예시는 문서마다 다를 수 있으므로 필요하면 IANA 등록 목록을 확인한다.
{% endhint %}

### 2.3 용어

| 용어 | 설명 |
|---|---|
| 네트워크 포트 | 프로세스를 식별하는 논리적 번호 |
| 서비스 포트 | 특정 서비스가 점유하는 포트(예: HTTP = 80/TCP) |

## 3. 동작 원리

같은 번호라도 `TCP/80`과 `UDP/80`은 서로 다른 포트(소켓)다. TCP로 열어 둔 서비스에 UDP로 접근하면 통신이 되지 않는다.

잘 알려진 포트(0~1023)에서 서비스를 실행하려면 Linux 같은 Unix 계열 OS에서 관리자 권한이 필요하다.

{% hint style="info" %}
NOTE: 원본은 이 권한 요건 때문에 "클라이언트가 이 대역의 서비스를 관리자의 것이라 신뢰할 수 있다"고 적었다. 오늘날 이 신뢰는 보장되지 않고, Windows는 같은 제한이 없다. 이 문장은 뺐다. 확인 필요.
{% endhint %}
