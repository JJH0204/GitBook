# 데이터그램 (Datagram)

| 유형 | D&O (개념) |

## 1. 목적

데이터그램은 비연결형(connectionless) 네트워크에서 독립적으로 전송되는 패킷이다. 수신자와 사전에 연결을 설정하지 않고, 각 패킷이 서로 독립적으로 전송된다. 빠른 전송에 적합하지만 전송 계층에서 신뢰성을 보장하지 않는다.

## 2. 구성 요소

### 2.1 특징

| 번호 | 특징 | 설명 |
|---|---|---|
| 1 | 비연결형 | 전송 전에 연결을 설정하지 않는다 |
| 2 | 순서 비보장 | 패킷마다 경로가 달라 도착 순서가 바뀔 수 있다 |
| 3 | 신뢰성 낮음 | 유실된 패킷을 재전송하지 않는다 |
| 4 | 빠른 전송 | 연결 설정과 확인 응답이 없어 지연이 적다 |

### 2.2 데이터그램을 쓰는 프로토콜

| 프로토콜 | 설명 |
|---|---|
| UDP | 데이터그램 기반 전송 프로토콜이다. 빠르지만 신뢰성을 보장하지 않는다 |
| IP | 데이터를 패킷(IP 데이터그램) 단위로 전송하는 기본 프로토콜이다 |
| ICMP | 네트워크 오류 메시지를 전달한다. `ping`이 쓴다. ICMP 메시지는 IP 데이터그램에 실려 전달된다 |

### 2.3 데이터그램과 TCP의 차이

| 항목 | 데이터그램 (UDP) | TCP |
|---|---|---|
| 연결 방식 | 비연결형 | 연결형 |
| 신뢰성 | 낮음 | 높음 |
| 속도 | 빠름 | 상대적으로 느림 |
| 패킷 순서 | 보장하지 않는다 | 보장한다 |
| 사용 사례 | VoIP, 온라인 게임, DNS | 웹(HTTP), 이메일, FTP |

## 3. 동작 원리

```
송신자 --데이터그램 1--> (경로 가) --> 수신자
송신자 --데이터그램 2--> (경로 나) --> 수신자
```

1. 송신자가 데이터그램을 만들어 전송한다.
2. 각 데이터그램이 독립적으로 경로를 찾아 이동한다.
3. 수신자는 도착한 데이터그램을 도착한 대로 처리한다. 유실과 순서 변경은 응용 프로그램이 처리한다.

예: A가 B에게 인터넷 전화를 걸면 음성 데이터가 UDP 데이터그램으로 전송된다. 일부 패킷이 유실돼도 음성이 빨리 전달되는 것이 더 중요하므로 TCP보다 UDP가 알맞다.

활용 예: 온라인 게임, VoIP, 일부 스트리밍 서비스, DNS 질의.

{% hint style="info" %}
NOTE: 원본은 "수신자가 도착한 데이터그램을 조립하여 데이터를 완성한다"고 적었다. UDP는 재조립이나 순서 정렬을 하지 않으므로 위처럼 정정했다(IP 단편화의 재조립은 IP 계층이 한다). 원본의 "스트리밍 서비스" 일반은 TCP 기반 방식도 많아 "일부"로 좁혔다. 확인 필요.
{% endhint %}
