## 1. 목적

HDLC(High-Level Data Link Control)는 데이터 링크 계층(2계층)의 비트 지향(bit-oriented) 프로토콜이다. 프레임 구조를 정의하고 CRC 기반 오류 검출과 흐름 제어를 제공한다. 점대점(point-to-point)과 다중점(multipoint) 통신을 지원한다. ISO가 정의한 표준이다.

## 2. 구성 요소

### 2.1 주요 기능

| 기능 | 설명 |
|---|---|
| 프레임화 (Framing) | 데이터를 프레임 단위로 나누어 전송한다 |
| 흐름 제어 | 송신 속도를 조절해 수신 측 과부하를 막는다 |
| 오류 제어 | CRC(Cyclic Redundancy Check)로 오류를 검출한다 |
| 비트 지향 | 데이터를 비트 단위로 처리해 다양한 데이터 형식을 지원한다 |

### 2.2 프레임 구조

```
| Flag (01111110) | Address | Control | Data | FCS | Flag (01111110) |
```

| 필드 | 크기 | 설명 |
|---|---|---|
| 플래그 (Flag) | 8비트 | 프레임의 시작과 끝을 나타낸다. `01111110` (0x7E) |
| 주소 (Address) | 8비트 이상(확장 가능) | 통신 상대 스테이션을 지정한다 |
| 제어 (Control) | 8비트 또는 16비트 | 프레임 유형(정보, 감독, 비번호)과 순서 번호를 담는다 |
| 데이터 (Data) | 가변 | 전송할 실제 데이터 |
| FCS (Frame Check Sequence) | 16비트 또는 32비트 | CRC 오류 검출 값 |

{% hint style="info" %}
NOTE: 원본은 주소 필드를 "목적지 주소"로 적었다. HDLC에서 주소는 보조국(secondary) 주소이며, 명령 프레임에서는 목적지, 응답 프레임에서는 출발지를 가리킨다. 크기 범위도 원본의 "8~16비트"를 "8비트 이상(확장 가능)"으로 고쳤다. 확인 필요.
{% endhint %}

### 2.3 프레임 유형

| 유형 | 약칭 | 설명 |
|---|---|---|
| 정보 프레임 (Information) | I-Frame | 실제 데이터를 전송한다 |
| 감독 프레임 (Supervisory) | S-Frame | 흐름 제어(ACK/NACK)와 오류 제어를 한다 |
| 비번호 프레임 (Unnumbered) | U-Frame | 링크 설정과 관리를 한다 |

### 2.4 동작 모드

| 모드 | 설명 | 비고 |
|---|---|---|
| 정규 응답 모드 (NRM, Normal Response Mode) | 주국-종국(마스터-슬레이브) 방식이다. 종국은 주국이 허락할 때만 응답한다 | 중앙 집중식 네트워크 |
| 비동기 균형 모드 (ABM, Asynchronous Balanced Mode) | 점대점 방식이다. 두 장치가 송신과 수신을 자유롭게 한다 | 두 장치가 대등하다 |
| 비동기 응답 모드 (ARM, Asynchronous Response Mode) | 종국이 허락 없이 전송을 시작할 수 있다 | 거의 쓰지 않는다 |

### 2.5 장점과 단점

| 구분 | 내용 |
|---|---|
| 장점 | 오류 검출(CRC)과 흐름 제어로 신뢰성 있게 전송한다 |
| 장점 | 점대점과 다중점 통신을 지원한다 |
| 단점 | 플래그, 주소, 제어 필드가 붙어 헤더 오버헤드가 있다 |
| 단점 | 비트 스터핑이 필요하다. 데이터에 연속된 1이 5개 나오면 0을 하나 삽입해 플래그(`01111110`)와 구별한다 |
| 단점 | 주로 WAN 점대점 연결에서 쓰고 LAN에서는 쓰지 않는다 |

### 2.6 활용 분야

| 분야 | 설명 |
|---|---|
| WAN | 라우터 사이 점대점(시리얼) 연결 |
| 위성 통신 | 원거리 데이터 전송 |
| X.25 네트워크 | 패킷 교환 네트워크의 프레임 관리(X.25의 LAPB는 HDLC에서 파생) |
| PPP | HDLC에서 발전한 점대점 프로토콜 |

{% hint style="info" %}
NOTE: 원본 장점 칸의 "불필요한 헤더 없는 효율적 프레임 구조"는 단점 칸의 "헤더 오버헤드"와 상충해 장점에서 뺐다. 라우터 제조사가 쓰는 독자 HDLC 변형(예: Cisco HDLC)은 표준 HDLC와 다르다. 확인 필요.
{% endhint %}

## 3. 동작 원리

1. 송신 측이 데이터에 주소, 제어 필드를 붙이고 FCS를 계산한다.
2. 비트 스터핑을 적용하고 앞뒤에 플래그를 붙여 전송한다.
3. 수신 측이 플래그로 프레임 경계를 찾고 스터핑을 제거한다.
4. 수신 측이 FCS로 오류를 검사하고, 정상이면 S-Frame으로 확인 응답을 보낸다.

## 4. 약어·용어

| 용어 | 뜻 |
|---|---|
| CRC | Cyclic Redundancy Check. 순환 중복 검사 |
| FCS | Frame Check Sequence. 프레임 검사 순서 |
| 비트 스터핑 | 플래그와 같은 비트열이 데이터에 나오지 않게 비트를 삽입하는 기법 |
| PPP | Point-to-Point Protocol |
