# 라우팅 실습 (Packet Tracer)

## 작업 식별

| 항목 | 내용 |
|---|---|
| Task ID | NET-RSW-003-MP |
| 목적 | 라우터 2대를 시리얼로 연결하고 양쪽에 정적 경로를 추가해 `192.168.10.0/24`의 PC와 `192.168.100.0/24`의 서버가 통신하게 한다 |
| 적용 대상 | Cisco Packet Tracer 실습 환경. Cisco IOS 라우터 2대(시리얼 모듈 포함), PC 1대, 서버 1대. 실제 장비에도 적용되나 인터페이스 이름이 다르다 |
| 소요 시간 | 약 30분 |
| 확인 상태 | 미검증 (원본 페이지를 정리한 것이며 이 문서로 다시 실행해 확인하지 않았다) |
| 개정 | R1 (2026-11-18) |

{% hint style="info" %}
NOTE: 원본은 설정 화면과 명령을 이미지로 보였고 본문에는 명령이 없다. 이 문서의 인터페이스 이름, 라우터 IP, 명령은 원본 설명을 바탕으로 구성한 값이며 원본에 없던 내용이다. 원본의 경유지 `172.168.10.2`는 공인 대역이어서 사설 대역 `172.16.10.0/30`으로 바꿨다. 확인 필요.
{% endhint %}

{% hint style="info" %}
NOTE: 원본은 "라우터는 DCE에 속한다"고 적었다. 일반적으로 라우터는 DTE이고, 시리얼 케이블에서 클럭을 제공하는 쪽이 DCE다. 이 문서는 DCE 케이블이 꽂힌 라우터에 `clock rate`를 설정한다.
{% endhint %}

## 2. 필요 장비와 자재

| 번호 | 이름 | 사양 | 비고 |
|---|---|---|---|
| 1 | 라우터 | Cisco IOS, 시리얼 인터페이스와 LAN 인터페이스 각 1개 | R1, R2 |
| 2 | PC | 1대 | PC1 |
| 3 | 서버 | 1대 | SRV1 |
| 4 | 시리얼 케이블 | DCE-DTE 1쌍 | DCE 쪽 라우터를 R1로 가정한다 |
| 5 | 스위치 또는 크로스 케이블 | 장치당 LAN 연결용 | PC1-R1, SRV1-R2 |

### 구성 값

| 번호 | 장치 | 인터페이스 | IP / 마스크 | 비고 |
|---|---|---|---|---|
| 1 | PC1 | NIC | `192.168.10.2` / `255.255.255.0` | 게이트웨이 `192.168.10.1` |
| 2 | R1 | `GigabitEthernet0/0` | `192.168.10.1` / `255.255.255.0` | PC1 쪽 |
| 3 | R1 | `Serial0/0/0` | `172.16.10.1` / `255.255.255.252` | DCE 쪽 |
| 4 | R2 | `Serial0/0/0` | `172.16.10.2` / `255.255.255.252` | DTE 쪽 |
| 5 | R2 | `GigabitEthernet0/0` | `192.168.100.254` / `255.255.255.0` | SRV1 쪽 |
| 6 | SRV1 | NIC | `192.168.100.1` / `255.255.255.0` | 게이트웨이 `192.168.100.254` |

## 3. 안전 사항

{% hint style="danger" %}
WARNING: 실제 장비에 원격(SSH, Telnet)으로 접속한 상태에서 접속에 쓰는 인터페이스의 IP를 바꾸거나 `shutdown`하면 접속이 끊긴다. 콘솔 접근 수단을 확보한 뒤 설정한다. 이 문서는 Packet Tracer 같은 실습 환경을 전제로 한다.
{% endhint %}

{% hint style="danger" %}
WARNING: `erase startup-config`와 `reload`는 저장된 설정을 지우거나 저장하지 않은 설정을 잃게 한다. 이 문서의 절차에서는 쓰지 않는다. 복구 절에서만 쓴다.
{% endhint %}

{% hint style="warning" %}
CAUTION: 설정은 `running-config`에만 적용된다. `copy running-config startup-config`를 하기 전에 장비를 껐다 켜면 설정이 사라진다.
{% endhint %}

## 4. 준비

| 번호 | 항목 | 확인 방법 |
|---|---|---|
| 1 | 구성 값 표대로 장치를 배치하고 케이블을 연결한다 | 케이블이 모두 연결돼 있다 |
| 2 | R1, R2에서 현재 설정을 백업한다: `show running-config` | 출력 전체를 텍스트로 저장한다 |
| 3 | 라우팅 테이블 초기 상태를 확인한다: `show ip route` | 아직 `172.16.10.0` 외의 원격 경로가 없다 |

## 5. 절차

### A. 라우터 인터페이스 IP 설정

1. (5-A-01) R1에서 전역 구성 모드로 들어간다: `enable` 후 `configure terminal` → 결과: 프롬프트가 `R1(config)#`이다.
2. (5-A-02) LAN 인터페이스를 연다: `interface GigabitEthernet0/0` → 결과: 프롬프트가 `R1(config-if)#`이다.
3. (5-A-03) IP를 설정한다: `ip address 192.168.10.1 255.255.255.0`
4. (5-A-04) 인터페이스를 켠다: `no shutdown` → 결과: 링크 상태가 `up`으로 바뀐다는 메시지가 나온다.
5. (5-A-05) 시리얼 인터페이스를 연다: `interface Serial0/0/0`
6. (5-A-06) IP를 설정한다: `ip address 172.16.10.1 255.255.255.252`
7. (5-A-07) DCE 쪽이므로 클럭을 설정한다: `clock rate 64000` → 결과: 오류 없이 적용된다. (DTE 쪽에서 입력하면 오류가 난다.)
8. (5-A-08) 인터페이스를 켠다: `no shutdown` 후 `end`
9. (5-A-09) R2에서 같은 방법으로 `GigabitEthernet0/0`에 `192.168.100.254 255.255.255.0`을 설정한다.
10. (5-A-10) R2의 `Serial0/0/0`에 `172.16.10.2 255.255.255.252`를 설정하고 `no shutdown`한다. `clock rate`는 입력하지 않는다.

{% hint style="info" %}
NOTE: 양쪽 인터페이스가 모두 켜지면 연결선이 초록으로 바뀐다(Packet Tracer). 한쪽이라도 `shutdown` 상태면 선은 빨간색이다.
{% endhint %}

### B. 라우팅 전 상태 확인

1. (5-B-01) PC1에서 서버로 ping을 보낸다: `ping 192.168.100.1` → 결과: 응답이 오지 않는다. 라우터끼리 연결만 됐고 경로가 없기 때문이다.
2. (5-B-02) R1에서 라우팅 테이블을 확인한다: `show ip route` → 결과: `192.168.100.0`이 없다. `C`(Connected)와 `L`(Local) 경로만 보인다.

### C. R1에 정적 경로 추가

{% hint style="danger" %}
WARNING: 원격으로 R1에 접속해 있다면 잘못된 경로가 접속 경로를 바꿀 수 있다. 목적지 네트워크와 경유지(next hop) 값을 입력 전에 구성 값 표와 대조한다.
{% endhint %}

1. (5-C-01) R1 전역 구성 모드로 들어간다: `configure terminal`
2. (5-C-02) 서버 네트워크로 가는 경로를 추가한다: `ip route 192.168.100.0 255.255.255.0 172.16.10.2` → 결과: 오류 없이 적용된다. 마지막 값은 R2의 시리얼 IP이며, 외부 네트워크로 나가려면 거쳐야 하는 경유지(next hop)다.
3. (5-C-03) 구성 모드를 나온다: `end`
4. (5-C-04) 라우팅 테이블을 확인한다: `show ip route` → 결과: `S 192.168.100.0/24 [1/0] via 172.16.10.2`가 보인다. (`[1/0]`은 AD 1, 메트릭 0이다.)

### D. 상대 라우터(R2)에 역방향 경로 추가

1. (5-D-01) R2 전역 구성 모드로 들어간다: `configure terminal`
2. (5-D-02) PC 네트워크로 돌아오는 경로를 추가한다: `ip route 192.168.10.0 255.255.255.0 172.16.10.1` → 결과: 오류 없이 적용된다.
3. (5-D-03) `end`를 입력하고 `show ip route`로 확인한다. → 결과: `S 192.168.10.0/24 [1/0] via 172.16.10.1`가 보인다.

{% hint style="info" %}
NOTE: 한쪽 라우터에만 경로를 넣으면 요청은 가도 응답이 돌아오지 못한다. 반드시 양쪽에 경로를 넣는다.
{% endhint %}

### E. 호스트 게이트웨이 설정

1. (5-E-01) PC1의 IP 설정에서 기본 게이트웨이에 `192.168.10.1`을 입력한다.
2. (5-E-02) SRV1의 IP 설정에서 기본 게이트웨이에 `192.168.100.254`를 입력한다. → 결과: 두 호스트 모두 게이트웨이가 입력됐다.

{% hint style="warning" %}
CAUTION: 게이트웨이가 비어 있으면 라우팅이 맞아도 호스트가 패킷을 밖으로 내보내지 못해 통신이 되지 않는다.
{% endhint %}

### F. 설정 저장

1. (5-F-01) R1에서 기능 확인(6절)이 합격이면 저장한다: `copy running-config startup-config` → 결과: `[OK]`가 나온다.
2. (5-F-02) R2에서 같은 명령을 실행한다.

## 6. 기능 확인

| 번호 | 확인 동작 | 기대 결과 | 합격 기준 |
|---|---|---|---|
| 1 | PC1에서 `ping 192.168.100.1` | 응답이 온다 | 손실 0%. 첫 패킷은 ARP 때문에 실패할 수 있어 두 번째부터 본다 |
| 2 | R1에서 `show ip route` | 정적 경로가 보인다 | `S 192.168.100.0/24` 행이 있다 |
| 3 | R2에서 `show ip route` | 역방향 정적 경로가 보인다 | `S 192.168.10.0/24` 행이 있다 |
| 4 | R1에서 `show ip interface brief` | 사용 인터페이스가 켜져 있다 | `Status`와 `Protocol`이 모두 `up` |

## 7. 복구

1. (7-01) 추가한 정적 경로만 지운다: R1에서 `no ip route 192.168.100.0 255.255.255.0 172.16.10.2`, R2에서 `no ip route 192.168.10.0 255.255.255.0 172.16.10.1` → 결과: `show ip route`에서 `S` 행이 사라진다.
2. (7-02) 저장 전이라면 실습 전 상태로 되돌린다: `reload` → 결과: 저장하지 않은 변경이 사라진다. `Save?` 질문에는 `no`로 답한다.
3. (7-03) 이미 저장했다면 4절에서 백업한 `running-config`를 보고 변경한 값을 되돌린다. 백업이 `startup-config`와 같다면 `copy startup-config running-config`로 되돌릴 수 있으나, 이 명령은 합쳐 적용(merge)하므로 추가된 줄은 지워지지 않는다. 확실히 되돌리려면 7-01을 따른다.

{% hint style="danger" %}
WARNING: `erase startup-config` 후 `reload`는 저장된 모든 설정을 지운다. 실습 환경 초기화가 목적일 때만 쓴다.
{% endhint %}
