## 1. 목적

라우팅(Routing)은 패킷을 목적지 네트워크까지 보낼 경로를 정하고 다음 장치로 전달하는 과정이다. 라우터(또는 L3 장비)가 라우팅 테이블을 보고 판단한다. 경로는 정적 방식(관리자 입력) 또는 동적 방식(라우팅 프로토콜)으로 채운다.

## 2. 구성 요소

### 2.1 라우팅의 주요 기능

| 번호 | 기능 | 설명 |
|---|---|---|
| 1 | 경로 설정 | 목적지까지 갈 경로를 선택한다 |
| 2 | 패킷 전달 | 패킷을 다음 홉(next hop)으로 넘긴다 |
| 3 | 라우팅 테이블 관리 | 경로 정보를 저장하고 갱신한다 |
| 4 | 동적 라우팅 프로토콜 사용 | RIP, OSPF, EIGRP, BGP로 경로를 자동 학습한다 |

### 2.2 라우팅 방식 비교

| 번호 | 방식 | 설명 | 장점 | 단점 |
|---|---|---|---|---|
| 1 | 정적 라우팅 | 관리자가 경로를 직접 입력한다 | 설정이 단순하다. 프로토콜 트래픽이 없다. 경로가 노출되지 않는다 | 경로가 바뀌면 직접 고쳐야 한다. 장애 시 자동 우회가 없다 |
| 2 | 동적 라우팅 | 라우팅 프로토콜이 경로를 학습하고 갱신한다 | 네트워크 변화에 자동으로 적응한다 | 프로토콜 트래픽과 CPU·메모리를 쓴다. 설정이 복잡하다 |

정적 라우팅은 변경이 거의 없는 작은 네트워크(사무실 등)에, 동적 라우팅은 대규모 네트워크(기업, ISP)에 주로 쓴다. 정적 라우팅은 이웃 확인용 Hello 패킷을 주고받지 않으므로 부하가 적다.

{% hint style="info" %}
NOTE: 원본은 정적 라우팅의 장점을 "보안성이 높다"로 적었다. 라우팅 정보를 광고하지 않아 경로가 노출되지 않는다는 뜻이며, 별도의 보안 기능은 아니다.
{% endhint %}

### 2.3 정적 라우트 예시

| 번호 | 환경 | 명령 | 뜻 |
|---|---|---|---|
| 1 | Linux | `ip route add 192.168.2.0/24 via 192.168.1.1` | `192.168.2.0/24`로 가는 경로를 `192.168.1.1`을 거쳐 보낸다 |
| 2 | Cisco IOS | `ip route 192.168.2.0 255.255.255.0 192.168.1.1` | 위와 같다. 서브넷 마스크를 `255.255.255.0` 형식으로 쓴다 |

### 2.4 동적 라우팅 프로토콜

| 번호 | 프로토콜 | 방식 | 특징 | 주 용도 |
|---|---|---|---|---|
| 1 | RIP (Routing Information Protocol) | 거리 벡터 | 홉 수 기준, 최대 15홉 | 작은 네트워크 |
| 2 | OSPF (Open Shortest Path First) | 링크 상태 | 최단 경로 우선(다익스트라) 알고리즘, 표준 프로토콜 | 기업 네트워크 |
| 3 | EIGRP (Enhanced Interior Gateway Routing Protocol) | 고급 거리 벡터 | Cisco에서 개발했다. 대역폭·지연 기반 메트릭 | Cisco 장비 중심 네트워크 |
| 4 | BGP (Border Gateway Protocol) | 경로 벡터(외부 라우팅) | AS 사이 경로 교환 | ISP, 인터넷 |

{% hint style="info" %}
NOTE: 원본은 EIGRP를 "Cisco 전용"으로 적었다. EIGRP는 Cisco가 만든 프로토콜이며, 2016년에 RFC 7868(Informational)로 공개됐다. 실무에서는 대부분 Cisco 장비에서 쓴다. 확인 필요. 원본은 EIGRP를 "하이브리드"로 적었는데 Cisco는 "고급 거리 벡터"라 부른다.
{% endhint %}

### 2.5 라우팅 테이블

라우팅 테이블은 목적지 네트워크별로 가는 경로를 저장한 데이터베이스다. 라우터는 패킷을 받으면 이 테이블을 보고 내보낼 곳을 정한다. 항목마다 최소한 다음 3가지가 있다.

| 번호 | 항목 | 뜻 |
|---|---|---|
| 1 | 목적지 네트워크(대상 IP) | 가려는 네트워크 주소 |
| 2 | 서브넷 마스크 | 목적지 네트워크의 범위 |
| 3 | 경유지(next hop 또는 나가는 인터페이스) | 패킷을 넘길 다음 장치 또는 포트 |

예시 라우팅 테이블이다(Linux 형식).

```
Destination     Gateway         Interface
192.168.1.0     0.0.0.0         eth0
192.168.2.0     192.168.1.1     eth1
0.0.0.0         192.168.1.254   eth0 (Default Route)
```

* 직접 연결된 네트워크는 Gateway가 `0.0.0.0`이다.
* `0.0.0.0` 목적지는 기본 경로(Default Route)다. 일치하는 다른 경로가 없을 때 쓴다.

### 2.6 라우팅과 스위칭 비교

| 번호 | 구분 | 라우팅 | 스위칭 |
|---|---|---|---|
| 1 | 목적 | 패킷을 다른 네트워크로 전달한다 | LAN 안에서 프레임을 전달한다 |
| 2 | 기준 주소 | IP 주소 (L3, 네트워크 계층) | MAC 주소 (L2, 데이터 링크 계층) |
| 3 | 장비 | 라우터 | 스위치 |
| 4 | 주 사용처 | 서로 다른 네트워크 사이, WAN, 인터넷 | LAN 내부 |

### 2.7 DTE와 DCE

| 번호 | 용어 | 뜻 |
|---|---|---|
| 1 | DTE | Data Terminal Equipment. 데이터 단말 장비다. 일반적으로 라우터와 호스트가 이쪽이다 |
| 2 | DCE | Data Circuit-terminating Equipment. 회선 쪽 장비다. 시리얼 회선에서 클럭(clock rate)을 제공한다. 실제 회선에서는 CSU/DSU, 모뎀이다 |

실습 환경(Packet Tracer 등)에서 라우터끼리 시리얼 케이블로 직접 이으면, DCE 쪽 케이블이 꽂힌 라우터가 `clock rate`를 설정해야 한다.

## 3. 동작 원리

### 3.1 패킷 전달 순서

1. 송신 장치가 패킷을 만든다.
2. 라우터가 패킷의 목적지 IP를 라우팅 테이블과 비교한다.
3. 일치하는 경로가 여럿이면 접두사가 가장 긴(마스크가 가장 구체적인) 경로를 먼저 고른다.
4. 같은 접두사 길이의 경로가 여러 출처에서 오면 AD가 낮은 출처를 고른다. 같은 출처면 메트릭이 낮은 경로를 고른다.
5. 선택한 경로의 다음 홉으로 패킷을 보낸다.
6. 패킷이 목적지 네트워크에 닿으면 마지막 라우터가 최종 장치로 전달한다.

{% hint style="info" %}
NOTE: 원본은 최적 경로 기준을 "홉 수, 대역폭, 지연 시간"으로만 적었다. 메트릭 종류는 프로토콜마다 다르다(RIP는 홉 수, OSPF는 비용, EIGRP는 대역폭과 지연). 위 3~4단계의 선택 순서는 원본에 없던 내용이다.
{% endhint %}

### 3.2 관리 거리(AD) 기본값

| 번호 | 경로 출처 | AD (Cisco 기본값) |
|---|---|---|
| 1 | 직접 연결(Connected) | 0 |
| 2 | 정적 경로(Static) | 1 |
| 3 | EIGRP (내부) | 90 |
| 4 | OSPF | 110 |
| 5 | RIP | 120 |
| 6 | EIGRP (외부) | 170 |

### 3.3 실무에서 자주 틀리는 점

| 번호 | 오해 | 사실 |
|---|---|---|
| 1 | 라우터를 케이블로 이으면 통신된다 | 케이블 연결만으로는 안 된다. 라우팅 테이블에 목적지 경로(또는 기본 경로)가 있어야 한다 |
| 2 | 한쪽 경로만 넣으면 된다 | A에서 B로 가는 경로만 있으면 편도다. B에서 A로 돌아오는 경로도 있어야 왕복된다 |
| 3 | 라우팅만 되면 된다 | 호스트의 기본 게이트웨이가 없으면 패킷이 호스트 밖으로 나가지 못한다 |

### 3.4 라우팅 광고

라우팅 광고(Routing Advertisement)는 라우터가 자신과 주변의 경로 정보(라우팅 갱신 정보 등)를 일정 주기 또는 변화가 있을 때 이웃에게 알리는 과정이다.

## 4. 약어·용어

| 용어 | 뜻 |
|---|---|
| Hop / Next hop | 경로에서 지나는 라우터 한 대 / 다음에 패킷을 넘길 장치 |
| Default Route | 일치하는 경로가 없을 때 쓰는 기본 경로(`0.0.0.0/0`) |
| Metric | 경로 선택 기준값 |
| AD | Administrative Distance. 경로 출처의 신뢰도 값. 작을수록 우선한다 |
| DTE / DCE | 데이터 단말 장비 / 회선 장비 |
