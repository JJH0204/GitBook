## 1. 목적

프로토콜(protocol)은 장비가 데이터를 주고받는 규약이다. 이 문서는 프로토콜이 다르면 통신이 안 되는 이유, 공통 프로토콜의 역할, 데이터에 헤더를 붙이고 떼는 과정을 정리한다.

## 2. 구성 요소

| 번호 | 용어 | 설명 |
|---|---|---|
| 1 | 프로토콜 | 전송 규약이다. 데이터 형식, 주소 지정, 순서 등을 정한다 |
| 2 | 공통 프로토콜 | 서로 다른 네트워크가 통신하기 위해 모두가 따르기로 약속한 프로토콜이다. 예: IP |
| 3 | PDU | Protocol Data Unit. 프로토콜이 다루는 데이터 단위다. 계층마다 이름이 다르다 |
| 4 | 헤더(header) | 프로토콜이 데이터 앞에 붙이는 제어 정보다 |
| 5 | 캡슐화(encapsulation) | 데이터에 헤더를 덧붙여 "패키지화"하는 과정이다 |
| 6 | 역캡슐화(decapsulation) | 수신 측에서 헤더를 읽고 떼어 내 상위 계층에 데이터를 넘기는 과정이다 |

## 3. 동작 원리

### 3.1 프로토콜이 다르면 통신이 안 된다

A, B, C 세 네트워크가 각각 다른 프로토콜을 쓰면 규약이 달라 네트워크 사이의 데이터 전송이 불가능하다. 외부와 통신할 때는 모두가 공통 프로토콜(IP)을 쓰기로 미리 약속한다. 그러면 서로 다른 내부 기술을 쓰는 네트워크도 연결된다.

### 3.2 캡슐화와 역캡슐화

```
송신 PC                                      수신 PC
데이터                                       데이터
 | TCP 헤더 추가 -> 세그먼트                  ^ TCP 헤더 제거
 | IP 헤더 추가 -> 패킷                       ^ IP 헤더 제거
 | 이더넷 헤더·트레일러 추가 -> 프레임          ^ 이더넷 헤더·트레일러 제거
 v 비트 신호로 변환  ------ 회선 ------>      ^ 비트 신호 수신
```

1. 응용 프로그램이 데이터를 만든다. 데이터는 최초 PDU다.
2. 송신 측은 각 계층을 내려가며 헤더를 하나씩 덧붙인다.
3. 수신 측은 각 계층을 올라가며 해당 계층의 헤더를 읽고 떼어 낸다.
4. 마지막에 응용 프로그램이 원래 데이터를 읽는다.

계층별 PDU 이름은 NET-FND-005-DO에서 정리한다.
