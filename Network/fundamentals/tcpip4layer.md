# TCP/IP 4계층 모델

## 작업 식별

| 항목 | 내용 |
|---|---|
| Task ID | NET-FND-006-DO |
| 유형 | D&O (개념) |
| 목적 | 실제 인터넷에서 쓰는 TCP/IP 4계층 모델의 계층별 역할과 OSI 7계층과의 대응을 설명한다 |
| 확인 상태 | 미검증 (원본 페이지와 일반 네트워크 교재 지식을 정리한 것이며 출처를 다시 확인하지 않았다) |
| 개정 | R1 (2026-11-18) |

{% hint style="info" %}
NOTE: TCP/IP 모델의 계층 수와 이름은 문헌마다 다르다(4계층, 5계층 등). 이 문서는 원본을 따라 4계층으로 정리했다. 원본에서 정정하거나 보충한 곳은 "비고"에 표시했다.
{% endhint %}

## 1. 목적

TCP/IP 모델은 인터넷 통신에서 실제로 쓰이는 프로토콜을 기반으로 한 네트워크 모델이다. OSI 7계층을 단순화한 4계층 구조이고, 계층마다 특정 프로토콜이 통신을 담당한다.

## 2. 구성 요소

### 2.1 계층 요약

| 계층 | 명칭 | 역할 | PDU | 주요 프로토콜 |
|---|---|---|---|---|
| 4 | 응용 계층 (Application) | 사용자와 직접 상호작용하고 응용 서비스를 지원한다 | 데이터 | HTTP, HTTPS, FTP, SMTP, POP3, IMAP, DNS, SSH |
| 3 | 전송 계층 (Transport) | 포트 번호 기반 프로세스 간 전송, 신뢰성 제공 | 세그먼트 (TCP), 데이터그램 (UDP) | TCP, UDP |
| 2 | 인터넷 계층 (Internet) | 패킷 라우팅, 논리 주소(IP) 지정 | 패킷 | IP, ICMP, ARP, RIP, OSPF, BGP |
| 1 | 네트워크 액세스 계층 (Network Access) | 물리적 데이터 전송, MAC 주소 기반 프레임 전송 | 프레임, 비트 | Ethernet, Wi-Fi, PPP |

{% hint style="info" %}
NOTE: 원본 표에는 BGP가 빠져 있고 상세 설명에만 있어 표에 합쳤다. RIP, OSPF, BGP는 라우팅 프로토콜이다. 교재는 이들을 인터넷 계층에 두지만, 실제로 RIP는 UDP 위에서, BGP는 TCP 위에서 동작하고 OSPF는 IP 위에서 직접 동작한다. 확인 필요.
{% endhint %}

### 2.2 계층 상세

| 계층 | 세부 기능 | 장비·기술 |
|---|---|---|
| 네트워크 액세스 | 전기 신호·무선 신호로 물리 전송한다. MAC 주소로 데이터 프레임을 전송한다. LAN, WAN, Wi-Fi 같은 네트워크 기술을 포함한다 | 네트워크 카드(NIC), 허브, 스위치 |
| 인터넷 | IP 주소를 기반으로 출발지에서 목적지까지 최적 경로를 찾아(라우팅) 패킷 단위로 전송한다. IP 주소를 관리하고 ARP로 MAC 주소를 얻는다 | 라우터 |
| 전송 | 포트 번호로 프로세스 간 데이터를 전송한다. 신뢰성 있는 전송(TCP)과 빠른 전송(UDP)을 선택할 수 있다. 흐름 제어와 오류 제어를 제공한다. 세그먼트 단위로 전송한다 | |
| 응용 | 웹 브라우저, 이메일, 파일 전송 같은 네트워크 서비스를 제공한다. 데이터 요청과 응답을 처리한다 | |

### 2.3 OSI 7계층과의 대응

| TCP/IP 계층 | OSI 계층 | 비고 |
|---|---|---|
| 4 응용 | 7 응용, 6 표현, 5 세션 | 세 계층을 통합한 개념이다 |
| 3 전송 | 4 전송 | 같은 역할이다 |
| 2 인터넷 | 3 네트워크 | 같은 역할이다 |
| 1 네트워크 액세스 | 2 데이터 링크, 1 물리 | 두 계층과 유사하다 |

### 2.4 장점

| 번호 | 내용 |
|---|---|
| 1 | 실제 네트워크에서 쓰는 표준 모델이다 |
| 2 | OSI 모델보다 단순해 이해하기 쉽다 |
| 3 | TCP, IP, HTTP, DNS 등 모든 인터넷 프로토콜이 기반하는 모델이다 |
| 4 | 계층별 역할이 명확해 유지보수와 네트워크 설계에 유리하다 |

## 3. 동작 원리

```
송신 측                      수신 측
4 응용      데이터           4 응용
3 전송      세그먼트         3 전송
2 인터넷    패킷             2 인터넷
1 액세스    프레임, 비트 --> 1 액세스
```

1. 송신 측은 응용 계층에서 데이터를 만들어 아래 계층으로 넘긴다.
2. 각 계층은 자기 계층의 헤더를 덧붙인다(캡슐화).
3. 수신 측은 아래 계층부터 헤더를 읽고 떼며 위로 올린다(역캡슐화).
4. 응용 계층이 데이터를 응용 프로그램에 전달한다.

## 4. 약어·용어

| 용어 | 뜻 |
|---|---|
| TCP | Transmission Control Protocol. 신뢰성 있는 연결형 전송 프로토콜 |
| UDP | User Datagram Protocol. 비연결형 전송 프로토콜 |
| IP | Internet Protocol |
| ICMP | Internet Control Message Protocol. 오류·제어 메시지 프로토콜 |
| ARP | Address Resolution Protocol. IP 주소를 MAC 주소로 변환 |
| RIP / OSPF / BGP | 라우팅 프로토콜 |
| NIC | Network Interface Card. 네트워크 카드 |
| PPP | Point-to-Point Protocol. 두 지점 간 연결 프로토콜 |
