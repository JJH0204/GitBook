# LAN 환경 구축 실습

## 작업 식별

| 항목 | 내용 |
|---|---|
| Task ID | NET-BAS-003-MP |
| 목적 | 스위치 한 대로 장치 세 대를 연결하고 같은 서브넷의 IP를 설정해 서로 통신하는 LAN을 구축한다 |
| 적용 대상 | L2 스위치 1대, 장치 3대(PC 2대, 서버 1대). 실제 장비 또는 네트워크 시뮬레이터 |
| 소요 시간 | 약 20분 |
| 확인 상태 | 미검증 (원본 페이지를 정리한 것이며 이 문서로 다시 실행해 확인하지 않았다) |
| 개정 | R1 (2026-11-18) |

{% hint style="info" %}
NOTE: 원본은 장치 이름을 "PC", "server"로만 적었고 첫 PC의 주소를 적지 않았다. 이 문서는 첫 PC를 `PC1`로 부르고 `192.168.10.1`을 붙였다. 원본에 없던 값이다. 확인 필요.
{% endhint %}

## 2. 필요 장비와 자재

| 번호 | 이름 | 사양 | 비고 |
|---|---|---|---|
| 1 | L2 스위치 | 포트 3개 이상 | 그냥 스위치라고 부르기도 한다 |
| 2 | 장치 | PC 2대, 서버 1대 | 각각 NIC 1개 |
| 3 | 랜 케이블 | 꼬임쌍선(UTP) 3개 | 장치마다 1개 |

## 3. 안전 사항

{% hint style="danger" %}
WARNING: 이미 인터넷에 연결된 PC의 IP를 바꾸면 그 PC의 네트워크 접속이 끊길 수 있다. 원격으로 접속한 장치라면 IP를 바꾸기 전에 콘솔 접근 수단을 확보한다. 실습용 장치나 시뮬레이터에서 진행한다.
{% endhint %}

{% hint style="warning" %}
CAUTION: 같은 LAN 안에서 IP가 겹치면 통신이 불안정해진다. 장치마다 서로 다른 IP를 쓴다.
{% endhint %}

## 4. 준비

| 번호 | 항목 | 확인 방법 |
|---|---|---|
| 1 | 장치 3대와 스위치를 한자리에 둔다 | 장치가 서로 연결되지 않은 상태다 |
| 2 | 사용할 대역을 정한다: `192.168.10.0/24` | 서브넷 마스크가 `255.255.255.0`이다 |
| 3 | 장치별 IP를 정한다 | PC1 `192.168.10.1`, PC2 `192.168.10.2`, 서버 `192.168.10.3` |

## 5. 절차

### A. 장치 연결

1. (5-A-01) 장치 3대가 각각 떨어져 있는지 확인한다. → 결과: 장치끼리 케이블로 연결되지 않았다.
2. (5-A-02) 랜 케이블로 각 장치의 NIC를 스위치 포트에 연결한다. → 결과: 장치 3대가 모두 스위치에 연결된다.
3. (5-A-03) 스위치 포트의 링크 표시등을 확인한다. → 결과: 연결한 포트 3개의 표시등이 켜진다.

{% hint style="info" %}
NOTE: 스위치로 연결만 해서는 데이터 통신이 되지 않는다. 장치마다 IP를 설정해야 한다.
{% endhint %}

### B. IP 설정

{% hint style="danger" %}
WARNING: 5-B-01 이후의 설정은 해당 장치의 기존 네트워크 설정을 덮어쓴다. 변경 전 값(IP, 서브넷 마스크, 게이트웨이)을 기록한다.
{% endhint %}

1. (5-B-01) PC1의 네트워크 설정을 연다. → 결과: IP 주소 입력란이 보인다.
2. (5-B-02) IP 주소에 `192.168.10.1`을 입력한다.
3. (5-B-03) 서브넷 마스크에 `255.255.255.0`을 입력한다. → 결과: `192.168.10.0/24` 대역을 쓰게 된다.
4. (5-B-04) 설정을 적용한다. → 결과: 오류 없이 적용된다.
5. (5-B-05) PC2의 네트워크 설정에서 IP `192.168.10.2`, 서브넷 마스크 `255.255.255.0`을 입력하고 적용한다.
6. (5-B-06) 서버의 네트워크 설정에서 IP `192.168.10.3`, 서브넷 마스크 `255.255.255.0`을 입력하고 적용한다.

{% hint style="info" %}
NOTE: 같은 LAN 안의 통신에는 게이트웨이가 필요 없다. 게이트웨이는 다른 대역으로 나갈 때만 쓰므로 이 실습에서는 비워 둔다.
{% endhint %}

### C. 연결 확인

1. (5-C-01) PC1에서 PC2로 ping을 보낸다: `ping 192.168.10.2` → 결과: 응답이 돌아온다.
2. (5-C-02) PC1에서 서버로 ping을 보낸다: `ping 192.168.10.3` → 결과: 응답이 돌아온다.
3. (5-C-03) PC2에서 서버로 ping을 보낸다: `ping 192.168.10.3` → 결과: 응답이 돌아온다.

## 6. 기능 확인

| 번호 | 확인 동작 | 기대 결과 | 합격 기준 |
|---|---|---|---|
| 1 | PC1에서 `ping 192.168.10.2` | 응답이 온다 | 손실 0% |
| 2 | PC1에서 `ping 192.168.10.3` | 응답이 온다 | 손실 0% |
| 3 | PC2에서 `ping 192.168.10.3` | 응답이 온다 | 손실 0% |

{% hint style="warning" %}
CAUTION: IP 대역을 맞춘다. 장치 하나가 다른 대역(예: `192.168.20.x/24`)의 IP를 쓰면 같은 네트워크로 인식되지 않아 통신되지 않는다. 통신이 안 되면 세 장치의 IP와 서브넷 마스크를 먼저 비교한다.
{% endhint %}

## 7. 복구

1. (7-01) 5-B 전에 기록한 기존 IP, 서브넷 마스크, 게이트웨이를 각 장치에 다시 입력한다.
2. (7-02) 자동(DHCP)으로 쓰던 장치는 네트워크 설정을 자동 IP로 되돌린다.
3. (7-03) 접속이 끊겼다면 콘솔에서 7-01, 7-02를 수행한다.
