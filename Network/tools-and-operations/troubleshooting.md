## 1. 증상

특정 사이트나 서버에 접속되지 않는다. 원인은 케이블부터 응용 프로그램까지 어느 계층에도 있을 수 있다. 아래에서 위로 한 계층씩 확인해 범위를 좁힌다.

## 2. 가능 원인 표

| 단계 | 확인 대상 | 확인 방법 | 실패 시 가능 원인 |
|---|---|---|---|
| 1 | 물리 연결 | 링크 LED, 케이블, 무선 연결 상태 | 케이블 불량, 포트 꺼짐, 무선 미연결 |
| 2 | 내 IP 설정 | `ip addr`(Linux), `ipconfig`(Windows) | IP 없음(DHCP 실패), `169.254.x.x`(Windows 자동 사설 주소) |
| 3 | 자기 자신 | `ping 127.0.0.1` | TCP/IP 스택 문제 |
| 4 | 기본 게이트웨이 | 게이트웨이 IP로 `ping` | 서브넷 마스크·게이트웨이 오설정, 같은 LAN 문제 |
| 5 | 외부 IP | `ping <공인 IP 주소>` | 상위 회선 단절, 라우팅 문제, 방화벽 |
| 6 | 이름 해석 | `nslookup <도메인>` | DNS 서버 설정 오류, DNS 장애 |
| 7 | 서비스 포트 | 포트 접속 시험(예: `nc -vz <호스트> <포트>`) | 서비스 중지, 방화벽·ACL 차단 |
| 8 | 응용 | 브라우저·클라이언트 오류 메시지 | 프록시 설정, 인증서 오류, 서버 응용 오류 |

## 3. 격리 절차

1. 증상 범위를 정한다. 한 사이트만 안 되는지, 모든 사이트가 안 되는지, 나만 안 되는지 확인한다.
2. 표의 1단계부터 순서대로 확인한다.
3. 처음 실패한 단계에서 멈추고 그 단계의 원인만 점검한다.
4. 5단계는 되는데 6단계가 안 되면 DNS 문제다. 공인 IP로는 접속되는지로 구분한다.
5. 6단계까지 되는데 7단계가 안 되면 서비스·방화벽 문제다. 서버 쪽에서 포트가 열려 있는지(`ss -tln`)도 확인한다.
6. 한 번에 하나만 바꾸고 바꾼 뒤 같은 확인을 다시 한다.

{% hint style="warning" %}
CAUTION: 원격 접속 중인 장비의 네트워크 설정을 바꾸면 접속이 끊길 수 있다. 되돌릴 방법을 먼저 정한다.
{% endhint %}
