## 4. 준비

| 번호 | 항목 | 확인 방법 |
|---|---|---|
| 1 | Burp Suite를 설치하고 실행한다 | 시작 화면에서 `Temporary project`와 기본 설정으로 시작한다 |
| 2 | 테스트용 브라우저(또는 별도 프로필)를 준비한다 | 평소 쓰는 로그인 세션이 없다 |
| 3 | 현재 브라우저의 프록시 설정을 기록한다 | 7절 복구에서 같은 값으로 되돌린다 |

## 5. 절차

### A. 프록시 설정

1. (5-A-01) Burp Suite에서 `Proxy > Proxy settings`를 연다. → 결과: 수신 주소(Proxy listener)가 보인다. 기본값은 `127.0.0.1:8080`이다.
2. (5-A-02) 브라우저의 프록시 설정을 연다. Firefox는 `설정 > 일반 > 네트워크 설정`이다.
3. (5-A-03) 수동 프록시를 선택한다. HTTP 프록시에 `127.0.0.1`, 포트에 `8080`을 입력한다. `HTTPS에도 이 프록시 사용`을 선택한다.
4. (5-A-04) 설정을 저장한다.

### B. Burp 인증서 등록 (HTTPS 확인에만 필요)

1. (5-B-01) 프록시를 켠 브라우저에서 `http://burpsuite`에 접속한다. → 결과: Burp 안내 페이지가 열린다.
2. (5-B-02) `CA Certificate`를 눌러 인증서 파일을 내려받는다.
3. (5-B-03) 브라우저의 인증서 관리를 연다. Firefox는 `설정 > 개인 정보 및 보안 > 인증서 보기 > 인증 기관 > 가져오기`이다.
4. (5-B-04) 내려받은 파일을 선택하고 `웹 사이트 식별을 신뢰`를 체크한 뒤 확인한다.

### C. 요청 확인

1. (5-C-01) Burp Suite에서 `Proxy > Intercept`를 연다. 버튼이 `Intercept is on`인지 확인한다.
2. (5-C-02) 브라우저에서 허가받은 테스트 대상에 접속한다. → 결과: 요청이 전송되지 않고 Burp에 멈춰 나타난다.
3. (5-C-03) 요청의 주소, 메서드, 헤더를 확인한다.
4. (5-C-04) `Forward`를 눌러 요청을 서버로 보낸다. → 결과: 응답이 브라우저에 표시된다.
5. (5-C-05) 인터셉트를 끄려면 `Intercept is on`을 눌러 `off`로 바꾼다. → 결과: 이후 요청은 멈추지 않고, `Proxy > HTTP history`에 기록된다.

### D. 요청 수정과 재전송 (테스트 대상이 허가된 경우만)

1. (5-D-01) `Proxy > HTTP history`에서 요청 하나를 우클릭해 `Send to Repeater`를 선택한다.
2. (5-D-02) `Repeater`에서 요청의 값을 하나만 바꾼다.
3. (5-D-03) `Send`를 눌러 서버의 응답이 바뀌는지 확인한다. → 결과: 응답 상태 코드와 본문이 오른쪽에 표시된다.

## 6. 기능 확인

| 번호 | 확인 동작 | 기대 결과 | 합격 기준 |
|---|---|---|---|
| 1 | 프록시 설정 후 HTTP 사이트에 접속 | `HTTP history`에 요청이 기록된다 | 요청 줄이 1개 이상 나타난다 |
| 2 | HTTPS 사이트에 접속 (5-B 수행 후) | 인증서 경고 없이 열리고 요청이 기록된다 | 경고 화면이 없다 |
| 3 | 5-B를 하지 않고 HTTPS 사이트에 접속 | 인증서 경고가 나온다 | 정상 동작이다 (원본 인증서가 아닌 Burp 인증서이기 때문) |

## 7. 복구

1. (7-01) 브라우저의 프록시 설정을 4절에서 기록한 값으로 되돌린다. Firefox는 `프록시 없음` 또는 `시스템 프록시 설정 사용`이다. → 결과: 프록시를 끈 뒤 일반 사이트가 Burp 없이 열린다.
2. (7-02) 5-B에서 등록한 Burp 인증서를 삭제한다. Firefox는 `인증서 보기 > 인증 기관`에서 `PortSwigger CA`를 선택해 `삭제 또는 신뢰하지 않음`을 누른다.
3. (7-03) Burp Suite를 종료한다. 종료하지 않고 프록시 설정만 남기면 브라우저가 연결되지 않는다.
