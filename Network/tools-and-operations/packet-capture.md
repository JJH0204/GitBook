## 1. 목적

패킷 캡처는 네트워크 인터페이스를 지나는 패킷을 기록해 분석하는 방법이다. 연결이 안 되거나 느릴 때 실제로 어떤 패킷이 오갔는지 확인하는 근거가 된다.

## 2. 구성 요소

| 도구 | 형태 | 특징 |
|---|---|---|
| tcpdump | 명령줄 | 서버에서 가볍게 실행. 결과를 pcap 파일로 저장할 수 있다 |
| Wireshark | GUI | 프로토콜별 해석, 필터, 대화(스트림) 따라가기 제공. pcap 파일을 연다 |
| 캡처 필터 | 캡처 시 적용 | BPF 문법. 예: `host <주소>`, `port 53`, `tcp` |
| 디스플레이 필터 | 화면 표시 시 적용 | Wireshark 문법. 예: `ip.addr == <주소>`, `dns`, `tcp.flags.syn == 1` |

## 3. 동작 원리

1. 도구가 인터페이스를 캡처 모드로 열어 커널이 받은 프레임 사본을 읽는다.
2. 스위치 환경에서는 내 포트로 오는 프레임만 보인다. 다른 장치 트래픽을 보려면 스위치의 포트 미러링(SPAN)이나 TAP이 필요하다.
3. 기록한 프레임을 이더넷, IP, TCP/UDP, 응용 계층 순으로 해석해 보여 준다.
4. TCP 연결 확인은 SYN, SYN/ACK, ACK 순서를, 재전송이나 RST가 반복되는지를 본다.

### 3.1 읽을 때 보는 곳

- DNS 질의에 응답이 오는가.
- TCP 3-way handshake가 완료되는가.
- 재전송, 중복 ACK, RST가 많은가.
- 요청과 응답 사이 시간이 긴 구간이 어디인가.

{% hint style="danger" %}
WARNING: 캡처에는 암호화되지 않은 통신 내용(계정, 쿠키 등)이 담길 수 있다. 허가받은 네트워크에서 필요한 만큼만 캡처하고, 저장한 파일은 접근을 제한하며 분석 후 삭제한다.
{% endhint %}

{% hint style="info" %}
NOTE: HTTPS처럼 암호화된 통신은 내용이 보이지 않고 헤더 수준 정보만 보인다.
{% endhint %}

## 4. 약어·용어

| 용어 | 뜻 |
|---|---|
| pcap | 캡처 파일 형식 |
| BPF | 캡처 필터에 쓰는 Berkeley Packet Filter 문법 |
| SPAN | 스위치 포트 미러링 |
| TAP | 회선 중간에 끼워 트래픽 사본을 내는 장치 |
