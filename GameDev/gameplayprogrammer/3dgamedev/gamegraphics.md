# 3D 게임 그래픽스 기초

* 3차원 좌표계 (왼손 좌표계)
  * 벡터(Vector) 위치, 방향, 거리
* 수학적으로는 Vector와 Position은 다르다
* 행렬 (4x4 원소를 가지는 행렬 — 3차원상 물체의 변형을 나타냄)
* 평면, 광선
* 버텍스(정점): 마인크래프트의 경우 버텍스 버퍼를 최적화 이슈로 사용하지 않는다고 함
* 3차원을 표현하는데 최소한의 점 개수는 3 → 폴리곤은 삼각형
* 폴리곤을 무한정 늘릴 수 없어서 normalMap 을 사용한다.
* z 버퍼 (깊이 버퍼) - 먼저 그릴 오브젝트를 결정?
* 스텐실 버퍼 (특수효과를 제작하는데 사용 - 렌더링 할 부분을 정할 수도 있음)
* 더블버퍼링 (화면 주사율에 의해 프레임드랍이 일어나느 것을 방지)

세이딩 관련

* 세이딩 언어
* 세이딩 기법 (플랫 / 고러드 / 퐁 / 광원추적 / 난반사방식)
  * 면단위로 불러오는 플랫 : 퀄리티가 떨어지지만 연산이 적어 빠름
  * 연산이 매우 많은(딱봐도 많은) 퐁

재질 / 조명 / 렌더링

* 재질 / 조명
* 라이트 베이크
* 광원 (점, 방향, 스포트라이트)
* 텍스처
* 렌더링 파이프라인
  * 3D 공간의 가상카메라를 이용, 2D 이미지를 만들어 화면에 보여주는 과정

좌표계 및 스페이스

* 0,0,0이 정사각형의 중심에 오도록하려면? 버텍스를 어디에 그리느냐에 따라 결정 → 로컬 좌표계 (오브젝트를 기준으로 하는 위치)
* 월드 스페이스: 3차원 공간 전체를 기준으로 하는 위치
* 뷰 스페이스: 가상의 카메라를 기준으로 하는 위치

기타 렌더 관련

* 렌더 텍스처(타겟?) -> 카메라가 많아지면 부하가 많아짐
* 행렬로 관리
* GPU에서 연산
* 컬링 (보이는 부분만 남기기)
* 조명: 월드 스페이스에서 정의
  * 그림자나 명암이 처리되는 것을 뷰포트 변환시 적용
* 픽셀 쉐이더 (빛을 고려해서 폴리곤의 색을 결정)
* 클리핑(화면 밖은 잘라냄)
* 원근 투영: 원근감
* 직교 투영: 평면이 서로 평행(원근감 없음)
* 레스터라이즈: 스크린 좌표에 버텍스가 변환된 후 각 삼각형에 면과 컬러를 색으로 채움
* 프로그래머블 파이프라인: 기존의 그래픽파이프라인은 수정이 불가능했으나, 프로그래머가 개입할 수 있는 파이프라인이 있음

그래픽스 파이프라인 주요 블록

* 입력조립기 (Input-Assembler)
  * 비디오 메모리에 버텍스/인덱스버퍼를 만듬
* 테셀레이션 → 연산을 통해 버텍스 수를 늘리는 작업
* 헐 쉐이더: 컬링, 클리핑

GPU vs CPU

* CPU는 직렬(순차) 연산
* GPU는 병렬(프로세스마다 1개씩, 행렬 연산에 유리)
