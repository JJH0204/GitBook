## 2. 구성 요소

### 2.1 기본 요소

* 3차원 좌표계: Unity는 왼손 좌표계(+Y 위, +Z 앞)
  * 벡터(Vector): 위치, 방향, 거리를 표현
* 수학적으로 위치(점)와 벡터(방향+크기)는 다르다. 동차좌표에서 점은 `w = 1`, 방향은 `w = 0`이라 방향은 이동(translation) 변환을 받지 않는다.
* 행렬: 4x4 행렬 하나로 이동·회전·크기 변환을 함께 표현한다.
* 평면, 광선(ray)
* 버텍스(정점): 마인크래프트는 최적화 때문에 버텍스 버퍼를 쓰지 않는다고 들었다 (출처 미확인, 사실 확인 필요).
* 면을 만드는 최소 점의 개수는 3 → 폴리곤은 삼각형
* 폴리곤을 무한정 늘릴 수 없어서 노멀맵을 쓴다. 적은 폴리곤으로도 표면에 굴곡이 있는 것처럼 빛을 받게 한다.
* Z 버퍼(깊이 버퍼): 픽셀마다 지금까지 그린 것 중 가장 가까운 깊이를 저장한다. 뒤에 있는 면이 앞의 면을 덮어쓰지 않게 해서, 그리는 순서와 상관없이 가림이 맞게 된다.
* 스텐실 버퍼: 픽셀마다 붙이는 표시(마스크). 특정 영역에만 그리기, 외곽선, 포털 같은 효과에 쓴다.
* 더블 버퍼링: 뒤 버퍼에 다음 프레임을 다 그린 뒤 앞 버퍼와 바꾼다. 그리는 중인 화면이 보여서 깜빡이는 것을 막는다. 화면 찢어짐(tearing)은 수직 동기화(V-Sync)로 막는다.

### 2.2 셰이딩

* 셰이딩 언어: HLSL, GLSL 등
* 셰이딩 기법은 "조명을 어디서 계산하는가"로 나뉜다.

| 기법 | 조명 계산 위치 | 특징 |
|---|---|---|
| 플랫(Flat) | 면마다 한 번 | 면이 각져 보이지만 연산이 가장 적다 |
| 고러드(Gouraud) | 정점마다 계산 후 색을 보간 | 하이라이트가 뭉개지기 쉽다 |
| 퐁(Phong) | 법선을 보간해서 픽셀마다 계산 | 가장 매끄럽고 연산이 가장 많다 |

* 램버트(난반사) 모델은 셰이딩 기법이 아니라 "빛을 얼마나 받는가"를 계산하는 반사 모델이다. 광선 추적(레이 트레이싱)은 래스터화와 다른 렌더링 방식이다.

### 2.3 재질, 조명, 렌더링

* 재질 / 조명 / 텍스처
* 라이트 베이크: 움직이지 않는 조명 결과를 미리 텍스처(라이트맵)에 구워 둔다.
* 광원: 점(Point), 방향(Directional), 스포트(Spot)
* 렌더링 파이프라인: 3D 공간의 가상 카메라로 2D 이미지를 만들어 화면에 보여주는 과정

## 3. 동작 원리

### 3.1 좌표 공간

정점은 아래 순서로 변환된다. 앞의 세 단계 행렬을 묶어 MVP(Model·View·Projection)라고 부른다.

| 공간 | 기준 | 바꾸는 행렬/연산 |
|---|---|---|
| 오브젝트(로컬) | 오브젝트 자신의 원점 | — |
| 월드 | 씬 전체의 원점 | Model 행렬 |
| 뷰 | 카메라 위치와 방향 | View 행렬 |
| 클립 | 원근·직교 투영이 적용된 4차원 좌표 | Projection 행렬 |
| NDC | x, y는 -1~1, 깊이(z)는 API에 따라 0~1 또는 -1~1인 정규화 좌표 | `w`로 나누기 |
| 스크린 | 화면 픽셀 좌표 | 뷰포트 변환 |

* 정사각형의 중심을 (0,0,0)에 두려면? 모델링할 때 버텍스를 어디에 찍느냐(로컬 좌표)로 결정된다.

### 3.2 기타 렌더 관련

* 렌더 텍스처: 카메라 출력을 화면 대신 텍스처에 그린다. 카메라마다 렌더링을 한 번 더 하므로 많아지면 부하가 커진다.
* 변환은 행렬로 관리하고 GPU에서 계산한다.
* 컬링: 카메라에 보이지 않는 오브젝트(절두체 컬링)나 뒤를 향한 면(백페이스 컬링)을 그리지 않는다.
* 조명 계산은 버텍스·픽셀 셰이더에서 한다. 보통 월드 공간의 법선과 빛 방향으로 계산한다. 뷰포트 변환은 좌표를 화면 픽셀로 옮길 뿐 명암과는 관계없다.
* 픽셀(프래그먼트) 셰이더: 픽셀마다 빛을 고려해 최종 색을 정한다.
* 클리핑: 시야 절두체 밖의 부분을 잘라낸다.
* 원근 투영: 멀수록 작게 보인다. 직교 투영: 거리와 상관없이 크기가 같다.
* 래스터화: 삼각형이 덮는 픽셀을 찾고, 정점 값(UV, 법선 등)을 보간해 프래그먼트를 만든다.
* 프로그래머블 파이프라인: 예전 고정 파이프라인과 달리 정점·픽셀 단계를 셰이더 코드로 직접 작성할 수 있다.

### 3.3 그래픽스 파이프라인 단계 (Direct3D 11 기준)

| 순서 | 단계 | 하는 일 |
|---|---|---|
| 1 | 입력 조립기 (Input Assembler) | 버텍스·인덱스 버퍼를 읽어 삼각형 단위로 묶는다 |
| 2 | 버텍스 셰이더 | 정점을 클립 공간으로 변환한다 |
| 3 | 헐 셰이더 → 테셀레이터 → 도메인 셰이더 (선택) | 헐 셰이더가 분할 정도를 정하면 테셀레이터가 삼각형을 잘게 나누고, 도메인 셰이더가 새 정점 위치를 계산한다 |
| 4 | 지오메트리 셰이더 (선택) | 도형 단위로 정점을 추가·삭제한다 |
| 5 | 래스터라이저 | 클리핑, `w` 나누기, 뷰포트 변환, 백페이스 컬링 후 픽셀을 찾는다 |
| 6 | 픽셀 셰이더 | 픽셀마다 색을 계산한다 |
| 7 | 출력 병합기 (Output Merger) | 깊이·스텐실 테스트와 블렌딩 후 렌더 타깃에 쓴다 |

### 3.4 GPU와 CPU

* CPU: 소수의 강한 코어로 복잡한 작업을 순서대로 처리한다.
* GPU: 수천 개의 작은 코어로 같은 연산을 많은 데이터(정점, 픽셀)에 동시에 처리한다. 행렬·벡터 연산에 유리하다.

## 4. 약어·용어

| 용어 | 뜻 |
|---|---|
| MVP | Model·View·Projection 행렬 |
| NDC | Normalized Device Coordinates, 정규화 장치 좌표 |
| Z 버퍼 | 깊이 버퍼. 픽셀마다 가장 가까운 깊이를 저장한다 |
| V-Sync | 수직 동기화. 화면 갱신 주기에 맞춰 프레임을 교체한다 |
