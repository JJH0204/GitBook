## 1. 모델 준비

모델 출처는 Sketchfab(<https://sketchfab.com/>)이다.

| 순서 | 작업 | 메모 |
|---|---|---|
| 1 | Sketchfab에서 3D 모델을 받는다 | 라이선스 확인 |
| 2 | Blender에서 FBX로 내보낸다 | |
| 3 | FBX를 Unity 프로젝트에 추가한다 | |
| 4 | 텍스처 파일을 함께 추가한다 | FBX를 추가해도 텍스처가 자동으로 연결되지 않는다. 한동안 텍스처를 넣지 않았던 실수 |

## 2. 텍스처 맵

공유받은 모델에는 부위별로 텍스처 4종이 있다. 예: 왼쪽 다리 부위.

| 번호 | 이름 | 종류 |
|---|---|---|
| 1 | `UC_LLEG_OTHER_BUMP` | Bump Map |
| 2 | `UC_LLEG_OTHER_COL` | Color Map |
| 3 | `UC_LLEG_WHITE_BUMP` | Bump Map |
| 4 | `UC_LLEG_WHITE_COL` | Color Map |

| 맵 | 역할 |
|---|---|
| Color Map | 표면의 실제 색상을 표현한다 |
| Bump Map | 표면의 세부 높낮이, 굴곡 정보를 담는다. 광원 반응과 쉐이딩 효과에 쓴다 |

* 모델은 색상·질감에 따라 부위(Other, White)로 나뉘어 있다.
* 참고 셰이더: lilToon (<https://lilxyzw.booth.pm/>).

## 3. 0일차 기록

### 3-1. 머티리얼과 셰이더 적용

1. 임의의 머티리얼에 임의로 생성한 셰이더를 적용했다.
2. 일정 거리 이상 가까워지면 그림자가 졌다. 이것도 셰이더로 구현되는지 의문이다.
3. 부위마다 다른 셰이더를 적용한 탓인지 다리 표현이 어색해졌다.

### 3-2. 메탈 재질 추가

| 단계 | 동작 | 결과 |
|---|---|---|
| 1 | Shader Graph에서 Float 속성을 만든다 | |
| 2 | 그 값을 Metallic 입력에 연결한다 | 0~1 값이 적용된다 |

| Metallic 값 | 효과 |
|---|---|
| 낮을수록 | 광택이 줄어든다 |
| 높을수록 | 광택이 강조된다 |

광택을 받으면 광원과 주변 요소가 반사되는 것처럼 보였다. 착각인지는 확인하지 않았다.

### 3-3. 스크립트로 제어

| 단계 | 동작 | 결과 |
|---|---|---|
| 1 | 스크립트에서 Shader Graph 속성의 Reference 이름으로 접근한다 | |
| 2 | `Material`의 `SetFloat(<Reference 이름>, <값>)`으로 값을 넣는다 | 반짝이던 공이 무광이 됐다 |

{% hint style="info" %}
NOTE: 같은 머티리얼을 쓰는 모든 오브젝트에 한 번에 적용하려면 머티리얼 에셋(`sharedMaterial`)을 수정한다. `Renderer.material`을 읽으면 인스턴스 복제본이 만들어져 그 오브젝트에만 적용된다. 이 NOTE는 원본에 없던 내용이다(확인 필요).
{% endhint %}

### 3-4. 아웃라인 (Inverted Hull 방식)

아웃라인은 그림자 계산이 필요 없으므로 Unlit 셰이더로 만든다.

| 구분 | 그림자 |
|---|---|
| Lit | 광원 위치에 따라 그림자를 계산한다 (그림자 O) |
| Unlit | 그림자를 계산하지 않는다 (그림자 X) |

| 요소 | 뜻 |
|---|---|
| Normal Vector | 각 정점의 표면 방향. 위치가 아니라 방향이다 (정정된 내용) |
| Thickness (Float) | 두께를 정하는 실수 |
| Position | 정점의 원래 위치 |

수식: `이동한 정점 위치 = Position + Normal × Thickness`

1. Normal Vector와 Thickness를 곱한다. → 결과: 정점이 이동할 거리와 방향이 나온다.
2. 그 값을 원래 Position에 더한다. → 결과: 이동한 위치가 나온다.
3. 이 위치를 출력 정점 위치에 직접 넣는다. → 결과: 오브젝트가 두께만큼 부풀어 보인다.

## 4. 2일차 기록

### 4-1. 목표

* 고라니TV 영상([GMD-SGR-004-REF](goranitvshadertimeline.md))을 정독하고 건담 모델을 원하는 디자인으로 만든다.

### 4-2. 라이팅과 분위기 메모

| 주제 | 메모 |
|---|---|
| 얼굴 그림자 | 원래 그림자가 져야 하는 얼굴이 SDF를 따로 적용해 밝게 보인다 |
| 연출 방향 | 캐릭터 묘사보다 상황 연출 중심. 현실적인 효과 적용 |
| 광원 거리 | 빛이 멀리서 출발할수록 잔잔한 분위기를 만든다 |
| 광원 색 | 색 차이로 분위기를 바꾼다. 따뜻한 색은 이른 아침 느낌 |
| 역광 | 극적인 상황 연출에 쓴다 |
| 하이라이트 | 직접 그려 넣는다 |
| 약한 광원 | 촛불 정도 |
| 결정할 것 | 단계를 최소한으로 둘지, 머리로 눈(눈썹 포함)을 가릴지, 외곽선만 살릴지 |

### 4-3. 아웃라인 구현

1. 외곽선과 비슷한 효과를 만들었다. 이것을 아웃라인이라 할 수 있는지는 확인이 필요하다.
2. 정점을 얼마나 띄울지가 외곽선 두께를 결정한다.
3. 실제 메시의 정점 위치에 더해 위치를 조정하고, 조정한 위치를 적용해 출력한다.
4. 출력 색을 지정한다. 외곽선은 주로 검정이다. 나중에 사용자가 고를 수 있게 한다.

| 항목 | 내용 |
|---|---|
| 그래프 설정 | 설정을 수정해야 아웃라인이 적용된다고 한다. 다른 강의는 켜라고 하지만 켜도 꺼도 큰 변화가 없었다 |
| 면 뒤집기 | 정점이 앞을 보면 0, 뒤를 보면 1. 앞뒤를 뒤집어 렌더링한다는 뜻이다. Graph Settings의 `Render Face`를 Back으로 바꾸는 방식이 일반적이다(항목 이름은 버전별로 확인 필요) |
| 각진 메시 | 큐브 같은 메시에 아웃라인을 부드럽게 하려면 모델 설정(법선 관련)을 바꿔야 한다. 안 바꾸면 면이 조각나 보인다 |
| 입력 실수 방지 | 사용자 입력값의 범위를 제한한다 |
| 거리 | 카메라가 75 이상 멀어지면 아웃라인이 사라진다 (단위는 확인 필요) |
| 단순한 오브젝트 | 아웃라인이 잘 적용된다 |
| 복잡한 메시(캐릭터) | 결과가 흉하다 |

### 4-4. Inverted Hull 방식의 구조적 한계

복잡한 메시에서 결과가 흉한 이유는 [툰 셰이더 공부 노트 Day 12](../../toon-shader-study/day12-outline-inverted-hull.md)에 정리돼 있다. 멀어지면 외곽선이 사라지는 문제는 [Day 13](../../toon-shader-study/day13-outline-pixel-width.md)에 정리돼 있다.
