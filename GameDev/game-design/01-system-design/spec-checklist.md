# 스펙 체크리스트: 개발자가 물어볼 질문

> 기획서를 넘기면 개발자는 아래 질문을 **구현하다가** 하게 된다. 그때 답하면 늦다. 해당 없는 항목은 건너뛰고, 해당 항목 중 몇 개에 답했는지 문서 하단에 적는다.

## 입력

- [ ] 같은 프레임에 입력 두 개가 들어오면 무엇이 먼저인가?
- [ ] 입력이 불가능한 상태에서 들어온 입력은 버리는가, 버퍼에 저장하는가? 저장한다면 몇 프레임(초)까지?
- [ ] 누르기(탭), 길게 누르기(홀드), 떼기(릴리즈) 중 무엇에 반응하는가?
- [ ] 연타했을 때 원하는 동작인가? (연출 중 재입력)

## 판정

- [ ] 판정 순서가 명시돼 있는가? (조건 A와 B가 동시에 참이면?)
- [ ] 경계값이 포함인가 미포함인가? (`>=` 인가 `>` 인가)
- [ ] 확률 판정의 난수는 언제 굴리는가? 저장·재접속으로 다시 굴릴 수 있는가?
- [ ] 반올림·버림은 언제 하는가? (매 계산마다 / 최종 1회)

## 상태

- [ ] 모든 상태에서 모든 이벤트의 처리가 정의돼 있는가? (상태 전이표의 빈칸)
- [ ] 상태가 겹칠 수 있는가? 겹치면 우선순위는?
- [ ] 상태에 들어갈 때·나올 때 일어나는 일(수치, 연출, 사운드)이 적혀 있는가?
- [ ] 일시정지, 컷신, 메뉴 열기 중에 타이머가 흐르는가 멈추는가?

## 데이터

- [ ] 단위가 적혀 있는가? (초 vs 프레임, 퍼센트를 0.3으로 쓰나 30으로 쓰나)
- [ ] 정수인가 실수인가? 음수가 가능한가?
- [ ] 최솟값·최댓값(clamp)과 기본값이 있는가?
- [ ] 다른 테이블을 참조하는 컬럼은 무엇을 참조하는가? 참조 대상이 없으면?
- [ ] 저장해야 하는 값과 매번 다시 계산하는 값이 구분돼 있는가?

## 예외

- [ ] 값이 0이거나 최대일 때 공식이 깨지지 않는가? (0으로 나누기, 음수 데미지)
- [ ] 대상이 처리 도중 죽거나 사라지면?
- [ ] 처리 도중 씬 전환·저장·로드가 일어나면?
- [ ] 리소스(골드, 마나, 슬롯)가 정확히 부족하거나 정확히 맞으면?
- [ ] (온라인) 처리 도중 연결이 끊기면? 서버와 클라이언트 중 누가 판정하는가?

## 어뷰징

- [ ] 저장·재접속으로 결과를 다시 굴릴 수 있는가? (세이브 스컴)
- [ ] 사고팔기, 분해·재조합으로 이득이 나는 순환이 있는가?
- [ ] 판정 경계의 한 프레임을 반복해서 노릴 수 있는가?
- [ ] 매크로·방치로 무한히 반복할 수 있는가? 상한이 있는가?

## 피드백 (UX)

- [ ] 플레이어는 지금 상태를 어떻게 아는가? (아이콘, 색, 소리)
- [ ] 실패했을 때 이유를 알 수 있는가? ("골드 부족" vs 그냥 반응 없음)
- [ ] 다음에 무슨 일이 일어날지 예측할 수 있는가? (다음 비용, 남은 시간)

## 밸런스

- [ ] 튜닝 손잡이(조정 가능한 변수)가 어디 있는지 표시돼 있는가?
- [ ] 극단적인 빌드나 장비에서 공식이 무너지지 않는가?
- [ ] 의도한 수치(처치 시간, 기대 비용)가 문서에 적혀 있는가?

## 범위 밖 (기록만)

- [ ] 접근성 (색약, 한 손 조작), 로컬라이징 텍스트 길이, 성능(동시 처리 수)
