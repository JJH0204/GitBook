## 역기획 1장 요약

### 진행 순서

1. [주제 목록](reverse-design-topics.md)에서 고르거나, 최근 플레이한 게임에서 **시스템 하나**만 떼어 낸다.
2. [템플릿](reverse-design-template.md)을 [내 훈련 기록](../practice/README.md) 아래 새 페이지로 복사한다.
3. 25분 동안 AI·위키·공략 없이 쓴다. 기억나지 않는 수치는 추정해서 쓰고, 추정이라는 사실을 ④에 적는다.
4. [스펙 체크리스트](spec-checklist.md)로 5분 동안 점검한다.
5. 주말에 AI 검증을 하고, 놓친 항목을 `[AI]` 태그로 추가한다.

### 왜 1장인가

분량 제한이 우선순위를 강제한다. 한 장에 안 들어가면 시스템을 너무 크게 고른 것이니 쪼갠다.
"전투 시스템" ✗ → "패링 판정" ✓ / "성장 시스템" ✗ → "장비 강화 실패 처리" ✓

### 나쁜 1장과 좋은 1장

| 항목 | 나쁜 예 | 좋은 예 |
|---|---|---|
| 목적 | "전투를 재밌게 하기 위해" | "적의 공격에 맞서 들어가는 '공격적 방어'를 보상해서, 거리만 벌리는 플레이를 줄인다" |
| 플로우 | "타이밍 맞게 누르면 패링" | "적 공격 판정이 켜지기 전 N프레임 안에 입력하면 성공 / 판정이 켜진 뒤 입력하면 실패하고 피격 / 다단 공격은 타마다 따로 판정" |
| 데이터 | "패링 타이밍" | `parry_window_frames` (int, 4–12, 60fps 기준), 공격 종류별 오버라이드 컬럼 |
| 예외 | (없음) | "패링 입력 중 다른 적의 공격이 들어오면?", "패링 불가 공격은 어떻게 알려 주나?" |

좋은 예의 공통점: **동사**로 쓰고, **조건과 결과**가 짝지어져 있고, **단위**가 있다.

## 밸런스 시트

[balance-drills.md](balance-drills.md)의 B1 → B4를 순서대로 진행한다. 실습마다 **검산값**이 있으니, 시트를 다 만든 뒤 대조한다.

Unity 코드로 넘어가기 전에 시트에서 의도를 먼저 검증하는 습관을 만든다. 시트는 고치는 데 1초, 코드는 빌드 한 번이 든다.
