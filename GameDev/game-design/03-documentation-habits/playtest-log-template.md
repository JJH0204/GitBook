새 페이지 제목 양식: `플레이테스트 로그: [빌드 버전] / [날짜]`

> 면접관이 가장 좋아하는 것은 "살아 있는 기획 경험"이다. 그 원재료가 이 로그다. 관찰한 것을 기록하고, 그걸 근거로 무엇을 어떻게 고쳤는지(Before → After)를 남긴다.

## 관찰 규칙

1. **행동을 쓴다. 해석은 따로 쓴다.**

   | ✗ 해석이 섞인 기록 | ✓ 관찰 기록 |
   |---|---|
   | 유저가 튜토리얼이 지루해서 넘겼다 | 튜토리얼 안내문이 뜨고 약 1초 뒤 오른쪽으로 이동 입력. 안내문 쪽으로 시선이 가지 않음 |
   | 보스가 너무 어려웠다 | 보스전 3회 사망, 3번 모두 2페이즈 돌진 공격에 맞음. 3번째 시도에서 "이거 어떻게 피해요?" |
   | UI가 헷갈렸다 | 인벤토리를 연 뒤 장착 버튼을 찾는 데 약 15초, 아이템을 길게 누르기 2번 시도 |

2. **개입하지 않는다.** 테스터가 물어봐도 바로 답하지 않는다. "어떻게 하면 될 것 같으세요?"라고 되묻고, 그 질문 자체를 기록한다.
3. **발화는 그대로 인용한다.** 요약하면 내 해석이 섞인다.
4. **시각을 적는다.** 녹화했다면 타임스탬프, 아니면 세션 시작 기준 분:초.
5. **인원**: 반복되는 큰 문제는 대개 3–5명이면 드러난다. 10명을 한 번에 부르기보다 5명씩 두 번(고치고 다시) 하는 편이 낫다.

## 해석과 이슈

> 관찰 기록 여러 줄을 묶어서 이슈로 만든다. 한 명만 겪었는지 여러 명이 겪었는지 빈도를 꼭 적는다.

| ID | 근거 관찰 | 해석 (왜 그랬을까) | 다른 가능한 해석 | 심각도 | 빈도 |
|---|---|---|---|---|---|
| PT-01 | T1 00:42, T3 00:38, T4 00:51 | 안내문이 이동 가능한 상태에서 떠서, 읽기보다 이동이 먼저 됐다 | 안내문이 화면 구석에 있어 시선에 들어오지 않았다 | 상 | 3/5 |
| | | | | | |

심각도 기준:
- **상**: 진행이 막히거나 핵심 재미를 놓친다
- **중**: 불편하지만 스스로 해결한다
- **하**: 눈에 띄지만 경험에 영향이 적다
