# 03. '질문받는 기획자'가 되기 위한 문서화 습관

| 항목 | 내용 |
|---|---|

## 1. 목적

기획자의 내실은 문서의 **논리적 완결성**에서 드러난다. 이 폴더는 두 가지 습관을 만든다.

1. **AI 배제 구역**: 생각의 뼈대는 내 손으로 세우고, AI는 그 뒤 검증에만 쓴다.
2. **플레이테스트 로그**: 관찰한 행동을 기록하고 Before → After로 남긴다.

## 3. 동작 원리

### AI 배제 구역 규칙

#### AI를 쓰지 않는 일

| 작업 | 이유 |
|---|---|
| 문제 정의, 가설, 해결안 뼈대 (초안 v0) | 문제를 어떻게 정의하느냐가 기획자의 실력 그 자체다 |
| 역기획 1장 요약 | 구조화 근육을 기르는 훈련이다 |
| 밸런스 공식 설계 | 공식을 직접 세워야 숫자의 의미를 설명할 수 있다 |
| 플레이테스트 관찰 기록 | 관찰은 현장에 있던 사람만 할 수 있다 |
| "아이디어 10개 뽑아줘" | 내 아이디어가 먼저 나와야 AI의 것과 비교할 수 있다 |

#### AI를 써도 되는 일 (초안을 다 쓴 뒤에만)

| 작업 | 조건 |
|---|---|
| 엣지 케이스, 어뷰징 가능성 찾기 | 해결책은 묻지 않고 **목록만** 받는다 |
| 수식 검산, 극단값 확인 | 내가 먼저 계산한 값과 대조한다 |
| 문장 다듬기 | 논리와 수치는 바꾸지 않는다 |
| 내 주장의 논리 비약 찾기 | 반박만 받고 다시 쓰는 건 내가 한다 |

#### 기록 규칙

- AI가 찾아낸 항목은 문서 안에 `[AI]` 태그를 붙여 추가한다.
- AI 지적은 **유효 / 무효**로 판정하고 이유를 한 줄 쓴다. 무효 판정도 학습이다.
- 유효한 지적에는 "내가 왜 놓쳤나"를 한 줄 쓴다. 이 칸이 쌓이면 내 사고의 사각지대 목록이 된다.

### 성장 지표: AI 의존도가 줄고 있는가

문서마다 두 숫자를 기록한다.

- **A** = 내가 먼저 찾은 예외·리스크 수
- **B** = AI가 추가로 찾은 **유효한** 예외·리스크 수

`B ÷ (A + B)`가 **AI 보완율**이다. 이 값이 주마다 줄어든다면 내가 놓치던 것을 스스로 찾고 있다는 뜻이다. [GMD-DOC-005-REF](../practice/README.md)의 진도표에 매주 기록한다.

| 주 | 문서 수 | A 합계 | B 합계 | AI 보완율 |
|---|---|---|---|---|
| 예) 1주 | 3 | 14 | 6 | 30% |
| 예) 4주 | 4 | 26 | 3 | 10% |

### 초안 쓰는 순서

1. 타이머 25분. 완벽하게 쓰려 하지 않는다.
2. [GMD-DOC-002-REF](problem-framing-template.md)의 1 → 4번을 **순서대로** 채운다. 해결 방안부터 쓰고 싶어지면 문제 정의가 덜 된 것이다.
3. 모르는 것은 `모름`이라고 쓴다. 지어내지 않는다.
4. 하루 이상 묵힌 뒤 다시 읽고 고친다.
5. 그다음에 AI 검증을 한다 ([GMD-DOC-003-REF](ai-review-prompts.md)).

## 4. 약어·용어

| 용어 | 뜻 |
|---|---|
| `[AI]` 태그 | AI가 찾아낸 항목임을 문서 안에 표시하는 꼬리표 |
| A | 내가 먼저 찾은 예외·리스크 수 |
| B | AI가 추가로 찾은 유효한 예외·리스크 수 |
| AI 보완율 | `B ÷ (A + B)` |
